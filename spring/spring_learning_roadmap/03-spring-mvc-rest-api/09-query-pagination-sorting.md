# 09-查询、分页和排序约定

## 查询接口为什么要先约定

很多列表接口一开始能跑，但后面会越来越乱：

- 参数名不统一。
- 页码从 0 还是 1 不清楚。
- 排序字段随意透传。
- 筛选条件和导出条件不一致。

这类问题尽早约定，后面能省很多返工。

## 基本分页字段

至少先统一：

- `pageNo`
- `pageSize`
- `keyword`
- `sortBy`
- `sortOrder`

如果团队已有约定，优先沿用。

## 排序安全

排序字段不要直接无校验透传到 SQL。

更稳的做法：

- 在后端做白名单映射。
- 明确允许哪些字段排序。

## 条件查询边界

常见筛选项：

- 状态。
- 作者。
- 分类。
- 时间范围。

时间范围尤其要注意开始和结束边界是否含当天结束时刻。

## 本节通过标准

- 能设计一套稳定的分页参数约定。
- 能避免排序字段直接裸透传。
- 能保持列表和导出的条件口径一致。
