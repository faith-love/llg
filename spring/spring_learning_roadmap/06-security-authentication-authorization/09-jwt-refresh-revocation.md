# 09-JWT 结构、刷新和失效控制

## JWT 不是“更高级”的默认答案

JWT 适合前后端分离 API，但它带来的问题也很现实：

- 一旦签发，撤销不直观。
- 权限变更不一定立刻生效。
- 刷新机制需要额外设计。

## 设计时至少要考虑

- 访问令牌有效期。
- 刷新令牌有效期。
- 失效策略。
- 黑名单或版本控制。

## 不要把太多信息塞进 Token

Token 不是越大越方便。

过多信息会带来：

- 泄露风险。
- 更新困难。
- 权限变更滞后。

## 本节通过标准

- 能解释 JWT 的典型优点和代价。
- 能知道刷新和撤销为什么是核心设计点。
- 能避免把 JWT 当成“免维护方案”。
