# 05-依赖树、覆盖和排除策略

## 什么时候看依赖树

以下情况先看依赖树：

- 类找不到。
- 方法找不到。
- 同一个库版本冲突。
- 自动配置行为不符合预期。

命令：

```powershell
mvn dependency:tree
```

## 排除依赖

有时候 Starter 带进来的依赖不是你想要的，需要排除。

但排除前要先确认：

- 是真的有冲突。
- 还是你误解了默认依赖行为。

不要为了“精简依赖”盲目把很多传递依赖都排掉。

## 排除自动配置

如果只是某个自动配置不想启用，可以排除自动配置，而不是拆掉整个 Starter。

这通常比大面积排依赖更可控。

## 本节通过标准

- 能在依赖冲突时想到先看依赖树。
- 能区分“排除依赖”和“排除自动配置”。
- 能谨慎处理 Starter 带来的默认组合。
