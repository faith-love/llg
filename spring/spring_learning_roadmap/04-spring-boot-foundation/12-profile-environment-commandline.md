# 12-Profile、环境变量和命令行参数

## Profile 用来干什么

Profile 不是为了多写几个 yml 文件，而是为了明确环境差异。

最常见的就是：

- `dev`
- `test`
- `prod`

## 环境变量的价值

环境变量适合承载部署环境差异，尤其是：

- 数据库地址
- 用户名密码
- 第三方服务地址
- 运行开关

这样可以让同一份 jar 在不同环境下保持一致部署方式。

## 命令行参数

命令行参数适合：

- 临时覆盖。
- 启动调试。
- 容器或脚本层注入特定参数。

但不适合长期替代正式配置体系。

## 设计建议

- 环境共性写默认配置。
- 环境差异放 Profile。
- 部署敏感信息交给环境变量或外部配置。

## 本节通过标准

- 能建立稳定的 Profile 结构。
- 能区分 Profile、环境变量和命令行参数的使用场景。
- 能避免把敏感信息直接写死在仓库配置里。
