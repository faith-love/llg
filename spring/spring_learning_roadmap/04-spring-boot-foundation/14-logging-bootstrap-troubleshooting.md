# 14-日志、启动阶段和常见排错路径

## 启动日志为什么重要

Boot 项目很多问题在启动阶段就已经暴露：

- 端口占用。
- Bean 冲突。
- 配置缺失。
- 数据源连不上。
- 自动配置条件不满足。

如果你跳过启动日志，只盯着最后一个异常，很容易误判。

## 建议看的几类信息

- 当前 Profile。
- 启动端口。
- 应用名。
- 自动配置或 Bean 初始化相关错误。
- Web 容器是否真正启动。

## 排错顺序

建议按这条线看：

1. 先看根因异常。
2. 再看触发它的配置或依赖。
3. 判断是容器问题、配置问题还是外部依赖问题。
4. 最后再回头改代码。

## 常见错误类型

- `Port already in use`
- `NoSuchBeanDefinitionException`
- 数据库认证失败
- 配置绑定失败

这几类问题在 Boot 初学阶段最常见。

## 本节通过标准

- 能从启动日志中提取最关键的排错信息。
- 能建立一条稳定的排错顺序。
- 能避免只盯表面报错而忽略根因。
