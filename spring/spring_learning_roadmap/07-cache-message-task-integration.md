# 07-缓存、消息、任务和集成能力

## 阶段目标

这个阶段学习常见企业项目里的外围能力：缓存提升读取性能，消息削峰和解耦，任务处理周期性工作，集成能力连接外部系统。

学完后要能设计：

- 哪些数据适合缓存，缓存失效怎么处理。
- 哪些流程适合消息队列，失败如何重试。
- 定时任务如何避免重复执行。
- 文件、邮件、第三方接口调用如何隔离和治理。

## 缓存

先掌握 Spring Cache 抽象，再落到 Redis。

需要理解：

- `@Cacheable`、`@CachePut`、`@CacheEvict` 的差异。
- 缓存 key 设计。
- 过期时间和主动失效。
- 缓存穿透、击穿、雪崩。
- 本地缓存和分布式缓存的差异。

## 消息

消息队列适合：

- 下单后异步通知。
- 日志、审计、埋点。
- 批量任务削峰。
- 跨系统最终一致性。

必须补上：

- 消息幂等。
- 消费失败重试。
- 死信队列。
- 发送确认。
- 消息顺序要求。

## 定时任务

从简单到复杂：

- `@Scheduled`：单应用简单任务。
- Quartz：需要持久化、错过执行补偿、集群调度。
- XXL-JOB 等平台：统一调度和运维。

定时任务必须考虑重复执行、并发执行、失败告警和执行日志。

## 必做练习

- 给图书详情加 Redis 缓存。
- 更新图书信息时清理缓存。
- 写一个订单创建后发送消息的流程。
- 消费消息写操作日志，并保证重复消息不重复写。
- 写一个每日统计任务，记录执行开始、结束、失败原因。
- 写一个第三方接口客户端，设置超时、重试和错误转换。

## 验收标准

- 能说明缓存和数据库不一致的常见原因。
- 能解释为什么消费者必须幂等。
- 能说明定时任务在多实例部署下的重复执行风险。
- 能把外部接口调用封装成独立客户端，而不是散落在业务代码中。
