# 07-`@Transactional` 和代理边界

## 这个注解为什么不是“加上就完事”

`@Transactional` 的能力通常依赖 Spring 代理。

这意味着事务生效有前提：

- 目标对象是 Spring Bean。
- 调用经过代理对象。
- 方法可被代理增强。

## 为什么同类内部调用容易出问题

如果一个方法在同一个类里直接调用另一个事务方法，本质通常是 `this.xxx()`。

这种调用很可能绕过代理对象，导致事务增强不生效。

## 常见边界

要特别留意：

- 同类内部调用。
- `private` 方法。
- 非 Spring 管理对象。
- 异常被吞掉。

## 本节通过标准

- 能解释 `@Transactional` 为什么依赖代理。
- 能说出几个最常见的事务不生效场景。
- 能避免把事务理解成纯注解魔法。
