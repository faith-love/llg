# 04-学习顺序和时间安排

## 为什么要设计顺序

Spring 学习资料很多，但不是每个知识点都适合一开始学。初学者如果从 Spring Cloud、OAuth2、源码、分布式事务开始，很容易花很多时间却没有形成可运行项目能力。

更稳的顺序是：

```text
Spring 核心 -> Spring MVC -> Spring Boot -> 数据访问和事务 -> 安全 -> 工程化 -> 分布式
```

这个顺序从单体后端项目出发，先让你能写出稳定接口，再逐步补外围能力。

## 0-1 个月：核心和 Web

目标：

- 理解 IoC、DI、Bean 生命周期。
- 会写 Controller、Service、Repository 分层。
- 会写 REST API。
- 会做参数校验和统一异常。

建议产出：

- 一个最小 Spring Boot Web 项目。
- 一个图书 CRUD API。
- 一份 Bean 注入错误记录。
- 一份 HTTP 请求处理流程图。

不要过早纠结：

- Spring 源码全部细节。
- 微服务。
- 高并发架构。
- 复杂权限模型。

## 1-2 个月：数据访问、事务和 Boot 主线

目标：

- 能连接数据库。
- 能写 CRUD、分页、条件查询。
- 能理解事务边界。
- 能解释 Boot 自动配置和配置文件。

建议产出：

- 图书借阅数据库表。
- 借书和还书事务流程。
- `dev/test/prod` 三套配置。
- 数据库错误和事务回滚实验记录。

关键要求：

- 每个事务练习都要设计失败场景。
- 不要只测成功路径。

## 2-3 个月：安全、缓存、消息和测试

目标：

- 能实现登录认证。
- 能做接口权限控制。
- 能使用 Redis 缓存热点数据。
- 能用 MQ 或事件机制做异步解耦。
- 能写单元测试和集成测试。

建议产出：

- 后台登录接口。
- 用户、角色、权限模型。
- Redis 缓存和失效策略。
- 消息重复消费幂等实验。
- Controller 和 Service 测试。

## 3-4 个月：部署、监控和项目复盘

目标：

- 能打包 Spring Boot 应用。
- 能写 Dockerfile。
- 能通过环境变量切换配置。
- 能打开 Actuator 健康检查和指标。
- 能写项目 README。

建议产出：

- 可运行的 Docker 镜像。
- 本地部署说明。
- 接口文档。
- 数据库设计文档。
- 项目复盘文档。

## 4 个月以后：Spring Cloud 和长期提升

目标：

- 理解微服务拆分成本。
- 会用网关、注册中心、配置中心。
- 会处理服务间调用失败。
- 能做简单链路追踪和限流降级。

建议产出：

- 用户服务、订单服务、库存服务。
- 网关路由。
- OpenFeign 调用。
- 配置中心实验。
- 调用超时、重试、降级记录。

## 每周学习节奏

建议每周按这个节奏推进：

| 时间 | 内容 |
| --- | --- |
| 第 1 天 | 读阶段文档，明确本周目标 |
| 第 2-4 天 | 写代码练习，至少完成一个可运行功能 |
| 第 5 天 | 故意制造错误，记录报错和定位过程 |
| 第 6 天 | 整理笔记和 README |
| 第 7 天 | 复盘本周问题，补测试或重构 |

## 本节练习

写一份 `spring-study-plan.md`，回答：

1. 我每周能投入多少小时？
2. 我第一个月要完成哪个项目？
3. 我最薄弱的是 Java 基础、数据库、HTTP，还是工程工具？
4. 我准备使用 Spring Boot 4.x 还是 3.x？
5. 每周固定哪一天做复盘？

## 本节通过标准

- 能给自己排出 4-8 周学习计划。
- 能说明为什么先学单体项目，再学 Spring Cloud。
- 能把每周目标转化成可运行代码，而不是只写阅读清单。
