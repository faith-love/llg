# 阶段验收标准

验收标准用于判断“是否可以进入下一阶段”。不要求每个点都完美，但不能只靠感觉说自己会了。

## 总体验收规则

每个阶段至少要有 5 类产出：

- 知识点笔记。
- 可运行代码。
- 练习清单。
- 错误记录。
- 阶段复盘。

进入下一阶段前，至少满足：

- 本阶段核心代码能独立写出来。
- 能解释主要概念，而不是只会复制。
- 能处理 3-5 个常见错误。
- 有一个小产出可以演示。
- 说明 里写清楚运行方式。

## 00 阶段验收

完成当前阶段后，应能回答：

- 为什么选择当前 Python 版本。
- 学习资料放在哪里，练习代码放在哪里。
- 每周学习节奏是什么。
- 一个知识点文档应该包含哪些部分。
- 一个练习项目应该包含哪些文件。
- 后续每个阶段如何判断通过。

必须产出：

- `Python学习资料/说明.md`
- `Python学习路线/说明.md`
- `00-总览与版本基线/说明.md`
- 学习目标文档。
- 版本选择文档。
- 目录规范文档。
- 每周节奏文档。
- 阶段验收标准文档。
- 重点难点文档。

## 代码验收标准

练习代码最低要求：

- 能从命令行运行。
- 变量命名清晰。
- 有基本输入校验。
- 出错时有明确提示。
- 不把路径、密钥、环境参数硬编码死。
- 复杂逻辑拆成函数。

项目代码进阶要求：

- 有 `说明.md`。
- 有虚拟环境和依赖说明。
- 有测试命令。
- 有日志。
- 有配置文件或环境变量说明。
- 有异常处理。
- 有最小可演示数据。

## 文档验收标准

知识点文档要能回答：

- 这个知识点解决什么问题。
- 什么时候使用。
- 最小示例是什么。
- 常见错误有哪些。
- 和相近概念有什么区别。
- 怎么练习。
- 怎么判断掌握。

如果一个文档只有概念定义，没有示例和验收，它不算完成。

## 复盘验收标准

阶段复盘至少包含：

- 本阶段学了什么。
- 哪些知识点已经能独立使用。
- 哪些知识点还需要回看。
- 写过哪些练习和项目。
- 遇到过哪些典型错误。
- 下一阶段最需要注意什么。

复盘不是写感想，而是把经验变成下一次可以复用的判断规则。
