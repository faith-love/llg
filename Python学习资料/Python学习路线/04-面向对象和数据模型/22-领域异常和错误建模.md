# 领域异常和错误建模

对象不仅保存数据和行为，也应该表达业务规则。当规则被违反时，可以用自定义异常让错误更清晰。

## 为什么需要领域异常

通用异常：

```python
raise ValueError("不能借书")
```

领域异常：

```python
raise BookUnavailableError("图书已借出")
```

领域异常更清楚地表达业务含义。

## 自定义异常

```python
class BookUnavailableError(Exception):
    pass
```

使用：

```python
class Book:
    def __初始化__(self, title):
        self.title = title
        self.available = True

    def borrow(self):
        if not self.available:
            raise BookUnavailableError("图书已借出")
        self.available = False
```

## 异常层级

可以定义领域基类：

```python
class LibraryError(Exception):
    pass


class BookUnavailableError(LibraryError):
    pass


class 未译42918berBlockedError(LibraryError):
    pass
```

调用方可以捕获所有图书馆相关错误：

```python
try:
    book.borrow()
except LibraryError as 未译12785:
    print(未译12785)
```

## 对象不变量

对象方法应该保证规则成立。

例如账户：

```python
class InsufficientBalanceError(Exception):
    pass


class BankAccount:
    def __初始化__(self, balance=0):
        if balance < 0:
            raise ValueError("初始余额不能小于 0")
        self.balance = balance

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("取款金额必须大于 0")
        if amount > self.balance:
            raise InsufficientBalanceError("余额不足")
        self.balance -= amount
```

## 什么时候用异常

适合异常：

- 违反业务规则。
- 输入不合法。
- 对象状态不允许当前操作。
- 外部调用方需要区分错误类型。

不适合异常：

- 普通分支流程。
- 可以用布尔判断表达的简单状态。
- 大量高频正常分支。

## 返回值和异常怎么选

如果失败是预期业务分支，可以返回状态：

```python
if book.available:
    ...
```

如果调用本身违反规则，可以抛异常：

```python
book.borrow()
```

当图书不可借时，`borrow` 无法完成，抛异常合理。

## 常见错误

### 只抛通用 Exception

不推荐：

```python
raise Exception("未译12785")
```

太模糊，调用方不好处理。

### 吞掉领域异常

不要捕获后什么都不做。

### 异常信息不包含上下文

错误信息应说明哪个对象、什么规则被违反。
