# 抽象基类和接口思想

Python 不强制所有接口都用抽象基类。但当你需要明确约束子类必须实现某些方法时，可以使用 `abc` 模块。

## 接口思想

接口关注“对象应该提供什么行为”。

例如导出器应该提供：

```python
export(数据)
```

不同实现：

- CSV 导出器。
- JSON 导出器。
- Excel 导出器。

## 抽象基类

```python
from abc import ABC, abstractmethod


class Exporter(ABC):
    @abstractmethod
    def export(self, 数据):
        pass
```

子类必须实现抽象方法：

```python
class JsonExporter(Exporter):
    def export(self, 数据):
        return "{}"
```

## 不能实例化抽象类

```python
exporter = Exporter()
```

会报错。

## 子类未实现抽象方法

```python
class BadExporter(Exporter):
    pass
```

也不能实例化。

## 抽象基类适合什么

适合：

- 框架或库需要定义扩展点。
- 多个实现必须遵守同一方法。
- 希望错误尽早暴露。
- 团队协作需要明确约束。

不适合：

- 只有一两个简单实现。
- 只是为了形式上“像接口”。
- 鸭子类型已经足够清楚。

## 抽象方法可以有实现

抽象方法可以提供默认逻辑，但子类仍必须重写。

```python
class Exporter(ABC):
    @abstractmethod
    def export(self, 数据):
        return str(数据)
```

本阶段了解即可。

## 和鸭子类型的关系

鸭子类型更灵活，抽象基类更明确。

选择规则：

- 小脚本和简单对象协作：鸭子类型。
- 明确扩展点和强约束：抽象基类。

## 常见错误

### 为所有类都写抽象基类

会增加样板代码，不一定带来价值。

### 抽象方法签名不一致

子类方法参数应该和抽象方法兼容。

### 抽象类承担太多业务逻辑

抽象基类应表达接口和少量共性，不应变成大而全父类。

- 能保证子类方法签名兼容。
