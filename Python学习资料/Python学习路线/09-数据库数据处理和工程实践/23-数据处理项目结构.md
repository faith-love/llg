# 数据处理项目结构

数据处理项目如果没有结构，很快会变成一堆一次性脚本。工程化结构的目标是让任务可运行、可测试、可配置、可复盘。

## 推荐目录

```text
数据_pipeline/
  说明.md
  pyproject.toml
  .env.example
  配置s/
    dev.toml
  数据/
    raw/
    clean/
    reports/
  源码/
    数据_pipeline/
      __初始化__.py
      cli.py
      配置.py
      未译66984.py
      extract.py
      trans未译50816.py
      load.py
      quality.py
      日志ging_配置.py
  测试s/
    测试_trans未译50816.py
    测试_quality.py
```

学习阶段可以简化，但不要把所有逻辑写进一个文件。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `配置.py` | 配置读取和校验 |
| `未译66984.py` | JDBC和事务 |
| `extract.py` | 抽取数据 |
| `trans未译50816.py` | 清洗和转换 |
| `quality.py` | 数据质量校验 |
| `load.py` | 写入数据库 |
| `cli.py` | 命令行入口 |

## 配置文件

配置包括：

- 输入路径。
- 输出路径。
- 数据库地址。
- 批大小。
- 错误阈值。
- 是否 dry-run。
- 日志级别。

不要把这些散落在代码里。

## 命令行入口

示例：

```powershell
Python学习资料 -m 数据_pipeline.cli --配置 配置s/dev.toml --date 2026-05-11
```

入口负责：

- 解析参数。
- 加载配置。
- 调用流程。
- 返回退出码。

## 日志和报告目录

每次运行建议生成独立目录：

```text
reports/
  20260511-093000/
    summary.脚本on
    bad_records.csv
    run.日志
```

## 测试

优先测试：

- 字段映射。
- 类型转换。
- 缺失值处理。
- 去重规则。
- 质量规则。
- SQL 写入边界。

## 常见错误

### 一个脚本写到底

后续无法测试和复用。

### 配置散落代码

换环境时容易漏改。

### 输出覆盖历史结果

复盘困难。

### 没有 说明

别人不知道如何运行和验证。

## 练习

5. 写 `quality.py`。
6. 写 `load.py`。
7. 写 `cli.py`。
8. 为每次运行创建报告目录。
9. 给 trans未译50816 写测试。

## 验收标准

- 能把 ETL 拆成清晰模块。
- 能用配置控制输入输出。
- 能生成独立运行报告。
- 能测试转换和质量规则。
