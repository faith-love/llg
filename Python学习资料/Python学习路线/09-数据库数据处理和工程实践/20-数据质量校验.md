# 数据质量校验

数据质量校验是 ETL 的防线。没有校验，脏数据会进入数据库，后续报表、接口和业务判断都会被污染。

## 校验类型

常见校验：

| 类型 | 示例 |
| --- | --- |
| 必填 | order_id 不为空 |
| 唯一 | order_id 唯一 |
| 类型 | amount 是数字 |
| 范围 | amount >= 0 |
| 枚举 | status 在允许列表中 |
| 日期 | created_at 可解析 |
| 关系 | 用户_id 在用户表存在 |
| 行数 | 输出行数不应异常减少 |

## 质量报告

质量报告应包含：

- 输入行数。
- 输出行数。
- 通过行数。
- 失败行数。
- 缺失字段。
- 重复数量。
- 类型错误数量。
- 枚举错误数量。
- 关系错误数量。

## 阈值

可以设置阈值：

- 错误率超过 5% 直接失败。
- 输出行数低于昨日 80% 报警。
- 重复主键大于 0 直接失败。

阈值要写清楚，不要藏在代码里。

## 常见错误

### 只清洗不校验

清洗可能掩盖问题，校验用于确认结果可信。

### 只输出成功数据

失败数据也要报告，否则无法修复源头。

### 质量规则没有版本

规则变了，历史结果难解释。

### 阈值随意

阈值应结合业务和历史数据。

## 练习

1. 校验必填字段。
2. 校验 order_id 唯一。
3. 校验 amount 非负。
4. 校验 status 枚举。
5. 校验日期可解析。
6. 校验订单 用户_id 是否存在。
7. 生成质量报告 JSON。
8. 错误率超过阈值时终止任务。
9. 输出失败明细 CSV。

## 验收标准

- 能设计基础数据质量规则。
- 能输出质量报告和失败明细。
- 能设置明确阈值。
- 能防止脏数据直接入库。
