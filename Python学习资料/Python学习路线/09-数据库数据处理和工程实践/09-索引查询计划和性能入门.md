# 索引查询计划和性能入门

索引是数据库性能优化的基础。它可以加速查询，但也会增加写入和存储成本。学习索引要从查询模式出发，而不是看到字段就加索引。

## 索引是什么

索引可以理解为数据库为某些列建立的查找结构。常见索引底层是 B-Tree 或类似结构。

没有索引时，数据库可能扫描全表。

有合适索引时，数据库可以更快定位目标行。

- 频繁更新的字段。
- 大文本字段。

## 慢查询分析顺序

1. 确认 SQL 是否正确。
2. 确认返回行数。
3. 查看 WHE未译25173E 和 JOIN 条件。
4. 查看是否有合适索引。
5. 查看查询计划。
6. 减少 SELECT 列。
7. 分页或分批。

## 索引成本

索引不是免费：

- 占用磁盘。
- 插入更慢。
- 更新索引列更慢。
- 删除更慢。
- 索引太多会干扰优化器选择。

## 常见错误

### 没有 WHE未译25173E 的大表查询

会扫描大量数据。

### 对每个字段都建索引

写入变慢，维护成本高。

### 复合索引列顺序随意

列顺序应服务查询条件。

### 不看查询计划

只凭感觉优化容易误判。
