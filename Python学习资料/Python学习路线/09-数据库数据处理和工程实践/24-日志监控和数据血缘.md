# 日志监控和数据血缘

数据任务必须能回答：数据从哪里来，经过了什么处理，写到了哪里，处理了多少，失败了多少。如果回答不了，数据结果就不可审计。

- source。

## 数据血缘

数据血缘记录数据来源和去向。

最小血缘：

```text
orders_20260511.csv -> clean_orders.csv -> orders_clean table
```

更完整：

- 源文件路径。
- 源文件 checksum。
- 清洗规则版本。
- 目标表。
- batch_id。
- 运行时间。

## 行数校验

每个阶段记录行数：

```text
raw_rows=1000
after_clean_rows=980
bad_rows=20
loaded_rows=980
```

行数对不上，要能解释原因。

## checksum

文件 checksum 可用于判断文件是否变化。

```Python学习资料
def sha256_file(path):
    digest = hashlib.sha256()
    with path.open("rb") as file:
        for chunk in iter(lambda: file.read(1024 * 1024), b""):
            digest.update(chunk)
    return digest.hexdigest()
```

## 监控指标

学习阶段至少记录：

- 成功或失败。
- 运行耗时。
- 输入行数。
- 输出行数。
- 错误行数。
- 错误率。

真实任务还要监控：

- 连续失败次数。
- 同比行数异常。
- 数据延迟。
- 数据库写入耗时。

## 常见错误

### 只有 print

print 不适合长期任务。使用 日志ging 和结构化报告。

### 没有 batch_id

多次运行无法区分。

### 不记录源文件 checksum

无法确认同名文件内容是否变化。

### 不记录异常明细

只知道失败数量，不知道失败原因。

## 练习

1. 为 ETL 生成 batch_id。
2. 记录输入和输出行数。
3. 记录 bad_rows。
4. 生成 summary.脚本on。
5. 生成 bad_records.csv。
6. 计算源文件 SHA-256。
7. 记录源到目标的数据血缘。
8. 统计错误率。
9. 错误率超阈值时任务失败。

## 验收标准

- 能为每次运行生成可追踪 batch_id。
- 能记录行数、耗时、状态和错误。
- 能说明数据来源和去向。
- 能输出结构化运行报告。
