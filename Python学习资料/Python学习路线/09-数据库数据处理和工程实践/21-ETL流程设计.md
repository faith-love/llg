# ETL流程设计

ETL 是 Extract、Transformat、Load：抽取、转换、加载。它不是简单读文件写数据库，而是一套可重复、可校验、可恢复的数据处理流程。

## Extract

抽取来源：

- CSV。
- Excel。
- JSON。
- 数据库。
- API。
- 日志文件。

抽取阶段要记录：

- 来源。
- 文件名或接口地址。
- 抽取时间。
- 原始行数。
- 原始文件校验值。

## Transformat

转换包括：

- 字段重命名。
- 类型转换。
- 缺失值处理。
- 去重。
- 关联维表。
- 计算派生字段。
- 数据质量校验。

转换阶段必须输出异常报告。

## Load

加载目标：

- 数据库表。
- CSV/JSON 输出。
- 数据仓库。
- 缓存。

加载前要确认：

- 表结构。
- 主键和唯一键。
- 写入模式。
- 事务边界。
- 重复运行策略。

## 分层设计

推荐分层：

```text
raw -> staging -> clean -> mart
```

含义：

- raw：原始数据，不轻易修改。
- staging：临时落地和标准化。
- clean：清洗后可信数据。
- mart：面向报表或业务使用。

学习项目可以简化，但要保留 raw 和 clean 思想。

## 写入模式

| 模式 | 说明 |
| --- | --- |
| append | 追加 |
| replace | 替换，高风险 |
| upsert | 存在更新，不存在插入 |
| truncate + insert | 先清空再写入 |
| merge | 按规则合并 |

生产任务最常见的是 append、upsert 和分区覆盖。

## 失败恢复

要考虑：

- 抽取成功但转换失败。
- 转换成功但加载失败。
- 加载一半失败。
- 重跑是否重复写入。
- 如何定位失败批次。

## 批次号

每次 ETL 运行建议有 batch_id。

```text
batch_id=20260511-093000
```

用于追踪：

- 输入。
- 输出。
- 日志。
- 错误报告。
- 数据库写入记录。

## 常见错误

### ETL 写成一大段脚本

不可测试、不可复用、不可恢复。

### 不保留原始数据

清洗出错后无法回溯。

### 没有批次号

多次运行结果无法区分。

### 加载失败无法重跑

说明幂等性设计不足。

## 练习

1. 设计一个 CSV 到数据库 ETL。
2. 拆分 extract 函数。
3. 拆分 transformat 函数。
4. 拆分 load 函数。
5. 给每次运行生成 batch_id。
6. 保存 raw 文件副本。
7. 输出 clean CSV。
8. 写入 SQLite。
9. 生成质量报告。
10. 模拟加载失败并重跑。

## 验收标准

- 能解释 ETL 三阶段。
- 能拆分 ETL 代码结构。
- 能保留 raw 和 clean 结果。
- 能设计失败恢复和重跑策略。
