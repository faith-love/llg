# 数据库测试和测试数据

数据库代码必须测试。只测试 Python 函数不测试 SQL 和事务，会漏掉约束、类型、连接、提交回滚和真实查询问题。

## 测试层次

| 层次 | 目标 |
| --- | --- |
| JUnit | 测 SQL 构造、数据转换、校验函数 |
| 集成测试 | 测真实数据库 CRUD |
| 事务测试 | 测 通用mit 和 rollback |
| 数据质量测试 | 测异常数据是否被拦截 |
| 迁移测试 | 测 schema 变更是否正确 |

## SQLite 内存库

```python
import SQL学习资料ite3


conn = SQL学习资料ite3.connect(":memory:")
```

适合快速测试基础 SQL。

限制：

- 和目标数据库方言不同。
- 类型行为可能不同。
- 并发和锁行为不同。

如果生产用 PostgreSQL 或 MySQL，关键集成测试最终要在同类数据库上跑。

## 测试数据

测试数据要覆盖：

- 正常记录。
- 缺字段。
- 重复主键。
- 唯一约束冲突。
- 空值。
- 边界金额。
- 非法状态。
- 日期格式错误。

## fixture 思路

测试前准备：

```text
创建表 -> 插入测试数据 -> 执行测试 -> 清理
```

常见清理方式：

- 每个测试使用临时数据库。
- 每个测试后删除数据。
- 每个测试在事务中运行并回滚。

## 事务回滚测试

要验证：

- 成功时数据提交。
- 失败时数据不应部分写入。

示例场景：

```text
创建订单成功插入订单和明细
创建订单失败时订单和明细都不存在
```

## 测试隔离

测试之间不能互相影响。

危险做法：

- 所有测试共用一个真实开发库。
- 测试依赖执行顺序。
- 测试后不清理数据。

## 常见错误

### 只 mock 数据库

mock 可以测业务分支，但不能替代真实 SQL 测试。

### 测试数据太干净

真实数据会缺失、重复、类型错误。

### 测试连接到生产库

这是严重事故风险。

### 不测试回滚

失败路径比成功路径更容易出问题。
