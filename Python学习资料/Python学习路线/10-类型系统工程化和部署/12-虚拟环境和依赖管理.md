# 虚拟环境和依赖管理

依赖管理的目标是让项目在本地、CI、Docker和生产环境中尽可能可复现。不要让“我电脑能跑”成为唯一标准。

## 虚拟环境

创建：

```powershell
Python学习资料 -m venv .venv
```

激活：

```powershell
.\.venv\Scripts\Activate.ps1
```

安装依赖：

```powershell
pip install requests
```

## 为什么需要虚拟环境

原因：

- 不污染全局 Python。
- 项目之间依赖隔离。
- 便于删除重建。
- CI 和Docker更容易复现。

## requirements.txt

简单依赖文件：

```text
requests==2.32.3
py测试==8.3.4
```

安装：

```powershell
pip install -r requirements.txt
```

## 直接依赖和间接依赖

直接依赖：

- 你的代码直接 import 的包。

间接依赖：

- 直接依赖所依赖的包。

lock 文件通常固定完整依赖树。

## 版本范围

常见：

```text
requests>=2.32,<3
```

或固定：

```text
requests==2.32.3
```

应用项目更重视可复现，库项目更重视兼容范围。

## 依赖分组

常见分组：

- runtime：运行依赖。
- dev：开发依赖。
- 测试：测试依赖。
- 文档：文档依赖。

不要把测试工具打进生产镜像。

## 升级策略

依赖不是越新越好。

建议：

- 定期升级。
- 小步升级。
- 看 change日志。
- 跑测试。
- 记录破坏性变更。

## 常见错误

### 使用全局环境开发

项目依赖不可控。

### requirements 不固定版本

不同时间安装得到不同结果。

### 本地和 CI 依赖来源不同

CI 可能暴露本地没发现的问题。

### 生产安装 dev 依赖

镜像膨胀，攻击面增加。

## 练习

1. 创建 `.venv`。
2. 激活虚拟环境。
3. 安装一个依赖。
4. 生成 requirements。
5. 删除虚拟环境后重建。
6. 区分 runtime 和 dev 依赖。
7. 固定依赖版本。
8. 写依赖升级记录。

## 验收标准

- 能使用 venv 隔离环境。
- 能安装和固定依赖。
- 能区分直接依赖和间接依赖。
- 能说明 lock 文件的价值。
