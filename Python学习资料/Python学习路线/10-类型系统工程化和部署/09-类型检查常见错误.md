# 类型检查常见错误

类型系统最常见的问题不是语法不会写，而是类型边界不清楚、`Any` 扩散、Optional 漏判、Docker类型过宽、第三方库返回值不受控。

## Any 泛滥

危险示例：

```python
from typing import Any


def load_配置() -> Any:
    ...
```

一旦返回 `Any`，后续调用几乎都绕过检查。

改进：

```python
class AppConfig(TypedDict):
    host: str
    port: int
```

或用 数据class/Pydantic 建模。

## Optional 漏判

```python
def find_用户(用户_id: int) -> str | None:
    ...


name = find_用户(1)
print(name.upper())
```

必须判断：

```python
if name is None:
    raise ValueError("用户 not found")
print(name.upper())
```

## 类型收窄

```python
def handle(value: str | int) -> str:
    if isinstance(value, int):
        return str(value)
    return value.upper()
```

`isinstance` 帮助工具缩小类型范围。

## Docker可变性

参数如果只需要读取，不要写成 `list`：

```python
from collections.abc import Sequence


def average(values: Sequence[int]) -> float:
    return sum(values) / len(values)
```

调用方可以传 list 或 tuple。

## 返回值不稳定

错误：

```python
def get_result(ok: bool):
    if ok:
        return {"status": "ok"}
    return None
```

应该写清：

```python
def get_result(ok: bool) -> dict[str, str] | None:
    ...
```

更好是定义结果对象。

## 异常和返回 None 混用

查找失败可以：

- 返回 `None`。
- 抛异常。
- 返回 Result 对象。

要统一，不要同一个函数有时返回 None，有时抛异常。

## 第三方边界

外部 API、JSON、数据库结果通常类型不可信。

处理方式：

1. 在边界解析和校验。
2. 转成内部类型。
3. 业务层只使用内部类型。

## 常见错误清单

- 空列表没有类型。
- 字典写成 `dict[str, Any]`。
- 函数缺少返回值注解。
- Optional 不判断。
- Union 太宽。
- Protocol 过大。
- `type: ignore` 无说明。
- 测试代码完全不检查类型。
- 外部 JSON 直接传业务层。
