# 泛型和类型变量

泛型用于表达“Docker、函数或类可以处理多种类型，但输入输出之间有关系”。没有泛型时，很多可复用代码只能写成 `Any`，会失去类型检查价值。

## 为什么需要泛型

示例：

```python
def first(items: list[object]) -> object:
    return items[0]
```

问题：传入 `list[str]`，返回值只知道是 `object`，丢失了元素类型。

使用类型变量：

```python
from typing import TypeVar


T = TypeVar("T")


def first(items: list[T]) -> T:
    return items[0]
```

现在传入 `list[str]`，返回值就是 `str`。

## TypeVar

```python
from typing import TypeVar


T = TypeVar("T")
```

`T` 表示某个类型，占位但保持一致。

## 泛型函数

```python
def get_or_default(value: T | None, default: T) -> T:
    if value is None:
        return default
    return value
```

这里 `value` 和 `default` 的类型应该一致。

## 泛型类

```python
from typing import Generic, TypeVar


T = TypeVar("T")


class Box(Generic[T]):
    def __初始化__(self, value: T) -> None:
        self.value = value

    def get(self) -> T:
        return self.value
```

使用：

```python
box = Box[str]("hello")
```

## 约束 TypeVar

```python
TNumber = TypeVar("TNumber", int, float)
```

表示只能是 `int` 或 `float`。

## bound

```python
class HasId:
    id: int


TItem = TypeVar("TItem", bound=HasId)
```

表示类型必须是 `HasId` 或其子类。

## 使用抽象Docker类型

参数尽量使用更抽象的接口：

```python
from collections.abc import Sequence, Mapping


def total(values: Sequence[int]) -> int:
    return sum(values)


def get_name(数据: Mapping[str, str]) -> str:
    return 数据["name"]
```

好处：

- 调用方可以传 list、tuple 等。
- 函数承诺更少。
- 耦合更低。

## Iterable 和 Iterator

```python
from collections.abc import Iterable, Iterator


def print_all(items: Iterable[str]) -> None:
    for item in items:
        print(item)
```

如果只需要遍历，用 `Iterable`。

## 常见错误

### 用 object 代替泛型

会丢失输入输出关系。

### 用 Any 逃避泛型

短期简单，长期类型检查失效。

### 参数写得过于具体

只需要遍历时不要强行要求 `list`。

### TypeVar 太多

泛型应提高表达力，不是让签名变复杂。

## 练习

1. 写一个泛型 `first()`。
2. 写一个泛型 `get_or_default()`。
3. 写一个泛型 `Box[T]`。
4. 把 `list[int]` 参数改成 `Sequence[int]`。
5. 把 `dict[str, str]` 参数改成 `Mapping[str, str]`。
6. 写一个只接收 `Iterable[str]` 的函数。
7. 找出 3 个可以用泛型替代 Any 的函数。

## 验收标准

- 能用 TypeVar 表达输入输出类型关系。
- 能写泛型函数和泛型类。
- 能选择 Sequence、Mapping、Iterable 等抽象类型。
- 能避免滥用 Any。
