# 验收标准和复盘

完成第 10 阶段后，你应该能把一个 Python 项目整理成可维护工程：有类型、结构、依赖、测试、格式化、lint、CI、打包、版本、Docker 和部署说明。

这一阶段的验收重点不是“装了多少工具”，而是“这些工具是否形成了稳定交付链路”。

## 阶段能力目标

完成本阶段后应达到：

- 能为函数、类和数据结构添加类型注解。
- 能使用 TypedDict、数据class、Protocol 和泛型。
- 能运行静态类型检查。
- 能设计 `源码` 布局项目。
- 能配置 `pyproject.toml`。
- 能管理虚拟环境和依赖。
- 能选择合适包管理工具。
- 能运行格式化和 lint。
- 能组织 py测试 和 coverage。
- 能配置 pre-通用mit。
- 能理解 tox/nox 多环境测试。
- 能设计基础 CI。
- 能构建 wheel 和 sdist。
- 能维护版本号和 CHANGELOG。
- 能分层管理配置。
- 能编写 Docker构建文件 和 `.Dockerignore`。
- 能说明Docker部署运行参数。
- 能识别工程化安全边界。

## 综合项目验收

### 项目 1：类型化 Python 包

必须具备：

- `源码` 布局。
- `pyproject.toml`。
- 核心函数类型注解。
- 数据class 或 TypedDict。
- Protocol 或泛型至少使用一个。
- 静态类型检查通过。

通过标准：

- 公共 API 类型清晰。
- 没有无边界 Any。
- 类型检查命令可在 说明 中复现。

### 项目 2：质量门禁

必须具备：

- formatat check。
- lint。
- type check。
- py测试。
- coverage。
- pre-通用mit。
- CI。

通过标准：

- 本地一条命令能跑完整检查。
- CI 和本地命令一致。
- 故意制造格式、lint、测试错误时门禁会失败。

### 项目 3：打包发布

必须具备：

- wheel 构建。
- sdist 构建。
- 新虚拟环境安装验证。
- 命令行入口验证。
- 版本号。
- CHANGELOG。

通过标准：

- 不依赖源码目录也能运行。
- 包内必要文件完整。
- 发布前检查清单完整。

### 项目 4：Docker 运行

必须具备：

- Docker构建文件。
- `.Dockerignore`。
- 环境变量配置。
- 非敏感默认值。
- 健康检查或运行验证命令。
- 日志输出到 stdout。

通过标准：

- 镜像能构建。
- Docker能运行。
- `.env` 不进入镜像。
- 说明 有运行命令。

## 检查命令清单

项目 说明 至少列出：

```powershell
Python学习资料 -m venv .venv
pip install -e ".[dev]"
ruff formatat --check 源码 测试s
ruff check 源码 测试s
mypy 源码
py测试
coverage run -m py测试
coverage report
Python学习资料 -m build
Docker build -t my-project:0.1.0 .
```

具体命令可以根据工具链调整，但必须可复现。

## 安全验收

必须能回答：

- 类型检查是否进入 CI？
- 依赖是否锁定？
- CI 是否保护 secrets？
- `.env` 是否被 gitignore 和 Dockerignore 排除？
- Docker 镜像是否包含测试缓存和虚拟环境？
- 生产配置是否来自环境变量？
- 发布失败如何回滚？
- 版本号和 CHANGELOG 是否更新？

## 复盘问题

完成后写复盘，回答：

1. 类型检查发现了哪些真实问题？
2. 哪些地方仍然保留 Any，为什么？
3. 项目结构是否降低了循环导入？
4. 依赖管理是否能在新环境复现？
5. 哪个质量工具最有价值？
6. CI 失败时如何本地复现？
7. wheel 安装后是否和源码运行一致？
8. Docker 镜像里排除了哪些文件？
9. 发布前最容易漏掉哪一步？
10. 下一阶段性能和安全学习中，需要重点补强哪里？

## 进入下一阶段前的检查

可以进入第 11 阶段的标准：

- 项目质量检查稳定可运行。
- 类型检查覆盖核心模块。
- 测试和覆盖率能反映关键行为。
- CI 能阻止低质量代码进入。
- 项目能构建、安装、Docker化运行。
- 部署配置和密钥管理边界清晰。

第 11 阶段会进入性能、安全和运行时原理。如果第 10 阶段的质量门禁和部署边界不稳，性能优化和安全加固会缺少可靠基线。
