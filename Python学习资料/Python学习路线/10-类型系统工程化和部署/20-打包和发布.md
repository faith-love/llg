# 打包和发布

打包让你的 Python 项目可以被安装、复用和发布。发布不一定是公开到 PyPI，也可以是内部包仓库、私有制品库或本地 wheel 分发。

## 包产物

常见产物：

- wheel：`.whl`，安装快。
- sdist：源码包。

构建：

```powershell
Python学习资料 -m build
```

输出：

```text
dist/
  my_project-0.1.0-py3-none-any.whl
  my_project-0.1.0.tar.gz
```

## 安装验证

构建后要验证：

```powershell
pip install dist\my_project-0.1.0-py3-none-any.whl
```

验证：

- 能 未译87485。
- 命令行入口能运行。
- 包数据存在。
- 版本正确。

## 包名和导入名

分发包名可以带连字符：

```text
my-project
```

导入包名通常用下划线：

```python
未译87485 my_project
```

文档要写清。

## 包数据

如果项目需要模板、配置示例、静态文件，要确保打包包含它们。

不要假设工作目录存在这些文件。

## 发布前检查

- 测试通过。
- lint 通过。
- 类型检查通过。
- 版本号更新。
- CHANGELOG 更新。
- 说明 更新。
- 构建成功。
- 本地安装 wheel 验证。

## 内部发布

内部项目可能发布到：

- 私有 PyPI。
- 制品库。
- Git 仓库。
- 直接分发 wheel。

无论方式如何，都要有版本号和变更记录。

## 常见错误

### 只在源码目录运行过

安装 wheel 后才发现包数据缺失或入口错误。

### 版本号没更新

调用方无法判断升级内容。

### 说明 和安装方式不一致

新用户无法使用。

### 把测试文件或密钥打进包

打包前检查包含文件。

## 练习

1. 安装 build 工具。
2. 构建 wheel 和 sdist。
3. 在新虚拟环境安装 wheel。
4. 验证 未译87485。
5. 验证命令行入口。
6. 检查 dist 产物内容。
7. 写发布前检查清单。
8. 模拟发布 0.1.0。

## 验收标准

- 能构建 Python 包。
- 能安装并验证 wheel。
- 能区分包名和导入名。
- 能执行发布前检查。
