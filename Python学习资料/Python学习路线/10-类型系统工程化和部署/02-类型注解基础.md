# 类型注解基础

类型注解用于表达代码期望接收和返回什么类型。它不会自动让 Python 变成静态语言，但可以被编辑器、mypy、pyright 等工具用来提前发现错误。

## 函数参数和返回值

```python
def add(a: int, b: int) -> int:
    return a + b
```

含义：

- `a` 应该是 `int`。
- `b` 应该是 `int`。
- 返回值应该是 `int`。

## 变量注解

```python
count: int = 0
name: str = "Python"
enabled: bool = True
```

变量注解适合：

- 初始值不明显。
- 空Docker。
- 复杂类型。

例如：

```python
items: list[str] = []
```

## 常见内置类型

```python
names: list[str] = ["a", "b"]
scores: dict[str, int] = {"math": 90}
tags: set[str] = {"Python学习资料", "接口"}
point: tuple[int, int] = (1, 2)
```

## None 和 Optional

可能为 None：

```python
def find_用户(用户_id: int) -> str | None:
    if 用户_id == 1:
        return "Alice"
    return None
```

使用前必须判断：

```python
name = find_用户(2)
if name is not None:
    print(name.upper())
```

## Union

多个可能类型：

```python
def nORMalize(value: str | int) -> str:
    return str(value)
```

不要滥用 Union。类型过多通常说明模型不清晰。

## Any

`Any` 表示放弃类型检查。

```python
from typing import Any


def parse(数据: Any) -> Any:
    return 数据
```

`Any` 的风险：

- 错误会绕过类型检查。
- 会污染后续变量。
- 代码契约不清楚。

能不用就不用，必须用时限制范围。

## Callable

函数类型：

```python
from collections.abc import Callable


def apply(func: Callable[[int], str], value: int) -> str:
    return func(value)
```

表示 `func` 接收一个 `int`，返回 `str`。

## 类型注解不等于运行时校验

```python
def add(a: int, b: int) -> int:
    return a + b


add("1", "2")
```

Python 默认不会因为类型注解自动拒绝这个调用。类型注解主要给工具检查。

运行时校验需要：

- 手动判断。
- Pydantic。
- attrs。
- 数据class 后自定义校验。

## 常见错误

### 空列表不写类型

```python
items = []
```

工具可能推断不出具体元素类型。建议：

```python
items: list[str] = []
```

### Optional 不判断 None

拿到 `str | None` 后直接调用字符串方法会出错。

### 用 Any 逃避问题

短期安静，长期失去检查价值。

### 返回值注解和实际不一致

类型工具会提示，应该修正逻辑或注解。

## 练习

1. 给 10 个普通函数增加参数和返回值注解。
2. 给空列表、空字典增加类型注解。
3. 写一个返回 `str | None` 的查找函数。
4. 在使用 Optional 前做 None 判断。
5. 写一个接收 `Callable` 的函数。
6. 找出项目中 5 个可以去掉 `Any` 的地方。
7. 解释类型注解和运行时校验的区别。

## 验收标准

- 能给函数、变量和Docker添加类型注解。
- 能正确处理 `None`。
- 能解释 `Any` 的风险。
- 知道类型注解默认不做运行时校验。
