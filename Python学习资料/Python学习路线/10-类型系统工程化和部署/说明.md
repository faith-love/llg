# 10-类型系统工程化和部署

这一阶段的目标是把 Python 项目从“能运行”推进到“可维护、可检查、可发布、可部署”。你要掌握类型系统、项目结构、依赖管理、代码规范、质量门禁、打包发布、Docker、CI/CD 和运行配置。

如果前面阶段解决的是“怎么写功能”，第 10 阶段解决的是“多人长期维护一个 Python 项目时，怎样降低出错成本，并让项目稳定交付”。

## 本阶段产出

- 一个使用 `源码` 布局的 Python 包。
- 一份完整 `pyproject.toml`。
- 一套类型注解和静态检查配置。
- 一套格式化、lint、测试、覆盖率配置。
- 一个 pre-通用mit 本地质量门禁。
- 一个 CI 流水线示例。
- 一个可构建的 wheel 包。
- 一个 Docker构建文件 和 `.Dockerignore`。
- 一份发布、部署和回滚检查清单。

## 本阶段不做什么

- 不追求一次性把所有历史代码改成 strict 类型。
- 不把工具堆满项目而没有规则解释。
- 不把生产密钥写进配置、镜像或 CI 日志。
- 不在 Docker 镜像里保留无关缓存、测试数据和本地配置。
- 不把 CI 当成形式，必须让它真正阻止低质量代码进入主分支。
