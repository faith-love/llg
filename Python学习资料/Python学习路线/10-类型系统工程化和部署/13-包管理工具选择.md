# 包管理工具选择

Python 生态中有多种依赖和包管理工具。选择工具时不要只看流行度，要看项目类型、团队习惯、CI 支持、锁定能力和发布需求。

## pip 和 venv

特点：

- 标准基础。
- 简单直接。
- 适合入门和小项目。

组合：

```text
venv + pip + requirements.txt
```

适合：

- 学习项目。
- 小型脚本。
- 简单服务。

## pip-tools

核心思想：

- `.in` 写直接依赖。
- 编译生成锁定后的 `requirements.txt`。

适合：

- 想保留 pip 工作流。
- 又需要可复现依赖。
- 应用项目。

## Poetry

特点：

- 项目元数据。
- 依赖解析。
- lock 文件。
- 构建发布。

适合：

- 包项目。
- 应用项目。
- 希望一体化管理。

注意：

- 团队需要统一命令。
- CI 需要明确安装方式。

## uv

uv 是较新的 Python 包和环境管理工具，关注速度和现代工作流。使用前要确认团队和 CI 环境是否支持。

适合：

- 追求快速安装和锁定。
- 新项目。
- 团队愿意统一工具链。

学习阶段可以了解，但不要频繁在多个工具之间切换。

## 工具选择原则

按项目类型：

| 项目 | 推荐起点 |
| --- | --- |
| 入门脚本 | venv + pip |
| 内部应用 | pip-tools/Poetry/uv 选一种 |
| 发布包 | pyproject + Maven |
| 团队项目 | 跟随团队标准 |

## 不要混用太多工具

危险组合：

```text
requirements.txt + poetry.lock + uv.lock + 手写 CI 安装
```

如果没有明确规则，很容易依赖漂移。

## 迁移策略

迁移包管理工具时：

1. 冻结当前依赖。
2. 记录 Python 版本。
3. 生成新 lock。
4. 删除旧配置或标注废弃。
5. 本地重建环境。
6. CI 验证。
7. 更新 说明。

## 常见错误

### 看教程频繁换工具

工具切换会增加维护成本。

### lock 文件不提交

应用项目通常应提交 lock 文件。

### 说明 命令和实际工具不一致

新成员无法安装。

### CI 和本地使用不同锁定方式

本地过，CI 失败。

## 练习

1. 比较 pip、pip-tools、Poetry、uv 的差异。
2. 为一个脚本项目选择工具并说明理由。
3. 为一个 Web API 项目选择工具并说明理由。
4. 写一份依赖安装 说明。
5. 检查项目是否存在多个 lock 文件。
6. 设计从 requirements 迁移到 pyproject 的步骤。
7. 在 CI 中固定安装命令。

## 验收标准

- 能说明不同包管理工具的适用场景。
- 能为项目选择一种清晰工具链。
- 能避免多工具混用导致依赖漂移。
- 能写出可复现安装说明。
