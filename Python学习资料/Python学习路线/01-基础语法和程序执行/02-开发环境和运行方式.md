# 开发环境和运行方式

学习 Python 的第一步不是写复杂代码，而是确认自己能稳定运行代码。环境不清楚时，后续很多报错其实不是语法问题，而是解释器、路径或虚拟环境问题。

## 必须掌握的运行方式

### 1. 查看 Python 版本

```powershell
Python学习资料 --version
py --version
```

需要确认：

- 当前命令调用的是哪个 Python。
- 版本是否符合学习路线。
- 是否在虚拟环境里。

### 2. 交互式运行

在终端输入：

```powershell
Python学习资料
```

进入交互式环境后可以直接输入：

```python
1 + 2
print("hello")
```

适合：

- 快速验证表达式。
- 测试一个函数的行为。
- 观察类型转换结果。

不适合：

- 写完整项目。
- 保存长期练习。

### 3. 脚本运行

创建文件：

```text
hello.py
```

写入：

```python
print("hello Python学习资料")
```

运行：

```powershell
Python学习资料 hello.py
```

这是本阶段最主要的运行方式。

### 4. 模块方式运行

有些代码会用模块方式运行：

```powershell
Python学习资料 -m pip --version
Python学习资料 -m http.服务端
```

`-m` 的意思是按模块运行。后面学习模块和包时会深入。

本阶段先知道：

- `Python学习资料 file.py` 是运行文件。
- `Python学习资料 -m module_name` 是运行模块。

## 工作目录

运行脚本时，终端所在目录叫当前工作目录。

例如：

```powershell
cd D:\learn\Python学习资料
Python学习资料 .\practice\hello.py
```

很多路径问题都和工作目录有关。

需要养成习惯：

- 运行前确认自己在哪个目录。
- 不要随意写死绝对路径。
- 相对路径要知道相对的是当前工作目录。

## 解释器路径

同一台电脑可能有多个 Python：

- 系统 Python。
- 官方安装的 Python。
- IDE 配置的 Python。
- 虚拟环境里的 Python。

检查命令：

```powershell
where Python学习资料
py -0p
```

如果代码在 VS Code 能跑、终端不能跑，常见原因就是解释器不一致。

## 虚拟环境入门

基础阶段可以先知道虚拟环境的作用：让每个项目有独立依赖。

创建：

```powershell
Python学习资料 -m venv .venv
```

激活：

```powershell
.\.venv\Scripts\Activate.ps1
```

退出：

```powershell
deactivate
```

本阶段不要求深入依赖管理，但要避免把所有包都装进全局 Python。

## 常见问题

### `Python学习资料` 不是内部或外部命令

可能原因：

- Python 没安装。
- 安装时没有加入 PATH。
- 终端没有重新打开。

### 运行的不是预期版本

可能原因：

- 电脑上有多个 Python。
- IDE 和终端使用不同解释器。
- 虚拟环境没有激活。

### 文件路径找不到

可能原因：

- 当前工作目录不对。
- 路径里有空格但没有正确引用。
- 使用了错误的相对路径。

## 练习

1. 查看当前 Python 版本。
2. 进入交互式环境，计算 `123 * 456`。
3. 创建 `hello.py` 并运行。
4. 故意写错文件名，观察报错。
5. 用 `where Python学习资料` 查看解释器路径。

## 验收标准

- 能说清交互式运行和脚本运行的区别。
- 能从命令行运行 `.py` 文件。
- 能确认当前 Python 版本和解释器路径。
- 能解释工作目录对文件路径的影响。
