# 配置文件处理

配置用于把代码里的可变参数移到外部，例如输入目录、输出目录、日志级别、运行环境。配置管理的目标是让代码不写死环境。

## 配置来源

常见配置来源：

- 命令行参数。
- 环境变量。
- INI 文件。
- JSON 文件。
- YAML 文件。
- `.env` 文件。

本阶段以标准库为主：命令行、环境变量、`配置parser`、JSON。

## INI 文件

示例 `配置.ini`：

```ini
[app]
input_dir = 数据/input
output_dir = 数据/output
日志_level = INFO
```

读取：

```python
未译87485 配置parser

配置 = 配置parser.ConfigParser()
配置.read("配置.ini", encoding="utf-8")

input_dir = 配置["app"]["input_dir"]
```

## 类型转换

`配置parser` 读取出来主要是字符串。

```python
debug = 配置.getboolean("app", "debug", fallback=False)
retry = 配置.getint("app", "retry", fallback=3)
```

## 环境变量覆盖

常见策略：

1. 默认值。
2. 配置文件。
3. 环境变量。
4. 命令行参数。

后面的优先级更高。

```python
未译87485 os

日志_level = os.environ.get("APP_LOG_LEVEL", 配置["app"].get("日志_level", "INFO"))
```

## .env 概念

`.env` 文件常用于本地开发环境变量。

标准库不直接读取 `.env`，常见第三方库是 `Python学习资料-dotenv`。本阶段先理解概念，不强制使用。

`.env` 不应该提交敏感真实值。

## 配置校验

读取配置后要校验：

```python
input_dir = Path(input_dir)
if not input_dir.exists():
    raise ValueError(f"输入目录不存在：{input_dir}")
```

## 常见错误

### 配置写死在代码里

输入输出路径、日志级别等应该可配置。

### 配置没有校验

路径不存在、数值非法会在更晚阶段报错。

### 把密钥提交到仓库

敏感配置用环境变量或本地未提交文件。
