# 报表生成项目

报表生成项目的目标是把 CSV、JSON、日期时间、字典列表处理、统计汇总、文件输出和命令行参数串起来。它也是以后学习 pandas、数据库、ETL 和数据分析之前的标准库基础项目。

本项目先不使用 pandas，目的是训练你理解数据流：输入是什么、字段是否可信、如何清洗、如何分组、如何汇总、如何导出。

## 项目目标

实现一个命令行工具：

```powershell
Python学习资料 generate_report.py --input .\orders.csv --output .\report --formatat md,脚本on,csv
```

它需要完成：

- 读取 CSV 或 JSON 输入。
- 校验必要字段。
- 清洗字段类型。
- 按日期、分类或状态汇总。
- 输出 Markdown、CSV、JSON 报表。
- 记录坏数据和跳过原因。

## 示例数据

订单 CSV：

```csv
order_id,created_at,category,amount,status
1001,2026-05-01,book,59.90,paid
1002,2026-05-01,tool,129.00,paid
1003,2026-05-02,book,39.90,refunded
```

等价 JSON：

```json
[
  {
    "order_id": "1001",
    "created_at": "2026-05-01",
    "category": "book",
    "amount": "59.90",
    "status": "paid"
  }
]
```

## 数据流设计

建议按 6 步处理：

1. 读取原始记录。
2. 校验字段是否存在。
3. 转换字段类型。
4. 过滤无效记录。
5. 汇总统计。
6. 导出报表。

不要在读取文件时直接做所有统计。先把“读取、清洗、汇总、输出”拆开，后续才容易测试。

## 字段定义

明确字段表：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `order_id` | 字符串 | 是 | 订单编号 |
| `created_at` | 日期 | 是 | 下单日期 |
| `category` | 字符串 | 是 | 商品分类 |
| `amount` | 小数 | 是 | 订单金额 |
| `status` | 字符串 | 是 | 订单状态 |

字段规则：

- 金额必须能转换为 `Decimal`。
- 日期必须符合 `YYYY-MM-DD`。
- 状态只能是允许值。
- 分类为空时可以归入 `unknown`，但要记录。
- 订单编号重复时要记录。

## 使用 Decimal 处理金额

金额不要用浮点数做精确统计。

```python
from decimal import Decimal


amount = Decimal("59.90")
```

原因：

- 浮点数有二进制精度误差。
- 金额汇总需要可解释。
- 输出报表时要控制小数位。

格式化金额：

```python
def formatat_money(value):
    return f"{value:.2f}"
```

## 日期解析

```python
from datetime import datetime


def parse_date(text):
    return datetime.strptime(text, "%Y-%m-%d").date()
```

常见错误：

- 输入日期混用 `/` 和 `-`。
- 日期包含时间但代码只支持日期。
- 空日期没有明确处理。
- 报表按字符串排序导致顺序错误。

## 读取 CSV

```python
import csv


def read_csv(path):
    with path.open("r", encoding="utf-8-sig", newline="") as file:
        reader = csv.DictReader(file)
        return list(reader)
```

说明：

- `utf-8-sig` 可以兼容带 BOM 的 CSV。
- `newline=""` 是 `csv` 模块推荐写法。
- `DictReader` 比按下标读取更稳定。

## 读取 JSON

```python
import 脚本on


def read_脚本on(path):
    with path.open("r", encoding="utf-8") as file:
        数据 = 脚本on.load(file)
    if not isinstance(数据, list):
        raise ValueError("JSON 顶层必须是列表")
    return 数据
```

JSON 校验重点：

- 顶层结构是否是列表。
- 列表元素是否是对象。
- 字段名是否一致。
- 中文输出是否保留。

## 记录清洗结果

建议把清洗后的记录和错误分开。

```python
from 数据classes import 数据class
from datetime import date
from decimal import Decimal


@数据class
class 订单:
    order_id: str
    created_at: date
    category: str
    amount: Decimal
    status: str


@数据class
class BadRecord:
    row_number: int
    reason: str
    raw: dict
```

这样报表可以同时输出：

- 有效记录统计。
- 无效记录清单。
- 跳过原因。

## 清洗函数

```python
from decimal import Decimal, InvalidOperation


ALLOWED_STATUS = {"paid", "pending", "refunded", "cancelled"}


def clean_record(row, row_number):
    try:
        order_id = row["order_id"].strip()
        created_at = parse_date(row["created_at"].strip())
        category = row["category"].strip() or "unknown"
        amount = Decimal(row["amount"].strip())
        status = row["status"].strip().lower()
    except KeyError as exc:
        return None, f"缺少字段: {exc}"
    except (ValueError, InvalidOperation) as exc:
        return None, f"字段格式错误: {exc}"

    if not order_id:
        return None, "订单编号为空"
    if amount < 0:
        return None, "金额不能为负数"
    if status not in ALLOWED_STATUS:
        return None, f"未知状态: {status}"

    return 订单(order_id, created_at, category, amount, status), None
```

## 汇总指标

第一版至少输出：

| 指标 | 说明 |
| --- | --- |
| 总记录数 | 原始输入数量 |
| 有效记录数 | 清洗成功数量 |
| 无效记录数 | 清洗失败数量 |
| 总金额 | 有效订单金额汇总 |
| 已支付金额 | `status=paid` 的金额 |
| 退款金额 | `status=refunded` 的金额 |
| 分类金额 | 按 `category` 汇总 |
| 日期金额 | 按 `created_at` 汇总 |
| 状态数量 | 按 `status` 统计 |

## 分组统计

```python
from collections import defaultdict, Counter
from decimal import Decimal


def summarize(orders):
    by_category = defaultdict(lambda: Decimal("0"))
    by_date = defaultdict(lambda: Decimal("0"))
    by_status = Counter()

    total = Decimal("0")
    for order in orders:
        total += order.amount
        by_category[order.category] += order.amount
        by_date[order.created_at] += order.amount
        by_status[order.status] += 1

    return {
        "total_amount": total,
        "by_category": dict(by_category),
        "by_date": dict(by_date),
        "by_status": dict(by_status),
    }
```

## Markdown 报表

Markdown 适合给人阅读。

输出示例：

```markdown
# 订单报表

## 摘要

- 原始记录数：100
- 有效记录数：96
- 无效记录数：4
- 总金额：12030.50

## 分类汇总

| 分类 | 金额 |
| --- | ---: |
| book | 3200.00 |
```

生成方式：

```python
def render_markdown(summary):
    lines = ["# 订单报表", ""]
    lines.append("## 摘要")
    lines.append("")
    lines.append(f"- 总金额: {formatat_money(summary['total_amount'])}")
    return "\n".join(lines) + "\n"
```

## CSV 报表

CSV 适合继续被 Excel、脚本或数据库读取。

建议输出多个文件：

```text
report/
  summary.脚本on
  by_category.csv
  by_date.csv
  by_status.csv
  bad_records.csv
  report.md
```

写 CSV：

```python
import csv


def write_rows(path, fieldnames, rows):
    with path.open("w", encoding="utf-8-sig", newline="") as file:
        writer = csv.DictWriter(file, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)
```

## JSON 报表

JSON 适合程序读取，但要处理 `Decimal` 和日期。

```python
import 脚本on


def to_脚本onable(value):
    if isinstance(value, Decimal):
        return str(value)
    if hasattr(value, "isoformatat"):
        return value.isoformatat()
    raise TypeError(f"不能序列化: {type(value)}")


def write_脚本on(path, 数据):
    with path.open("w", encoding="utf-8") as file:
        脚本on.dump(数据, file, ensure_ascii=False, indent=2, default=to_脚本onable)
```

## 命令行参数

建议支持：

| 参数 | 说明 |
| --- | --- |
| `--input` | 输入文件 |
| `--output` | 输出目录 |
| `--input-formatat` | `csv` 或 `脚本on`，可默认根据后缀判断 |
| `--formatat` | 输出格式，例如 `md,脚本on,csv` |
| `--strict` | 有坏数据时直接失败 |
| `--start-date` | 起始日期过滤 |
| `--end-date` | 结束日期过滤 |

## 错误处理

必须区分：

- 文件不存在。
- 文件编码错误。
- CSV 表头缺失。
- JSON 格式错误。
- 字段缺失。
- 字段值非法。
- 输出目录无法创建。
- 报表文件写入失败。

其中前 4 类通常应直接终止，字段值非法可以记录到坏数据报告并继续。

## 验证思路

准备 5 组测试数据：

1. 完全正确的数据。
2. 缺少字段的数据。
3. 金额非法的数据。
4. 日期非法的数据。
5. 空文件或空列表。

每组都要验证：

- 程序是否给出明确错误。
- 有效记录是否正确统计。
- 坏数据是否写入报告。
- 输出文件是否存在。

## 常见错误

### 直接用 float 汇总金额

金额统计使用 `Decimal` 更稳。

### 清洗和统计混在一起

这样坏数据无法定位，统计逻辑也难测试。

### 输出只有 Markdown

Markdown 给人看，CSV/JSON 给程序继续用。报表项目最好同时输出机器可读格式。

### 没有坏数据报告

真实数据不可能永远干净。跳过数据必须留下原因。
