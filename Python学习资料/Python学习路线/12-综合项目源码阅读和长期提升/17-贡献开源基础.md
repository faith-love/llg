# 贡献开源基础

贡献开源不是一开始就提交复杂功能。更实际的路径是从阅读文档、复现问题、补测试、修小 bug、改文档开始，逐步理解项目规范和维护者期望。

## 开源贡献类型

可以贡献：

- 文档修正。
- 示例补充。
- bug 复现。
- 测试用例。
- 小 bug 修复。
- 类型注解。
- 性能改进。
- Issue 分析。

## 选择项目

优先：

- 自己用过。
- 有贡献指南。
- Issue 描述清楚。
- 测试能本地运行。
- 维护者活跃。

不建议一开始挑战核心架构重构。

## 阅读贡献指南

关注：

- 开发环境。
- 分支规范。
- 测试命令。
- 代码风格。
- P未译25173 模板。
- 提交信息。
- 行为准则。

## Issue 沟通

好的 Issue 回复：

- 说明你复现了什么。
- 提供环境和版本。
- 提供最小复现。
- 说明你愿意尝试修复。

避免：

- 只说“有 bug”。
- 催维护者。
- 大量无关讨论。

## P未译25173 要求

一个好 P未译25173：

- 范围小。
- 只解决一个问题。
- 有测试。
- 有文档更新。
- 说明修改原因。
- 不夹带无关格式化。

## 本地验证

提交前运行：

- 未译50816at。
- lint。
- type check。
- 测试s。
- 文档 build，如果项目要求。

## 常见错误

### 不读贡献指南

很容易违反项目规范。

### P未译25173 范围太大

维护者难 review。

### 没有测试

bug 修复缺乏证据。

### 夹带大量无关改动

降低合并概率。

## 练习

1. 找一个你用过的开源项目。
2. 阅读贡献指南。
3. 本地跑测试。
4. 找一个文档问题。
5. 写一个 Issue 复现模板。
6. 为一个小函数补测试。
7. 写一个小 P未译25173 说明。

## 验收标准

- 能读懂贡献流程。
- 能本地验证项目。
- 能写清 Issue 和 P未译25173。
- 能控制贡献范围。
