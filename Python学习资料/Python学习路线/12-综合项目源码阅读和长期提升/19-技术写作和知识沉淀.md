# 技术写作和知识沉淀

技术写作用于把经验变成可复用资产。你写下来的内容越清晰，未来越容易复用、迁移和讲解。

## 写作类型

常见：

- 学习笔记。
- 项目复盘。
- 源码阅读笔记。
- 故障报告。
- ADR。
- 教程。
- API 文档。
- 面试讲稿。

## 学习笔记结构

```markdown
# 主题

## 要解决的问题

## 核心概念

## 示例

## 常见错误

## 练习

## 复盘
```

## 项目复盘结构

```markdown
# 项目复盘

## 背景

## 做了什么

## 遇到的问题

## 解决方案

## 取舍

## 结果

## 下次改进
```

## ADR

ADR 是架构决策记录。

结构：

```markdown
# ADR: 选择 FastAPI 作为 API 框架

## 状态

## 背景

## 决策

## 影响

## 替代方案
```

## 故障报告

结构：

- 时间线。
- 影响范围。
- 根因。
- 处理过程。
- 修复措施。
- 预防措施。

## 写作原则

- 写具体问题。
- 写上下文。
- 写证据。
- 写取舍。
- 写可复现命令。
- 写下一步。

## 常见错误

### 只摘抄概念

没有自己的例子和复盘。

### 不写失败过程

失败是最有价值的经验。

### 文章没有结论

读者不知道该怎么用。

### 不更新旧文档

过期文档会误导。

## 练习

1. 写一篇项目复盘。
2. 写一篇源码阅读笔记。
3. 写一个 ADR。
4. 写一份故障报告模板。
5. 把一个知识点写成教程。
6. 更新一个过期 说明。
7. 建立个人知识目录。

## 验收标准

- 能写结构化技术文档。
- 能记录证据、取舍和复盘。
- 能把项目经验沉淀为可复用知识。
