# 阶段目标

第 12 阶段是整条 Python 学习路线的收束阶段。目标不是继续增加零散知识点，而是把前面阶段形成的能力整合成项目、文档、源码理解、复盘能力和长期学习系统。

完成本阶段后，你应该能拿出项目证明自己会写、会测、会调、会部署、会解释取舍，并能持续跟进 Python 生态变化。

## 本阶段要解决的问题

你需要能回答：

- 我能拿出哪些项目证明 Python 能力？
- 每个项目解决什么真实问题？
- 项目如何安装、运行、测试和部署？
- 项目里体现了哪些 Python 核心能力？
- 我如何解释架构取舍？
- 我如何证明项目质量？
- 我读过哪些源码，学到了什么设计？
- 我如何参与代码评审或开源贡献？
- 面试时如何讲清项目难点和复盘？
- 接下来一年如何持续提升？

## 能力地图

| 能力 | 说明 | 产出 |
| --- | --- | --- |
| 综合项目 | 把语法、工程、测试、部署串起来 | 可演示项目 |
| 文档能力 | 需求、方案、说明、复盘 | 项目文档集 |
| 质量能力 | 测试、CI、覆盖率、安全检查 | 质量报告 |
| 源码阅读 | 读标准库和第三方库 | 源码笔记 |
| 协作能力 | review、Issue、PR、沟通 | 评审记录 |
| 表达能力 | 简历、面试、项目讲解 | 项目讲稿 |
| 长期提升 | 周计划、月复盘、技术雷达 | 学习系统 |

## 推荐时间安排

第 1-2 周：

- 选择综合项目。
- 写需求文档。
- 写技术方案。
- 拆任务。
- 搭项目骨架。

第 3-6 周：

- 完成核心功能。
- 加测试和日志。
- 加配置和部署。
- 写 说明 和演示材料。

第 7-8 周：

- 性能和安全加固。
- 写质量报告。
- 部署或Docker化。
- 做项目复盘。

长期：

- 源码阅读。
- 开源贡献。
- 代码评审。
- 面试复盘。
- 技术雷达更新。

## 必须完成的事情

至少完成：

- 3 个综合项目。
- 3 份项目 说明。
- 3 份项目复盘。
- 1 份源码阅读笔记。
- 1 份代码评审记录。
- 1 份项目面试讲解稿。
- 1 份年度学习路线。

## 项目完成标准

一个项目只有同时满足以下条件，才算阶段项目：

- 能一条命令安装或启动。
- 说明 能让别人运行起来。
- 有明确输入和输出。
- 有测试。
- 有错误处理。
- 有日志或报告。
- 有配置说明。
- 有质量检查命令。
- 有已知问题和后续计划。

## 难点

### 难点 1：从知识点转向作品

知识点练习只证明你会局部技能，综合项目证明你能交付完整结果。

### 难点 2：文档和代码同步

说明、Swagger、运行命令、配置说明必须和代码一致。文档过期会直接降低项目可信度。

### 难点 3：讲清取舍

面试和评审最看重的不是“用了什么技术”，而是“为什么这样选，放弃了什么，风险是什么”。

### 难点 4：持续维护

项目不是写完就结束。依赖升级、bug 修复、版本记录、复盘才是长期能力。

## 验收口径

通过本阶段需要满足：

- 项目能运行。
- 项目能测试。
- 项目能解释。
- 项目能部署或Docker化。
- 源码阅读有笔记。
- 面试表达有结构。
- 长期学习有计划。

## 记录要求

每个项目保留：

- 项目背景。
- 需求范围。
- 技术方案。
- 任务拆分。
- 运行命令。
- 测试结果。
- 演示截图或示例。
- 问题记录。
- 复盘。
