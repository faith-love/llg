# 测试验收和质量报告

质量报告用于证明项目不是“碰巧能跑”，而是经过系统验证。它应该覆盖功能、错误路径、性能、安全和已知风险。

## 测试矩阵

示例：

| 类型 | 覆盖内容 |
| --- | --- |
| JUnit | 函数和 服务 |
| 集成测试 | 数据库、文件、外部接口替身 |
| API 测试 | 路由、状态码、响应 |
| CLI 测试 | 命令参数、输出文件 |
| 错误测试 | 参数错误、权限错误、文件缺失 |
| 性能测试 | 大输入、耗时、内存 |
| 安全测试 | 路径穿越、认证失败、注入 |

## 覆盖率

覆盖率报告要说明：

- 总覆盖率。
- 核心模块覆盖率。
- 未覆盖原因。
- 不追求覆盖的文件。

不要只贴数字。

## 验收用例

每个核心功能都要有：

- 输入。
- 操作。
- 预期结果。
- 实际结果。
- 是否通过。

## 质量报告结构

```markdown
# 质量报告

## 测试环境

## 测试范围

## 测试结果

## 覆盖率

## 性能结果

## 安全检查

## 已知问题

## 结论
```

## 性能结果

记录：

- 输入规模。
- 耗时。
- 内存峰值。
- 优化前后对比。

## 安全检查

记录：

- 输入校验。
- 权限。
- 密钥。
- 文件路径。
- 依赖。
- CO未译25173S。

## 常见错误

### 只测正常路径

错误路径更能体现质量。

### 覆盖率没有解释

数字不能说明测试质量。

### 不记录测试环境

结果不可复现。

### 已知问题不写

别人会以为你没发现。

## 练习

1. 写测试矩阵。
2. 列出核心验收用例。
3. 生成覆盖率报告。
4. 写性能测试结果。
5. 写安全检查结果。
6. 写已知问题。
7. 写质量结论。

## 验收标准

- 有测试矩阵。
- 有覆盖率和解释。
- 有性能和安全结果。
- 有已知问题和结论。
