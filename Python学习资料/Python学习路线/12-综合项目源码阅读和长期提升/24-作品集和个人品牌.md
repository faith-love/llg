# 作品集和个人品牌

作品集的目标是让别人快速判断你的能力。它不是堆项目链接，而是展示你能解决什么问题、如何设计、如何验证、如何复盘。

## 作品集内容

至少包含：

- 3 个代表项目。
- 每个项目一句话说明。
- 技术栈。
- 运行方式。
- 演示材料。
- 测试和质量说明。
- 复盘链接。

## GitHub 项目整理

要求：

- 说明 完整。
- 目录清晰。
- 有 license。
- 有 测试s。
- 有 CI 更好。
- 有 release 或 tag 更好。
- 不包含密钥和个人隐私。

## 项目展示页

可以做：

- Markdown 索引。
- GitHub profile 说明。
- 简单文档站。
- 项目合集 说明。

## 演示视频

短视频结构：

1. 项目解决什么问题。
2. 如何运行。
3. 核心功能演示。
4. 技术亮点。
5. 质量和测试。

控制在 3-5 分钟。

## 案例文章

每个项目可以写一篇：

- 为什么做。
- 怎么设计。
- 遇到什么问题。
- 如何解决。
- 学到什么。

## 常见错误

### 项目不能运行

作品集可信度大幅下降。

### 说明 空泛

只写“这是一个 Python 项目”没有价值。

### 暴露密钥或真实数据

严重风险。

### 只展示功能不展示质量

测试、文档、部署同样重要。

## 练习

1. 选择 3 个代表项目。
2. 给每个项目写一句话定位。
3. 补齐 说明。
4. 增加运行示例。
5. 增加测试徽章或测试说明。
6. 写项目合集 说明。
7. 录制 3 分钟项目演示。

## 验收标准

- 作品集项目能运行。
- 说明 清晰。
- 有测试和质量说明。
- 能快速展示能力方向。
