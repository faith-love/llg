# 技术雷达和版本跟进

Python 生态持续变化。你不需要追每个热点，但需要有机制跟进版本、工具、弃用、迁移和安全公告。

## 技术雷达

可以分四类：

- Adopt：当前采用。
- Trial：小范围试用。
- Assess：观察评估。
- Hold：暂缓或避免。

## 跟进内容

关注：

- Python 新版本。
- 标准库变化。
- 类型系统变化。
- 包管理工具。
- Web 框架版本。
- 数据库和 ORM。
- 安全公告。
- 弃用通知。

## Python 版本

每次新版本发布，关注：

- 新语法。
- 性能变化。
- 标准库新增。
- 弃用和移除。
- 兼容性风险。

不要盲目升级生产项目，先测试依赖兼容。

## 工具升级

工具包括：

- ruff。
- mypy/pyright。
- py测试。
- FastAPI。
- SQLAlchemy。
- pandas。

升级步骤：

1. 看 change日志。
2. 小版本升级。
3. 跑测试。
4. 修复警告。
5. 记录变更。

## 弃用管理

看到 deprecation 网页归档ning 不要忽略。

处理：

- 记录来源。
- 查迁移方案。
- 加测试。
- 小步修改。

## 安全公告

关注：

- 依赖漏洞。
- 框架安全更新。
- Docker基础镜像漏洞。
- 密钥泄露事件。

## 常见错误

### 盲目追新

项目稳定性下降。

### 长期不升级

安全和兼容风险积累。

### 忽略弃用警告

未来升级成本更高。

### 没有技术取舍记录

为什么采用或放弃某工具说不清。

## 练习

1. 建一个技术雷达表。
2. 列出当前 Adopt 工具。
3. 列出 3 个 Trial 工具。
4. 跟进一次 Python 新版本变化。
5. 跟进一个依赖 change日志。
6. 处理一个 deprecation 网页归档ning。
7. 写一次工具升级记录。

## 验收标准

- 能维护技术雷达。
- 能有节奏地跟进版本变化。
- 能处理弃用和安全公告。
- 能记录技术采用取舍。
