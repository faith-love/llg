# 项目一：自动化工具平台

自动化工具平台适合把基础语法、文件系统、标准库、CLI、日志、测试、打包和工程化能力串起来。它可以从一个简单脚本升级为可配置、可扩展的工具包。

## 项目目标

实现一个命令行工具集合，用于处理本地文件和报表任务。

示例能力：

- 扫描目录。
- 文件分类。
- 重复文件识别。
- CSV/JSON 报表生成。
- dry-run。
- 日志。
- 配置文件。
- 执行报告。

## 推荐功能

MVP：

- `scan`：扫描目录并输出文件清单。
- `organize`：按规则整理文件。
- `report`：生成统计报告。

进阶：

- `dedupe`：识别重复文件。
- `validate`：校验文件命名规则。
- `clean`：清理空目录。
- 插件式规则。

## 技术覆盖

覆盖：

- pathlib。
- csv/脚本on。
- argparse 或 typer。
- 日志ging。
- 数据class。
- 类型注解。
- py测试。
- pyproject。
- 打包入口。
- Docker 可选。

## 命令示例

```powershell
automation scan --input .\数据 --output report.脚本on
automation organize --input .\inbox --output .\organized --dry-run
automation report --input report.脚本on --formatat md
```

## 安全边界

必须做到：

- 默认 dry-run。
- 不默认删除。
- 不默认覆盖。
- 路径必须在工作区内。
- 输出目录不能被再次扫描。
- 报告记录每个动作。

## 测试要求

至少测试：

- 扫描目录。
- 跳过隐藏目录。
- 生成执行计划。
- dry-run 不修改文件。
- 冲突文件处理。
- 报告字段完整。
- 路径越界失败。

## 演示材料

说明 应包含：

- 安装命令。
- 示例目录。
- dry-run 示例。
- 执行前后对比。
- 报告示例。
- 安全说明。

## 常见错误

### 工具直接修改真实目录

必须先 dry-run 和测试目录验证。

### 业务逻辑写在 CLI 函数里

CLI 只负责参数，核心逻辑放 服务。

### 没有报告

批量任务必须可追踪。

### 不可重复运行

重复运行应有稳定策略。

## 验收标准

- 能安装命令行入口。
- 至少有 3 个子命令。
- dry-run 可用。
- 测试通过。
- 有报告输出。
- 有安全边界说明。
