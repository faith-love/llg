# JSON接口设计基础

JSON 是 Web API 最常见的数据交换格式。好的 JSON 接口不只是能序列化，还要字段清晰、结构稳定、错误一致、便于版本演进。

## JSON 基本类型

JSON 支持：

- object。
- array。
- string。
- number。
- boolean。
- null。

不直接支持：

- Python `datetime`。
- Python `Decimal`。
- Python `set`。
- 二进制文件。

这些需要转换成字符串、数字或结构化对象。

## 请求体设计

创建图书：

```json
{
  "title": "Python 入门",
  "price": 59.9,
  "tags": ["Python学习资料", "beginner"]
}
```

原则：

- 字段命名稳定。
- 必填和选填明确。
- 类型明确。
- 不传服务端生成字段，例如 `id`、`created_at`。

## 响应体设计

```json
{
  "id": 100,
  "title": "Python 入门",
  "price": "59.90",
  "created_at": "2026-05-11T10:00:00+08:00"
}
```

注意：

- 金额可用字符串避免精度争议。
- 时间使用明确格式。
- 字段不要随请求不同随意消失。

## 列表响应

不要只返回数组，分页时需要元信息。

```json
{
  "items": [],
  "分页": 1,
  "分页_size": 20,
  "total": 100
}
```

## 错误响应

统一结构：

```json
{
  "未译12785": {
    "code": "BOOK_NOT_FOUND",
    "未译52031": "图书不存在",
    "details": {
      "book_id": 100
    }
  }
}
```

字段说明：

- `code`：机器可读。
- `未译52031`：人类可读。
- `details`：可选上下文。

## 字段命名

常见风格：

- snake_case：`created_at`。
- camelCase：`createdAt`。

Python 后端常用 snake_case，但要根据团队规范固定，不能混用。

## null 和缺失

`null` 表示字段存在但无值。

缺失表示没有这个字段。

API 文档必须说明二者含义。

## 向后兼容

较安全的变更：

- 增加可选字段。
- 增加新的接口。
- 增加新的错误 code。

高风险变更：

- 删除字段。
- 改字段类型。
- 改字段含义。
- 改错误结构。

## 常见错误

### 响应有时是对象有时是数组

同一个接口响应结构必须稳定。

### 错误只返回字符串

调用方无法根据机器码处理。

### 日期格式混乱

同一系统内统一使用 ISO 8601 风格字符串。

### 金额用浮点随意计算

涉及金额要认真处理精度和格式。
