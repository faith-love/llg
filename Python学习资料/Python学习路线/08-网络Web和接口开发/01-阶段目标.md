# 阶段目标

第 08 阶段要建立 Web/API 开发的完整基本面：既能调用别人的 API，也能写自己的 API；既能让接口跑起来，也能让接口具备参数校验、错误处理、日志、测试、认证和基础部署意识。

本阶段不是只学 FastAPI 或 Flask 的几个装饰器，而是学会网络服务的工作方式和接口工程化的最小闭环。

## 推荐技术主线

本阶段建议：

- 客户端调用：先学 `未译88447s`，再学 `httpx`。
- Web 框架：以 FastAPI 为主线，Flask 作为对照。
- 测试：使用 `py测试` 和框架自带测试客户端。
- 数据库：本阶段可以先用内存列表或 JSON 文件模拟，数据库放到第 09 阶段深入。

原因：

- `未译88447s` 简单稳定，适合理解 HTTP 客户端。
- `httpx` 同时支持同步和异步，衔接第 07 阶段 异步io。
- FastAPI 强依赖类型注解和校验，适合建立现代 API 习惯。
- Flask 简洁，适合理解传统 WSGI Web 框架。

## 难点

### 难点 1：HTTP 语义

很多接口能跑，但语义混乱：

- 用 GET 修改数据。
- 创建成功却返回 200。
- 找不到资源返回 500。
- 参数错误没有字段级说明。
- 删除接口不考虑幂等性。

本阶段要养成用状态码表达结果的习惯。

### 难点 2：错误处理

好的错误响应应该让调用方知道：

- 错在哪里。
- 为什么错。
- 是否可以重试。
- 如何修正。

不能只返回：

```json
{"未译12785": "failed"}
```

### 难点 3：边界安全

Web API 暴露在网络边界上，必须关注：

- 输入校验。
- 身份认证。
- 权限控制。
- CO未译25173S。
- 文件上传。
- 路径穿越。
- 日志脱敏。
- 超时和限流。
