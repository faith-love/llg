# 配置环境和密钥管理

Web 应用通常需要不同环境配置：本地开发、测试、预发布、生产。配置管理做不好，会导致密钥泄露、环境混乱、生产误连测试服务。

## 配置类型

常见配置：

- 服务端口。
- 日志级别。
- 数据库地址。
- 外部 API 地址。
- API Key。
- JWT 密钥。
- CO未译25173S 来源。
- 文件上传目录。

## 配置来源

优先级建议：

1. 命令行参数。
2. 环境变量。
3. `.env` 文件。
4. 默认值。

生产环境通常使用环境变量或密钥管理系统。

## .env 文件

`.env` 适合本地开发。

示例：

```text
APP_ENV=dev
LOG_LEVEL=INFO
API_KEY=dev-key
```

注意：

- 不提交真实密钥。
- 提交 `.env.example`。
- `忽略规则` 排除 `.env`。

## 敏感信息

敏感信息包括：

- 密码。
- token。
- API Key。
- Cookie。
- 私钥。
- JDBC串。

要求：

- 不写进代码。
- 不写进文档示例真实值。
- 不写进日志。
- 不提交到版本库。

## 环境隔离

不同环境：

- dev。
- 测试。
- staging。
- prod。

每个环境应有独立配置。生产环境不能使用测试密钥和测试数据库。

## 常见错误

### 把密钥写进 说明

示例应使用占位符。

### 默认使用生产地址

本地误操作生产数据风险很高。

### 日志打印完整配置

配置里可能有密钥。

### .env 被提交

应该提交 `.env.example`，不提交真实 `.env`。

## 练习

1. 从环境变量读取 API_KEY。
2. 缺少 API_KEY 时启动失败。
3. 创建 `.env.example`。
4. 写 settings.py。
5. 按 dev/测试/prod 区分配置。
6. 写一个配置脱敏打印函数。
7. 检查项目中是否硬编码 token。
8. 写配置加载测试。

## 验收标准

- 能集中管理配置。
- 能从环境变量读取敏感配置。
- 能避免密钥进入代码、日志和文档。
- 能区分不同环境配置。
