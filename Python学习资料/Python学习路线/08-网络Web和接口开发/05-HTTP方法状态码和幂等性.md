# HTTP方法状态码和幂等性

HTTP 方法和状态码是 API 语义的基础。接口能跑不代表设计正确，调用方需要通过方法和状态码理解接口行为。

## 常见 HTTP 方法

| 方法 | 常见用途 | 是否安全 | 是否幂等 |
| --- | --- | --- | --- |
| GET | 查询资源 | 是 | 是 |
| POST | 创建资源、提交动作 | 否 | 通常否 |
| PUT | 整体替换资源 | 否 | 是 |
| PATCH | 局部更新资源 | 否 | 通常不保证 |
| DELETE | 删除资源 | 否 | 通常设计为幂等 |

安全是指不会修改服务端资源。

幂等是指同一个请求执行一次和执行多次，最终效果一致。

## GET

用于读取资源：

```text
GET /books
GET /books/100
```

不要用 GET 修改数据。

## POST

用于创建资源或提交动作：

```text
POST /books
POST /orders/100/cancel
```

创建成功常用 `201 Created`。

## PUT

用于整体替换：

```text
PUT /books/100
```

客户端通常提交完整资源表示。

## PATCH

用于局部更新：

```text
PATCH /books/100
```

只提交需要变更的字段。

## DELETE

用于删除：

```text
DELETE /books/100
```

删除成功可以返回：

- `204 No Content`。
- `200 OK` 加删除结果。

## 常见状态码

成功：

- `200 OK`：请求成功。
- `201 Created`：资源创建成功。
- `204 No Content`：成功但无响应体。

客户端错误：

- `400 Bad Request`：请求格式错误。
- `401 Unauthorized`：未认证。
- `403 Forbidden`：无权限。
- `404 Not Found`：资源不存在。
- `409 Conflict`：资源冲突。
- `422 Unprocessable Entity`：语义校验失败。
- `429 Too Many Requests`：请求过多。

服务端错误：

- `500 Internal 服务端 Error`：服务端未知错误。
- `502 Bad Gateway`：网关收到错误响应。
- `503 Service Unavailable`：服务不可用。
- `504 Gateway Timeout`：网关超时。

## 幂等性设计

幂等接口更容易重试。

例如删除：

```text
DELETE /books/100
```

如果第一次删除成功，第二次再删除可以返回 404，也可以返回 204，取决于接口约定。关键是文档要明确。

创建资源时如果需要安全重试，可以引入幂等键：

```text
Idempotency-Key: request-123
```

## 常见错误

### 用 POST 做所有事情

会丢失 HTTP 语义，让缓存、重试、文档都变差。

### 用 GET 删除资源

严重错误。GET 可能被缓存、预取或爬虫触发。

### 参数错误返回 500

参数错误是客户端错误，应该返回 400 或 422。

### 不考虑重试

网络失败时，调用方可能重试。非幂等接口要有防重复策略。
