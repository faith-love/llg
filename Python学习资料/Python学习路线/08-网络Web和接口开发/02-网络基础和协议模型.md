# 网络基础和协议模型

Web API 的底层是网络通信。你不需要一开始就深入所有协议细节，但必须理解客户端如何找到服务端、如何建立连接、如何发送请求，以及哪些环节可能失败。

## 客户端和服务端

客户端负责发起请求：

- 浏览器。
- 手机 App。
- Python 脚本。
- 另一个后端服务。
- 命令行工具。

服务端负责监听端口、接收请求、处理业务并返回响应。

```text
客户端 -> network -> 服务端 -> network -> 客户端
```

## IP 地址

IP 地址用于定位网络中的主机。

常见：

- `127.0.0.1`：本机回环地址。
- `localhost`：通常解析到本机。
- 内网 IP：局域网内访问。
- 公网 IP：互联网访问。

学习阶段常见服务地址：

```text
http://127.0.0.1:8000
http://localhost:5000
```

## 端口

端口用于区分同一台机器上的不同服务。

例如：

- `8000`：常见本地开发端口。
- `5000`：Flask 常见开发端口。
- `80`：HTTP 默认端口。
- `443`：HTTPS 默认端口。

如果端口被占用，服务启动会失败。

## DNS

DNS 用于把域名解析成 IP。

```text
接口.example.通用 -> 203.0.113.10
```

API 调用失败可能发生在 DNS 阶段：

- 域名写错。
- DNS 解析失败。
- 网络环境无法访问。
- 代理配置错误。

## TCP

HTTP 通常运行在 TCP 连接之上。TCP 提供可靠传输。

你需要知道：

- 建立连接需要时间。
- 连接可能超时。
- 连接可能被重置。
- 长连接可以复用。
- 连接数过多会占用资源。

HTTP 客户端的 Session 或 Client 通常能复用连接。

## TLS 和 HTTPS

HTTPS 是 HTTP 加 TLS。

TLS 提供：

- 加密。
- 完整性校验。
- 服务端身份验证。

调用 HTTPS API 时可能出现：

- 证书过期。
- 证书域名不匹配。
- 本地证书链问题。
- 代理拦截证书。

不要为了省事长期关闭证书验证。

## 请求链路

一个 API 请求大致经过：

1. 解析 U未译25173L。
2. DNS 解析域名。
3. 建立 TCP 连接。
4. TLS 握手。
5. 发送 HTTP 请求。
6. 服务端处理。
7. 返回 HTTP 响应。
8. 客户端读取响应体。
9. 客户端解析 JSON。

任何一步都可能失败。

## 本地开发地址

常见差异：

| 地址 | 含义 |
| --- | --- |
| `127.0.0.1` | 本机 IPv4 |
| `localhost` | 本机域名 |
| `0.0.0.0` | 服务监听所有网卡，不能作为浏览器目标语义使用 |

开发服务器监听 `0.0.0.0:8000`，通常表示局域网其他机器也可能访问。

## 常见错误

### 把 0.0.0.0 当访问地址

服务可以监听 `0.0.0.0`，但浏览器通常访问 `127.0.0.1` 或实际 IP。

### 端口被占用

需要换端口或停止占用进程。

### 只看到请求失败，不区分阶段

要区分 DNS、连接、TLS、HTTP 状态码、JSON 解析错误。

### 在生产环境使用开发服务器

框架自带开发服务器不等于生产部署方案。

## 练习

1. 解释 `localhost` 和 `127.0.0.1`。
2. 启动一个本地 Web 服务并访问端口。
3. 故意访问错误端口，观察错误。
4. 故意访问不存在域名，观察 DNS 错误。
5. 解释 HTTP 和 HTTPS 的区别。
6. 画出一次 API 请求的链路。
7. 记录一次请求可能失败的 8 个位置。

## 验收标准

- 能解释客户端、服务端、IP、端口、DNS、TCP、TLS。
- 能区分本地监听地址和访问地址。
- 能按链路定位网络请求失败位置。
