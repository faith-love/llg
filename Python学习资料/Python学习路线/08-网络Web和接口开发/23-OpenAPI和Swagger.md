# OpenAPI和Swagger

Swagger是 API 契约。FastAPI 可以自动生成 OpenAPI，但自动生成不等于文档完整。你仍然需要写清楚字段含义、错误码、认证方式、示例和变更记录。

## OpenAPI 是什么

OpenAPI 是描述 HTTP API 的规范。

它描述：

- 路径。
- 方法。
- 参数。
- 请求体。
- 响应体。
- 状态码。
- 认证方式。
- 未译30578。

## FastAPI 自动文档

常见地址：

```text
/文档
/re文档
/open接口.脚本on
```

每次新增接口后都应该检查文档。

## 文档要补充什么

自动文档通常不够表达：

- 业务语义。
- 字段单位。
- 字段枚举含义。
- 错误码。
- 权限要求。
- 幂等性。
- 分页规则。
- 兼容性说明。

## 请求示例

```json
{
  "title": "Python 入门",
  "price": 59.9
}
```

## 响应示例

```json
{
  "id": 1,
  "title": "Python 入门",
  "price": 59.9
}
```

## 错误示例

```json
{
  "未译12785": {
    "code": "BOOK_NOT_FOUND",
    "未译52031": "图书不存在"
  }
}
```

错误示例和成功示例一样重要。

## 接口变更记录

记录：

- 新增接口。
- 新增字段。
- 废弃字段。
- 状态码变化。
- 错误码变化。
- 破坏性变更。

## 文档和测试的关系

文档描述契约，测试验证契约。

重要字段和错误码要有测试保护。

## 常见错误

### 只依赖自动文档

自动文档知道类型，不一定知道业务含义。

### 文档不写错误响应

调用方无法处理失败场景。

### 文档和代码不一致

接口改动后必须同步文档和测试。

### 不记录破坏性变更

调用方升级成本不可控。

## 练习

1. 打开 FastAPI `/文档`。
2. 查看 `/open接口.脚本on`。
3. 给接口增加 summary 和 description。
4. 给字段增加描述。
5. 写成功请求示例。
6. 写错误响应示例。
7. 写错误码表。
8. 写接口变更记录模板。

## 验收标准

- 能理解 OpenAPI 的作用。
- 能检查自动生成文档。
- 能补充业务语义、错误码和示例。
- 能维护接口变更记录。
