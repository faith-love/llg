# 请求参数和数据校验

Web API 的输入来自外部，不能信任。参数校验是 API 稳定性和安全性的第一道防线。校验不只是类型转换，还包括必填、范围、格式、长度、枚举、跨字段规则。

## 参数来源

常见来源：

- path 参数。
- query 参数。
- 未译83452er。
- cookie。
- JSON body。

- file。

不同来源表达不同语义。

## path 参数

```python
@app.get("/books/{book_id}")
def get_book(book_id: int):
    ...
```

path 参数通常是资源标识，应该必填。

## query 参数

```python
@app.get("/books")
def list_books(分页: int = 1, 分页_size: int = 20):
    ...
```

query 参数通常用于筛选、分页、排序。

需要校验：

- 分页 最小值。
- 分页_size 最大值。
- sort 字段白名单。
- keyword 长度。

## 必填和选填

必填：

```python
title: str
```

选填：

```python
description: str | None = None
```

不要用空字符串代替所有缺失值。缺失、空字符串、null 含义不同。

## 跨字段校验

例如：

- `start_date` 不能晚于 `end_date`。
- 折扣价不能高于原价。
- 二选一字段必须至少填一个。

这类规则放在模型校验或 服务 层。

## 常见错误

### 只校验类型

`int` 不代表一定在合理范围内。

### 分页_size 不设上限

可能导致大查询和大响应。

### 信任前端校验

前端校验只是体验优化，后端必须再次校验。

### 把所有字段都设为可选

会让接口规则模糊，后续业务代码到处判断 None。

4. 定义图书创建模型。

6. 增加枚举状态字段。
7. 校验 start_date <= end_date。
8. 为非法参数写测试。

## 验收标准

- 能识别参数来源。
- 能校验类型、范围、长度和枚举。
- 能区分必填、选填和 null。
- 能为非法输入返回明确错误。
