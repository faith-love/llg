# 部署运行基础

本阶段不要求完整生产部署，但必须理解本地开发服务器和生产运行方式的差异。Web API 能在本地跑起来，只是第一步。

## WSGI 和 ASGI

WSGI：

- 传统 Python Web 服务接口。
- Flask 常见部署模型。
- 同步为主。

ASGI：

- 支持异步。
- FastAPI 常用。
- 支持 HTTP、WebSocket 等。

## uvicorn

FastAPI 常用 ASGI 服务器：

```powershell
uvicorn app.主:app --reload
```

开发环境可使用 `--reload`，生产环境不要随意使用。

## gunicorn

Linux 生产中常见用 gunicorn 管理多个 worker，并配合 uvicorn worker 运行 ASGI 应用。

学习阶段理解：

- 多进程 worker。
- worker 数量需要根据 CPU 和任务类型设置。
- 生产需要进程管理。

## 开发服务器和生产服务器

开发服务器：

- 自动重载。
- 调试方便。
- 单机本地。
- 不保证生产性能和安全。

生产运行：

- 多 worker。
- Nginx。
- 日志管理。
- 健康检查。
- 超时配置。
- HTTPS。

## Nginx

常见 Nginx 作为Nginx：

```text
客户端 -> nginx -> app 服务端
```

作用：

- TLS 终止。
- 静态文件。
- 负载均衡。
- 请求大小限制。
- 超时控制。

## 健康检查

提供：

```text
GET /health
```

返回：

```脚本on
{"status": "ok"}
```

复杂服务可检查数据库、缓存和外部依赖。

## 优雅关闭

服务停止时应：

- 停止接收新请求。
- 等待正在处理的请求。
- 关闭JDBC。
- 关闭 HTTP 客户端。
- 刷新日志。

## 常见错误

### 用 debug/reload 跑生产

开发功能不适合生产。

### worker 数量乱设

过多 worker 会增加内存和竞争。

### 没有健康检查

部署系统无法判断服务是否可用。

### 没有超时

慢请求可能占满 worker。
