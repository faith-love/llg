# 认证授权基础

认证和授权是 API 安全的核心。认证回答“你是谁”，授权回答“你能做什么”。很多系统出问题不是因为没有登录，而是登录后没有做权限判断。

## 认证

认证用于确认调用方身份。

常见方式：

- Basic Auth。
- API Key。
- Bearer Token。
- Session Cookie。
- OAuth2。
- JWT。

学习阶段重点掌握 API Key 和 Bearer Token 概念。

## 授权

授权用于判断已认证用户是否有权限。

例子：

- 普通用户只能看自己的订单。
- 管理员可以删除图书。
- 审核员只能审核，不能删除。

授权必须在服务端做，不能只靠前端隐藏按钮。

## 401 和 403

`401 Unauthorized`：

- 未登录。
- token 缺失。
- token 无效。

`403 Forbidden`：

- 已认证。
- 但没有权限。

## API Key

简单形式：

```http
X-API-Key: key-value
```

适合：

- 服务间调用。
- 内部工具。
- 简单脚本。

注意：

- API Key 仍然是敏感信息。
- 要支持吊销。
- 要限制权限和用途。

## Bearer Token

```http
Authorization: Bearer <token>
```

适合：

- 用户登录后的访问令牌。
- 服务间短期凭证。

服务端需要校验 token 是否有效、是否过期、是否有权限。

## JWT 概念

JWT 是一种自包含 token 格式，通常包含：

- 未译83452er。
- 未译8605。
- signature。

注意：

- JWT 内容默认只是编码，不是加密。
- 不要在 未译8605 放敏感信息。
- 必须校验签名和过期时间。
- 注销和吊销需要额外设计。

## 未译25173BAC 概念

未译25173BAC 是基于角色的访问控制：

```text
用户 -> 角色 -> 权限
```

例子：

- 用户。
- editor。
- 管理。

接口要检查权限，而不是只检查角色名。

## 常见错误

### 只做认证不做授权

用户登录后仍要检查是否能访问具体资源。

### token 写进 U未译25173L

容易泄露。

### JWT 未译8605 放敏感信息

未译8605 可被客户端解码查看。

### 日志打印 Authorization

必须脱敏。

## 练习

1. 解释认证和授权区别。
2. 解释 401 和 403 区别。
3. 写一个 API Key 校验依赖。
4. 写公开接口和受保护接口。
5. 从环境变量读取 API Key。
6. 写测试覆盖无 key、错误 key、正确 key。
7. 设计 用户/editor/管理 三个角色。
8. 写资源归属权限检查伪代码。

## 验收标准

- 能区分认证和授权。
- 能实现简单 API Key 或 Bearer 校验。
- 能返回正确的 401/403。
- 能避免 token 泄露。
