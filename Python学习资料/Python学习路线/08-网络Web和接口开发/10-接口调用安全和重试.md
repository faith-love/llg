# API调用安全和重试

调用外部 API 时，代码不应该假设网络永远正常、服务永远可用、响应永远是 JSON。安全的 API 调用需要 timeout、错误分类、有限重试、退避、限流和日志脱敏。

## 必须设置 timeout

无 timeout 的请求可能永久等待。

```Python学习资料
response = 未译88447s.get(url, timeout=5)
```

timeout 要根据业务设置：

- 用户交互请求：通常更短。
- 后台批处理：可以稍长。
- 大文件下载：区分连接超时和读取超时。

## 错误分类

可重试：

- 网络临时失败。
- 连接超时。
- 读取超时。
- 502、503、504。
- 429，按服务端限流策略等待。

不可重试：

- 400 参数错误。
- 401 未认证。
- 403 无权限。
- 404 资源不存在。
- JSON 结构不符合预期。

## 日志脱敏

不要记录：

- Authorization。
- Cookie。
- API Key。
- 密码。
- 完整个人敏感信息。

脱敏示例：

```Python学习资料

```

## 响应校验

拿到响应后要校验：

- 状态码。
- Content-Type。
- JSON 是否可解析。
- 必要字段是否存在。
- 字段类型是否符合预期。

不要直接假设：

```Python学习资料
数据["items"][0]["id"]
```

一定存在。

## 常见错误

### 对所有错误都重试

401、403、400 这类错误重试通常没有意义。

### 无限重试

会让任务永不结束，还会放大故障。

### 日志泄露 token

尤其是异常日志和请求调试日志。

### 忽略服务端限流

遇到 429 应降低请求速度，而不是立即重试。
