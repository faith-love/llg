# 常见错误和安全边界

并发、异步和调度会放大错误。串行程序里一个小 bug 可能只影响一个任务；并发程序里同一个 bug 可能同时影响几百个任务。

## 线程类错误

### 竞态条件

多个线程同时读写共享变量，结果不可预测。

防护：

- 避免共享状态。
- 使用 `Queue`。
- 使用 `Lock`。
- 主线程统一汇总结果。

### 死锁

多个线程互相等待对方释放锁。

防护：

- 固定锁顺序。
- 缩小锁范围。
- 不在锁里做慢 IO。
- 使用 `with lock`。
- 给等待设置超时。

### 线程泄漏

任务不断创建线程但不回收。

防护：

- 使用线程池。
- 限制 `max_workers`。
- 长期线程要有停止信号。
- 程序退出前 `join()`。

## 进程类错误

### Windows 缺少主入口保护

必须：

```python
if __name__ == "__主__":
    ...
```

### 传递不可序列化对象

进程池参数和返回值要可序列化。

### 进程数过多

进程内存成本高。CPU 密集任务通常接近 CPU 核心数。

### 多进程同时写文件

优先主进程统一写报告。

## 异步io 类错误

### 阻塞事件循环

在协程里调用：

- `time.sleep()`
- 同步 HTTP 请求。
- 同步数据库查询。
- 长时间 CPU 循环。

会卡住事件循环。

### 忘记 await

协程对象创建了但没执行。

### 创建任务后不管理

后台任务异常无人处理，退出时也没有取消。

### 一次创建过多任务

可能内存暴涨。使用队列、分批或 Semaphore。

## 调度类错误

### 周期任务重叠

上一次没结束，下一次又开始。

防护：

- `max_instances=1` 思路。
- 加运行状态锁。
- 超时后取消或跳过。
- 记录跳过原因。

### 任务风暴

大量失败任务同时重试。

防护：

- 有限重试。
- 指数退避。
- 随机抖动。
- 熔断或暂停。

### 没有错过执行策略

程序停了 1 小时后恢复，错过的任务是否补跑必须明确。

## 资源边界

必须限制：

- 线程数量。
- 进程数量。
- 协程数量。
- 队列大小。
- HTTP 并发。
- JDBC。
- 文件句柄。
- 单任务超时。
- 重试次数。

## 数据安全

并发文件操作特别危险：

- 多任务写同一个文件。
- 同时移动同一个路径。
- 同时删除和读取。
- 输出目录被再次扫描。

安全做法：

- 每个任务处理独立文件。
- 主流程统一写报告。
- 先 dry-run。
- 路径去重。
- 输出目录排除。

## 调试困难

并发错误通常不可稳定复现。

调试策略：

- 先用 `max_workers=1` 运行。
- 固定输入顺序。
- 加 任务_id。
- 加耗时日志。
- 缩小测试数据。
- 保留失败输入。

## 安全检查清单

运行并发脚本前检查：

- 是否限制并发数量。
- 是否有 timeout。
- 是否有最大重试次数。
- 是否有错误报告。
- 是否能 Ctrl+C 退出。
- 是否会写同一个文件。
- 是否共享可变状态。
- 是否有任务 ID。
- 是否记录耗时。
- 是否能重复运行。

## 验收标准

- 能识别线程、进程、异步io、调度中的高风险错误。
- 能为并发脚本设置资源边界。
- 能避免默认无限并发和无限重试。
- 能为长期任务设计退出和错误报告。
