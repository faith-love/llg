# 验收标准和复盘

完成第 07 阶段后，你应该能独立判断任务类型，选择线程、进程或 异步io，并写出带并发上限、超时、错误处理、日志和报告的任务执行程序。

这一阶段的核心验收不是“会写多少并发语法”，而是“并发之后还能不能控制风险”。

## 阶段能力目标

完成本阶段后应达到：

- 能解释并发、并行、异步。
- 能区分 IO 密集和 CPU 密集任务。
- 能解释 GIL 对线程和 CPU 计算的影响。
- 能使用 `threading` 创建和停止线程。
- 能使用锁、事件、信号量和队列。
- 能使用 `ThreadPoolExecutor`。
- 能使用 `多processing` 和 `ProcessPoolExecutor`。
- 能理解进程通信和序列化限制。
- 能使用 异步io 编写协程和任务。
- 能使用 `gather`、`as_通用pleted`、`Semaphore`。
- 能处理超时、取消和异常。
- 能实现生产者消费者模式。
- 能设计限流、重试和退避。
- 能写简单调度任务。
- 能为并发任务提供日志和报告。

## 项目验收

### 项目 1：多线程 URL 或文件检查器

必须具备：

- 命令行参数。
- `ThreadPoolExecutor`。
- 可配置并发数。
- 单任务 timeout。
- 失败记录。
- CSV 或 JSON 报告。
- 成功率统计。

通过标准：

- 并发数可调。
- 单个任务失败不影响整体。
- 所有异常能定位到输入。
- 报告包含成功、失败、耗时。

### 项目 2：进程池 CPU 工具

必须具备：

- `ProcessPoolExecutor`。
- 主入口保护。
- CPU 密集任务。
- 串行和进程池耗时对比。
- 异常收集。
- 结果报告。

通过标准：

- 能说明为什么使用进程而不是线程。
- 参数和返回值可序列化。
- 进程数设置合理。
- 结果由主进程统一输出。

### 项目 3：异步io 并发任务执行器

必须具备：

- `异步io.run()`。
- `create_任务` 或 `gather`。
- `Semaphore` 限制并发。
- timeout。
- cancel。
- 结构化结果。
- 错误报告。

通过标准：

- 不阻塞事件循环。
- 并发数量可控。
- 超时任务可记录。
- 退出时能取消后台任务。

### 项目 4：周期调度脚本

必须具备：

- 固定间隔运行。
- 记录下次运行时间。
- 防止任务重叠。
- 单次任务超时。
- Ctrl+C 优雅退出。
- 运行日志。

通过标准：

- 上一次未结束时不会盲目启动下一次。
- 任务失败后不会无限快速重试。
- 日志能说明每次运行结果。

## 安全验收

必须能回答：

- 任务为什么适合这个并发模型？
- 并发数量为什么设置为这个值？
- 单个任务卡住怎么办？
- 单个任务失败怎么办？
- 所有任务同时失败怎么办？
- 重试几次，间隔多久？
- 是否会写同一个文件？
- 是否有共享可变状态？
- 是否能 Ctrl+C 退出？
- 是否能从日志中定位失败输入？

## 测试验收

至少完成：

- 3 个线程安全测试。
- 3 个线程池异常测试。
- 3 个进程池异常测试。
- 5 个 异步io 超时和取消测试。
- 3 个调度重叠测试。
- 3 个报告输出测试。

测试原则：

- 先用小输入。
- 并发数从 1 开始。
- 固定随机种子或固定输入。
- 保留失败样例。
- 测试超时和取消。

## 复盘问题

完成后写复盘，回答：

1. 哪个任务适合线程，为什么？
2. 哪个任务适合进程，为什么？
3. 哪个任务适合 异步io，为什么？
4. 你遇到过哪些竞态条件？
5. 哪些地方必须加并发上限？
6. 哪些错误可以重试？
7. 哪些错误不应该重试？
8. 任务取消时清理了什么资源？
9. 调度任务如何防止重叠？
10. 如果任务数量扩大 100 倍，最先出问题的是什么？
