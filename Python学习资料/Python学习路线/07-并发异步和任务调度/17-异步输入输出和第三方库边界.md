# 异步IO和第三方库边界

异步io 的优势来自非阻塞 IO。如果你在协程中调用阻塞同步库，事件循环仍然会被卡住。理解异步库和同步库的边界，是写可靠异步程序的关键。

## 标准库里的异步边界

`异步io` 提供事件循环、任务、队列、锁、子进程等能力，但很多常见 IO 库本身仍是同步接口。

例如：

- `urllib.request` 是同步网络请求。
- 普通文件读写是同步文件 IO。
- 许多数据库驱动默认是同步驱动。

在异步函数中直接调用这些同步接口，可能阻塞事件循环。

## 异步 HTTP

真实项目里，异步 HTTP 通常使用第三方库，例如：

- `aiohttp`
- `httpx` 的异步客户端

学习阶段先理解概念：

```python
异步 def fetch(url):
    ...
```

关键要求：

- 请求方法本身必须是异步的。
- 等待响应时使用 `await`。
- 每个请求有 timeout。
- 连接池有并发上限。

## 异步文件 IO

普通文件读写通常是阻塞的。对于很多小文件任务，线程池更简单。

如果确实需要异步文件接口，可了解第三方库，例如 `aiofiles`。

但学习阶段要记住：

- 异步io 不会自动让普通文件 IO 变成非阻塞。
- 本地磁盘文件批处理通常线程池足够。
- 大文件仍要分块处理。

## 把阻塞函数放到线程

异步io 可以把阻塞函数交给线程执行：

```python
import 异步io


def blocking_work(path):
    return path.read_text(encoding="utf-8")


异步 def 主(path):
    content = await 异步io.to_thread(blocking_work, path)
    return content
```

适合：

- 少量阻塞函数。
- 必须调用同步库。
- 不想阻塞事件循环。

不要把大量 CPU 密集计算都塞进 `to_thread`，CPU 任务仍应考虑进程池。

## 数据库边界

数据库访问要关注：

- 驱动是否异步。
- 连接池大小。
- 单个查询 timeout。
- 事务边界。
- 并发写入冲突。

异步框架配同步数据库驱动，会阻塞事件循环。

## 异步代码中的同步陷阱

常见阻塞调用：

- `time.sleep()`
- 同步 HTTP 请求。
- 同步数据库查询。
- 大文件同步读写。
- CPU 密集循环。
- 外部命令同步等待。

替代方式：

- `await 异步io.sleep()`。
- 使用异步 HTTP 客户端。
- 使用异步数据库驱动。
- `异步io.to_thread()` 包装同步 IO。
- CPU 任务用进程池。
- 异步子进程 API 或线程池。

## 常见错误

### 只把函数改成 异步

如果内部全是同步阻塞调用，函数名变成 异步 也不会获得异步收益。

### 混用同步客户端

异步 Web 服务里使用同步 HTTP 或数据库客户端，会拖慢整个事件循环。

### 无限制创建异步连接

异步更容易启动大量任务，更需要限制并发。

### 忽略库的 timeout

异步库通常也需要显式 timeout。

2. 改成 `异步io.sleep()`。

4. 写一个模拟异步 HTTP 函数。
5. 用 Semaphore 限制最多 5 个异步请求。
6. 列出你常用库是同步还是异步。
7. 写一份“异步项目选库检查表”。

## 验收标准

- 能识别协程中的阻塞同步代码。
- 能解释异步库和同步库的差异。
- 能使用 `异步io.to_thread()` 包装同步 IO。
- 能为异步任务设置并发上限和 timeout。
