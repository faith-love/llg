# 生产者消费者模式

生产者消费者模式用于解耦“产生任务”和“处理任务”。它是并发程序中最常见、最实用的结构之一。

## 模式结构

```text
生产者 -> 队列 -> 消费者
```

生产者负责：

- 扫描文件。
- 读取输入。
- 拉取消息。
- 生成任务。

消费者负责：

- 下载。
- 解析。
- 转换。
- 写入结果。

队列负责：

- 缓冲任务。
- 协调速度。
- 限制内存。
- 传递停止信号。

## 为什么需要队列

如果生产者太快，消费者太慢，没有队列限制就会内存暴涨。

如果消费者太快，生产者太慢，队列会让消费者等待。

队列是并发系统里的“缓冲区”和“节流阀”。

## 背压

背压是指下游处理不过来时，上游放慢速度。

实现方式：

- 设置 `Queue(maxsize=...)`。
- 生产者 `put()` 时等待。
- 限制消费者数量。
- 限制外部请求并发。

没有背压时，系统可能不断堆积任务直到崩溃。

## 多阶段流水线

复杂任务可以拆成多个队列：

```text
扫描文件 -> 读取队列 -> 解析队列 -> 写入队列 -> 报告
```

注意：

- 每一阶段都要有容量限制。
- 每一阶段都要有停止机制。
- 错误要能回传或记录。

## 错误处理

消费者处理失败时：

- 记录任务输入。
- 记录错误原因。
- 决定是否重试。
- 超过重试次数进入失败队列。

不要让消费者异常退出后没人处理剩余任务。

## 常见错误

### 没有停止信号

消费者可能永久等待。

### 停止信号太早发送

任务还没处理完，消费者就退出。

### 队列无限大

生产过快时内存上涨。

### 消费者异常退出无人发现

必须记录错误和任务状态。
