# 后台任务和守护进程边界

后台任务是长期运行或脱离主流程运行的任务。它们看起来只是循环加 sleep，但真正难点在启动、停止、错误恢复、资源释放和可观测性。

## 后台任务类型

常见后台任务：

- 定时扫描目录。
- 周期生成报表。
- 消费队列消息。
- 定期检查服务状态。
- 刷新缓存。
- 清理临时文件。

## 前台脚本和后台服务

前台脚本：

- 手动运行。
- 运行一次结束。
- 出错后人工查看。

后台任务：

- 长期运行。
- 需要自动恢复或报警。
- 需要日志轮转。
- 需要优雅退出。
- 需要资源清理。

学习阶段先写前台可控脚本，再逐步长期运行。

## 优雅退出

优雅退出要做：

- 停止接收新任务。
- 等待正在执行的任务完成或超时。
- 取消可取消任务。
- 写入最终报告。
- 关闭文件、连接、线程池。

## Ctrl+C 处理

```python
try:
    run_forever()
except KeyboardInterrupt:
    print("收到退出信号")
```

更复杂任务可使用 `signal` 模块，但 Windows 和 Unix 行为有差异，学习阶段先掌握 Ctrl+C 和停止标记。

## 后台线程

daemon 线程会在主程序退出时被强制结束，不适合关键任务。

更稳妥：

- 非 daemon 线程。
- 使用 `Event` 通知停止。
- `join()` 等待完成。

## 异步io 后台任务退出

```python
任务 = 异步io.create_任务(background())
try:
    await 主_work()
finally:
    任务.cancel()
    try:
        await 任务
    except 异步io.CancelledError:
        pass
```

重点：

- 保存 任务 引用。
- 退出时 cancel。
- 等待取消完成。
- 在任务内部 finally 清理资源。

## 健康检查

长期任务需要知道自己是否正常：

- 最近一次成功时间。
- 最近一次失败时间。
- 连续失败次数。
- 队列长度。
- 当前运行任务数。
- 下次运行时间。

这些可以写到日志、状态文件或监控系统。

## 日志轮转

长期运行脚本不能无限写一个日志文件。

可以了解：

- `日志ging.处理器s.RotatingFileHandler`
- `日志ging.处理器s.TimedRotatingFileHandler`

学习阶段至少要把日志写到文件，并记录每次启动和退出。

## 常见错误

### while True 没有停止条件

程序只能强杀，资源可能无法释放。

### 异常导致后台任务直接退出

外层循环要捕获可恢复错误并记录。

### 失败后马上无限重试

需要退避和最大重试次数。

### 没有运行状态

任务看起来还在运行，但可能已经长期没有成功处理任何任务。

## 练习

1. 写一个可 Ctrl+C 退出的周期脚本。
2. 用 Event 停止后台线程。
3. 用 异步io 取消后台任务。
4. 记录启动和退出日志。
5. 记录最近一次成功时间。
6. 增加连续失败次数统计。
7. 给失败重试增加退避。
8. 使用日志轮转。

## 验收标准

- 能说明后台任务和一次性脚本差异。
- 能实现优雅退出。
- 能管理后台线程或 异步io 后台任务。
- 能记录长期运行状态。
