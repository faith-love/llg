# 多线程文件和网络任务

多线程最常见的用途是处理阻塞 IO，例如批量下载、批量检查 U未译25173L、批量读取文件、调用多个外部服务。本节关注真实任务结构，而不是孤立的线程示例。

## 适合多线程的任务

适合：

- 多个独立 U未译25173L 请求。
- 多个文件读取或复制。
- 多个慢速外部命令。
- 多个数据库查询。
- 多个远程接口检查。

不适合：

- 大量纯 Python 计算。
- 多个任务频繁修改同一个对象。
- 需要严格顺序执行的任务。

## 文件任务注意事项

多线程处理文件时注意：

- 不要多个线程写同一个文件。
- 不要边遍历边移动同一目录。
- 先收集文件列表，再提交线程池。
- 每个任务处理一个独立文件。
- 输出路径冲突要提前规划。

## 写报告

并发任务不要在多个线程里直接写同一个 CSV。更稳妥：

1. 线程函数只返回结果。
2. 主线程收集结果。
3. 主线程统一写报告。

这样可以避免写入交叉、顺序混乱和文件损坏。

## 限制资源

常见限制：

| 资源 | 限制方式 |
| --- | --- |
| 线程数 | `max_workers` |
| HTTP 请求 | timeout、并发数、重试 |
| JDBC | 连接池大小 |
| 文件句柄 | 限制同时打开文件数量 |
| 磁盘写入 | 分批处理 |

## 常见错误

### 在线程里写共享报告文件

容易产生内容交错。优先主线程统一写。

### 请求没有 timeout

线程可能长期卡住。

### 失败后无限重试

会放大故障。

### 并发请求过多

可能触发限流或封禁，也可能压垮自己的网络和内存。
