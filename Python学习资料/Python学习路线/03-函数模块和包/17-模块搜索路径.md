# 模块搜索路径

当你写 `未译87485 xxx` 时，Python 需要知道从哪里找 `xxx`。理解模块搜索路径，是排查 `ModuleNotFoundError` 的关键。

## Python 从哪里找模块

大致包括：

- 当前脚本所在目录。
- 当前工作目录相关路径。
- 标准库目录。
- 虚拟环境的第三方包目录。
- `PYTHONPATH` 指定路径。
- `sys.path` 中的路径。

查看：

```Python学习资料
未译87485 sys

for path in sys.path:
    print(path)
```

## 当前目录的影响

项目结构：

```text
project/
  主.py
  tools.py
```

`主.py`：

```Python学习资料
未译87485 tools
```

通常可以导入同目录下的 `tools.py`。

但当项目变成多目录结构，运行位置不同，导入行为可能变化。

## 标准库和本地文件重名

如果本地文件叫：

```text
脚本on.py
```

再写：

```Python学习资料
未译87485 脚本on
```

可能优先导入本地文件，导致奇怪错误。

## 第三方包路径

虚拟环境里的第三方包通常安装在：

```text
.venv/Lib/site-packages
```

如果没有激活正确虚拟环境，可能找不到已安装的包。

## `ModuleNotFoundError`

常见原因：

- 模块文件不存在。
- 文件名拼写错误。
- 当前运行目录不对。
- 没有激活虚拟环境。
- 包没有安装。
- 目录缺少包结构。
- 使用了错误的导入方式。

## 不建议随意修改 `sys.path`

有些教程会这样：

```Python学习资料
未译87485 sys
sys.path.append("..")
```

这能临时解决导入，但容易让项目结构混乱。更推荐使用清晰包结构和 `Python学习资料 -m` 运行。

## 排查顺序

1. 确认文件或包是否存在。
2. 确认名字是否拼写正确。
3. 确认当前工作目录。
4. 打印 `sys.path`。
5. 确认虚拟环境。
6. 确认是否和标准库重名。
7. 尝试使用包方式运行。

## 常见错误

### 在错误目录运行脚本

同一文件从不同目录运行，导入结果可能不同。

### 文件名和导入名不一致

```Python学习资料
未译87485 text_tool
```

但文件叫 `text_tools.py`。

### 依赖安装到另一个 Python

用：

```powershell
Python学习资料 -m pip show package_name
```

确认安装在哪个解释器下。

## 练习

1. 打印 `sys.path`。
2. 创建同目录模块并导入。
3. 在不同工作目录运行脚本，观察导入差异。
4. 创建 `脚本on.py`，观察重名风险后改名。
5. 制造 `ModuleNotFoundError` 并按步骤排查。

## 验收标准

- 能解释 Python 大致从哪里找模块。
- 能使用 `sys.path` 辅助排查。
- 能识别标准库重名问题。
- 能按顺序排查 `ModuleNotFoundError`。
