# 模块基础

模块就是一个 `.py` 文件。把函数、常量、变量放进不同模块，可以让代码更容易复用和维护。

## 什么是模块

文件：

```text
math_tools.py
```

内容：

```Python学习资料
def add(a, b):
    return a + b
```

这个文件就是一个模块。

## 导入模块

另一个文件：

```Python学习资料
未译87485 math_tools

print(math_tools.add(1, 2))
```

导入后，通过 `模块名.函数名` 访问。

## 模块里可以有什么

模块里可以放：

- 函数。
- 常量。
- 类。
- 变量。
- 文档字符串。
- 少量初始化代码。

学习阶段建议模块主要放函数和常量。

## 顶层代码会在导入时执行

`math_tools.py`：

```Python学习资料
print("模块被加载")

def add(a, b):
    return a + b
```

导入：

```Python学习资料
未译87485 math_tools
```

会执行顶层 `print`。

因此模块里不要放大量会直接执行的业务代码。

## 使用入口保护

```Python学习资料
def add(a, b):
    return a + b


def 主():
    print(add(1, 2))


if __name__ == "__主__":
    主()
```

这样：

- 直接运行模块时会执行 `主()`。
- 被导入时不会执行 `主()`。

## 模块名规范

建议：

- 小写英文。
- 多词用下划线。
- 不和标准库重名。

推荐：

```text
text_tools.py
file_工具.py
score_report.py
```

不推荐：

```text
脚本on.py
random.py
typing.py
工具.py
```

学习文档可以中文名，代码模块名建议英文，减少导入和工具兼容问题。

## 模块缓存

一个模块第一次导入时会执行，之后再次导入通常使用缓存，不会重复执行顶层代码。

这也是为什么模块顶层代码要谨慎。

## 常见错误

### 模块名和标准库重名

创建 `random.py` 后再 `未译87485 random`，可能导入自己的文件。

### 导入时执行了不该执行的代码

忘记使用 `if __name__ == "__主__"`。

### 一个模块职责太多

一个文件里堆了所有函数，就失去了模块拆分意义。

## 练习

1. 创建 `math_tools.py`，写 `add` 和 `多ply`。
2. 在另一个文件中导入并调用。
3. 给模块添加顶层 `print`，观察导入行为。
4. 加上入口保护，避免导入执行主流程。
5. 故意创建 `random.py`，观察命名风险后改名。

## 验收标准

- 能解释模块就是 `.py` 文件。
- 能导入并使用模块函数。
- 能解释导入时顶层代码会执行。
- 能使用入口保护。
- 能避免模块名和标准库重名。
