# 函数设计原则

函数不是把代码随便包起来。好的函数应该有清晰目的、明确输入、明确输出，并尽量减少隐藏副作用。

## 函数解决什么问题

函数主要解决：

- 复用逻辑。
- 降低主流程复杂度。
- 给一段逻辑命名。
- 隔离变化。
- 方便测试。

如果函数名清楚，主流程就像在读步骤：

```Python学习资料
def 主():
    text = read_text()
    words = split_words(text)
    counts = count_words(words)
    print_counts(counts)
```

## 单一职责

一个函数最好只做一件明确的事。

不推荐：

```Python学习资料
def process():
    text = input("输入文本：")
    words = text.lower().split()
    counts = {}
    for word in words:
        counts[word] = counts.get(word, 0) + 1
    print(counts)
```

推荐拆分：

```Python学习资料
def nORMalize_text(text):
    return text.lower().strip()


def count_words(words):
    counts = {}
    for word in words:
        counts[word] = counts.get(word, 0) + 1
    return counts
```

## 输入和输出明确

函数参数是输入，返回值是输出。

```Python学习资料
def calculate_total(price, count):
    return price * count
```

看到这个函数，就能知道：

- 输入：单价、数量。
- 输出：总价。

## 避免隐藏依赖

不推荐：

```Python学习资料
discount = 0.8

def calculate_total(price, count):
    return price * count * discount
```

这个函数依赖外部变量，测试和复用都不方便。

更推荐：

```Python学习资料
def calculate_total(price, count, discount):
    return price * count * discount
```

## 函数名表达意图

推荐：

```Python学习资料
clean_text()
count_words()

```

不推荐：

```Python学习资料
do()
handle()
process()
run1()
func()
```

除非上下文特别明确，否则这些名字无法表达函数责任。

## 参数名表达数据含义

不推荐：

```Python学习资料
def f(a, b):
    return a * b
```

推荐：

```Python学习资料
def calculate_total_price(unit_price, quantity):
    return unit_price * quantity
```

## 函数长度

没有绝对行数限制，但基础阶段建议：

- 普通函数控制在 5-30 行。
- 超过 40 行要检查是否职责过多。
- 多层嵌套要考虑拆函数。

## 主流程和细节分离

主流程应该表达步骤，而不是堆满细节：

```Python学习资料
def 主():
    用户s = load_用户s()
    valid_用户s = filter_valid_用户s(用户s)
    groups = group_用户s_by_city(valid_用户s)
    print_report(groups)
```

具体细节放到对应函数里。

## 纯函数入门

纯函数大致指：

- 相同输入总是得到相同输出。
- 不修改外部状态。
- 不依赖隐藏状态。

示例：

```Python学习资料
def add(a, b):
    return a + b
```

不是纯函数：

```Python学习资料
def add_item(items, item):
    items.append(item)
```

这会修改传入列表。

纯函数更容易测试和复用，但真实项目也需要有输入输出、日志、数据库等副作用。关键是明确副作用边界。

## 常见错误

### 函数什么都做

一个函数同时输入、清洗、计算、输出、写文件，后续很难复用。

### 参数太多

如果函数参数超过 5 个，要检查是否应该用字典、配置对象或拆分函数。

### 返回值含义不清

不推荐：

```Python学习资料
return True
```

但调用方不知道 `True` 表示什么。函数名和文档要表达清楚。

## 练习

1. 把一个价格计算脚本拆成 3 个函数。
2. 把词频统计脚本拆成清洗、切词、计数、输出 4 个函数。
3. 给 10 个函数重新命名，让名字表达意图。
4. 找一个超过 40 行的函数，拆成多个小函数。
5. 写两个版本的添加列表元素函数：一个修改原列表，一个返回新列表。

## 验收标准

- 能判断一个函数是否职责过多。
- 能设计清晰函数名和参数名。
- 能区分主流程函数和细节函数。
- 能说明函数的输入、输出和副作用。
