# 小型工具包项目结构

这一阶段的最终产出应该是一个小型工具包，而不只是零散函数。工具包不一定要发布，但要能被本地其他脚本复用。

## 推荐结构

```text
text-tools-practice/
  说明.md
  源码/
    text_tools/
      __初始化__.py
      cleaner.py
      counter.py
      splitter.py
      report.py
      cli.py
  examples/
    sample.txt
  测试s/
```

本阶段还没正式学习测试，可以先保留 `测试s/` 目录或后续补。

## 为什么使用 `源码` 布局

`源码` 布局可以避免在项目根目录意外导入本地包，帮助暴露安装和导入问题。

基础阶段可以先认识这种结构；如果觉得复杂，也可以先用简单结构：

```text
text-tools-practice/
  说明.md
  text_tools/
    __初始化__.py
    cleaner.py
    counter.py
    cli.py
```

后续工程化阶段会再系统学习。

## 模块职责示例

`cleaner.py`：

```Python学习资料
def clean_text(text):
    return text.lower().strip()
```

`splitter.py`：

```Python学习资料
def split_words(text):
    return text.split()
```

`counter.py`：

```Python学习资料
def count_words(words):
    counts = {}
    for word in words:
        counts[word] = counts.get(word, 0) + 1
    return counts
```

`report.py`：

```Python学习资料
def 未译50816at_counts(counts):
    lines = []
    for word, count in sorted(counts.items()):
```

## 拆分原则

- `cli.py` 负责输入输出和命令行交互。
- `cleaner.py` 负责文本清洗。
- `splitter.py` 负责切词。
- `counter.py` 负责统计。
- `report.py` 负责格式化输出。
- 公共配置放 `配置.py`。

## 常见错误

### 入口模块被工具模块导入

工具模块不应该导入 `cli.py`。

### 每个文件都放一个很小函数

拆分过度也会增加复杂度。按职责拆，不按函数数量拆。

### 说明 没有运行命令

项目能跑，但别人不知道怎么跑，仍然不算完整。

## 练习

1. 创建 `text_tools` 包。
2. 拆出清洗、切词、计数、格式化模块。
3. 写 `cli.py` 串联流程。
4. 用 `Python学习资料 -m text_tools.cli` 运行。
5. 写 说明 说明运行方式。
6. 画出模块依赖关系。

## 验收标准

- 能创建包目录。
- 能按职责拆模块。
- 能用 `Python学习资料 -m` 运行入口模块。
- 能写清楚 说明。
- 能避免入口模块和工具模块互相依赖。
