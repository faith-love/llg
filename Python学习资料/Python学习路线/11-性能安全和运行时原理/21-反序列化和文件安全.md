# 反序列化和文件安全

反序列化和文件处理是 Python 项目中的高风险区域。很多严重漏洞来自把不可信数据交给危险解析器，或把压缩包、上传文件写到不受控路径。

## pickle 风险

`pickle` 可以执行对象构造逻辑，不适合处理不可信输入。

危险：

```python
import pickle


数据 = pickle.loads(用户_input)
```

原则：

- 不对不可信数据使用 pickle。
- 对外部数据使用 JSON 等安全格式。
- 内部 pickle 文件也要保护来源和权限。

## YAML 风险

使用 PyYAML 时不要对不可信输入使用危险 load。

应使用安全加载方式，例如 safe load 概念。

原则：

- 不加载任意对象。
- 限制 schema。
- 校验解析结果。

## zip slip

压缩包中可能包含路径穿越文件名：

```text
../../evil.py
```

解压时如果直接写入，可能覆盖目标目录外文件。

防护：

- 遍历每个成员。
- resolve 目标路径。
- 确认在解压目录内。
- 限制文件数量和总大小。

## 上传文件风险

风险：

- 文件过大。
- 文件名路径穿越。
- 恶意脚本。
- 假扩展名。
- 覆盖已有文件。
- 存储目录可执行。

防护：

- 服务端生成文件名。
- 限制大小。
- 后缀白名单。
- 路径范围检查。
- 下载鉴权。
- 存储隔离。

## 临时文件安全

使用 `tempfile`：

```python
from tempfile import TemporaryDirectory


with TemporaryDirectory() as temp_dir:
    ...
```

不要手写可预测临时文件名。

## 文件权限

敏感文件：

- 密钥。
- token。
- 配置。
- 用户上传文件。

要控制访问权限，避免放在公开静态目录。

## 常见错误

### pickle 处理用户上传文件

高风险。

### 解压包不检查成员路径

可能 zip slip。

### 原样保存上传文件名

可能覆盖或路径穿越。

### 临时文件名可预测

可能被竞争或覆盖。

## 练习

1. 解释为什么不信任 pickle。
2. 把 pickle 输入改成 JSON。
3. 写 zip 成员路径检查函数。
4. 限制解压总文件大小。
5. 上传文件服务端生成文件名。
6. 使用 TemporaryDirectory。
7. 写文件上传安全测试。
8. 写反序列化安全清单。

## 验收标准

- 能解释不可信反序列化风险。
- 能防 zip slip 和路径穿越。
- 能安全处理上传文件和临时文件。
