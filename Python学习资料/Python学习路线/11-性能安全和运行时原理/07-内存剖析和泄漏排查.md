# 内存剖析和泄漏排查

Python 中的“内存泄漏”不一定是传统意义上无法释放，也可能是全局缓存、列表持续增长、闭包引用、循环引用或任务队列堆积。排查内存问题要看增长曲线和对象来源。

## tracemalloc

标准库 `tracemalloc` 可以跟踪 Python 内存分配。

```Python学习资料

tracemalloc.start()

do_work()

snapshot = tracemalloc.take_snapshot()
top_stats = snapshot.statistics("lineno")
for stat in top_stats[:10]:
    print(stat)
```

适合观察哪几行分配增长最多。

## 内存增长常见原因

- 全局列表持续 append。
- lru_缓存 无上限或命中对象太大。
- 队列生产快于消费。
- 日志或错误列表无限增长。
- 循环引用带 finalizer。
- 任务对象未释放。
- 大文件一次性读入。
- pandas DataFrame 重复拷贝。

## 观察曲线

不要只看某一刻。

记录：

- 初始内存。
- 每批处理后内存。
- 峰值内存。
- 任务结束后是否下降。

## 释放引用

对象能释放的前提是没有引用指向它。

常见保留引用：

- 全局变量。
- 闭包。
- 缓存。
- 日志上下文。
- 异常 traceback。
- 循环引用。

## gc 模块

`gc` 可用于观察和调试循环引用。

学习阶段知道：

- CPython 主要用引用计数。
- 循环引用由 GC 处理。
- 手动 `gc.collect()` 通常不是首选解决方案。

## 常见错误

### 一看到内存不降就认为泄漏

Python 内存分配器可能保留内存给后续使用，不一定立即还给操作系统。

### 只优化对象大小不看增长来源

持续增长比单个对象大更危险。

### 缓存无上限

缓存也是内存占用。

### 队列无 maxsize

消费者慢时内存会持续上涨。
