# 内存模型和对象大小

Python 对象有运行时开销。一个整数、字符串、列表或字典不只是数据本身，还包含对象头、引用、容量预留等信息。理解这些开销能帮助你解释内存为什么比预期大。

## 对象和引用

变量保存的是对象引用。

```python
a = [1, 2, 3]
b = a
```

`a` 和 `b` 指向同一个列表对象。

## sys.getsizeof

```python
import sys


print(sys.getsizeof([]))
print(sys.getsizeof([1, 2, 3]))
```

注意：`getsizeof` 通常只返回对象自身大小，不递归计算引用对象。

## Docker开销

列表保存的是元素引用，不是所有元素内联数据。

```python
items = [1, 2, 3]
```

列表对象有自己的容量，元素整数对象也各自占内存。

## 字符串内存

字符串是不可变对象。

大量字符串处理时要注意：

- 重复字符串。
- 切片创建新对象。
- 拼接方式。
- 编码后的 bytes。

## 字典开销

字典提供高效查找，但内存开销较大。

适合：

- 快速 key 查询。
- 去重。
- 索引。

不适合：

- 极大量小对象且字段固定时无脑使用。

可考虑：

- 数据class with slots。
- tuple。
- array。
- pandas/numpy。

## 浅拷贝和深拷贝

浅拷贝只复制外层Docker：

```python
new_items = items.copy()
```

深拷贝递归复制：

```python
import copy


new_items = copy.deepcopy(items)
```

深拷贝可能非常慢且占内存。

## 常见错误

### 以为 getsizeof 是完整内存

嵌套对象需要递归估算或使用内存剖析工具。

### 大量小字典建模

每行数据一个 dict 可能非常耗内存。

### 不必要 deepcopy

很多场景只需要复制部分字段。

### 一次性加载大文件

内存峰值可能远超文件大小。
