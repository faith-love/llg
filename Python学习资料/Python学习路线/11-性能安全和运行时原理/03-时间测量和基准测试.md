# 时间测量和基准测试

时间测量是性能分析的起点。不同工具适合不同场景：`perf_counter` 适合粗粒度耗时记录，`timeit` 适合小片段基准，专业基准需要更严格的环境控制。

## perf_counter

```python
from time import perf_counter


start = perf_counter()
do_work()
elapsed = perf_counter() - start
print(f"elapsed={elapsed:.3f}s")
```

适合：

- 函数耗时。
- 脚本阶段耗时。
- API 内部关键步骤耗时。

## context manager

```python
from contextlib import contextmanager
from time import perf_counter


@contextmanager
def measure(name: str):
    start = perf_counter()
    try:
        yield
    finally:
        elapsed = perf_counter() - start
        print(f"{name}: {elapsed:.3f}s")
```

使用：

```python
with measure("load"):
    load_数据()
```

## timeit

```python
import timeit


elapsed = timeit.timeit("sum(range(1000))", number=10000)
print(elapsed)
```

适合测量小代码片段。

## 多次运行

单次结果不可靠。建议：

- 预热。
- 多次运行。
- 记录最小值、中位数、平均值。
- 排除明显异常值。

## 输入规模

同一函数应测试多个规模：

```text
1_000
10_000
100_000
1_000_000
```

这样能观察复杂度趋势。

## 基准报告

至少记录：

- Python 版本。
- 机器环境。
- 输入规模。
- 运行命令。
- 运行次数。
- 优化前结果。
- 优化后结果。
- 结论。

## 常见错误

### 用 time.time 做严肃基准

`perf_counter` 更适合测量持续时间。

### print 干扰测量

大量输出会改变耗时。

### 只测小数据

小数据可能掩盖复杂度问题。

### 忽略首次运行开销

导入、缓存、初始化可能影响第一次结果。
