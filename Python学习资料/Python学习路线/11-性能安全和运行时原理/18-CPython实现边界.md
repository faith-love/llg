# CPython实现边界

Python 是语言规范，CPython 是最常用的实现。很多行为来自 CPython 实现细节，不一定适用于其他解释器或未来版本。理解边界能避免写出依赖偶然行为的代码。

## Python 和 CPython

Python：

- 语言规范。
- 语法和标准库行为。

CPython：

- 使用 C 实现的主流解释器。
- 有引用计数。
- 有 GIL。
- 有特定字节码实现。

## 其他实现

可能包括：

- PyPy。
- GraalPy。
- MicroPython。

它们的性能特征、GC、实现细节可能不同。

## 不要依赖实现细节

谨慎依赖：

- 引用计数立即释放。
- 某些对象 interning。
- 字节码具体指令。
- dict 内部实现细节。
- CPython 特定性能特征。

## dict 顺序

现代 Python 语言层面保证 dict 保持插入顺序。这个已经不是单纯 CPython 偶然行为。但仍要区分哪些是规范，哪些是实现细节。

## 性能差异

同一段代码在不同解释器上可能：

- CPU 性能不同。
- 内存占用不同。
- GC 行为不同。
- C 扩展兼容性不同。

项目要先明确支持哪些解释器和 Python 版本。

## C 扩展边界

很多性能库依赖 C 扩展。

注意：

- 安装需要平台 wheel 或编译环境。
- 可能不支持所有解释器。
- 可能释放 GIL，也可能不释放。

## 常见错误

### 把 CPython 行为当语言规范

导致跨版本或跨解释器问题。

### 优化只对当前版本有效

升级 Python 后收益消失甚至变慢。

### 不写 Python 版本要求

用户在不支持版本运行。

### 忽略依赖 wheel 可用性

部署环境可能无法安装。

## 练习

1. 查明当前 Python 实现和版本。
2. 记录项目支持的 Python 版本。
3. 找出一个 CPython 实现细节例子。
4. 判断一个行为是否语言规范保证。
5. 检查依赖是否有平台 wheel。
6. 写一份运行时支持说明。

## 验收标准

- 能区分 Python 语言和 CPython 实现。
- 能识别实现细节风险。
- 能为项目写 Python 版本和解释器支持范围。
