# 常见错误和安全边界

第 11 阶段最常见的问题可以分成两类：性能上凭感觉优化，安全上默认信任输入。二者都会让项目在真实环境中暴露风险。

## 性能错误

### 没有基准就优化

必须有优化前数据。

### 没有 profile 就改代码

容易优化错地方。

### 微优化牺牲可读性

如果收益很小，不值得。

### 小数据测试推断大数据

复杂度问题只有数据变大才明显。

### 忽略数据库和网络

慢请求可能不在 Python 代码。

### 并发无上限

会造成外部服务限流、内存上涨和队列堆积。

## 内存错误

### 一次性加载大文件

应流式处理。

### 缓存无上限

内存增长。

### 队列无 maxsize

生产快于消费时持续堆积。

### 不必要 deepcopy

占用大量内存和时间。

## 运行时误解

### 所有慢都怪 GIL

先 profile。

### 依赖 CPython 实现细节

跨版本可能失效。

### import 顶层副作用

导致启动慢、测试不稳定。

### 依赖 `del` 立即释放系统内存

不可靠。

## 安全错误

### 信任前端输入

后端必须校验。

### 拼接 SQL 或 shell 命令

使用参数化和参数列表。

### 反序列化不可信 pickle

高风险。

### 原样保存上传文件名

路径穿越和覆盖风险。

### token 写进日志

严重泄露。

### CORS 全放开

生产环境风险高。

## 发布前性能安全检查

- 是否有性能基准？
- 是否有 profile 证据？
- 是否记录优化前后对比？
- 是否限制并发？
- 是否限制缓存大小？
- 是否避免大文件全量加载？
- 是否校验所有外部输入？
- 是否使用参数化查询？
- 是否避免 shell=True？
- 是否防路径穿越？
- 是否脱敏日志？
- 是否扫描依赖风险？
- 是否检查 CORS 和权限？

## 练习

1. 找出一个无基准优化案例并补基准。
2. 找出一个无 timeout 网络调用并修复。
3. 找出一个无上限缓存并修复。
4. 找出一个路径拼接风险并修复。
5. 找出一个日志泄露风险并脱敏。
6. 给一个接口增加资源归属检查。
7. 写性能安全发布前检查表。

- 能把检查项落到代码和配置。
- 能形成发布前性能安全清单。
