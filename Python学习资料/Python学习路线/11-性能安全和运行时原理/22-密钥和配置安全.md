# 密钥和配置安全

密钥泄露是最常见也最严重的安全事故之一。密钥包括 API token、数据库密码、JWT secret、私钥、Cookie secret、云服务凭证等。

## 密钥不能放哪里

不要放在：

- 源代码。
- 说明 示例真实值。
- Git 提交历史。
- Docker 镜像。
- CI 日志。
- 异常堆栈。
- 前端代码。
- URL query 参数。

## 环境变量

常见方式：

```python
import os


secret = os.environ.get("SECRET_KEY")
if not secret:
    raise RuntimeError("缺少 SECRET_KEY")
```

生产环境缺少密钥应启动失败，而不是使用默认弱密钥。

## .env 文件

`.env` 适合本地开发。

要求：

- `.env` 不提交。
- 提交 `.env.example`。
- 示例值使用占位符。
- Docker ignore 排除 `.env`。

## 日志脱敏

脱敏字段：

- authorization。
- cookie。
- password。
- token。
- secret。
- 接口_key。

示例：

```python
def mask(value: str) -> str:
    if len(value) <= 8:
        return "***"
    return value[:4] + "***" + value[-4:]
```

## 密钥轮换

密钥应支持轮换：

- 生成新密钥。
- 同时接受新旧密钥一段时间。
- 更新客户端。
- 废弃旧密钥。
- 记录轮换时间。

## 最小权限

密钥应限制：

- 可访问资源。
- 可执行操作。
- 可用环境。
- 过期时间。

不要一个 token 拥有全部权限。

## CI secrets

CI 中：

- 使用平台 secrets。
- 不在日志 echo。
- 限制 PR 来源使用。
- 发布权限只给发布 作业。

## 常见错误

### 默认 SECRET_KEY

生产忘记配置会使用弱默认值。

### 打印完整配置

配置对象中可能有密钥。

### token 放 URL

URL 容易被日志记录。

### 密钥永不过期

泄露后影响长期存在。

## 练习

1. 检查项目是否硬编码密钥。
2. 从环境变量读取 SECRET_KEY。
3. 缺失密钥时启动失败。
4. 创建 `.env.example`。
5. 写日志脱敏函数。
6. 检查 Docker 镜像构建上下文是否包含 `.env`。
7. 设计密钥轮换步骤。
8. 写 CI secrets 使用规则。

## 验收标准

- 能识别密钥泄露路径。
- 能安全加载配置和密钥。
- 能做日志脱敏。
- 能设计密钥轮换和最小权限。
