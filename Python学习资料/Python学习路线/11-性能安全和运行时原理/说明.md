# 11-性能安全和运行时原理

这一阶段的目标是让你从“会写 Python 项目”进入“能诊断、优化和加固 Python 项目”的层次。重点是先测量再优化，先理解风险再防护，先掌握运行时机制再做判断。

如果第 10 阶段关注“项目如何工程化交付”，第 11 阶段关注“项目在真实负载和真实风险下是否可靠、可解释、可防护”。

## 本阶段产出

- 至少 80 个性能、安全和运行时练习。
- 一份性能基准报告。
- 一份 cProfile 分析报告。
- 一份内存增长排查记录。
- 一个经过优化的文件或数据处理脚本。
- 一份 Web/API 安全检查清单。
- 一份依赖安全和密钥安全检查记录。
- 一份运行时原理笔记。
- 一份阶段复盘。

## 本阶段不做什么

- 不凭感觉优化，必须先测量。
- 不为了微小收益牺牲可读性。
- 不把性能问题都归因于 GIL。
- 不使用危险反序列化处理不可信输入。
- 不把密钥、token、cookie 写入代码、镜像和日志。
- 不把安全检查当成上线前一次性动作，而要纳入工程流程。
