# 阶段目标

第 11 阶段要建立三种能力：能定位性能瓶颈，能理解 Python 运行时关键机制，能识别和修复常见安全风险。

这一阶段的关键不是“背很多底层概念”，而是能在真实项目里形成判断链路：观察现象、收集数据、定位原因、选择方案、验证改进、记录取舍。

## 本阶段要解决的问题

你需要能回答：

- 程序慢在哪里？
- 你如何证明某个函数是瓶颈？
- 优化前后的基准数据是什么？
- 内存为什么持续增长？
- 哪种数据结构适合当前场景？
- 什么时候该用缓存，什么时候不能用？
- GIL 对当前任务是否真的有影响？
- 循环引用和垃圾回收有什么关系？
- import 为什么会出现循环导入？
- 字节码能帮你理解什么？
- 输入为什么默认不可信？
- 如何防 SQL 注入、命令注入、路径穿越？
- 为什么不能对不可信数据用 pickle？
- 密钥如何存放、轮换和脱敏？
- 依赖包如何带来供应链风险？

## 必须完成的项目

### 项目 1：性能基准与优化报告

选择一个真实脚本或服务接口：

- 记录当前耗时。
- 用 profile 定位瓶颈。
- 提出优化方案。
- 修改代码。
- 对比优化前后。
- 记录取舍。

### 项目 2：内存增长排查

构造或选择一个内存增长场景：

- 使用 tracemalloc 记录快照。
- 找出增长来源。
- 修复或解释增长原因。
- 输出排查报告。

### 项目 3：安全加固清单

对一个 API 或自动化工具做安全检查：

- 输入校验。
- 路径安全。
- 命令执行安全。
- 密钥管理。
- 日志脱敏。
- 依赖漏洞。
- 权限边界。

### 项目 4：运行时原理笔记

整理：

- GIL 对你的项目是否影响。
- GC 对象生命周期。
- import 和循环导入。
- 字节码观察。
- CPython 实现细节边界。

## 难点

### 难点 1：不凭感觉优化

很多性能优化失败不是因为技术不够，而是没有测量。必须先有基准和 profile，再决定优化。

### 难点 2：性能和可读性取舍

优化不是越复杂越好。只有当性能收益明确、瓶颈稳定、可读性损失可接受时，才值得改。

### 难点 3：安全不是单点功能

安全不是“加一个登录”就结束。输入、权限、依赖、日志、配置、部署都可能成为风险点。

### 难点 4：实现细节不能当语言规范

CPython 的某些行为是实现细节，不一定适用于 PyPy、未来版本或其他解释器。理解它们有价值，但不要随意依赖偶然行为。

## 阶段验收口径

通过本阶段需要满足：

- 能用数据说明性能瓶颈。
- 能使用 cProfile 或等价工具。
- 能使用 tracemalloc 或等价方法排查内存。
- 能根据复杂度选择数据结构。
- 能解释 GIL、GC、import、字节码基础。
- 能识别注入、路径穿越、反序列化、密钥泄露风险。
- 能为 API 或脚本写安全检查清单。
- 能输出性能优化和安全加固复盘。

## 记录要求

每个性能或安全任务要保留：

- 原始现象。
- 复现步骤。
- 测量命令。
- 原始数据。
- 分析过程。
- 修改方案。
- 对比结果。
- 剩余风险。
