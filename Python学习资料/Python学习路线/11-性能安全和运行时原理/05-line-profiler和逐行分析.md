# line_profiler和逐行分析

函数级 profile 能告诉你哪个函数慢，但有时还需要知道函数内部哪一行慢。逐行分析适合定位热点循环、重复计算和不必要的对象创建。

## 适用场景

适合：

- 一个函数内部逻辑复杂。
- cProfile 显示某函数很慢。
- 想知道慢在哪一行。
- 优化循环体。

不适合：

- 整个程序入口级粗略分析。
- 大量函数无目标地全量分析。

## line_profiler 概念

`line_profiler` 是第三方工具，常用于行级耗时分析。学习阶段重点理解方法，不强制绑定工具。

基本思路：

1. 先用 cProfile 找到慢函数。
2. 再对慢函数做行级分析。
3. 修改热点行。
4. 重新测量。

## 手动行级测量

没有工具时，可以临时拆分阶段：

```python
start = perf_counter()
step1()
print("step1", perf_counter() - start)

start = perf_counter()
step2()
print("step2", perf_counter() - start)
```

这不如专业工具精细，但能快速定位大块耗时。

## 热点循环

常见问题：

- 循环中重复读取配置。
- 循环中重复编译正则。
- 循环中执行数据库查询。
- 循环中重复创建大对象。
- 循环中做不必要的类型转换。

## 优化方向

- 把不变计算移出循环。
- 预构建 dict/set。
- 批量处理 IO。
- 减少重复解析。
- 使用生成器降低内存。
- 拆分函数让热点更清晰。

## 常见错误

### 没有 cProfile 就直接逐行分析

可能在不重要函数上浪费时间。

### 过度微优化

行级优化容易让代码变复杂，要看收益。

### 忽略算法问题

把一行代码写得更快，不如把 O(n²) 改成 O(n)。

### print 调试影响性能

大量 print 本身会改变耗时。

## 练习

1. 用 cProfile 找一个慢函数。
2. 对慢函数做手动阶段测量。
3. 找出循环中的重复计算。
4. 把不变计算移出循环。
5. 把 list 成员测试改成 set。
6. 对比优化前后耗时。
7. 写逐行分析记录。

## 验收标准

- 能说明何时需要逐行分析。
- 能从函数级热点深入到行级热点。
- 能识别循环中的重复成本。
- 能避免无意义微优化。
