# 安全基本原则

安全不是某个库或某个功能，而是一套设计原则。Python 项目常见风险来自不可信输入、权限边界不清、密钥泄露、危险反序列化、依赖漏洞和部署配置错误。

## 输入不可信

所有外部输入都不可信：

- HTTP 参数。
- JSON 请求体。
- 文件上传。
- CSV/Excel。
- 环境变量。
- 命令行参数。
- 外部 API 响应。
- 数据库中的历史脏数据。

必须校验、限制、转换。

## 最小权限

程序只应拥有完成任务所需的最低权限。

例子：

- 数据库账号只给必要表权限。
- API token 只给必要 scope。
- Docker不以 root 运行。
- 文件操作限制在工作目录。

## 纵深防御

不要依赖单一防线。

例如文件上传：

- 前端限制。
- 后端校验。
- 文件大小限制。
- 后缀白名单。
- 存储隔离。
- 下载鉴权。
- 日志审计。

## 默认安全

默认配置应该安全：

- 默认不覆盖。
- 默认不删除。
- 默认不执行 shell。
- 默认不开 debug。
- 默认不允许任意 CO未译25173S。
- 默认不暴露内部错误。

## 失败安全

出错时应该进入安全状态。

例如：

- 权限校验失败时拒绝。
- 配置缺失时启动失败。
- 密钥无效时拒绝请求。

不要在错误时默认放行。

## 审计和日志

安全事件要记录：

- 登录失败。
- 权限拒绝。
- 文件上传失败。
- 关键资源删除。
- token 校验失败。
- 异常请求频率。

同时避免记录敏感信息。

## 常见错误

### 只信任前端

前端可以被绕过。

### 为了方便给过大权限

泄露后影响范围更大。

### debug 模式暴露内部信息

生产禁用 debug。

### 安全检查只在上线前做一次

应该进入开发、测试、CI 和运维流程。

## 练习

1. 列出项目的外部输入来源。
2. 为每个输入写校验规则。
3. 写最小权限清单。
4. 检查默认配置是否安全。
5. 写失败时默认拒绝的例子。
6. 设计安全审计日志字段。
7. 写一份威胁建模草稿。

## 验收标准

- 能解释输入不可信、最小权限、纵深防御。
- 能识别项目输入边界。
- 能设计安全默认值和失败策略。
