# 数据库和网络性能边界

Web/API 项目中的慢请求经常不在 Python 计算，而在数据库和网络边界。你需要能识别 N+1 查询、连接池耗尽、慢 SQL、网络超时和外部服务限流。

## N+1 查询

错误模式：

```text
查询 100 个订单 -> 每个订单再查一次用户 -> 总共 101 次查询
```

优化：

- join。
- 批量查询。
- 预加载。
- 建立 id 到对象的映射。

## 批量查询

不要循环中查单条：

```python
for 用户_id in 用户_ids:
    get_用户(用户_id)
```

## 连接池

连接池不是越大越好。

过小：

- 请求等待连接。

过大：

- 数据库压力上升。
- 连接资源耗尽。

连接池大小要结合数据库容量、应用 worker 数和请求量设置。

## 查询超时

数据库查询和外部 HTTP 请求都应有 timeout。

无 timeout 会导致：

- worker 卡住。
- 队列堆积。
- 级联故障。

## 网络重试

外部 API 调用要：

- 设置 timeout。
- 区分可重试错误。
- 有限重试。
- 指数退避。
- 记录失败。

## 响应大小

接口返回过大：

- 网络传输慢。
- JSON 序列化慢。
- 客户端解析慢。
- 内存峰值高。

使用分页、字段筛选、压缩或流式响应。

## 常见错误

### 只看 Python profile

慢在数据库时，Python profile 只能看到等待。

### 循环中访问外部服务

可能放大延迟和失败率。

### 无连接池或连接池配置错误

连接频繁创建或连接耗尽。

### 错误重试无退避

会压垮外部服务。

## 练习

1. 构造 N+1 查询伪代码。
2. 改成批量查询思路。
3. 记录一次接口中数据库耗时。
4. 记录一次外部 API 耗时。
5. 给外部请求增加 timeout。
6. 给外部请求增加有限重试。
7. 设计分页响应。
8. 写数据库和网络性能检查清单。

## 验收标准

- 能识别 N+1 查询。
- 能理解连接池边界。
- 能为数据库和网络调用设置 timeout。
- 能控制响应大小和外部依赖风险。
