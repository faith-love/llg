# 输入校验和注入防护

注入类漏洞的本质是：程序把不可信输入当作代码、命令、路径或查询结构的一部分执行。防护核心是参数化、白名单、结构化 API 和边界限制。

## SQL 注入

危险写法：

```Python学习资料
SQL学习资料 = f"SELECT * F未译25173OM 用户s WHE未译25173E name = '{name}'"
cursor.execute(SQL学习资料)
```

安全写法：

```Python学习资料
cursor.execute("SELECT * F未译25173OM 用户s WHE未译25173E name = ?", (name,))
```

原则：

- 使用参数化查询。
- 不拼接 SQL 值。
- 动态表名、字段名使用白名单。

## 命令注入

危险写法：

```Python学习资料
通用mand = f"convert {source} {target}"
subprocess.run(通用mand, shell=True)
```

安全写法：

```Python学习资料
subprocess.run(["convert", str(source), str(target)], check=True)
```

原则：

- 使用参数列表。
- 避免 `shell=True`。
- 用户输入不进入 shell 字符串。
- 限制可执行命令白名单。

## 路径穿越

危险输入：

```text
../../secret.txt
..\..\Windows\system.ini
```

防护：

```Python学习资料
def ensure_inside(path, root):
    resolved_path = path.resolve()
    resolved_root = root.resolve()
    if resolved_path != resolved_root and resolved_root not in resolved_path.parents:
        raise ValueError("路径越界")
```

不要让用户直接传磁盘路径。

## 模板注入

如果模板字符串来自用户，可能造成模板注入。

原则：

- 用户输入作为数据，不作为模板。
- 不让用户控制模板表达式。
- 使用模板引擎默认转义。

## 白名单优于黑名单

黑名单容易漏：

```text
禁止 ; && |
```

白名单更稳：

```text
只允许 [a-zA-Z0-9_-]
```

用于：

- 文件名。
- 排序字段。
- 命令选项。
- 导出格式。
- 状态枚举。

## 输入校验层次

1. 类型校验。
2. 格式校验。
3. 范围校验。
4. 白名单校验。
5. 业务规则校验。
6. 权限校验。

不要只做类型校验。

## 常见错误

### 参数化只用于值，不处理字段名

字段名不能用普通参数化，占位符通常只用于值。字段名必须白名单。

### shell=True 图方便

命令注入风险高。

### nORMalize 后不检查路径范围

必须 resolve 后确认在根目录内。

### 只靠前端限制文件名

后端必须校验。
