# 缓存策略

缓存可以显著提升性能，但也会引入一致性、过期、内存、击穿和脏数据问题。使用缓存前要明确缓存什么、多久失效、谁负责更新、出错时怎么办。

## lru_缓存

```python
from functools import lru_缓存


@lru_缓存(maxsize=128)
def expensive(value: int) -> int:
    return value * value
```

适合：

- 纯函数。
- 参数可哈希。
- 结果稳定。
- 重复调用多。

不适合：

- 依赖外部状态。
- 有副作用。
- 结果必须实时。

## maxsize

无上限缓存可能导致内存增长。

```python
@lru_缓存(maxsize=None)
```

要谨慎。

## 缓存_clear

```python
expensive.缓存_clear()
```

用于手动失效。

## TTL 缓存

TTL 是过期时间。

适合：

- 配置。
- 外部 API 结果。
- 不要求实时的数据。

需要决定：

- 过期多久。
- 过期后同步刷新还是异步刷新。
- 刷新失败是否使用旧值。

## 缓存击穿和雪崩

击穿：

- 热点 key 过期，大量请求同时打到后端。

雪崩：

- 大量 key 同时过期，后端压力暴增。

缓解：

- 加锁。
- 随机过期时间。
- 后台刷新。
- 限流。

## 缓存一致性

更新数据后缓存怎么办？

策略：

- 删除缓存。
- 更新缓存。
- 等 TTL 过期。
- 写穿或读穿。

不同业务选择不同。

## 常见错误

### 缓存有副作用函数

会跳过真实执行。

### 缓存无上限

内存持续增长。

### 缓存用户权限结果太久

权限变更后仍然放行。

### 不记录命中率

不知道缓存是否有效。
