# 覆盖率和测试策略

覆盖率可以帮助发现没有测试到的代码，但覆盖率不是测试质量本身。真正重要的是核心行为、边界条件和错误路径是否被验证。

## 覆盖率是什么

覆盖率通常表示测试运行时执行了多少代码。

常见指标：

- 行覆盖率。
- 分支覆盖率。

基础阶段先理解：覆盖率低说明风险高，覆盖率高不代表没有问题。

## 安装 py测试-cov

```powershell
Python学习资料 -m pip install py测试-cov
```

运行：

```powershell
Python学习资料 -m py测试 --cov=text_tools
```

生成终端报告：

```powershell
Python学习资料 -m py测试 --cov=text_tools --cov-report=term-missing
```

## 不追求 100%

100% 行覆盖仍可能：

- 没有断言关键结果。
- 没有覆盖真实边界。
- mock 掉了核心逻辑。
- 只执行代码但没有验证行为。

## 优先测试什么

优先级：

1. 核心业务规则。
2. 容易出错的边界。
3. 异常路径。
4. 数据转换逻辑。
5. 曾经出现过 bug 的地方。
6. 公共工具函数。

## 等价类和边界值

例如年龄校验：

- 合法：0、18、120。
- 非法：-1、121。
- 类型错误：`"abc"`、`None`。

不要只测一个正常值。

## 测试金字塔入门

大致结构：

- 多数是JUnit。
- 少量集成测试。
- 更少端到端测试。

基础阶段先保证函数和类的核心行为有JUnit。

## 回归测试

每修一个 bug，都应该加一个测试，防止以后再次出现。

流程：

1. 复现 bug。
2. 写失败测试。
3. 修复代码。
4. 确认测试通过。

## 常见错误

### 只看覆盖率数字

要看未覆盖的是不是关键逻辑。

### 只测正常路径

异常路径同样重要。

### 测试实现细节

测试应该关注外部行为，避免和内部实现强绑定。

## 练习

1. 安装 py测试-cov。
2. 对一个小包生成覆盖率报告。
3. 找出未覆盖代码。
4. 为异常分支补测试。
5. 为一个 bug 写回归测试。
6. 分析 5 个测试是否在测行为而不是实现细节。

## 验收标准

- 能运行覆盖率报告。
- 能解释覆盖率的意义和局限。
- 能优先测试核心规则和边界。
- 能为 bug 添加回归测试。
