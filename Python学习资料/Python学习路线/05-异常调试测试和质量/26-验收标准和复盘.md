# 验收标准和复盘

本阶段通过标准是：能处理错误、定位错误、验证行为、保持代码质量。完成后，你的项目应该不再依赖手工试运行来判断是否正确。

## 知识验收

你应该能回答：

- 异常如何传播。
- traceback 应该怎么看。
- `try/except/else/finally` 分别什么时候执行。
- 为什么不能裸 `except`。
- `raise` 和 `raise from` 有什么区别。
- 自定义异常应该如何设计。
- 异常应该在哪一层捕获。
- 什么时候用断点，什么时候用日志。
- `日志ger.异常` 适合什么场景。
- `assert` 为什么不能做用户输入校验。
- unit测试 和 py测试 有什么区别。
- py测试 fixture 如何工作。
- 参数化测试适合什么场景。
- 如何测试异常分支。
- mock 应该替换什么，不应该替换什么。
- 覆盖率有什么意义和局限。
- Ruff、Black、isort、mypy 分别解决什么问题。

## 代码验收

必须完成：

- 至少 70 个练习。
- 至少 1 个自定义异常层级。
- 至少 1 个带异常处理的入口函数。
- 至少 20 个 py测试 测试。
- 至少 5 个异常分支测试。
- 至少 3 个 fixture。
- 至少 3 个参数化测试。
- 至少 1 个 mock 或 monkeypatch 测试。
- 至少 1 份覆盖率报告。
- 至少 1 次格式化和静态检查记录。

## 错误排查验收

应该能独立处理：

- 捕获过宽。
- 吞异常。
- traceback 过长。
- breakpoint 遗留。
- 日志缺少上下文。
- 测试发现不到。
- fixture 污染状态。
- 参数化字段不匹配。
- mock 位置错误。
- 覆盖率高但断言不足。
