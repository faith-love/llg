# 代码风格和格式化

代码风格不是审美问题，而是协作和维护问题。统一格式能减少无意义争论，让注意力集中在逻辑上。

## PEP 8

PEP 8 是 Python 官方风格指南。

基础阶段重点：

- 变量和函数使用小写加下划线。
- 类名使用大驼峰。
- 常量使用全大写。
- 每行不要过长。
- 导入分组。
- 运算符两侧适当空格。
- 函数之间保留空行。

## 注释风格

注释应该解释原因，不重复代码。

不推荐：

```Python学习资料
count += 1  # count 加 1
```

推荐：

```Python学习资料
# 失败重试会重复调用，因此这里只统计最终成功次数。
success_count += 1
```

## 常见错误

### 手工争论格式

格式交给工具。

### 命名太抽象

`数据`、`info`、`manager`、`处理器` 过多会降低可读性。

### 导入顺序混乱

用 isort。
