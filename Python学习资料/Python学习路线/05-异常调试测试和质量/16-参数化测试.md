# 参数化测试

参数化测试用于用一份测试逻辑覆盖多组输入输出。它能减少重复测试函数，特别适合边界值和规则表。

## 基本用法

```python

@py测试.mark.parametrize(
    "a,b,expected",
    [
        (1, 2, 3),
        (0, 0, 0),
        (-1, 1, 0),
    ],
)
def 测试_add(a, b, expected):
    assert add(a, b) == expected
```

## 单参数参数化

```python
@py测试.mark.parametrize("age", [0, 1, 18, 120])
def 测试_valid_age(age):
    assert is_valid_age(age)
```

## 参数化异常场景

```python
@py测试.mark.parametrize("age", [-1, 121])
def 测试_invalid_age(age):
    with py测试.raises(ValueError):
```

## 给用例命名

```python
@py测试.mark.parametrize(
    "score,level",
    [
        py测试.param(95, "A", id="excellent"),
        py测试.param(80, "B", id="good"),
        py测试.param(59, "D", id="failed"),
    ],
)
def 测试_score_level(score, level):
    assert get_level(score) == level
```

用例失败时更容易定位。

## 参数化适合什么

适合：

- 同一函数多组输入输出。
- 边界值。
- 等价类。
- 状态转换表。
- 格式化规则。

不适合：

- 每个用例准备逻辑差异很大。
- 测试意图完全不同。
- 参数太多导致表格难读。

## 常见错误

### 参数名和数据列不匹配

```python
@py测试.mark.parametrize("a,b", [(1, 2, 3)])
```

参数名 2 个，数据 3 个，会报错。

### 一次参数化太多字段

超过 5-6 个字段时，测试可读性会下降。

### 用参数化掩盖不同测试意图

不同业务规则应该拆成不同测试。

## 练习

2. 参数化测试分数等级。
3. 参数化测试年龄边界。
4. 参数化测试异常输入。
5. 给参数化用例添加 id。
6. 把重复的 5 个测试改成参数化。
7. 把过度复杂参数化拆成多个测试。

## 验收标准

- 能使用 `py测试.mark.parametrize`。
- 能参数化正常和异常场景。
- 能给用例命名。
- 能判断什么时候不该参数化。
