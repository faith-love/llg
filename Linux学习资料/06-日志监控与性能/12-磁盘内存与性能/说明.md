# 12 磁盘、内存与性能

## 作用

资源与性能排查解决“服务器为什么变慢、服务为什么崩溃、系统为什么不可写”的问题。CPU、内存、磁盘、IO、网络、文件句柄和进程数量都可能成为瓶颈。这个章节重点建立资源排查顺序和常见指标含义。

## 痛点

- 服务器负载高，但不知道是 CPU、IO 还是内存问题。
- 磁盘满后应用报各种奇怪错误。
- 内存高时只会重启，不知道是否 OOM。
- 文件句柄耗尽导致连接失败。
- 删除大文件后磁盘空间没有释放。

## CPU 和负载

查看负载：

```bash
uptime
top
```

`load average` 表示等待 CPU 或不可中断 IO 的任务数量。粗略判断：

- 单核机器 load 长期大于 1，可能繁忙。
- 4 核机器 load 长期大于 4，可能繁忙。
- load 高但 CPU 不高，可能是 IO 等待。

查看 CPU 高进程：

```bash
ps aux --sort=-%cpu | head
top
```

处理思路：

1. 找到高 CPU 进程。
2. 判断是否业务高峰、死循环、批任务、压缩或备份。
3. 查看应用日志是否有异常。
4. 必要时限流、降级、重启或扩容。

## 内存

查看内存：

```bash
free -h
top
ps aux --sort=-%mem | head
```

关注：

- `available` 比 `free` 更有参考意义。
- Linux 会用空闲内存做缓存，不代表内存泄漏。
- swap 大量使用会导致服务变慢。

查看 OOM：

```bash
dmesg | grep -i "out of memory"
journalctl -k | grep -i "killed process"
```

处理思路：

- 确认是否进程内存泄漏。
- 检查 JVM、Node、Python 进程内存限制。
- 降低并发或批处理规模。
- 增加内存或拆分服务。

## 磁盘空间

查看分区：

```bash
df -h
```

找大目录：

```bash
du -h --max-depth=1 /var | sort -h
du -h --max-depth=1 /opt/apps | sort -h
```

常见大户：

- 应用日志。
- Nginx access 日志。
- Docker 镜像和Docker日志。
- 上传文件。
- 备份文件。
- 旧版本 release。

删除后空间没释放：

```bash
sudo lsof | grep deleted
```

原因：文件已删除，但仍被进程打开。需要重启对应进程或让它重新打开日志。

## 磁盘 IO

常用命令：

```bash
iostat -x 1
iotop
```

如果系统没有这些命令，需要安装 `sysstat` 或 `iotop`。

常见现象：

- CPU 不高但系统很慢，可能是 IO 等待。
- 数据库、日志写入、备份压缩可能造成高 IO。
- 磁盘接近满时性能和稳定性都会变差。

## 文件句柄

查看限制：

```bash
unofile -n
cat /proc/sys/fs/file-max
```

查看进程打开文件：

```bash
pid=$(pgrep -f demo-接口 | head -n 1)
ls /proc/$pid/fd | wc -l
```

查看监听和连接：

```bash
ss -s
ss -ant | awk '{print $1}' | sort | uniq -c
```

文件句柄耗尽常见表现：

- `Too many open files`。
- 新连接失败。
- 日志无法写入。
- JDBC异常。

systemd 可配置：

```ini
[Service]
LimitNOFILE=65535
```

## 网络资源

查看连接：

```bash
ss -ant
ss -s
```

查看监听：

```bash
ss -lntup
```

常见问题：

- 大量 `TIME-WAIT`。
- 大量连接堆积。
- 后端连接池耗尽。
- 上游服务超时。

## 性能排查顺序

1. `uptime` 看负载。
2. `top` 看 CPU、内存、load。
3. `free -h` 看内存。
4. `df -h` 看磁盘。
5. `du` 找大目录。
6. `ss` 看端口和连接。
7. `journalctl` 和应用日志看错误。
8. 根据现象继续查 IO、句柄、数据库或应用内部。

## 难点

- load 高不一定是 CPU 高，可能是 IO 等待。
- Linux 缓存占内存不等于内存不足。
- 删除文件不释放空间，可能是进程仍占用。
- 性能问题经常是应用、数据库、网络和系统共同作用，不要只盯一个指标。

## 重点

- 先判断瓶颈类型：CPU、内存、磁盘、IO、网络、句柄。
- 磁盘满优先止血，再分析日志和清理策略。
- 资源问题要结合时间线和最近变更。
- 生产环境调优前先备份配置，记录原值。

## 练习

1. 用 `dd` 或日志文件制造一个大文件，用 `du` 找到它。
2. 启动一个占用 CPU 的测试进程，用 `top` 定位。
3. 查看当前 Shell 的 `unofile -n`，再给 systemd 服务配置 `LimitNOFILE`。
4. 删除一个被 `tail -f` 打开的文件，观察 `lsof | grep deleted`。
