# 用户级与全局环境变量

## 作用

用户级与全局环境变量用于解决“变量如何持久生效、对哪些用户生效、在哪些 Shell 中生效”的问题。临时 `export` 只对当前终端有效，如果希望下次登录仍然生效，就要写到合适的配置文件里。

但这些文件有生效范围差异：`.bashrc`、`.profile`、`/etc/profile`、`/etc/environment` 并不是一回事。理解它们的边界，能避免“我写了变量但服务读不到”的问题。

## 痛点

- 把变量写进 `.bashrc`，以为 systemd 服务也能读到。
- 修改 `/etc/profile` 影响所有用户，却没有评估风险。
- `source ~/.bashrc` 后当前终端有效，重新登录另一个用户却无效。
- `/etc/environment` 写了复杂 Shell 语法，不生效。
- 不知道登录 Shell 和非登录 Shell 差异。

## 优点

- 能正确选择变量持久化位置。
- 能控制变量影响范围。
- 能避免污染全局环境。
- 能区分用户终端配置和服务运行配置。

## 用户级配置文件

常见文件：

| 文件 | 常见用途 | 影响范围 |
| --- | --- | --- |
| `~/.bashrc` | 交互式 Bash 配置 | 当前用户交互 Shell |
| `~/.profile` | 登录 Shell 配置 | 当前用户登录会话 |
| `~/.bash_profile` | Bash 登录配置 | 部分发行版使用 |

示例：

```bash
echo 'export APP_ENV=dev' >> ~/.bashrc
source ~/.bashrc
echo $APP_ENV
```

适合放：

- 个人命令别名。
- 开发机 PATH 调整。
- 用户级工具配置。

不适合放：

- 生产服务运行变量。
- 所有用户共享的强制配置。
- 密钥明文。

## `.bashrc`

`.bashrc` 通常在交互式 Bash 中加载。

适合：

- alias。
- 命令提示符。
- 用户级 PATH。
- 开发环境变量。

示例：

```bash
export PATH="$HOME/bin:$PATH"
alias ll='ls -lah'
```

注意：

- systemd 不会自动读取你的 `.bashrc`。
- cron 通常也不会自动读取你的 `.bashrc`。

## `.profile`

`.profile` 常用于登录 Shell。

适合：

- 登录时初始化环境。
- 用户级 PATH。
- 加载 `.bashrc`。

常见写法：

```bash
if [ -f "$HOME/.bashrc" ]; then
  . "$HOME/.bashrc"
fi
```

注意：不同发行版和 Shell 读取顺序可能不同。

## 全局配置文件

常见文件：

| 文件 | 作用 |
| --- | --- |
| `/etc/profile` | 全局 Shell 初始化 |
| `/etc/profile.d/*.sh` | 推荐放全局环境脚本片段 |
| `/etc/environment` | 简单环境变量文件 |

### `/etc/profile.d`

比直接改 `/etc/profile` 更清晰。

示例：

```bash
sudo vim /etc/profile.d/Java学习资料.sh
```

内容：

```bash
export JAVA_HOME=/opt/jdkk
export PATH=$JAVA_HOME/bin:$PATH
```

生效：

```bash
source /etc/profile.d/Java学习资料.sh
```

注意：这影响读取该配置的用户 Shell，不是所有已运行进程。

### `/etc/environment`

适合简单变量：

```text
JAVA_HOME=/opt/jdkk
APP_REGION=cn
```

不适合复杂 Shell 语法：

```bash
export PATH=$JAVA_HOME/bin:$PATH
```

因为 `/etc/environment` 不是 Shell 脚本。

## 生效验证

当前终端：

```bash
echo $JAVA_HOME
env | grep JAVA_HOME
```

重新登录后验证：

```bash
ssh 用户@服务端
echo $JAVA_HOME
```

切换用户验证：

```bash
sudo -iu app env | grep JAVA_HOME
```

注意：`sudo -iu app` 模拟登录 app 用户，更接近该用户登录环境。

## 使用技巧

- 用户自己的命令增强写 `~/.bashrc`。
- 全局运行时路径可放 `/etc/profile.d/*.sh`。
- 简单系统变量可放 `/etc/environment`。
- 生产服务变量优先写 systemd `EnvironmentFile`。
- 修改全局配置前评估所有用户影响。

## 难点

- 登录 Shell、交互 Shell、非交互 Shell 读取文件不同。
- `source` 只影响当前 Shell。
- 已运行进程不会自动读取新配置。
- systemd 和 cron 不等于普通登录 Shell。

## 重点

- `.bashrc` 主要影响当前用户交互 Shell。
- `/etc/profile.d/*.sh` 适合全局 Shell 配置片段。
- `/etc/environment` 只适合简单键值。
- 服务变量不要依赖 `.bashrc`。
- 修改后要用目标用户重新登录或模拟验证。

## 练习

1. 在 `~/.bashrc` 添加一个变量，`source` 后验证。
2. 重新开一个 Shell，确认变量是否还在。
3. 在 `/etc/profile.d/测试.sh` 添加测试变量，用普通用户登录验证。
4. 在 `/etc/environment` 添加简单变量，观察它和 Shell 脚本的区别。
5. 用 `sudo -iu 用户 env` 验证目标用户环境。
