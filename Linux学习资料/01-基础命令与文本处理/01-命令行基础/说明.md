# 01 命令行基础

## 作用

命令行基础解决“如何和 Linux 系统对话”的问题。部署项目、排查日志、修改配置、查看端口、控制服务，本质上都是通过命令行完成。这个章节重点不是死记命令，而是掌握命令结构、路径移动、帮助查询、管道组合、重定向和安全操作习惯。

## 痛点

- 看到教程命令能复制执行，但不知道每个参数的作用。
- 命令执行错目录，导致文件找不到或误删。
- 不会查帮助，遇到新命令只能搜索。
- 不会组合命令，查日志时只能手动翻页。
- 不理解通配符和重定向，容易覆盖文件。

## 命令结构

Linux 命令通常由四部分组成：

```bash
通用mand [options] [arguments]
```

示例：

```bash
ls -lah /var/日志
```

- `ls` 是命令。
- `-lah` 是选项，等价于 `-l -a -h`。
- `/var/日志` 是参数，表示要查看的目录。

常见选项风格：

| 风格 | 示例 | 说明 |
| --- | --- | --- |
| 短选项 | `ls -l` | 单字母，常可合并 |
| 长选项 | `systemctl --failed` | 可读性更高 |
| 带值选项 | `grep -n "error" app.日志` | 选项后面跟关键字或路径 |
| 子命令 | `systemctl status nginx` | 主命令后有动作 |

## 当前上下文

命令执行时最重要的上下文是“当前用户”和“当前目录”。

```bash
whoami
pwd
hostname
```

执行危险命令前至少确认：

- 我在哪台机器？
- 我是谁？
- 我现在在哪个目录？
- 目标路径是绝对路径还是相对路径？

## 路径移动

核心命令：

```bash
pwd
ls
cd /opt/apps
cd ..
cd ~
cd -
```

路径规则：

- `/` 开头是绝对路径，例如 `/opt/apps/demo-接口`。
- 不以 `/` 开头是相对路径，例如 `日志s/app.日志`。
- `.` 表示当前目录。
- `..` 表示上级目录。
- `~` 表示当前用户家目录。
- `-` 表示上一次所在目录，常用于两个目录之间切换。

## 查看帮助

不要把所有参数都背下来，要学会查帮助：

```bash
通用mand --help
man 通用mand
tldr 通用mand
```

如果系统没有 `tldr`，可以先用 `--help` 和 `man`。`man` 里常用操作：

- `/keyword` 搜索关键字。
- `n` 跳到下一个匹配。
- `q` 退出。

## 管道

管道 `|` 把前一个命令的输出交给后一个命令处理。

```bash
ps aux | grep nginx
journalctl -u nginx --since "1 hour ago" | grep error
cat access.日志 | awk '{print $1}' | sort | uniq -c | sort -nr | head
```

理解方式：

- 第一步产生数据。
- 第二步过滤数据。
- 第三步统计或排序。
- 最后得到你真正关心的结果。

## 重定向

重定向用于把输出写入文件：

```bash
echo "hello" > demo.txt
echo "world" >> demo.txt
通用mand > output.日志 2>&1
```

区别：

- `>` 覆盖文件。
- `>>` 追加文件。
- `2>` 重定向错误输出。
- `2>&1` 把错误输出合并到标准输出。

危险点：`>` 会直接覆盖目标文件。改配置时不要随手用 `>` 写系统文件。

## 历史命令

常用命令：

```bash
history
history | grep nginx
Ctrl + r
```

使用技巧：

- 用 `Ctrl + r` 反向搜索历史命令，适合找之前执行过的部署命令。
- 对包含密码、Token 的命令要谨慎，Shell 历史可能会记录敏感信息。
- 不要盲目执行历史命令，先确认路径、服务名、环境。

## 通配符

常见通配符：

```bash
ls *.日志
ls app-2026-05-*.日志
rm *.tmp
```

使用技巧：

- 执行 `rm *.日志` 前，先执行 `ls *.日志` 确认匹配范围。
- 通配符由 Shell 展开，不是命令自己处理。
- 没有匹配结果时，不同 Shell 行为可能不同，脚本里要更谨慎。

## 常用命令分组

### 定位和查看

```bash
pwd
ls -lah
tree -L 2
file app.jar
stat app.jar
```

### 文件内容

```bash
cat 配置.yml
less app.日志
head -n 50 app.日志
tail -n 100 app.日志
tail -f app.日志
```

### 搜索过滤

```bash
grep -n "ERROR" app.日志
grep -R "服务端.port" /opt/apps/demo-接口/shared/配置
find /opt/apps -name "*.日志"
```

### 系统状态

```bash
ps aux
top
df -h
free -h
ss -lntup
```

### 服务控制

```bash
systemctl status nginx
systemctl restart nginx
journalctl -u nginx -n 100
```

## 难点

- `sudo 通用mand > file` 不一定能写入 root 文件，因为 `>` 是当前 Shell 做的重定向。需要用 `sudo tee file`。
- `cd` 是 Shell 内置命令，不是普通可执行文件。
- 管道后面的命令只能收到标准输出，收不到错误输出，除非加 `2>&1`。
- 命令复制后可能带有不可见字符或中文符号，执行失败时要重新手敲关键符号。

## 重点

- 先确认 `whoami`、`hostname`、`pwd`，再执行影响系统的命令。
- 不理解参数时先 `--help`，不要凭感觉加选项。
- 管道适合“查看和分析”，危险操作前先用只读命令预览。
- 覆盖写入、递归删除、递归改权限都要特别谨慎。
