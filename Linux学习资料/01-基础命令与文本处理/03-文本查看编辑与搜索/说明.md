# 03 文本查看、编辑与搜索

## 作用

Linux 运维离不开文本：配置文件是文本，日志是文本，脚本是文本，Nginx、systemd、环境变量文件也都是文本。这个章节解决如何快速查看大文件、实时跟踪日志、搜索关键字、批量处理文本，以及安全编辑配置文件。

## 痛点

- 日志文件很大，用编辑器打开卡住。
- 只会 `cat`，不会分页、实时追踪和过滤。
- 改配置没有备份，出错后不知道改了什么。
- 不会用 `grep` 定位错误，只能人工翻日志。
- 编辑 Linux 文件时引入 Windows 换行，脚本无法执行。

## 查看文本

### 小文件

```bash
cat 配置.yml
```

`cat` 适合小文件，不适合大日志。大文件用 `cat` 会刷屏，也可能影响终端响应。

### 分页查看

```bash
less app.日志
```

`less` 常用操作：

- `Space` 下一页。
- `b` 上一页。
- `/ERROR` 搜索。
- `n` 下一个匹配。
- `Shift + f` 跟踪文件追加，类似 `tail -f`。
- `q` 退出。

### 看头尾

```bash
head -n 50 app.日志
tail -n 100 app.日志
tail -f app.日志
tail -F app.日志
```

区别：

- `tail -f` 跟踪当前文件。
- `tail -F` 在日志轮转后也尽量继续跟踪新文件。

## 搜索文本

### 基础 grep

```bash
grep "ERROR" app.日志
grep -n "ERROR" app.日志
grep -i "error" app.日志
grep -v "health" access.日志
grep -R "服务端.port" /opt/apps/demo-接口
```

常用参数：

- `-n` 显示行号。
- `-i` 忽略大小写。
- `-v` 反向匹配，排除某些行。
- `-R` 递归搜索目录。

### 上下文搜索

```bash
grep -C 3 "Exception" app.日志
grep -A 20 "NullPointerException" app.日志
grep -B 10 "OutOfMemoryoryError" app.日志
```

说明：

- `-C` 显示前后文。
- `-A` 显示匹配行之后。
- `-B` 显示匹配行之前。

### 多条件组合

```bash
grep "ERROR" app.日志 | grep "orderId=1001"
grep "ERROR" app.日志 | grep -v "timeout"
```

排障时常用思路：

1. 先找错误等级。
2. 再加请求 ID、用户 ID、订单号等业务关键字。
3. 再排除无关噪声。

## 文本统计和处理

常用命令：

```bash
wc -l app.日志
sort access.日志
uniq -c
awk '{print $1}' access.日志
sed -n '100,150p' app.日志
```

示例：统计访问日志里请求最多的 IP：

```bash
awk '{print $1}' access.日志 | sort | uniq -c | sort -nr | head
```

示例：查看第 100 到 150 行：

```bash
sed -n '100,150p' app.日志
```

## 编辑文件

### Nano

`nano` 对新手更友好：

```bash
nano app.conf
```

常用操作：

- `Ctrl + O` 保存。
- `Enter` 确认文件名。
- `Ctrl + X` 退出。

### Vim

Vim 更常见，但需要理解模式：

```bash
vim app.conf
```

常用操作：

- `i` 进入插入模式。
- `Esc` 回到普通模式。
- `:w` 保存。
- `:q` 退出。
- `:wq` 保存并退出。
- `:q!` 不保存退出。
- `/keyword` 搜索。
- `dd` 删除当前行。
- `u` 撤销。

## 安全改配置流程

推荐流程：

```bash
cp nginx.conf nginx.conf.bak-$(date +%F-%H%M%S)
vim nginx.conf
nginx -t
systemctl reload nginx
```

对 systemd：

```bash
cp demo-接口.服务 demo-接口.服务.bak-$(date +%F-%H%M%S)
vim demo-接口.服务
systemctl daemon-reload
systemctl restart demo-接口
systemctl status demo-接口
```

对应用配置：

```bash
cp 应用配置.yml 应用配置.yml.bak-$(date +%F-%H%M%S)
vim 应用配置.yml
systemctl restart demo-接口
journalctl -u demo-接口 -n 100
```

## 比较文件差异

```bash
diff -u old.conf new.conf
```

用途：

- 查看配置改了哪些行。
- 复盘故障时确认变更范围。
- 回滚时知道要恢复什么。

## Windows 换行问题

如果脚本从 Windows 复制到 Linux，可能出现 `^M` 或执行失败。检查方式：

```bash
file deploy.sh
cat -A deploy.sh | head
```

修复方式：

```bash
dos2unix deploy.sh
```

如果没有 `dos2unix`，可以用编辑器保存为 Unix LF 换行。

## 难点

- `grep` 默认按行匹配，不适合直接匹配跨多行堆栈。
- 大文件不要用图形编辑器或直接 `cat` 全量输出。
- `sed -i` 会原地修改文件，执行前先备份。
- 编辑配置后只保存文件不代表服务已加载，需要重启或 reload。

## 重点

- 日志排查优先用 `less`、`tail`、`grep`，不要打开大文件硬翻。
- 改配置前备份，改后做语法检查。
- 搜索日志要结合时间、错误等级、请求 ID 和业务关键字。
- 编辑脚本要注意执行权限和换行格式。

## 练习

1. 创建一个包含 `INFO`、`WARN`、`ERROR` 的日志文件，用 `grep -n` 找出错误行。
2. 用 `sed -n` 查看第 5 到第 10 行。
3. 用 `diff -u` 比较两个配置文件的差异。
4. 用 Vim 打开文件，完成搜索、修改、保存和退出。
