# 02 文件与目录操作

## 作用

文件与目录操作是 Linux 运维的基本功。部署项目时要上传文件、解压包、创建目录、复制配置、清理旧版本、查看磁盘占用；排障时要找日志、查配置、定位大文件。这个章节重点建立安全、可控、可回滚的文件操作习惯。

## 痛点

- 不区分文件和目录权限，导致项目能启动但不能写日志。
- 使用相对路径误删或移动错误文件。
- 不会查大文件，磁盘满时只能盲目删除。
- 解压包直接覆盖当前目录，导致版本混乱。
- 不理解软链接，回滚时不知道 `current` 指向哪里。

## Linux 目录结构

常见目录：

| 目录 | 用途 | 运维注意点 |
| --- | --- | --- |
| `/bin`、`/usr/bin` | 系统命令 | 不要手动删除或覆盖 |
| `/etc` | 配置文件 | 改前备份，改后验证 |
| `/var` | 日志、缓存、运行数据 | 磁盘满常发生在这里 |
| `/var/日志` | 日志目录 | 排障重点 |
| `/opt` | 第三方应用 | 推荐放业务项目 |
| `/home` | 普通用户目录 | 用户脚本和配置 |
| `/root` | root 家目录 | 不建议放业务项目 |
| `/tmp` | 临时目录 | 可能被系统清理 |

## 查看文件和目录

```bash
ls
ls -l
ls -lah
ls -lt
ls -lhS
stat file.txt
file app.jar
```

说明：

- `-l` 显示权限、属主、大小、时间。
- `-a` 显示隐藏文件。
- `-h` 以人类可读方式显示大小。
- `-t` 按修改时间排序。
- `-S` 按文件大小排序。
- `stat` 查看更完整的时间和权限信息。
- `file` 判断文件类型。

## 创建目录和文件

```bash
mkdir 日志s
mkdir -p /opt/apps/demo-接口/shared/日志s
touch app.日志
```

使用技巧：

- `mkdir -p` 可以创建多级目录，目录已存在也不会报错。
- `touch` 常用于创建空文件或更新时间戳。
- 创建部署目录后立刻确认属主和权限。

## 复制、移动、重命名

```bash
cp app.jar app.jar.bak
cp -r 配置 配置.bak
mv app.jar /opt/apps/demo-接口/releases/
mv old-name new-name
```

使用技巧：

- 复制配置前建议带时间戳：`cp nginx.conf nginx.conf.bak-$(date +%F-%H%M%S)`。
- `mv` 在同一文件系统内通常很快，因为只是改目录项。
- 跨文件系统移动可能等价于复制后删除，时间更长。

## 删除文件

```bash
rm app.日志
rm -r old-dir
rm -rf old-dir
```

安全规则：

- 删除前先用 `ls` 确认目标。
- 使用通配符删除前先用 `ls pattern` 预览。
- 不要在变量为空时执行 `rm -rf "$dir"`，脚本里要检查变量。
- 不要把业务数据放在临时目录后再清理。

更稳妥的清理方式：

```bash
mkdir -p /tmp/delete-review
mv old-release /tmp/delete-review/
```

先移动到待删除目录，观察一段时间后再真正删除。

## 查找文件

```bash
find /opt/apps -name "*.日志"
find /var/日志 -type f -mtime -7
find /opt/apps -type f -size +100M
find /opt/apps -type d -name "日志s"
```

常见条件：

- `-name` 按名称匹配。
- `-type f` 只找文件。
- `-type d` 只找目录。
- `-mtime -7` 7 天内修改过。
- `-size +100M` 大于 100MB。

危险点：

```bash
find /opt/apps -name "*.日志" -delete
```

这种命令会直接删除匹配文件。先不加 `-delete` 预览结果，确认后再执行。

## 查看磁盘占用

```bash
df -h
du -sh /var/日志
du -h --max-depth=1 /opt/apps | sort -h
```

区别：

- `df` 看文件系统整体空间。
- `du` 看目录或文件实际占用。

磁盘满排查顺序：

1. `df -h` 找满的分区。
2. `du -h --max-depth=1 /目标目录 | sort -h` 找大目录。
3. 继续进入大目录逐层查。
4. 确认是否是日志、缓存、旧版本、上传文件。
5. 先压缩或迁移，再删除。

## 压缩和解压

常用 `tar`：

```bash
tar -czf app-日志s.tar.gz 日志s/
tar -xzf app-日志s.tar.gz
tar -tzf app-日志s.tar.gz | 未译83452
```

说明：

- `c` 创建压缩包。
- `x` 解压。
- `t` 查看压缩包内容。
- `z` 使用 gzip。
- `f` 指定文件名。

安全技巧：

- 解压前用 `tar -tf` 看压缩包内部路径。
- 不要在重要目录直接解压不明压缩包。
- 建议先解压到临时目录确认结构。

## 文件同步和传输

```bash
scp app.jar 用户@服务端:/opt/apps/demo-接口/releases/
rsync -avz dist/ 用户@服务端:/opt/apps/web/current/
```

`scp` 适合简单上传。`rsync` 适合目录同步、增量传输和部署静态资源。

使用 `rsync` 注意斜杠：

```bash
rsync -avz dist/ target/
rsync -avz dist target/
```

- `dist/` 表示同步目录里的内容。
- `dist` 表示把目录本身同步过去。

## 软链接

软链接常用于发布版本：

```bash
ln -sfn /opt/apps/demo-接口/releases/2026-05-11-120000 /opt/apps/demo-接口/current
readlink -f /opt/apps/demo-接口/current
```

用途：

- `current` 永远指向当前版本。
- 回滚时只需要切换软链接。
- systemd 和 Nginx 可以固定指向 `current`。

注意点：

- 删除软链接本身不会删除真实目录。
- 删除真实目录会让软链接变成失效链接。
- 使用 `readlink -f` 确认真正指向。

## 难点

- 目录的执行权限 `x` 表示能进入目录，不是执行目录。
- 文件删除权限取决于所在目录的写权限，不完全取决于文件本身权限。
- 软链接权限看起来通常是 `777`，真实权限取决于目标文件。
- `du` 和 `df` 结果不一致时，可能有已删除但仍被进程占用的文件。

## 重点

- 配置文件改前备份。
- 删除前预览目标范围。
- 部署目录、日志目录、上传目录要分开。
- 旧版本不要马上删，至少保留最近几个可回滚版本。

## 练习

3. 把 `日志s` 打包成 `日志s.tar.gz`，再解压到另一个目录。
4. 创建两个版本目录，用 `current` 软链接指向其中一个，再切换到另一个。
