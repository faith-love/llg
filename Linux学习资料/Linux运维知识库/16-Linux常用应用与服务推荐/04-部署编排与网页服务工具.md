# 04 部署编排与 Web 服务工具

部署编排工具负责让应用稳定运行、开机自启、异常重启、日志可查、入口可控。小型 Linux 项目通常从 `systemd + Nginx` 开始，Docker化场景再引入 Docker 和 Docker Compose。

## systemd

### 作用

systemd 是 Linux 原生服务管理器，用于托管长期运行的服务。

### 适合场景

- Java Jar 服务。
- Node.脚本/Python 后端服务。
- Worker 进程。
- 自定义脚本服务。

[Install]

### 常用命令

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now demo-接口
systemctl status demo-接口 --no-分页r
journalctl -u demo-接口 -f
sudo systemctl restart demo-接口
```

### 使用建议

- 长期服务优先用 systemd，不要长期使用 `nohup`。
- 服务使用独立用户运行。
- 配置、日志、上传目录权限分开。
- unit 文件纳入版本管理或模板管理。

## Nginx

### 作用

Nginx 是常用 Web 入口，可提供静态资源、Nginx、HTTPS、简单负载均衡。

### 适合场景

- 部署前端静态站点。
- Nginx后端 API。
- 配置域名、证书、HTTP 到 HTTPS 跳转。
- 统一入口限流和日志。

## Caddy

### 作用

Caddy 是现代 Web 服务端，自动 HTTPS 体验好，配置简单。

### 示例

```text
example.通用 {
    reverse_proxy 127.0.0.1:8080
}
```

静态站点：

```text
example.通用 {
    root * /var/www/demo-web
    file_服务端
    try_files {path} /首页.html
}
```

### 适合场景

- 小型站点快速启用 HTTPS。
- 个人项目。
- 配置复杂度不高的服务。

### 注意事项

- 企业环境 Nginx 更常见，仍建议先掌握 Nginx。
- 自动证书需要服务器公网可访问并正确解析域名。

## Supervisor

### 作用

Supervisor 是进程管理工具，可管理多个非守护进程。

### 示例

```ini
[program:demo-worker]
通用mand=/usr/bin/Python学习资料3 /opt/apps/demo-worker/worker.py
directory=/opt/apps/demo-worker
用户=app
autostart=true
autorestart=true
stdout_日志file=/var/日志/demo-worker.日志
stderr_日志file=/var/日志/demo-worker.err
```

常用命令：

```bash
supervisorctl status
supervisorctl restart demo-worker
```

### 使用建议

- 旧项目或多 worker 场景可用。
- 现代 Linux 生产环境优先 systemd。
- 不要和 systemd 重复管理同一个进程。

- 打包应用运行环境。

### 注意事项

- 数据必须使用 未译27462lume 持久化。
- 不要把生产密钥写进镜像。

- Docker日志要配置轮转。

## 选型建议

| 场景 | 推荐 |
| --- | --- |
| 单个后端服务 | systemd |
| 前端静态站点和反代 | Nginx |
| 小型 HTTPS 站点 | Caddy |
| 旧式多进程 worker | Supervisor |
| 本地依赖环境 | Docker Compose |
| 小规模Docker部署 | Docker Compose |
| 多机大规模Docker | Kubernetes |

## 发布验证清单

- 服务状态正常。
- 端口监听符合预期。
- Nginx 配置测试通过。
- 健康检查通过。
- 日志无明显错误。
- 重启后服务能自动恢复。
- 回滚路径明确。
