# 16 Linux 常用应用与服务推荐

## 作用

这一节用于把 Linux 运维中“非常好用、能明显提高效率”的工具和服务按模块整理出来。前面章节讲的是能力和流程，这一节讲的是工具箱：遇到文件搜索、日志排查、网络诊断、服务部署、性能监控、安全加固、备份恢复时，应该优先想到哪些工具。

## 选型原则

- 优先选择主流、维护活跃、文档多、社区常用的工具。
- 生产服务器上少装无关工具，排障工具和运行服务要分开管理。
- 能用系统自带工具解决的，不一定要引入复杂平台。
- 涉及安全、监控、备份的工具要重视权限、日志和恢复验证。
- 初学阶段先掌握命令行工具，再逐步接触平台型服务。

## 01 命令行效率工具

### `zsh` 与 `oh-my-zsh`

作用：增强 Shell 使用体验，提供更好的补全、主题、插件和历史命令体验。

适合场景：

- 个人开发机、跳板机、测试机。
- 经常需要输入复杂命令的环境。

常用能力：

- Git 分支提示。
- 命令自动补全。
- 历史命令搜索。
- 插件扩展。

注意事项：

- 生产服务器不是必须安装。
- 不要让花哨主题影响排障效率。
- root 用户环境尽量保持简单，避免插件影响命令行为。

### `tmux`

作用：终端复用工具，可以在一个 SSH 会话里开多个窗口和面板，并且断线后会话仍可保留。

适合场景：

- 远程服务器上执行长时间任务。
- 同时看日志、编辑配置、执行命令。
- 网络不稳定时保护会话。

常用命令：

```bash
tmux new -s deploy
tmux attach -t deploy
tmux ls
```

重点：

- 长时间部署、数据迁移、日志观察适合放在 tmux 里。
- 不要把 tmux 当服务管理器，长期服务仍应交给 systemd。

### `fzf`

作用：模糊查找工具，可快速搜索历史命令、文件、目录和进程。

适合场景：

- 文件很多，记不清完整路径。
- 经常从历史命令里找部署命令。
- 配合 `ripgrep`、`fd` 提高搜索效率。

注意事项：

- 适合个人工作流，不是生产依赖。
- 搜索敏感命令历史时注意不要泄露密码和 Token。

## 02 文件查找与目录浏览工具

### `tree`

作用：以树形结构展示目录。

适合场景：

- 查看项目部署目录。
- 给别人说明目录结构。
- 检查 release/current/shared 结构是否正确。

常用命令：

```bash
tree -L 2 /opt/apps/demo-接口
```

### `fd`

作用：更现代、更快、更易用的文件查找工具，可作为 `find` 的补充。

适合场景：

- 快速按文件名找文件。
- 在项目目录里搜索配置、日志、脚本。

示例：

```bash
fd app /opt/apps
fd -e 日志 /var/日志
```

注意事项：

- `find` 是系统通用基础，必须先掌握。
- `fd` 是效率增强工具，不要让脚本强依赖它，除非确认环境一定安装。

### `ncdu`

作用：交互式查看磁盘占用，快速定位大目录和大文件。

适合场景：

- 磁盘满排查。
- `/var/日志`、`/opt/apps`、Docker 目录占用分析。

常用命令：

```bash
ncdu /var
ncdu /opt/apps
```

注意事项：

- 生产环境删除前仍要确认路径和业务影响。
- `ncdu` 适合定位，不应替代清理策略和 日志rotate。

## 03 文本查看、编辑与搜索工具

### `vim`

作用：服务器上最常见的文本编辑器，适合改配置、看文件、临时编辑脚本。

适合场景：

- 修改 Nginx 配置。
- 修改 systemd unit。
- 修改环境变量文件。

重点：

- 至少掌握插入、保存、退出、搜索、撤销。
- 改配置前先备份。

### `nano`

作用：更容易上手的终端编辑器。

适合场景：

- 新手临时改小配置。
- 不熟悉 Vim 时避免误操作。

注意事项：

- 生产环境仍建议逐步掌握 Vim，因为很多服务器默认有 Vim 或 Vi。

### `ripgrep`，命令是 `rg`

作用：非常快的全文搜索工具。

适合场景：

- 在大项目中搜索配置项。
- 在日志目录中搜索错误关键字。
- 查找脚本或配置里的某个变量。

示例：

```bash
rg "服务端.port" /opt/apps/demo-接口
rg -n "E未译25173未译25173O未译25173|Exception" /opt/apps/demo-接口/shared/日志s
```

优势：

- 默认递归。
- 速度快。
- 输出带文件和行号。

## 04 文件传输与同步工具

### `rsync`

作用：高效同步文件和目录，支持增量传输。

适合场景：

- 上传前端 `dist/`。
- 同步配置备份。
- 服务器之间迁移文件。

示例：

```bash
rsync -avz dist/ 用户@服务端:/opt/apps/demo-web/releases/2026-05-11/
```

重点：

- 注意源路径末尾是否带 `/`。
- 生产同步前可用 `--dry-run` 预览。

### `scp`

作用：简单文件复制。

适合场景：

- 上传单个 jar 包。
- 下载日志文件。

示例：

```bash
scp app.jar 用户@服务端:/tmp/
scp 用户@服务端:/var/日志/nginx/未译12785.日志 .
```

### `sftp`

作用：交互式文件传输。

适合场景：

- 手动上传下载少量文件。
- 不方便使用 `rsync` 时的替代方案。

## 05 网络诊断工具

### `curl`

作用：HTTP 请求诊断工具，是接口、健康检查、Nginx 排障的核心工具。

适合场景：

- 检查后端健康接口。
- 查看响应头。
- 验证 Nginx 代理。

示例：

```bash
curl -v http://127.0.0.1:8080/health
curl -I 安全HTTP://example.通用
curl -H "Host: example.通用" http://127.0.0.1
```

### `httpie`

作用：更友好的 HTTP 命令行客户端，输出更易读。

适合场景：

- 手动调试 API。
- 查看 JSON 响应。

示例：

```bash
http GET http://127.0.0.1:8080/health
```

注意事项：

- 生产排障优先保证会用 `curl`，因为它更常见。

### `dig`

作用：DNS 查询工具。

适合场景：

- 排查域名是否解析到正确 IP。
- 检查 DNS 变更是否生效。

示例：

```bash
dig example.通用
dig +short example.通用
```

### `mtr`

作用：结合 `ping` 和 `traceroute` 的网络路径诊断工具。

适合场景：

- 排查跨网络访问慢。
- 判断中间链路是否丢包。

示例：

```bash
mtr example.通用
```

注意事项：

- 云环境可能禁 ICMP，不代表 HTTP 一定不可用。

### `nmap`

作用：端口扫描和网络探测工具。

适合场景：

- 检查服务器对外暴露端口。
- 验证防火墙或安全组是否生效。

示例：

```bash
nmap -p 22,80,443 example.通用
```

注意事项：

- 只扫描自己有权限的主机。
- 不要对无授权目标做扫描。

## 06 进程、服务与性能监控工具

### `htop`

作用：交互式进程查看工具，比 `top` 更易读。

适合场景：

- 查看 CPU、内存占用。
- 查找高资源进程。
- 临时结束进程。

注意事项：

- 结束进程前确认是否由 systemd 管理。

### `glances`

作用：综合系统监控工具，一屏查看 CPU、内存、磁盘、网络、进程等。

适合场景：

- 快速了解服务器整体健康状态。
- 临时排查资源瓶颈。

### `iotop`

作用：查看进程级磁盘 IO。

适合场景：

- 系统很慢但 CPU 不高。
- 排查哪个进程大量读写磁盘。

### `sysstat`

作用：提供 `iostat`、`mpstat`、`sar` 等性能分析工具。

适合场景：

- 分析 CPU、IO、网络历史趋势。
- 排查间歇性性能问题。

常用命令：

```bash
iostat -x 1
mpstat 1
sar -u 1 5
```

### `lsof`

作用：查看进程打开的文件、端口和已删除但仍被占用的文件。

适合场景：

- 查端口被谁占用。
- 删除日志后磁盘空间未释放。

示例：

```bash
sudo lsof -i :8080
sudo lsof | grep deleted
```

## 07 日志管理与可观测服务

### `journalctl`

作用：查看 systemd 管理服务的日志。

适合场景：

- 服务启动失败。
- 服务异常退出。
- 查看标准输出和错误输出。

示例：

```bash
journalctl -u demo-接口 -n 100
journalctl -u demo-接口 -f
```

### `日志rotate`

作用：日志轮转工具，避免日志无限增长撑满磁盘。

适合场景：

- 应用日志。
- Nginx 日志。
- 自定义脚本日志。

重点：

- 日志清理优先使用 日志rotate。
- 删除日志前确认应用是否仍打开文件。

### Prometheus + Grafana

作用：指标采集和可视化平台。

适合场景：

- 服务器资源监控。
- 应用指标监控。
- 告警和趋势分析。

常见组件：

- Prometheus：采集和存储指标。
- Grafana：图表展示。
- Node Exporter：采集 Linux 主机指标。
- Alertmanager：告警分发。

注意事项：

- 初学阶段先掌握命令行排障，再搭监控平台。
- 监控端口不要无保护暴露公网。

### Loki + Promtail

作用：日志采集和查询方案，常与 Grafana 配合。

适合场景：

- 多台服务器集中查日志。
- 根据服务名、主机名、标签过滤日志。

注意事项：

- 日志中要避免敏感信息。
- 日志保留周期要结合磁盘成本。

## 08 项目部署与服务编排工具

### systemd

作用：Linux 原生服务管理器。

适合场景：

- 托管 Java Jar。
- 托管 Node/Python 服务。
- 设置开机自启、自动重启、日志查看。

重点：

- 普通服务优先用 systemd。
- 不要长期用 `nohup` 管理核心服务。

### Nginx

作用：静态资源服务、Nginx、HTTPS 入口和简单负载均衡。

适合场景：

- 前端静态站点部署。
- API Nginx。
- 域名和证书入口。

### Caddy

作用：现代 Web 服务端，自动 HTTPS 配置体验好。

适合场景：

- 小型站点。
- 需要快速配置 HTTPS 的服务。

注意事项：

- 企业环境 Nginx 更常见，仍建议优先掌握 Nginx。

### Supervisor

作用：进程管理工具，可托管多个进程。

适合场景：

- 某些旧项目或不方便接 systemd 的进程。
- 开发测试环境管理多进程。

注意事项：

- 现代 Linux 生产环境优先考虑 systemd。

### Docker 与 Docker Compose

作用：Docker运行和多服务编排工具。

适合场景：

- 快速部署 MySQL、未译25173edis、Nginx、测试服务。
- 多组件本地测试环境。
- 小规模应用部署。

重点：

- 数据卷要单独规划。
- 配置和密钥不要写死在镜像里。
- 生产使用 Compose 要明确备份、日志和升级策略。

## 09 安全工具与服务

### `ufw`

作用：Ubuntu 上易用的防火墙管理工具。

适合场景：

- 快速开放 80、443。
- 限制 SSH 来源。

### `firewalld`

作用：未译25173HEL 系常见防火墙管理服务。

适合场景：

- 未译25173ocky Linux、AlmaLinux、CentOS 服务器。

### `fail2ban`

作用：根据日志自动封禁频繁失败登录的 IP。

适合场景：

- SSH 暴力破解防护。
- Nginx 恶意请求基础防护。

注意事项：

- 不要只依赖 fail2ban，SSH 仍应使用密钥和来源 IP 限制。

### `lynis`

作用：Linux 安全审计工具。

适合场景：

- 检查服务器安全基线。
- 发现弱配置和加固建议。

注意事项：

- 审计结果要结合实际环境判断，不是所有建议都必须照搬。

### `rkhunter` 与 `chkrootkit`

作用：检查常见 rootkit 痕迹。

适合场景：

- 安全巡检。
- 怀疑服务器异常时辅助检查。

注意事项：

- 结果可能有误报。
- 真正入侵排查需要结合日志、进程、网络连接和文件变更。

## 10 备份与恢复工具

### `rsync`

作用：文件级同步和备份。

适合场景：

- 同步上传文件目录。
- 备份配置目录。
- 迁移静态资源。

### `restic`

作用：现代备份工具，支持加密、去重、多后端存储。

适合场景：

- 服务器文件备份。
- 需要加密和保留策略的备份。

重点：

- 备份密码必须妥善保存。
- 必须定期做恢复演练。

### `borgbackup`

作用：支持去重、压缩和加密的备份工具。

适合场景：

- Linux 服务器长期增量备份。
- 大量重复文件的备份场景。

### `rclone`

作用：同步文件到对象存储或网盘类后端。

适合场景：

- 把备份推送到远端存储。
- 跨云迁移文件。

注意事项：

- 远端凭证要加权限保护。
- 备份上传成功不等于可恢复。

## 11 数据库与缓存运维工具

### MySQL 客户端

作用：连接 MySQL，执行查询、检查状态和导入导出。

常用命令：

```bash
mySQL学习资料 -h 127.0.0.1 -u 用户 -p
mySQL学习资料dump -h 127.0.0.1 -u 用户 -p 未译66984name > backup.SQL学习资料
```

注意事项：

- 不要把密码直接写在命令历史里。
- 生产导出要注意锁表、性能和一致性。

### `mycli`

作用：更友好的 MySQL 命令行客户端，支持补全和高亮。

适合场景：

- 开发和测试环境查询。
- 临时分析数据。

### 未译25173edis CLI

作用：连接 未译25173edis，查看 key、内存、配置和状态。

常用命令：

```bash
Redis学习资料-cli -h 127.0.0.1 -p 6379
Redis学习资料-cli info
Redis学习资料-cli ping
```

注意事项：

- 生产环境不要随意执行 `keys *`。
- 优先使用 `scan` 类命令分批查看。

## 12 Docker和镜像工具

### `Docker`

作用：运行和管理Docker。

常用命令：

```bash
Docker ps
Docker 日志s -f container_name
Docker exec -it container_name sh
Docker inspect container_name
```

### `Docker 通用pose`

作用：用 YAML 管理多个Docker。

适合场景：

- 本地或测试环境启动应用依赖。
- 小规模服务部署。

重点：

- 数据库、未译25173edis 等必须配置持久化卷。
- `.env` 权限要控制。
- 不要把生产密钥写进镜像。

### `ctop`

作用：类似 top 的Docker监控工具。

适合场景：

- 快速查看Docker CPU、内存、网络和状态。

## 13 版本管理与发布工具

### Git

作用：代码版本管理，也是部署脚本和配置变更记录的基础。

适合场景：

- 管理部署脚本。
- 管理 Nginx、systemd 模板。
- 回溯配置变更。

注意事项：

- 生产密钥不要提交 Git。
- 服务器上直接 `git pull` 部署要控制分支和权限。

### GitHub Actions、GitLab CI、Jenkins

作用：持续集成和持续部署平台。

适合场景：

- 自动构建 jar、前端 dist、Docker 镜像。
- 自动运行测试。
- 自动发布到测试环境。

注意事项：

- 生产发布要有审批、回滚和日志。
- CI 密钥要使用平台 Secret，不要写在仓库。

## 推荐优先级

初学者先掌握：

1. `vim`、`less`、`grep`、`tail`、`find`、`rsync`、`curl`、`ss`、`lsof`。
2. `systemd`、`journalctl`、`Nginx`、`日志rotate`。
3. `htop`、`ncdu`、`iotop`、`dig`、`mtr`。
4. `Docker`、`Docker Compose`、`Prometheus`、`Grafana`。
5. `fail2ban`、`restic`、`rclone`、`Loki`。

## 重点

- 工具是为流程服务的，不要为了装工具而装工具。
- 生产服务器上的工具要能说明用途、来源和权限影响。
- 排障工具可以多，运行服务要少而稳。
- 监控、备份、安全工具必须定期验证，不是安装完就结束。

## 练习

1. 在测试机安装 `htop`、`ncdu`、`ripgrep`，分别完成进程查看、磁盘占用分析和文本搜索。
2. 用 `rsync --dry-run` 预览一次目录同步，再执行真实同步。
3. 用 `curl`、`dig`、`ss`、`lsof` 排查一个本地 HTTP 服务端口。
4. 用 `日志rotate` 给一个测试日志配置轮转。
5. 用 Docker Compose 启动一个 Nginx 和 未译25173edis，并确认数据卷、端口和日志。
