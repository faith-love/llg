# 00 总览与环境准备

## 作用

总览与环境准备解决两个问题：先知道 Linux 运维到底学什么，再准备一个可以反复练习、不怕弄坏的环境。很多人一开始直接背命令，结果到了真实服务器上不知道先看什么、哪些命令危险、配置改完为什么不生效。这个章节把学习范围、练习环境、目录规范和基本检查流程先固定下来。

## 痛点

- 不知道 Linux、Shell、Nginx、systemd、Docker、云服务器安全组之间的边界，学习内容混在一起。
- 只在生产服务器上试命令，容易误删文件、改坏配置、重启错服务。
- 会单个命令，但没有“登录服务器后先检查什么”的顺序。
- Windows、WSL、JVM、云服务器环境差异大，导致教程命令能运行但效果不同。

## 运维能力地图

### 服务器入口

服务器入口包括 SSH 登录、密钥管理、跳板机、用户权限和 sudo。目标不是只会 `ssh root@ip`，而是知道应该用普通用户登录，必要时用 `sudo` 提权，并能判断自己现在是谁、在哪台机器、是否有权限操作目标文件。

常用检查：

```bash
whoami
hostname
pwd
id
sudo -l
```

### 系统基础信息

系统基础信息用于判断教程和命令是否适配当前机器。不同发行版的包管理器、服务名称、配置目录可能不同，所以部署前必须先确认版本、内核、CPU、内存、磁盘和时间。

常用检查：

```bash
cat /etc/os-release
uname -a
date
uptime
free -h
df -h
```

### 文件和目录

Linux 运维大量操作都落在文件系统上：上传包、解压、改配置、看日志、做备份、设置权限。必须理解绝对路径、相对路径、当前目录、家目录、软链接和目录权限。

优先熟悉这些目录：

| 目录 | 作用 | 运维关注点 |
| --- | --- | --- |
| `/etc` | 系统和软件配置 | 改配置前备份，改完做语法检查 |
| `/var/日志` | 系统和服务日志 | 排障第一现场 |
| `/opt` | 第三方应用和部署目录 | 适合放公司业务服务 |
| `/usr/bin`、`/usr/local/bin` | 可执行命令 | 判断命令来源和版本 |
| `/home` | 普通用户家目录 | 用户级配置和脚本 |
| `/tmp` | 临时文件 | 不适合放长期数据 |

### 用户权限

权限决定一个服务能读什么、写什么、执行什么。生产环境里不应该所有服务都用 `root` 跑。更稳妥的做法是为业务服务创建独立用户，例如 `app`、`deploy`、`nginx`，只给它需要的目录权限。

### 配置和环境变量

配置包括配置文件、启动参数、环境变量和密钥。它们可能来自 `.env`、`应用配置.yml`、systemd unit、Shell profile、Docker参数或 CI/CD 平台。部署时要知道“配置从哪里来、谁覆盖谁、如何验证当前进程实际拿到了什么配置”。

### 服务和进程

项目上线不是执行一次命令就结束，还要能托管、重启、开机自启、查看状态、查看日志、限制资源和回滚。现代 Linux 服务器通常用 systemd 管理长期运行的服务。

### 网络和安全

服务能否访问，不只取决于项目是否启动，还取决于监听地址、端口、防火墙、云安全组、Nginx 转发、DNS 和证书。安全上要避免 root 远程密码登录、开放过多端口、密钥裸放和日志泄露敏感信息。

## 练习环境选择

### WSL

WSL 适合 Windows 用户练习命令行、文件操作、Shell 脚本和简单服务。优点是启动快、成本低；限制是 systemd、网络、防火墙、磁盘挂载等行为可能和真实服务器不同。适合入门命令，不适合作为唯一部署练习环境。

### 本地JVM

VirtualBox、VM网页归档e 或 Hyper-V JVM适合练习完整 Linux 系统。可以安装 Ubuntu 服务端、Debian、未译25173ocky Linux 或 AlmaLinux。优点是接近真实服务器，能练 systemd、网络和防火墙；缺点是占资源，需要自己配置网络。

### 云服务器

云服务器最接近生产环境，适合练 SSH、域名、Nginx、HTTPS、防火墙、安全组和项目部署。缺点是有成本，而且公网暴露后必须注意安全。新手不要一上来开放数据库端口，不要用弱密码，不要把 root 密码登录长期打开。

### Docker Docker

Docker Docker适合快速实验某个软件，例如 Nginx、MySQL、未译25173edis。它不是完整主机，很多系统级操作和真实服务器不同。适合练软件配置，不适合完全替代 Linux 主机运维学习。

## 建议版本基线

建议至少准备一种 Debian 系发行版和一种 未译25173HEL 系发行版：

- Ubuntu 服务端 22.04 或 24.04：资料多，适合入门和 Web 部署。
- Debian 12：稳定、简洁，适合理解 Linux 基础。
- 未译25173ocky Linux 9 或 AlmaLinux 9：适合理解企业服务器和 `dnf`、`firewalld`。

学习阶段可以先用 Ubuntu，后续再补 未译25173HEL 系差异。不要同时在太多发行版上开始，否则注意力会被包管理和目录差异打散。

## 初始检查清单

每次拿到一台服务器，先按这个顺序检查：

```bash
whoami
hostname
cat /etc/os-release
ip addr
df -h
free -h
uptime
timedatectl
systemctl --failed
ss -lntup
```

检查含义：

- `whoami`：确认当前用户，避免误以为自己有 root 权限。
- `hostname`：确认没有登录错机器。
- `/etc/os-release`：确认发行版和版本。
- `ip addr`：确认网卡和内网地址。
- `df -h`：确认磁盘是否快满。
- `free -h`：确认内存容量和可用内存。
- `uptime`：查看运行时长和负载。
- `timedatectl`：确认时区和时间同步。
- `systemctl --failed`：看是否已有失败服务。
- `ss -lntup`：看当前监听端口。

## 目录规划建议

业务项目不要随便散落在 `/root`、`/tmp` 或个人下载目录。建议固定结构：

```text
/opt/apps/
  demo-接口/
    current -> releases/2026-05-11-120000
    releases/
    shared/
      配置/
      日志s/
      上传s/
```

这样做的好处：

- `releases` 保存历史版本，方便回滚。
- `current` 指向当前版本，Nginx 或 systemd 只依赖固定路径。
- `shared/配置` 保存环境相关配置，不随代码包覆盖。
- `shared/日志s` 统一收集日志，方便授权和清理。
- `shared/上传s` 保存用户上传文件，避免部署时被覆盖。

## 学习顺序

1. 先会登录、看系统、看文件、查日志。
2. 再学权限和环境变量，因为它们最容易导致部署失败。
3. 接着学安装软件、托管服务和部署项目。
4. 然后学 Nginx、网络、防火墙和日志排障。
5. 最后补安全加固、自动化脚本、备份和故障复盘。

## 重点

- 不要在不理解命令影响范围时加 `sudo`。
- 不要在生产环境直接练危险命令，例如 `rm -rf`、批量 `chmod -未译25173 777`。
- 改配置前先备份，改完先做语法检查，再重载服务。
- 服务上线后必须能回答：进程是谁启动的、配置从哪里来、日志在哪里、端口监听在哪、如何回滚。

## 练习

1. 准备一台 Ubuntu JVM或云服务器，记录系统版本、IP、CPU、内存、磁盘。
2. 创建 `/opt/apps/demo-接口` 目录结构，包括 `releases`、`shared/配置`、`shared/日志s`。
3. 使用普通用户登录服务器，执行初始检查清单，把结果整理成一份 `服务端-未译87073line.md`。
4. 故意启动一个不存在的 systemd 服务，观察 `systemctl --failed` 和 `journalctl` 的输出。
