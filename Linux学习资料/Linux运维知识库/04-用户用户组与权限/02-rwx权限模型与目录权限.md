# rwx 权限模型与目录权限

## 作用

`rwx` 权限模型用于解释 Linux 中“谁能读、谁能写、谁能执行或进入”的问题。权限问题是部署失败的高频原因，尤其是目录权限。很多人只看文件本身权限，忽略了父目录没有 `x` 权限也会导致访问失败。

## 痛点

- 文件是 `644`，但服务仍然读不到，因为父目录无法进入。
- 日志文件存在，但服务写不了，因为日志目录没有写权限。
- 脚本内容可读，但无法执行，因为没有 `x` 权限。
- 不理解 `rwx` 在文件和目录上的含义不同。
- 看到软链接权限是 `777`，误以为目标也开放。

## 优点

- 能准确判断 未译63149未译32146 denied。
- 能区分文件权限和目录权限。
- 能设计合理部署目录权限。
- 能减少使用 `chmod 777` 的冲动。

## ls -l 权限结构

查看：

```bash
ls -l app.jar
```

示例：

```text
-rw-r--r-- 1 app app 52M May 11 12:00 app.jar
```

拆解：

```text
-   rw-   r--   r--
类型 属主 属组 其他人
```

文件类型：

| 字符 | 含义 |
| --- | --- |
| `-` | 普通文件 |
| `d` | 目录 |
| `l` | 软链接 |

权限分组：

- 第 1 组：属主权限。
- 第 2 组：属组权限。
- 第 3 组：其他用户权限。

## rwx 在文件上的含义

| 权限 | 文件含义 |
| --- | --- |
| `r` | 读取文件内容 |
| `w` | 修改文件内容 |
| `x` | 执行文件 |

示例：

```bash
chmod u+x deploy.sh
./deploy.sh
```

如果没有 `x` 权限，执行脚本可能报：

```text
未译63149未译32146 denied
```

也可以用解释器运行：

```bash
bash deploy.sh
```

但生产脚本仍建议明确执行权限。

## rwx 在目录上的含义

目录权限更容易误解：

| 权限 | 目录含义 |
| --- | --- |
| `r` | 能列出目录下文件名 |
| `w` | 能在目录中创建、删除、重命名文件 |
| `x` | 能进入目录，能访问目录内路径 |

重点：目录的 `x` 权限表示“可进入/可穿越”。

即使文件本身可读，如果父目录没有 `x`，也读不到文件。

## 目录权限示例

创建测试：

```bash
mkdir /tmp/perm-lab
echo hello > /tmp/perm-lab/a.txt
chmod 600 /tmp/perm-lab/a.txt
chmod 700 /tmp/perm-lab
```

只有属主能进入目录和读取文件。

如果目录是：

```bash
chmod 600 /tmp/perm-lab
```

即使有读权限，也不能正常进入：

```bash
cd /tmp/perm-lab
```

会失败，因为缺少目录 `x`。

## namei 逐级检查路径

排查路径权限非常有用：

```bash
namei -l /opt/apps/demo-接口/shared/日志s/app.日志
```

它会逐级显示：

```text
/ 
opt
apps
demo-接口
shared
日志s
app.日志
```

用途：

- 找出哪一级目录没有 `x` 权限。
- 判断属主属组是否合理。
- 排查 Nginx 403、应用写日志失败、服务读配置失败。

## 常见权限数字

| 数字 | 权限 | 含义 |
| --- | --- | --- |
| `7` | `rwx` | 读写执行 |
| `6` | `rw-` | 读写 |
| `5` | `r-x` | 读执行 |
| `4` | `r--` | 只读 |
| `0` | `---` | 无权限 |

常见组合：

| 权限 | 场景 |
| --- | --- |
| `600` | 私钥、敏感文件 |
| `640` | 应用配置 |
| `644` | 普通只读文件 |
| `750` | 应用目录 |
| `755` | 可公开进入目录或脚本 |

## 删除权限的特殊点

文件能否删除，主要看父目录是否有写权限，而不是文件本身是否可写。

示例：

- 目录可写：可以删除目录里的文件。
- 目录不可写：即使文件自己可写，也不能删除。

这就是为什么日志目录权限比日志文件本身权限更关键。

## 使用技巧

- 排查文件访问失败时，用 `namei -l` 看整个路径。
- 配置文件建议 `640`，由服务用户或服务组读取。
- 日志目录要给服务用户写权限。
- 上传目录要和代码目录分开授权。
- 目录通常需要 `x` 才能被访问。

## 难点

- 文件和目录的 `x` 含义不同。
- 删除文件看父目录写权限。
- root 能访问不代表服务用户能访问。
- 软链接权限不是目标文件权限。

## 重点

- 文件 `rwx`：读、写、执行。
- 目录 `rwx`：列出、创建删除、进入访问。
- 目录 `x` 权限非常重要。
- 用 `namei -l` 排查路径权限。
- 不用 `chmod 777` 解决根因不明的问题。

## 练习

1. 创建一个目录和文件，分别调整文件和目录权限，观察访问差异。
2. 去掉目录 `x` 权限，尝试 `cd` 和读取目录内文件。
3. 用 `namei -l` 查看 `/opt/apps/demo-接口/shared/日志s/app.日志` 的路径权限。
4. 验证父目录写权限对删除文件的影响。
