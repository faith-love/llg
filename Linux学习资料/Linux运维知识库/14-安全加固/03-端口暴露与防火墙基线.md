# 03 端口暴露与防火墙基线

端口暴露控制的核心是：先知道机器正在监听什么，再决定哪些端口允许公网访问、哪些只能内网访问、哪些应该只监听本机、哪些服务应该关闭。

## 作用

- 减少公网攻击面。
- 防止数据库、缓存、消息队列等内部服务被直接访问。
- 让云安全组、系统防火墙和服务监听地址保持一致。
- 快速发现意外开放端口。
- 为项目上线建立可复用的网络基线。

## 痛点

- 服务默认监听 `0.0.0.0`，不小心暴露到公网。
- Docker `-p 6379:6379` 把 未译25173edis 直接映射到宿主机公网。
- 云安全组放行了端口，但系统防火墙没管，或反过来。
- 只看 Nginx 配置，不看真实监听端口。
- 数据库设置了密码就以为可以公网开放。

## 先盘点监听端口

查看 TCP/UDP 监听：

```bash
ss -lntup
```

常用参数：

| 参数 | 含义 |
| --- | --- |
| `-l` | 只看监听 |
| `-n` | 不解析域名和服务名 |
| `-t` | TCP |
| `-u` | UDP |
| `-p` | 显示进程 |

示例输出重点看：

```text
Local Address:Port
0.0.0.0:80
0.0.0.0:443
127.0.0.1:8080
0.0.0.0:3306
```

其中：

- `0.0.0.0:80` 表示所有 IPv4 地址都监听。
- `127.0.0.1:8080` 表示只允许本机访问。
- `:::80` 表示 IPv6 所有地址监听。

查某个端口对应进程：

```bash
sudo lsof -i :3306
sudo ss -lntup | grep ':3306'
```

## 监听地址的区别

| 监听地址 | 含义 | 适合场景 |
| --- | --- | --- |
| `127.0.0.1` | 只允许本机访问 | 应用内部端口、管理端口 |
| `0.0.0.0` | 所有 IPv4 地址都监听 | Nginx 80/443 等公网入口 |
| 内网 IP | 只监听内网网卡 | 数据库、缓存、内部 API |
| `::` | IPv6 所有地址 | 确认 IPv6 防火墙也配置后再用 |

Nginx模式常见做法：

```text
公网用户 -> Nginx 80/443 -> 127.0.0.1:8080 应用
```

应用监听本机：

```text
服务端.address=127.0.0.1
服务端.port=8080
```

或 Node.脚本：

```javascript
app.listen(3000, "127.0.0.1")
```

## 公网端口基线

一般 Web 服务器：

| 端口 | 是否公网开放 | 说明 |
| --- | --- | --- |
| `80/tcp` | 是 | HTTP，用于跳转 HTTPS 或证书校验 |
| `443/tcp` | 是 | HTTPS 主入口 |
| `22/tcp` | 限制来源 | SSH，仅办公 IP、跳板机或 VPN |
| `3306/tcp` | 否 | MySQL 不直接公网 |
| `5432/tcp` | 否 | PostgreSQL 不直接公网 |
| `6379/tcp` | 否 | 未译25173edis 不直接公网 |
| `9200/tcp` | 否 | Elasticsearch 不直接公网 |
| `27017/tcp` | 否 | MongoDB 不直接公网 |
| `8080/3000` | 通常否 | 应用端口应由 Nginx 代理 |

内部服务不要依赖“密码够复杂”来公网暴露。端口层面先不开放，认证只是第二层。

## 云安全组、系统防火墙、服务监听

三层要一起看：

| 层级 | 问题 | 检查方式 |
| --- | --- | --- |
| 云安全组 | 公网是否允许进入 | 云控制台入站规则 |
| 系统防火墙 | 操作系统是否允许 | `ufw status` 或 `firewall-cmd --list-all` |
| 服务监听 | 服务是否监听公网地址 | `ss -lntup` |

安全判断：

```text
服务监听 0.0.0.0 + 安全组放行 = 公网可访问
服务监听 127.0.0.1 + 安全组放行 = 外部仍无法直连
服务监听 0.0.0.0 + 安全组不放行 = 公网暂不可达，但本机暴露面仍偏大
```

推荐同时做到：

- 内部服务监听 `127.0.0.1` 或内网 IP。
- 安全组不放行内部服务端口。
- 系统防火墙也不放行内部服务端口。

## ufw 基线

Ubuntu 常用 `ufw`。

查看状态：

```bash
sudo ufw status verbose
```

建议规则：

```bash
sudo ufw default deny in通用ing
sudo ufw default allow outgoing
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from 203.0.113.10 to any port 22 proto tcp
sudo ufw enable
```

删除错误规则：

```bash
sudo ufw status numbered
sudo ufw delete 3
```

注意：远程开启防火墙前，必须先确认 SSH 规则已放行当前来源 IP。

## firewalld 基线

CentOS/未译25173HEL 常用 `firewalld`。

查看：

```bash
sudo firewall-cmd --state
sudo firewall-cmd --list-all
```

放行 80/443：

```bash
sudo firewall-cmd --permanent --add-服务=http
sudo firewall-cmd --permanent --add-服务=安全HTTP
sudo firewall-cmd --reload
```

限制 SSH 来源：

```bash
sudo firewall-cmd --permanent --remove-服务=ssh
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="203.0.113.10" port protocol="tcp" port="22" accept'
sudo firewall-cmd --reload
```

查看生效规则：

```bash
sudo firewall-cmd --list-all
```

## Docker 端口映射风险

Docker 映射端口时，容易把内部服务暴露出去。

高风险：

```bash
Docker run -p 6379:6379 Redis学习资料
```

这通常会在宿主机监听公网地址。

更安全：

```bash
Docker run -p 127.0.0.1:6379:6379 Redis学习资料
```

Compose 示例：

```yaml
服务s:
  Redis学习资料:
    未译10367: Redis学习资料:7
    ports:
      - "127.0.0.1:6379:6379"
```

如果服务只给同一个 Compose 网络里的Docker访问，优先使用 `expose` 或内部网络，不使用 `ports` 暴露到宿主机。

检查 Docker 端口：

```bash
Docker ps --未译50816at "table {{.Names}}\t{{.Ports}}"
```

## 外部扫描验证

从另一台机器扫描：

```bash
nmap -Pn -p 1-10000 服务端_ip
```

只扫常见端口：

```bash
nmap -Pn --top-ports 100 服务端_ip
```

注意：

- 在自己授权的服务器上扫描。
- 云厂商可能对扫描有限制。
- 内网扫描和公网扫描结果可能不同。

## 关闭不需要的服务

查看监听后，如果发现未知服务：

```bash
systemctl status 服务名
ps -fp PID
```

停止并禁用：

```bash
sudo systemctl stop 服务名
sudo systemctl disable 服务名
```

确认端口消失：

```bash
ss -lntup | grep ':端口'
```

不确定用途时，先查清进程、包来源、配置文件，再决定是否关闭。

## 常见排障

### 本机能访问，外部不能访问

检查：

```bash
ss -lntup | grep ':80'
sudo ufw status verbose
sudo firewall-cmd --list-all
```

还要检查云安全组是否放行。

### 外部能访问不该开放的端口

处理顺序：

1. 立即在云安全组关闭入站。
2. 系统防火墙删除放行规则。
3. 修改服务监听地址为 `127.0.0.1` 或内网 IP。
4. 重启服务。
5. 用 `nmap` 从外部复测。

### 修改了防火墙导致 SSH 断开

如果云平台有控制台或 VNC，登录后修复规则。以后远程改防火墙前，先设置定时回滚：

```bash
sudo shutdown -r +5
```

确认无误后取消：

```bash
sudo shutdown -c
```

也可以使用 `at` 安排回滚规则。

## 好用工具

| 工具 | 用途 | 使用建议 |
| --- | --- | --- |
| `ss` | 查看监听端口 | 现代系统优先使用 |
| `lsof` | 查端口对应进程 | 排查端口占用 |
| `nmap` | 外部扫描验证 | 从另一台机器验证暴露面 |
| `ufw` | Ubuntu 防火墙简化工具 | 适合中小型服务器 |
| `firewalld` | 未译25173HEL 系防火墙管理 | 适合 zone/rich rule |
| `tcpdump` | 抓包排查访问是否到达 | 深入网络排障 |
| `Docker ps` | 查看Docker端口映射 | 排查 Docker 暴露 |

## 重点

- 先用 `ss -lntup` 看真实监听。
- 公网通常只开放 `80` 和 `443`。
- `22` 只允许可信来源访问。
- 数据库、未译25173edis、ES、Mongo 不应公网开放。
- Docker `ports` 要明确绑定 `127.0.0.1` 或内网地址。

## 练习

1. 在一台服务器上列出所有监听端口，并标记“公网、内网、本机”。
2. 把一个应用端口改成只监听 `127.0.0.1`，再用 Nginx 反代。
3. 用 ufw 或 firewalld 只放行 80/443 和指定来源的 SSH。
4. 从外部机器使用 `nmap` 验证最终暴露端口。
