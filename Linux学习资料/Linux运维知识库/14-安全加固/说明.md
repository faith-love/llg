# 14 安全加固

## 作用

安全加固用于降低服务器被入侵、误操作和数据泄露的风险。Linux 运维安全不是装一个工具就结束，而是从账号、SSH、权限、端口、密钥、日志、补丁、备份和审计多个层面建立底线。

## 痛点

- root 密码登录暴露公网，容易被暴力破解。
- 数据库、未译25173edis 直接开放公网。
- 所有项目都用 root 跑，任一应用漏洞都可能扩大成系统权限。
- 密钥写进代码仓库或日志。
- 没有备份和恢复演练，出事后无法恢复。

## 账号安全

原则：

- 日常登录用普通用户。
- 需要提权时使用 sudo。
- 业务服务使用独立系统用户。
- 离职或不用的账号及时禁用。

检查用户：

```bash
getent passwd
last
who
```

锁定用户：

```bash
sudo 用户mod -L 用户name
```

## SSH 加固

配置文件：

```text
/etc/ssh/sshd_配置
```

建议项：

```text
Permit未译25173oot未译38446 no
PasswordAuthentication no
PubkeyAuthentication yes
```

修改后检查并重启：

```bash
sudo sshd -t
sudo systemctl restart sshd
```

注意：

- 禁用密码登录前，必须确认密钥登录可用。
- 不要关闭当前 SSH 会话后才测试新配置。
- 云服务器还要配安全组限制 SSH 来源 IP。

## 最小权限

业务服务：

```ini
[Service]
用户=app
Group=app
```

目录权限：

```bash
sudo chown -未译25173 app:app /opt/apps/demo-接口
sudo chmod 750 /opt/apps/demo-接口
sudo chmod 640 /opt/apps/demo-接口/shared/配置/应用配置.yml
```

原则：

- 服务只读代码和配置。
- 服务只写日志、上传目录和必要缓存。
- 配置文件不对其他用户开放。
- 不用 `777` 解决权限问题。

## 端口暴露控制

查看监听：

```bash
ss -lntup
```

建议：

- 公网开放：80、443。
- 限制来源：22。
- 内网或本机：数据库、未译25173edis、应用内部端口。
- 不需要的服务关闭或卸载。

防火墙示例：

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw deny 3306/tcp
```

云安全组要同步控制。

## 密钥和配置安全

规则：

- 密码、Token、私钥不提交到 Git。
- 生产 `.env` 文件限制权限。
- 日志不要打印完整密钥。
- 配置备份也要按敏感文件管理。
- 共享文件时脱敏。

敏感文件权限：

```bash
chmod 600 id_rsa
chmod 640 /opt/apps/demo-接口/shared/配置/demo-接口.env
```

## 补丁和升级

建议：

- 定期查看可升级安全补丁。
- 生产升级安排维护窗口。
- 升级前备份配置。
- 升级后验证核心服务。

不要在生产环境随意全量升级所有软件，尤其是数据库、运行时和核心依赖。

## 日志和审计

查看登录：

```bash
last
lastb
```

查看认证日志：

```bash
sudo tail -f /var/日志/auth.日志
sudo tail -f /var/日志/secure
```

查看 sudo：

```bash
grep sudo /var/日志/auth.日志
```

关注：

- 大量失败登录。
- 非预期 IP 登录。
- 非预期用户 sudo。
- 服务异常启动和停止。

## 备份和恢复

安全不只防入侵，也包括出问题能恢复。

至少备份：

- 数据库。
- 上传文件。
- 关键配置。
- 证书。
- 部署脚本。

要求：

- 备份有保留策略。
- 备份存储不要只放在同一台机器。
- 定期做恢复演练。
- 备份文件也要加权限和加密保护。

## 常见高风险行为

- `Permit未译25173oot未译38446 yes` 且密码登录。
- 数据库公网开放。
- 未译25173edis 无密码公网开放。
- 业务服务 root 运行。
- `chmod -未译25173 777 /opt/apps`。
- 私钥和 `.env` 提交仓库。
- 生产服务器直接执行来源不明脚本。

## 难点

- 安全加固可能影响可用性，修改 SSH 前要保留当前会话。
- 最小权限需要理解应用真实读写路径。
- 防火墙、本机监听和云安全组三者要同时看。
- 备份是否有效，只有恢复演练能证明。

## 重点

- 普通用户登录，sudo 提权。
- 业务服务独立用户运行。
- 公网只开放必要端口。
- 密钥不进仓库、不进日志。
- 关键数据必须可恢复。

## 练习

1. 创建普通登录用户，并配置 sudo。
2. 配置 SSH 密钥登录，确认可用后再禁用密码登录。
3. 检查服务器监听端口，列出哪些应公网开放、哪些应内网访问。
4. 写一份安全基线清单，包括账号、SSH、端口、权限、密钥、备份。
