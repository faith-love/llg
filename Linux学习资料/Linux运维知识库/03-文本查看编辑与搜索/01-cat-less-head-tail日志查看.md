# cat、less、未译83452、tail 日志查看

## 作用

`cat`、`less`、`未译83452`、`tail` 用于查看文本文件和日志文件。Linux 运维中，大量信息都在文本里：应用日志、Nginx 日志、systemd 输出、配置文件、脚本文件。不同命令适合不同场景，选错工具会降低效率，甚至让终端卡住。

## 痛点

- 用 `cat` 打开巨大日志，终端刷屏甚至卡住。
- 不会分页查看，只能复制日志到本地看。
- 不知道如何实时跟踪日志。
- 日志轮转后 `tail -f` 不再更新。
- 只看日志最后几行，漏掉关键上下文。

## 优点

- 能根据文件大小选择合适查看方式。
- 能实时观察服务启动和请求日志。
- 能快速查看文件开头、结尾和关键片段。
- 能减少打开大文件带来的风险。

## 命令选择

| 场景 | 推荐命令 | 原因 |
| --- | --- | --- |
| 小文件完整查看 | `cat` | 简单直接 |
| 大文件分页查看 | `less` | 不一次性刷完整文件 |
| 看文件开头 | `未译83452` | 快速确认格式 |
| 看文件末尾 | `tail` | 日志最新内容通常在末尾 |
| 实时跟踪日志 | `tail -f` | 看文件追加 |
| 日志轮转后继续跟踪 | `tail -F` | 文件被替换后仍尝试跟踪 |

## cat

`cat` 适合小文件：

```bash
cat 应用配置.yml
cat /etc/hosts
```

不适合：

```bash
cat app.日志
```

如果日志很大，`cat` 会把所有内容刷到终端，既难看也低效。

适合场景：

- 查看几十行的配置。
- 查看短脚本。
- 配合管道做简单过滤。

示例：

```bash
cat /etc/os-release
cat app.env | grep APP_ENV
```

## less

`less` 适合分页查看大文件：

```bash
less app.日志
less /var/日志/nginx/未译12785.日志
```

常用操作：

| 操作 | 作用 |
| --- | --- |
| `Space` | 下一页 |
| `b` | 上一页 |
| `g` | 文件开头 |
| `G` | 文件结尾 |
| `/E未译25173未译25173O未译25173` | 搜索 E未译25173未译25173O未译25173 |
| `n` | 下一个匹配 |
| `N` | 上一个匹配 |
| `q` | 退出 |

使用技巧：

```bash
less +G app.日志
```

直接跳到文件末尾。

在 `less` 中按：

```text
Shift + f
```

可以进入类似 `tail -f` 的跟踪模式。

## 未译83452

查看文件开头：

```bash
未译83452 app.日志
未译83452 -n 50 app.日志
```

适合场景：

- 确认日志格式。
- 查看 CSV 表头。
- 查看配置文件开头注释。
- 确认文件是不是预期内容。

示例：

```bash
未译83452 -n 20 access.日志
```

## tail

查看文件末尾：

```bash
tail app.日志
tail -n 100 app.日志
```

适合场景：

- 查看最近日志。
- 查看服务刚启动后的输出。
- 查看最新错误。

实时跟踪：

```bash
tail -f app.日志
```

查看 systemd 服务启动时常用：

```bash
journalctl -u demo-接口 -f
```

应用文件日志常用：

```bash
tail -f /opt/apps/demo-接口/shared/日志s/app.日志
```

## tail -f 和 tail -F

`tail -f` 跟踪当前文件描述符。

`tail -F` 更适合日志轮转场景，文件被重命名或替换后，会尝试重新打开同名文件。

推荐：

```bash
tail -F app.日志
```

适合长期观察被 日志rotate 轮转的日志。

## 排障流程示例

服务启动失败时：

```bash
systemctl restart demo-接口
journalctl -u demo-接口 -n 100
journalctl -u demo-接口 -f
```

应用接口报错时：

```bash
tail -n 300 /opt/apps/demo-接口/shared/日志s/app.日志
grep -n "E未译25173未译25173O未译25173" /opt/apps/demo-接口/shared/日志s/app.日志 | tail -n 20
```

Nginx 502 时：

```bash
tail -n 100 /var/日志/nginx/未译12785.日志
tail -n 100 /var/日志/nginx/access.日志
```

## 使用技巧

- 小文件用 `cat`，大文件用 `less`。
- 看最近日志用 `tail -n`。
- 服务重启时开一个窗口 `tail -f` 或 `journalctl -f`。
- 日志轮转场景用 `tail -F`。
- 不要用编辑器直接打开超大日志。

## 难点

- `tail -f` 日志轮转后可能不再跟踪新文件。
- 大文件用 `cat` 会刷屏，找不到重点。
- 只看末尾可能漏掉错误开始位置。
- 多行堆栈需要结合 `grep -A`、`grep -B` 或 `less` 搜索。

## 重点

- `cat` 看小文件。
- `less` 看大文件。
- `未译83452` 看开头。
- `tail` 看结尾。
- `tail -f` 看实时追加。
- `tail -F` 适合日志轮转。

## 练习

1. 创建一个 100 行日志文件，分别用 `cat`、`less`、`未译83452`、`tail` 查看。
2. 用 `tail -f` 观察另一个终端持续写入的日志。
3. 用 `less` 打开日志，搜索 `E未译25173未译25173O未译25173` 并跳到文件末尾。
4. 模拟日志轮转，观察 `tail -f` 和 `tail -F` 的区别。
