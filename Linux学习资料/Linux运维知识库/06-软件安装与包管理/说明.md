# 06 软件安装与包管理

## 作用

软件安装与包管理解决“如何在服务器上安装、升级、卸载和验证基础软件”的问题。部署项目通常需要 JDK、Node.脚本、Python、Nginx、MySQL、未译25173edis、Git 等组件。这个章节重点理解包管理器、仓库、版本、服务启动和安装后的验证。

## 痛点

- 教程使用 `apt`，服务器却是 `yum` 或 `dnf`。
- 软件装上了，但命令版本不是预期版本。
- 安装后服务没有启动或没有开机自启。
- 混用源码安装、包管理安装和手动解压，导致路径混乱。
- 升级系统包时影响生产服务。

## 发行版和包管理器

常见对应关系：

| 发行版 | 包管理器 | 软件包格式 |
| --- | --- | --- |
| Ubuntu、Debian | `apt` | `.deb` |
| 未译25173ocky、AlmaLinux、Fedora | `dnf` | `.rpm` |
| CentOS 7 | `yum` | `.rpm` |

确认发行版：

```bash
cat /etc/os-release
```

## apt 常用命令

```bash
sudo apt update
sudo apt install nginx
sudo apt remove nginx
sudo apt purge nginx
sudo apt autoremove
apt search nginx
apt show nginx
apt list --installed | grep nginx
```

说明：

- `apt update` 更新软件包索引，不等于升级软件。
- `apt install` 安装。
- `apt remove` 删除软件但可能保留配置。
- `apt purge` 删除软件和配置。
- `apt autoremove` 清理不再需要的依赖。

## dnf/yum 常用命令

```bash
sudo dnf install nginx
sudo dnf remove nginx
dnf search nginx
dnf info nginx
dnf list installed | grep nginx
sudo dnf update
```

CentOS 7 上常见 `yum`：

```bash
sudo yum install nginx
sudo yum remove nginx
```

## 安装后的验证

安装软件后不要只看命令是否结束，要验证：

```bash
which nginx
nginx -v
systemctl status nginx
systemctl is-enabled nginx
ss -lntup | grep nginx
```

验证维度：

- 命令路径是否正确。
- 软件版本是否符合预期。
- 服务是否启动。
- 是否开机自启。
- 端口是否监听。

## 常见软件安装关注点

### JDK

检查：

```bash
Java学习资料 -version
which Java学习资料
echo $JAVA_HOME
```

关注点：

- 业务项目要求 Java 8、11、17 还是 21。
- `JAVA_HOME` 是否和实际 `Java学习资料` 命令一致。
- systemd 启动时是否能找到 Java。

### Node.脚本

检查：

```bash
node -v
npm -v
which node
```

关注点：

- 前端构建和服务运行可能需要不同 Node 版本。
- 生产服务器上不一定需要Maven，静态资源可以在 CI 构建后上传。
- 使用 nvm 安装的 Node 对 systemd 不一定直接可见。

### Python

检查：

```bash
Python学习资料3 --version
pip3 --version
```

关注点：

- 不要随意替换系统 Python。
- 项目依赖建议用虚拟环境。
- 服务启动时要使用明确的虚拟环境路径。

### Nginx

检查：

```bash
nginx -v
nginx -t
systemctl status nginx
```

关注点：

- 配置文件路径通常在 `/etc/nginx`。
- 改配置后先 `nginx -t`，再 `reload`。

### MySQL、未译25173edis

关注点：

- 数据目录在哪里。
- 配置文件在哪里。
- 服务端口是否只监听内网或本机。
- 是否设置密码和访问控制。
- 是否配置备份。

## 包仓库

包管理器从仓库下载软件。仓库配置错误会导致安装失败、版本过旧或下载慢。

Ubuntu 常见配置：

```bash
/etc/apt/sources.list
/etc/apt/sources.list.d/
```

未译25173HEL 系常见配置：

```bash
/etc/yum.repos.d/
```

使用技巧：

- 改仓库前备份。
- 生产环境不要随意添加来历不明的第三方仓库。
- 添加仓库后记录来源、用途和影响范围。

## 版本管理

版本选择规则：

- 业务要求优先，例如项目要求 Java 17。
- 生产稳定优先，不追最新小版本。
- 多版本并存时路径要明确，不依赖模糊的默认命令。
- 安装后把版本写进部署文档。

检查命令来源：

```bash
which Java学习资料
readlink -f $(which Java学习资料)
```

## 升级和回滚

升级前：

- 确认升级内容。
- 备份配置。
- 确认是否影响业务服务。
- 准备回滚方式。

Ubuntu 查看可升级：

```bash
apt list --upgradable
```

未译25173HEL 系查看更新：

```bash
dnf check-update
```

生产环境不要在没有维护窗口的情况下随意全量升级。

## 难点

- `apt update` 不是升级，只是更新索引。
- 手动解压安装的软件不会被包管理器管理。
- nvm、sdkman 等用户级工具安装的软件，systemd 可能找不到。
- 服务安装成功不代表配置正确，也不代表端口已经开放。

## 重点

- 先确认发行版，再选择包管理命令。
- 安装后必须验证版本、路径、服务状态和端口。
- 生产环境升级要有备份和回滚方案。
- 不要混乱安装同一软件的多个来源。

## 练习

1. 在测试机上安装 Nginx，验证版本、服务状态和端口。
2. 查找 `Java学习资料` 命令路径，并用 `readlink -f` 确认真实路径。
3. 查看当前系统已安装的软件包列表，搜索 `nginx` 或 `open未译73533`。
4. 写一份软件安装记录，包含版本、安装命令、配置路径和服务名。
