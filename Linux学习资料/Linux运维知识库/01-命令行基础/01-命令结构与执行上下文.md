# 命令结构与执行上下文

## 作用

命令结构与执行上下文用于解决“我正在执行什么命令、它会作用到哪里、会以谁的身份执行”的问题。Linux 命令不是一串可以随便复制的文本，它由命令、选项、参数、当前用户、当前目录、环境变量和主机上下文共同决定结果。

同一条命令，在不同目录、不同用户、不同服务器上执行，影响可能完全不同。例如 `rm -rf 日志s` 在测试目录只是删日志，在生产应用目录可能删掉关键运行数据。

## 痛点

- 复制教程命令时不知道哪个是命令、哪个是参数、哪个是路径。
- 不确认当前主机，可能在生产机器执行测试命令。
- 不确认当前目录，导致相对路径误删或找不到文件。
- 不确认当前用户，导致权限不足或误用 root。
- 看见命令成功退出，但没有验证目标是否真的改变。

## 优点

- 能读懂命令，而不是只会复制。
- 能在执行前判断风险范围。
- 能快速定位“为什么同一条命令在别人机器能跑，我这里不行”。
- 能减少生产误操作。

## 命令结构

Linux 命令通常是：

```bash
命令 [选项] [参数]
```

示例：

```bash
ls -lah /var/日志
```

拆开理解：

- `ls`：命令，表示列出目录内容。
- `-lah`：选项，等价于 `-l -a -h`。
- `/var/日志`：参数，表示目标目录。

再看一个服务命令：

```bash
systemctl status nginx
```

拆开理解：

- `systemctl`：命令。
- `status`：子命令，表示查看状态。
- `nginx`：参数，表示服务名。

## 命令、选项、参数的区别

| 部分 | 作用 | 示例 |
| --- | --- | --- |
| 命令 | 要执行的程序或 Shell 内置能力 | `ls`、`grep`、`systemctl` |
| 短选项 | 单字母参数，通常用 `-` | `-l`、`-a`、`-f` |
| 长选项 | 可读性更强，通常用 `--` | `--help`、`--failed` |
| 参数 | 命令作用的对象 | 文件、目录、服务名、关键字 |
| 子命令 | 某些工具里的动作 | `git status`、`systemctl restart` |

短选项可以组合：

```bash
ls -l -a -h
ls -lah
```

这两条通常等价。

## 执行上下文

执行命令前先确认 4 件事：

```bash
whoami
hostname
pwd
id
```

### 当前用户

当前用户决定权限。

```bash
whoami
id
sudo -l
```

判断：

- 普通用户执行系统配置修改可能权限不足。
- root 执行命令权限很大，误操作影响也更大。
- systemd 服务实际运行用户不一定是你当前登录用户。

### 当前主机

当前主机决定操作环境。

```bash
hostname
hostname -I
```

高风险操作前再确认一次主机：

```bash
hostname && pwd && whoami
```

适合在执行重启、删除、发布、清理前使用。

### 当前目录

当前目录决定相对路径含义。

```bash
pwd
ls -lah
```

例如：

```bash
rm -rf 日志s
```

这条命令删除的是“当前目录下的 日志s”，不是固定的 `/opt/apps/demo-接口/shared/日志s`。所以脚本和生产操作中更推荐使用绝对路径。

### 当前环境变量

环境变量会影响命令查找路径和应用运行行为。

```bash
echo $PATH
env | sort
which Java学习资料
通用mand -v nginx
```

注意：

- 当前终端能找到 `Java学习资料`，不代表 systemd 服务也能找到。
- `PATH` 顺序会影响执行哪个版本的命令。

## 命令是否成功

Linux 命令通常用退出码表示成功失败：

```bash
echo $?
```

约定：

- `0` 通常表示成功。
- 非 `0` 通常表示失败。

示例：

```bash
ls /not-exist
echo $?
```

但要注意：命令成功不等于业务目标成功。例如 `systemctl restart demo-接口` 命令返回成功后，还要继续检查：

```bash
systemctl status demo-接口
journalctl -u demo-接口 -n 100
curl -f http://127.0.0.1:8080/health
```

## 使用技巧

- 先读懂命令结构，再执行。
- 对不熟悉的命令先加 `--help`。
- 对文件操作先用 `ls`、`find` 预览目标。
- 对服务操作后要看 `status` 和日志。
- 对网络操作后要用 `curl` 或端口检查验证。

## 难点

- 有些命令是 Shell 内置命令，例如 `cd`，不是普通二进制文件。
- `sudo 通用mand > file` 可能失败，因为 `>` 重定向由当前 Shell 执行，不是 sudo 执行。
- 命令成功退出不代表服务真的健康。
- 同一命令在不同发行版上参数可能略有差异。

## 重点

- 命令 = 命令名 + 选项 + 参数 + 执行上下文。
- 执行前确认 `whoami`、`hostname`、`pwd`。
- 相对路径有风险，高风险操作优先用绝对路径。
- 执行后要验证结果，不只看命令有没有报错。

2. 分析 `systemctl status nginx` 的命令、子命令和参数。
3. 在两个不同目录执行 `pwd && ls`，理解当前目录变化。
4. 执行一个失败命令后查看 `echo $?`。
5. 写一条高风险命令的执行前检查：用户、主机、目录、目标路径。
