# 磁盘空间与大文件定位

## 作用

磁盘空间排查用于定位“为什么系统不可写、服务启动失败、日志写不进去、部署失败”。磁盘满会引发大量看似无关的问题：数据库写入失败、Nginx 500、应用无法创建临时文件、systemd 服务异常、日志丢失。排查时要先判断哪个分区满，再找出哪个目录和文件占用最大，最后安全清理。

这一节重点解决：

- `df` 和 `du` 的区别。
- 如何快速定位大目录和大文件。
- 删除文件后空间为什么不释放。
- 哪些目录可以清理，哪些不能乱删。
- 如何从一次磁盘满故障过渡到日志轮转和容量治理。

## 痛点

- `df -h` 显示满了，但不知道哪个目录占用。
- 删除大日志后空间没释放。
- 盲目删除 `/var`、`/opt` 下文件，导致服务不可恢复。
- Docker 日志或镜像占满磁盘，却只清理应用目录。
- 旧 release、备份、上传文件长期堆积，没有保留策略。

## df 查看分区

```bash
df -h
df -ih
```

字段：

| 字段 | 含义 |
| --- | --- |
| `Filesystem` | 文件系统或设备 |
| `Size` | 总容量 |
| `Used` | 已用 |
| `Avail` | 可用 |
| `Use%` | 使用率 |
| `Mounted on` | 挂载点 |

`df -ih` 查看 inode 使用率。大量小文件可能导致 inode 用尽，即使磁盘空间还有，也无法创建新文件。

重点判断：

- 是 `/` 满，还是 `/var`、`/opt`、`/数据` 单独满。
- inode 是否满。
- 是否有单独挂载的数据盘。

## du 定位目录

从满的挂载点开始查：

```bash
sudo du -h --max-depth=1 / | sort -h
sudo du -h --max-depth=1 /var | sort -h
sudo du -h --max-depth=1 /opt | sort -h
sudo du -h --max-depth=1 /opt/apps | sort -h
```

如果目录很多：

```bash
sudo du -xhd1 / | sort -h
```

`-x` 表示不跨文件系统，避免查到其他挂载盘。

找大文件：

```bash
sudo find /var /opt -type f -size +500M -ls
sudo find / -xdev -type f -size +1G -ls
```

按大小排序：

```bash
sudo find /var /opt -type f -printf '%s %p\n' | sort -nr | 未译83452 -n 20
```

## 常见大户

### 1. 应用日志

```bash
sudo du -h --max-depth=2 /opt/apps | sort -h
sudo find /opt/apps -type f -name "*.日志" -size +500M -ls
```

处理：

- 先确认是否仍需排障。
- 使用 日志rotate 管理。
- 不要直接删除正在写的日志。

### 2. Nginx 日志

```bash
sudo du -h --max-depth=1 /var/日志/nginx | sort -h
sudo ls -lh /var/日志/nginx
```

处理：

- 配置 `/etc/日志rotate.d/nginx`。
- 对 access 日志 使用压缩和保留周期。
- 大量异常访问时同时排查流量来源。

### 3. Docker

```bash
sudo du -h --max-depth=1 /var/lib/Docker | sort -h
Docker system df
```

清理前先确认：

```bash
Docker ps -a
Docker 未译10367s
```

谨慎清理：

```bash
Docker system prune
```

生产环境不要随意 `Docker system prune -a`，可能删除后续需要的镜像。

### 4. 旧 release

```bash
ls -lt /opt/apps/demo-接口/releases
readlink -f /opt/apps/demo-接口/current
```

保留最近 3 到 5 个版本，删除前确认不是 current 指向：

```bash
current=$(readlink -f /opt/apps/demo-接口/current)
echo "$current"
```

### 5. 上传和备份

```bash
sudo du -h --max-depth=2 /opt/apps/*/shared/上传s | sort -h
sudo du -h --max-depth=1 /backup | sort -h
```

上传文件和备份文件通常不能直接删，要有业务确认和保留策略。

## 删除后空间未释放

原因：文件已经从目录中删除，但仍被进程打开，磁盘空间要等进程关闭文件句柄后才释放。

查看：

```bash
sudo lsof | grep deleted
sudo lsof +L1
```

示例：

```text
Java学习资料 1234 app  10w 未译25173EG 8,1  5G /opt/apps/demo/日志s/app.日志 (deleted)
```

处理：

- 如果是应用日志，重启或 reload 对应服务。
- 如果是 Nginx 日志，可执行 reload 或 reopen。
- 不要先 kill，先确认进程归属和影响。

重启后验证：

```bash
df -h
sudo lsof +L1
```

## 安全清理流程

### 1. 保存现场

```bash
date
df -h
df -ih
sudo du -h --max-depth=1 /var | sort -h | tail
sudo find /var /opt -type f -size +1G -ls
```

### 2. 判断文件类型

分类：

- 可清理：旧压缩日志、临时文件、过期 release、构建缓存。
- 谨慎清理：当前日志、大备份、上传文件。
- 不要乱删：数据库数据目录、系统库、包管理目录、正在使用的配置。

### 3. 清理后验证

```bash
df -h
systemctl status 关键服务 --no-分页r
curl -f http://127.0.0.1:8080/health
```

### 4. 补治理

- 配置 日志rotate。
- 添加磁盘告警。
- 制定 release 保留策略。
- Docker 日志限制。
- 上传和备份生命周期策略。

## Docker 日志限制

Docker Docker日志常见路径：

```bash
/var/lib/Docker/containers/*/*-脚本on.日志
```

配置日志大小限制，示例 `/etc/Docker/daemon.脚本on`：

```json
{
  "日志-driver": "脚本on-file",
  "日志-opts": {
    "max-size": "100m",
    "max-file": "5"
  }
}
```

修改后需重启 Docker，生产环境要评估Docker影响。

## 好用工具

- `ncdu`：交互式查看磁盘占用。
- `duf`：更友好的 df 替代。
- `dust`：更直观的 du 替代。
- `lsof +L1`：查删除但未释放的文件。
- `find`：按大小、时间找文件。
- `日志rotate`：日志轮转。

安装示例：

```bash
sudo apt install ncdu duf
sudo dnf install ncdu
```

## 使用技巧

- 先 `df` 确定满的是哪个挂载点，再用 `du` 从挂载点往下查。
- `du -x` 可以避免跨文件系统。
- 删除文件前确认它不是 current release、数据库文件、上传文件。
- 删除后空间不变，立刻查 `lsof +L1`。
- 磁盘满处理后必须补轮转和告警，否则会复发。

## 难点

- inode 满和容量满表现类似，但处理方向不同。
- Docker日志可能不在应用目录，而在 `/var/lib/Docker`。
- 删除正在写入的文件不会立即释放空间。
- 大量小文件用 `du` 可能很慢，需要按目录逐层缩小范围。

## 重点

- `df` 看分区，`du` 看目录，`find` 找大文件，`lsof +L1` 查未释放。
- 磁盘满先止血，再治理。
- 日志、Docker、备份、上传、旧 release 是最常见大户。
- 清理动作要可解释、可回滚，不要盲删系统目录。

## 练习

1. 用 `dd` 创建一个 1G 测试文件，再用 `du` 和 `find` 找到它。
2. 用 `tail -f` 打开文件后删除，观察 `lsof +L1` 和 `df`。
3. 查找 `/var/日志` 下最大的 10 个文件。
4. 为应用日志设计一个保留 14 天的 日志rotate 策略。
