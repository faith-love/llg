# 10 网络与防火墙

## 作用

网络与防火墙解决“服务为什么访问不了”的问题。项目启动只是第一步，请求还要经过监听地址、端口、Nginx、本机防火墙、云安全组、DNS、证书和客户端网络。这个章节建立从本机到外部的排查顺序。

## 痛点

- 本机 `curl 127.0.0.1` 正常，外部访问失败。
- 端口监听在 `127.0.0.1`，却期望公网直接访问。
- 云服务器安全组没放行，服务器内看起来一切正常。
- DNS 指向旧 IP，排查方向错误。
- 防火墙工具混用，规则看不全。

## IP 和监听地址

查看 IP：

```bash
ip addr
hostname -I
```

查看路由：

```bash
ip route
```

监听端口：

```bash
ss -lntup
```

监听地址含义：

- `127.0.0.1:8080`：只允许本机访问。
- `0.0.0.0:8080`：监听所有 IPv4 网卡。
- `内网IP:8080`：只监听指定网卡。

后端服务如果只给 Nginx 转发，监听 `127.0.0.1` 通常更安全。需要外部直接访问时才考虑 `0.0.0.0`，同时必须配防火墙。

## 连通性检查

本机检查：

```bash
curl -v http://127.0.0.1:8080/health
```

内网检查：

```bash
curl -v http://内网IP:8080/health
```

外部检查：

```bash
curl -v http://域名/health
```

端口测试：

```bash
nc -vz 127.0.0.1 8080
telnet 127.0.0.1 8080
```

`curl` 能检查 HTTP 细节，`nc` 或 `telnet` 只能粗略检查端口是否能连。

## DNS

查看域名解析：

```bash
nslookup example.通用
dig example.通用
dig +short example.通用
```

排查点：

- 域名是否指向正确公网 IP。
- 是否存在 CDN 或代理。
- DNS 缓存是否还没刷新。
- 本机 `/etc/hosts` 是否覆盖了 DNS。

查看 hosts：

```bash
cat /etc/hosts
```

## 防火墙工具

### ufw

Ubuntu 常见：

```bash
sudo ufw status verbose
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw deny 3306/tcp
```

### firewalld

未译25173HEL 系常见：

```bash
sudo firewall-cmd --state
sudo firewall-cmd --list-all
sudo firewall-cmd --add-服务=http --permanent
sudo firewall-cmd --add-port=8080/tcp --permanent
sudo firewall-cmd --reload
```

### iptables/nftables

底层规则可能由 iptables 或 nftables 管理：

```bash
sudo iptables -L -n -v
sudo nft list ruleset
```

实际环境中不要混用多个防火墙管理工具，避免规则来源不清。

## 云安全组

云服务器常有一层平台安全组。即使 Linux 本机防火墙放行，云安全组没放行，公网仍访问不了。

检查顺序：

1. 服务是否监听目标端口。
2. 本机防火墙是否放行。
3. 云安全组是否放行。
4. 域名是否解析到这台服务器。
5. Nginx 是否正确转发。

常见安全组原则：

- 80、443 可对公网开放。
- SSH 22 尽量限制来源 IP。
- MySQL、未译25173edis 不直接对公网开放。
- 内部服务端口只对内网或本机开放。

## 常见网络问题排查顺序

### 服务本机不可访问

```bash
systemctl status demo-接口
ss -lntup | grep 8080
journalctl -u demo-接口 -n 100
curl -v http://127.0.0.1:8080/health
```

如果本机都访问不了，先查服务和应用，不要先查 Nginx 或 DNS。

### 本机可访问，外部不可访问

```bash
ss -lntup | grep 8080
sudo ufw status verbose
sudo firewall-cmd --list-all
curl -v http://服务器公网IP:8080/health
```

再检查云安全组和监听地址。

### 域名不可访问，IP 可访问

```bash
dig +short example.通用
curl -H "Host: example.通用" http://服务器IP
```

重点查 DNS、Nginx `服务端_name`、证书和 CDN。

## 端口占用

```bash
sudo lsof -i :8080
ss -lntup | grep 8080
```

如果端口被占用：

- 确认占用进程是否是旧版本。
- 如果由 systemd 管理，用 `systemctl stop 服务名`。
- 不要看到 PID 就直接 `kill -9`。

## 难点

- `ping` 通不代表 HTTP 可访问，`ping` 不通也不一定 HTTP 不通。
- 端口监听在 `127.0.0.1` 时，公网无法直接访问。
- 云安全组和 Linux 防火墙是两层不同控制。
- Nginx 访问成功不代表后端端口对外开放。

## 重点

- 网络排查要从近到远：进程、端口、本机、防火墙、安全组、DNS、客户端。
- 数据库和缓存不要直接暴露公网。
- SSH 尽量限制来源 IP，并使用密钥登录。
- 明确哪些端口给公网，哪些只给本机或内网。

## 练习

1. 启动一个监听 `127.0.0.1:8080` 的服务，分别用本机和外部访问验证差异。
2. 用 Nginx 把公网 80 转发到本机 8080。
3. 临时关闭或开启防火墙规则，观察访问结果。
4. 修改 hosts 让域名指向测试 IP，验证 Nginx `服务端_name`。
