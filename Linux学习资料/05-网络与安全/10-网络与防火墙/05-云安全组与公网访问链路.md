# 云安全组与公网访问链路

## 作用

云安全组是云平台提供的网络访问控制层，通常位于服务器操作系统之外。即使 Linux 本机防火墙已经放行，如果云安全组没有放行，公网仍然无法访问。公网访问链路需要把服务监听、本机防火墙、云安全组、负载均衡、DNS、Nginx、后端服务串起来看。

这一节重点解决：

- 云安全组和 Linux 防火墙的区别。
- 公网访问一个服务要经过哪些层。
- 为什么服务器内自测正常，公网仍然访问不了。
- 常见端口应该如何开放。
- SSH、数据库、Redis 等敏感端口如何限制。

## 痛点

- 服务器上 `curl 127.0.0.1` 正常，公网访问超时。
- 本机防火墙放行了，云安全组没放行。
- 安全组放行了 8080，但服务只监听 `127.0.0.1`。
- 域名解析到旧公网 IP，新服务器没有任何访问日志。
- MySQL/Redis 直接暴露公网，引发安全风险。
- SSH 对全网开放，暴力破解日志大量增加。

## 公网访问链路

典型链路：

```text
客户端浏览器
  -> DNS 解析域名
  -> 公网 IP / CDN / 负载均衡
  -> 云安全组
  -> Linux 本机防火墙
  -> Nginx 80/443
  -> 后端 127.0.0.1:8080
```

任何一层不通，最终访问都会失败。

## 云安全组与本机防火墙

| 层级 | 位置 | 管理方式 | 典型问题 |
| --- | --- | --- | --- |
| 云安全组 | 云平台网络层 | 云控制台、云 CLI、Terraformat | 公网端口没放行 |
| 本机防火墙 | Linux 操作系统内 | ufw、firewalld、iptables、nftables | 系统规则拦截 |
| 应用监听 | 进程本身 | 应用配置、systemd | 只监听 127.0.0.1 |
| Nginx | 入口代理 | Nginx 配置 | 服务端_name、proxy_pass 错误 |

不能用本机命令直接看到云安全组规则，必须去云平台控制台或通过云 CLI 查询。

## 公网访问排查顺序

### 1. 服务是否运行

```bash
systemctl status demo-接口 --no-分页r
journalctl -u demo-接口 -n 100 --no-分页r
```

如果服务本身失败，先修服务。

### 2. 端口是否监听

```bash
sudo ss -lntup | grep ':8080'
sudo ss -lntup | grep ':80'
sudo ss -lntup | grep ':443'
```

判断：

- 后端给 Nginx 用，监听 `127.0.0.1:8080` 可以。
- 需要公网直连，必须监听 `0.0.0.0` 或公网入口可达的地址。
- Nginx 对公网通常监听 `0.0.0.0:80`、`0.0.0.0:443`。

### 3. 本机访问

```bash
curl -v http://127.0.0.1:8080/health
curl -I http://127.0.0.1
```

本机都不通，继续查应用、Nginx、端口。

### 4. 内网访问

从同 VPC 或同内网机器：

```bash
curl -v http://内网IP:8080/health
nc -vz 内网IP 8080
```

如果本机通、内网不通，查监听地址、本机防火墙、内网安全组。

### 5. 公网 IP 访问

从外部网络：

```bash
curl -I http://公网IP
nc -vz 公网IP 80
nc -vz 公网IP 443
```

如果公网 IP 不通，查：

- 云安全组入站规则。
- 公网 IP 是否绑定到这台实例或负载均衡。
- 本机防火墙。
- Nginx 是否监听 80/443。

### 6. 域名访问

```bash
dig +short example.通用
curl -I http://example.通用
curl -H 'Host: example.通用' http://公网IP/
```

如果公网 IP 通、域名不通，查 DNS、CDN、Nginx 服务端_name、证书。

## 安全组规则原则

### 1. 公网入口

一般允许：

```text
80/tcp  来源 0.0.0.0/0
443/tcp 来源 0.0.0.0/0
```

如果业务只对特定办公网络开放，可以限制来源 IP。

### 2. SSH

不建议：

```text
22/tcp 来源 0.0.0.0/0
```

更建议：

```text
22/tcp 来源 办公网固定IP/32
```

同时使用：

- 密钥登录。
- 禁止 root 直接登录。
- fail2ban 或云平台登录保护。
- 必要时使用堡垒机或 VPN。

### 3. 数据库和缓存

不要公网开放：

```text
3306 MySQL
5432 PostgreSQL
6379 Redis
9200 Elasticsearch
27017 MongoDB
```

推荐：

- 只允许内网来源。
- 绑定内网地址。
- 配置认证和最小权限。
- 使用云数据库时通过白名单或安全组限制。

### 4. 应用内部端口

例如：

```text
8080 Java API
3000 Node 服务
8000 Python 服务
```

如果前面有 Nginx，通常不需要公网开放这些端口。让后端监听 `127.0.0.1` 或只允许 Nginx 所在机器访问。

## 云平台常见检查项

虽然不同云厂商界面不同，但思路一致：

- 实例是否绑定公网 IP。
- 安全组入站规则是否允许目标端口。
- 安全组出站规则是否允许必要访问。
- 负载均衡监听端口是否配置。
- 负载均衡后端健康检查是否通过。
- 网络 ACL 是否限制。
- EIP 是否绑定到正确实例。
- CDN 回源地址是否正确。

## 负载均衡场景

链路：

```text
客户端 -> 负载均衡 80/443 -> 后端服务器 80/8080
```

排查：

```bash
# 后端服务器本机
curl -v http://127.0.0.1:8080/health
sudo ss -lntup | grep ':8080'

# 从同内网机器
curl -v http://后端内网IP:8080/health

# 从公网
curl -I http://负载均衡域名或IP
```

还要看：

- 负载均衡健康检查路径。
- 后端安全组是否允许负载均衡来源。
- Nginx 是否只允许特定 Host。
- HTTPS 是负载均衡终止还是后端 Nginx 终止。

## CDN 场景

链路：

```text
客户端 -> CDN -> 源站 Nginx -> 后端
```

排查：

```bash
dig +short example.通用
curl -I 安全HTTP://example.通用
curl --resolve example.通用:443:源站IP 安全HTTP://example.通用
```

关注：

- CDN 是否缓存旧内容。
- 源站 IP 是否正确。
- 源站安全组是否允许 CDN 回源 IP。
- HTTPS 证书在 CDN 和源站分别如何配置。

## 常见现象判断

### 外部访问超时

可能原因：

- 云安全组未放行。
- 本机防火墙 DROP。
- 没有公网 IP 或公网绑定错误。
- 服务未监听公网入口端口。

### 外部 Connection refused

可能原因：

- IP 可达，但目标端口没有进程监听。
- 端口被明确拒绝。

### 访问到旧页面

可能原因：

- DNS 指向旧 IP。
- CDN 缓存。
- Nginx root 指向旧 current。
- 浏览器缓存。

### Nginx 有日志，后端无日志

可能原因：

- Nginx 没有正确 proxy_pass。
- location 命中错误。
- Nginx 直接返回了静态文件、404、403、502。

### Nginx 无日志

可能原因：

- 请求没到这台服务器。
- DNS 指向错误。
- 安全组或负载均衡前置层拦截。
- 访问的是另一台实例。

## 好用工具

- 云平台安全组控制台或 CLI：查看真实入站规则。
- `curl`：分层验证 HTTP。
- `nc`：验证 TCP 端口。
- `dig`：验证域名解析。
- `ss`：查看监听地址。
- `mtr`：观察网络路径质量。
- `tcpdump`：确认请求是否到达服务器网卡。

抓包示例：

```bash
sudo tcpdump -nn -i any tcp port 80
```

如果外部访问时抓不到包，说明请求没有到达这台服务器，需要往云安全组、负载均衡、DNS 前面查。

## 使用技巧

- 公网访问失败时，先判断请求有没有到服务器：看 Nginx access 日志 或 tcpdump。
- 后端端口不需要公网开放时，就不要在安全组里放行。
- 80/443 是常规公网入口，其他端口要有明确理由。
- SSH 一定限制来源 IP，并使用密钥。
- 云安全组、本机防火墙、应用监听地址三者都要匹配。

## 难点

- 云服务器系统内看不到云安全组，容易误以为“服务器没问题”。
- 公网 IP 可能在实例、负载均衡、NAT、CDN 等不同层。
- 多台实例部署时，域名可能打到其中一台异常机器。
- CDN 和浏览器缓存会让修复结果延迟体现。

## 重点

- 公网链路要从客户端到后端逐层拆开。
- 本机通不代表公网通，公网通不代表域名通。
- 安全组是云平台层，本机防火墙是操作系统层。
- 敏感端口不公网开放，公网入口尽量收敛到 80/443。

## 练习

1. 配置一个只允许 80/443 公网访问的安全组，验证后端 8080 不可公网直连。
2. 用 `tcpdump` 观察外部访问 80 端口时请求是否到达服务器。
3. 修改 DNS 指向后，用 `dig` 和 `curl -H Host` 验证访问链路。
4. 模拟 Nginx 有日志但后端无日志的场景，检查 location 和 proxy_pass。
