# 进程查看与端口占用

## 作用

进程查看与端口占用排查，是判断“服务是否真的在运行、由谁启动、占用多少资源、监听哪个端口”的基础能力。项目部署后，如果接口访问不了、端口冲突、CPU 飙高、内存异常、服务重复启动，第一步通常不是重启，而是先把进程和端口状态看清楚。

这一节要解决四类问题：

1. 找到某个服务对应的进程。
2. 判断进程的启动用户、PID、命令、CPU、内存占用。
3. 找到某个端口被哪个进程占用。
4. 区分“进程存在”“端口监听”“外部可访问”这几个不同层次。

## 痛点

- 服务启动失败提示端口被占用，但不知道哪个进程占着。
- `ps | grep` 查到多个结果，不知道哪个才是真正业务进程。
- 进程存在，但端口没有监听，外部请求仍然失败。
- 端口在本机监听，但被防火墙、安全组或 Nginx 配置挡住。
- 看到高 CPU 或高内存就直接 kill，结果误杀核心服务。

## 核心小点

### 1. 用 ps 查看进程

常用命令：

```bash
ps aux
ps aux | grep nginx
ps aux | grep '[n]ginx'
ps -ef | grep Java学习资料
```

`ps aux` 常见字段：

| 字段 | 含义 |
| --- | --- |
| `USER` | 进程所属用户 |
| `PID` | 进程 ID |
| `%CPU` | CPU 占用比例 |
| `%MEM` | 内存占用比例 |
| `VSZ` | 虚拟内存大小 |
| `RSS` | 常驻物理内存大小 |
| `STAT` | 进程状态 |
| `START` | 启动时间 |
| `COMMAND` | 启动命令 |

更适合排障的格式：

```bash
ps -eo pid,ppid,用户,stat,%cpu,%mem,etime,cmd --sort=-%cpu | head
ps -eo pid,ppid,用户,stat,%cpu,%mem,etime,cmd --sort=-%mem | head
```

说明：

- `pid` 是当前进程。
- `ppid` 是父进程。
- `etime` 是进程运行时长。
- `--sort=-%cpu` 按 CPU 从高到低排序。

### 2. 用 pgrep 精准定位

`pgrep` 比 `ps | grep` 更适合查找进程。

```bash
pgrep nginx
pgrep -af nginx
pgrep -u app -af demo-接口
```

常用参数：

- `-a`：显示完整命令。
- `-f`：匹配完整命令行，而不只是进程名。
- `-u`：按用户过滤。

示例：

```bash
pgrep -af 'Java学习资料.*demo-接口'
```

适合查找 Java、Node、Python 这类进程名不直接等于项目名的服务。

### 3. 用 top 和 htop 查看资源

`top` 是系统自带的实时资源查看工具：

```bash
top
top -p 进程PID
```

常用交互键：

- `P`：按 CPU 排序。
- `M`：按内存排序。
- `1`：展开每个 CPU 核心。
- `c`：显示完整命令行。
- `k`：发送信号结束进程，生产环境慎用。

`htop` 更直观：

```bash
htop
```

安装：

```bash
sudo apt install htop
sudo dnf install htop
```

注意：资源高不一定就是异常。比如部署后首次启动、缓存预热、定时任务执行，都可能短时间资源升高。要结合日志、业务时间点和最近变更判断。

### 4. 用 ss 查看监听端口

`ss` 用于查看 SocketIO 状态，比旧的 `netstat` 更推荐。

```bash
ss -lntup
sudo ss -lntup
sudo ss -lntup | grep ':8080'
```

参数说明：

- `-l`：只看监听状态。
- `-n`：显示数字端口，不解析服务名。
- `-t`：TCP。
- `-u`：UDP。
- `-p`：显示进程。

示例输出：

```text
LISTEN 0 511 0.0.0.0:80 0.0.0.0:* 用户s:(("nginx",pid=1234,fd=6))
```

重点看：

- 监听地址是 `127.0.0.1`、`0.0.0.0`，还是具体内网 IP。
- 监听端口是否是预期端口。
- 占用端口的进程名和 PID。

监听地址含义：

| 地址 | 含义 |
| --- | --- |
| `127.0.0.1:8080` | 只允许本机访问 |
| `0.0.0.0:8080` | 监听所有 IPv4 网卡 |
| `[::]:8080` | 监听 IPv6，可能同时影响 IPv4 |
| `内网IP:8080` | 只监听指定网卡 |

### 5. 用 lsof 查端口和文件

查看端口占用：

```bash
sudo lsof -i :8080
sudo lsof -iTCP:8080 -sTCP:LISTEN
```

查看某个进程打开了哪些文件：

```bash
sudo lsof -p 进程PID
```

查看某个目录是否仍被进程占用：

```bash
sudo lsof +D /opt/apps/demo-接口
```

`lsof` 在排查“文件已经删除但磁盘空间没有释放”时也很有用，后续磁盘章节会继续用到。

### 6. 用 f用户 快速找占用者

`f用户` 可以快速查看某个端口或文件被哪些进程使用：

```bash
sudo f用户 -n tcp 8080
sudo f用户 -v -n tcp 8080
```

它也支持杀进程：

```bash
sudo f用户 -k -n tcp 8080
```

生产环境不建议直接用 `-k`，除非你已经确认影响范围。

## 排查流程

### 场景 1：启动时报端口被占用

```bash
sudo ss -lntup | grep ':8080'
sudo lsof -iTCP:8080 -sTCP:LISTEN
ps -fp 进程PID
systemctl status 服务名
```

判断：

- 是旧版本服务没停干净？
- 是同机另一个项目占用了端口？
- 是 Nginx、Java、Node、Python 哪类进程？
- 是否由 systemd 托管？如果是，优先用 `systemctl stop`。

### 场景 2：服务进程存在但接口访问失败

```bash
pgrep -af demo-接口
sudo ss -lntup | grep ':8080'
curl -v http://127.0.0.1:8080/health
journalctl -u demo-接口 -n 100 --no-分页r
```

继续分层：

- 本机 `curl` 失败：优先看应用日志、配置、端口监听。
- 本机成功，内网失败：看监听地址、防火墙、安全组。
- 内网成功，域名失败：看 Nginx、DNS、证书、Nginx配置。

### 场景 3：CPU 或内存异常

```bash
top
ps -eo pid,ppid,用户,stat,%cpu,%mem,etime,cmd --sort=-%cpu | head -20
ps -eo pid,ppid,用户,stat,%cpu,%mem,etime,cmd --sort=-%mem | head -20
```

如果是 Java 进程：

```bash
jcmd 进程PID VM.通用mand_line
jcmd 进程PID Thread.print
jcmd 进程PID GC.heap_info
```

如果没有 JDK 工具，至少先记录 PID、命令、启动时间、日志时间点，再决定是否重启。

## 好用工具

- `htop`：更友好的进程查看工具。
- `glances`：综合系统资源监控。
- `lsof`：查看端口、文件、目录占用。
- `pstree`：查看父子进程树。
- `pidstat`：按进程观察 CPU、内存、IO。
- `jcmd` / `脚本tack`：Java 进程排障工具。

安装示例：

```bash
sudo apt install htop glances lsof psmisc sysstat
sudo dnf install htop glances lsof psmisc sysstat
```

## 使用技巧

- 端口问题先用 `ss`，需要更详细进程信息再用 `lsof`。
- 查 Java、Node、Python 服务时，优先用 `pgrep -af 项目关键词`。
- 看到多个同名进程时，看启动用户、工作目录、完整命令和父进程。
- 对 systemd 托管服务，不要先 kill，先看 `systemctl status` 和 unit 文件。
- 排查外部访问失败时，把“进程存在、端口监听、本机访问、内网访问、外网访问”分开验证。

## 难点

- 进程存在不代表端口监听，端口监听也不代表业务接口健康。
- `127.0.0.1` 监听只能本机访问，外部访问不到不是防火墙唯一原因。
- `grep` 自己也会出现在 `ps | grep` 结果中，可以用 `pgrep` 或 `grep '[n]ginx'` 避免误判。
- 高资源占用不一定是故障，要结合时间、日志、请求量和最近变更。

## 重点

- 进程排查先确认 PID、用户、命令、启动时间和资源占用。
- 端口排查先确认监听地址、监听端口和占用进程。
- 生产环境处理端口冲突前要判断进程归属，不要直接强杀。
- 服务不可访问要分层：进程、端口、本机请求、内网请求、外网请求。

## 练习

1. 启动一个简单 HTTP 服务，占用 8080 端口，用 `ss` 和 `lsof` 找到 PID。
2. 用 `pgrep -af` 查找一个 Java、Node 或 Python 进程。
3. 用 `top` 或 `htop` 找出当前 CPU 最高的 5 个进程。
4. 分别监听 `127.0.0.1:8080` 和 `0.0.0.0:8080`，观察访问范围差异。
