# 04 环境变量不生效

环境变量不生效的根因通常是“你看到的 Shell 环境”和“服务实际运行环境”不是同一个环境。systemd、cron、Docker、SSH 登录 Shell、CI/CD 都有各自的变量加载方式。

## 作用

- 区分终端变量、systemd 变量、cron 变量和Docker变量。
- 验证进程实际拿到的环境变量。
- 正确使用 `Environment=`、`EnvironmentFile=` 和 `.env`。
- 避免应用继续连接旧数据库、旧 Redis 或旧第三方服务。

## 常见现象

- 终端里 `echo $APP_ENV` 有值，服务里读不到。
- 改了 `.bashrc`，应用配置没有变化。
- 修改 `.env` 后服务仍连接旧数据库。
- systemd 服务启动时报缺少环境变量。
- cron 手动执行成功，定时执行失败。
- Docker Docker内变量和宿主机变量不一致。

## 先确认变量在哪个环境中失效

| 场景 | 变量来源 | 检查重点 |
| --- | --- | --- |
| 交互式终端 | `.bashrc`、`.profile`、当前 shell | `echo $VAR` |
| systemd 服务 | unit 的 `Environment` / `EnvironmentFile` | `systemctl show`、进程环境 |
| cron | crontab 顶部变量、脚本内变量 | cron 日志、脚本日志 |
| Docker | `Docker run -e`、通用pose `environment`、`env_file` | `Docker exec env` |
| CI/CD | 平台变量 | 是否 masked/protected、是否传入部署脚本 |

不要用终端中的 `echo $VAR` 证明 systemd 服务能读到变量。

## systemd 环境变量配置

方式一：直接写在 unit 中。

```ini
[Service]
Environment="APP_ENV=prod"
Environment="SERVER_PORT=8080"
```

方式二：使用环境文件。

```ini
[Service]
EnvironmentFile=/opt/apps/demo-接口/shared/配置/demo-接口.env
ExecStart=/usr/bin/Java学习资料 -jar /opt/apps/demo-接口/current/demo-接口.jar
```

环境文件示例：

```bash
APP_ENV=prod
SERVER_PORT=8080
DB_HOST=127.0.0.1
DB_PORT=3306
```

注意：

- systemd 的 `EnvironmentFile` 通常不写 `export`。
- 值里有空格时要谨慎处理引号。
- 变量文件权限要允许服务读取。
- 修改 unit 后需要 `daemon-reload`。
- 修改环境文件后需要重启服务。

## 检查 systemd 实际配置

查看 unit：

```bash
systemctl cat demo-接口
```

查看 systemd 记录的环境：

```bash
systemctl show demo-接口 -p Environment
systemctl show demo-接口 -p EnvironmentFiles
```

修改后：

```bash
sudo systemctl daemon-reload
sudo systemctl restart demo-接口
```

如果只改了环境文件，一般也要重启服务：

```bash
sudo systemctl restart demo-接口
```

## 查看进程实际环境

找到 PID：

```bash
pid=$(pgrep -f demo-接口 | head -n 1)
echo $pid
```

查看变量：

```bash
sudo tr '\0' '\n' < /proc/$pid/environ | grep APP_ENV
```

查看全部变量名：

```bash
sudo tr '\0' '\n' < /proc/$pid/environ | cut -d= -f1 | sort
```

注意：进程环境中可能包含敏感信息，不要随意复制到聊天工具或工单。

## .bashrc 为什么不生效

`.bashrc` 主要用于交互式 Bash。systemd 启动服务时不会自动读取你的 `.bashrc`。

这些写法只影响当前 Shell 或登录用户：

```bash
export APP_ENV=prod
echo 'export APP_ENV=prod' >> ~/.bashrc
source ~/.bashrc
```

对 systemd 服务，应写入：

- `Environment=`
- `EnvironmentFile=`
- 应用自己的配置文件
- 部署平台的变量注入机制

## cron 环境变量不生效

cron 环境通常很小，`PATH` 也不同。

查看任务：

```bash
crontab -l
```

推荐写法：

```cron
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
APP_ENV=prod

*/5 * * * * /opt/apps/demo-接口/scripts/作业.sh >> /var/日志/demo-作业.日志 2>&1
```

脚本里也可以显式加载：

```bash
#!/usr/bin/env bash
set -euo pipefail
source /opt/apps/demo-接口/shared/配置/作业.env
```

## Docker 环境变量不生效

Compose 示例：

```yaml
服务s:
  demo-接口:
    image: demo-接口:la测试
    env_file:
      - ./demo-接口.env
    environment:
      APP_ENV: prod
```

查看Docker环境：

```bash
Docker exec demo-接口 env | sort
```

注意：

- 修改 Compose env 后要重新创建Docker。
- 宿主机环境变量不会自动进入Docker。
- `env_file` 路径相对 通用pose 文件所在目录。

重新创建：

```bash
Docker 通用pose up -d --force-recreate demo-接口
```

## 常见错误和修复

### 环境文件路径错误

检查：

```bash
systemctl cat demo-接口
ls -lah /opt/apps/demo-接口/shared/配置/demo-接口.env
```

修复路径后：

```bash
sudo systemctl daemon-reload
sudo systemctl restart demo-接口
```

### 环境文件权限不足

检查：

```bash
namei -l /opt/apps/demo-接口/shared/配置/demo-接口.env
sudo -u app 测试 -r /opt/apps/demo-接口/shared/配置/demo-接口.env && echo readable
```

修复：

```bash
sudo chown root:app /opt/apps/demo-接口/shared/配置/demo-接口.env
sudo chmod 640 /opt/apps/demo-接口/shared/配置/demo-接口.env
```

### 修改后没有重启服务

环境变量是进程启动时读取的。修改文件不会自动改变已运行进程。

```bash
sudo systemctl restart demo-接口
```

### 变量名写错

检查变量名清单：

```bash
sudo tr '\0' '\n' < /proc/$pid/environ | cut -d= -f1 | sort
```

对照 `.env.example` 或应用配置文档。

## 安全注意

- 不要把完整环境变量输出到公共日志。
- `.env` 不提交 Git。
- 生产 `.env` 权限建议 `640` 或更严格。
- 排障截图要遮挡密码、Token、连接串。
- CI/CD 中使用安全变量，避免明文写进脚本。

## 预防

- 每个项目维护 `.env.example`。
- 生产变量使用统一路径，例如 `/opt/apps/项目/shared/配置/项目.env`。
- systemd unit 中只引用环境文件，不散落写大量变量。
- 发布后验证 `/proc/PID/environ` 中关键变量。
- 把变量变更纳入发布记录。

## 好用工具

| 工具 | 用途 |
| --- | --- |
| `systemctl cat` | 查看 unit 配置 |
| `systemctl show` | 查看 systemd 解析后的环境 |
| `/proc/PID/environ` | 查看进程真实环境 |
| `env`/`printenv` | 查看当前 Shell 环境 |
| `crontab -l` | 查看 cron 环境和任务 |
| `Docker exec env` | 查看Docker环境 |
| `namei -l` | 排查环境文件权限 |

## 练习

1. 在终端设置 `APP_ENV=dev`，观察 systemd 服务是否能读取。
2. 使用 `EnvironmentFile` 给服务配置 `APP_ENV=prod`。
3. 通过 `/proc/PID/environ` 验证服务真实变量。
4. 写一个 cron 任务，分别测试有无 `PATH` 时的执行差异。
