# 13 定时任务与 Shell 自动化

## 作用

定时任务与 Shell 自动化用于把重复运维动作沉淀成脚本：定时备份、清理日志、检查服务、同步文件、生成报表、重启失败服务。这个章节重点是写可维护、可观测、出错可追踪的脚本，而不是把一堆命令随便塞进 `cron`。

## 痛点

- 手动操作容易漏步骤，且不可追踪。
- cron 没执行或执行失败，但没有日志。
- 脚本在终端能跑，放到 cron 里失败。
- 环境变量在 cron 中缺失。
- 多个脚本同时运行，互相覆盖文件。

## Shell 脚本基础

脚本开头：

```bash
#!/usr/bin/env bash
set -euo pipefail
```

含义：

- `set -e` 命令失败时退出。
- `set -u` 使用未定义变量时报错。
- `set -o pipefail` 管道中任一命令失败都算失败。

注意：严格模式不是万能的，复杂脚本中要对允许失败的命令单独处理。

变量：

```bash
APP_NAME="demo-接口"
BASE_DIR="/opt/apps/${APP_NAME}"
```

引用变量时建议加双引号：

```bash
rm -rf "$TARGET_DIR"
```

但执行删除前要检查变量不能为空。

## 脚本安全模板

```bash
#!/usr/bin/env bash
set -euo pipefail

APP_NAME="demo-接口"
BASE_DIR="/opt/apps/${APP_NAME}"
LOG_FILE="/var/日志/${APP_NAME}-deploy.日志"

日志() {
  echo "[$(date '+%F %T')] $*" | tee -a "$LOG_FILE"
}

if [[ ! -d "$BASE_DIR" ]]; then
  日志 "base dir not found: $BASE_DIR"
  exit 1
fi

日志 "start 任务"
```

要点：

- 有日志。
- 有变量集中定义。
- 有关键路径检查。
- 出错时明确退出。

## cron 基础

编辑当前用户 crontab：

```bash
crontab -e
crontab -l
```

格式：

```text
分 时 日 月 周 命令
```

示例：

```text
*/5 * * * * /opt/scripts/check-demo-接口.sh >> /var/日志/check-demo-接口.日志 2>&1
0 2 * * * /opt/scripts/backup-db.sh >> /var/日志/backup-db.日志 2>&1
```

含义：

- 每 5 分钟检查一次服务。
- 每天凌晨 2 点执行备份。

## cron 环境问题

cron 的环境变量很少，不会自动加载你的 `.bashrc`。

建议：

- 脚本中使用绝对路径。
- 在 crontab 中设置必要 PATH。
- 把日志重定向到文件。
- 不依赖交互式输入。

示例：

```text
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
APP_ENV=prod

*/5 * * * * /opt/scripts/check-demo-接口.sh >> /var/日志/check-demo-接口.日志 2>&1
```

## 防止重复执行

使用 `flock`：

```bash
flock -n /tmp/backup-db.lock /opt/scripts/backup-db.sh
```

crontab：

```text
0 2 * * * flock -n /tmp/backup-db.lock /opt/scripts/backup-db.sh >> /var/日志/backup-db.日志 2>&1
```

用途：防止上一次任务没结束，下一次又开始。

## 服务检查脚本

示例：

```bash
#!/usr/bin/env bash
set -euo pipefail

SERVICE="demo-接口"
URL="http://127.0.0.1:8080/health"

if ! systemctl is-active --quiet "$SERVICE"; then
  echo "服务 inactive: $SERVICE"
  systemctl restart "$SERVICE"
  exit 1
fi

if ! curl -fsS "$URL" > /dev/null; then
  echo "health check failed: $URL"
  systemctl restart "$SERVICE"
  exit 1
fi

echo "ok"
```

注意：自动重启是止血手段，不应掩盖根因。频繁重启必须告警和排查。

## 日志清理脚本

更推荐用 日志rotate。如果必须写脚本，先预览：

```bash
find /opt/apps/demo-接口/shared/日志s -type f -name "*.日志.*" -mtime +14
```

确认后再删除：

```bash
find /opt/apps/demo-接口/shared/日志s -type f -name "*.日志.*" -mtime +14 -delete
```

不要写成无范围的：

```bash
find / -name "*.日志" -delete
```

这类命令风险极高。

## 备份脚本要点

备份脚本至少包含：

- 备份目标。
- 备份路径。
- 时间戳。
- 保留天数。
- 成功和失败日志。
- 恢复验证方式。

只会备份不会恢复，等于没有完整备份方案。

## 难点

- cron 默认工作目录通常不是脚本所在目录。
- cron 环境和手动终端环境不同。
- 脚本中变量为空可能导致危险路径。
- 自动化脚本如果没有日志，失败后很难追踪。

## 重点

- 脚本使用绝对路径。
- cron 一定要写日志。
- 删除和覆盖操作前先检查变量和目标范围。
- 备份任务必须定期验证恢复。
- 重复执行风险用锁控制。

## 练习

1. 写一个脚本检查当前磁盘使用率，并输出到日志。
2. 用 cron 每 5 分钟执行一次脚本。
3. 故意把 PATH 清空，观察脚本中相对命令失败，再改为绝对路径。
4. 用 `flock` 防止同一个脚本重复运行。
