# 服务器初始检查清单

## 作用

服务器初始检查清单用于建立固定起手式。每次拿到一台新服务器、登录一台测试机、准备部署一个项目之前，都应该先确认这台机器的身份、系统、资源、网络、时间、服务状态和端口占用。

这一步不是形式主义。很多部署失败不是项目本身的问题，而是服务器早就磁盘满了、时间不对、端口被占用、系统版本不匹配、已有服务失败或登录错机器。

## 痛点

- 登录错服务器后执行部署或重启命令。
- 服务器磁盘已满，还继续排查应用代码。
- 系统版本不清楚，复制了不适配的安装命令。
- 端口已被旧进程占用，新服务启动失败。
- 时间和时区错误，日志时间对不上，HTTPS 或 Token 校验异常。
- 已有失败服务未处理，部署后问题叠加。

## 优点

- 部署前先排除基础环境问题。
- 能快速建立服务器基线。
- 排障时减少猜测。
- 多台服务器可以用统一格式记录，方便对比。

## 一键检查顺序

建议每次登录后先执行：

```bash
whoami
hostname
pwd
cat /etc/os-release
ip addr
df -h
free -h
uptime
timedatectl
systemctl --failed
ss -lntup
```

这些命令都是只读命令，风险低，适合作为初始检查。

## 检查项详解

### 1. 当前用户

```bash
whoami
id
sudo -l
```

要确认：

- 当前是不是预期用户。
- 是否正在用 root。
- 是否有 sudo 权限。
- sudo 权限是否足够执行部署或服务管理。

判断规则：

- 日常部署尽量用普通用户。
- 需要改系统配置时再 sudo。
- 如果 `sudo -l` 没权限，不要硬改目录权限绕过，应先确认授权策略。

### 2. 当前主机

```bash
hostname
hostname -I
```

要确认：

- 主机名是不是目标服务器。
- IP 是否和预期一致。
- 是否登录到了测试环境还是生产环境。

使用技巧：

- 生产服务器建议主机名带环境标识，例如 `prod-接口-01`。
- 执行重启、删除、发布前再看一次 `hostname`。

### 3. 当前目录

```bash
pwd
ls -lah
```

要确认：

- 当前目录是否是目标部署目录。
- 是否在 `/root`、`/tmp` 这种不适合长期部署的位置。
- 操作是否使用绝对路径。

风险点：

- `rm -rf 日志s` 这种相对路径命令非常依赖当前目录。
- 部署脚本最好使用明确变量和绝对路径。

### 4. 系统版本

```bash
cat /etc/os-release
uname -a
```

要确认：

- 发行版和版本。
- 包管理器使用 `apt`、`dnf` 还是 `yum`。
- 内核版本是否过旧。

常见判断：

- Ubuntu、Debian：优先查 `apt`。
- Rocky、AlmaLinux、CentOS：优先查 `dnf` 或 `yum`。

### 5. IP 和网络

```bash
ip addr
ip route
```

要确认：

- 内网 IP。
- 是否有公网 IP。
- 默认路由是否存在。
- 网卡状态是否正常。

注意：

- 云服务器里系统看到的可能是内网 IP，公网 IP 在云平台映射。
- 服务监听内网、本机或所有地址，会影响访问方式。

### 6. 磁盘空间

```bash
df -h
du -h --max-depth=1 /var 2>/dev/null | sort -h
```

要确认：

- 根分区是否快满。
- `/var`、`/var/日志`、`/opt` 是否占用异常。

判断规则：

- 超过 80% 要关注。
- 超过 90% 要优先处理。
- 100% 时很多服务会出现连锁故障。

### 7. 内存和负载

```bash
free -h
uptime
top
```

要确认：

- 内存是否充足。
- swap 是否大量使用。
- load average 是否明显高于 CPU 核数。

注意：

- Linux 会用空闲内存做缓存，`free` 小不一定是问题。
- 更关注 `available`。

### 8. 时间和时区

```bash
date
timedatectl
```

要确认：

- 时间是否正确。
- 时区是否符合预期。
- NTP 是否同步。

时间错误可能导致：

- 日志时间对不上。
- HTTPS 证书校验失败。
- Token 过期判断异常。
- cron 执行时间异常。

### 9. 失败服务

```bash
systemctl --failed
```

要确认：

- 是否已有失败服务。
- 失败服务是否和当前部署有关。

进一步查看：

```bash
systemctl status 服务名
journalctl -u 服务名 -n 100
```

### 10. 监听端口

```bash
ss -lntup
```

要确认：

- 目标端口是否已被占用。
- 哪些服务正在对外监听。
- 是否存在不该暴露的端口。

常见判断：

- `127.0.0.1:8080` 只允许本机访问。
- `0.0.0.0:8080` 表示所有 IPv4 网卡监听。
- 数据库和 Redis 不应直接公网暴露。

## 推荐记录模板

可以把检查结果写成：

```markdown
# 服务器基线记录

- 检查时间：
- 主机名：
- 登录用户：
- 系统版本：
- 内网 IP：
- 公网 IP：
- CPU/内存：
- 磁盘使用率：
- 时区：
- 失败服务：
- 监听端口：
- 备注：
```

## 使用技巧

- 部署前检查一次，部署后再检查一次。
- 多台服务器使用同一模板记录，便于比较差异。
- 发现磁盘、时间、失败服务异常时，先处理基础问题再部署。
- 高风险操作前再次确认 `hostname` 和 `pwd`。

## 难点

- 云服务器公网 IP 可能不在 `ip addr` 输出里，要结合云控制台。
- `systemctl --failed` 显示历史失败服务，不一定都是当前故障，但不能忽略。
- 端口监听存在不代表业务健康，还需要 HTTP 健康检查。
- `df` 和 `du` 不一致时，可能有已删除但仍被进程占用的文件。

## 重点

- 初始检查是部署和排障的第一步。
- 先看身份、主机、目录，再做任何修改。
- 先看系统、资源、时间、服务和端口，再判断应用问题。
- 把检查结果记录成服务器基线。

## 练习

1. 登录一台测试服务器，按本节命令完整检查一次。
2. 把检查结果整理成 `server-baseline.md`。
3. 故意启动一个占用端口的测试服务，再用 `ss -lntup` 找到它。
4. 把系统时间、磁盘、失败服务、监听端口四类信息分别解释给自己听。
