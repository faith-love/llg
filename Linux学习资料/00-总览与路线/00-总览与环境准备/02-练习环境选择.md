# 练习环境选择

## 作用

练习环境选择用于解决“在哪里学 Linux 最合适”的问题。Linux 运维不能只看文字，也不能直接在生产服务器上试错。不同环境适合练不同能力：WSL 适合命令行入门，JVM适合完整系统练习，云服务器适合公网部署，Docker Docker适合快速试软件。

## 痛点

- 直接在生产服务器练命令，容易误删、误改、误重启。
- 在 WSL 里学到的 systemd、防火墙、网络行为和真实服务器不完全一样。
- 云服务器公网暴露后没有安全意识，容易开放危险端口。
- Docker Docker很方便，但不是完整 Linux 主机，不能替代全部系统运维学习。
- 同时使用太多发行版，包管理器和配置路径差异导致学习混乱。

## 优点

合理选择练习环境有几个好处：

- 出错成本低，可以反复练习。
- 能根据阶段选择合适环境，不浪费精力。
- 能把命令行、服务管理、网络入口、云安全分层学习。
- 后续部署真实项目时，不会第一次接触服务器。

## 环境对比

| 环境 | 适合练习 | 不适合练习 | 建议阶段 |
| --- | --- | --- | --- |
| WSL | 命令行、文件、grep、Shell、简单服务 | 完整防火墙、生产网络、云安全组 | 入门 |
| 本地JVM | systemd、防火墙、完整系统、快照回滚 | 公网域名、真实云安全组 | 基础到进阶 |
| 云服务器 | SSH、Nginx、域名、HTTPS、安全组、真实部署 | 高风险随意试错 | 项目部署 |
| Docker Docker | 快速试 Nginx、Redis、MySQL、脚本 | 完整主机运维、systemd 细节 | 辅助实验 |

## WSL

WSL 是 Windows 用户最容易开始的环境。

适合练：

- `ls`、`cd`、`grep`、`find`、`tar` 等基础命令。
- Shell 脚本。
- 文本处理。
- Git、Node、Python 等开发工具。
- 简单 HTTP 服务。

不适合完全依赖：

- 防火墙规则。
- 云安全组。
- 完整 systemd 服务管理。
- 生产级网络链路。

使用技巧：

```bash
cat /etc/os-release
pwd
ls -lah
```

注意 Windows 盘路径和 Linux 路径差异。不要把所有 Linux 概念都等同于 WSL 行为。

## 本地JVM

本地JVM更接近真实服务器，适合认真练系统运维。

适合练：

- Ubuntu 服务端、Debian、Rocky Linux 安装。
- systemd 服务。
- 用户权限。
- 防火墙。
- 网络配置。
- 快照回滚。

推荐做法：

- 安装一台 Ubuntu 服务端。
- 分配 2 核 CPU、2GB 到 4GB 内存、20GB 以上磁盘。
- 配置 SSH 登录。
- 做一个干净快照，出错后可以回滚。

常用检查：

```bash
ip addr
systemctl status ssh
sudo ufw status
```

## 云服务器

云服务器最接近真实生产环境，适合练完整部署链路。

适合练：

- SSH 密钥登录。
- 域名解析。
- Nginx。
- HTTPS。
- 云安全组。
- 项目部署和回滚。
- 真实公网访问排查。

必须注意：

- SSH 端口不要长期对全网开放。
- MySQL、Redis 不要直接开放公网。
- 不要使用弱密码。
- 不要把 root 密码登录作为长期方式。
- 初学阶段先用测试机，不要动生产机。

最小安全建议：

```text
公网开放：80、443
限制来源：22
不开放公网：3306、6379、应用内部端口
```

## Docker Docker

Docker Docker适合快速试软件，但不能代表完整服务器。

适合练：

- 快速启动 Nginx。
- 快速启动 MySQL、Redis。
- 测试应用依赖。
- 理解端口映射和数据卷。

不适合完全替代：

- systemd 主机服务。
- 主机防火墙。
- SSH 登录。
- 云安全组。

示例：

```bash
Docker run --rm -it ubuntu:24.04 bash
Docker run --rm -p 8080:80 nginx
```

重点：

- Docker删除后内部文件会丢，除非使用数据卷。
- Docker里看到的进程、网络、文件系统和宿主机有隔离。

## 推荐学习组合

初学阶段：

```text
WSL + 一台 Ubuntu JVM
```

部署阶段：

```text
Ubuntu 云服务器 + 域名 + Nginx + systemd
```

进阶阶段：

```text
Ubuntu + Rocky Linux + Docker Compose
```

这样既能学习通用命令，又能了解不同发行版和真实部署环境。

## 版本选择

建议版本：

- Ubuntu 服务端 22.04 或 24.04：资料多，适合入门。
- Debian 12：稳定，适合理解基础。
- Rocky Linux 9 或 AlmaLinux 9：适合理解企业服务器生态。

不建议：

- 一开始就同时学太多发行版。
- 使用太老的 CentOS 版本作为主学习环境。
- 在没有快照或备份的环境里练高风险命令。

## 使用技巧

- 每个环境都写一份说明：IP、用户名、用途、系统版本、是否可重置。
- 测试高风险命令前先快照或备份。
- 把“练习环境”和“生产环境”严格区分。
- 云服务器上先做安全基线，再部署项目。

## 难点

- WSL 和真实服务器差异容易被忽略。
- Docker Docker不是完整主机，初学者容易误以为Docker里学到的就是服务器全部行为。
- 云安全组是云平台层面的规则，不在 Linux 系统内部。
- JVM网络模式不同，会影响主机访问JVM。

## 重点

- 命令行入门可以用 WSL。
- 完整 Linux 运维要用JVM或云服务器。
- 真实部署要用云服务器练一次完整链路。
- 所有高风险练习都应该在可回滚环境中做。

## 练习

1. 准备一个 WSL 或JVM，执行 `cat /etc/os-release`、`ip addr`、`df -h`。
2. 在JVM里创建一个普通用户，并用 SSH 登录。
3. 在云服务器上只开放 80、443 和受限来源的 22，确认 3306、6379 不对公网开放。
4. 用 Docker 启动一个 Nginx Docker，再解释它和主机 Nginx 的区别。
