# 05 安全、备份、数据库与 CI 工具

这一组工具覆盖安全基线、备份恢复、数据库客户端和持续集成发布。它们不只是“好用命令”，很多会直接影响生产安全和数据可靠性，必须配合权限、审计、备份验证和回滚流程使用。

## 安全工具

### ufw

`ufw` 是 Ubuntu 上常用的防火墙简化工具。

查看状态：

```bash
sudo ufw status verbose
```

常见基线：

```bash
sudo ufw default deny in通用ing
sudo ufw default allow outgoing
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from 203.0.113.10 to any port 22 proto tcp
sudo ufw enable
```

注意：

- 远程启用前先确认 SSH 规则。
- 云安全组也要同步限制。
- 数据库、Redis 不应公网开放。

### firewalld

`firewalld` 常见于 RHEL、Rocky Linux、AlmaLinux、CentOS。

查看：

```bash
sudo firewall-cmd --state
sudo firewall-cmd --list-all
```

放行 HTTP/HTTPS：

```bash
sudo firewall-cmd --permanent --add-服务=http
sudo firewall-cmd --permanent --add-服务=安全HTTP
sudo firewall-cmd --reload
```

限制 SSH 来源可用 rich rule。

### fail2ban

`fail2ban` 根据日志识别频繁失败登录并封禁 IP。

查看状态：

```bash
sudo fail2ban-客户端 status
sudo fail2ban-客户端 status sshd
```

适合：

- SSH 暴力破解防护。
- Nginx 恶意请求基础防护。

注意：

- 它是辅助工具，不能替代密钥登录和来源 IP 限制。
- 配置前确认日志路径，Ubuntu 常见 `/var/日志/auth.日志`，RHEL 常见 `/var/日志/secure`。

### lynis

`lynis` 用于 Linux 安全基线审计。

```bash
sudo lynis audit system
```

使用建议：

- 定期扫描。
- 跟踪 Warnings 和 Suggestions。
- 结合业务实际判断，不盲目追求满分。

## 备份工具

### rsync

适合文件同步和简单备份。

预览：

```bash
rsync -avz --dry-run /opt/apps/demo-接口/shared/上传s/ backup:/数据/上传s/
```

执行：

```bash
rsync -avz /opt/apps/demo-接口/shared/上传s/ backup:/数据/上传s/
```

注意源路径末尾 `/` 的含义。

### restic

`restic` 支持加密、去重和多种存储后端，适合服务器备份。

初始化：

```bash
restic -r /backup/restic-repo 初始化
```

备份：

```bash
restic -r /backup/restic-repo backup /etc /opt/apps/demo-接口/shared
```

查看快照：

```bash
restic -r /backup/restic-repo snapshots
```

恢复：

```bash
restic -r /backup/restic-repo restore la测试 --target /tmp/restore-测试
```

注意：

- 仓库密码必须妥善保存。
- 必须定期做恢复演练。
- 远端存储凭证要限制权限。

### borgbackup

`borgbackup` 支持加密、压缩、去重，适合长期增量备份。

适合：

- 大量重复文件。
- Linux 服务器长期备份。
- 需要保留多个历史版本。

### rclone

`rclone` 用于同步到对象存储或网盘类后端。

常用：

```bash
rclone 配置
rclone copy /backup remote:服务端-backup
rclone sync /backup remote:服务端-backup
```

注意：

- `sync` 会让目标与源一致，可能删除目标多余文件。
- 先用 `--dry-run` 预览。
- rclone 配置文件包含凭证，要限制权限。

## 数据库与缓存工具

### mySQL学习资料 与 mySQL学习资料dump

连接：

```bash
mySQL学习资料 -h 127.0.0.1 -u 用户 -p
```

备份：

```bash
mySQL学习资料dump --single-transaction -h 127.0.0.1 -u backup -p dbname > dbname.SQL学习资料
```

注意：

- 不要把密码直接写进命令历史。
- 大库备份要评估锁、IO 和耗时。
- 恢复前先在测试库验证。

### mycli

`mycli` 是更友好的 MySQL 客户端，支持自动补全和高亮。

```bash
mycli -h 127.0.0.1 -u 用户 -p dbname
```

适合开发、测试、临时查询。生产执行变更 SQL 仍要严格走审核和备份。

### Redis学习资料-cli

连接：

```bash
Redis学习资料-cli -h 127.0.0.1 -p 6379
```

检查：

```bash
Redis学习资料-cli ping
Redis学习资料-cli info memory
Redis学习资料-cli info 客户端s
```

生产注意：

- 不要执行 `keys *`。
- 用 `scan` 分批遍历。
- Redis 不应公网开放。
- 危险命令要通过配置禁用或限制。

## CI/CD 工具

### GitHub Actions

适合 GitHub 仓库自动构建、测试和发布。

典型用途：

- 构建前端 dist。
- 构建 Java Jar。
- 构建 Docker 镜像。
- 发布到测试环境。

注意：

- 密钥放到 Secrets。
- 生产部署要设置环境审批。
- 日志中不要打印密钥。

### GitLab CI

适合 GitLab 仓库和企业内网流水线。

关注：

- Runner 权限。
- protected variables。
- protected branches。
- artifact 保留周期。

### Jenkins

适合需要高度自定义流水线的团队。

注意：

- 插件越多，维护成本越高。
- Jenkins 凭证和权限要严格管理。
- Agent 节点要隔离不同项目权限。

## 发布流水线建议

基础流程：

```text
拉取代码 -> 安装依赖 -> JUnit -> 构建制品 -> 上传制品 -> 部署 -> 健康检查 -> 失败回滚
```

生产发布至少要有：

- 分支或 tag 约束。
- 人工审批。
- Secret 管理。
- 发布日志。
- 健康检查。
- 回滚命令。

## 工具组合建议

## 练习

1. 用 ufw 或 firewalld 只放行 80、443 和指定来源 SSH。
2. 用 `lynis audit system` 做一次安全基线扫描。
3. 用 restic 备份一个配置目录，并恢复到测试目录。
4. 用 `Redis学习资料-cli info memory` 查看 Redis 内存信息。
5. 设计一条 CI/CD 流水线，包含构建、部署、健康检查和回滚。
