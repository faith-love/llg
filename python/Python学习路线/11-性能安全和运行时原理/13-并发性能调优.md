# 并发性能调优

并发可以提升吞吐，但也会放大资源竞争、失败率和调试难度。并发调优的核心是找到合适并发度，而不是无限增加线程、进程或协程。

## 并发度

并发度过低：

- 资源利用不足。
- 总耗时长。

并发度过高：

- CPU 上下文切换增加。
- 内存增长。
- 外部服务限流。
- 数据库连接耗尽。
- 队列堆积。

## 线程池调优

适合 IO 密集。

关注：

- `max_workers`。
- 单任务 timeout。
- 错误重试。
- 队列大小。
- 外部资源限制。

## 进程池调优

适合 CPU 密集。

关注：

- CPU 核心数。
- 任务粒度。
- 序列化成本。
- 返回值大小。
- 内存占用。

## asyncio 调优

适合高并发 IO。

关注：

- Semaphore 并发上限。
- Queue maxsize。
- timeout。
- cancellation。
- 阻塞同步调用。
- 连接池。

## 背压

背压用于让生产者在消费者处理不过来时放慢。

实现：

- 有界队列。
- 限流。
- 拒绝新任务。
- 降级。

## 并发测试

测试不同并发度：

```text
1, 2, 5, 10, 20, 50
```

记录：

- 总耗时。
- 成功率。
- 平均耗时。
- P95。
- 错误数。
- CPU/内存。

## 常见错误

### 并发越大越好

通常会先撞到外部资源限制。

### 无 timeout

并发 worker 被卡住。

### 队列无限大

内存堆积。

### CPU 任务用线程硬撑

纯 Python CPU 密集任务通常考虑进程。

## 练习

1. 对线程池测试多个 max_workers。
2. 对进程池测试多个 max_workers。
3. 对 asyncio 请求测试多个并发上限。
4. 记录成功率和耗时。
5. 设置队列 maxsize。
6. 模拟外部服务限流。
7. 增加退避重试。
8. 写并发调优报告。

## 验收标准

- 能通过数据选择并发度。
- 能设置 timeout 和背压。
- 能区分线程、进程、asyncio 调优重点。
