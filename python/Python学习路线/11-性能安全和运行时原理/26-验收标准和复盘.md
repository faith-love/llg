# 验收标准和复盘

完成第 11 阶段后，你应该能用工具定位性能瓶颈，能解释关键运行时机制，能系统识别 Python 项目的常见安全风险，并能输出可复现的性能报告和安全加固清单。

这一阶段的验收重点是“证据链”：性能优化要有测量证据，安全加固要有风险来源和防护说明。

## 阶段能力目标

完成本阶段后应达到：

- 能建立性能基准。
- 能使用 `perf_counter` 和 `timeit`。
- 能使用 `cProfile`。
- 能进行行级热点分析。
- 能解释对象引用和内存开销。
- 能使用 `tracemalloc`。
- 能根据复杂度选择数据结构。
- 能优化字符串、集合、IO 和数据库边界。
- 能设计缓存策略。
- 能调优线程池、进程池和 asyncio 并发。
- 能解释 GIL、GC、import、字节码、CPython 边界。
- 能识别 SQL 注入、命令注入、路径穿越。
- 能规避危险反序列化。
- 能保护密钥和配置。
- 能检查依赖供应链风险。
- 能做 Web/API 安全加固。

## 综合项目验收

### 项目 1：性能优化报告

必须包含：

- 原始现象。
- 固定输入。
- 优化目标。
- 基准命令。
- cProfile 输出摘要。
- 热点分析。
- 修改方案。
- 优化前后对比。
- 剩余风险。

通过标准：

- 优化目标可测量。
- 改动针对 profile 热点。
- 优化后数据明确改善。
- 没有明显牺牲正确性。

### 项目 2：内存排查报告

必须包含：

- 内存增长复现。
- tracemalloc 快照。
- 快照对比。
- 增长来源。
- 修复方案。
- 修复后对比。

通过标准：

- 能定位到代码位置。
- 能解释增长原因。
- 能避免无上限缓存或队列。

### 项目 3：安全加固报告

必须包含：

- 输入边界清单。
- 注入风险检查。
- 路径安全检查。
- 反序列化检查。
- 密钥和日志检查。
- 依赖安全检查。
- Web/API 权限检查。
- 修复记录。

通过标准：

- 高风险输入有校验。
- 命令和 SQL 不拼接不可信输入。
- token 不进日志。
- 上传下载有路径边界。
- 认证授权有测试或检查证据。

### 项目 4：运行时原理笔记

必须包含：

- GIL 对项目的影响判断。
- GC 和对象生命周期案例。
- import 循环或顶层副作用案例。
- dis 字节码观察。
- CPython 实现细节边界。

## 检查命令清单

示例：

```powershell
python -m timeit "sum(range(1000))"
python -m cProfile -s cumulative script.py
python -X tracemalloc script.py
python -m dis module.py
```

具体命令可根据项目调整，但报告必须能复现。

## 安全验收问题

必须能回答：

- 所有外部输入在哪里校验？
- SQL 是否全部参数化？
- 是否使用 `shell=True`？
- 文件路径是否限制在工作区？
- 是否使用 pickle 处理不可信输入？
- token 是否可能进入日志？
- `.env` 是否进入镜像或版本库？
- 依赖是否固定并检查漏洞？
- API 是否有越权检查？
- CORS 是否生产收紧？

## 复盘问题

完成后写复盘，回答：

1. 你最初猜测的性能瓶颈是否正确？
2. cProfile 发现了什么意外热点？
3. 哪个优化收益最大？
4. 哪个优化没有价值，为什么？
5. 内存增长的真正来源是什么？
6. 哪个安全风险最容易被忽略？
7. 哪些输入边界还需要长期监控？
8. 哪些运行时细节会影响你的编码习惯？
9. 哪些检查应该加入 CI？
10. 下一阶段综合项目中如何应用这些能力？

## 进入下一阶段前的检查

可以进入第 12 阶段的标准：

- 能输出性能优化证据链。
- 能输出安全加固证据链。
- 能解释关键运行时机制。
- 能把性能和安全检查纳入项目工程流程。

第 12 阶段会进入综合项目、源码阅读和长期提升。如果第 11 阶段没有建立测量和安全检查习惯，综合项目很容易只停留在“功能能跑”的层面。
