# 导入系统和模块缓存

Python 的 import 不只是读文件，它涉及模块搜索路径、模块初始化、缓存和命名空间。理解导入系统能帮助你排查循环导入、命名冲突和启动慢问题。

## import 基本流程

大致过程：

1. 检查 `sys.modules` 是否已有模块。
2. 根据 `sys.path` 查找模块。
3. 加载模块。
4. 执行模块顶层代码。
5. 把模块对象放入缓存。

## sys.modules

`sys.modules` 是模块缓存。

同一个模块通常只初始化一次。

```python
import sys


print("json" in sys.modules)
```

## sys.path

`sys.path` 决定模块搜索路径。

常见来源：

- 当前脚本目录。
- 虚拟环境。
- site-packages。
- PYTHONPATH。

不要依赖随意修改 `sys.path` 解决结构问题。

## 顶层代码副作用

模块导入时会执行顶层代码。

避免在顶层做：

- 连接数据库。
- 读取生产配置。
- 发网络请求。
- 启动线程。
- 执行重任务。

应放到函数或入口中。

## 循环导入

示例：

```text
a.py import b
b.py import a
```

常见原因：

- 模块职责不清。
- 依赖方向混乱。
- 类型注解导入导致循环。

解决：

- 提取公共模块。
- 调整依赖方向。
- 延迟导入。
- 使用 `if TYPE_CHECKING`。

## if TYPE_CHECKING

```python
from typing import TYPE_CHECKING


if TYPE_CHECKING:
    from my_project.models import User
```

用于只在类型检查时导入，避免运行时循环导入。

## 常见错误

### 文件名和标准库重名

例如 `json.py`、`typing.py`，会遮蔽标准库。

### 导入时执行重任务

导致启动慢和测试不稳定。

### 用 sys.path hack

说明项目结构需要整理。

### 循环导入靠随机移动 import 解决

应从模块依赖设计上修复。
