# 进程通信和共享状态

进程之间默认不共享内存。一个进程修改自己的变量，另一个进程看不到。需要通信时，应优先传递消息，而不是强行共享复杂状态。

## 为什么进程通信更复杂

线程在同一进程内，能访问同一份内存。进程有各自独立的内存空间。

这带来好处：

- 隔离性更好。
- 一个进程崩溃不一定影响其他进程。
- 可以利用多核。

也带来成本：

- 数据需要序列化。
- 通信更慢。
- 共享状态更难维护。

## Queue

`multiprocessing.Queue` 可以在进程之间传递消息。

```python
from multiprocessing import Process, Queue


def worker(q):
    q.put("hello")


if __name__ == "__main__":
    q = Queue()
    p = Process(target=worker, args=(q,))
    p.start()
    print(q.get())
    p.join()
```

适合：

- 子进程返回结果。
- 主进程分发任务。
- 收集错误信息。

## Pipe

`Pipe` 提供两个连接端。

```python
from multiprocessing import Pipe


parent_conn, child_conn = Pipe()
```

适合两个进程之间简单通信。多生产者、多消费者优先用 Queue。

## Manager

`Manager` 可以创建跨进程共享对象：

```python
from multiprocessing import Manager


with Manager() as manager:
    shared_list = manager.list()
```

但它有明显开销。不要把它当普通列表高频读写。

适合：

- 少量共享状态。
- 简单协调。
- 学习理解。

不适合：

- 高频计数。
- 大量数据交换。
- 性能敏感路径。

## Value 和 Array

`Value` 和 `Array` 用于共享简单 C 类型数据。

```python
from multiprocessing import Value


counter = Value("i", 0)
```

使用共享值仍然要考虑锁。

## 最佳实践：少共享，多传递

推荐结构：

```text
主进程生成任务 -> 子进程独立处理 -> 返回结果摘要 -> 主进程统一写报告
```

避免：

```text
多个子进程同时修改同一个复杂对象
```

## 进程池中的通信

使用 `ProcessPoolExecutor` 时，最简单的通信方式是：

- 参数传入。
- 返回值传出。
- 异常通过 `future.result()` 传出。

这比手写 Queue 更清晰。

## 常见错误

### 以为全局变量在进程间共享

子进程拿到的是自己的内存副本。

### Manager 滥用

共享代理对象性能较低，不适合高频操作。

### 多进程同时写同一个文件

容易造成内容交错和文件损坏。优先主进程统一写。

### Queue 没有消费导致阻塞

生产速度大于消费速度时，队列可能变成瓶颈。

## 练习

1. 用进程 Queue 返回结果。
2. 用 Queue 收集子进程异常。
3. 用 Pipe 在两个进程之间发送消息。
4. 用 Manager list 收集少量结果。
5. 观察 Manager 高频写入的性能问题。
6. 把共享列表设计改成返回值收集。
7. 多进程处理文件路径，主进程写 CSV 报告。

## 验收标准

- 知道进程默认不共享内存。
- 能使用 Queue 传递结果。
- 能解释 Manager 的开销。
- 能优先采用“子进程返回结果，主进程统一汇总”的结构。
