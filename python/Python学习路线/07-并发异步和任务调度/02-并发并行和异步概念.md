# 并发并行和异步概念

并发、并行和异步经常被混用，但它们不是同一个概念。理解这些概念是选择线程、进程和 asyncio 的前提。

## 并发

并发是指一个程序在同一段时间内处理多个任务。

它强调“任务管理方式”，不一定表示同一瞬间真的有多个任务在 CPU 上运行。

例子：

- 下载 100 个文件。
- 同时处理多个用户请求。
- 一个任务读文件时，另一个任务可以准备数据。

并发的目标：

- 减少等待时间浪费。
- 提高资源利用率。
- 改善吞吐量。

## 并行

并行是指多个任务在同一时刻真正同时执行，通常需要多个 CPU 核心。

例子：

- 4 个进程分别在 4 个 CPU 核心上计算。
- 多个 worker 同时处理图像。
- 多台机器同时跑任务。

并行的目标：

- 缩短 CPU 密集计算总耗时。
- 使用多核能力。

## 异步

异步是一种编程方式：任务发起等待后不阻塞整个程序，而是把控制权交回调度器，等结果准备好再继续。

例子：

- 发起网络请求后，事件循环继续运行其他协程。
- `await asyncio.sleep(1)` 期间，其他任务可以执行。

异步强调：

- 非阻塞等待。
- 事件循环调度。
- 协作式切换。

## 阻塞和非阻塞

阻塞：

```python
import time

time.sleep(3)
```

当前线程会停住 3 秒。

非阻塞或协作式等待：

```python
import asyncio

await asyncio.sleep(3)
```

当前协程暂停，事件循环可以执行其他协程。

## 同步和异步

同步通常是：

```text
发起任务 -> 等结果 -> 得到结果 -> 做下一步
```

异步通常是：

```text
发起任务 -> 让出控制权 -> 其他任务运行 -> 结果就绪 -> 回来继续
```

同步不等于慢，异步也不等于快。任务少、逻辑简单时，同步代码更清晰。

## 线程、进程、协程的粗略对比

| 模型 | 单位 | 适合 | 不适合 |
| --- | --- | --- | --- |
| 线程 | OS 线程 | 阻塞 IO、调用同步库 | 大量 Python CPU 计算 |
| 进程 | OS 进程 | CPU 密集、多核计算 | 大量小任务、共享复杂状态 |
| 协程 | 用户态任务 | 高并发网络 IO | 调用阻塞同步库 |

## 一个形象例子

串行：

```text
烧水 -> 等水开 -> 切菜 -> 炒菜
```

并发：

```text
烧水 -> 水在烧时切菜 -> 水开后继续
```

并行：

```text
一个人烧水，另一个人切菜
```

异步：

```text
设置水壶提醒 -> 去切菜 -> 提醒响了再回来
```

## 常见误解

### 并发一定更快

不一定。并发有调度、上下文切换、同步和调试成本。任务太少或太快时，串行更合适。

### 线程一定能用多核

在常规 CPython 中，Python 字节码执行会受到 GIL 影响。线程适合很多 IO 任务，但不适合指望它加速纯 Python CPU 密集计算。

### asyncio 会自动把同步代码变快

不会。如果协程内部调用 `time.sleep()`、同步网络请求、同步数据库查询，事件循环仍会被阻塞。

### 进程池可以随便开很大

进程有内存和启动成本。进程数量通常接近 CPU 核心数，而不是越多越好。

## 判断问题

面对一个慢任务，先问：

1. 慢在哪里？
2. 是等网络、等磁盘、等数据库，还是 CPU 在计算？
3. 任务之间是否独立？
4. 是否需要共享状态？
5. 单个任务失败是否影响整体？
6. 是否需要限制并发数量？
7. 是否需要取消和超时？
