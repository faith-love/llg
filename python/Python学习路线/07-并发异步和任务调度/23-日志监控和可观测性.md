# 日志监控和可观测性

并发程序如果没有可观测性，出错时很难排查。你需要知道每个任务什么时候开始、什么时候结束、耗时多久、是否成功、失败原因是什么、是否重试过。

## 可观测性包含什么

基础层面包括：

- 日志。
- 指标。
- 运行报告。
- 错误记录。
- 任务状态。

学习阶段先掌握日志和报告。

## 任务 ID

每个任务都应该有标识。

例如：

- URL。
- 文件路径。
- 订单编号。
- 批次号。
- 自动生成 UUID。

日志中至少包含：

```text
task_id=xxx status=success elapsed=1.23s
```

## 结构化结果

```python
from dataclasses import dataclass


@dataclass
class TaskResult:
    task_id: str
    success: bool
    elapsed: float
    attempts: int
    message: str
```

并发任务返回 `TaskResult`，主流程统一汇总。

## 日志字段

建议记录：

| 字段 | 说明 |
| --- | --- |
| task_id | 任务标识 |
| status | success/failed/skipped |
| elapsed | 耗时 |
| attempts | 尝试次数 |
| worker | 线程、进程或任务名 |
| error | 错误摘要 |
| input | 必要输入摘要 |

不要记录密码、token、完整敏感数据。

## 线程日志

```python
import logging


logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(threadName)s %(message)s",
)
```

线程名能帮助定位哪个 worker 出错。

## asyncio 日志

可以在任务创建时传入任务 ID，并在每次日志中显式带上。

```python
async def work(task_id):
    logging.info("task_id=%s start", task_id)
```

不要过度依赖当前 Task 名称，业务 task_id 更清晰。

## 指标

最小指标：

- 总任务数。
- 成功数。
- 失败数。
- 跳过数。
- 平均耗时。
- 最大耗时。
- 重试次数。
- 超时次数。

这些指标可以写入 Markdown、CSV 或 JSON 报告。

## 运行报告

报告示例：

```json
{
  "total": 100,
  "success": 92,
  "failed": 8,
  "timeout": 3,
  "elapsed_seconds": 31.2
}
```

明细报告：

```csv
task_id,status,elapsed,attempts,message
url-1,success,0.32,1,ok
url-2,failed,5.00,3,timeout
```

## 告警边界

学习阶段可以只打印或写日志。真实环境要考虑告警：

- 连续失败超过 N 次。
- 失败率超过阈值。
- 单次任务超时。
- 队列长度持续增长。
- 周期任务长时间没有成功。

## 常见错误

### 只记录“失败了”

没有任务 ID、输入和异常类型，无法复现。

### 多线程 print 混乱

使用 logging，避免多线程输出交错。

### 日志过多

并发任务多时，DEBUG 日志可能非常大。正常运行用 INFO，排查时再提高详细度。

### 日志包含敏感信息

token、密码、cookie、密钥不能写入日志。

## 练习

1. 给线程池任务增加 task_id。
2. 记录每个任务开始和结束。
3. 记录每个任务耗时。
4. 输出成功失败统计。
5. 生成 CSV 明细报告。
6. 生成 JSON 汇总报告。
7. 统计超时次数和重试次数。
8. 给长期任务记录最近一次成功时间。

## 验收标准

- 能为并发任务设计 task_id。
- 能记录成功、失败、耗时和重试。
- 能输出汇总和明细报告。
- 能避免日志泄露敏感信息。
