# 阶段目标

第 07 阶段要建立一个核心判断：并发不是让程序“看起来高级”，而是用合适的执行模型处理合适的任务，并且在出错、超时、取消、重试、退出时仍然可控。

本阶段结束后，你应该能写出可运行、可观察、可限制资源的并发程序，而不是只会复制几个 `threading` 或 `asyncio` 示例。

## 本阶段要解决的问题

你需要能回答：

- 这个任务适合串行、线程、进程还是 asyncio？
- 程序慢是因为 IO 等待，还是 CPU 计算？
- 线程为什么不一定能让 CPU 计算变快？
- 多个任务同时写同一个变量会发生什么？
- 如何限制并发数量？
- 如何收集每个任务的成功、失败和耗时？
- 如何处理超时和取消？
- 如何避免无限重试和任务风暴？
- 周期任务错过执行时该怎么办？
- 后台任务如何优雅退出？

## 必须完成的项目

### 项目 1：多线程批量 IO 工具

示例方向：

- 并发检查多个文件。
- 并发下载多个 URL。
- 并发调用多个慢速命令。

必须包含：

- 线程池。
- 并发数量限制。
- 超时。
- 错误记录。
- 汇总报告。

### 项目 2：进程池 CPU 计算工具

示例方向：

- 批量计算文件哈希。
- 批量图片处理。
- 大量数值计算。

必须包含：

- 进程池。
- 主入口保护。
- 参数和结果可序列化。
- 耗时对比。
- 异常收集。

### 项目 3：asyncio 并发任务执行器

示例方向：

- 并发请求多个接口。
- 异步处理任务队列。
- 周期拉取并处理任务。

必须包含：

- `asyncio.create_task`。
- `asyncio.gather` 或 `as_completed`。
- 并发上限。
- 超时。
- 取消。
- 日志。

### 项目 4：定时任务脚本

示例方向：

- 每 10 分钟扫描目录。
- 每天生成报表。
- 每小时检查 URL 状态。

必须包含：

- 下次运行时间。
- 单次任务超时。
- 防止上一次未结束又启动下一次。
- 退出信号处理。
- 运行日志。

## 难点

### 难点 1：模型选择

很多初学者会把线程、进程、asyncio 混在一起用。正确思路是先判断瓶颈：

- 等待网络、磁盘、数据库：通常考虑线程或 asyncio。
- 大量 Python 计算：通常考虑进程。
- 任务少、耗时短：串行可能更简单。
- 任务需要长期等待大量连接：考虑 asyncio。

### 难点 2：共享状态

并发程序最容易错在共享可变数据：

- 多个线程同时修改列表或字典。
- 多个任务同时写同一个文件。
- 多个进程共享状态但没有同步。
- 异步任务读写同一个对象导致顺序混乱。

优先使用队列传递数据，少共享状态。

### 难点 3：异常不会自动浮上来

线程、进程池、异步任务里的异常可能被保存在 `Future` 或 `Task` 中。如果不取结果，你可能以为任务成功了。

必须显式收集：

- 每个任务是否完成。
- 每个任务的返回值。
- 每个任务的异常。
- 每个任务耗时。

### 难点 4：取消和超时

超时不是“让程序快一点”，而是控制失败边界。取消也不是立刻杀死所有代码，它需要任务配合。

必须理解：

- 哪些等待可以被取消。
- 取消时如何清理资源。
- 超时后是否重试。
- 重试是否有限制。

## 阶段验收口径

通过本阶段需要满足：

- 能独立解释线程、进程、asyncio 的差异。

- 能写进程池处理 CPU 任务。
- 能写 asyncio 并发任务。
- 能限制并发数量。
- 能处理超时、取消、异常。
- 能写一个简单周期调度任务。
- 能用日志说明任务成功率、失败原因和耗时。
