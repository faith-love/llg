# 限流重试和退避

并发程序必须控制速度。没有限流会压垮外部系统或自己；没有重试会让临时错误直接失败；没有退避会在故障时制造更大的压力。

## 限流

限流是限制单位时间或同一时刻的任务数量。

常见限制：

- 同时最多 10 个请求。
- 每秒最多 5 次请求。
- 每分钟最多 100 个任务。
- 同时最多 3 个数据库写入。

## 并发上限

线程池：

```python
ThreadPoolExecutor(max_workers=10)
```

asyncio：

```python
semaphore = asyncio.Semaphore(10)


async with semaphore:
    await work()
```

## 速率限制

简单方式：

```python
import asyncio


async def worker(items):
    for item in items:
        await work(item)
        await asyncio.sleep(0.2)
```

这表示每个 worker 每 0.2 秒执行一次。真实项目可使用更严格的令牌桶算法。

## 重试

只重试可能恢复的错误：

- 网络超时。
- 连接重置。
- 临时 5xx。
- 临时限流。

不要重试：

- 参数错误。
- 权限错误。
- 认证失败。
- 数据格式错误。
- 404 这类明确不存在。

## 指数退避

```python
delay = min(base * (2 ** attempt), max_delay)
```

示例：

```text
1s -> 2s -> 4s -> 8s
```

目的：

- 给外部系统恢复时间。
- 避免所有任务同时重试。
- 降低故障放大。

## 抖动

抖动是在退避时间上增加随机值，避免大量任务同时重试。

```python
import random


delay = base * (2 ** attempt) + random.uniform(0, 0.5)
```

## 重试模板

```python
import asyncio
import random


async def retry_async(func, attempts=3, base_delay=1, max_delay=10):
    last_error = None
    for attempt in range(attempts):
        try:
            return await func()
        except Exception as exc:
            last_error = exc
            if attempt == attempts - 1:
                break
            delay = min(base_delay * (2 ** attempt), max_delay)
            delay += random.uniform(0, 0.5)
            await asyncio.sleep(delay)
    raise last_error
```

工程中还要加：

- 错误分类。
- 日志。
- 任务 ID。
- 最大总耗时。

## 熔断概念

如果失败率极高，继续重试可能没有意义。熔断是暂时停止请求，等一段时间后再尝试。

学习阶段了解即可，重点先掌握限流、有限重试和退避。

## 常见错误

### 无限重试

会让任务永不结束。

### 所有任务同时重试

可能造成流量尖峰。使用抖动。

### 对不可重试错误重试

浪费资源，还可能触发封禁。

### 只限制任务数量，不限制外部资源

例如线程数 20，但数据库连接池只有 5，会导致大量等待和超时。

4. 写一个异步重试函数。
5. 增加指数退避。
6. 增加随机抖动。
7. 区分可重试和不可重试错误。
8. 统计每个任务重试次数。

## 验收标准

- 能限制并发数量。
- 能写有限重试。
- 能实现指数退避和抖动。
- 能说明哪些错误不应该重试。
