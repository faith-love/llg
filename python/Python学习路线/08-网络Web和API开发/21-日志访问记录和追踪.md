# 日志访问记录和追踪

Web API 必须能回答：谁在什么时候请求了哪个接口，耗时多久，返回了什么状态，失败原因是什么。没有日志和追踪，线上问题很难定位。

## 访问日志

访问日志通常包含：

- 请求方法。
- 路径。
- 状态码。
- 耗时。
- 客户端 IP。
- User-Agent。
- Request ID。

示例：

```text
method=GET path=/books status=200 elapsed=12ms request_id=abc123
```

## Request ID

Request ID 用于串联一次请求的日志。

来源：

- 客户端传入 `X-Request-ID`。
- 服务端生成。

要求：

- 每条相关日志都带 request_id。
- 响应头可返回 request_id。
- 错误报告中包含 request_id。

## 业务日志

业务日志记录关键事件：

- 创建图书。
- 删除资源。
- 登录失败。
- 权限拒绝。
- 外部 API 调用失败。

不要记录敏感信息。

## 错误日志

错误日志应包含：

- request_id。
- 路由。
- 状态码。
- 错误类型。
- 错误摘要。
- 必要输入上下文。

内部堆栈写日志，不直接返回给客户端。

## 耗时统计

至少记录：

- 请求总耗时。
- 外部 API 调用耗时。
- 数据库操作耗时。
- 文件处理耗时。

慢请求要能定位慢在哪里。

## 日志级别

| 级别 | 用途 |
| --- | --- |
| DEBUG | 调试细节 |
| INFO | 正常请求和关键业务事件 |
| WARNING | 可恢复异常 |
| ERROR | 请求失败或任务失败 |
| CRITICAL | 服务不可用级别错误 |

## 日志脱敏

必须脱敏：

- Authorization。
- Cookie。
- password。
- token。
- api_key。
- 身份证、手机号等敏感字段。

## 常见错误

### 只在出错时打印一句 failed

没有 request_id 和输入上下文无法定位。

### 日志包含完整请求体

可能泄露密码、token、个人信息。

### 没有耗时

慢接口无法分析。

### request_id 没有贯穿外部调用

调用链断裂。

## 练习

1. 给每次请求生成 request_id。
2. 在响应头返回 request_id。
3. 记录请求方法、路径、状态码、耗时。
4. 给业务操作增加 INFO 日志。
5. 给异常增加 ERROR 日志。
6. 写 headers 脱敏函数。
7. 记录外部 API 调用耗时。
8. 输出慢请求日志。

## 验收标准

- 能设计访问日志字段。
- 能使用 request_id 追踪请求。
- 能记录耗时和错误上下文。
- 能避免敏感信息进入日志。
