# 常见错误和安全边界

Web API 暴露在网络边界上，错误输入、恶意请求、网络故障和权限问题都是常态。本节集中整理第 08 阶段必须规避的高风险错误。

## 客户端调用错误

### 不设置 timeout

请求可能永久卡住。

必须：

```python
requests.get(url, timeout=5)
```

或在 httpx Client 中统一设置。

### 不区分错误类型

DNS 错误、连接错误、超时、HTTP 4xx/5xx、JSON 解析错误，处理方式不同。

### 对所有错误无限重试

会放大故障。必须有限重试、退避、错误分类。

## 服务端输入错误

### 信任前端校验

后端必须校验所有输入。

### page_size 没有限制

可能导致大查询、大响应、内存上升。

### 任意排序字段

可能导致查询错误或注入风险。

### JSON 字段类型不校验

后续业务逻辑会出现隐蔽错误。

## 认证授权错误

### 只认证不授权

登录用户也只能访问自己有权限的资源。

### 资源归属不检查

例如用户通过改 ID 访问别人订单。

### token 写日志

Authorization 和 Cookie 必须脱敏。

### JWT 不校验签名和过期

JWT 不是可信数据，必须验证。

## CORS 错误

### 生产环境允许任意来源

尤其是带凭证时风险更高。

### 把 CORS 当认证

CORS 不是权限系统，服务端仍要认证授权。

## 文件上传错误

### 原样使用文件名

可能路径穿越或覆盖文件。

### 不限制大小

可能导致磁盘或内存耗尽。

### 下载接口接受任意路径

必须用文件 ID 映射，不允许客户端传磁盘路径。

## 错误响应错误

### 返回内部堆栈

生产环境不要把内部错误细节返回给客户端。

### 所有错误返回 200

调用方无法判断成功失败。

### 错误结构不统一

调用方无法稳定解析错误。

## 日志错误

### 日志包含敏感信息

要脱敏：

- token。
- Cookie。
- password。
- API Key。
- 身份证、手机号。

### 没有 request_id

多条日志无法串联同一次请求。

## 部署错误

### debug 模式上生产

可能泄露调试信息。

### 没有 HTTPS

生产认证信息应通过 HTTPS 传输。

### 没有健康检查

无法判断服务是否可用。

### 没有限流

接口容易被突发流量压垮。

## 安全检查清单

上线前检查：

- 所有外部请求有 timeout。
- 所有输入有校验。
- 分页有最大值。
- 排序和过滤字段有白名单。
- 错误响应统一。
- 认证信息不进 URL。
- token 和 cookie 日志脱敏。
- 受保护接口检查权限。
- CORS 来源明确。
- 上传文件限制大小和类型。
- 下载接口没有路径穿越。
- 生产关闭 debug。
- 有健康检查。
- 有 API 测试。

## 练习

1. 找出一个无 timeout 的 API 调用并修复。
2. 给分页增加最大 page_size。
3. 给排序字段增加白名单。
4. 写 token 脱敏函数。
5. 写资源归属检查伪代码。
6. 修复一个路径穿越下载接口。
7. 把错误响应统一成 error 对象。
8. 写一份上线前安全检查清单。

## 验收标准

- 能识别 Web/API 常见安全错误。
- 能为客户端调用设置 timeout、重试和脱敏。
- 能为服务端输入、认证、文件、CORS 设置边界。
- 能写出上线前检查清单。
