# 源码阅读方法

源码阅读不是从第一行读到最后一行，而是带着问题找入口、走调用链、做实验、写笔记。读源码的目标是理解设计和取舍，不是背实现细节。

## 阅读前准备

先明确：

- 想解决什么问题？
- 想理解哪个功能？
- 入口函数是什么？
- 最小复现代码是什么？
- 版本号是多少？

## 阅读流程

推荐：

1. 读官方文档。
2. 写最小示例。
3. 找入口函数。
4. 跟调用链。
5. 画流程图。
6. 打断点或加日志。
7. 写笔记。
8. 总结设计取舍。

## 最小示例

例如读 `json.dumps`：

```python
import json


json.dumps({"name": "Python"})
```

从这个最小调用开始追踪。

## 调用链笔记

记录格式：

```markdown
## 调用链

入口：A
A -> B -> C

## 关键对象

## 关键分支

## 设计取舍

## 未解决问题
```

## 调试技巧

可以使用：

- IDE 跳转。
- 断点。
- print 临时日志。
- `inspect`。
- `help()`。
- `dir()`。

## 阅读层次

先读：

- 公共 API。
- 核心流程。
- 关键对象。
- 错误处理。

后读：

- 兼容分支。
- 性能优化细节。
- 平台差异。
- 历史包袱。

## 常见错误

### 从文件第一行硬读

容易迷失。

### 没有问题意识

不知道读完要回答什么。

### 不写笔记

读过很快忘。

### 过度纠结细节

先理解主线，再看细节。

## 练习

1. 选择一个标准库函数。
2. 写最小示例。
3. 找入口函数。
4. 跟 5 层调用链。
5. 画流程图。
6. 写源码阅读笔记。
7. 总结一个设计取舍。

## 验收标准

- 能带问题读源码。
- 能找到入口和调用链。
- 能用最小示例验证理解。
- 能输出源码阅读笔记。
