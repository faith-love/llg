# 常见错误和长期风险

长期学习最常见的问题不是“不够努力”，而是方向分散、没有作品、没有复盘、只学不用、只追热点。第 12 阶段要主动规避这些风险。

## 半成品堆积

症状：

- 很多项目开头。
- 很少项目完成。
- README 不完整。
- 没有测试。
- 无法演示。

解决：

- 限制同时项目数。
- 先完成 MVP。
- 每周交付小闭环。
- 完成后再开新项目。

## 只学不用

症状：

- 看了很多教程。
- 没有项目。
- 遇到真实问题不会拆解。

解决：

- 每个知识点配练习。
- 每个阶段配项目。
- 每周至少一次输出。

## 追热点

症状：

- 新框架都想学。
- 旧项目没人维护。
- 基础不扎实。

解决：

- 技术雷达。
- 主线优先。
- 新工具先 Trial，不直接 Adopt。

## 无复盘

症状：

- 同类错误重复出现。
- 项目经验无法讲清。
- 面试表达空泛。

解决：

- 每个项目写复盘。
- 每次故障写记录。
- 每月总结重复问题。

## 无质量意识

症状：

- 项目能跑但没测试。
- 没有 CI。
- 没有错误处理。
- 没有安全边界。

解决：

- 固定质量清单。
- 新项目默认加测试。
- README 写检查命令。

## 常见错误清单

- 项目没有验收标准。
- 文档和代码不一致。
- 面试项目无法运行。
- 只会讲技术名词。
- 不维护依赖。
- 不处理安全风险。
- 没有源码阅读记录。
- 没有代码评审记录。

## 练习

1. 清点所有半成品项目。
2. 选择 1 个优先完成。
3. 为它写 MVP 验收。
4. 补 README。
5. 补测试。
6. 写复盘。
7. 关闭或归档不继续的项目。
8. 写长期风险清单。

## 验收标准

- 能识别长期学习风险。
- 能减少半成品。
- 能用复盘修正学习路径。
- 能把质量要求变成习惯。
