# 项目三：数据处理和报表系统

数据处理和报表系统适合展示数据库、pandas、ETL、数据质量、增量同步、报表输出和自动化调度能力。

## 项目目标

实现一个从原始数据到报表输出的处理流程。

示例：

- 订单数据日报。
- 多 CSV 合并清洗。
- 日志统计系统。
- 库存变更报表。
- API 数据拉取和分析。

## 必备流程

```text
extract -> validate -> clean -> transform -> load -> report
```

每一步都要可记录、可测试、可重跑。

## 输入来源

可选：

- CSV。
- JSON。
- SQLite。
- 外部 API。
- 日志文件。

学习阶段建议先用 CSV/SQLite，降低外部依赖。

## 输出形式

至少包含：

- 清洗后数据。
- 汇总 CSV。
- JSON 摘要。
- Markdown 报告。

进阶：

- HTML 报告。
- 图表。
- 数据质量报告。

## 数据质量校验

校验：

- 必填字段。
- 类型转换。
- 枚举值。
- 日期范围。
- 重复记录。
- 主键唯一。
- 金额非负。
- 外键存在。

## 增量处理

进阶要求：

- 记录上次处理位置。
- 只处理新增数据。
- 可重复运行。
- 避免重复写入。

## 测试要求

至少测试：

- 正常输入。
- 缺字段。
- 类型错误。
- 重复记录。
- 空文件。
- 增量重复运行。
- 报告字段。

## 常见错误

### 清洗规则写死且无说明

规则要文档化。

### 坏数据直接丢弃

必须输出坏数据报告。

### 不能重复运行

ETL 必须考虑幂等性。

### 没有数据血缘

不知道报表来自哪些输入。

## 验收标准

- 能从输入生成报表。
- 有数据质量报告。
- 有坏数据输出。
- 支持重复运行。
- 至少有 10 个测试。
- README 能说明数据流。
