# 面试准备和项目表达

面试准备不是背答案，而是把自己的项目、问题、取舍和复盘讲清楚。优秀表达应具体、有证据、有边界、有反思。

## 项目讲解结构

建议：

1. 项目背景。
2. 目标用户。
3. 核心功能。
4. 技术架构。
5. 关键难点。
6. 解决方案。
7. 质量保障。
8. 性能或安全处理。
9. 结果。
10. 复盘和改进。

## STAR

STAR：

- Situation：背景。
- Task：任务。
- Action：行动。
- Result：结果。

示例：

```text
背景：批量文件整理容易误删。
任务：做一个安全整理工具。
行动：设计 dry-run、执行计划和报告。
结果：可以追踪每个文件处理结果。
```

## 项目亮点

不要只说用了什么技术，要说解决了什么问题：

- 用 dry-run 降低批量操作风险。
- 用队列和限流防止任务堆积。
- 用 response_model 保证 API 输出稳定。
- 用 profile 找到真实瓶颈。
- 用 CI 阻止未测试代码合并。

## 常见问题

准备回答：

- 为什么选这个框架？
- 数据库表怎么设计？
- 如何处理错误？
- 如何测试？
- 如何部署？
- 性能瓶颈在哪里？
- 如何做权限？
- 如果数据量扩大 100 倍怎么办？
- 如果外部 API 失败怎么办？

## 代码题准备

Python 方向常见：

- 字符串。
- 列表字典。
- 排序。
- 双指针。
- 哈希表。
- 栈队列。
- 文件处理。
- SQL。
- 并发基础。

重点是写清边界和复杂度。

## 常见错误

### 只背技术名词

面试官更关心你如何解决问题。

### 项目讲不出难点

说明项目太浅或没有复盘。

### 夸大规模

容易被追问细节击穿。

### 不讲失败和改进

复盘能力很重要。

## 练习

1. 为每个项目写 3 分钟讲稿。
2. 为每个项目写 10 个追问。
3. 用 STAR 写一个问题解决案例。
4. 准备性能优化案例。
5. 准备安全修复案例。
6. 准备一次失败复盘。
7. 录音复述项目并修改。

## 验收标准

- 能清晰讲项目背景、架构、难点和结果。
- 能回答技术取舍。
- 能用证据说明质量、性能和安全。
- 能讲出复盘和后续改进。
