# 断点调试和 pdb 入门

断点调试可以让程序暂停在某一行，逐步观察变量和执行流程。它比大量 `print` 更适合复杂问题。

## 断点调试能做什么

可以：

- 暂停程序。
- 查看变量值。
- 单步执行。
- 进入函数。
- 跳出函数。
- 查看调用栈。
- 修改表达式观察结果。

## IDE 断点

在 VS Code 或 PyCharm 中：

1. 点击代码行左侧设置断点。
2. 用 Debug 模式运行。
3. 程序运行到断点处暂停。
4. 查看变量窗口和调用栈。

重点观察：

- 当前行是否符合预期。
- 输入变量是什么。
- 条件判断为什么走了这个分支。
- 循环变量如何变化。

## `breakpoint()`

Python 3 内置：

```python
def calculate_total(price, count):
    breakpoint()
    return price * count
```

程序运行到 `breakpoint()` 会进入调试器。

## pdb 常用命令

进入 pdb 后常用：

| 命令 | 含义 |
| --- | --- |
| `n` | 执行下一行，不进入函数 |
| `s` | 进入函数 |
| `c` | 继续运行到下一个断点 |
| `q` | 退出调试 |
| `p expr` | 打印表达式 |
| `pp expr` | 更友好打印表达式 |
| `l` | 查看附近代码 |
| `where` | 查看调用栈 |

## 调试条件分支

```python
def get_level(score):
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    return "C"
```

断点放在函数第一行，逐步观察 `score` 和分支跳转。

## 调试循环

循环问题常见于：

- 边界少一。
- 条件永远成立。
- 数据被意外修改。

断点可以放在循环内部，观察每次迭代变量。

## 什么时候用断点

适合：

- 分支复杂。
- 循环状态变化。
- 对象属性变化。
- 多函数调用链。
- 测试失败但原因不明显。

不适合：

- 简单一行类型转换错误。
- 生产环境随意暂停程序。

## 常见错误

### 一直用 print 不看调用栈

复杂调用关系下，断点更有效。

### 调试时忘记当前工作目录和输入

调试运行配置可能和终端运行不同。

### 提交代码时留下 breakpoint()

提交前必须清理。

## 练习

1. 在一个函数里添加 `breakpoint()`。
2. 使用 `p` 查看变量。
3. 使用 `n` 单步执行。
4. 使用 `s` 进入函数。
5. 调试一个分支判断错误。
6. 调试一个循环边界错误。
7. 清理所有 `breakpoint()`。

## 验收标准

- 能用 IDE 断点或 `breakpoint()` 暂停程序。
- 能查看变量和调用栈。
- 能用 pdb 基础命令。
- 能用断点定位分支和循环问题。
