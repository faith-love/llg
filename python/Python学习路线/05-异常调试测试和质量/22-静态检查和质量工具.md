# 静态检查和质量工具

静态检查工具可以在运行前发现问题，例如未使用导入、变量未定义、风格问题、潜在 bug 和类型不匹配。它不能替代测试，但能减少低级错误。

## Ruff

Ruff 是速度很快的 Python linter 和格式相关工具。

安装：

```powershell
python -m pip install ruff
```

检查：

```powershell
python -m ruff check .
```

自动修复部分问题：

```powershell
python -m ruff check . --fix
```

格式化：

```powershell
python -m ruff format .
```

如果使用 Ruff format，可以减少 Black/isort 组合工具的数量。学习阶段知道两种路线即可。

## Ruff 能发现什么

常见：

- 未使用导入。
- 未使用变量。
- 未定义变量。
- 重复导入。
- 部分复杂度问题。
- 不推荐写法。

## mypy 入门

mypy 用于静态类型检查。

安装：

```powershell
python -m pip install mypy
```

示例代码：

```python
def add(a: int, b: int) -> int:
    return a + b


add("1", "2")
```

检查：

```powershell
python -m mypy .
```

可能发现类型问题。

## 类型检查的边界

mypy 有价值，但不是越严格越好。基础阶段先从核心函数类型标注开始。

适合标注：

- 公共函数。
- 复杂数据结构。
- 模块边界。
- 返回值不明显的函数。

可以暂缓：

- 小脚本临时代码。
- 很快会重写的实验代码。

## 复杂度

一个函数过长、分支过多、嵌套过深，测试和维护都会变难。

信号：

- 函数超过 50 行。
- 嵌套超过 3 层。
- 参数超过 5 个。
- 同一个函数既读文件、又解析、又写输出。

## pre-commit 入门

pre-commit 可以在提交前自动运行检查。基础阶段了解即可。

常见用途：

- 格式化。
- lint。
- 检查大文件。
- 检查尾随空格。

## 常见错误

### 把工具警告全部无脑忽略

先理解警告含义，再决定是否忽略。

### 为了过检查牺牲可读性

工具服务于代码，不是反过来。

### 类型标注写错还不检查

类型标注不配合工具，价值会降低。

## 练习

1. 安装并运行 Ruff。
2. 修复未使用导入。
3. 修复未定义变量。
4. 给 5 个函数添加类型标注。
5. 安装并运行 mypy。
6. 找一个复杂函数并拆分。
7. 了解 pre-commit 的用途。

## 验收标准

- 能运行 Ruff 检查。
- 能理解常见 lint 问题。
- 能给核心函数写类型标注。
- 能运行 mypy 基础检查。
- 能识别复杂函数需要拆分。
