# 异常模型总览

异常是程序执行过程中出现的非正常情况。Python 使用异常对象表达错误，并通过调用栈向上传播，直到被捕获或导致程序终止。

## 异常是什么

示例：

```python
int("abc")
```

会抛出：

```text
ValueError
```

异常不是字符串，而是对象。异常对象包含错误类型和错误信息。

## 异常传播

```python
def parse_age(text):
    return int(text)


def create_user(age_text):
    age = parse_age(age_text)
    return {"age": age}


create_user("abc")
```

`ValueError` 会从 `parse_age` 传播到 `create_user`，再传播到顶层调用。

## 调用栈

调用栈记录函数调用链。traceback 会显示异常从哪里一路传出来。

读 traceback 时重点看：

- 最后一行异常类型和信息。
- 调用栈中自己写的文件。
- 最接近异常发生的代码行。

## 常见异常类型

| 异常 | 常见原因 |
| --- | --- |
| `SyntaxError` | 语法错误 |
| `IndentationError` | 缩进错误 |
| `NameError` | 名字未定义 |
| `TypeError` | 类型不支持当前操作或参数错误 |
| `ValueError` | 类型对，但值不合法 |
| `IndexError` | 序列索引越界 |
| `KeyError` | 字典键不存在 |
| `AttributeError` | 对象属性不存在 |
| `FileNotFoundError` | 文件不存在 |
| `ZeroDivisionError` | 除数为 0 |
| `ImportError` | 导入失败 |
| `ModuleNotFoundError` | 模块不存在 |

## 异常层级

所有常规异常通常继承自 `Exception`。

不要随便捕获 `BaseException`，因为它还包含 `KeyboardInterrupt`、`SystemExit` 等不应该被普通业务吞掉的异常。

## 错误和异常的区别

日常开发里通常都说“报错”。更精确地说：

- 语法错误：代码无法被解析。
- 异常：代码运行中出现问题。
- 业务错误：违反业务规则，可以用自定义异常表达。

## 异常不是控制正常流程的首选

不建议把高频正常分支全部写成异常。

例如用户是否存在：

```python
user = find_user(user_id)
if user is None:
    print("用户不存在")
```

如果是明确违反调用规则，再抛异常更合理：

```python
if amount <= 0:
    raise ValueError("金额必须大于 0")
```

## 常见错误

### 捕获所有异常

```python
try:
    run()
except Exception:
    pass
```

这会隐藏真实问题。

### 只打印错误，不处理

```python
except ValueError as error:
    print(error)
```

如果调用方需要知道失败，应该重新抛出或返回明确结果。

### 异常类型太模糊

自定义业务错误时，不要都用 `Exception`。
