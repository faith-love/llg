# 文档字符串和注释质量

文档字符串和注释的目标是降低理解成本。好注释解释意图、约束和边界；坏注释重复代码，甚至误导读者。

## 文档字符串是什么

模块、函数、类开头的字符串可以作为文档字符串。

```python
def calculate_total_price(unit_price, quantity):
    """计算商品总价。"""
    return unit_price * quantity
```

查看：

```python
print(calculate_total_price.__doc__)
```

## 函数 docstring 写什么

适合说明：

- 函数做什么。
- 参数含义。
- 返回值含义。
- 抛出什么异常。
- 重要边界。

示例：

```python
def parse_age(text):
    """把文本解析为年龄。

    Raises:
        ValueError: 文本为空、不是整数或年龄超出 0-120。
    """
```

## 类 docstring

```python
class ShoppingCart:
    """购物车，负责维护购物项并计算总价。"""
```

说明类的职责，而不是列出每个属性。

## 模块 docstring

```python
"""文本清洗工具。

提供空白清理、大小写归一化和简单标点处理。
"""
```

## 注释应该解释为什么

不推荐：

```python
count += 1  # count 加 1
```

推荐：

```python
# 空行不计入有效日志行，避免统计结果偏大。
if line.strip():
    count += 1
```

## TODO 注释

TODO 要具体：

```python
# TODO: 支持负数金额的输入校验，目前只处理正整数。
```

不要写：

```python
# TODO: fix
```

## 注释和代码同步

过期注释比没有注释更危险。改代码时要同步更新注释。

## README 和代码注释分工

README 说明：

- 项目目标。
- 安装和运行。
- 示例。
- 目录结构。

代码注释说明：

- 局部复杂逻辑。
- 业务边界。
- 非显而易见的取舍。

## 常见错误

### 注释重复代码

没有增加信息。

### 注释解释错误原因但不修代码

如果可以通过重命名或拆函数让代码清楚，优先改代码。

### 文档字符串过长但没有边界信息

长不等于有用。

## 练习

1. 给 5 个核心函数写 docstring。
2. 给一个类写职责说明。
3. 删除 5 条重复代码的注释。
4. 给复杂业务判断补“为什么”注释。
5. 改写 3 条模糊 TODO。
6. 检查 README 和代码注释是否重复。

## 验收标准

- 能写函数、类、模块 docstring。
- 能写解释意图的注释。
- 能删除无意义注释。
- 能保持注释和代码同步。
