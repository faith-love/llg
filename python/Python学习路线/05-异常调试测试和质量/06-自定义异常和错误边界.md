# 自定义异常和错误边界

自定义异常用于表达业务错误或模块边界错误。它能让调用方区分不同错误类型，而不是只能读字符串。

## 定义自定义异常

```python
class AppError(Exception):
    pass
```

更具体：

```python
class ValidationError(AppError):
    pass


class NotFoundError(AppError):
    pass
```

## 业务异常示例

```python
class InsufficientBalanceError(Exception):
    pass


class Account:
    def __init__(self, balance):
        self.balance = balance

    def withdraw(self, amount):
        if amount > self.balance:
            raise InsufficientBalanceError("余额不足")
        self.balance -= amount
```

## 异常层级

建议为一个模块或领域定义基础异常：

```python
class LibraryError(Exception):
    pass


class BookUnavailableError(LibraryError):
    pass


class MemberBlockedError(LibraryError):
    pass
```

调用方可以选择捕获具体异常或领域总异常。

## 错误边界

错误边界是指异常应该在哪一层被处理。

通常：

- 底层函数发现错误并抛出。
- 中间层补充上下文或转换异常。
- 入口层统一捕获并给用户友好提示。

示例：

```python
def main():
    try:
        run()
    except AppError as error:
        print(f"操作失败：{error}")
```

## 不要在底层直接退出程序

不推荐：

```python
def parse_config(path):
    if not path.exists():
        print("配置不存在")
        exit(1)
```

更推荐：

```python
def parse_config(path):
    if not path.exists():
        raise ConfigError(f"配置不存在：{path}")
```

入口层决定如何退出。

## 自定义异常带字段

```python
class ValidationError(Exception):
    def __init__(self, field, message):
        self.field = field
        self.message = message
        super().__init__(f"{field}: {message}")
```

这样调用方可以读取结构化信息。

## 常见错误

### 所有错误都用 Exception

调用方无法区分错误。

### 自定义异常太多

每个小错误都一个异常类会增加维护成本。

### 在错误边界内吞异常

底层捕获后不抛出，入口层就不知道失败了。
