# 配置和环境分层

工程化项目必须区分开发、测试、预发布和生产环境。配置不清晰会导致本地误连生产、测试污染真实数据、密钥泄露和部署不可复现。

## 环境类型

常见：

- dev：本地开发。
- test：自动化测试。
- staging：预发布。
- prod：生产。

不同环境的数据库、密钥、日志级别、外部 API 地址都应隔离。

## 配置来源优先级

建议：

1. 命令行参数。
2. 环境变量。
3. 配置文件。
4. 默认值。

敏感配置优先环境变量或密钥管理系统。

## settings 对象

```python
from dataclasses import dataclass
import os


@dataclass(frozen=True)
class Settings:
    app_env: str
    log_level: str
    database_url: str


def load_settings() -> Settings:
    database_url = os.environ.get("DATABASE_URL")
    if not database_url:
        raise RuntimeError("缺少 DATABASE_URL")
    return Settings(
        app_env=os.environ.get("APP_ENV", "dev"),
        log_level=os.environ.get("LOG_LEVEL", "INFO"),
        database_url=database_url,
    )
```

## .env.example

提交示例：

```text
APP_ENV=dev
LOG_LEVEL=INFO
DATABASE_URL=sqlite:///local.db
```

不要提交真实 `.env`。

## 测试环境配置

测试应使用：

- 临时数据库。
- 临时目录。
- fake 外部服务。
- 测试密钥。

不能依赖生产配置。

## 配置校验

启动时校验：

- 必填项存在。
- URL 格式合理。
- 数值范围合理。
- 环境名称合法。
- 生产环境不使用 dev key。

## 常见错误

### 配置散落在代码各处

难排查、难修改、难测试。

### 默认连接生产

本地误操作风险极高。

### 打印完整配置

可能泄露密钥。

### 测试读取本地真实配置

导致测试不可复现。

## 练习

1. 定义 Settings dataclass。
2. 从环境变量加载配置。
3. 缺少必填配置时报错。
4. 创建 `.env.example`。
5. 区分 dev/test/prod。
6. 给生产环境增加防误配置检查。
7. 写配置脱敏输出。
8. 写配置加载测试。

## 验收标准

- 能集中管理配置。
- 能区分环境。
- 能校验必填配置。
- 能避免密钥泄露和误连生产。
