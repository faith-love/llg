# 阶段目标

第 10 阶段要建立 Python 工程化闭环：类型系统帮助你在运行前发现错误，项目结构帮助你控制复杂度，依赖管理保证环境可复现，质量工具保证代码风格和基础质量，CI/CD 和 Docker 保证交付流程稳定。

这一阶段结束后，你应该能把一个脚本项目整理成可维护的 Python 包，并能给它加上类型检查、测试、格式化、lint、打包、CI 和容器化运行能力。

## 本阶段要解决的问题

你需要能回答：

- 为什么 Python 需要类型注解？
- 类型注解和运行时校验有什么区别？
- `Any` 为什么危险？
- 如何逐步引入 mypy 或 pyright？
- 为什么推荐 `src` 布局？
- `pyproject.toml` 负责什么？
- requirements 和 lock 文件解决什么问题？
- black、ruff、isort 分别解决什么问题？
- pre-commit 和 CI 的边界是什么？
- 如何打包一个可安装 Python 包？
- 如何给项目做版本号和变更日志？
- Dockerfile 怎么写才不泄露密钥、不膨胀镜像？
- 部署前要检查哪些配置和运行参数？

## 推荐学习节奏

第 1 周：

- 类型别名、泛型、Protocol、TypedDict、dataclass。
- mypy 或 pyright 渐进式检查。

第 2 周：

- `src` 项目结构。
- `pyproject.toml`。
- 虚拟环境和依赖管理。
- 格式化、lint、测试覆盖率。

第 3 周：

- pre-commit。
- tox/nox。

第 4 周：

- Docker。
- 容器运行参数。

## 必须完成的项目

### 项目 1：类型化工具包

把前面阶段的一个脚本改造成包：

- 使用 `src` 布局。
- 公开 API 有类型注解。
- 内部数据模型使用 dataclass 或 TypedDict。
- 通过静态类型检查。

### 项目 2：质量门禁项目

为项目增加：

- ruff 或 black 格式化。
- ruff lint。
- pytest。
- coverage。
- pre-commit。
- CI。

### 项目 3：打包发布项目

完成：

- `pyproject.toml` 元数据。
- 版本号。
- wheel 构建。
- 本地安装验证。
- CHANGELOG。

### 项目 4：Docker 部署项目

完成：

- Dockerfile。
- `.dockerignore`。
- 环境变量配置。
- 健康检查。
- 日志输出到 stdout。
- 运行说明。

## 难点

### 难点 1：渐进式类型

不要指望一次性 strict。正确方式是：

- 新代码先加类型。
- 公共接口先加类型。
- 关键业务先加类型。
- 对遗留代码逐步收紧。
- 严格控制 `Any` 扩散。

### 难点 2：工具不是越多越好

工具要形成清晰链路：

```text
format -> lint -> type check -> test -> build -> deploy
```

每个工具都要有明确职责，不要重复冲突。

### 难点 3：环境可复现

本地能跑不代表 CI 能跑，CI 能跑不代表容器能跑。必须固定 Python 版本、依赖版本、环境变量和启动命令。

### 难点 4：部署安全

部署产物必须避免：

- 镜像里有密钥。
- CI 日志打印 token。
- Dockerfile 安装无关工具。
- 容器以 root 跑不必要进程。
- 生产环境使用开发配置。

## 阶段验收口径

通过本阶段需要满足：

- 项目有清晰 `src` 布局。
- 公共函数和核心模型有类型注解。
- 静态类型检查可运行。
- 格式化和 lint 可运行。
- pytest 和 coverage 可运行。
- pre-commit 可运行。
- CI 能执行质量检查。
- 项目能构建 wheel。
- 项目能用 Docker 构建和运行。
- 有发布、部署和回滚检查清单。

## 记录要求

每个项目要保留：

- 目录结构。
- 关键配置文件。
- 本地运行命令。
- 检查命令。
- CI 结果。
- 构建产物。
- Docker 构建命令。
- 遇到的问题和修复记录。
