# 测试工程化和覆盖率

测试工程化不是只写几个测试函数，而是建立稳定、可重复、可分层的验证体系。覆盖率不是目标本身，它是发现测试盲区的工具。

## pytest 基本命令

```powershell
pytest
```

指定目录：

```powershell
pytest tests
```

显示详细：

```powershell
pytest -q
```

## 测试分层

常见：

- 单元测试。
- 集成测试。
- API 测试。
- 端到端测试。

单元测试快，定位精确。集成测试覆盖真实协作，但成本更高。

## fixture

```python
import pytest


@pytest.fixture
def sample_items():
    return [1, 2, 3]
```

fixture 用于复用测试准备逻辑。

## 参数化

```python
import pytest


@pytest.mark.parametrize("value,expected", [(1, 2), (2, 4)])
def test_double(value, expected):
    assert value * 2 == expected
```

适合多组输入输出。

## coverage

运行覆盖率：

```powershell
coverage run -m pytest
coverage report
```

或：

```powershell
pytest --cov=src
```

覆盖率关注：

- 哪些文件未测。
- 哪些分支未测。
- 关键错误路径是否覆盖。

## 覆盖率阈值

可以设置最低阈值：

```powershell
pytest --cov=src --cov-fail-under=80
```

阈值要逐步提高，不要一开始设置不现实目标。

## 测试稳定性

稳定测试应：

- 不依赖真实外网。
- 不依赖执行顺序。
- 不依赖本机绝对路径。
- 使用临时目录。
- 固定时间或 mock 时间。
- 清理测试数据。

## 常见错误

### 只追求覆盖率数字

100% 覆盖率也可能没有断言关键行为。

### 测试过慢

开发者不会频繁运行。快慢测试要分层。

### 测试依赖外部服务

会导致不稳定。

### fixture 太复杂

测试准备比被测逻辑还难懂。

## 练习

1. 为一个纯函数写测试。
2. 为错误输入写测试。
3. 使用 fixture。
4. 使用 parametrize。
5. 使用临时目录测试文件输出。
6. 生成覆盖率报告。
7. 设置覆盖率最低阈值。
8. 把慢测试标记出来。

## 验收标准

- 能用 pytest 组织测试。
- 能使用 fixture 和参数化。
- 能生成覆盖率报告。
- 能设计稳定、不依赖外部环境的测试。
