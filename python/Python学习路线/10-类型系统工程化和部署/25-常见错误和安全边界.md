# 常见错误和安全边界

工程化阶段的错误通常不是单行 bug，而是流程、配置、依赖和交付链路的问题。这些问题一旦进入团队项目，会长期制造不稳定。

## 类型系统错误

### Any 扩散

外部数据返回 `Any` 后直接进入业务层，会让类型检查失效。

防护：

- 边界解析。
- TypedDict/dataclass/Pydantic 建模。
- 小范围 Any。

### Optional 漏判

`str | None` 使用前必须判断。

### 类型检查没有进 CI

本地偶尔跑没有意义，必须成为门禁。

## 项目结构错误

### 单文件膨胀

所有逻辑写在一个文件里，难测试、难复用、难维护。

### 循环导入

说明模块职责和依赖方向需要调整。

### `__init__.py` 有副作用

导入包就连数据库或读配置，会导致工具和测试不稳定。

## 依赖错误

### 依赖不锁定

不同时间安装得到不同版本。

### 多个依赖文件不一致

pyproject、requirements、lock、CI 安装命令互相冲突。

### 生产安装 dev 依赖

镜像变大，攻击面增加。

### 不看依赖安全公告

长期不升级会积累风险。

## 质量门禁错误

### pre-commit 太慢

开发者会绕过。

### CI 不跑完整检查

低质量代码仍能进主分支。

### 覆盖率只看数字

没有测试关键路径，数字再高也没用。

### lint 忽略无说明

未来没人知道为什么忽略。

## 打包发布错误

### 没有安装 wheel 验证

源码目录能跑，安装包不一定能跑。

### 包含敏感文件

打包前检查产物内容。

### 版本号不更新

发布不可追踪。

### CHANGELOG 不写破坏性变更

调用方升级风险高。

## Docker 错误

### `.env` 进入镜像

严重密钥泄露。

### 使用 `latest`

构建不可复现。

### COPY 整个工作目录

缓存、测试数据、虚拟环境都可能进去。

### 生产镜像包含构建工具和测试依赖

体积大，攻击面大。

## CI/CD 安全错误

### secrets 写进 workflow

必须使用 CI 平台 secrets。

### 日志打印 token

构建日志可能被多人访问。

### 不限制发布触发条件

任意分支都能发布很危险。

### 部署没有回滚策略

上线失败无法快速恢复。

## 发布前检查清单

- 类型检查通过。
- lint 通过。
- format check 通过。
- 测试通过。
- 覆盖率达到阈值。
- 构建 wheel 成功。
- 新环境安装 wheel 成功。
- Docker 镜像构建成功。
- 镜像不包含 `.env` 和缓存。
- 配置从环境变量读取。
- CHANGELOG 更新。
- 版本号更新。
- 回滚方式明确。

## 练习

1. 找出项目中的 Any 扩散点。
2. 检查依赖文件是否冲突。
3. 检查 `.dockerignore` 是否排除 `.env`。
4. 检查 CI 是否打印 secrets。
5. 安装 wheel 验证命令行入口。
6. 生成发布前检查清单。
7. 写一个回滚方案。
8. 记录一次工程化问题复盘。

## 验收标准

- 能识别类型、依赖、CI、打包、Docker 的常见风险。
- 能写发布前检查清单。
- 能保护密钥和构建产物。
- 能让质量门禁真正生效。
