# 类型别名和新类型

类型别名和新类型用于提高类型表达力。它们能让复杂类型更可读，也能减少把不同业务含义的相同基础类型混用的风险。

## 类型别名

```python
type UserId = int
type UserName = str
```

或使用兼容写法：

```python
from typing import TypeAlias


UserId: TypeAlias = int
```

类型别名只是给类型起名字，不会创建新的运行时类型。

## 复杂结构别名

```python
from typing import TypeAlias


JsonObject: TypeAlias = dict[str, object]
Headers: TypeAlias = dict[str, str]
```

好处：

- 函数签名更短。
- 业务含义更明确。
- 修改结构时影响范围更清晰。

## NewType

`NewType` 用于创建静态检查层面的新类型。

```python
from typing import NewType


UserId = NewType("UserId", int)
OrderId = NewType("OrderId", int)
```

这样类型检查工具可以区分 `UserId` 和 `OrderId`。

```python
def get_user(user_id: UserId) -> str:
    return "user"
```

传入 `OrderId` 会被静态检查工具提示。

## Literal

`Literal` 用于限定固定值：

```python
from typing import Literal


LogLevel = Literal["DEBUG", "INFO", "WARNING", "ERROR"]


def set_level(level: LogLevel) -> None:
    ...
```

适合：

- 状态。
- 模式。
- 排序方向。
- 配置开关。

## Final

`Final` 表示变量不应被重新赋值：

```python
from typing import Final


MAX_PAGE_SIZE: Final = 100
```

这是一种静态检查约束，不是运行时强制常量。

## ClassVar

类变量：

```python
from typing import ClassVar


class User:
    table_name: ClassVar[str] = "users"
```

用于区分类变量和实例变量。

## 何时使用类型别名

适合：

- 类型表达很长。
- 业务含义重要。
- 多处重复使用。
- 想统一修改。

不适合：

- 简单类型只出现一次。
- 别名名字比原类型更难懂。

## 何时使用 NewType

适合：

- 多个业务 ID 都是 int 或 str。
- 容易传错参数。
- 希望静态工具帮你区分。

例如：

- `UserId`。
- `OrderId`。
- `ProductId`。

## 常见错误

### 以为类型别名会运行时校验

不会。类型别名只是静态表达。

### NewType 后到处强转

如果每一行都在强转，说明数据边界设计需要整理。

### Literal 取值太多

值很多时可以考虑 Enum。

### Final 当运行时常量保护

Python 不会自动阻止重新赋值，工具会提示。
