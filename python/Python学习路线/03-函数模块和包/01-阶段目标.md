# 阶段目标

本阶段要解决的问题是：代码变多之后，怎么拆、怎么复用、怎么让别人能读懂、怎么避免导入混乱。

完成前两个阶段后，你已经能写基础脚本和处理数据。但如果所有逻辑都写在一个文件里，脚本很快会出现这些问题：

- 主流程和细节混在一起。
- 重复代码越来越多。
- 改一个地方影响多个功能。
- 很难测试单个逻辑。
- 文件之间互相导入报错。
- 不知道从哪里运行项目。

函数、模块和包就是为了解决这些问题。

## 你要达到的能力

完成本阶段后，应该能做到：

- 能把一段脚本拆成多个职责清晰的函数。
- 能设计函数参数和返回值。
- 能区分返回值和副作用。
- 能解释默认参数、可变默认值、`*args`、`**kwargs`。
- 能读懂作用域、闭包、`global`、`nonlocal` 的基本行为。
- 能使用 `lambda`、`key` 函数和常见高阶函数。
- 能写简单递归、生成器和装饰器。
- 能把多个 `.py` 文件组织成模块。
- 能创建包目录和 `__init__.py`。
- 能处理常见导入错误。
- 能设计一个小型工具包项目结构。

## 学习边界

### 必须掌握

- 函数定义、调用、参数、返回值。
- 位置参数、关键字参数、默认参数。
- 可变参数 `*args` 和 `**kwargs`。
- 函数副作用。
- 作用域和 LEGB。
- 模块导入。
- 包结构。
- 绝对导入。
- `python -m` 运行方式。
- 循环导入原因和常见解决思路。

### 需要理解但不必过度深入

- 闭包。
- 装饰器。
- 迭代器协议。
- 生成器。
- 相对导入。
- `__all__`。

这些后续读框架源码和标准库时会反复出现。

### 暂时不深入

- 面向对象架构。
- 插件系统。
- 发布 Python 包。
- 命令行框架。
- 复杂元编程。

## 本阶段的核心转变

从：

```python
text = input("请输入文本：")
words = text.lower().split()
counts = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1
print(counts)
```

转为：

```python
def normalize_text(text):
    return text.lower().strip()


def count_words(text):
    counts = {}
    for word in normalize_text(text).split():
        counts[word] = counts.get(word, 0) + 1
    return counts


def main():
    text = input("请输入文本：")
    print(count_words(text))


if __name__ == "__main__":
    main()
```

进一步转为：

```text
text_tools/
  __init__.py
  cleaner.py
  counter.py
main.py
```

这就是从脚本思维到模块化思维。

## 阶段通过标准

满足以下条件，可以进入下一阶段：

- 能把一个 150 行脚本拆成 5-10 个清晰函数。
- 每个函数都有明确输入和输出。
- 能避免可变默认参数问题。
- 能解释函数是否修改原数据。
- 能把函数拆到不同模块并正确导入。
- 能用包结构组织一个小工具。
- 能修复 `ModuleNotFoundError`、`ImportError`、参数数量错误、作用域错误。
