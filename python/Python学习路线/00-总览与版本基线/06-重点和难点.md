# 重点和难点

Python 入门看起来容易，真正难的是从“脚本能跑”走到“项目可靠”。这一阶段先把后续学习的重点和难点列出来，学习时就不会只盯着语法表面。

## 重点一：变量不是盒子，是名字绑定对象

很多初学问题都来自对变量的误解。

需要掌握：

- 变量名绑定到对象。
- 多个变量可以指向同一个对象。
- 可变对象修改会影响所有引用。
- 不可变对象的“修改”通常是创建新对象。

典型坑：

```python
a = []
b = a
b.append(1)
print(a)
```

如果不能解释为什么 `a` 也变了，后面学习列表、字典、函数参数、类属性都会反复踩坑。

## 重点二：可变对象和不可变对象

必须重点掌握：

- 可变：`list`、`dict`、`set`。
- 不可变：`int`、`float`、`bool`、`str`、`tuple`。
- 元组不可变指的是元组本身不能替换元素，不代表里面引用的可变对象不能变。

典型难点：

- 函数默认参数不能随便用空列表。
- 浅拷贝和深拷贝区别。
- 嵌套数据结构修改会影响原对象。

验收方式：

- 能画出变量和对象引用关系。
- 能解释浅拷贝为什么只复制第一层。
- 能修复默认可变参数问题。

## 重点三：缩进和代码块是语义，不是格式

Python 用缩进表示代码块。缩进错误不是“排版问题”，而是程序结构错误。

需要掌握：

- `if`、`for`、`while`、`def`、`class` 后面的代码块。
- 同一代码块缩进必须一致。
- 空格和 Tab 不要混用。
- 缩进会影响变量是否在循环或条件内部执行。

典型坑：

- 循环里本该执行多次的代码写到了循环外。
- 条件判断只包住了一行，后续行无条件执行。

## 重点四：函数是控制复杂度的第一工具

函数不是为了少写几行代码，而是为了让逻辑有边界。

需要掌握：

- 一个函数只做一件明确的事。
- 参数是输入，返回值是输出。
- 函数内部尽量少依赖全局变量。
- 可测试的函数通常比巨大的 `main.py` 更可靠。

难点：

- 什么时候拆函数。
- 函数参数怎么设计。
- 返回值和异常怎么选择。
- 副作用如何控制。

验收方式：

- 能把 100 行脚本拆成 5-8 个有名字的函数。
- 每个函数能单独写测试。
- 函数名能表达业务意图，而不是 `handle`、`process`、`do_it`。

## 重点五：导入、模块和包决定项目能否变大

很多人写小脚本没问题，项目一变大就卡在导入错误。

需要掌握：

- `import module` 和 `from module import name`。
- Python 如何查找模块。
- 脚本运行和包运行的区别。
- `__init__.py` 的作用。
- 相对导入和绝对导入。
- 循环导入为什么发生。

难点：

- 同一个文件从不同工作目录运行，导入结果不同。
- 文件名和标准库重名，例如 `json.py`、`typing.py`。
- 两个模块互相导入导致初始化不完整。

验收方式：

- 能解释 `ModuleNotFoundError` 的常见原因。
- 能设计一个两层以上的包结构。
- 能避免循环导入。

## 重点六：异常处理不是把错误藏起来

异常处理的目标是让错误可理解、可恢复、可定位。

需要掌握：

- 只捕获自己能处理的异常。
- 不要裸 `except`。
- 保留原始错误信息。
- 关键边界要有清晰错误提示。
- 资源释放用 `finally` 或上下文管理器。

典型错误：

```python
try:
    run()
except Exception:
    pass
```

这类写法会让程序“看起来没报错”，但实际结果可能已经错了。

## 重点七：测试和调试要尽早引入

不要等项目变大才学测试。越早写测试，越容易形成正确习惯。

需要掌握：

- `assert` 的基本使用。
- pytest 的测试发现规则。
- 正常输入、边界输入、异常输入。
- 断点调试和调用栈。
- 日志与 print 的区别。

难点：

- 测试不是重复手工验证，而是固定行为。
- Mock 不是万能替代真实依赖。
- 测试要覆盖核心规则，不是追求无意义行覆盖率。

## 重点八：依赖和环境是工程能力的一部分

Python 很多问题不是代码问题，而是环境问题。

需要掌握：

- 虚拟环境。
- 依赖安装。
- 依赖版本记录。
- Python 解释器路径。
- 系统环境变量。

典型坑：

- 在 A 环境安装依赖，在 B 环境运行代码。
- 电脑上有多个 Python，命令指向不一致。
- 只提交代码，不提交依赖说明。
- 教程依赖版本和本地版本不一致。

验收方式：

- 能在新目录重新创建虚拟环境并跑通项目。
- 能解释 `pip` 安装到了哪个环境。
- 能写清楚项目运行步骤。

## 重点九：标准库比第三方库更基础

入门阶段不要见问题就装库。很多高频任务标准库已经能解决。

必须熟悉：

- `pathlib`
- `json`
- `csv`
- `datetime`
- `collections`
- `itertools`
- `functools`
- `argparse`
- `logging`
- `subprocess`
- `re`

难点：

- 标准库 API 多，不需要一次背完。
- 先掌握高频组合，再查文档补细节。
- 知道什么时候标准库够用，什么时候引入第三方库。

## 重点十：从脚本思维转到项目思维

脚本思维关注“这一次能跑”。项目思维关注“以后还能跑、别人也能跑、出错能定位”。

项目思维包括：

- 目录清晰。
- 输入输出明确。
- 配置不写死。
- 错误可定位。
- 依赖可复现。
- 测试可执行。
- README 可操作。
- 复盘可追溯。

真正从入门走向精通，核心就是不断把临时经验沉淀成稳定结构。
