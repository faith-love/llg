# 每周节奏

学习节奏要能长期坚持，也要保证每周都有可验证产出。建议按“输入、练习、项目、复盘”四件事组织每周安排。

## 标准周节奏

适合每周能投入 8-12 小时的人。

| 时间 | 内容 | 产出 |
| --- | --- | --- |
| 周一 | 阅读本周主题文档，跑通最小示例 | 知识点笔记 |
| 周二 | 手写 3-5 个小练习 | 练习代码 |
| 周三 | 改造练习，增加边界条件 | 错误记录 |
| 周四 | 做一个小功能或小脚本 | 可运行程序 |
| 周五 | 补测试、日志、README | 可复用版本 |
| 周六 | 做阶段项目或综合练习 | 项目提交 |
| 周日 | 复盘、整理问题、规划下周 | 周复盘 |

## 每天学习块

单次学习建议控制在 60-120 分钟。

推荐比例：

- 20%：读概念。
- 50%：写代码。
- 20%：调试和改错。
- 10%：记录和复盘。

如果只有 30 分钟，优先写一个小练习，不要只刷视频。

## 每周必须完成的 5 件事

1. 至少读完 3 个知识点文档。
2. 至少写 10 个小练习。
3. 至少完成 1 个可运行小脚本。
4. 至少记录 5 个错误或疑问。
5. 至少做 1 次周复盘。

## 复盘模板

每周复盘可以固定成下面格式：

```markdown
# Python 第 N 周复盘

## 本周主题

## 完成内容

## 可运行产出

## 遇到的问题

## 已解决的问题

## 仍然不清楚的问题

## 下周计划
```

## 阶段节奏

不同阶段投入重点不同。

| 阶段 | 主要投入 | 不该做的事 |
| --- | --- | --- |
| 基础语法 | 多写小程序 | 不急着装复杂库 |
| 数据结构 | 多做文本和集合处理 | 不只背方法名 |
| 函数模块 | 拆分代码、复用代码 | 不把所有逻辑写进 main |
| 面向对象 | 建模、封装、协议 | 不过早设计复杂继承 |
| 测试质量 | pytest、日志、调试 | 不只靠 print 排查 |
| 自动化 | 文件、表格、命令行 | 不忽略异常和输入校验 |
| Web API | 请求响应、数据库、错误处理 | 不直接堆路由代码 |
| 工程化 | 结构、依赖、部署 | 不依赖本机隐式环境 |

## 学习强度分级

### 轻量模式

每周 4-6 小时。

- 每周 2 个知识点。
- 每周 5 个练习。
- 每两周一个小脚本。

适合工作忙时保持连续性。

### 标准模式

每周 8-12 小时。

- 每周 3-5 个知识点。
- 每周 10-15 个练习。
- 每周一个小脚本。

适合主线学习。

### 强化模式

每周 15-20 小时。

- 每周 5-8 个知识点。
- 每周 20 个以上练习。
- 每周一个小项目。

适合短期集中突破，但必须保留复盘，否则很容易学得快忘得也快。

## 卡住时的处理顺序

遇到问题不要立刻跳过，按这个顺序处理：

1. 复制最小代码，确认错误能稳定复现。
2. 读报错最后一行，找异常类型。
3. 读报错调用栈，找自己写的文件和行号。
4. 打印或断点检查关键变量。
5. 查官方文档或库文档。
6. 记录问题、原因、修复方式。

超过 40 分钟仍解决不了，可以先写下最小复现和疑问，继续下一个小任务，周复盘时集中处理。
