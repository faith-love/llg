# 事务隔离和并发控制

事务用于保证一组数据库操作要么全部成功，要么全部失败。没有事务，数据很容易出现只写了一半的中间状态。

## 事务的基本操作

```text
BEGIN -> SQL 1 -> SQL 2 -> COMMIT
```

失败时：

```text
BEGIN -> SQL 1 -> SQL 2 失败 -> ROLLBACK
```

Python 示例：

```python
try:
    conn.execute("BEGIN")
    conn.execute(...)
    conn.execute(...)
    conn.commit()
except Exception:
    conn.rollback()
    raise
```

## ACID

| 特性 | 含义 |
| --- | --- |
| Atomicity | 原子性，要么全成，要么全失败 |
| Consistency | 一致性，约束不被破坏 |
| Isolation | 隔离性，并发事务互不干扰到一定程度 |
| Durability | 持久性，提交后数据持久保存 |

## 事务边界

一个事务应该覆盖一个业务原子操作。

例如创建订单：

- 插入订单。
- 插入订单明细。
- 扣库存。
- 写订单日志。

这些要么一起成功，要么一起失败。

## 隔离级别

常见隔离级别：

- Read Uncommitted。
- Read Committed。
- Repeatable Read。
- Serializable。

学习阶段先理解：隔离越强，并发能力可能越低；隔离越弱，可能看到更多并发异常。

## 并发问题

常见问题：

| 问题 | 含义 |
| --- | --- |
| 脏读 | 读到未提交数据 |
| 不可重复读 | 同一事务内两次读结果不同 |
| 幻读 | 同一范围查询出现新行 |
| 丢失更新 | 两个事务覆盖彼此更新 |

## 锁

数据库会通过锁保护数据一致性。

锁可能导致：

- 等待。
- 超时。
- 死锁。

长事务会扩大锁影响范围。

## 死锁

死锁示例：

```text
事务 A 锁住订单 1，等待订单 2
事务 B 锁住订单 2，等待订单 1
```

预防：

- 固定访问顺序。
- 缩短事务时间。
- 不在事务里做慢 IO。
- 捕获死锁错误并有限重试。

## 常见错误

### 忘记 commit

写操作没有真正保存。

### 异常后不 rollback

连接可能处于异常事务状态。

### 事务里做网络请求

会长时间持有锁。

### 一个事务处理太多数据

会造成锁范围大、回滚成本高。
