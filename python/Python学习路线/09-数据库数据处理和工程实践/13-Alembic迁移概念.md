# Alembic迁移概念

数据库结构会随着业务变化。手动在不同环境执行 SQL 很容易遗漏或顺序错误。迁移工具用于记录和执行 schema 变更。Python 生态中 SQLAlchemy 常配合 Alembic。

## 什么是迁移

迁移是数据库结构变化的版本记录。

例如：

- 创建表。
- 增加字段。
- 删除字段。
- 修改字段类型。
- 创建索引。
- 增加约束。

每次变化都应该有迁移脚本。

## 为什么需要迁移

迁移解决：

- 本地、测试、生产结构一致。
- 变更可追踪。
- 可以按顺序升级。
- 必要时可以回滚。
- 团队协作不靠口头通知。

## upgrade 和 downgrade

迁移脚本通常包含：

```python
def upgrade():
    ...


def downgrade():
    ...
```

`upgrade` 应用变更，`downgrade` 回滚变更。

有些变更不可安全回滚，例如删除字段导致数据丢失，要在迁移说明中明确。

## 自动生成和人工检查

Alembic 可以根据模型和数据库差异自动生成迁移，但不能完全信任。

必须人工检查：

- 字段类型是否正确。
- 默认值是否正确。
- 是否会丢数据。
- 索引和约束是否符合预期。
- 大表变更是否会锁表。

## 数据迁移和结构迁移

结构迁移：

- 增加列。
- 建表。
- 建索引。

数据迁移：

- 把旧字段拆成新字段。
- 回填历史数据。
- 清洗脏数据。

数据迁移风险更高，需要备份、分批和验证。

## 常见错误

### 直接改生产数据库

没有迁移记录，后续环境不一致。

### 自动生成后不检查

可能生成危险操作。

### 删除字段没有备份

数据丢失后难恢复。

### 迁移里做大量慢数据处理

可能锁表或超时。大数据回填应分批。

## 练习

1. 了解 Alembic 的 revision 概念。
2. 写一个创建 users 表的迁移说明。
3. 写一个给 users 增加 phone 字段的迁移说明。
4. 写一个创建索引的迁移说明。
5. 说明一个不可安全 downgrade 的例子。
6. 设计大表加字段的执行步骤。
7. 写迁移前检查清单。

## 验收标准

- 能解释数据库迁移的价值。
- 能区分结构迁移和数据迁移。
- 能说明 upgrade 和 downgrade。
- 能识别危险 schema 变更。
