# 数据库基础和关系模型

关系型数据库把数据组织为表。表由行和列组成，行代表一条记录，列代表字段。学习数据库不是只会写 SQL，还要理解数据之间的关系、约束和一致性。

## 表、行、列

示例订单表：

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,
    amount NUMERIC NOT NULL,
    status TEXT NOT NULL,
    created_at TEXT NOT NULL
);
```

含义：

- `orders` 是表。
- 每一行是一笔订单。
- `id`、`user_id`、`amount` 是列。
- 每一列应该有明确类型和含义。

## 主键

主键用于唯一标识一行记录。

主键要求：

- 唯一。
- 稳定。
- 不为空。
- 不承载容易变化的业务含义。

常见选择：

- 自增整数。
- UUID。
- 业务唯一编号。

学习阶段优先使用自增整数或明确业务编号。

## 外键

外键表示表之间的关系。

```sql
CREATE TABLE order_items (
    id INTEGER PRIMARY KEY,
    order_id INTEGER NOT NULL,
    product_name TEXT NOT NULL,
    quantity INTEGER NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(id)
);
```

`order_items.order_id` 指向 `orders.id`。

外键解决：

- 防止明细记录指向不存在的订单。
- 让关系更明确。
- 帮助维护数据一致性。

## 关系类型

常见关系：

| 类型 | 示例 |
| --- | --- |
| 一对一 | 用户和用户资料 |
| 一对多 | 用户和订单 |
| 多对多 | 学生和课程 |

多对多通常需要中间表：

```text
students
courses
student_courses
```

## 约束

约束用于让数据库帮你守住数据底线。

常见约束：

| 约束 | 作用 |
| --- | --- |
| PRIMARY KEY | 唯一标识 |
| NOT NULL | 不允许为空 |
| UNIQUE | 不允许重复 |
| FOREIGN KEY | 保持引用关系 |
| CHECK | 限制取值范围 |
| DEFAULT | 默认值 |

不要把所有校验都放在 Python 代码里。数据库约束是最后防线。

## NULL

`NULL` 表示未知、缺失或不适用。

注意：

- `NULL` 不等于空字符串。
- `NULL` 不等于 0。
- `NULL` 和任何值比较都需要特殊处理。

查询：

```sql
WHERE deleted_at IS NULL
```

不要写：

```sql
WHERE deleted_at = NULL
```

## 数据类型

常见类型：

- 整数。
- 小数。
- 字符串。
- 日期时间。
- 布尔值。
- JSON。

设计字段时要明确：

- 是否允许为空。
- 是否有默认值。
- 长度范围。
- 枚举范围。
- 是否需要索引。

## 规范化

规范化是减少重复和异常的设计思想。

例如不要在订单表里重复存很多商品明细列：

```text
product1_name, product2_name, product3_name
```

更合理的是订单表加订单明细表。

## 反规范化

反规范化是为了查询性能或报表方便，适当冗余字段。

例如订单表保存：

- `user_name_snapshot`
- `total_amount`

但冗余字段要有同步规则，否则会产生不一致。

## 常见错误

### 没有主键

没有主键会导致更新、删除、去重和同步都困难。

### 所有字段都允许 NULL

数据质量会变差，业务逻辑要到处处理缺失。

### 把列表塞进一个字符串字段

例如 `"1,2,3"`。后续查询、统计和约束都会变困难。

### 外键关系只靠记忆

表多以后很难维护。至少要在文档中明确关系。

## 练习

1. 设计用户表。
2. 设计订单表。
3. 设计订单明细表。
4. 给订单状态增加 CHECK 约束。
5. 给用户邮箱增加 UNIQUE 约束。
6. 画出用户、订单、订单明细关系。
7. 找出一个字段是否应该允许 NULL。
8. 写一份数据字典。

## 验收标准

- 能解释表、行、列、主键、外键。
- 能设计一对多和多对多关系。
- 能使用常见约束。
- 能区分规范化和反规范化。
