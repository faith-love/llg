# 连接配置和连接池

数据库连接不是普通变量。它涉及网络、认证、事务、超时和资源上限。工程代码里要把连接配置、连接生命周期和连接池边界设计清楚。

## 连接配置

常见配置：

- host。
- port。
- database。
- username。
- password。
- connect timeout。
- read timeout。
- SSL。
- charset。

不要把密码硬编码在代码里。

推荐来源：

1. 命令行参数。
2. 环境变量。
3. 本地配置文件。
4. 密钥管理工具。

## 环境变量示例

```python
import os


database_url = os.environ.get("DATABASE_URL")
if not database_url:
    raise RuntimeError("缺少环境变量 DATABASE_URL")
```

## 连接生命周期

短脚本：

```text
打开连接 -> 执行任务 -> 提交/回滚 -> 关闭连接
```

Web 服务：

```text
应用启动 -> 创建连接池 -> 每次请求借连接 -> 归还连接 -> 应用关闭释放连接池
```

后台任务：

```text
任务开始前获取连接 -> 执行一批数据 -> 提交 -> 关闭或归还
```

## 连接池概念

连接池维护一组可复用连接，避免每次请求都重新建立连接。

好处：

- 降低连接创建成本。
- 控制最大连接数。
- 提高稳定性。

风险：

- 池太小会排队。
- 池太大会压垮数据库。
- 连接泄漏会耗尽池。
- 长事务会占用连接。

## 连接池大小

不要盲目设置很大。需要考虑：

- 数据库最大连接数。
- 应用实例数量。
- 并发请求数。
- 每个请求持有连接时间。
- 后台任务连接数。

示例判断：

```text
数据库最大连接数 100
应用实例 4 个
每个实例连接池最大值不能随便设到 50
```

## 超时

必须关注：

- 连接超时。
- 查询超时。
- 事务超时。
- 空闲连接超时。

没有超时，连接可能长期卡住。

## 常见错误

### 每条 SQL 新建一个连接

成本高，也容易超过数据库连接上限。

### 全局共享一个连接处理所有并发任务

线程安全和事务边界都可能出问题。

### 连接拿了不还

连接池耗尽后请求会排队或失败。

### 日志打印数据库密码

连接字符串要脱敏。
