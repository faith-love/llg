# 多态和鸭子类型

多态表示不同对象可以用同一种方式调用。Python 更强调鸭子类型：如果一个对象表现得像某种东西，就可以按这种方式使用它，不一定需要继承同一个父类。

## 多态基础

```python
class Dog:
    def speak(self):
        return "woof"


class Cat:
    def speak(self):
        return "meow"


def make_sound(animal):
    print(animal.speak())
```

调用：

```python
make_sound(Dog())
make_sound(Cat())
```

`make_sound` 不关心具体类型，只关心对象是否有 `speak` 方法。

## 鸭子类型

“如果它走起来像鸭子，叫起来像鸭子，那它就可以当鸭子用。”

Python 里通常写：

```python
def export(data, writer):
    writer.write(data)
```

只要 `writer` 有 `write` 方法，就可以使用。

## 不必强制继承

Java 等语言常要求实现接口。Python 中很多时候不需要强制继承：

```python
class FileWriter:
    def write(self, data):
        print(f"写文件：{data}")


class ConsoleWriter:
    def write(self, data):
        print(f"控制台：{data}")
```

两者没有共同父类，也可以被同一个函数使用。

## 多态的价值

- 调用方依赖行为，不依赖具体类。
- 新增实现时少改调用方代码。
- 更适合插件、策略、输出格式等场景。

## 示例：不同折扣策略

```python
class NoDiscount:
    def apply(self, amount):
        return amount


class PercentDiscount:
    def __init__(self, percent):
        self.percent = percent

    def apply(self, amount):
        return amount * (1 - self.percent)


def calculate_payable(amount, discount):
    return discount.apply(amount)
```

## 运行时检查

可以使用 `hasattr` 做简单检查：

```python
if hasattr(writer, "write"):
    writer.write("hello")
```

但过度检查会让代码啰嗦。更常见的是直接调用，出错时暴露清楚错误。

## 常见错误

### 过度依赖具体类型

不推荐：

```python
if isinstance(writer, FileWriter):
    writer.write(data)
```

如果只需要 `write` 行为，不必限定具体类型。

### 同名方法语义不一致

多态要求同名方法有兼容语义，否则调用方会困惑。

### 错误吞掉 AttributeError

如果对象缺少方法，应该暴露明确错误，不要静默忽略。

4. 写两个折扣策略，都实现 `apply`。
5. 把一个 `if type(...)` 分支改成多态。
6. 判断 5 个场景是否适合鸭子类型。
