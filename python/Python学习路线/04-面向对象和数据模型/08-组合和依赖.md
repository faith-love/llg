# 组合和依赖

组合表示“一个对象包含另一个对象”。在实际项目里，组合通常比继承更常用、更安全。很多关系不是“谁是谁的一种”，而是“谁拥有谁、谁使用谁”。

## 什么是组合

```python
class Address:
    def __init__(self, city, street):
        self.city = city
        self.street = street


class User:
    def __init__(self, name, address):
        self.name = name
        self.address = address
```

`User` 拥有一个 `Address`，这是组合。

## 组合适合什么关系

适合表达：

- 用户有地址。
- 订单有订单项。
- 购物车有商品项。
- 图书馆有图书。
- 报告生成器使用格式化器。

关键词通常是：

- has-a。
- contains。
- uses。

## 示例：订单和订单项

```python
class OrderItem:
    def __init__(self, name, price, quantity):
        self.name = name
        self.price = price
        self.quantity = quantity

    def subtotal(self):
        return self.price * self.quantity


class Order:
    def __init__(self):
        self.items = []

    def add_item(self, item):
        self.items.append(item)

    def total_price(self):
        return sum(item.subtotal() for item in self.items)
```

`Order` 通过组合管理多个 `OrderItem`。

## 依赖是什么

依赖表示一个对象使用另一个对象完成工作，但不一定拥有它。

```python
class ReportService:
    def __init__(self, formatter):
        self.formatter = formatter

    def generate(self, data):
        return self.formatter.format(data)
```

`ReportService` 依赖 `formatter`。

## 依赖注入入门

把依赖从外部传入，而不是在类内部写死。

不推荐：

```python
class ReportService:
    def __init__(self):
        self.formatter = JsonFormatter()
```

更灵活：

```python
class ReportService:
    def __init__(self, formatter):
        self.formatter = formatter
```

这样测试和替换实现更容易。

## 组合优先于继承

如果只是想复用功能，先考虑组合，而不是继承。

例如“报告服务使用格式化器”，不是“报告服务是格式化器的一种”。

## 什么时候不用类

如果只是简单转换函数，不需要维护状态，也不需要多个对象协作，函数就足够：

```python
def clean_text(text):
    return text.lower().strip()
```

不要为了面向对象而强行建类。

## 常见错误

### 用继承表达拥有关系

用户不是地址的一种，订单不是商品项的一种。

### 在类内部写死依赖

写死依赖会让替换和测试变难。

### 组合层级太深

对象套对象过多时，要检查模型是否过度设计。

- 能解释组合和依赖。

- 能用组合表达对象协作。
- 能避免用继承表达拥有关系。
