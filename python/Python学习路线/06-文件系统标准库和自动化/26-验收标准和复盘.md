# 验收标准和复盘

完成第 06 阶段后，你应该具备独立写 Python 自动化脚本的能力：能读写真实文件，能处理常见数据格式，能使用标准库完成批量任务，能用日志和报告说明执行结果，也能主动规避高风险文件操作。

这一阶段的验收重点不是“记住多少标准库函数”，而是“能否把标准库组合成可靠工具”。

## 阶段能力目标

完成本阶段后应达到：

- 能使用 `pathlib` 处理路径。
- 能安全读写文本和二进制文件。
- 能处理 UTF-8、BOM、换行和文件模式问题。
- 能遍历目录并筛选文件。
- 能用 `csv` 和 `json` 处理结构化数据。
- 能用 `os`、`shutil`、`tempfile` 处理系统和文件任务。
- 能用 `subprocess` 调用外部命令并检查返回码。
- 能用 `datetime` 处理日期和文件名时间戳。
- 能用 `re` 处理明确的文本匹配和替换。
- 能用 `argparse` 写命令行脚本。
- 能用 `collections`、`itertools`、`functools` 提升数据处理质量。
- 能写带 dry-run、日志、错误报告的批量脚本。

## 阶段项目验收

### 项目 1：文件整理工具

必须具备：

- 接收输入目录和输出目录。
- 支持递归扫描。
- 按后缀分类文件。
- 支持 dry-run。
- 支持移动或复制。
- 默认不覆盖。
- 目标冲突有处理策略。
- 能识别重复文件。
- 输出 CSV 或 JSON 报告。
- 有日志。

通过标准：

- dry-run 不修改任何文件。
- 真实执行后文件进入正确分类目录。
- 目标冲突不会覆盖原文件。
- 重复文件会出现在报告中。
- 输入目录不存在时给出明确错误。
- 输出报告能追踪每个文件的结果。

### 项目 2：报表生成工具

必须具备：

- 支持 CSV 输入。
- 支持 JSON 输入。
- 校验必要字段。
- 清洗金额、日期、状态。
- 记录坏数据。
- 按分类、日期、状态汇总。
- 输出 Markdown 报表。
- 输出 CSV 汇总。
- 输出 JSON 摘要。
- 支持命令行参数。

通过标准：

- 正确数据能生成三种格式报告。
- 坏数据不会悄悄进入统计。
- 金额统计使用 `Decimal` 或有明确理由。
- 日期排序正确。
- 空文件、缺字段、非法金额都有明确错误。

### 项目 3：自选自动化工具

从下面任选一个：

- 日志统计工具。
- 批量重命名工具。
- 空目录清理工具。
- CSV 合并工具。
- 文件名合法性检查工具。
- 目录体积统计工具。

必须具备：

- `argparse` 参数。
- `--dry-run`。
- 日志。
- 报告。
- 错误处理。
- README 使用说明。

## 代码质量验收

检查项：

- 入口函数是 `main()`。
- 参数解析和业务逻辑分离。
- 文件扫描和文件修改分离。
- 先生成执行计划，再执行。
- 函数名能表达意图。
- 没有大段重复代码。
- 没有默认危险操作。
- 异常信息包含文件路径或行号。
- 输出文件使用明确编码。
- 外部命令使用参数列表。

## 测试验收

至少完成：

- 5 个路径相关测试。
- 5 个 CSV/JSON 清洗测试。
- 5 个执行计划测试。
- 3 个错误输入测试。
- 2 个 dry-run 测试。

测试重点：

- 不依赖真实重要目录。
- 使用临时目录。
- 验证文件是否真的创建、移动或保留。
- 验证错误报告内容。
- 验证重复运行结果。

## 安全验收

必须能回答：

- 如果输入目录传错会发生什么？
- 如果目标文件已存在会发生什么？
- 如果执行中断会发生什么？
- 如果文件编码错误会发生什么？
- 如果外部命令失败会发生什么？
- 如何确认 dry-run 和真实执行计划一致？
- 如何防止处理输出目录里的结果文件？
- 哪些操作会删除或覆盖数据？

如果回答不清楚，说明脚本还不能用于真实文件。
