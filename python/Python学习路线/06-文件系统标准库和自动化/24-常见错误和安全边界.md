# 常见错误和安全边界

文件系统、标准库和自动化脚本最大的风险是“代码看起来很短，但影响范围很大”。一个错误的路径、一个错误的通配符、一个默认覆盖行为，都可能造成大量文件丢失或数据污染。

本节集中整理本阶段必须提前规避的错误。

## 路径类错误

### 相对路径依赖当前工作目录

同一个脚本从不同目录执行，`data/input.csv` 指向的位置可能不同。

解决方式：

- 命令行传入路径后立刻转成 `Path`。
- 关键路径打印到日志。
- 必要时转成绝对路径。
- 不假设当前工作目录固定。

```python
path = Path(args.input).resolve()
```

### 拼接路径使用字符串

错误写法：

```python
target = root + "\\" + filename
```

推荐：

```python
target = root / filename
```

原因：

- Windows 和 Linux 分隔符不同。
- 手动拼接容易多斜杠或少斜杠。
- `Path` 对象有更多路径操作方法。

### 对根目录执行批量操作

危险输入：

```text
C:\
D:\
/
~ 
```

防护：

- 拒绝磁盘根目录。
- 拒绝空路径。
- 对用户主目录要求二次确认。
- dry-run 展示完整计划。

## 删除和覆盖错误

### 默认删除源文件

整理文件时，第一版优先 copy 而不是 move。确认规则稳定后再启用 move。

### 默认覆盖目标文件

覆盖必须显式开启。

安全顺序：

1. 默认跳过。
2. 支持自动改名。
3. 支持备份。
4. 最后才支持 `--overwrite`。

### 递归删除没有范围检查

删除前必须确认目标路径在允许的工作区内。

```python
def is_relative_to(path, parent):
    path = path.resolve()
    parent = parent.resolve()
    return path == parent or parent in path.parents
```

不要把用户输入直接传给删除逻辑。

## 编码错误

### 默认编码不一致

Windows 环境下默认编码可能不是 UTF-8。读写中文文件时显式指定编码。

```python
path.read_text(encoding="utf-8")
path.write_text(content, encoding="utf-8")
```

CSV 常用：

```python
open(path, "r", encoding="utf-8-sig", newline="")
```

### 忽略编码错误导致数据丢失

`errors="ignore"` 会悄悄丢字符，不适合重要数据。

可选策略：

| 策略 | 说明 |
| --- | --- |
| `strict` | 默认，遇到错误直接失败 |
| `replace` | 用替代符显示坏字符 |
| `ignore` | 丢弃坏字符，高风险 |

学习阶段优先使用 `strict`，让错误暴露出来。

## 换行错误

### CSV 多空行

写 CSV 时忘记 `newline=""`，可能在 Windows 下出现空行。

```python
with path.open("w", encoding="utf-8-sig", newline="") as file:
    ...
```

### 混用换行符

不同系统可能使用 `\n` 或 `\r\n`。普通文本可让 Python 处理，CSV 交给 `csv` 模块处理。

## glob 和遍历错误

### 通配符范围过大

例如：

```python
Path("D:/").rglob("*")
```

这可能扫描整个磁盘。

防护：

- 限制输入目录。
- 增加 `--limit`。
- 先统计数量再执行。
- 输出扫描耗时。

### 遍历时同时修改目录

边 `rglob` 边移动文件可能影响遍历结果。

正确方式：

```python
files = [p for p in input_dir.rglob("*") if p.is_file()]
```

先固定列表，再执行批量修改。

### 符号链接循环

递归遍历时要明确是否跟随符号链接。默认不要跟随。

## subprocess 安全

### 拼接 shell 命令

危险写法：

```python
command = f"convert {source} {target}"
subprocess.run(command, shell=True)
```

推荐：

```python
subprocess.run(["convert", str(source), str(target)], check=True)
```

原则：

- 参数列表优先。
- 能不用 `shell=True` 就不用。
- 用户输入不能直接进入 shell 字符串。
- 记录返回码和错误输出。

### 忽略返回码

外部命令失败时，如果不检查返回码，脚本会继续使用不存在或不完整的输出。

```python
result = subprocess.run(args, capture_output=True, text=True)
if result.returncode != 0:
    raise RuntimeError(result.stderr)
```

或者：

```python
subprocess.run(args, check=True)
```

## 环境变量和配置错误

### 把密钥写进代码

密钥、令牌、密码不要写入脚本和 Markdown 示例。

应使用：

- 环境变量。
- 本地配置文件。
- 系统密钥管理工具。

### 环境变量不存在

读取环境变量要给出清晰错误。

```python
import os


token = os.environ.get("API_TOKEN")
if not token:
    raise RuntimeError("缺少环境变量 API_TOKEN")
```

### 配置优先级混乱

建议固定优先级：

1. 命令行参数。
2. 环境变量。
3. 配置文件。
4. 默认值。

## 时间日期错误

### 本地时间和 UTC 混用

日志、报表、文件名中使用时间时要明确：

- 是本地时间还是 UTC。
- 是否包含时区。
- 是否只需要日期。

### 用时间字符串排序

如果格式不是 `YYYY-MM-DD`，字符串排序可能错误。应解析成日期再排序。

### 文件名包含非法字符

Windows 文件名不能包含：

```text
< > : " / \ | ? *
```

时间戳文件名建议：

```python
datetime.now().strftime("%Y%m%d-%H%M%S")
```

## 正则表达式错误

### 正则过度复杂

如果规则可以用 `startswith`、`endswith`、`in`、`split` 完成，就不要强行使用正则。

### 贪婪匹配误伤

`.*` 可能匹配过多内容。需要时使用非贪婪或更明确的字符范围。

### 没有测试边界样例

正则至少测试：

- 空字符串。
- 正常样例。
- 多个匹配。
- 不应匹配的样例。
- 中文、空格、特殊符号。

## 大文件错误

### 一次性读入内存

危险：

```python
content = path.read_text(encoding="utf-8")
```

对于大文件，应逐行处理：

```python
with path.open("r", encoding="utf-8") as file:
    for line in file:
        ...
```

二进制大文件哈希应分块读取。

### 输出无限增长

日志和报告也可能很大。批量任务要考虑：

- 限制日志级别。
- 错误明细和摘要分开。
- 大报告使用 CSV/JSONL。
- 必要时按日期或任务编号分文件。

## 权限错误

常见原因：

- 文件正在被其他程序占用。
- 没有目录写权限。
- 目标文件只读。
- 杀毒软件或同步软件锁定文件。

处理方式：

- 捕获异常并记录路径。
- 不因为单个文件失败终止全部任务。
- 报告失败数量。
- 对关键输出使用 fail-fast。

## 幂等性错误

### 重复运行产生重复结果

例如第一次生成 `report.csv`，第二次又把 `report.csv` 当输入处理。

解决：

- 输入目录和输出目录分离。
- 输出目录加入排除规则。
- 每次运行写独立报告目录。
- 目标存在时有稳定策略。

### 任务中断后无法恢复

建议：

- 每个动作有结果记录。
- 已完成动作可识别。
- 输出报告及时写入。
- 重要步骤使用临时文件再替换。

## 日志错误

### 只有 print

`print` 适合学习和小脚本，批量任务应使用 `logging`。

日志应包含：

- 时间。
- 级别。
- 操作对象。
- 错误原因。
- 汇总结果。

### 日志泄露敏感信息

不要把 token、密码、完整连接串写进日志。

## 安全执行清单

每次运行批量脚本前检查：

- 输入目录是否正确。
- 输出目录是否正确。
- 是否先执行 dry-run。
- 计划数量是否符合预期。
- 是否存在覆盖、删除、移动。
- 是否有备份或可恢复路径。
- 是否限制了处理范围。
- 是否记录日志和报告。
- 是否用测试目录跑过。

## 高风险操作清单

以下操作必须更谨慎：

- `unlink`
- `rmdir`
- `shutil.rmtree`
- `shutil.move`
- 覆盖写入同名文件
- 递归遍历整个磁盘
- `subprocess.run(..., shell=True)`
- 根据用户输入生成命令
- 批量重命名
- 批量转换后删除源文件

## 练习

1. 写一个函数，拒绝磁盘根目录作为输入。
2. 写一个函数，检查目标路径是否在工作区内。
3. 给文件整理脚本增加 dry-run。
4. 给目标文件冲突增加 skip 策略。
5. 把字符串拼接命令改成参数列表。
6. 对一个错误编码文件做最小复现。
7. 写一个分块计算哈希的函数。
8. 给批量脚本增加错误报告 CSV。
9. 模拟文件被占用时的错误处理。
10. 写一份自己的批量脚本执行前检查表。

## 验收标准

- 能说出批量脚本最危险的 5 类错误。
- 能解释为什么 dry-run 必须和真实执行共用计划。
- 能避免默认覆盖和默认删除。
- 能正确处理编码、换行、路径和外部命令。
- 能为自己的脚本写出安全执行清单。
