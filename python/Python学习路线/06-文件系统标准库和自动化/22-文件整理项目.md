# 文件整理项目

文件整理项目是本阶段第一个综合项目。它把 `pathlib`、目录遍历、文件操作、哈希、CSV/JSON 报告、日志、dry-run 和错误处理串起来。

项目目标不是写一个“能跑一次”的脚本，而是写一个可以放心对测试目录执行、可以解释每一步结果、可以逐步扩展的批量整理工具。

## 项目目标

实现一个命令行工具：

```powershell
python organize_files.py --input .\inbox --output .\organized --dry-run
```

它需要完成：

- 扫描输入目录中的文件。
- 按规则分类文件。
- 识别重复文件。
- 生成移动或复制计划。
- 支持 dry-run。
- 处理目标文件名冲突。
- 输出整理报告。
- 记录错误日志。

## 最小可用版本

第一版只做 4 件事：

1. 递归扫描输入目录。
2. 按后缀分类到输出目录。
3. dry-run 展示移动计划。
4. 真实执行时移动文件。

示例分类：

```text
organized/
  images/
    a.jpg
    b.png
  documents/
    report.pdf
  data/
    users.csv
  archives/
    backup.zip
  others/
    unknown.xyz
```

## 输入规则

输入目录要求：

- 必须存在。
- 必须是目录。
- 不允许直接使用磁盘根目录。
- 不建议直接使用用户主目录。
- 不允许输出目录位于输入目录内部，除非非常明确地做过防护。

可接受参数：

| 参数 | 说明 |
| --- | --- |
| `--input` | 待整理目录 |
| `--output` | 整理输出目录 |
| `--recursive` | 是否递归扫描 |
| `--mode move/copy` | 移动或复制 |
| `--dry-run` | 预演 |
| `--dedupe` | 是否识别重复文件 |
| `--report` | 报告输出路径 |
| `--overwrite` | 是否允许覆盖 |

## 分类规则

建议先用后缀分类，再逐步扩展。

```python
CATEGORY_MAP = {
    ".jpg": "images",
    ".jpeg": "images",
    ".png": "images",
    ".gif": "images",
    ".pdf": "documents",
    ".docx": "documents",
    ".xlsx": "documents",
    ".csv": "data",
    ".json": "data",
    ".zip": "archives",
    ".rar": "archives",
    ".7z": "archives",
}
```

分类函数：

```python
def classify_file(path):
    suffix = path.suffix.lower()
    return CATEGORY_MAP.get(suffix, "others")
```

后续可扩展规则：

- 按文件大小分类。
- 按修改日期分类。
- 按文件名前缀分类。
- 按图片尺寸分类。
- 按业务关键字分类。

## 文件名冲突处理

目标文件已存在时不能默认覆盖。

常见策略：

| 策略 | 行为 |
| --- | --- |
| skip | 跳过并记录 |
| overwrite | 覆盖，必须显式启用 |
| rename | 自动改名 |
| error | 直接报错 |

自动改名示例：

```python
def unique_target(path):
    if not path.exists():
        return path

    stem = path.stem
    suffix = path.suffix
    parent = path.parent
    index = 1

    while True:
        candidate = parent / f"{stem}_{index}{suffix}"
        if not candidate.exists():
            return candidate
        index += 1
```

## 重复文件识别

重复文件不能只看文件名。更可靠的方式：

1. 先按文件大小分组。
2. 大小相同的文件再计算哈希。
3. 哈希相同的文件视为内容重复。

示例：

```python
import hashlib


def file_hash(path, chunk_size=1024 * 1024):
    digest = hashlib.sha256()
    with path.open("rb") as file:
        while chunk := file.read(chunk_size):
            digest.update(chunk)
    return digest.hexdigest()
```

注意：

- 大文件哈希计算可能耗时。
- 不要一次性把大文件读入内存。
- 哈希相同也应在报告中保留所有路径。
- 第一版可以只报告重复文件，不自动删除。

## 执行计划设计

计划对象建议包含：

| 字段 | 含义 |
| --- | --- |
| `source` | 原始路径 |
| `target` | 目标路径 |
| `category` | 分类 |
| `operation` | move/copy/skip |
| `reason` | 操作原因 |
| `conflict` | 是否有冲突 |
| `duplicate_group` | 重复文件分组 |

示例：

```python
from dataclasses import dataclass
from pathlib import Path


@dataclass
class FileAction:
    source: Path
    target: Path
    category: str
    operation: str
    reason: str
```

## 报告内容

报告至少包含：

- 本次运行时间。
- 输入目录。
- 输出目录。
- 是否 dry-run。
- 扫描文件数量。
- 成功数量。
- 跳过数量。
- 失败数量。
- 分类统计。
- 重复文件统计。
- 冲突文件清单。

CSV 报告适合人工查看：

```text
source,target,category,operation,status,message
D:\inbox\a.jpg,D:\organized\images\a.jpg,images,move,success,
```

JSON 报告适合程序继续处理：

```json
{
  "summary": {
    "scanned": 120,
    "success": 110,
    "skipped": 8,
    "failed": 2
  },
  "items": []
}
```

## 推荐实现步骤

### 第 1 步：扫描文件

```python
def collect_files(input_dir, recursive):
    pattern = "**/*" if recursive else "*"
    return [p for p in input_dir.glob(pattern) if p.is_file()]
```

验收：

- 能区分文件和目录。
- 能开关递归。
- 能跳过隐藏文件或临时文件。

### 第 2 步：生成分类目标

```python
def get_target(source, output_dir):
    category = classify_file(source)
    return output_dir / category / source.name
```

验收：

- 后缀统一小写处理。
- 无后缀文件归入 `others`。
- 目标路径不丢失原文件名。

### 第 3 步：处理冲突

验收：

- 默认不覆盖。
- 冲突文件有明确状态。
- 自动改名策略稳定。

### 第 4 步：dry-run

验收：

- 不创建目录。
- 不移动文件。
- 输出完整计划。
- 计划数量和真实执行一致。

### 第 5 步：真实执行

验收：

- 先创建目标目录。
- 使用 `shutil.move` 或 `shutil.copy2`。
- 单个文件失败不影响全部任务。
- 每个失败有错误原因。

### 第 6 步：输出报告

验收：

- 报告路径可配置。
- 报告使用 UTF-8。
- CSV 字段固定。
- JSON 保留摘要和明细。

## 安全边界

必须做到：

- 默认 dry-run 或强烈提示先 dry-run。
- 不自动删除重复文件。
- 不默认覆盖目标文件。
- 不在输入目录中直接生成大量结果文件。
- 不处理路径为空、根目录、系统目录的输入。
- 不跟随符号链接，除非显式启用。
- 操作前打印输入目录和输出目录。

## 常见错误

### 把输出目录放进输入目录

递归扫描时可能把刚整理出来的文件再次扫描，造成重复处理。

### 只按文件名判断重复

同名文件不一定重复，不同名文件也可能重复。

### 执行计划没有落盘

出错后无法知道脚本到底打算做什么。

### 默认覆盖

默认覆盖是高风险行为。覆盖必须由参数显式开启。
