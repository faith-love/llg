# TypeScript 深入理解

这个专题面向已经能写 JavaScript 或前端业务代码、希望系统掌握 TypeScript 类型系统和工程实践的前端工程师。重点不是把类型语法背一遍，而是理解 TypeScript 如何在编译期描述 JavaScript 的运行时形状，并在项目中用类型降低协作、重构和维护成本。

## 学习目标

- 能解释 TypeScript 只在编译期工作，运行时仍然是 JavaScript。
- 能区分值空间和类型空间，理解 `typeof`、`keyof`、`as const`、`satisfies` 的边界。
- 能写清楚对象、函数、数组、元组、联合、交叉、泛型和工具类型。
- 能理解类型收窄、控制流分析、可辨识联合和穷尽检查。
- 能读懂 React、Vue、组件库、SDK、请求层和状态管理里的复杂类型。
- 能设计项目级类型边界，避免 `any` 扩散。
- 能配置 `tsconfig`，理解严格模式、模块解析、路径别名和声明文件。
- 能排查常见类型报错，而不是靠断言绕过去。

## 总体心智模型

TypeScript 做的事情可以概括为：

```text
用类型在编译期描述 JavaScript 运行时数据的形状、约束和变化关系。
```

它不会让运行时自动变安全：

```typescript
type User = {
  id: string
  name: string
}

const user = JSON.parse('{"id":1}')
```

这里 `JSON.parse` 返回的数据运行时是什么，TypeScript 并不知道。你需要在边界处校验或转换。TypeScript 擅长的是让边界之后的代码更可靠。

## 推荐阅读顺序

1. 先读 `00-04`，建立类型空间、值空间、推断和对象建模基础。
2. 再读 `05-08`，掌握数组、函数、联合、收窄和泛型。
3. 然后读 `09-13`，进入类型编程能力。
4. 项目中用 TS 的同学继续读 `15-18`，补齐工程配置和业务实践。
5. 最后用 `19-21` 做报错排查、面试复盘和练习。

## 学习原则

- 不要为了“高级”而写复杂类型。能清晰表达业务约束才是好类型。
- 先保证边界安全，再追求内部类型优雅。
- `any` 是债务，`unknown` 是边界。
- 类型应该服务重构和协作，不应该变成绕不开的谜题。
- 学 TS 必须同时理解 JavaScript 运行时，否则只会写出看似安全的错觉。
