# 面试题与复盘

TypeScript 面试不应该只背工具类型实现。更重要的是能讲清楚类型系统如何服务真实项目。

## TypeScript 和 JavaScript 的关系

参考回答：

TypeScript 是 JavaScript 的超集，增加了静态类型系统和一些类型相关语法。TypeScript 代码最终会编译成 JavaScript，类型标注在运行时会消失。它主要在编译期发现错误、提升编辑器提示和重构可靠性，但不会自动校验运行时数据。

## type 和 interface 区别

要点：

- 都能描述对象结构。
- `interface` 支持声明合并和 extends。
- `type` 能表达联合、交叉、元组、条件类型等更多形式。
- 业务中保持风格一致比绝对选择更重要。

## any 和 unknown 区别

回答：

`any` 会关闭类型检查，可以访问任意属性和调用任意方法，容易传染。`unknown` 表示未知类型，使用前必须通过类型收窄或断言。外部输入边界优先用 `unknown`，临时迁移或兼容层才少量使用 `any`。

## never 是什么

回答：

`never` 表示不可能出现的值。常见于永不返回的函数、被穷尽检查排除后的分支、联合类型成员被完全排除后的结果。

例子：

```typescript
function assertNever(value: never): never {
  throw new Error(String(value))
}
```

## 泛型解决什么问题

回答：

泛型用于表达类型之间的关系，让函数、组件、工具类型在复用的同时保留具体类型。例如 `identity<T>(value: T): T` 表示返回值类型和输入类型一致。

## 联合类型如何安全使用

回答：

联合类型表示一个值可能是多个类型之一。使用时需要通过 `typeof`、`instanceof`、`in`、判别字段或自定义类型守卫收窄。复杂业务状态适合用可辨识联合，并配合 `never` 做穷尽检查。

## as const 有什么用

回答：

`as const` 会让对象或数组保留更窄的字面量类型，并把属性或数组变成只读。常用于从常量数组或配置对象生成联合类型。

例子：

```typescript
const statuses = ['idle', 'success'] as const
type Status = (typeof statuses)[number]
```

## satisfies 和 as 的区别

回答：

`as` 是类型断言，可能绕过错误。`satisfies` 是类型检查，能验证值满足某个类型，同时保留值自身更精确的推断。配置对象更推荐用 `satisfies`。

## tsconfig strict 为什么重要

回答：

`strict` 开启一组严格检查，比如空值、隐式 any、函数参数、属性初始化等。它能显著提升类型安全，是新项目推荐基线。老项目可以分阶段开启。

## 项目里如何治理 any

回答：

先定位 any 来源，优先把外部输入改成 `unknown`，在边界处校验或转换。迁移旧项目时允许短期 any，但要隔离在 adapter 层，配 TODO 和检查规则，避免进入核心业务模型和公共 API。

## 如何讲 TS 项目经验

回答结构：

```text
项目痛点 -> 类型设计 -> 工程配置 -> 迁移策略 -> 收益 -> 遇到的问题和治理
```
