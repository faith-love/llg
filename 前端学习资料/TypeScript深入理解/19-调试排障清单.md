# 调试排障清单

TypeScript 报错不要第一反应加 `as any`。先判断是值不对、类型不对、配置不对，还是第三方类型不对。

## Type 'X' is not assignable to type 'Y'

这是最常见的类型不兼容。

排查：

1. 看目标类型 `Y` 需要什么。
2. 看当前值 `X` 缺了什么或多了什么。
3. 看可选字段和 `undefined`。
4. 看字面量是否被推宽成 `string`。
5. 看泛型是否推断错了。

常见修复：

```typescript
const status = 'success' as const
```

或显式标注：

```typescript
const status: RequestStatus = 'success'
```

## Object is possibly 'undefined'

```typescript
user.profile.name
```

如果 `profile` 可选，需要处理：

```typescript
user.profile?.name
```

或先判断：

```typescript
if (user.profile) {
  user.profile.name
}
```

不要随手写：

```typescript
user.profile!.name
```

除非你能证明它一定存在。

## Property does not exist on type

```typescript
function print(value: string | number) {
  value.toUpperCase()
}
```

联合类型只能访问共有属性。先收窄：

```typescript
if (typeof value === 'string') {
  value.toUpperCase()
}
```

## Element implicitly has an any type

```typescript
function get(obj: User, key: string) {
  return obj[key]
}
```

`key` 太宽了。改成：

```typescript
function get<K extends keyof User>(obj: User, key: K) {
  return obj[key]
}
```

## Cannot find module

排查：

1. 依赖是否安装。
2. 类型包是否安装。
3. `paths` 是否配置。
4. Vite/Webpack/Jest 是否也配置了别名。
5. `moduleResolution` 是否匹配。
6. `.d.ts` 是否被 include。

## 类型推断太宽

```typescript
const config = {
  status: 'success'
}
```

`config.status` 可能被推断为 `string`。需要保留字面量：

```typescript
const config = {
  status: 'success'
} as const
```

如果还要检查结构：

```typescript
const config = {
  status: 'success'
} satisfies { status: 'success' | 'error' }
```

## 泛型推断不符合预期

```typescript
function request<T>(url: string): Promise<T> {}
```

调用：

```typescript
const user = await request('/api/user')
```

如果没有传泛型，`T` 可能无法推断。需要：

```typescript
const user = await request<User>('/api/user')
```

更好的方式是在 API 封装层固定返回类型：

```typescript
function getUser() {
  return request<User>('/api/user')
}
```

## 第三方库类型不准

处理顺序：

1. 升级库和类型包。
2. 查看库是否自带类型。
3. 用模块声明补类型。
4. 在很窄的 adapter 层断言。
5. 不要把不准的类型扩散到业务层。

## 排障模板

遇到类型问题，按这个顺序看：

```text
值来自哪里 -> 运行时形状是什么 -> 当前静态类型是什么 -> 目标类型是什么 -> 是代码错还是类型表达错
```

如果运行时数据不可信，先校验。

如果类型太宽，考虑 `as const`、显式标注或 `satisfies`。

如果类型太窄，检查泛型约束和字面量推断。

如果只想快速绕过，先把绕过限制在最小范围，并写 TODO。
