# 练习项目

这些练习用于验证 TypeScript 类型设计能力。每个练习都要先写运行时代码，再补类型，不要只写类型体操。

## 练习一：请求状态建模

要求：

- 定义 `AsyncState<T>`。
- 支持 `idle`、`loading`、`success`、`error`。
- 写 `renderState` 函数。
- 使用 `never` 做穷尽检查。

参考：

```typescript
type AsyncState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error }
```

## 练习二：类型安全的 getProperty

要求：

- 写 `getProperty(obj, key)`。
- `key` 必须是对象合法键。
- 返回值类型要根据 key 变化。

参考：

```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}
```

## 练习三：从常量生成联合类型

要求：

- 定义 `routes` 常量对象。
- 使用 `as const`。
- 生成 `RouteName` 和 `RoutePath`。

参考：

```typescript
const routes = {
  home: '/',
  user: '/users/:id'
} as const

type RouteName = keyof typeof routes
type RoutePath = (typeof routes)[RouteName]
```

## 练习四：实现 typed EventEmitter

要求：

- 事件名和 payload 类型关联。
- `on` 注册事件。
- `emit` 触发事件。
- 传错 payload 要报类型错误。

骨架：

```typescript
type Events = {
  login: { userId: string }
  logout: undefined
}

class EventEmitter<E extends Record<string, unknown>> {
  on<K extends keyof E>(event: K, listener: (payload: E[K]) => void) {}
  emit<K extends keyof E>(event: K, payload: E[K]) {}
}
```

## 练习五：API 响应类型封装

要求：

- 定义 `ApiResponse<T>`。
- 定义 `request<T>()`。
- 定义 `getUser()` 固定返回 `Promise<User>`。
- 思考运行时校验放在哪里。

## 练习六：表单草稿和提交模型

要求：

- 定义完整 `LoginForm`。
- 定义 `LoginFormDraft`。
- 写一个 `normalizeLoginForm`，把草稿转换成完整提交模型。
- 缺字段时返回错误。

目标是理解 `Partial<T>` 不能替代运行时校验。

## 练习七：实现工具类型

手写这些工具类型：

```typescript
type MyPartial<T> = ...
type MyPick<T, K extends keyof T> = ...
type MyExclude<T, U> = ...
type MyReturnType<T> = ...
type MyAwaited<T> = ...
```

每个工具类型都要写一个使用例子。

## 练习八：迁移一个 JS 工具模块

选择一个已有 JS 工具模块：

1. 给函数参数和返回值加类型。
2. 去掉隐式 any。
3. 用 `unknown` 处理外部输入。
4. 给测试补类型。
5. 记录哪些地方必须断言，以及为什么。

## 验收标准

- 不使用大面积 `any`。
- 能解释每个泛型参数的意义。
- 能说清类型和运行时校验的边界。
- 能用 `tsc --noEmit` 通过检查。
- 能把类型错误转化成更清晰的代码，而不是靠断言压掉。
