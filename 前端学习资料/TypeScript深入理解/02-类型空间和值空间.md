# 类型空间和值空间

TypeScript 同时处理两套东西：运行时的值，以及编译期的类型。很多 TS 困惑都来自把这两套空间混在一起。

## 值空间

值空间里的东西会出现在运行时 JavaScript 中：

```typescript
const user = { id: '1', name: 'Ada' }

function getName() {
  return user.name
}

class User {}
```

这些会编译成 JavaScript。

## 类型空间

类型空间里的东西只用于编译期检查：

```typescript
type User = {
  id: string
  name: string
}

interface Product {
  id: string
  price: number
}
```

编译后 `type` 和 `interface` 会消失。

## 同名可以同时存在

```typescript
type User = {
  id: string
}

const User = {
  defaultId: '1'
}
```

这里 `User` 在类型空间和值空间各有一个含义：

```typescript
const user: User = { id: User.defaultId }
```

第一个 `User` 是类型，第二个 `User` 是值。

## class 同时存在于两个空间

```typescript
class User {
  constructor(public name: string) {}
}

const user: User = new User('Ada')
```

`User` 既是运行时构造函数，也是实例类型。

如果要表示构造函数本身的类型：

```typescript
type UserConstructor = typeof User
```

这里的 `typeof User` 是 TypeScript 类型查询，不是 JavaScript 运行时 `typeof` 表达式。

## import type

只导入类型时，使用 `import type`：

```typescript
import type { User } from './types'
```

好处：

- 明确这个导入只用于类型。
- 避免某些构建工具生成不必要的运行时代码。
- 减少循环依赖风险。

如果既需要值又需要类型：

```typescript
import { UserModel } from './model'
```

## typeof 的两种含义

运行时：

```typescript
console.log(typeof 'Ada') // 'string'
```

类型空间：

```typescript
const user = {
  id: '1',
  name: 'Ada'
}

type User = typeof user
```

`type User = typeof user` 的意思是：根据变量 `user` 的静态类型生成一个类型。

## 常见错误

错误一：把类型当值用。

```typescript
type User = {
  id: string
}

console.log(User)
```

`User` 是类型，运行时不存在。

错误二：把值直接当类型用。

```typescript
const status = 'success'

let current: status
```

如果要从值生成类型，使用 `typeof`：

```typescript
let current: typeof status
```

## 判断规则

看名字出现在什么位置：

| 位置 | 需要什么 |
| --- | --- |
| `const x = ...` | 值 |
| `function fn(x: X)` | 类型 |
| `new X()` | 值 |
| `type A = X` | 类型 |
| `extends X` | 可能是值，也可能是类型，取决于语法位置 |
| `implements X` | 类型 |

理解类型空间和值空间，是读懂 TypeScript 高级类型的基础。
