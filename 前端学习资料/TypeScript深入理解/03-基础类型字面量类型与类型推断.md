# 基础类型、字面量类型与类型推断

TypeScript 会尽量从代码中推断类型。好的 TS 代码不是到处写类型标注，而是在关键边界标注，局部让推断工作。

## 基础类型

```typescript
let name: string = 'Ada'
let age: number = 18
let enabled: boolean = true
let nothing: null = null
let missing: undefined = undefined
let id: symbol = Symbol('id')
let big: bigint = 100n
```

这些类型描述 JavaScript 的基础值。

## 类型推断

```typescript
let name = 'Ada'
let age = 18
```

TypeScript 会推断：

```typescript
let name: string
let age: number
```

不需要重复写：

```typescript
let name: string = 'Ada'
```

除非你想表达更宽或更窄的类型。

## const 和 let 的推断差异

```typescript
let a = 'success'
const b = 'success'
```

推断结果：

```typescript
let a: string
const b: 'success'
```

`let` 变量后续可以改成其他字符串，所以推断为 `string`。`const` 变量不能重新赋值，所以推断为字面量类型 `'success'`。

## 字面量类型

```typescript
type Direction = 'left' | 'right' | 'up' | 'down'

function move(direction: Direction) {}

move('left')
move('center') // 类型错误
```

字面量类型适合表达有限集合。

常见业务场景：

```typescript
type RequestStatus = 'idle' | 'loading' | 'success' | 'error'
type ButtonSize = 'small' | 'medium' | 'large'
type ThemeMode = 'light' | 'dark'
```

## null 和 undefined

开启 `strictNullChecks` 后：

```typescript
let name: string = null
```

会报错。必须显式表达可能为空：

```typescript
let name: string | null = null
```

使用前要收窄：

```typescript
if (name !== null) {
  console.log(name.toUpperCase())
}
```

## void

`void` 常用于函数没有有效返回值：

```typescript
function log(message: string): void {
  console.log(message)
}
```

在回调类型中也常见：

```typescript
type ClickHandler = (event: MouseEvent) => void
```

这里的 `void` 表示调用方不关心返回值。

## object、Object 和 {}

不建议随便使用 `Object` 和 `{}`。

```typescript
let a: object = { id: 1 }
```

`object` 表示非原始值，不能直接访问具体属性。

```typescript
let b: {} = 1
```

`{}` 在 TS 中非常宽，很多非 `null`、非 `undefined` 的值都能赋给它。

实际业务中更推荐写明确对象结构：

```typescript
type User = {
  id: string
  name: string
}
```

## 类型标注应该写在哪里

应该标注：

- 函数参数。
- 函数返回值边界。
- API 数据结构。
- 组件 props。
- 复杂对象模型。
- 不能被正确推断的变量。

可以省略：

- 简单局部变量。
- 从明确函数返回值拿到的结果。
- 字面量临时变量。

```typescript
function formatUser(user: User): string {
  const name = user.name.trim()
  return name.toUpperCase()
}
```

`name` 不需要写成 `const name: string`，TS 能推断。
