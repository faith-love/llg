# 阅读路线与心智模型

TypeScript 学习不要从工具类型和复杂泛型开始。更稳的路线是先理解它和 JavaScript 的关系，再逐步掌握类型表达、类型推导、类型收窄、类型复用和工程边界。

## TypeScript 的定位

TypeScript 不是一门完全独立的运行时语言。它最终会被编译成 JavaScript：

```typescript
const name: string = 'Ada'
```

编译后类型标注会消失：

```javascript
const name = 'Ada'
```

所以要记住：

```text
TypeScript 负责编译期检查。
JavaScript 负责运行时执行。
```

类型写得再严谨，也不会自动校验接口返回值、localStorage 数据、URL 参数或用户输入。运行时边界仍然需要校验。

## 三个核心问题

学 TS 时反复问三个问题：

1. 这个值运行时长什么样？
2. 这个类型在编译期如何描述它？
3. 这个值从哪里来，边界是否可信？

例如接口数据：

```typescript
type User = {
  id: string
  name: string
}

async function getUser(): Promise<User> {
  const res = await fetch('/api/user')
  return res.json()
}
```

这段代码告诉 TypeScript `getUser` 返回 `User`，但运行时接口可能返回 `{ id: 1 }`。类型标注不是校验，它只是承诺。承诺来自不可信边界时，应该配合运行时校验。

## 推荐学习顺序

| 阶段 | 主题 | 目标 |
| --- | --- | --- |
| 1 | 类型和值 | 搞清类型空间和值空间，不混淆运行时和编译期 |
| 2 | 基础类型与推断 | 能看懂 TS 为什么推断成某个类型 |
| 3 | 对象和函数 | 能给业务对象、组件 props、请求函数建模 |
| 4 | 联合和收窄 | 能表达多种状态，并在代码中安全分支 |
| 5 | 泛型 | 能写复用函数、组件、请求封装和工具类型 |
| 6 | 类型派生 | 能用 `keyof`、索引访问、映射类型从已有类型生成新类型 |
| 7 | 工程配置 | 能配置严格模式、模块解析、路径别名和声明文件 |
| 8 | 项目治理 | 能控制 `any`、迁移 JS 项目、维护公共类型边界 |

## 类型系统服务代码，不是替代代码

坏方向：

```typescript
type VerySmartType<T> = ...
```

如果团队没人读得懂，维护成本可能高于收益。

好方向：

```typescript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error }
```

这个类型能直接约束业务状态，减少错误分支。

## 两条边界

### 外部输入边界

外部输入包括：

- 后端接口。
- URL 参数。
- 表单输入。
- localStorage。
- postMessage。
- 第三方 SDK。

这些数据不能只靠类型标注相信。

### 内部协作边界

内部协作包括：

- 函数参数。
- 组件 props。
- 状态对象。
- 事件 payload。
- 工具函数返回值。

这些地方很适合用 TypeScript 明确约束。

## 最重要的心智模型

```text
运行时数据先存在。
TypeScript 类型用来描述和约束这些数据。
类型越接近真实运行时形状，价值越高。
类型和运行时不一致时，错的是代码设计，不是编译器。
```
