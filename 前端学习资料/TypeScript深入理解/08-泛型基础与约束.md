# 泛型基础与约束

泛型用于表达“类型之间的关系”。它让函数、组件、类、工具类型可以复用，同时保留具体类型信息。

## 为什么需要泛型

没有泛型：

```typescript
function identity(value: any): any {
  return value
}

const result = identity('Ada')
```

`result` 是 `any`，类型信息丢了。

使用泛型：

```typescript
function identity<T>(value: T): T {
  return value
}

const result = identity('Ada')
```

`result` 推断为 `string`。

## 泛型表达输入和输出的关系

```typescript
function first<T>(list: T[]): T | undefined {
  return list[0]
}

const name = first(['Ada', 'Grace'])
const age = first([18, 20])
```

`name` 是 `string | undefined`，`age` 是 `number | undefined`。

## 多个泛型参数

```typescript
function map<T, U>(list: T[], mapper: (item: T) => U): U[] {
  return list.map(mapper)
}

const lengths = map(['a', 'bb'], (item) => item.length)
```

`T` 是输入项类型，`U` 是输出项类型。

## 泛型约束

```typescript
function getId<T extends { id: string }>(value: T): string {
  return value.id
}
```

`extends` 表示 `T` 至少要有 `id: string`。

调用后仍能保留完整类型：

```typescript
const user = getId({ id: '1', name: 'Ada' })
```

## keyof 约束

```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}

const user = { id: '1', name: 'Ada' }
const name = getProperty(user, 'name')
```

`K extends keyof T` 表示 `key` 必须是对象的合法键。

## 默认泛型参数

```typescript
type ApiResponse<T = unknown> = {
  code: number
  data: T
}
```

使用时可以不传：

```typescript
const response: ApiResponse = {
  code: 0,
  data: {}
}
```

也可以传：

```typescript
const response: ApiResponse<User> = {
  code: 0,
  data: { id: '1', name: 'Ada' }
}
```

## 泛型组件思路

```typescript
type SelectProps<T> = {
  options: T[]
  value: T
  onChange: (value: T) => void
  getLabel: (value: T) => string
}
```

这里 `options`、`value`、`onChange` 共享同一个 `T`，可以防止选项和值类型不一致。

## 泛型不是越多越好

不好的写法：

```typescript
function getValue<T, K, R>(obj: T, key: K): R {
  return (obj as any)[key as any]
}
```

这个泛型没有建立真实约束，只是在制造绕过类型系统的入口。

更好：

```typescript
function getValue<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}
```

判断泛型是否合理，问一句：这些类型参数之间有没有真实关系？
