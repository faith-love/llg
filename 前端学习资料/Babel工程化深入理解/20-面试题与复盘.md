# 面试题与复盘

Babel 和打包工程化面试通常不只问配置，而是问你是否理解整个构建链路。

## Babel 是什么

参考回答：

Babel 是 JavaScript 编译器，核心流程是 parse、transform、generate。它把源码解析成 AST，通过插件修改 AST，再生成目标代码。它常用于语法降级、JSX 转换、TypeScript 类型擦除和自定义代码转换。Babel 本身不是打包器，不负责建立完整依赖图和输出 chunk。

## Babel 和 Webpack 区别

回答要点：

- Babel 处理单个文件的语法转换。
- Webpack 从入口开始建立依赖图。
- Webpack 通过 loader 调 Babel。
- Webpack 负责 chunk、资源、plugin、输出。
- Babel 不决定分包策略。

## preset 和 plugin 区别

plugin 是具体转换能力。

preset 是一组 plugin 的集合。

执行顺序：

```text
plugins 从前到后
presets 从后到前
```

## preset-env 做了什么

参考回答：

`@babel/preset-env` 根据目标环境决定需要启用哪些语法转换，并可以配合 `core-js` 注入 polyfill。目标环境可以通过 `targets` 或 Browserslist 指定。它解决的是“按目标环境做最少必要转换”。

## 语法转换和 polyfill 区别

语法转换：

```javascript
const fn = () => {}
```

转成旧语法。

polyfill：

```javascript
Promise.resolve()
Array.from()
```

补运行时 API。

Babel 能帮你插入 polyfill 引用，但 API 实现来自 core-js 等库。

## transform-runtime 解决什么

回答：

它把 Babel helper 从每个文件内联改为从 `@babel/runtime` 引入，减少重复代码。库项目中还可以避免某些全局污染问题。它和 `preset-env` 不是一回事。

## Babel 处理 TypeScript 是否做类型检查

不做。`@babel/preset-typescript` 主要移除类型语法，输出 JavaScript。类型检查需要 `tsc --noEmit` 或其他类型检查流程。

## Webpack 打包流程

回答结构：

```text
entry -> resolve -> loader transform -> module graph -> chunk graph -> optimization -> emit
```

说明：

- entry 是入口。
- resolve 找文件。
- loader 转换模块。
- module graph 描述依赖。
- chunk graph 决定产物分包。
- optimization 做 tree-shaking、splitChunks、minify。
- emit 输出 assets。

## Vite 为什么开发快

回答：

Vite 开发模式利用浏览器原生 ESM，按需转换浏览器请求到的模块，不需要启动时把整个应用打成 bundle。依赖会预构建以减少请求和处理 CommonJS。生产构建则仍然会进入打包优化流程。

## tree-shaking 为什么失败

常见原因：

- CommonJS。
- Babel 提前转了模块。
- 依赖没有 ESM 产物。
- 顶层副作用。
- `sideEffects` 不准确。
- 动态 require。
- 没有生产压缩。

## 如何优化构建速度

回答顺序：

1. 先测量。
2. 缩小 Babel/loader 范围。
3. 开启缓存。
4. 减少不必要插件。
5. 调整 source map。
6. 使用更快转译器。
7. 类型检查并行。
8. 分析大依赖和压缩耗时。

## 如何讲项目经验

回答结构：

```text
项目背景 -> 构建工具 -> Babel 负责什么 -> 打包器负责什么 -> 兼容目标 -> 分包策略 -> 性能优化 -> 遇到的问题和排查
```

不要只说“配置过 Babel”。要能说清 Babel 在整个 pipeline 中的位置。
