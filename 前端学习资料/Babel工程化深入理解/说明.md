# Babel 工程化深入理解

这个专题面向已经会写前端业务代码、但想真正理解 Babel 和打包工程链路的工程师。重点不是只会复制 `.babelrc`，而是能说清楚：Babel 在构建流程里负责哪一段、打包器负责哪一段、一次从源码到产物的构建中每个步骤做了什么、能优化什么、会出什么问题。

## 先说结论

Babel 是 JavaScript 编译器，不是打包器。

```text
Babel 主要做：解析代码 -> 转换 AST -> 生成代码
Bundler 主要做：找入口 -> 建依赖图 -> 转换模块 -> 分包 -> tree-shaking -> 输出资源
```

Webpack、Rollup、Vite、Rspack、esbuild、SWC 等工具可能都会参与构建，但职责不同。工程化学习的关键，是不要把“语法转换”“模块打包”“代码压缩”“polyfill 注入”“资源处理”“开发服务器 HMR”混成一件事。

## 学习目标

- 能解释 Babel 的 parse、transform、generate 三阶段。
- 能区分 plugin、preset、polyfill、helper、runtime 的职责。
- 能配置 `@babel/preset-env`、targets、Browserslist 和 core-js。
- 能理解 Babel 如何处理 JSX、TypeScript、class fields、decorators。
- 能说清 Webpack/Rollup/Vite 一次打包的完整链路。
- 能解释 tree-shaking、code splitting、dynamic import、source map、cache。
- 能判断一个问题应该在 Babel、bundler、minifier、TypeScript 还是浏览器兼容层排查。
- 能设计应用项目和库项目不同的构建策略。
