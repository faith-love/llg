# 从源码到产物的全过程

这一章把 Babel 和打包器放到同一条生产构建流水线里看。以下不是某个工具的唯一实现，而是现代前端构建的通用过程。

## 1. 读取配置

构建工具读取：

- `package.json`
- `vite.config.ts` / `webpack.config.js` / `rollup.config.js`
- `babel.config.js`
- `tsconfig.json`
- Browserslist 配置
- 环境变量

这一阶段决定：

- 入口在哪里。
- 输出到哪里。
- 目标环境是什么。
- 是否开启 sourcemap。
- 是否压缩。
- 是否需要 Babel。
- 别名和模块解析规则。

## 2. 确定入口

应用项目：

```text
index.html -> src/main.tsx
```

或：

```javascript
entry: './src/main.tsx'
```

库项目：

```text
src/index.ts
```

入口是依赖图起点。

## 3. 解析模块路径

遇到：

```javascript
import Button from '@/components/Button'
```

打包器要解析：

```text
@ -> src
Button -> Button.tsx / Button.ts / Button.js / Button/index.tsx
```

这一阶段由 resolve 规则、alias、extensions、package exports、main/module 字段共同影响。

## 4. 加载模块内容

打包器读取文件内容：

```text
src/main.tsx
src/App.tsx
src/style.css
src/logo.svg
```

不同文件类型会进入不同处理链。

## 5. 转换模块

JS/TS/JSX 可能经过：

```text
Babel / esbuild / SWC / TypeScript
```

Babel 在这里做：

- 解析语法。
- 转换 JSX。
- 移除 TS 类型。
- 降级语法。
- 执行自定义插件。
- 生成 source map。

CSS 可能经过：

- PostCSS。
- Sass/Less。
- CSS Modules。
- autoprefixer。

图片和字体可能被：

- 内联成 base64。
- 复制到 assets。
- 改名加 hash。

## 6. 收集依赖

转换后，打包器继续分析 import：

```javascript
import './style.css'
import { request } from './request'
```

递归处理，直到依赖图完整。

## 7. 建立 module graph

module graph 描述模块之间的依赖关系：

```text
main.tsx
  -> App.tsx
    -> Button.tsx
    -> style.css
  -> request.ts
```

后续 tree-shaking、分包、缓存都依赖这个图。

## 8. 标记副作用和使用关系

打包器判断：

- 哪些 export 被用到。
- 哪些模块有副作用。
- 哪些语句可以删除。
- 哪些依赖必须保留。

`package.json` 的 `sideEffects`、ESM 静态结构、代码写法都会影响结果。

## 9. 生成 chunk graph

同步依赖通常进入当前 chunk。

动态导入产生异步 chunk：

```javascript
const Page = import('./pages/Admin')
```

公共依赖可能被抽成 shared/vendor chunk。

结果可能是：

```text
main.js
vendor.js
admin-page.js
style.css
```

## 10. 渲染代码

打包器把模块包装成运行时代码：

- 模块注册。
- 模块缓存。
- chunk 加载函数。
- import/export 连接。
- publicPath。

Rollup 更倾向输出接近 ESM 的结构。Webpack 通常有更明显的 runtime 包装。

## 11. 压缩和混淆

minifier 做：

- 删除空白和注释。
- 缩短变量名。
- 删除不可达代码。
- 常量折叠。
- 合并表达式。
- 删除纯函数调用。

常见工具：

- Terser。
- esbuild minify。
- SWC minify。

## 12. 生成 source map

source map 用于把产物位置映射回源码。

开发环境通常需要高质量 source map。

生产环境要考虑：

- 是否公开源码。
- 上传到错误监控平台。
- 是否只生成 hidden source map。
- 文件体积和构建时间。

## 13. 输出 dist

最终输出：

```text
dist/
  index.html
  assets/
    main.8f3a1.js
    vendor.92ab0.js
    admin.7c11d.js
    style.aabbc.css
    logo.31aa.svg
```

文件名 hash 用于浏览器缓存。

## 14. 部署和运行时加载

浏览器加载：

```text
index.html -> main.js -> vendor.js -> async chunks
```

动态 chunk 会在路由切换或功能触发时加载。

如果 public path、资源路径、CDN、base 配错，打包成功也可能运行时报 404。

## Babel 在整条链里的位置

```text
第 5 步：转换单个 JS/TS/JSX 模块
```

它不决定 chunk 怎么拆，也不决定 HTML 怎么生成。它的输出会继续交给打包器做模块图、分包和优化。
