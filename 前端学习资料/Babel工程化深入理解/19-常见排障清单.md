# 常见排障清单

构建问题要按阶段定位：解析、转换、打包、压缩、运行时、类型检查。不要一上来改一堆配置。

## Unexpected token

现象：

```text
Unexpected token ?
Unexpected token <
```

排查：

1. 是 JS 新语法不被 parser 支持，还是 JSX 没处理？
2. 文件是否经过 Babel/esbuild/SWC？
3. loader include/exclude 是否漏了文件？
4. 依赖包是否发布了现代语法但没有被转译？
5. Babel parser 是否需要对应 plugin？

## JSX 没转换

现象：

```text
Unexpected token '<'
```

排查：

1. 是否配置 `@babel/preset-react`。
2. 文件扩展名是否匹配 loader。
3. Vite/React plugin 是否启用。
4. tsconfig jsx 配置是否匹配。

## TypeScript 类型没报错

原因：Babel 只移除 TS 类型，不做类型检查。

修复：

```bash
tsc --noEmit
```

并把它加入 CI。

## Promise is not defined

说明语法转换完成了，但 API 缺失。

排查：

1. targets 是否包含旧环境。
2. 是否配置 `useBuiltIns`。
3. 是否安装 `core-js`。
4. 是否需要 regenerator runtime。

## 装饰器报错

排查：

1. 新版标准装饰器还是 legacy decorators？
2. Babel 插件和 TypeScript 配置是否一致？
3. `experimentalDecorators` 是否需要开启？
4. 是否依赖 `emitDecoratorMetadata`？
5. 插件顺序是否正确？
6. 框架版本是否支持当前语义？

## tree-shaking 失效

排查：

1. Babel 是否把 ESM 转成 CommonJS。
2. 依赖包是否有 ESM 入口。
3. `sideEffects` 是否准确。
4. 模块是否有顶层副作用。
5. 是否使用了动态 require。
6. 是否开启生产压缩。

## chunk 加载失败

现象：

```text
Loading chunk failed
```

排查：

1. public path/base 是否正确。
2. CDN 是否上传完整。
3. HTML 是否引用旧 hash。
4. 用户浏览器缓存了旧入口文件。
5. 部署是否原子更新。

## source map 不准

排查：

1. Babel 是否传递 source map。
2. loader 链是否保留 source map。
3. minifier 是否生成 source map。
4. 上传的 map 是否和线上文件 hash 对应。
5. 是否多次编译但丢失原始映射。

## 构建很慢

排查：

1. Babel 是否扫了过多文件。
2. 是否转译了所有 node_modules。
3. 是否没有开缓存。
4. source map 是否太重。
5. minify 是否耗时。
6. TypeScript 类型检查是否阻塞主构建。
7. 是否有大依赖导致预构建慢。

## 最小定位法

1. 单独用 Babel CLI 编译出问题文件。
2. 如果 Babel CLI 正常，查 bundler loader/plugin。
3. 如果 Babel CLI 失败，查 Babel 配置和语法插件。
4. 如果构建成功运行失败，查 polyfill、路径、chunk、环境变量。
5. 如果只有类型问题，查 TypeScript，不要改 Babel。
