# 应用项目和库项目构建差异

应用项目和库项目的 Babel 策略不同。应用项目控制最终运行环境，库项目要被别人打包和运行。

## 应用项目目标

应用项目关注：

- 目标浏览器兼容。
- 首屏体积。
- 分包和缓存。
- polyfill 是否完整。
- source map 和线上排障。
- 部署路径。

应用可以决定：

```text
我要兼容哪些浏览器
我要不要注入全局 polyfill
我要怎么拆 chunk
```

## 库项目目标

库项目关注：

- 产物格式。
- 类型声明。
- tree-shaking 友好。
- 不污染使用方全局。
- helper 不重复。
- peerDependencies。

库不应该随便替使用方决定全局 polyfill。

## 应用项目 Babel 示例

```json
{
  "presets": [
    ["@babel/preset-env", {
      "targets": "> 0.5%, not dead",
      "useBuiltIns": "usage",
      "corejs": "3.37",
      "modules": false
    }],
    ["@babel/preset-react", {
      "runtime": "automatic"
    }],
    "@babel/preset-typescript"
  ]
}
```

应用项目可以注入 polyfill，因为它控制页面运行环境。

## 库项目 Babel 示例

```json
{
  "presets": [
    ["@babel/preset-env", {
      "modules": false
    }],
    "@babel/preset-typescript"
  ],
  "plugins": [
    "@babel/plugin-transform-runtime"
  ]
}
```

库项目通常还需要：

```bash
tsc --emitDeclarationOnly
```

生成 `.d.ts`。

## package.json 字段

```json
{
  "main": "./dist/index.cjs",
  "module": "./dist/index.esm.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/index.esm.js",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    }
  },
  "sideEffects": false
}
```

这些字段决定使用方如何加载你的包。

## 多格式输出

库常见格式：

- ESM：给现代 bundler tree-shaking。
- CJS：给 Node 或老工具。
- UMD/IIFE：给浏览器 script 标签，现代库较少。

不要发布过多格式，维护成本会增加。根据使用场景选择。

## external

库构建通常把 React、Vue 等 peer dependency 外置：

```javascript
external: ['react', 'react-dom']
```

否则使用方可能打进两份 React。

## polyfill 策略差异

应用：

```text
可以全局 polyfill
```

库：

```text
尽量不污染全局，文档说明使用方需要的环境或 polyfill
```

## 发布前检查

库项目发布前检查：

- ESM 是否保留。
- CJS 是否可用。
- `.d.ts` 是否生成。
- `exports` 是否正确。
- `sideEffects` 是否准确。
- 是否错误打包 peerDependencies。
- 是否引入全局 polyfill。
- tree-shaking 是否有效。
