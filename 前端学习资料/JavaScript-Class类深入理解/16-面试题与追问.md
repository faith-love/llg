# 面试题与追问

这一章不是背答案，而是训练你把 class 的运行时结构说清楚。回答时尽量按“是什么 -> 运行时结构 -> 例子 -> 常见坑”组织。

## class 是什么，是不是语法糖

参考答案：

`class` 是 JavaScript 提供的类语法，用来更清晰地定义构造函数、原型方法、静态成员、字段和继承关系。它运行时仍然基于函数对象、原型对象和原型链，所以可以说它在很大程度上是原型模型的语法封装。但它不只是普通语法糖，因为 class 构造器不能裸调用，class 体内部是严格模式，方法默认不可枚举，还支持私有字段、静态块、派生类构造等更严格的新语义。

追问：

- `typeof class A {}` 是什么？
- class 方法在哪里？
- class 构造器能不能 `call`？
- class 方法为什么 `Object.keys(A.prototype)` 看不到？

## class 和 function 构造器有什么区别

要点：

- class 必须用 `new`。
- class 声明有暂时性死区。
- class 体强制严格模式。
- class 方法不可枚举。
- class 方法不能作为构造器。
- class 支持 `extends`、`super`、`#private`、fields、static block。

示例：

```javascript
class User {}
User() // TypeError

function Admin() {}
Admin() // 可以调用
```

## new 做了什么

回答框架：

1. 创建新对象。
2. 把新对象原型指向构造函数的 `prototype`。
3. 绑定 `this` 并执行构造逻辑。
4. 初始化实例字段。
5. 返回实例；如果构造器显式返回对象，则可能替换默认实例。

追问：

- 构造器返回对象会怎样？
- 派生类构造器返回基本类型会怎样？
- `new.target` 是什么？

## 方法和字段有什么区别

回答：

普通方法定义在 `Class.prototype` 上，所有实例共享。实例字段定义在每个实例自己身上，每次实例化都会初始化。方法默认不可枚举，公共字段默认可枚举。

示例：

```javascript
class User {
  name = 'Ada'
  sayHi() {}
}

const user = new User()

Object.hasOwn(user, 'name') // true
Object.hasOwn(user, 'sayHi') // false
```

追问：

- 箭头字段方法在哪里？
- 为什么箭头字段不能被 `super.method()` 调用？

## #private 和 private 有什么区别

回答：

`#private` 是 JavaScript 运行时私有成员，有私有槽和品牌检查，类外语法上不能访问。TypeScript 的 `private` 主要是编译期约束，编译后通常仍是普通属性。需要运行时强封装时用 `#private`；只需要类型层面的访问控制时可以用 TypeScript `private`。

追问：

- `obj['#x']` 能访问私有字段吗？
- `#x in obj` 是什么？
- 静态私有字段能被子类静态方法复用吗？

## extends 做了什么

回答：

`extends` 建立两条原型链：子类构造函数的原型指向父类构造函数，用于静态成员继承；子类 `prototype` 的原型指向父类 `prototype`，用于实例方法继承。

代码：

```javascript
class Base {}
class Sub extends Base {}

Object.getPrototypeOf(Sub) === Base
Object.getPrototypeOf(Sub.prototype) === Base.prototype
```

追问：

- 静态方法能继承吗？
- `super.method()` 的 this 是谁？
- 父类构造器调用子类重写方法有什么风险？

## 为什么派生类 constructor 里要先 super

回答：

派生类的实例初始化依赖父类构造器。调用 `super()` 前，`this` 还没有完成绑定，所以不能访问 `this`。`super()` 调用父类构造器，返回后子类实例字段初始化，然后继续执行子类构造器剩余代码。

追问：

- 父类构造器里能看到子类字段吗？
- `super()` 可以调用两次吗？

## this 为什么会丢

回答：

class 方法中的 `this` 由调用方式决定，不由定义位置永久绑定。`obj.method()` 调用时 `this` 是 `obj`；把方法赋给变量或作为回调传递后，调用时没有接收者，严格模式下 `this` 是 `undefined`。

修复：

- 保留 `obj.method()` 调用形式。
- 使用 `bind`。
- 使用箭头函数包装。
- 使用箭头字段，但接受每实例创建函数和不适合 `super` 的代价。

## static 适合放什么

回答：

静态成员属于构造函数对象，不属于实例。适合放类级别工厂、注册表、常量、静态缓存、和类强相关的工具方法。不适合只是为了模拟命名空间而把所有工具函数都塞进 class；普通模块函数通常更简单。

追问：

- 静态方法中的 `this` 是什么？
- 静态字段什么时候执行？
- 静态块有什么用？

## 如何判断该用 class 还是函数

回答：

如果需要多个实例、共享原型方法、封装内部状态、表达生命周期或继承平台基类，可以用 class。如果只是无状态计算、数据转换、工具函数、React 新业务组件逻辑，普通函数或组合通常更轻。

回答时可以补一句：class 是组织状态和行为的一种方式，不是默认答案。
