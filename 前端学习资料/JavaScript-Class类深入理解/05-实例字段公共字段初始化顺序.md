# 实例字段、公共字段与初始化顺序

实例字段是 class fields 语法的一部分。它让“每个实例自己的属性”可以直接写在 class 体里，而不是全部塞进 `constructor`。

## 基本写法

```javascript
class Counter {
  count = 0

  inc() {
    this.count += 1
  }
}

const counter = new Counter()
console.log(counter.count) // 0
```

`count` 是实例自己的属性：

```javascript
console.log(Object.hasOwn(counter, 'count')) // true
```

## 类体字段和构造器变量不是一回事

类体里的字段会变成实例属性：

```javascript
class User {
  name = 'Ada'
}

const user = new User()
console.log(user.name) // 'Ada'
```

构造器里的普通变量只是临时变量：

```javascript
class User {
  constructor(name) {
    const normalizedName = name.trim()
  }
}

const user = new User(' Ada ')
console.log(user.normalizedName) // undefined
```

如果要把构造器里的计算结果留在实例上，需要显式赋给 `this`：

```javascript
class User {
  constructor(name) {
    const normalizedName = name.trim()
    this.name = normalizedName
  }
}
```

也可以保存到私有字段：

```javascript
class User {
  #name

  constructor(name) {
    this.#name = name.trim()
  }

  getName() {
    return this.#name
  }
}
```

一句话区分：类体字段和 `this.xxx` 都是在描述实例状态；构造器里的 `const`、`let`、函数参数只是构造过程中的局部数据。

## 字段初始化每次实例化都会执行

```javascript
class Demo {
  id = Math.random()
}

const a = new Demo()
const b = new Demo()

console.log(a.id === b.id) // false
```

字段初始化表达式不是 class 定义时执行，而是每次创建实例时执行。

## 字段可以引用 this

```javascript
class User {
  firstName = 'Ada'
  lastName = 'Lovelace'
  fullName = `${this.firstName} ${this.lastName}`
}

console.log(new User().fullName) // 'Ada Lovelace'
```

字段按源码顺序初始化，所以后面的字段可以读取前面的字段。

## 字段初始化顺序

```javascript
class Demo {
  a = 1
  b = this.a + 1
  a = 10
}

console.log(new Demo()) // Demo { a: 10, b: 2 }
```

顺序是：

1. 初始化 `a = 1`。
2. 初始化 `b = this.a + 1`，此时 `this.a` 是 `1`。
3. 再初始化 `a = 10`，覆盖之前的 `a`。

不要在同一个 class 里重复声明同名字段，除非你明确想覆盖。

## 字段和 constructor 的顺序

基础类中，实例字段先于构造器主体执行：

```javascript
class User {
  name = 'default'

  constructor(name) {
    console.log(this.name)
    this.name = name
  }
}

new User('Ada') // 'default'
```

派生类中，子类字段在 `super()` 之后、子类构造器剩余语句之前执行：

```javascript
class Base {
  constructor() {
    console.log('base', this.name)
  }
}

class User extends Base {
  name = 'field'

  constructor() {
    super()
    console.log('after super', this.name)
  }
}

new User()
```

输出：

```text
base undefined
after super field
```

父类构造器执行时，子类字段还没有初始化。

## 字段使用 Define 语义

公共字段会在实例上定义自有属性，而不是简单执行 `this.x = value`。这会影响继承场景中的 setter。

```javascript
class Base {
  set x(value) {
    console.log('setter', value)
  }
}

class Sub extends Base {
  x = 1
}

new Sub()
```

标准 class fields 语义下，`x = 1` 会直接在实例上定义属性，不会调用父类原型上的 setter。

如果改成构造器赋值：

```javascript
class Sub extends Base {
  constructor() {
    super()
    this.x = 1
  }
}
```

这会触发 setter。

这也是 Babel、TypeScript 历史配置中 `loose` 或 `useDefineForClassFields` 容易造成差异的地方。

## 字段描述符

```javascript
class User {
  name = 'Ada'
}

const user = new User()
console.log(Object.getOwnPropertyDescriptor(user, 'name'))
```

典型结果：

```text
{
  value: 'Ada',
  writable: true,
  enumerable: true,
  configurable: true
}
```

公共实例字段默认可写、可枚举、可配置。

## 字段中不要做重副作用

可以写：

```javascript
class Store {
  cache = new Map()
}
```

谨慎写：

```javascript
class Store {
  data = fetch('/api/data')
}
```

原因：

- 字段初始化发生在构造期间，副作用不容易被调用方感知。
- 测试时不容易替换。
- 继承时顺序更难推断。
- 异步结果和实例生命周期容易耦合。

更清晰的方式通常是显式方法：

```javascript
class Store {
  data = null

  async load() {
    this.data = await fetch('/api/data').then((res) => res.json())
  }
}
```
