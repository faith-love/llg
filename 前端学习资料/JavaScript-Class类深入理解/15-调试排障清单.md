# 调试与排障清单

这一章按常见现象整理 class 问题。遇到报错时先定位对象在哪一层：构造函数对象、原型对象、实例对象，还是私有槽。

## Class constructor cannot be invoked without new

现象：

```text
TypeError: Class constructor User cannot be invoked without 'new'
```

常见原因：

```javascript
class User {}
User()
```

或某个框架、工具把 class 当普通函数调用。

修复：

```javascript
new User()
```

如果你需要工厂函数：

```javascript
class User {}

function createUser() {
  return new User()
}
```

## Cannot access before initialization

现象：

```text
ReferenceError: Cannot access 'User' before initialization
```

常见原因：

```javascript
new User()
class User {}
```

或循环导入导致模块执行顺序中提前访问 class。

排查：

1. 看 class 是否在声明前使用。
2. 看是否有循环依赖。
3. 把副作用初始化延后到函数调用阶段。
4. 把共享类型和值拆分到更底层模块。

## Cannot read properties of undefined

现象：

```text
TypeError: Cannot read properties of undefined
```

常见原因：

```javascript
class User {
  name = 'Ada'

  sayHi() {
    return this.name
  }
}

const user = new User()
const fn = user.sayHi
fn()
```

修复方式：

```javascript
const fn = user.sayHi.bind(user)
```

或：

```javascript
const fn = () => user.sayHi()
```

或把回调写成箭头字段：

```javascript
class User {
  sayHi = () => this.name
}
```

## Must call super constructor before accessing this

现象：

```text
ReferenceError: Must call super constructor before accessing 'this'
```

错误：

```javascript
class Sub extends Base {
  constructor() {
    this.x = 1
    super()
  }
}
```

修复：

```javascript
class Sub extends Base {
  constructor() {
    super()
    this.x = 1
  }
}
```

派生类构造器中，访问 `this` 前必须先 `super()`。

## Cannot read private member

现象：

```text
TypeError: Cannot read private member
```

常见原因：

```javascript
class User {
  #token = 'secret'

  read(obj) {
    return obj.#token
  }
}

new User().read({})
```

传入的对象没有对应私有品牌。

修复：

```javascript
class User {
  #token = 'secret'

  static isUser(obj) {
    return #token in obj
  }
}
```

访问前先做品牌检查，或者不要让方法读取任意对象的私有字段。

## super.method is not a function

常见原因一：父类没有这个原型方法。

```javascript
class Base {}

class Sub extends Base {
  save() {
    return super.save()
  }
}
```

常见原因二：父类把方法写成了箭头字段。

```javascript
class Base {
  save = () => {}
}

class Sub extends Base {
  save() {
    return super.save()
  }
}
```

`super.save()` 找的是 `Base.prototype.save`，不是父类实例字段。

修复：需要继承重写的方法应写成原型方法。

## 字段值被覆盖

现象：

```javascript
class Base {
  constructor() {
    this.name = 'base'
  }
}

class Sub extends Base {
  name = 'sub'
}

console.log(new Sub().name) // 'sub'
```

原因：子类字段在 `super()` 后初始化，覆盖父类构造器设置的同名属性。

排查：

1. 找父类构造器赋值。
2. 找子类字段声明。
3. 找子类构造器赋值。
4. 按执行顺序判断最后谁覆盖谁。

## setter 没有触发

```javascript
class Base {
  set value(v) {
    console.log(v)
  }
}

class Sub extends Base {
  value = 1
}

new Sub()
```

公共字段初始化不会触发父类原型 setter。

如果你需要触发 setter，使用构造器赋值：

```javascript
class Sub extends Base {
  constructor() {
    super()
    this.value = 1
  }
}
```

## instanceof 判断不符合预期

可能原因：

- 构造器返回了另一个对象。
- 原型链被手动修改。
- 对象来自不同 iframe 或 realm。
- 使用代理或 mock 改写了原型。
- 多份包导致存在多个同名 class。

排查：

```javascript
Object.getPrototypeOf(obj)
obj.constructor
obj instanceof User
Object.getPrototypeOf(User.prototype)
```

对于跨包实体，优先用稳定字段、品牌方法或协议判断，不要只依赖 `instanceof`。

## 最小排查模板

把问题对象放进这个模板：

```javascript
console.log('obj own keys', Reflect.ownKeys(obj))
console.log('obj proto', Object.getPrototypeOf(obj))
console.log('proto keys', Reflect.ownKeys(Object.getPrototypeOf(obj)))
console.log('ctor', obj.constructor)
console.log('is instance', obj instanceof Constructor)
console.log('ctor own keys', Reflect.ownKeys(Constructor))
console.log('ctor proto', Object.getPrototypeOf(Constructor))
```

先看清对象结构，再判断语义问题。
