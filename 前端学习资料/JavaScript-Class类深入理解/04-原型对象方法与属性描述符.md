# 原型对象、方法与属性描述符

class 的普通方法不会复制到每个实例上，而是定义在 `ClassName.prototype` 上。所有实例通过原型链共享这些方法。

## 方法在原型上

```javascript
class User {
  name = 'Ada'

  sayHi() {
    return `Hi, ${this.name}`
  }
}

const a = new User()
const b = new User()

console.log(a.sayHi === b.sayHi) // true
console.log(a.sayHi === User.prototype.sayHi) // true
```

`sayHi` 只有一份，保存在 `User.prototype` 上。

## 实例字段在实例上

```javascript
class User {
  name = 'Ada'

  sayHi() {}
}

const user = new User()

console.log(Object.hasOwn(user, 'name')) // true
console.log(Object.hasOwn(user, 'sayHi')) // false
```

字段是每个实例自己的属性。方法是原型共享属性。

## 实例字段和静态字段的位置

看这个例子：

```javascript
class User {
  name = 'Ada'
  static age = 18
}

const user1 = new User()
const user2 = new User()
```

`name` 没有加 `static`，它是实例字段。每次 `new User()` 都会在新实例上创建一份 `name`：

```javascript
console.log(user1.name) // 'Ada'
console.log(user2.name) // 'Ada'
console.log(Object.hasOwn(user1, 'name')) // true
console.log(Object.hasOwn(user2, 'name')) // true
```

`age` 加了 `static`，它是静态字段。它不属于实例，而是属于 `User` 这个构造函数对象：

```javascript
console.log(User.age) // 18
console.log(user1.age) // undefined
console.log(Object.hasOwn(User, 'age')) // true
console.log(Object.hasOwn(user1, 'age')) // false
```

所以这段 class 可以拆成：

```text
User.age              -> 静态字段，挂在构造函数对象 User 上
user1.name            -> 实例字段，挂在 user1 实例上
user2.name            -> 实例字段，挂在 user2 实例上
User.prototype        -> 普通方法所在的位置，这个例子里暂时没有方法
```

注意一个容易混淆的点：`User.name` 本来就是函数对象的内置 `name` 属性，值通常是类名字符串 `'User'`，它和实例字段 `user.name` 不是同一个东西。

```javascript
class User {
  name = 'Ada'
}

const user = new User()

console.log(User.name) // 'User'
console.log(user.name) // 'Ada'
```

如果写的是 `static name = 'Ada'`，那就是在处理构造函数对象自己的 `name` 属性，这和普通实例字段完全不同，也容易影响调试显示，不建议用 `static name` 表达业务含义。

## 类体字段、constructor 赋值和局部变量

类体里的实例字段：

```javascript
class User {
  name = 'Ada'
}
```

含义是：每次创建实例时，在这个实例上定义一个 `name` 属性。

构造器里给 `this` 赋值：

```javascript
class User {
  constructor(name) {
    this.name = name
  }
}
```

含义也是：给当前实例创建或修改 `name` 属性。区别在于值来自构造参数，并且它使用赋值语义，和 class fields 的 Define 语义在继承、setter 等场景下会有差异。

构造器里的普通变量：

```javascript
class User {
  constructor(name) {
    const displayName = name.trim()
  }
}
```

`displayName` 只是构造器执行期间的局部变量。构造器执行完就不能从实例上访问它：

```javascript
const user = new User(' Ada ')
console.log(user.displayName) // undefined
```

如果希望实例后续还能访问，必须保存到 `this` 或私有字段：

```javascript
class User {
  #displayName

  constructor(name) {
    const normalizedName = name.trim()
    this.name = normalizedName
    this.#displayName = normalizedName
  }

  getDisplayName() {
    return this.#displayName
  }
}
```

简单判断规则：

| 写法 | 位置 | 访问方式 | 生命周期 |
| --- | --- | --- | --- |
| `name = 'Ada'` | 每个实例自己身上 | `user.name` | 跟随实例 |
| `static age = 18` | 构造函数对象 `User` 身上 | `User.age` | 跟随 class |
| `this.name = name` | 当前实例自己身上 | `user.name` | 跟随实例 |
| `const x = ...` | 构造器局部作用域 | 只能在构造器内部用 | 构造器执行结束后消失 |

## class 方法默认不可枚举

```javascript
class User {
  sayHi() {}
}

console.log(Object.keys(User.prototype)) // []
console.log(Object.getOwnPropertyNames(User.prototype)) // ['constructor', 'sayHi']
```

方法不可枚举，但仍然是原型对象自己的属性。

查看描述符：

```javascript
console.log(Object.getOwnPropertyDescriptor(User.prototype, 'sayHi'))
```

典型结果：

```text
{
  value: [Function: sayHi],
  writable: true,
  enumerable: false,
  configurable: true
}
```

## constructor 也在 prototype 上

```javascript
class User {}

console.log(User.prototype.constructor === User) // true
```

实例能通过原型链访问到 `constructor`：

```javascript
const user = new User()
console.log(user.constructor === User) // true
```

但不要在业务逻辑中过度依赖 `obj.constructor` 判断类型，因为它可以被改写，跨 iframe、代理对象、混入对象也可能让判断变复杂。

## class 方法不能作为构造器

```javascript
class User {
  create() {}
}

const method = User.prototype.create
new method()
```

会抛：

```text
TypeError
```

class 体里的普通方法没有 `[[Construct]]`，不能被 `new` 调用。

## 原型链查找

```javascript
class User {
  sayHi() {
    return 'hi'
  }
}

const user = new User()
```

访问 `user.sayHi` 时：

1. 先查 `user` 自己有没有 `sayHi`。
2. 没有就查 `User.prototype`。
3. 再没有就查 `Object.prototype`。
4. 再没有就是 `undefined`。

可以验证：

```javascript
console.log(Object.getPrototypeOf(user) === User.prototype) // true
console.log(Object.getPrototypeOf(User.prototype) === Object.prototype) // true
```

## 覆盖原型方法

实例可以创建同名自有属性，遮蔽原型方法：

```javascript
class User {
  sayHi() {
    return 'prototype'
  }
}

const user = new User()
user.sayHi = function () {
  return 'own'
}

console.log(user.sayHi()) // 'own'
console.log(User.prototype.sayHi.call(user)) // 'prototype'
```

这种写法有时用于测试或局部改写，但业务代码里要谨慎。它会让实例行为不一致。

## 修改 prototype 的风险

```javascript
class User {
  sayHi() {
    return 'hi'
  }
}

User.prototype.sayHi = function () {
  return 'changed'
}
```

所有已有实例和未来实例都会受到影响，因为它们共享同一个原型方法。

```javascript
const before = new User()
User.prototype.sayHi = () => 'changed'
const after = new User()

console.log(before.sayHi()) // 'changed'
console.log(after.sayHi()) // 'changed'
```

这也是为什么不要在业务代码里随意 monkey patch 原型。
