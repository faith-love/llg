# 状态管理副作用与生命周期

库内部通常需要管理状态，例如配置、缓存、订阅者、任务队列、实例生命周期。状态越多，越容易出现顺序问题和内存泄漏。高级库设计要把状态和副作用显式化。

## 状态分类

| 状态 | 示例 | 管理方式 |
| --- | --- | --- |
| 配置状态 | options、defaults | 初始化后尽量不可变 |
| 运行状态 | loading、connected、disposed | 状态机 |
| 缓存状态 | memo cache、request cache | TTL、容量、清理 |
| 订阅状态 | listeners、watchers | subscribe/unsubscribe |
| 任务状态 | queue、pending tasks | 调度器 |

不同状态不要混在一个巨大对象里。

## 可变和不可变

库内部可以使用可变结构提升性能，但 public API 尽量避免让使用者直接修改内部状态。

```typescript
class Store<T> {
  private state: T

  getState() {
    return this.state
  }

  setState(next: T) {
    this.state = next
    this.notify()
  }
}
```

如果返回对象可能被外部修改，要考虑冻结、拷贝或文档约束。

## 生命周期

库实例通常需要生命周期：

```text
created -> started -> running -> disposed
```

示例：

```typescript
const client = createClient()
client.start()
client.dispose()
```

`dispose` 很重要，它负责清理：

- 事件监听。
- 定时器。
- pending request。
- cache。
- DOM 引用。
- worker。

## 副作用边界

副作用包括：

- 网络请求。
- DOM 操作。
- localStorage。
- 定时器。
- 事件监听。
- 日志上报。

核心逻辑尽量保持纯，副作用放到 adapter 或 runtime 层：

```text
core 计算应该做什么
adapter 真正执行外部副作用
```

这样测试会简单很多。

## 订阅模型

订阅 API 要返回取消函数：

```typescript
const unsubscribe = store.subscribe((state) => {
  console.log(state)
})

unsubscribe()
```

这比单独提供 `removeListener(fn)` 更不容易用错。

## 防止内存泄漏

检查这些地方：

- 监听器是否可取消。
- dispose 是否幂等。
- 定时器是否清理。
- 缓存是否有容量或过期策略。
- 异步回调是否在实例销毁后仍然 setState。

## 自检清单

- 状态是否分类清楚？
- 核心逻辑是否和副作用解耦？
- 实例是否有 dispose？
- dispose 是否可以重复调用？
- 订阅是否返回 unsubscribe？
- 缓存和任务队列是否有清理策略？

## 知识点展开与对应练习

| 知识点 | 小点展开 | 对应练习 | 验收标准 |
| --- | --- | --- | --- |
| 状态分类 | 配置、运行、缓存、订阅、任务状态要分开管理 | 为 `mini-request` 列出 5 类状态 | 每类状态都说明存放位置、读写者和清理时机 |
| 不可变配置 | 初始化配置尽量不可变，避免运行中被外部改坏 | 实现 `resolveOptions` 后冻结或拷贝配置 | 外部修改原始 options 不影响 client 内部配置 |
| 生命周期 | 实例要有 created、running、disposed 等状态 | 给 client 增加 `dispose()` 和 `isDisposed()` | dispose 后再次 request 会得到明确错误 |
| 副作用边界 | 网络、DOM、storage、timer 都应放在 runtime 或 adapter 层 | 把一个使用 `localStorage` 的功能改成 storage adapter | core 可以用 memory storage 测试 |
| 订阅模型 | subscribe 返回 unsubscribe，降低移除监听器出错概率 | 实现 `subscribe(listener)` | unsubscribe 后 listener 不再触发，重复 unsubscribe 不报错 |
| 内存泄漏 | 定时器、listener、pending task、cache 都要清理 | 给 client 写一组 dispose 清理测试 | dispose 后 listener 数量、pending 数量、timer 数量为 0 |
| 状态机 | 用状态联合类型限制非法状态 | 实现 request task 的 idle/loading/success/error/canceled 状态 | 类型上不能同时存在 success data 和 error |
