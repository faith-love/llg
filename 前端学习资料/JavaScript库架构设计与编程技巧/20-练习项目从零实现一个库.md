# 练习项目：从零实现一个库

这个练习用一个轻量请求库串起 JS 库设计能力。目标不是替代 Axios，而是通过一个足够真实的小项目，练习 API、核心模型、插件机制、adapter、异步、错误、类型、构建、测试和文档。

## 项目目标

实现一个 `mini-request`：

```typescript
const client = createClient({
  baseURL: 'https://api.example.com',
  timeout: 5000,
  plugins: [retry({ times: 2 }), logger()]
})

const user = await client.get<User>('/users/1')
```

## 阶段一：定位和 API

任务：

- 写 README 定位。
- 定义 goals 和 non-goals。
- 设计 `createClient`、`client.get`、`client.request`。
- 设计 options 和返回值。

验收：

- 最小示例能说明库价值。
- API 不依赖具体业务。
- 参数和返回值有 TypeScript 类型。

## 阶段二：核心模型

任务：

- 定义 `RequestConfig`、`NormalizedRequest`、`Response`、`RequestError`。
- 实现配置归一化。
- 实现 URL、headers、method 标准化。

验收：

- 外部简写输入能转成内部统一模型。
- 核心逻辑不依赖 fetch。
- 单元测试覆盖配置边界。

## 阶段三：adapter

任务：

- 定义 `Adapter` 接口。
- 实现 `fetchAdapter`。
- 实现 `mockAdapter` 用于测试。

验收：

- core 只依赖 adapter 接口。
- 测试不需要真实网络。
- 未来可以加 Node adapter。

## 阶段四：插件和中间件

任务：

- 实现插件注册。
- 设计 `onRequest`、`onResponse`、`onError` hook。
- 实现 logger 插件。
- 实现 retry 插件。

验收：

- 插件顺序可预测。
- 插件不能直接修改所有内部状态。
- retry 能配置次数和 delay。

## 阶段五：取消、超时和错误

任务：

- 支持 `AbortSignal`。
- 支持 timeout。
- 设计错误码。
- 提供 debug logger。

验收：

- 取消后 promise 正确 reject。
- timeout 错误有明确 code。
- 错误 message 能指导修复。

## 阶段六：缓存和并发

任务：

- 实现同 key pending 去重。
- 实现可选内存缓存。
- 支持 TTL。

验收：

- 并发相同请求只执行一次 adapter。
- 缓存过期后重新请求。
- dispose 能清理缓存和 pending。

## 阶段七：构建和发布

任务：

- 输出 ESM。
- 输出 `.d.ts`。
- 配置 package exports。
- 标记 sideEffects。

验收：

- TypeScript 能识别类型。
- 构建产物不包含测试代码。

## 阶段八：测试和文档

任务：

- 单元测试核心模型。
- 契约测试 public API。
- 类型测试泛型推断。
- 构建产物测试。

## 最终验收清单

## Public API 规格

最终至少实现这些 API：

| API | 作用 | 练习重点 |
| --- | --- | --- |
| `createClient(options)` | 创建请求客户端实例 | options 设计、默认值、生命周期 |
| `client.request(config)` | 完整请求入口 | config 归一化、pipeline、adapter |
| `client.get<T>(url, options)` | GET 快捷方式 | 泛型推断、返回类型 |
| `client.post<T>(url, body, options)` | POST 快捷方式 | body 标准化 |
| `client.use(plugin)` | 注册插件 | 插件顺序和 cleanup |
| `client.dispose()` | 销毁实例 | 清理 pending、listener、cache、timer |
| `retry(options)` | 重试插件 | 策略模式、取消、错误分类 |
| `logger(options)` | 日志插件 | debug 和 logger 注入 |
| `cache(options)` | 缓存插件 | key、TTL、容量 |

API 验收：

- 每个 public API 都有 TypeScript 类型。
- 每个 public API 都有 README 示例。
- 每个 public API 都有契约测试。
- 每个 public API 都说明错误行为。

## 核心类型规格

建议定义这些 public 类型：

```typescript
export type ClientOptions = {
  baseURL?: string
  timeout?: number
  headers?: Record<string, string>
  debug?: boolean
  adapter?: Adapter
  plugins?: Plugin[]
  logger?: Logger
}

export type RequestConfig = {
  url: string
  method?: HttpMethod
  headers?: Record<string, string>
  body?: unknown
  timeout?: number
  signal?: AbortSignal
  meta?: Record<string, unknown>
}

export type Response<T> = {
  status: number
  headers: Record<string, string>
  data: T
  config: RequestConfig
  duration: number
}

export type Adapter = (
  request: NormalizedRequest
) => Promise<Response<unknown>>
```

类型验收：

- `client.get<User>()` 能推断为 `Promise<User>` 或 `Promise<Response<User>>`，二者选一种并保持一致。
- 插件作者能拿到必要 public 类型。
- 内部 `NormalizedRequest` 不从主入口导出，除非你决定它是 adapter 契约。
- 类型测试覆盖成功响应、错误响应、插件 options 和 adapter。

## 分阶段里程碑

### M1：最小可用

目标：

- `createClient` 可创建实例。
- `client.get` 能通过 mock adapter 返回数据。
- README 有最小示例。

验收命令：

```bash
pnpm test
pnpm build
```

### M2：稳定核心

目标：

- config normalize 完整。
- 错误码可用。
- timeout 和 abort 可用。
- dispose 可用。

验收：

- 取消请求会得到 `ABORTED`。
- 超时请求会得到 `TIMEOUT`。
- dispose 后不能继续 request。

### M3：扩展体系

目标：

- plugin container 可用。
- logger、retry、cache 插件可用。
- middleware 顺序可调试。

验收：

- 插件执行顺序有测试。
- retry 不重试 4xx。
- cache 命中时不调用 adapter。

### M4：工程发布

目标：

- ESM 产物。
- `.d.ts` 产物。
- package exports。
- README、CHANGELOG、errors 文档。

验收：

- example 项目能从 dist import。
- TypeScript 能识别类型。

### M5：质量完善

目标：

- 契约测试覆盖 public API。
- 类型测试覆盖泛型推断。
- benchmark 覆盖 normalize 和 pipeline。
- 回归测试覆盖已知 bug。

验收：

- 每个 public API 至少 1 个契约测试。
- 每个错误码至少 1 个触发测试。
- benchmark 输出基础数据。

## 进阶挑战

- 实现 `client.createScope(options)`，生成继承父配置的子 client。
- 实现 `onProgress`，支持上传或下载进度。
- 实现请求队列，支持 `priority` 和 `concurrency`。
- 实现 `cachePlugin` 的 stale-while-revalidate 策略。
- 实现 `devtoolsPlugin`，记录最近 100 次请求。
- 实现 `schemaPlugin`，用 schema 校验响应数据。
- 实现 `nodeAdapter`，支持 Node 环境。
- 实现 `codemod`，把 v1 的 `initClient` 迁移到 v2 的 `createClient`。
