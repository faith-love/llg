# 性能设计缓存懒加载与批处理

库的性能问题会被所有使用者放大。一个库如果初始化慢、包体大、运行时频繁分配对象或触发大量回调，会在各种项目里成为隐性成本。

## 性能关注点

| 指标 | 说明 |
| --- | --- |
| 包体 | 安装和下载成本 |
| 初始化 | import 或 create 时的成本 |
| 运行时 | 每次调用的 CPU 和内存 |
| 分配 | 是否创建大量临时对象 |
| 订阅通知 | 是否重复通知或同步阻塞 |
| 异步调度 | 是否制造过多微任务或宏任务 |

## Tree-shaking 友好

库要避免顶层副作用：

```typescript
// 不推荐：import 时就执行副作用
initGlobalListener()

// 推荐：使用者显式启动
export function start() {
  initGlobalListener()
}
```

还要优先使用 ESM，并正确配置 `sideEffects`。

## 懒加载

把低频能力延后加载：

```typescript
async function loadDevtools() {
  const { createDevtools } = await import('./devtools')
  return createDevtools()
}
```

适合：

- devtools。
- 大型解析器。
- 可选 adapter。
- 低频插件。

不要把所有东西都放进核心入口。

## 缓存

缓存要回答：

- key 怎么生成？
- value 多久过期？
- 最大容量是多少？
- 什么时候清理？
- 错误结果是否缓存？
- 并发时是否复用 pending？

简单 memo：

```typescript
function memoize<TArgs extends unknown[], TResult>(
  fn: (...args: TArgs) => TResult
) {
  const cache = new Map<string, TResult>()

  return (...args: TArgs) => {
    const key = JSON.stringify(args)
    if (cache.has(key)) return cache.get(key) as TResult

    const result = fn(...args)
    cache.set(key, result)
    return result
  }
}
```

真实库中要谨慎使用 `JSON.stringify` 做 key，因为对象顺序和循环引用会有问题。

## 批处理

批处理可以减少重复通知：

```typescript
let scheduled = false

function scheduleFlush() {
  if (scheduled) return
  scheduled = true

  queueMicrotask(() => {
    scheduled = false
    flush()
  })
}
```

适合状态库、日志上报、DOM 更新、请求合并。

## 性能测试

不要只凭感觉优化。可以建立 benchmark：

```text
初始化 1000 个实例
执行 10000 次 parse
注册和触发 10000 个 listener
构建产物 gzip/brotli 体积
```

优化前后要有数据。

## 自检清单

- import 是否有顶层副作用？
- 低频能力是否能拆成子入口或动态加载？
- 缓存是否有清理策略？
- 订阅通知是否能批处理？
- 是否有 benchmark 或包体检查？
- 优化是否破坏 API 和可读性？

## 知识点展开与对应练习

| 知识点 | 小点展开 | 对应练习 | 验收标准 |
| --- | --- | --- | --- |
| 包体 | 核心入口要小，低频能力拆子入口或插件 | 把 devtools、mock、retry 拆成子路径导出 | `import { createClient }` 不包含 devtools 代码 |
| 顶层副作用 | import 时不应自动注册全局监听或启动任务 | 找出并改写 3 个顶层副作用示例 | 所有副作用都改成显式 `start()` 或 plugin setup |
| 懒加载 | 低频能力可以动态 import | 实现 `loadDevtools()` | devtools 代码只在调用时加载 |
| 缓存 key | 缓存要明确 key、TTL、容量和错误缓存策略 | 实现 `createCache({ ttl, maxSize })` | 支持过期、容量淘汰、手动清理 |
| 批处理 | 多次同步更新可以合并成一次通知 | 实现 `scheduleFlush()` | 同一 tick 内多次 setState 只通知一次 |
| benchmark | 性能优化要有数据 | 写一个 benchmark：执行 10000 次 normalize | 输出优化前后耗时，不只凭感觉 |
| 体积预算 | 发布前检查 gzip/brotli 体积 | 给库设置核心包体预算 | 超过预算需要说明原因或拆包 |
