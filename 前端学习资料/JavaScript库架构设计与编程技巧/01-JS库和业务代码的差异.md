# JS 库和业务代码的差异

业务代码面对的是明确需求，库代码面对的是不确定使用场景。业务代码可以为了当前页面快速调整，库代码一旦发布，API、行为、错误信息和类型就会成为使用者依赖的契约。

## 核心差异

| 维度 | 业务代码 | 库代码 |
| --- | --- | --- |
| 使用者 | 同团队或同项目 | 不确定团队、项目、运行环境 |
| 变更成本 | 可跟随业务一起改 | public API 改动可能是 breaking change |
| 设计重点 | 快速交付需求 | 稳定契约、组合能力、兼容性 |
| 错误处理 | 可依赖业务上下文 | 必须给出清晰错误和调试信息 |
| 测试重点 | 业务流程 | API 契约、边界、兼容、回归 |
| 文档要求 | 内部约定可补充 | 文档就是产品的一部分 |

## 库代码要少假设

业务代码可以假设当前项目使用 React、当前接口返回结构固定、当前浏览器范围已知。库代码要谨慎得多：

- 不要假设使用者的构建工具。
- 不要假设全局变量存在。
- 不要假设 DOM 一定可用。
- 不要假设调用顺序总是正确。
- 不要假设配置一定完整。
- 不要假设使用者会读源码。

库要通过 API、类型、默认值、错误提示和文档让正确用法更容易。

## Public API 是契约

一旦暴露，使用者就可能依赖：

```typescript
export function createStore(options: StoreOptions): Store
```

这些都属于契约：

- 函数名。
- 参数结构。
- 默认值。
- 返回值。
- 错误类型。
- 异步时机。
- 副作用。
- 类型推断。

内部实现可以随时改，public API 要尽量稳定。

## 稳定性优先于聪明实现

库代码不追求“最短写法”，而追求：

- 行为可预测。
- 边界清晰。
- 错误可定位。
- 组合不冲突。
- 类型能表达真实约束。
- 内部复杂度可维护。

例如一个简单工具函数，也要考虑输入边界：

```typescript
export function clamp(value: number, min: number, max: number) {
  if (min > max) {
    throw new Error('clamp: min should not be greater than max')
  }

  return Math.min(Math.max(value, min), max)
}
```

## 什么时候不应该抽成库

不要看到重复代码就立刻抽库。适合抽库的信号：

- 逻辑在多个项目稳定复用。
- API 边界能清晰定义。
- 有明确 owner 维护。
- 变更频率不完全跟随单一业务。
- 能写出测试和文档。

不适合抽库：

- 业务还在快速试错。
- 重复只是表面重复，领域语义不同。
- 抽出来后仍然频繁被业务细节污染。
- 没有人维护版本和文档。

## 写库的基本原则

```text
先定义问题，再设计 API
先保证可理解，再追求灵活
先稳定核心，再开放扩展
先测试契约，再优化实现
```

如果一个库需要使用者理解大量内部细节才能正确使用，说明 API 设计还没有完成。

## 知识点展开与对应练习

| 知识点 | 小点展开 | 对应练习 | 验收标准 |
| --- | --- | --- | --- |
| 使用者差异 | 业务代码面向当前项目，库代码面向未知项目、未知构建工具和未知运行环境 | 把一个业务工具函数改写成库函数，移除所有项目专属假设 | 不能依赖项目全局变量、业务接口、固定框架或固定目录 |
| 契约意识 | 函数名、参数、返回值、错误、默认值、异步时机都会成为契约 | 为 `createClient(options)` 写一份契约说明 | 说明必须包含默认值、错误情况、是否有副作用和兼容承诺 |
| 少假设原则 | 库不能假设 DOM、window、fetch、localStorage 一定存在 | 写一个 `getRuntime()` 判断当前运行环境 | 能区分 browser、node、unknown，并且不在 Node 中直接访问 `window` |
| 稳定性 | 库代码要可预测、可测试、可升级，不能只追求短代码 | 给 `clamp`、`parseJSON`、`safeGet` 各写一个边界用例 | 每个函数至少覆盖正常值、异常值和错误提示 |
| 抽库判断 | 重复代码不一定值得抽库，要看边界、复用、owner 和维护成本 | 从当前项目中找 3 段重复逻辑，判断是否适合抽库 | 每段都写出“适合/不适合”的理由和后续成本 |
| 文档优先 | 库的正确用法不能只藏在源码里 | 为一个小工具库写 README 的第一屏 | 包含定位、安装、最小示例和不适用场景 |
