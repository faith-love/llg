# 异步并发取消重试与调度

很多库的复杂度来自异步：请求会并发、任务会取消、结果会乱序、重试会放大流量、超时会和取消冲突。异步设计要显式处理这些问题，而不是只写 `await`。

## 异步风险

| 风险 | 现象 |
| --- | --- |
| 竞态 | 后发请求先返回，覆盖新状态 |
| 泄漏 | 实例销毁后异步回调仍执行 |
| 重复 | 同一任务并发执行多次 |
| 雪崩 | 重试同时触发，放大流量 |
| 卡死 | promise 永远 pending |
| 取消不彻底 | 外层取消了，底层请求还在跑 |

## 取消

现代 JS 常用 `AbortController`：

```typescript
const controller = new AbortController()

fetch('/api/users', {
  signal: controller.signal
})

controller.abort()
```

库 API 可以接收 signal：

```typescript
client.get('/users', {
  signal: controller.signal
})
```

内部也可以组合超时取消。

## 请求去重

对于相同 key 的请求，可以复用 pending promise：

```typescript
const pending = new Map<string, Promise<unknown>>()

function dedupe<T>(key: string, task: () => Promise<T>) {
  if (pending.has(key)) return pending.get(key) as Promise<T>

  const promise = task().finally(() => {
    pending.delete(key)
  })

  pending.set(key, promise)
  return promise
}
```

适合配置加载、字典数据、schema 拉取等场景。

## 重试

重试必须有边界：

- 最大次数。
- 间隔策略。
- 是否只重试幂等请求。
- 是否遇到 4xx 直接失败。
- 是否支持取消。
- 是否加入随机抖动。

```typescript
type RetryOptions = {
  times: number
  delay: (attempt: number) => number
  shouldRetry: (error: unknown) => boolean
}
```

不要无条件重试所有错误。

## 并发限制

大量任务可以用队列限制并发：

```typescript
class TaskQueue {
  private running = 0
  private queue: Array<() => void> = []

  constructor(private limit: number) {}
}
```

适合上传、批量请求、图片处理、预加载。

## 调度

调度要考虑优先级：

| 任务 | 优先级 |
| --- | --- |
| 用户当前交互 | 高 |
| 首屏关键数据 | 高 |
| 预加载 | 中 |
| 日志上报 | 低 |
| 缓存清理 | 低 |

库可以把低优先级任务延后，避免阻塞用户关键路径。

## 自检清单

- API 是否支持取消？
- 取消后底层副作用是否真的停止？
- 是否处理请求乱序？
- 重试是否有最大次数和退避策略？
- 并发是否可能压垮服务？
- 实例销毁后 pending task 如何处理？

## 知识点展开与对应练习

| 知识点 | 小点展开 | 对应练习 | 验收标准 |
| --- | --- | --- | --- |
| 竞态 | 后发请求可能先返回，要用 requestId 或 abort 处理乱序 | 模拟搜索输入连续请求 | 只有最后一次请求结果能更新状态 |
| 取消 | `AbortSignal` 是取消异步任务的通用契约 | 为 `client.get` 支持外部 signal | 调用 abort 后 adapter 收到取消，promise reject 为取消错误 |
| 超时 | timeout 本质是内部 AbortController 和 timer 协作 | 实现 `timeout: 1000` | 超时后清理 timer，并返回 `TIMEOUT` 错误码 |
| 去重 | 同 key pending 请求复用同一个 promise | 实现 pending dedupe | 并发 3 次相同 key，adapter 只执行 1 次 |
| 重试 | 重试要限制次数、错误类型、间隔和取消 | 实现 retry plugin | 5xx 会重试，4xx 不重试，abort 后停止重试 |
| 并发限制 | 批量任务需要 queue 控制并发 | 实现 `TaskQueue(limit)` | limit=2 时同时运行任务不超过 2 个 |
| 调度优先级 | 用户交互任务优先于预加载和日志 | 设计 high/normal/low 三档任务队列 | 高优先级任务能先于低优先级任务执行 |
