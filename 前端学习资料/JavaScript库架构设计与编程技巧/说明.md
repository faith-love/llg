# JavaScript 库架构设计与编程技巧

这个专题面向想从“会写业务代码”升级到“能设计一个可复用 JavaScript/TypeScript 库”的前端工程师。重点不是堆语法技巧，而是理解一个库如何定义边界、设计 API、组织核心模型、暴露扩展点、处理副作用、保证类型质量、构建产物、测试兼容性并长期维护。

## 先说结论

写库和写业务代码的思维不同。

```text
业务代码优先完成需求
库代码优先定义稳定契约、扩展边界和长期兼容
```

一个好库不是“代码很聪明”，而是让使用者少犯错、容易理解、容易组合、容易调试、容易升级，并且在复杂场景下仍然可预测。

## 学习目标

- 能判断一个逻辑是否值得抽成库。
- 能设计稳定、清晰、可演进的 public API。
- 能区分 core、adapter、plugin、runtime、types、utils 的职责。
- 能设计插件机制、hook 系统、事件系统和中间件管道。
- 能处理状态、副作用、生命周期、异步、取消、重试和调度。
- 能设计错误码、调试信息、日志和开发者体验。
- 能用函数式、面向对象、组合式和策略模式解决真实问题。
- 能写出 tree-shaking 友好、类型友好、测试友好的库。
- 能设计构建产物、模块格式、package exports 和版本策略。
- 能通过源码阅读理解 React Query、Redux、Axios、Lodash、Zod、Vite 插件等库的设计思想。

## 推荐阅读顺序

1. 先读 `00-03`，建立写库的边界意识和 API 设计意识。
2. 再读 `04-08`，理解核心模型、模块分层、扩展机制和生命周期。
3. 接着读 `09-11`，处理异步、错误、调试和性能。
4. 然后读 `12-15`，补齐编程范式、类型设计和构建发布。
5. 最后读 `16-20`，通过测试、文档、源码阅读、反模式和练习项目落地。

## 练习方式

每篇文档都补充了 `知识点展开与对应练习`。阅读时不要只看概念，建议按这个节奏执行：

1. 先读本章概念，确认它解决什么库设计问题。
2. 再看表格里的每个小点，理解它在真实库中的风险。
3. 逐个完成对应练习，至少写出代码、类型或设计文档。
4. 用验收标准自测，不满足就回到设计重新调整。
5. 最后把本章练习合并到 [练习项目：从零实现一个库](20-练习项目从零实现一个库.md)。
