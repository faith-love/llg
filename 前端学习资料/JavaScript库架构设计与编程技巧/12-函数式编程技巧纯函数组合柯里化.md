# 函数式编程技巧纯函数组合柯里化

函数式编程在库设计中很有价值，因为它强调输入输出、组合和副作用隔离。不是所有库都要写成函数式风格，但纯函数、组合、柯里化、不可变更新等技巧能显著降低核心逻辑复杂度。

## 纯函数

纯函数只依赖输入，不修改外部状态：

```typescript
function add(a: number, b: number) {
  return a + b
}
```

适合放在 core 层。纯函数的好处：

- 容易测试。
- 容易组合。
- 容易缓存。
- 不依赖运行环境。

## 副作用外移

```typescript
// core
function buildRequest(config: RequestConfig): NormalizedRequest {
  return normalize(config)
}

// adapter
async function send(request: NormalizedRequest) {
  return fetch(request.url, request)
}
```

核心负责计算，adapter 负责副作用。

## 函数组合

```typescript
const normalizeRequest = pipe(
  withDefaultMethod,
  normalizeHeaders,
  resolveURL,
  validateRequest
)
```

组合可以把复杂流程拆成可测试的小步骤。

## 柯里化

柯里化适合预先固定一部分参数：

```typescript
function withBaseURL(baseURL: string) {
  return function resolve(path: string) {
    return new URL(path, baseURL).toString()
  }
}

const resolveAPI = withBaseURL('https://api.example.com')
resolveAPI('/users')
```

在库中常用于创建定制化函数或策略。

## 高阶函数

高阶函数接收函数或返回函数：

```typescript
function withTiming<TArgs extends unknown[], TResult>(
  fn: (...args: TArgs) => TResult
) {
  return (...args: TArgs) => {
    const start = performance.now()
    const result = fn(...args)
    console.log(performance.now() - start)
    return result
  }
}
```

适合日志、缓存、权限、错误包装。

## 不可变更新

```typescript
function setHeader(config: RequestConfig, key: string, value: string) {
  return {
    ...config,
    headers: {
      ...config.headers,
      [key]: value
    }
  }
}
```

不可变更新更容易追踪变化，但深层对象频繁拷贝有性能成本。库内部可以在性能热点使用可变结构，但要避免暴露给使用者。

## 自检清单

- core 逻辑是否尽量纯？
- 副作用是否集中到 adapter/runtime？
- 流程能否拆成小函数组合？
- 高阶函数是否让逻辑更清晰，而不是更难读？
- 不可变更新是否带来过度拷贝？
- 是否为了函数式而牺牲可理解性？

## 知识点展开与对应练习

| 知识点 | 小点展开 | 对应练习 | 验收标准 |
| --- | --- | --- | --- |
| 纯函数 | 输入相同输出相同，不读写外部状态 | 把 `normalizeConfig` 写成纯函数 | 不访问全局变量，不修改入参，单测可直接断言输出 |
| 副作用外移 | core 只计算，adapter/runtime 执行副作用 | 把 fetch 调用从核心流程移到 adapter | core 测试不需要 mock 全局 fetch |
| 函数组合 | 把大流程拆成小 transform，按顺序组合 | 实现 `pipe(withDefaults, resolveURL, validate)` | 每个 transform 都能单独测试 |
| 柯里化 | 先固定一部分参数，生成特定场景函数 | 实现 `withBaseURL(baseURL)` | 返回函数能解析相对路径，且不依赖外部可变状态 |
| 高阶函数 | 用函数包装函数，增加日志、缓存、错误处理 | 实现 `withTiming(fn)` 和 `withErrorBoundary(fn)` | 原函数返回值和 this 行为不被破坏 |
| 不可变更新 | 避免外部对象被内部意外修改 | 实现 `setHeader(config, key, value)` | 返回新对象，原 config.headers 不变 |
| 取舍 | 函数式不是目的，过度抽象会降低可读性 | 重构一个 50 行流程函数为 5 个小函数 | 新版本可读性提高，测试覆盖每个小函数 |
