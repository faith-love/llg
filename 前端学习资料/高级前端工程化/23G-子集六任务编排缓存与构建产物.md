# 子集六：任务编排、缓存与构建产物

这一节把 monorepo 从“目录集合”升级为“任务图”。核心是让每个任务知道依赖谁、输入是什么、输出是什么。

## 根 turbo.json

`turbo.json`：

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "dev": {
      "cache": false,
      "persistent": true
    },
    "lint": {
      "outputs": []
    },
    "typecheck": {
      "outputs": []
    },
    "test": {
      "outputs": ["coverage/**"]
    },
    "build": {
      "dependsOn": ["^build"],
      "inputs": [
        "$TURBO_DEFAULT$",
        ".env*",
        "tsconfig*.json",
        "vite.config.ts"
      ],
      "outputs": ["dist/**"]
    }
  }
}
```

## package 构建脚本

应用：

```json
{
  "scripts": {
    "dev": "vite --host 0.0.0.0",
    "lint": "eslint .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run --passWithNoTests",
    "build": "vite build"
  }
}
```

库：

```json
{
  "scripts": {
    "lint": "eslint .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run --passWithNoTests",
    "build": "vite build && tsc --emitDeclarationOnly"
  }
}
```

配置包：

```json
{
  "scripts": {
    "lint": "eslint .",
    "typecheck": "echo config package has no typecheck",
    "test": "echo config package has no tests",
    "build": "echo config package has no build"
  }
}
```

## 库构建配置

`packages/api-client/vite.config.ts`：

```typescript
import { defineConfig } from 'vite'

export default defineConfig({
  build: {
    lib: {
      entry: 'src/index.ts',
      formats: ['es'],
      fileName: 'index'
    }
  }
})
```

`packages/api-client/package.json`：

```json
{
  "name": "@acme/api-client",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "sideEffects": false,
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "vite build && tsc --emitDeclarationOnly"
  }
}
```

## 任务图理解

当执行：

```bash
pnpm build
```

期望任务顺序：

```text
@acme/shared:build
  -> @acme/ui:build
  -> admin:build
  -> portal:build

@acme/api-client:build
  -> admin:build
  -> portal:build
```

原因是应用依赖这些包，`build.dependsOn = ["^build"]` 会先构建依赖包。

## 缓存验证

第一次：

```bash
pnpm build
```

第二次：

```bash
pnpm build
```

第二次应该看到 cache hit。

修改 `packages/ui/src/button/Button.tsx` 后：

```bash
pnpm build
```

应该重新执行：

- `@acme/ui:build`
- 依赖 `@acme/ui` 的 app build

## affected 构建

根脚本：

```json
{
  "scripts": {
    "affected:build": "turbo build --filter=...[HEAD^1]"
  }
}
```

练习：

```bash
git add .
git commit -m "chore: baseline"

# 修改 packages/shared
pnpm affected:build
```

## 产物检查

每个库构建后检查：

```text
packages/api-client/dist/index.js
packages/api-client/dist/index.d.ts
packages/ui/dist/index.js
packages/ui/dist/index.d.ts
```

应用构建后检查：

```text
apps/admin/dist/
apps/portal/dist/
```

## 验收标准

- `pnpm build` 能全量构建。
- 第二次 `pnpm build` 能命中缓存。
- `build` 任务声明了 `outputs`。
- 修改共享包能影响依赖它的 app。
- 库包输出 ESM 和 `.d.ts`。
- 应用产物在 `dist`。
