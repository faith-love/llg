# 页面服务编排、状态加载、错误与权限接入

这一页拆页面如何接入服务。页面层可以组合请求、权限、UI 和状态，但不要把请求客户端、权限算法写死在页面内部。

## 步骤一：把应用服务集中创建

`apps/admin/src/app/services.ts`：

```typescript
import { createClient, createMockAdapter } from '@acme/api-client'
import { createAdminSession } from '@acme/auth'
import { createFeatureFlags } from '@acme/feature-flags'

export const session = createAdminSession()

export const api = createClient({
  baseURL: 'http://localhost',
  adapter: createMockAdapter({
    'GET /users': [
      { id: 'u1', name: 'Ada', status: 'active' },
      { id: 'u2', name: 'Linus', status: 'disabled' }
    ]
  })
})

export const flags = createFeatureFlags({
  newUserTable: {
    defaultValue: false,
    rollout: 50
  }
})
```

代码说明：

- 页面不直接 new client。
- 服务集中创建，后续替换 mock adapter、baseURL、runtime config 更容易。
- `session`、`api`、`flags` 是应用级服务，不是组件内部状态。

## 步骤二：页面 service 封装业务请求

`apps/admin/src/pages/users/users.types.ts`：

```typescript
export type User = {
  id: string
  name: string
  status: 'active' | 'disabled'
}
```

`apps/admin/src/pages/users/users.service.ts`：

```typescript
import { api } from '../../app/services'
import type { User } from './users.types'

export function listUsers() {
  return api.get<User[]>('/users')
}
```

解释：

- `api-client` 只知道 HTTP，不知道“用户列表”。
- `users.service.ts` 把业务接口语义补上。
- 页面只调用 `listUsers()`，不拼 URL。

## 步骤三：页面处理加载和错误

`apps/admin/src/pages/users/UsersPage.tsx`：

```typescript
import { useEffect, useState } from 'react'
import { DataTable, StatusBadge } from '@acme/ui'
import { listUsers } from './users.service'
import type { User } from './users.types'

type LoadState =
  | { status: 'loading' }
  | { status: 'success'; users: User[] }
  | { status: 'error'; message: string }

export function UsersPage() {
  const [state, setState] = useState<LoadState>({ status: 'loading' })

  useEffect(() => {
    let ignore = false

    listUsers()
      .then((users) => {
        if (!ignore) setState({ status: 'success', users })
      })
      .catch((error: unknown) => {
        if (!ignore) setState({ status: 'error', message: String(error) })
      })

    return () => {
      ignore = true
    }
  }, [])

  if (state.status === 'loading') return <p>Loading users...</p>
  if (state.status === 'error') return <p role="alert">{state.message}</p>

  return (
    <section>
      <h2>Users</h2>
      <DataTable
        rows={state.users}
        getRowKey={(row) => row.id}
        columns={[
          { key: 'name', title: 'Name', render: (row) => row.name },
          { key: 'status', title: 'Status', render: (row) => <StatusBadge status={row.status} /> }
        ]}
      />
    </section>
  )
}
```

代码说明：

- `LoadState` 用联合类型表达 loading、success、error，避免多个 boolean 状态互相矛盾。
- `ignore` 避免组件卸载后继续 setState。
- 页面只组合 `listUsers`、`DataTable`、`StatusBadge`。

## 步骤四：权限接入

`apps/admin/src/pages/flags/FlagsPage.tsx`：

```typescript
import { hasPermission } from '@acme/auth'
import { session } from '../../app/services'

export function FlagsPage() {
  if (!hasPermission(session, 'flags:read')) {
    return <p role="alert">You do not have permission to view feature flags.</p>
  }

  return (
    <section>
      <h2>Feature Flags</h2>
      <p>Flag management will be implemented later.</p>
    </section>
  )
}
```

权限判断来自 `@acme/auth`，页面只决定 UI 展示。不要在页面里手写 `session.role === 'admin'`，否则权限规则会散落各处。

## 练习

1. 给 `tickets` 页面也创建 `tickets.service.ts` 和 `tickets.types.ts`。
2. 页面用联合类型管理 loading、success、error。
3. 给 `flags` 页面加权限保护。
4. 把 mock 数据从页面移到 `services.ts`。

## 验收

- 页面不直接调用 `fetch`。
- 页面不直接拼接 API baseURL。
- 权限算法不写在页面内部。
- loading、error、success 状态互斥。
- 页面目录里能看出业务域边界。
