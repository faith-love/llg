# 设计系统组件库与工程化发布

组件库不是一组漂亮组件，设计系统也不是一个 UI 包。成熟的设计系统包含设计 token、组件规范、交互状态、可访问性、文档、测试、版本发布和治理机制。组件库只是它的工程实现之一。

## 设计系统组成

| 部分 | 内容 |
| --- | --- |
| Design Token | 色彩、字体、间距、圆角、阴影、动效 |
| 基础组件 | Button、Input、Modal、Select、Table |
| 业务组件 | 用户选择器、权限树、上传面板 |
| 文档站 | 使用方式、API、示例、设计规范 |
| 测试体系 | 单测、交互测试、视觉回归、可访问性 |
| 发布体系 | 版本、changelog、兼容策略、迁移指南 |

## 包结构

```text
packages/ui/
  src/
    button/
    input/
    modal/
    theme/
  package.json
  tsconfig.json
  vite.config.ts
```

对外导出要稳定：

```typescript
export { Button } from './button'
export type { ButtonProps } from './button'
```

避免消费者直接引用内部路径，否则重构会变成 breaking change。

## 组件 API 设计

一个好组件 API 应该：

- 命名稳定。
- 类型明确。
- 默认行为合理。
- 支持受控和非受控场景。
- 暴露必要扩展点。
- 不把内部实现泄露给用户。

示例：

```typescript
type ButtonProps = {
  variant?: 'primary' | 'secondary' | 'danger'
  size?: 'sm' | 'md' | 'lg'
  loading?: boolean
  disabled?: boolean
  onClick?: () => void
}
```

## 样式和主题

推荐把视觉规范抽成 token：

```text
color.brand.primary
space.2
radius.sm
font.size.body
```

这样主题切换、品牌定制、暗色模式才有统一基础。

## 可访问性

组件库必须关注 a11y：

- 键盘可操作。
- focus 状态清晰。
- ARIA 语义正确。
- 弹窗焦点管理。
- 表单错误可读。
- 颜色对比度达标。

如果基础组件不可访问，所有业务页面都会继承问题。

## 构建产物

组件库通常要输出：

- ESM。
- CJS 或兼容格式。
- `.d.ts` 类型声明。
- CSS 或样式入口。
- package exports。

还要正确配置：

- `peerDependencies`。
- `sideEffects`。
- `files`。
- `exports`。
- `types`。

## 文档和 Story

文档不是附属品。组件没有文档，就很难被正确使用。

文档应包括：

- 基础用法。
- API。
- 受控和非受控示例。
- loading、disabled、error、empty 状态。
- 设计规范。
- 迁移说明。
- 常见问题。

## 发布策略

组件库发布要注意兼容性：

- patch：bug 修复。
- minor：新增能力，兼容旧 API。
- major：破坏性变更。

breaking change 必须有迁移指南。大团队最好提供 codemod。

## 落地清单

- 是否有稳定导出入口？
- 是否输出类型声明？
- React/Vue 是否声明为 peer 依赖？
- 是否有 Story、文档和可视化回归？
- 是否覆盖键盘和可访问性？
- 是否有 changelog 和迁移策略？
- 是否能检测破坏性 API 变更？

## 深入展开：组件库要治理 API、主题和发布

组件库的长期成本主要来自 API 兼容。

每个组件都应该明确：

| 维度 | 要求 |
| --- | --- |
| API | props 命名稳定，类型导出，默认值清晰 |
| 状态 | loading、disabled、error、empty、focus、hover |
| 主题 | token 驱动，不写死业务颜色 |
| 可访问性 | 键盘、ARIA、焦点、对比度 |
| 测试 | 单测、交互测试、视觉回归 |
| 文档 | 用法、禁用场景、迁移说明 |

发布前要做 API diff。删除 props、改变默认行为、修改 DOM 结构，都可能是 breaking change。大团队要为 major 升级提供 codemod 或迁移清单。
