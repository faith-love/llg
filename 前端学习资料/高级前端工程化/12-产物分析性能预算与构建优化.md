# 产物分析性能预算与构建优化

产物分析解决的是“构建出来的东西到底是什么”。没有产物分析，性能优化只能靠猜。高级工程化要把 bundle 体积、chunk 拆分、缓存策略、source map、构建耗时纳入持续治理。

## 分析什么

| 指标 | 说明 |
| --- | --- |
| 初始 JS 体积 | 首屏必须下载和执行的代码 |
| 异步 chunk 体积 | 路由、组件、功能按需加载的代码 |
| CSS 体积 | 首屏阻塞渲染风险 |
| 第三方依赖占比 | React、图表、编辑器、日期库等 |
| 重复依赖 | 多版本同包或重复打包 |
| source map 体积 | 上传和存储成本 |
| 构建耗时 | 开发效率和 CI 成本 |
| 缓存命中率 | monorepo 或构建缓存效果 |

## 性能预算

预算要提前定义，不要等包体爆炸后才讨论。

示例：

```text
首屏 JS gzip <= 200 KB
单个异步 chunk gzip <= 150 KB
图片资源单个 <= 300 KB
生产 sourcemap 不对公网开放
构建时间 P95 <= 8 min
```

预算要分应用制定。后台管理系统和面向用户的营销页，对首屏性能要求不同。

## 产物分析工具

常见能力：

- 查看每个 chunk 包含哪些模块。
- 查看 gzip、brotli 后体积。
- 查看依赖重复。
- 对比两次构建差异。
- CI 中评论 PR 包体变化。

关键不是工具截图，而是把结果变成规则：

```text
如果 PR 让初始 JS gzip 增加超过 20 KB，需要说明原因。
```

## 优化方向

| 问题 | 优化 |
| --- | --- |
| 首屏 JS 太大 | 路由级懒加载、组件懒加载、减少首屏依赖 |
| 第三方库太大 | 换轻量库、按需引入、拆异步 chunk |
| 重复依赖 | 统一版本、依赖提升、external |
| tree-shaking 无效 | 使用 ESM、声明 sideEffects、避免顶层副作用 |
| CSS 太大 | 移除未用样式、组件级样式、关键 CSS |
| 图片太大 | 压缩、现代格式、响应式图片、懒加载 |

## 分包策略

分包不是越细越好。过多小 chunk 会增加请求和调度成本。

常见策略：

- 路由级分包。
- 大型组件异步加载，例如富文本、图表、地图。
- 稳定 vendor 单独缓存。
- 低频功能延迟加载。
- SSR 场景结合路由和数据预取。

不要为了追求首屏小，把用户马上需要的交互代码拆得过碎，导致点击后长时间加载。

## 缓存策略

静态资源要使用内容 hash：

```text
assets/index.9f1d3a.js
assets/vendor.a82c10.css
```

推荐：

- 带 hash 的 JS/CSS 长缓存。
- HTML 短缓存或不缓存。
- runtime config 短缓存。
- source map 不公开访问，只上传监控平台或内部存储。

## 构建性能优化

构建慢先定位瓶颈：

- 依赖安装慢。
- 类型检查慢。
- 转换慢。
- 打包慢。
- 压缩慢。
- 测试慢。
- 缓存未命中。

优化手段：

- CI 缓存包管理器 store。
- monorepo affected 只跑受影响项目。
- 类型检查和打包并行。
- 使用更快的 transformer 或 minifier。
- 减少不必要的 Babel 插件。
- 合理配置 source map。
- 对大型依赖预构建。

## 落地清单

- 每次构建是否生成产物分析报告？
- PR 是否能看到包体变化？
- 是否有首屏、异步 chunk 和资源体积预算？
- 是否能查出重复依赖和无效 tree-shaking？
- 静态资源缓存策略是否清晰？
- 构建耗时是否有 P95 指标和优化计划？

## 深入展开：包体优化要先定位再动作

不要一看到包体大就立刻拆包。先用报告回答：

| 问题 | 判断方式 |
| --- | --- |
| 是首屏大还是异步包大 | 看 initial chunk 和 async chunk |
| 是业务代码还是第三方库 | 看模块组成 |
| 是重复依赖还是单个库过大 | 看同包多版本和 vendor 占比 |
| 是没 tree-shaking 还是确实被使用 | 看 sideEffects、ESM 和引用路径 |
| 是 gzip 大还是 parse/execute 慢 | 结合运行时性能和长任务 |

优化优先级：

```text
移除不需要的代码 > 替换重依赖 > 正确按需加载 > 调整分包 > 压缩和缓存
```

Babel 也会影响产物体积，例如 helper 重复、polyfill 注入过多、targets 过旧都会让 JS 增大。包体分析时要把 Babel 输出和 bundler 输出一起看。
