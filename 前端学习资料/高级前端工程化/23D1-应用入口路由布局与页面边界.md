# 应用入口、路由、布局与页面边界

这一页拆应用骨架。应用层的核心职责是组合页面、注入服务、处理路由和布局，不应该把通用能力沉淀在 app 内部。

## 步骤一：入口文件只负责挂载

`apps/admin/src/main.tsx`：

```typescript
import React from 'react'
import { createRoot } from 'react-dom/client'
import { App } from './app/App'

const rootElement = document.getElementById('root')

if (!rootElement) {
  throw new Error('Root element #root is missing')
}

createRoot(rootElement).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
)
```

代码说明：

- `main.tsx` 不写业务逻辑。
- 先检查 `rootElement`，避免 `as HTMLElement` 掩盖运行时错误。
- `StrictMode` 可以帮助发现副作用和不稳定渲染。

## 步骤二：App 负责应用框架

`apps/admin/src/app/App.tsx`：

```typescript
import { AdminLayout } from './AdminLayout'
import { AdminRoutes } from './routes'

export function App() {
  return (
    <AdminLayout>
      <AdminRoutes />
    </AdminLayout>
  )
}
```

App 不直接写 header、nav、page 逻辑，而是组合 layout 和 routes。这样后续接 Provider、错误边界、权限上下文时不会挤在一个文件里。

## 步骤三：布局组件负责壳子

`apps/admin/src/app/AdminLayout.tsx`：

```typescript
import type { ReactNode } from 'react'

type AdminLayoutProps = {
  children: ReactNode
}

export function AdminLayout({ children }: AdminLayoutProps) {
  return (
    <div className="admin-shell">
      <header className="admin-header">
        <h1>ACME Admin</h1>
        <nav aria-label="Admin navigation">
          <a href="/users">Users</a>
          <a href="/tickets">Tickets</a>
          <a href="/flags">Feature Flags</a>
        </nav>
      </header>
      <main className="admin-main">{children}</main>
    </div>
  )
}
```

代码说明：

- `children` 用 `ReactNode`，表示可以接收任何 React 可渲染内容。
- `aria-label` 让多个 nav 场景更清晰。
- layout 只关心结构，不关心当前页面的数据。

## 步骤四：路由层负责选择页面

`apps/admin/src/app/routes.tsx`：

```typescript
import { FlagsPage } from '../pages/flags/FlagsPage'
import { TicketsPage } from '../pages/tickets/TicketsPage'
import { UsersPage } from '../pages/users/UsersPage'

export function AdminRoutes() {
  const path = window.location.pathname

  if (path.startsWith('/tickets')) return <TicketsPage />
  if (path.startsWith('/flags')) return <FlagsPage />

  return <UsersPage />
}
```

练习阶段可以手写这个最小路由。真实项目可以换成 React Router，但职责不变：路由层只决定渲染哪个页面。

## 步骤五：页面目录按业务域组织

推荐：

```text
apps/admin/src/pages/
  users/
    UsersPage.tsx
    users.service.ts
    users.types.ts
  tickets/
    TicketsPage.tsx
  flags/
    FlagsPage.tsx
```

不要这样：

```text
apps/admin/src/
  components/
  hooks/
  services/
  types/
```

后者按技术类型分层，小项目看起来整齐，大项目会导致一个业务改动跨很多目录。页面下按业务域聚合，更容易维护。

## 练习

1. 把 `admin` 的 `App` 拆成 `App`、`AdminLayout`、`routes`。
2. 给每个页面建独立目录。
3. 在 `portal` 里按同样模式创建 `PortalLayout` 和 `PortalRoutes`。
4. 确认 app 之间没有互相 import。

## 验收

- `main.tsx` 只负责挂载。
- `App.tsx` 只组合 layout 和 routes。
- layout 不读取业务数据。
- route 不实现业务组件。
- 页面按业务域组织，而不是只按 components、hooks、services 粗分。
