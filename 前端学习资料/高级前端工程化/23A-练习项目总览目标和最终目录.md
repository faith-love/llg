# 练习项目总览、目标和最终目录

这一节先不写业务代码，先把项目目标、目录、包职责和验收方式定清楚。真实工程里，先写清楚边界比先敲代码更重要。

## 目标

你要搭建一个 monorepo：

```text
acme-frontend-platform
  apps/admin
  apps/portal
  packages/ui
  packages/api-client
  packages/auth
  packages/feature-flags
  packages/shared
  packages/config-ts
  packages/config-eslint
  packages/config-vite
  packages/config-vitest
  tooling/generators
```

核心目标：

- 两个应用共享内部包。
- 所有包复用统一配置。
- 每个包有明确 owner 和职责。
- 任务能按依赖图执行。
- 质量检查能进入 CI。

## 包职责

| 包 | 负责 | 禁止 |
| --- | --- | --- |
| `apps/admin` | 内部运营页面和业务编排 | 被 packages 引用 |
| `apps/portal` | 客户门户页面和业务编排 | 复制 admin 业务逻辑 |
| `@acme/ui` | 通用 UI 组件 | 请求接口和权限判断 |
| `@acme/api-client` | 请求、错误、mock adapter | UI loading 和页面状态 |
| `@acme/auth` | session、角色、权限判断 | 依赖具体页面 |
| `@acme/feature-flags` | flag 类型、默认值、灰度判断 | 直接渲染 UI |
| `@acme/shared` | 无框架工具函数 | 业务实体和 React 代码 |
| `@acme/config-*` | 统一工程配置 | 业务代码 |

## 根 README 草稿

先写 README，约束项目目标：

````markdown
# acme-frontend-platform

企业级前端 monorepo 练习项目。

## Apps

- `admin`: 内部运营后台
- `portal`: 客户门户

## Packages

- `@acme/ui`: 通用组件库
- `@acme/api-client`: 请求客户端
- `@acme/auth`: 权限和 session
- `@acme/feature-flags`: Feature Flag 客户端
- `@acme/shared`: 无框架工具函数

## Commands

```bash
pnpm dev
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```
````

## 练习任务

1. 新建一个空目录 `acme-frontend-platform`。
2. 写上面的 README。
3. 在 README 中补充每个包的 owner，例如 `platform`、`design-system`、`admin-team`。
4. 画一张包依赖图。

包依赖图建议：

```text
apps/admin
  -> @acme/ui
  -> @acme/api-client
  -> @acme/auth
  -> @acme/feature-flags

apps/portal
  -> @acme/ui
  -> @acme/api-client
  -> @acme/auth
  -> @acme/feature-flags

@acme/ui
  -> @acme/shared

@acme/auth
  -> @acme/shared
```

## 验收标准

- 能说清 `apps` 和 `packages` 的区别。
- 能说清每个包为什么存在。
- 能指出哪些依赖方向是禁止的。
- README 能让新同事理解项目目标。
