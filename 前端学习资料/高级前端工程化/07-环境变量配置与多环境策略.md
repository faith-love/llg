# 环境变量配置与多环境策略

环境配置是前端工程里最容易被低估的风险点。很多线上事故不是代码逻辑错误，而是接口地址、开关、CDN、权限、密钥或构建模式配置错了。高级工程化要把配置从“散落变量”治理成清晰的配置体系。

## 三类配置

| 类型 | 何时确定 | 示例 |
| --- | --- | --- |
| build-time | 构建时确定 | 是否开启 sourcemap、目标浏览器、构建模式 |
| deploy-time | 部署时确定 | CDN 路径、部署环境、版本号 |
| runtime | 浏览器运行时确定 | API 网关、Feature Flag、实验分流 |

最常见错误是把 runtime 配置写进 build-time 环境变量，导致同一份产物无法跨环境部署。

## 环境命名

推荐用环境用途命名，而不是只用机器名：

```text
local       本地开发
dev         联调环境
test        测试环境
staging     预发环境
production 生产环境
```

每个环境要明确：

- API 域名。
- 静态资源域名。
- 登录和权限服务。
- 监控上报地址。
- 是否启用实验功能。
- 数据隔离规则。

## 前端公开变量和私密变量

前端构建进浏览器的变量都不是秘密。

```typescript
console.log(import.meta.env.VITE_API_BASE_URL)
```

凡是能被浏览器读取的内容，用户都能看到。不要把密钥、数据库密码、服务端 token 放到前端环境变量里。

## Runtime 配置

如果希望一份构建产物部署到多个环境，可以用 runtime config：

```html
<script src="/runtime-config.js"></script>
<script type="module" src="/assets/app.js"></script>
```

`runtime-config.js` 由部署系统生成：

```javascript
window.__APP_CONFIG__ = {
  apiBaseUrl: 'https://api.example.com',
  release: '2026.05.22.1',
  env: 'production'
}
```

应用启动时读取并校验：

```typescript
type AppConfig = {
  apiBaseUrl: string
  release: string
  env: 'local' | 'dev' | 'test' | 'staging' | 'production'
}
```

## 配置校验

配置必须在启动时校验，不要等请求失败才发现。

校验内容：

- 必填字段是否存在。
- URL 是否合法。
- env 是否在白名单。
- release 是否存在。
- 开关值类型是否正确。
- 生产环境是否误连测试域名。

## 多环境发布策略

推荐流程：

```text
同一 commit
  -> 构建一次产物
  -> 部署 test
  -> 验证
  -> 推进 staging
  -> 验证
  -> 推进 production
```

尽量不要每个环境重新构建一次。多次构建会让“测试通过的产物”和“生产上线的产物”不完全一致。

## 常见反模式

| 反模式 | 风险 |
| --- | --- |
| `.env.production` 提交敏感信息 | 密钥泄露 |
| 环境变量名没有前缀规范 | 变量来源混乱 |
| 每个环境重新构建 | 产物不可追溯 |
| 构建时写死 API 地址 | 产物无法环境推进 |
| 配置缺失时静默降级 | 线上隐性错误 |

## 落地清单

- 是否区分 build-time、deploy-time、runtime 配置？
- 前端公开变量是否不含秘密？
- 生产环境配置是否有启动校验？
- 同一份产物是否能推进多个环境？
- release、commit、环境是否能在页面和监控中追溯？
- Feature Flag 是否属于 runtime 配置，而不是每次重新构建？

## 深入展开：配置要可校验、可审计、可回滚

多环境配置的高级要求不是“能切环境”，而是配置变更本身可治理。

| 能力 | 说明 |
| --- | --- |
| schema 校验 | 配置缺字段、类型错误、URL 非法时启动失败 |
| 审计 | 谁在什么时候改了哪个环境配置 |
| 灰度 | 配置可以按用户、租户、地区逐步生效 |
| 回滚 | 配置错误时能快速回到上一版本 |
| 观测 | 错误率和性能能按配置版本拆分 |

推荐给 runtime config 增加版本：

```javascript
window.__APP_CONFIG__ = {
  env: 'production',
  release: '2026.05.22.1',
  configVersion: 'cfg-20260522-001',
  apiBaseUrl: 'https://api.example.com'
}
```

线上问题排查时，除了问“哪个代码版本”，还要问“哪个配置版本”。很多事故其实是配置发布事故，不是代码发布事故。
