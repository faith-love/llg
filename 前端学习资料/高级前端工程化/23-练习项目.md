# 练习项目

这个练习项目用一个小型 monorepo 串起高级前端工程化能力。目标不是做复杂业务，而是把架构、依赖、构建、规范、测试、发布、性能、监控、灰度和 Babel 编译链路都落到一个可执行项目里。

项目名称：`acme-frontend-platform`

业务背景：一个 SaaS 团队维护两个前端应用：

- `admin`：内部运营后台，管理用户、工单、角色和 Feature Flag。
- `portal`：客户门户，给客户查看工单、通知和个人资料。

共享能力：

- `@acme/ui`：基础组件库。
- `@acme/api-client`：请求客户端。
- `@acme/auth`：登录态和权限判断。
- `@acme/feature-flags`：Feature Flag 客户端。
- `@acme/shared`：无框架工具函数。
- `@acme/config-*`：统一 TS、ESLint、Vite、Vitest 配置。
- `tooling/generators`：代码生成器。

## 推荐完成顺序

1. 先做 `23A-23B`，把仓库跑起来。
2. 再做 `23C-23D`，建立规范和两个应用骨架。
3. 接着做 `23E-23F`，沉淀共享组件和业务基础包。
4. 然后做 `23G-23H`，接入任务编排、缓存、测试和 CI。
5. 最后做 `23I`，补齐性能、监控、灰度和 Babel 编译链路。
6. 如果要写成作品项目，按 `23A1-23I2` 逐页补齐代码、解释和验收记录。

## 最终验收命令

完成所有子集后，根目录应该能执行：

```bash
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm affected:build
```

## 最终验收清单

- 仓库结构清晰，应用和包职责明确。
- `admin` 和 `portal` 能独立开发、构建和测试。
- 内部包通过 workspace 引用，不需要发布也能本地联调。
- `@acme/ui`、`@acme/api-client`、`@acme/auth`、`@acme/feature-flags` 有清晰 public API。
- `@acme/config-*` 被应用和包复用。
- `turbo.json` 有合理的 `dependsOn`、`inputs`、`outputs`。
- 修改共享包时，能说明受影响应用。
- lint、typecheck、test、build 进入 CI。
- runtime config、Feature Flag、错误监控和 Web Vitals 有最小实现。
- Babel、TypeScript、Vite、minifier 的职责边界能说清楚。
