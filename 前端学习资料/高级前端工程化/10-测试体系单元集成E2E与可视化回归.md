# 测试体系单元集成 E2E 与可视化回归

测试体系的目标不是追求百分百覆盖率，而是用合适成本覆盖关键风险。高级前端工程化要清楚每类测试保护什么、不能保护什么，以及它们应该放在开发、CI 和发布流程的哪个阶段。

## 测试金字塔

```text
          E2E / Visual
       Integration / Component
    Unit / Hook / Pure Function
```

越底层越快、越稳定、越适合频繁执行；越上层越接近用户，但成本更高、也更容易不稳定。

## 测试类型

| 类型 | 保护对象 | 适合工具 |
| --- | --- | --- |
| 单元测试 | 纯函数、hook、状态机、工具函数 | Vitest、Jest |
| 组件测试 | 组件交互、props、事件、渲染分支 | Testing Library、Vitest |
| 集成测试 | API mock、路由、状态流转 | MSW、Testing Library |
| E2E | 用户关键路径 | Playwright、Cypress |
| 可视化回归 | UI 截图差异 | Storybook、Chromatic、Playwright |
| 合约测试 | 前后端接口契约 | OpenAPI、Pact |

## 先测什么

优先覆盖高价值路径：

- 登录、支付、下单、审批、发布等核心流程。
- 复杂表单和权限逻辑。
- 组件库基础组件。
- 数据转换和边界条件。
- 曾经出过事故的模块。

不要先给所有简单展示组件补低价值快照测试。

## 单元测试

单元测试适合稳定业务规则：

```typescript
export function canDeleteUser(role: string, targetStatus: string) {
  return role === 'admin' && targetStatus !== 'owner'
}
```

测试重点：

- 正常路径。
- 边界值。
- 异常输入。
- 权限组合。
- 回归案例。

## E2E 测试

E2E 不应该覆盖所有分支，只保护关键用户路径。

典型路径：

```text
打开页面 -> 登录 -> 搜索用户 -> 编辑角色 -> 保存 -> 看到成功提示
```

E2E 要稳定，需要：

- 独立测试账号。
- 可控测试数据。
- 明确等待条件。
- 避免依赖第三方不稳定服务。
- 失败时保存截图、视频、trace。

## 可视化回归

适合组件库、营销页、复杂布局、设计系统。

关注：

- 不同 viewport。
- 暗色模式。
- 国际化长文本。
- loading、empty、error 状态。
- hover、focus、disabled 状态。

可视化回归要设置合理阈值，避免因为字体抗锯齿或环境差异频繁误报。

## Flaky 治理

不稳定测试会摧毁团队信任。

常见原因：

- 等待固定时间。
- 数据没有隔离。
- 依赖真实网络。
- 测试之间共享状态。
- 选择器不稳定。

治理方式：

- 使用稳定 test id 或可访问性选择器。
- 每个测试独立准备和清理数据。
- 对外部接口 mock。
- 失败自动重试只能作为缓冲，不能掩盖问题。
- 统计 flaky 测试并定期清理。

## CI 策略

```text
pull request:
  lint + typecheck + unit + build

merge to main:
  integration + e2e smoke + artifact

release:
  full e2e + visual diff + deploy gate
```

不同阶段跑不同测试，不要让每个 PR 承担所有最慢任务。

## 落地清单

- 是否明确每类测试保护什么风险？
- 关键用户路径是否有 E2E smoke？
- 组件库是否有交互和视觉回归？
- 测试数据是否可重复、可隔离？
- CI 是否保存失败截图、日志和 trace？
- flaky 测试是否有治理指标？

## 深入展开：测试要和风险分层绑定

不要为了覆盖率而测试，要为风险选择测试层。

| 风险 | 推荐测试 |
| --- | --- |
| 纯业务规则计算错误 | 单元测试 |
| Hook 状态流转错误 | 单元测试或组件测试 |
| 表单交互和校验错误 | 组件测试或集成测试 |
| 登录、支付、发布等核心链路中断 | E2E smoke |
| 组件视觉样式回归 | 可视化回归 |
| 前后端字段不一致 | 合约测试或 schema 校验 |

测试也要进入发布分层：

```text
开发本地：单元测试、组件测试
PR 阶段：lint、typecheck、unit、build
合入 main：集成测试、E2E smoke
发布前：关键路径 E2E、视觉回归、线上 smoke
```

如果某个线上事故发生过，复盘行动项最好落实成具体测试，而不是笼统写“加强测试”。
