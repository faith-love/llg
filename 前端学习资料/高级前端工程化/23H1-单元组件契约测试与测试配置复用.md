# 单元测试、组件测试、契约测试与测试配置复用

这一页拆测试分层。不同测试保护不同风险：工具函数靠单元测试，组件靠渲染测试，请求库靠契约测试。

## 步骤一：共享 Vitest 配置

`packages/config-vitest/index.ts`：

```typescript
import { defineConfig } from 'vitest/config'

export function defineTestConfig() {
  return defineConfig({
    test: {
      globals: true,
      environment: 'jsdom',
      setupFiles: ['./vitest.setup.ts'],
      coverage: {
        reporter: ['text', 'html']
      }
    }
  })
}
```

说明：

- `globals: true` 允许直接用 `test`、`expect`。
- `environment: 'jsdom'` 支持 React 组件测试。
- `setupFiles` 统一加载测试扩展。
- coverage 统一输出文本和 html。

## 步骤二：包内复用配置

`packages/ui/vitest.config.ts`：

```typescript
import { defineTestConfig } from '@acme/config-vitest'

export default defineTestConfig()
```

`packages/ui/vitest.setup.ts`：

```typescript
import '@testing-library/jest-dom/vitest'
```

每个包不复制完整 Vitest 配置，只补自己的 setup。

## 步骤三：shared 单元测试

`packages/shared/src/date.test.ts`：

```typescript
import { formatDate } from './date'

test('formatDate returns yyyy-mm-dd', () => {
  expect(formatDate(new Date('2026-05-22T10:00:00.000Z'))).toBe('2026-05-22')
})
```

单元测试关注纯函数输入输出，不需要 jsdom，也不需要 React。

## 步骤四：组件测试

`packages/ui/src/button/Button.test.tsx`：

```typescript
import { render, screen } from '@testing-library/react'
import { Button } from './Button'

test('disables button while loading', () => {
  render(<Button loading>Save</Button>)

  const button = screen.getByRole('button', { name: 'Loading...' })

  expect(button).toBeDisabled()
  expect(button).toHaveAttribute('aria-busy', 'true')
})
```

组件测试关注用户能看到和能交互的结果，不测试内部 className map。

## 步骤五：api-client 契约测试

`packages/api-client/src/createClient.test.ts`：

```typescript
import { ApiError } from './errors'
import { createClient } from './createClient'
import { createMockAdapter } from './mockAdapter'

test('returns typed data from get request', async () => {
  const client = createClient({
    baseURL: 'http://localhost',
    adapter: createMockAdapter({
      'GET /users': [{ id: 'u1', name: 'Ada' }]
    })
  })

  const users = await client.get<Array<{ id: string; name: string }>>('/users')

  expect(users[0]?.name).toBe('Ada')
})

test('throws ApiError for missing mock route', async () => {
  const client = createClient({
    baseURL: 'http://localhost',
    adapter: createMockAdapter({})
  })

  await expect(client.get('/missing')).rejects.toBeInstanceOf(ApiError)
})
```

契约测试保护的是“调用方式”和“错误模型”稳定，不关心真实网络。

## 练习

1. 给 shared 写两个纯函数测试。
2. 给 Button 写 loading 和 disabled 测试。
3. 给 DataTable 写空状态测试。
4. 给 api-client 写成功和失败契约测试。

## 验收

- 测试配置通过 `@acme/config-vitest` 复用。
- 纯函数测试不依赖页面。
- 组件测试按用户视角断言。
- api-client 测试覆盖成功和失败协议。
