# 08-缓存、插件和执行原理了解

## 一级缓存

MyBatis 默认有一级缓存，作用域通常是 SqlSession。

同一个 SqlSession 中相同查询可能命中缓存。

Spring 项目中不要过度依赖一级缓存，重点了解它可能影响你对 SQL 执行次数的判断。

## 二级缓存

二级缓存作用域更大，但实际项目中要谨慎使用。

原因：

- 数据一致性复杂。
- 多表关联更新难处理。
- 与业务缓存边界容易混乱。

很多项目更倾向使用 未译25173edis 管业务缓存。

## 插件机制

MyBatis 插件可以拦截执行过程，例如：

- 分页。
- SQL 打印。
- 性能分析。
- 数据权限。

## 执行流程简化理解

```text
Mapper 方法 -> 找到 MappedStatement -> 解析参数 -> 执行 SQL -> 映射结果
```

小白不需要深入源码，但要知道 Mapper 方法不是普通方法，它背后有代理和映射。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 一级缓存 | 减少同会话重复查询 | 可能影响你观察 SQL 次数 | 了解即可，不依赖业务正确性 | 重点是作用域 |
| 二级缓存 | 更大范围缓存 | 一致性复杂 | 初学不建议开启 | 重点是慎用 |
| 插件 | 拦截 MyBatis 执行过程 | 可扩展分页、审计、权限 | 用成熟插件，少手写 | 难点是拦截点理解 |
| 执行流程 | 理解 Mapper 背后机制 | 出错时能定位到 SQL 映射 | 记住代理 + MappedStatement | 重点是接口方法对应 SQL |
