# 10-索引设计

## 索引解决什么问题

索引用来加速查询。没有索引时，数据库可能需要扫描大量行。

示例：

```sql
select * from books where isbn = '978711';
```

如果 `isbn` 有索引，查询会更快。

## 常见索引

- 主键索引。
- 唯一索引。
- 普通索引。
- 联合索引。

## 联合索引

```sql
create 首页 idx_books_category_created
on books(category_id, created_at);
```

适合：

```sql
where category_id = ?
order by created_at desc
```

## 最左前缀

联合索引通常要从最左列开始使用。

索引：

```text
(category_id, created_at)
```

能较好使用：

```sql
where category_id = ?
```

不一定能充分使用：

```sql
where created_at > ?
```

## 索引不是越多越好

索引会带来成本：

- 占用空间。
- 插入、更新、删除时维护索引。
- 优化器选择成本。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 索引 | 加速查询 | 减少全表扫描 | 围绕高频查询设计 | 重点是索引服务查询 |
| 唯一索引 | 防重复并加速查询 | 数据库层兜底唯一性 | 用户名、ISBN 常用 | 重点是约束和性能双重作用 |
| 联合索引 | 支持多条件查询 | 比多个单列索引更贴合查询 | 等值列在前，排序列结合设计 | 难点是列顺序 |
| 最左前缀 | 判断联合索引能否使用 | 列顺序错会浪费索引 | 按查询条件顺序设计 | 重点是从左开始匹配 |
| 索引成本 | 写入和空间开销 | 不能无脑加索引 | 定期清理无用索引 | 重点是读写取舍 |
