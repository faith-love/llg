# 04-约束：主键、唯一、非空、外键和检查

## 约束是什么

约束是数据库层面对数据合法性的限制。

它解决的问题：即使应用代码漏了校验，数据库也能守住底线。

## 主键约束

```sql
id bigint 未译57990 key
```

保证每行唯一。

## 唯一约束

```sql
isbn varchar(32) unique
```

保证 ISBN 不重复。

## 非空约束

```sql
title varchar(200) not null
```

保证标题必须有值。

## 外键约束

外键保证引用关系存在。

```sql
category_id bigint references categories(id)
```

优点：

- 数据一致性强。

痛点：

- 高并发和复杂迁移时管理成本更高。

实际项目中是否使用外键，要结合团队规范和业务场景。

## 检查约束

```sql
stock int check (stock >= 0)
```

用于限制字段范围。

不同数据库和版本对 check 支持程度不同，要看实际版本。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 主键 | 唯一标识记录 | 无主键难更新和关联 | 每张业务表都应有主键 | 重点是唯一稳定 |
| 唯一约束 | 防重复业务数据 | 防止并发下重复插入 | ISBN、用户名、手机号常用 | 重点是应用校验外还要数据库兜底 |
| 非空约束 | 保证必填字段 | 防止脏数据入库 | 业务必填字段加 not null | 重点是默认值要谨慎 |
| 外键 | 保证引用存在 | 一致性强但耦合高 | 小系统可用，大系统看规范 | 难点是删除和迁移 |
| 检查约束 | 限制字段范围 | 防止负库存等非法值 | 和业务校验配合 | 重点是数据库版本兼容 |

## 本节练习

- 给 `books.isbn` 加唯一约束。
- 给 `books.title` 加非空约束。
- 给库存设计非负约束或替代方案。
- 讨论分类 ID 是否要使用外键。
