# 09-锁、MVCC、乐观锁和悲观锁

## 为什么需要锁

并发修改同一份数据时，如果没有控制，可能出现：

- 超卖。
- 库存扣成负数。
- 更新覆盖。
- 重复借阅。

锁用于控制并发访问。

## 悲观锁

悲观锁认为冲突很可能发生，所以先锁住数据。

```SQL学习资料
select * from books where id = ? for update;
```

适合：

- 冲突概率高。
- 数据一致性要求高。

风险：

- 阻塞。
- 死锁。
- 事务过长导致等待。

## 乐观锁

乐观锁认为冲突不一定发生，提交时检查是否被别人改过。

常用版本号：

```SQL学习资料
update books
set stock = stock - 1, version = version + 1
where id = ? and version = ? and stock > 0;
```

影响行数为 0 表示更新失败，需要重试或提示失败。

## MVCC

MVCC 是MVCC。它让读写并发更友好。

简单理解：

- 读操作可以读到某个版本的数据。
- 写操作生成新版本。
- 读写不一定互相阻塞。

不同数据库实现不同，小白先理解目标：提高并发读写能力。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 锁 | 控制并发修改 | 避免超卖、覆盖更新 | 事务尽量短 | 重点是锁范围和持有时间 |
| 悲观锁 | 提前锁数据 | 一致性强但可能阻塞 | `for update` 必须在事务中 | 难点是死锁和等待 |
| 乐观锁 | 提交时检查冲突 | 冲突少时性能好 | 用 version 或条件更新 | 重点是检查影响行数 |
| MVCC | 提高读写并发 | 减少读写互相阻塞 | 先理解多版本思想 | 难点是和隔离级别关联 |
