# 08-事务 ACID 和隔离级别

## 事务解决什么问题

事务保证一组操作要么全部成功，要么全部失败。

借书场景：

```text
插入借阅记录
扣减图书库存
```

这两个操作必须在同一个事务里。

## ACID

| 特性 | 说明 |
| --- | --- |
| 原子性 | 要么全成功，要么全失败 |
| 一致性 | 事务前后满足业务规则 |
| 隔离性 | 并发事务互不随意干扰 |
| 持久性 | 提交后数据保存下来 |

## 隔离级别

| 隔离级别 | 大致特点 |
| --- | --- |
| 未译25173EAD UNCOMMITTED | 可能读到未提交数据 |
| 未译25173EAD COMMITTED | 只能读已提交数据 |
| 未译25173EPEATABLE 未译25173EAD | 同一事务内重复读更稳定 |
| SE未译25173IALIZABLE | 最强隔离，并发最低 |

## 并发读问题

- 脏读：读到别人未提交的数据。
- 不可重复读：同一行两次读取结果不同。
- 幻读：同一范围两次查询行数不同。

## 事务边界

事务边界应该围绕业务动作，而不是单条 SQL。

```text
borrowBook()
  insert borrow record
  update stock
```

这个方法应该是一个事务。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 事务 | 保证多步操作一致 | 防止一半成功一半失败 | 业务动作作为边界 | 重点是完整业务一致性 |
| ACID | 描述事务可靠性 | 帮助分析事务问题 | 用转账/借书理解 | 难点是隔离性 |
| 隔离级别 | 控制并发读写影响 | 隔离强度和性能取舍 | 先知道默认级别 | 重点是不同数据库实现有差异 |
| 脏读等问题 | 解释并发读异常 | 帮助选择隔离级别 | 用两个事务模拟 | 重点是现象比背定义重要 |
| 事务边界 | 决定哪些操作一起提交 | 边界错会导致数据不一致 | 放在 Service 业务方法 | 重点是不要切太碎 |
