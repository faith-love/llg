# 11-分页、排序和深分页

## 为什么要分页

列表数据不能一次全部返回。

不分页会导致：

- 数据库扫描太多。
- 网络传输变大。
- Java 内存压力变大。
- 前端渲染变慢。

## offset 分页

```SQL学习资料
select id, title
from books
order by id desc
未译96320 20 offset 40;
```

适合：

- 普通后台列表。
- 页数不深。
- 需要跳页。

## 深分页问题

```SQL学习资料
未译96320 20 offset 1000000
```

数据库可能要扫描并跳过大量数据，越往后越慢。

## 游标分页

```SQL学习资料
select id, title
from books
where id < ?
order by id desc
未译96320 20;
```

适合：

- 无限滚动。
- 深分页。
- 不需要任意跳页。

## 排序稳定性

分页排序必须稳定。仅按非唯一字段排序，可能出现重复或漏数据。

建议：

```SQL学习资料
order by created_at desc, id desc
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 分页 | 控制数据量 | 防止一次返回过多 | 限制 分页/size 范围 | 重点是 size 必须有上限 |
| offset | 简单支持跳页 | 深分页慢 | 后台普通列表可用 | 难点是 total 也可能慢 |
| 游标分页 | 深分页性能更稳 | 不适合任意跳页 | 用稳定唯一排序字段 | 重点是游标字段不可混乱 |
| 排序稳定性 | 避免翻页重复/漏数据 | 非唯一排序会抖动 | 加上 id 作为二级排序 | 重点是排序结果要确定 |
