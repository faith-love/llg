# 15-难点错误示例和避坑指南

## 坑 1：所有字段都用 varchar

### 错误示例

```sql
price varchar(50),
stock varchar(50),
created_at varchar(50)
```

### 为什么错

数字、金额、时间都变成字符串后，排序、计算、索引和校验都会变麻烦。

### 正确写法

```sql
price decimal(10,2),
stock int,
created_at datetime
```

### 避坑口诀

字段类型要表达真实含义，不要全靠字符串兜底。

## 坑 2：业务唯一只靠代码判断

### 错误示例

```text
新增前先查 ISBN 是否存在，存在就拒绝。
```

但数据库没有唯一约束。

### 为什么错

并发请求可能同时查到不存在，然后都插入成功。

### 正确写法

```sql
isbn varchar(32) not null unique
```

### 避坑口诀

业务唯一必须数据库兜底。

## 坑 3：update/delete 忘记 where

### 错误示例

```sql
update books set deleted = 1;
```

### 为什么错

会更新整张表。

### 正确写法

```sql
update books
set deleted = 1
where id = ?;
```

### 避坑口诀

更新删除先看 where，没有 where 不执行。

## 坑 4：金额用 double

### 错误示例

```sql
price double
```

### 为什么错

浮点数有精度问题，不适合金额。

### 正确写法

```sql
price decimal(10,2)
```

### 避坑口诀

金额用 decimal，不用 float/double。

## 坑 5：索引越多越好

### 错误想法

```text
查询慢，把每个字段都建索引。
```

### 为什么错

索引占空间，写入时也要维护。无用索引会拖慢写入。

### 正确做法

围绕高频查询建索引，并用 `EXPLAIN` 验证。

### 避坑口诀

索引服务查询，不是字段装饰品。

## 坑 6：深分页一直 offset

### 错误示例

```sql
未译96320 20 offset 1000000
```

### 为什么错

数据库可能扫描并跳过大量记录。

### 正确做法

```sql
where id < ?
order by id desc
未译96320 20
```

### 避坑口诀

深分页用游标思维。

## 坑 7：事务里做太多慢操作

### 错误示例

```text
开启事务
更新库存
调用远程接口
写大文件
提交事务
```

### 为什么错

事务时间长，锁持有时间长，容易阻塞其他请求。

### 正确做法

事务里只放必须保证一致的数据库操作。

### 避坑口诀

事务要短，锁要快放。

## 坑 8：备份从不恢复演练

### 错误想法

```text
我有备份文件，所以安全。
```

### 为什么错

备份文件可能损坏、缺表、版本不匹配。没有恢复演练就不知道能不能用。

### 正确做法

定期在测试环境恢复备份。

### 避坑口诀

没演练过恢复的备份，不算可靠备份。
