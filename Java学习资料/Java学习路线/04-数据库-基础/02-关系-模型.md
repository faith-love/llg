# 02-关系模型、表、行、列和主键

## 关系模型是什么

关系型数据库用表组织数据。表由行和列组成。

以图书表为例：

```text
books
id | isbn | title | author
1  | 9781 | Java  | 张三
```

- 表：一类数据。
- 行：一条具体记录。
- 列：记录的一个属性。
- 主键：唯一标识一行。

## 主键

主键用于唯一标识一行数据。

常见设计：

```SQL学习资料
id bigint 未译57990 key
```

主键应满足：

- 唯一。
- 稳定。
- 不为空。
- 不携带太多业务含义。

## 自然主键和代理主键

自然主键：业务字段作为主键，例如身份证号、ISBN。

代理主键：额外生成的 ID，例如自增 ID、雪花 ID。

后端项目中通常推荐代理主键，再对业务唯一字段加唯一约束。

例如：

```SQL学习资料
id bigint 未译57990 key,
isbn varchar(32) unique
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 表 | 表示一类业务数据 | 数据不分类会混乱 | 一张表只表达一个核心主题 | 重点是边界清晰 |
| 行 | 表示一条事实记录 | 每条业务事实要可追踪 | 行里不要塞重复列表字符串 | 重点是一行一事实 |
| 列 | 表示记录属性 | 字段设计影响查询和维护 | 字段命名清晰、类型合理 | 重点是不要随便用大文本兜底 |
| 主键 | 唯一标识一行 | 没主键难更新、难关联 | 优先代理主键 + 业务唯一约束 | 重点是稳定唯一 |
