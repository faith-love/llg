# 17-通过标准和复盘清单

## 阶段通过标准

完成这一阶段后，你应该能做到：

- 能设计 5-10 个类完成一个小程序。
- 能解释类、对象、字段、方法、构造器。
- 能使用封装保护对象状态。
- 能使用继承和多态。
- 能区分接口和抽象类。
- 能重写 `toString`、`equals`、`hashCode`。
- 能根据场景选择集合。
- 能写自定义异常。
- 能写泛型类或泛型方法。
- 能用 Stream 完成过滤、映射、分组。
- 能使用文件保存程序数据。

## 知识点深挖通过标准

每学完一个知识点，除了会写代码，还要能回答：

- 作用：它让代码具备了什么能力？
- 痛点：没有它时会遇到什么问题？
- 优点：使用它之后代码哪里更清晰、更安全或更灵活？
- 技巧：实际写项目时怎么用更稳？
- 难点：小白最容易误解或写错哪里？
- 重点：复习和面试时必须抓住哪一句核心结论？

如果只能写出语法，但说不出这些内容，说明还需要回到对应小节复习。

## 常见问题

### 类太少

如果所有代码都在一个类里，说明你还停留在基础语法阶段。

试着按职责拆：

- 数据对象。
- 业务服务。
- 数据存储。
- 用户界面。
- 异常。

### getter/setter 太多但没有行为

对象不是只有字段的Docker。

例如图书借出，不要只写：

```java
book.setStatus(BookStatus.BORROWED);
```

更好的写法：

```java
book.borrow();
```

这样业务规则可以封装在对象内部。

### 接口不知道怎么用

先记住一句话：接口用来隔离调用方和实现方。

例如 `BookService` 依赖 `BookRepository` 接口，而不是直接依赖文件实现。以后从文件换成数据库，Service 可以少改甚至不改。

### Stream 写得太复杂

Stream 是工具，不是目标。如果写出来比 `for` 循环更难懂，就先用 `for`。
