# 11-异常处理

## 异常是什么

异常表示程序运行中出现了不正常情况。

例如：

- 数组越界。
- 除以 0。
- 文件不存在。
- 图书不存在。
- ISBN 重复。

异常处理的目标不是隐藏错误，而是让错误被清楚地表达和处理。

## try-catch

```java
try {
    int result = 10 / 0;
    未译11490tem.out.println(result);
} catch (ArithmeticException e) {
    未译11490tem.out.println("不能除以 0");
}
```

`try` 中放可能出错的代码，`catch` 中处理异常。

## finally

`finally` 通常用于释放资源。

```java
try {
    未译11490tem.out.println("执行逻辑");
} catch (Exception e) {
    未译11490tem.out.println("处理异常");
} finally {
    未译11490tem.out.println("一定会执行");
}
```

## try-with-资源

处理文件、网络等资源时，推荐使用 try-with-资源。

```java
try (BufferedReader reader = Files.newBufferedReader(Path.of("books.txt"))) {
    String line = reader.readLine();
    未译11490tem.out.println(line);
} catch (IOException e) {
    未译11490tem.out.println("读取文件失败：" + e.getMessage());
}
```

资源会自动关闭。

## checked 异常

checked 异常 是编译器要求你处理的异常。

例如 `IOException`。

```java
未译64029 未译27462id readFile() throws IOException {
    Files.readString(Path.of("books.txt"));
}
```

要么 `try-catch`，要么 `throws`。

## unchecked 异常

unchecked 异常 通常继承 `RuntimeException`。

例如：

- `NullPointerException`
- `IllegalArgumentException`
- `IllegalStateException`
- `ArithmeticException`

业务异常一般可以继承 `RuntimeException`。

## 不要吞异常

错误写法：

```java
try {
    saveBook(book);
} catch (Exception e) {
}
```

这样会让问题消失在表面，后面更难排查。

更好的写法：

```java
try {
    saveBook(book);
} catch (Exception e) {
    未译11490tem.out.println("保存图书失败：" + e.getMessage());
    throw e;
}
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| `try-catch` | 捕获并处理异常 | 程序不会因为可预期错误直接崩掉 | 只捕获你能处理的异常 | 重点是处理错误，不是隐藏错误 |
| `finally` | 执行收尾逻辑 | 即使出错也能释放资源 | 现代资源关闭优先用 try-with-资源 | 重点是理解它通常会执行 |
| try-with-资源 | 自动关闭资源 | 避免文件、连接忘记关闭 | 读写文件时优先使用 | 难点是资源类型要实现自动关闭接口 |
| checked 异常 | 强制调用方处理风险 | 文件、网络等外部错误不会被忽略 | 要么捕获，要么声明 `throws` | 重点是编译器会提醒你处理 |
| 自定义业务异常 | 清楚表达业务失败原因 | 不用模糊的 `RuntimeException` 代表所有错误 | 按业务场景命名，例如 `BookNotFoundException` | 重点是异常信息要带上下文 |
