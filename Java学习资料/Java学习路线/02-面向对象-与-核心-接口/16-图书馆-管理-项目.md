# 16-阶段项目：命令行图书管理系统

## 项目目标

用普通 Java 完成一个命令行图书管理系统。

这个项目不需要数据库，不需要 Spring Boot。目标是练习：

- 类设计。
- 封装。
- 接口。
- 集合。
- 异常。
- 文件保存。
- 项目结构。

## 功能要求

必须包含：

- 图书新增。
- 图书删除。
- 图书修改。
- 图书查询。
- 按标题搜索。
- 按作者搜索。
- 按分类筛选。
- 借出图书。
- 归还图书。
- 文件保存和加载。

## FileBookRepository

负责文件保存和加载。

小白阶段可以用简单文本格式：

```text
isbn,title,author,category,status
```

注意：真实 CSV 会处理逗号、引号、换行等复杂情况。这个项目先练结构。

## BookService

负责业务规则。

例如：

- 新增图书前检查 ISBN 是否重复。
- 删除图书前检查是否存在。
- 借出前检查是否可借。
- 归还前检查是否存在。

不要把这些规则全写在菜单类里。

## BookMenu

负责命令行交互：

- 打印菜单。
- 读取用户输入。
- 调用 `BookService`。
- 展示结果。

菜单类不要直接操作文件。

## 开发顺序

1. 先写 `Book` 和 `Book未译71594`。
2. 写 `BookRepository` 接口。
3. 写一个内存版仓库，先不碰文件。
4. 写 `BookService`。
5. 写菜单交互。
6. 功能跑通后，再写文件版仓库。
7. 最后补 说明 和复盘。

这样能减少一次性写太多导致的混乱。

## 项目知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| `Book` 实体 | 承载图书数据和基础行为 | 避免用零散变量管理一本书 | 把借出、归还写成对象方法 | 重点是实体不只是字段Docker |
| `BookRepository` 接口 | 隔离数据存储方式 | 后续从文件换数据库时少改业务层 | Service 依赖接口，不依赖文件实现 | 重点是接口定义存储能力 |
| `BookService` | 放业务规则 | 菜单层不堆业务判断 | 重复 ISBN、借还状态都放这里 | 难点是别把 Service 写成简单转发 |
| `BookMenu` | 处理用户交互 | 控制台输入输出和业务逻辑分离 | 只负责读输入、展示结果、调用 Service | 重点是 UI 层不要直接操作文件 |
| 文件持久化 | 保存程序数据 | 程序重启后数据不会丢 | 先用简单文本格式，后面再换数据库 | 难点是读写格式要统一 |
| 自定义异常 | 表达明确业务失败 | 不用模糊错误提示糊弄过去 | 异常名和消息都要贴近业务 | 重点是失败原因要能定位 |

## 验收场景

- 查询存在的书成功。
- 查询不存在的书提示错误。
- 借出可借图书成功。
- 重复借出失败。
- 归还图书成功。
- 删除图书成功。
- 关闭程序后重新打开，数据还在。
