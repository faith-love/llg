# 01-最终学习目标

## 为什么要先定目标

小白学习 Java 时，最容易把“看过”当成“学会”。比如看过 `HashMap`、线程池、Spring 事务，不代表能在项目里正确使用。

这一节先把最终目标说清楚。后面每个知识点都要服务于这些目标。

## 总目标

学完这条路线后，你应该能独立完成一个 Java 后端项目，并能解释项目里关键技术为什么这么用。

更具体地说，你要达到下面 6 个能力。

## 目标 1：能写 Java 程序

这不是只会写 `Hello World`，而是能写出有结构的小程序。

你需要做到：

- 会创建类、对象、方法。
- 会使用数组、集合、字符串、日期时间。
- 会处理异常。
- 会读写文件。
- 会把一段大逻辑拆成多个类和方法。

小白判断标准：

- 给你一个“图书管理系统”的需求，你能写出命令行版本。
- 程序出错时，你能看懂报错位置，而不是只会重启 IDE。

## 目标 2：能理解后端请求流程

后端开发不是只写 Java 文件。一个请求从浏览器或前端发出来，会经过 HTTP、Controller、Service、数据库，再返回 JSON。

你需要能讲清：

```text
用户请求 -> HTTP -> Controller -> Service -> Mapper/Repository -> Database -> 返回 JSON
```

小白判断标准：

- 你知道 GET、POST、PUT、DELETE 的大致区别。
- 你知道 Controller 不应该直接写大量业务逻辑。
- 你知道事务通常放在 Service 层。

## 目标 3：能做 Spring Boot 项目

Spring Boot 是 Java 后端最常见的开发主线之一。

你需要做到：

- 能创建 Spring Boot 项目。
- 能写 REST API。
- 能连接数据库。
- 能做参数校验。
- 能做统一异常处理。
- 能做登录鉴权。
- 能写测试。
- 能用 Docker 启动项目依赖。

小白判断标准：

- 你能独立做一个“图书馆 REST API”或“个人博客系统”。
- 别人按你的 说明 能把项目跑起来。

## 目标 4：能理解 JVM 和并发基础

刚开始不需要变成 JVM 专家，但必须知道 Java 程序运行时发生了什么。

你需要理解：

- `.Java学习资料` 文件会编译成 `.class` 文件。
- 对象大多放在堆内存里。
- 方法调用会用到栈。
- 内存不够会出现 OOM。
- 多线程共享数据可能出错。
- 线程池不能乱建。

小白判断标准：

- 看到 `OutOfMemoryError`、`StackOverflowError` 不会完全慌。
- 能解释为什么多个线程同时修改同一个变量可能出错。

## 目标 5：能测试、部署和排查问题

真实工作里，代码不是“能跑一次”就结束。还要能测试、部署、看日志、定位错误。

你需要做到：

- 会写 JUnit 测试。
- 会执行 `mvn clean 测试`。
- 会看日志。
- 会区分开发、测试、生产配置。
- 会用 Docker 启动 MySQL、Redis 等依赖。
- 会写清楚项目启动步骤。

小白判断标准：

- 项目报错时，你能根据日志定位到具体接口或 SQL。
- 你能让别人按 说明 启动你的项目。

## 目标 6：能讲清自己的项目

如果未来要面试，项目不是堆功能，而是证明你解决过问题。

你需要能讲清：

- 项目要解决什么问题。
- 你负责哪些模块。
- 数据库表怎么设计。
- 接口怎么设计。
- 遇到过什么问题。
- 为什么使用 Redis、MQ、事务或线程池。
- 还有哪些可以改进的地方。

小白判断标准：

- 不说“我用了 Spring Boot”，而是能说“为什么这里需要事务，事务失败时会发生什么”。

## 本节练习

写一个 `my-Java学习资料-goals.md`，回答下面问题：

1. 我学习 Java 的目的是什么？
2. 我希望 3 个月后能做出什么？
3. 我希望 6 个月后能做出什么？
4. 我现在最薄弱的地方是什么？
5. 我每周能投入多少小时？

## 本节通过标准

- 能用自己的话解释 Java 后端要学哪些模块。
- 能写出 3 个月和 6 个月目标。
- 能说清“看过”和“学会”的区别。
