# 13-阶段项目：把图书 API 工程化

## 项目目标

把前面做过的图书 REST API 改造成一个更像真实项目的工程化版本。

不是新增很多业务功能，而是补齐可维护能力：

- 版本管理。
- 测试。
- 日志。
- 配置。
- Docker。
- 说明。
- 部署验证。

## 必做清单

| 模块 | 要求 |
| --- | --- |
| Git | 至少 8 次清晰提交 |
| Maven | 能执行 `mvn clean 测试` |
| 测试 | Service 和 Controller 都有测试 |
| 日志 | 借阅、归还、登录有关键日志 |
| 配置 | dev/测试 分开 |
| Docker | Compose 启动 MySQL 和应用 |
| 说明 | 写清本地启动和接口示例 |
| 排查记录 | 记录 3 个遇到的问题 |

## 推荐目录结构

```text
book-接口
  源码/主/Java学习资料
  源码/主/资源
  源码/测试/Java学习资料
  SQL学习资料/初始化.SQL学习资料
  Docker构建文件
  Docker-编排.yml
  说明.md
```

## 测试最低要求

- 新增图书成功。
- ISBN 重复失败。
- 借阅成功。
- 库存不足失败。
- 参数非法返回 400。
- 未登录访问返回 401。
- 无权限访问返回 403。
- 借阅第二步失败时事务回滚。

## 说明 最低要求

必须包含：

- 项目简介。
- 技术栈。
- JDK 和 Maven 版本。
- 数据库版本。
- 本地启动步骤。
- Docker 启动步骤。
- 环境变量说明。
- 常用接口示例。
- 测试命令。
- 常见问题。

## 交付物

最终你应该提交：

- 项目代码。
- 数据库初始化脚本。
- Docker 配置。
- 测试代码。
- 说明。
- 一份工程化复盘。

## 复盘模板

```markdown
# 工程化复盘

## 本次改造目标

## 已完成内容

## 测试覆盖了什么

## Docker 怎么启动

## 遇到的问题

## 如何排查和解决

## 仍然可以改进的地方
```

## 本节通过标准

- 新人能按 说明 启动项目。
- `mvn clean 测试` 通过。
- Docker Compose 能启动依赖。
- 至少 5 个关键测试通过。
- 出错时能通过日志定位。
