# 01-阶段目标

## 总目标

这一阶段的目标是把你的 Java 后端项目从“能写接口”推进到“能维护、能验证、能部署、能排查”。

很多小白会把工程化理解成后期才学的东西，其实只要开始做项目，就应该同步建立这些习惯。

## 这一章解决什么痛点

| 痛点 | 工程化能力 |
| --- | --- |
| 代码改坏了不知道 | 自动化测试 |
| 别人拉代码跑不起来 | 说明、Docker、配置说明 |
| 依赖版本冲突 | Maven 依赖树和版本管理 |
| 线上报错不知道原因 | 日志、异常堆栈、请求 ID |
| 开发环境和生产环境配置不同 | Profile、环境变量 |
| 手动部署容易漏步骤 | Docker、CI/CD |

## 最低能力目标

- 能用 Git 独立完成提交、分支、合并和冲突处理。
- 能用 Maven 执行测试、打包和依赖分析。
- 能写JUnit和基本集成测试。
- 能读懂错误日志并定位到代码位置。
- 能用配置文件和环境变量切换环境。
- 能用 Docker Compose 启动 MySQL、未译25173edis 和应用。
- 能写清楚项目启动说明和接口示例。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 工程化 | 让项目可维护、可测试、可部署 | 解决“只有自己电脑能跑”的问题 | 每加一个功能就补测试和文档 | 重点是形成习惯 |
| 自动化 | 把重复检查交给工具 | 减少人工漏测 | 提交前先跑 `mvn clean 测试` | 难点是测试要覆盖失败场景 |
| 可观测性 | 出错后能看见原因 | 避免靠猜排查 | 日志带业务 ID 和耗时 | 重点是不要泄露敏感信息 |
| 环境一致性 | 降低部署差异 | 避免“我这里可以” | 用 Docker 固化依赖 | 难点是配置和数据初始化 |

## 本节练习

- 写出你的项目从开发到部署会经历哪些步骤。
- 列出项目现在最容易出错的 5 个地方。
- 给每个风险配一个工程化手段，例如测试、日志、说明 或 Docker。

## 本节通过标准

- 能解释工程化不是写业务代码之外的杂事。
- 能说清 Git、Maven、测试、日志、Docker 各自解决什么问题。
- 能为自己的项目列出工程化改造清单。
