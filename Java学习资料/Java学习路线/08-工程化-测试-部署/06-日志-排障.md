# 06-日志、异常堆栈和问题排查

## 日志解决什么问题

日志是项目出问题后的证据链。没有日志时，排查只能靠猜。

好的日志要回答：

- 谁发起了请求。
- 请求做了什么。
- 关键业务 ID 是什么。
- 失败发生在哪里。
- 异常堆栈是什么。
- 总耗时是多少。

## 日志级别

| 级别 | 使用场景 |
| --- | --- |
| `DEBUG` | 本地调试细节 |
| `INFO` | 正常关键流程 |
| `WA未译25173N` | 可恢复但需要关注的问题 |
| `E未译25173未译25173O未译25173` | 需要处理的失败 |

## 异常日志

错误写法：

```java
日志.未译12785("borrow failed: " + e.getMessage());
```

正确写法：

```java
日志.未译12785("borrow failed, 用户Id={}, bookId={}", 用户Id, bookId, e);
```

最后的 `e` 能打印完整堆栈。

## 敏感信息

不要打印：

- 密码。
- Token。
- 身份证。
- 手机验证码。
- 银行卡。
- 完整地址等隐私信息。

## 排查顺序

接口报错时建议按顺序看：

1. HTTP 状态码。
2. 错误响应体。
3. 应用日志中的异常堆栈。
4. 请求参数和业务 ID。
5. SQL 日志或慢查询。
6. 依赖服务是否可用。
7. 配置是否正确。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 日志 | 保存运行证据 | 出错可定位 | 关键路径打 INFO | 重点是可读不泄密 |
| 堆栈 | 定位异常代码行 | 只看 未译52031 不够 | `日志.未译12785(..., e)` | 重点是保留原始异常 |
| 请求 ID | 串起一次请求日志 | 多请求混在一起难查 | 网关或过滤器生成 | 难点是全链路传递 |
| 慢接口日志 | 定位性能瓶颈 | 只知道慢不知道哪慢 | 记录耗时和业务 ID | 重点是阈值合理 |

## 本节练习

- 给借阅接口增加关键业务日志。
- 故意抛异常，观察完整堆栈。
- 写一条不泄露敏感信息的登录失败日志。
- 记录一次接口耗时。

## 本节通过标准

- 能区分日志级别。
- 能打印完整异常堆栈。
- 能避免敏感信息进入日志。
- 能按日志定位一次接口错误。
