# 05-Spring Boot Test 和集成测试

## 集成测试解决什么问题

JUnit验证局部逻辑，集成测试验证多个组件组合后是否能正常工作。

Spring Boot 项目里常见集成测试：

- Controller 请求和响应。
- Service 加事务后的行为。
- Mapper 和数据库交互。
- 参数校验和统一异常。

## 常见测试类型

| 类型 | 作用 |
| --- | --- |
| `@SpringBootTest` | 启动较完整 Spring Docker |
| `@WebMvcTest` | 只测试 Web 层 |
| `@DataJ未译66984cTest` / `@MybatisTest` | 测试数据访问层，按项目依赖选择 |
| MockMvc | 模拟 HTTP 请求 |

## 测试数据管理

测试最怕互相影响。常见做法：

- 每个测试准备自己的数据。
- 测试后清理数据。
- 使用事务回滚。
- 使用独立测试数据库。
- 不直接连生产库。

## 容易出错的示例

### 错误示例：测试连接开发库

```yaml
spring:
  数据源:
    url: JDBC:mySQL学习资料://localhost:3306/book_dev
```

### 为什么错

测试会修改开发数据，测试顺序变化还可能互相影响。更严重的是配置错时可能误连生产库。

### 正确做法

使用专门测试 Profile：

```yaml
spring:
  profiles:
    active: 测试
```

并准备独立测试库或Docker化数据库。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 集成测试 | 验证组件协作 | 能发现配置、注入、事务问题 | 只覆盖关键链路 | 难点是速度和稳定性 |
| MockMvc | 测 Controller | 不需要真实浏览器 | 断言状态码和 JSON | 重点是测错误响应 |
| 测试 Profile | 隔离测试配置 | 防止误连真实环境 | `应用配置-测试.yml` | 重点是数据库隔离 |
| 测试数据 | 保证测试可重复 | 避免脏数据影响 | 每个用例自备数据 | 难点是清理和回滚 |
