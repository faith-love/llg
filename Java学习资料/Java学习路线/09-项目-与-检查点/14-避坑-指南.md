# 14-难点错误示例和避坑指南

## 坑 1：项目贪大

### 错误示例

```text
我要做完整商城：商品、订单、支付、秒杀、推荐、微服务、分库分表。
```

### 为什么错

小白阶段很容易做不完，最后没有一个可演示闭环。

### 正确做法

先做简化版订单系统，重点放在下单、扣库存、状态流转和幂等。

### 避坑口诀

项目先闭环，再扩展。

## 坑 2：只有 CRUD，没有业务规则

### 错误示例

图书只做新增、删除、修改、查询，没有借阅、库存、权限、异常。

### 为什么错

面试时很难展示后端核心能力。

### 正确做法

增加业务规则：库存不足不能借、重复借阅不能借、归还恢复库存、管理员才能维护图书。

### 避坑口诀

业务规则才是项目含金量。

## 坑 3：数据库没有初始化脚本

### 错误做法

```text
表都是我本地手动建的。
```

### 为什么错

别人无法复现项目，部署也容易漏表或漏数据。

### 正确做法

提供 `SQL学习资料/初始化.SQL学习资料`。

### 避坑口诀

没有建库脚本，项目不可复现。

## 坑 4：接口错误全部 200

### 错误示例

库存不足、未登录、参数错误都返回 HTTP 200。

### 为什么错

客户端和监控无法区分成功和失败。

### 正确做法

按错误类型返回 400、401、403、404、409 等状态码。

### 避坑口诀

状态码表达类别，错误码表达原因。

## 坑 5：事务边界讲不清

### 错误说法

```text
我在项目里用了事务。
```

### 为什么错

没有说明事务保护哪些操作，也没有说明失败后如何回滚。

### 正确说法

```text
借阅时新增借阅记录和扣减库存必须在同一个事务里，任何一步失败都要回滚。
```

### 避坑口诀

事务要讲业务动作，不讲注解名字。

## 坑 6：测试只测成功

### 错误示例

只有新增成功、查询成功、借阅成功。

### 为什么错

项目最容易出错的是失败路径。

### 正确做法

补充库存不足、重复 ISBN、未登录、无权限、事务回滚测试。

### 避坑口诀

失败场景决定项目可靠性。

## 坑 7：面试只报技术栈

### 错误说法

```text
项目用了 Spring Boot、MyBatis、MySQL、Redis。
```

### 为什么错

这只能说明用过工具，不能说明解决了什么问题。

### 正确说法

讲清场景、问题、方案、取舍、结果。

### 避坑口诀

技术名词不是项目讲法。
