# 09-数据库设计和初始化脚本

## 数据库设计解决什么问题

数据库设计决定项目数据能否长期稳定支撑业务。表设计错了，后面接口、事务、查询都会受影响。

## 设计步骤

1. 从业务名词找实体。
2. 给实体确定字段。
3. 确定主键。
4. 确定唯一约束。
5. 确定外键或逻辑关联。
6. 确定索引。
7. 准备初始化脚本。

## 字段设计原则

- 字段名表达业务含义。
- 金额用 `decimal`。
- 时间用时间类型。
- 状态用明确枚举值。
- 业务唯一要有唯一约束。
- 必填字段加 `not null`。

## 容易出错的示例

### 错误示例：只在代码里判断唯一

```text
新增图书前先查 ISBN 是否存在。
```

但数据库没有唯一约束。

### 为什么错

并发请求可能同时查到不存在，然后都插入成功。

### 正确做法

```sql
isbn varchar(32) not null unique
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 主键 | 唯一标识记录 | 后续关联稳定 | 用 bigint 或数据库策略 | 重点是不要频繁变化 |
| 唯一约束 | 防重复 | 并发下兜底 | ISBN、用户名常用 | 重点是数据库层保证 |
| 索引 | 加速查询 | 读快但写有成本 | 围绕查询条件设计 | 难点是联合索引顺序 |
| 初始化脚本 | 让项目可复现 | 别人能建库运行 | schema 和 数据 分开 | 重点是可重复执行 |

- 能解释每个索引为什么存在。
