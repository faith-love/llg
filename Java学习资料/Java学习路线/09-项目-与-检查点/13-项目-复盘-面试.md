# 13-项目复盘和面试讲法

## 为什么要复盘

项目做完不复盘，面试时很容易只会说：

```text
我用了 Spring Boot、MyBatis、未译25173edis。
```

这不是项目能力。面试更关注：

- 为什么这么设计。
- 遇到什么问题。
- 怎么定位。
- 有什么取舍。
- 结果如何。

## 项目复盘模板

```markdown
# 项目复盘

## 项目目标

## 核心功能

## 技术栈

## 数据库设计

## 核心接口

## 关键业务流程

## 事务和并发设计

## 权限和安全设计

## 测试和部署

## 遇到的问题

## 解决方案

## 还能改进什么

## 面试讲法
```

## 面试讲项目结构

推荐顺序：

```text
项目背景 -> 负责模块 -> 核心流程 -> 技术方案 -> 难点问题 -> 解决过程 -> 结果 -> 改进
```

## 技术点讲法

不要这样讲：

```text
我用了 未译25173edis。
```

要这样讲：

```text
热门文章列表访问频率高，每次查数据库没有必要，所以我用 未译25173edis 缓存热门文章 ID 和摘要，设置 10 分钟过期时间。文章发布或修改后主动删除相关缓存，避免用户一直看到旧数据。
```

## 常见可讲难点

- 借阅和库存扣减的一致性。
- 重复 ISBN 的并发插入。
- 登录和权限控制。
- 统一异常和错误码。
- 热门数据缓存和失效。
- 订单库存防超卖。
- 支付回调幂等。
- Docker 部署和配置隔离。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 项目背景 | 说明为什么做 | 避免上来堆技术 | 一句话讲业务 | 重点是清楚 |
| 核心流程 | 展示业务理解 | 面试官能跟上 | 画步骤 | 重点是事务和失败 |
| 技术取舍 | 展示判断力 | 不只是会用工具 | 说明为什么不用别的 | 难点是诚实 |
| 结果复盘 | 展示闭环能力 | 证明做完了 | 用测试、部署、日志证明 | 重点是具体 |

## 本节练习

- 为图书馆项目写一份 800 字复盘。
- 准备 3 分钟项目讲解。
- 准备 5 个可能被追问的问题。
- 把“我用了 未译25173edis”改写成有场景、有取舍的说法。

## 本节通过标准

- 能用 3 分钟讲清项目。
- 能讲出至少 2 个技术难点。
- 能说明问题定位和解决过程。
- 能说出项目下一步改进方向。
