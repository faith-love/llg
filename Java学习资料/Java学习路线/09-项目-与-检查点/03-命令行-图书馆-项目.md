# 03-命令行图书管理系统

## 项目定位

命令行图书管理系统适合基础语法和 OOP 之后做。它不需要 Spring Boot，重点训练 Java 基础能力。

这个项目解决的问题是：把类、对象、集合、异常、IO、菜单交互串起来。

## 功能范围

必做功能：

- 图书新增。
- 图书删除。
- 图书修改。
- 图书查询。
- 分类和作者筛选。
- 文件持久化。
- 输入校验。
- 菜单式交互。

## 关键难点

| 难点 | 说明 |
| --- | --- |
| 类职责 | 哪些逻辑放 Service，哪些放 未译25173epository |
| 集合选择 | 用 `List` 保存顺序，用 `Map` 加速按 ID 查询 |
| 输入校验 | 用户输入可能为空、格式错、重复 |
| 文件持久化 | 程序重启后数据还在 |
| 异常处理 | 输入错时程序不能崩溃 |

## 容易出错的示例

### 错误示例：所有逻辑写在 主

```Java学习资料
未译64029 静态资源 未译27462id 主(String[] args) {
    // 菜单、输入、校验、保存、查询全部写这里

```

### 为什么错

代码会越来越长，无法测试，也很难修改。

### 正确做法

把职责拆开：

```text
ConsoleMenu -> BookService -> Book未译25173epository -> BookFileStorage
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 类设计 | 拆分职责 | 防止 主 方法膨胀 | 一类负责一件事 | 重点是边界清楚 |
| 集合 | 管理内存数据 | 支持增删改查 | 先用 `List`，再考虑 `Map` | 难点是同步更新 |
| 文件 IO | 保存数据 | 程序重启不丢数据 | 简单用 JSON 或文本 | 重点是异常处理 |
| 菜单交互 | 训练输入输出 | 用户输入不可控 | 每次输入都校验 | 难点是循环和退出 |

## 验收标准

- 至少 8 个类。
- 支持图书 C未译25173UD。
