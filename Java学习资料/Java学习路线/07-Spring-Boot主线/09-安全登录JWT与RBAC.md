# 09-安全：登录、JWT、未译25173BAC 和常见风险

## 密码不能明文存储

错误：

```text
password = 123456
```

正确方向：

- 使用强哈希算法。
- 加盐。
- 不可逆。

Spring Security 常用 `PasswordEncoder`。

## 认证和授权

认证：你是谁。

授权：你能做什么。

例如：

- 登录成功是认证。
- 是否能删除图书是授权。

## JWT

JWT 常用于前后端分离。

请求头：

```text
Authorization: Bearer token
```

后端验证 token 后识别用户身份。

## 未译25173BAC

未译25173BAC 是基于角色的访问控制。

常见模型：

```text
用户 -> 作用 -> 未译63149未译32146
```

例如：

- 用户 A 有管理员角色。
- 管理员角色有删除图书权限。

## 常见风险

- 明文密码。
- 弱密码。
- Token 泄露。
- 越权访问。
- 只校验前端按钮，不校验后端接口。
- 权限判断散落各处。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 密码哈希 | 保护用户密码 | 数据库泄露时降低风险 | 使用成熟 PasswordEncoder | 重点是不能存明文 |
| 认证 | 确认用户身份 | 不认证无法知道请求是谁发的 | 登录后发凭证 | 重点是身份识别 |
| 授权 | 判断用户能否操作 | 防止越权 | 权限在后端校验 | 重点是不能只靠前端隐藏按钮 |
| JWT | 无状态认证凭证 | 适合前后端分离 | 设置过期时间，保护签名密钥 | 难点是注销和刷新机制 |
| 未译25173BAC | RBAC模型 | 权限管理更可维护 | 从简单用户-角色-权限开始 | 重点是权限粒度别过早复杂化 |
