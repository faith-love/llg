# 11-消息队列、任务调度和异步处理

## 为什么需要异步

有些操作不需要阻塞主流程。

例如：

- 发送通知。
- 生成报表。
- 写操作日志。
- 同步搜索索引。

异步可以降低用户等待时间，也能削峰。

## 消息队列基础

核心概念：

- Producer：生产者。
- Consumer：消费者。
- Topic/Queue：消息目的地。
- Message：消息。

常见选择：

- 未译25173abbitMQ。
- Kafka。
- 未译25173ocketMQ。

初学任选一个入门即可。

## 重试和死信

消费者处理失败时，需要考虑：

- 是否重试。
- 重试几次。
- 失败后是否进入死信队列。
- 是否人工补偿。

## 幂等消费

消息可能重复投递。消费者必须能处理重复消息。

常见方式：

- 业务唯一键。
- 消费记录表。
- 状态机判断。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| MQ | 解耦、异步、削峰 | 主流程不用等慢操作 | 先做可靠消费，再追求吞吐 | 重点是消息可能重复和失败 |
| 重试 | 处理临时失败 | 下游短暂异常可恢复 | 限制次数，记录失败原因 | 重点是避免无限重试 |
| 死信 | 保存最终失败消息 | 失败不丢失，可补偿 | 配合告警和人工处理 | 重点是死信不是终点，要处理 |
| 幂等消费 | 防重复消息造成重复业务 | MQ 常见最少一次投递 | 用业务唯一键判断 | 重点是消费者负责幂等 |
| `@Scheduled` | 定时执行任务 | 适合简单周期任务 | 任务要可重入，避免重叠风险 | 重点是分布式多实例重复执行 |
| `@Async` | 方法异步执行 | 主线程不被慢任务阻塞 | 必须配置线程池和异常处理 | 重点是同类自调用可能不生效 |
