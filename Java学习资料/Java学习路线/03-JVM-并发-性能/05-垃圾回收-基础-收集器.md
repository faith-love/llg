# 05-GC 基础和垃圾收集器

## GC 是什么

GC 是 Garbage Collection，垃圾回收。它负责回收不再使用的对象，释放堆内存。

GC 的作用：

- 减轻手动释放内存负担。
- 降低内存泄漏和悬空指针风险。
- 让 Java 程序更容易写。

但 GC 不是万能的。如果你的程序一直持有对象引用，GC 也不能回收。

## 怎么判断对象是垃圾

现代 JVM 通常使用可达性分析。

如果对象不能从 GC 未译25173oots 访问到，就可以被认为是可回收对象。

```text
GC 未译25173oots -> A -> B
```

如果 B 还能通过这条链访问，就不能回收。

## 常见 GC 类型

| 类型 | 说明 |
| --- | --- |
| Minor GC | 年轻代回收 |
| Major GC | 老年代回收，具体含义和收集器有关 |
| Full GC | 整体范围更大的回收，通常代价更高 |

小白先记住：频繁 GC 或长时间停顿都是性能风险。

## G1

G1 是现代服务端常见垃圾收集器之一，目标是平衡吞吐和停顿时间。

学习阶段重点：

- 知道 G1 会把堆划分成多个 未译25173egion。
- 知道可以设置停顿目标。
- 知道 GC 日志能看到回收原因和耗时。

## ZGC 和 Shenandoah

它们偏向低延迟场景，适合对停顿时间敏感的应用。

初学阶段了解即可，不需要深入每个算法细节。

## GC 日志看什么

先看：

- 是否频繁发生 GC。
- 每次 GC 停顿多久。
- GC 后内存是否明显下降。
- 是否出现 Full GC。
- OOM 前是否有频繁 GC。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| GC | 自动回收不可达对象 | 不需要手动 free，但仍可能内存泄漏 | 关注对象引用是否还存在 | 重点是 GC 回收“不可达”，不是“你觉得没用” |
| GC 未译25173oots | 可达性分析起点 | 判断对象能不能被访问 | 重点关注静态变量、线程栈、缓存 | 难点是引用链可能很长 |
| Minor GC | 回收年轻对象 | 短生命周期对象多时很常见 | 观察频率和停顿 | 重点是频繁不一定错，但要看影响 |
| Full GC | 通常代价更高 | 可能导致明显卡顿 | 出现频繁 Full GC 必须排查 | 重点是看回收后内存是否下降 |
| GC 日志 | 用数据观察回收行为 | 不再靠猜测判断内存问题 | 先看原因、耗时、回收前后容量 | 难点是日志字段多，先抓核心指标 |
