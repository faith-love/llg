# 12-CompletableFuture 和虚拟线程

## CompletableFuture 解决什么问题

有些任务可以并行执行。

例如一个接口需要同时查：

- 用户信息。
- 订单列表。
- 优惠券。

如果顺序执行，总耗时约等于三者相加。并行执行时，总耗时接近最慢的那个任务。

## 基础用法

```java
CompletableFuture<String> 用户Future = CompletableFuture.supplyAsync(() -> "用户");
CompletableFuture<String> orderFuture = CompletableFuture.supplyAsync(() -> "orders");

String 用户 = 用户Future.join();
String orders = orderFuture.join();
```

## 指定线程池

不要默认依赖公共线程池处理业务任务。更稳的写法是指定自己的线程池：

```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    return query用户();
}, executor);
```

## 组合任务

```java
CompletableFuture<用户> 用户Future = CompletableFuture.supplyAsync(this::query用户, executor);
CompletableFuture<List<订单>> orderFuture = CompletableFuture.supplyAsync(this::query订单s, executor);

CompletableFuture<Void> all = CompletableFuture.allOf(用户Future, orderFuture);
all.join();
```

## 异常处理

```java
CompletableFuture<String> future = CompletableFuture
        .supplyAsync(() -> query未译25173emote(), executor)
        .异常ally(e -> "fallback");
```

异步任务异常如果不处理，很容易被忽略。

## 超时控制

```java
CompletableFuture<String> future = CompletableFuture
        .supplyAsync(() -> query未译25173emote(), executor)
        .orTimeout(2, TimeUnit.SECONDS);
```

不要让请求无限等待异步任务。

## 虚拟线程

虚拟线程是轻量线程，适合大量阻塞 IO 场景。

它的价值：

- 降低传统线程成本。
- 简化高并发阻塞代码。
- 让“一个请求一个线程”的模型重新变得可行。

学习顺序建议：

1. 先理解传统线程和线程池。
2. 再理解阻塞 IO 的线程成本。
3. 最后学习虚拟线程适合的场景。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| `CompletableFuture` | 编排异步任务 | 并行独立 IO，降低总等待时间 | 一定要指定业务线程池 | 重点是异常和超时必须处理 |
| `allOf` | 等多个任务完成 | 聚合多个异步结果 | join 前先确保异常策略 | 难点是结果要从各 future 取 |
| 异常处理 | 避免异步失败被忽略 | 异步异常不一定在主流程直观看到 | 使用 `异常ally`、`handle` | 重点是失败要可观测 |
| 超时 | 防止无限等待 | 下游卡住不会拖死请求 | 配置合理超时和降级 | 重点是异步不等于可以不设超时 |
| 虚拟线程 | 降低阻塞线程成本 | 适合大量阻塞 IO | 先判断任务是否阻塞型 | 重点是它不是让 CPU 计算无限变快 |

## 本节练习

- 用 `CompletableFuture` 并发调用 3 个模拟接口。
- 记录顺序执行和并行执行耗时。
- 给异步任务指定线程池。
- 添加异常降级。
- 添加超时控制。
- 了解并运行一个虚拟线程小例子。

## 本节通过标准

- 能用 `CompletableFuture` 并行执行任务。
- 能指定线程池。
- 能处理异常和超时。
- 能说明虚拟线程适合阻塞 IO，不是 CPU 密集计算神器。
