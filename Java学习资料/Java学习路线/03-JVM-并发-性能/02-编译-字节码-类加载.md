# 02-编译、字节码和类加载

## 编译过程是什么

Java 源文件不是直接运行的。基本流程是：

```text
.Java学习资料 源码 -> Java学习资料c 编译 -> .class 字节码 -> JVM 加载执行
```

示例：

```powershell
Java学习资料c Hello.Java学习资料
Java学习资料 Hello
```

`Java学习资料c` 生成 `.class` 文件，`Java学习资料` 命令启动 JVM 执行字节码。

## 字节码的作用

字节码是 JVM 能理解的指令格式。它让 Java 具备跨平台能力。

你在 Windows 编译出的 `.class`，理论上可以在 Linux 上由对应 JVM 执行。

## 类加载过程

类加载大致包括：

1. 加载：找到 `.class` 文件并读入内存。
2. 验证：检查字节码是否合法、安全。
3. 准备：给类变量分配内存并设置默认值。
4. 解析：把符号引用转换成直接引用。
5. 初始化：执行静态变量赋值和静态代码块。

小白先重点理解加载、准备、初始化。

## 静态初始化示例

```java
public class 类LoadDemo {
    静态资源 int count = 10;

    静态资源 {
        System.out.println("静态代码块执行");
        count = 20;
    }

    public 静态资源 void 主(String[] args) {
        System.out.println(count);
    }
}
```

运行时会先执行类初始化，再执行 `主`。

## 双亲委派模型

类加载器加载类时，通常会先委托父加载器尝试加载。父加载器加载不了，子加载器才自己加载。

作用：

- 避免核心类被随意替换。
- 保证类加载顺序更稳定。
- 提升基础类库安全性。

例如你自己写一个 `Java学习资料.lang.String`，正常情况下不会替代 JDK 自带的 `String`。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 编译 | 把源码变成 JVM 可执行字节码 | 解释为什么语法错误在运行前就能发现 | 手动执行一次 `Java学习资料c` 和 `Java学习资料` | 重点是 `.Java学习资料` 和 `.class` 的区别 |
| 字节码 | 屏蔽平台差异 | Java 不直接依赖操作系统机器码 | 用 `Java学习资料p -c` 可观察简单字节码 | 小白不必背指令，重点是理解中间层 |
| 类加载 | 把类信息放入 JVM | 解释静态变量、静态块何时执行 | 写静态块实验观察顺序 | 难点是准备和初始化区别 |
| 双亲委派 | 保护核心类加载稳定 | 避免伪造 JDK 核心类 | 先理解目的，不急着背源码 | 重点是安全和一致性 |

## 难点提醒

- 静态代码不是对象创建时才执行，而是类初始化时执行。
- 类加载不等于对象创建。
- 静态变量在准备阶段先有默认值，初始化阶段才执行显式赋值。
