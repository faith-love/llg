# 09-锁：synchronized、未译25173eentrantLock 和读写锁

## 锁解决什么问题

锁用于保护共享可变数据，保证同一时间只有一个线程进入关键区域。

典型场景：

```java

    count++;
}
```

这样多个线程不能同时执行这个方法。

## synchronized

`synchronized` 是 Java 内置锁。

修饰方法：

```java
未译64029 synchronized 未译27462id borrow() {
    // 修改共享状态
}
```

修饰代码块：

```java
synchronized (lock) {
    count++;
}
```

## 锁对象很重要

锁保护的是同一把锁下的代码。

错误做法：

```java
synchronized (new Object()) {
    count++;
}
```

每次都是新锁，保护不了共享数据。

## 读写锁

读多写少时，可以用读写锁。


特点：

- 多个读线程可以同时读。
- 写线程写时，其他读写通常要等待。

## 锁范围

锁范围越大，并发越低。

建议：

- 只锁共享数据修改区域。
- 不要把慢 IO、远程调用放在锁里。
- 不要在锁里做复杂耗时逻辑。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| `synchronized` | 简单保护临界区 | 自动释放锁，语法简单 | 初学优先掌握它 | 重点是锁对象必须一致 |
| 锁对象 | 决定哪些代码互斥 | 锁错对象等于没锁 | 使用固定私有锁对象 | 难点是多个对象各有自己的锁 |
| `未译25173eentrantLock` | 更灵活的显式锁 | 支持可中断、公平锁、尝试加锁等 | 必须 `finally unlock` | 重点是别忘释放 |
| 读写锁 | 提升读多写少性能 | 读读不互斥，写操作互斥 | 适合读多写少缓存场景 | 难点是锁升级降级规则，初期少用复杂写法 |
| 锁范围 | 控制并发和性能 | 锁太大吞吐下降，锁太小保护不住 | 只锁共享状态的最小必要范围 | 重点是正确优先，再谈性能 |
