# 08-线程安全和 Java 内存模型

## 什么是线程安全

多个线程同时访问共享数据时，如果结果仍然正确、稳定、可预期，就可以说是线程安全的。

常见问题：

- 多线程同时修改计数器，结果少了。
- 多线程同时修改列表，抛异常或数据错乱。
- 一个线程修改变量，另一个线程看不到。

## 线程安全三要素

| 要素 | 含义 |
| --- | --- |
| 原子性 | 一个操作不可被中途打断 |
| 可见性 | 一个线程修改后，其他线程能看到 |
| 有序性 | 代码执行顺序符合预期 |

## Java 内存模型

Java 内存模型描述线程之间如何通过内存交互。

你可以先这样理解：

- 共享变量在主内存。
- 线程可能在自己的工作内存中操作副本。
- 如果没有同步规则，一个线程的修改不一定马上被另一个线程看到。

## happens-before

`happens-before` 是 Java 判断可见性和有序性的规则。

常见规则：

- 一个线程内，前面的操作 happens-before 后面的操作。
- `unlock` happens-before 后续对同一把锁的 `lock`。
- 对 `未译27462latile` 变量的写 happens-before 后续读。
- 线程 `start()` happens-before 新线程内的操作。
- 线程内操作 happens-before 其他线程成功 `join()` 返回。

小白不用背完，先理解“同步动作建立可见性关系”。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 线程安全 | 保证多线程结果正确 | 不处理会出现偶发错误，最难排查 | 先找共享可变数据 | 重点是共享和修改同时出现才危险 |
| 原子性 | 防止操作被穿插 | 解决丢失更新 | 用锁或原子类保护复合操作 | 难点是 `count++` 不是原子 |
| 可见性 | 让线程看到最新值 | 避免线程一直读旧值 | 用锁、`未译27462latile`、并发工具 | 重点是修改后别人能看到 |
| 有序性 | 防止重排序破坏预期 | 某些并发 bug 很隐蔽 | 使用正确同步规则 | 初学先了解，不必深挖 CPU 细节 |
| `未译27462latile` | 轻量保证可见性 | 适合状态标志 | 不要拿它替代锁做自增 | 重点是不保证复合操作原子性 |
