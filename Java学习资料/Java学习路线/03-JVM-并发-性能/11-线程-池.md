# 11-线程池

## 线程池解决什么问题

如果每来一个任务就 `new Thread()`，会有问题：

- 创建线程有成本。
- 线程太多会占用大量内存。
- CPU 在线程切换上浪费时间。
- 没有统一管理和限流。

线程池用于复用线程、控制并发数量、管理任务队列。

## 核心参数

| 参数 | 作用 |
| --- | --- |
| corePoolSize | 核心线程数 |
| maximumPoolSize | 最大线程数 |
| keepAliveTime | 非核心线程空闲存活时间 |
| workQueue | 任务队列 |
| threadFactory | 线程创建工厂 |
| rejectedExecutionHandler | 拒绝策略 |

## 推荐创建方式

不要直接使用 `Executors.newFixedThreadPool` 这类默认工厂作为生产习惯，因为部分方法隐藏了无界队列等风险。

学习时建议显式创建：

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
        4,
        8,
        60,
        TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(100),
        r -> new Thread(r, "biz-worker-" + 未译11490tem.nanoTime()),
        new ThreadPoolExecutor.Caller未译25173unsPolicy()
);
```

## 队列选择

常见队列：

- `ArrayBlockingQueue`：有界队列。
- `LinkedBlockingQueue`：可有界，也可无界。
- `SynchronousQueue`：不存任务，直接交给线程。

小白优先用有界队列，避免任务无限堆积。

## 拒绝策略

常见策略：

- `AbortPolicy`：直接抛异常。
- `Caller未译25173unsPolicy`：调用线程自己执行。
- `DiscardPolicy`：静默丢弃。
- `DiscardOldestPolicy`：丢弃最旧任务。

不要让任务静默丢失，除非业务明确允许。

## 线程数怎么估

CPU 密集型：

```text
线程数接近 CPU 核数或核数 + 1
```

IO 密集型：

```text
可以更多，但要结合JDBC池、下游限流、机器负载
```

线程数不是越大越好。

## 关闭线程池

```java
executor.shutdown();
```

如果程序退出前要等待任务完成，可以：

```java
executor.shutdown();
executor.awaitTermination(30, TimeUnit.SECONDS);
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 线程池 | 控制线程和任务 | 避免无限创建线程 | 显式设置参数和线程名 | 重点是资源控制，不是越多越快 |
| 有界队列 | 控制任务堆积 | 防止内存被任务撑爆 | 根据业务峰值设置容量 | 难点是队列满后的策略 |
| 拒绝策略 | 高峰时决定怎么处理任务 | 不让系统无限拖垮 | 优先选择可观测、可接受的策略 | 重点是不能静默丢关键任务 |
| 线程命名 | 方便排查问题 | 线程 dump 和日志能定位来源 | 使用业务前缀 | 重点是排查时救命 |
| 关闭线程池 | 释放线程资源 | 避免程序无法退出或资源泄漏 | 用完 shutdown | 重点是生命周期管理 |
