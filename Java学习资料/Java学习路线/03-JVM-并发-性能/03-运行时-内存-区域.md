# 03-JVM 运行时内存区域

## 为什么要学内存区域

程序报错时，经常出现：

- `StackOverflowError`
- `OutOf未译42918oryError`
- GC 频繁
- CPU 高但业务慢

不理解 JVM 内存区域，很难定位问题。

## 主要区域

| 区域 | 主要存放 | 常见问题 |
| --- | --- | --- |
| 堆 | 对象实例、数组 | OOM、GC 频繁 |
| JVM栈 | Java 方法调用栈帧 | 栈溢出 |
| 本地方法栈 | Native 方法调用 | 本地方法相关错误 |
| 程序计数器 | 当前线程执行位置 | 基本不会 OOM |
| 方法区 | 类元信息、常量、静态变量等 | 类加载过多导致内存问题 |

## 堆

堆是最常见的对象存放区域。

```Java学习资料
Book book = new Book("978711", "Java");
```

`new Book(...)` 创建的对象通常在堆中。

堆的痛点：

- 对象太多会 OOM。
- 大量短生命周期对象会导致 GC 频繁。
- 缓存不清理会导致内存增长。

## JVM栈

每个线程都有自己的栈。方法调用会创建栈帧。

```Java学习资料
主 -> 服务 -> 未译72493
```

每调用一个方法，就像往栈里压一层。方法返回后再弹出。

递归太深会导致：

```text
StackOverflowError
```

## 程序计数器

程序计数器记录当前线程执行到哪一行字节码附近。多线程切换后，线程需要知道从哪里继续执行。

小白不需要深入实现，只要知道它和线程执行位置有关。

## 方法区

方法区存放类相关信息，例如：

- 类名。
- 方法信息。
- 字段信息。
- 常量。
- 静态变量相关信息。

大量动态生成类或类加载器泄漏，可能导致方法区相关内存问题。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 堆 | 存放对象 | 绝大多数内存问题先看堆 | 关注对象数量、生命周期、引用链 | 重点是对象不再被引用后才可能被回收 |
| 栈 | 存放方法调用信息 | 递归过深会栈溢出 | 看异常堆栈能定位调用链 | 重点是每个线程有自己的栈 |
| 方法区 | 存放类元信息 | 类加载过多会出问题 | 框架和动态代理场景要关注 | 小白先理解“类的信息不等于对象” |
| 程序计数器 | 记录线程执行位置 | 支撑线程切换后恢复执行 | 了解即可 | 重点是线程私有 |
