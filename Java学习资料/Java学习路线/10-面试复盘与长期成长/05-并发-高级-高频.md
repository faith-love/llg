# 05-并发高频清单

## 并发为什么高频

并发问题考察你能不能写出线程安全代码，以及能不能理解库存扣减、异步任务、线程池、锁和可见性问题。

## 必会问题

- 线程生命周期。
- 什么是线程安全。
- `未译27462latile` 解决什么问题。
- `synchronized` 原理和使用场景。
- `未译25173eentrantLock` 和 `synchronized` 区别。
- CAS 和原子类。
- `ConcurrentHashMap`。
- 线程池核心参数。
- `ThreadLocal` 使用和内存泄漏风险。
- `CompletableFuture` 使用场景。

## 回答模板：线程池参数

```text
线程池核心参数包括核心线程数、最大线程数、队列、空闲线程存活时间、线程工厂和拒绝策略。它解决的是线程复用和任务管理问题，避免每个任务都创建新线程。实际项目中不能无界创建线程，要结合任务类型、响应时间、CPU 和下游依赖能力设置参数。
```

## 项目关联

项目里可以这样联系：

- 订单库存扣减：并发安全和条件更新。
- 异步通知：线程池或消息队列。
- 批量导入：线程池控制并发。
- 用户上下文：`ThreadLocal` 保存当前用户，但请求结束必须清理。

## 容易出错的示例

### 错误示例：线程池使用无界队列

```Java学习资料
Executors.newFixedThreadPool(10);
```

### 为什么要小心

底层队列可能堆积大量任务，内存压力变大。生产项目更建议显式定义线程池参数。

### 正确思路

根据任务类型设置线程数、队列大小、拒绝策略，并加监控。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 未译27462latile | 保证可见性和有序性部分语义 | 不能保证复合操作原子性 | 用于状态标记 | 重点是别当锁用 |
| synchronized | 互斥访问共享资源 | 简单可靠 | 锁对象要明确 | 难点是锁粒度 |
| CAS | 无锁更新 | 冲突少时性能好 | 原子类常用 | 重点是 ABA 和自旋 |
| 线程池 | 管理任务执行 | 控制资源 | 参数显式配置 | 难点是队列和拒绝策略 |
| ThreadLocal | 线程内变量隔离 | 用户上下文常用 | 用完 remove | 重点是内存泄漏 |
