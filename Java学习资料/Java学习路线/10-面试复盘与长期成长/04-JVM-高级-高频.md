# 04-JVM 高频清单

## JVM 为什么高频

JVM 相关问题主要考察你是否理解 Java 程序如何运行，以及出问题时能不能排查内存、线程和类加载问题。

## 必会问题

- 类加载过程。
- 双亲委派模型。
- JVM 内存区域。
- 对象创建过程。
- GC Roots。
- 常见垃圾收集器。
- Minor GC、Major GC、Full GC 的理解。
- OOM 类型和排查。
- CPU 高如何排查。
- 线程阻塞如何排查。

## 回答模板：JVM 内存区域

```text
JVM 运行时内存主要包括堆、方法区、JVM栈、本地方法栈和程序计数器。堆主要存放对象实例，是 GC 关注的重点；栈保存方法调用帧、局部变量等；方法区保存类元数据等信息。排查内存问题时，要先判断是堆 OOM、元空间 OOM，还是线程过多导致的栈相关问题。
```

## 排查思路

CPU 高：

```text
top 找进程
找高 CPU 线程
转换线程 ID
脚本tack 查看线程栈
定位代码
```

内存高：

```text
确认进程
看 GC 日志
dump 堆
分析大对象和引用链
定位泄漏来源
```

## 容易出错的示例

### 错误说法：OOM 都是堆不够大

### 为什么错

OOM 可能来自：

- Java heap space。
- Metaspace。
- unable to create new native thread。
- Direct buffer memory。

### 正确做法

先看具体错误类型，再决定是调参数、修泄漏还是限制线程。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 类加载 | 把 class 变成可用类 | 理解框架加载和隔离 | 记加载、验证、准备、解析、初始化 | 难点是初始化时机 |
| 双亲委派 | 保证类加载安全和一致 | 避免核心类被替换 | 从父加载器开始 | 重点是为什么需要 |
| 堆 | 存对象 | 内存问题高发 | 配合 GC 理解 | 重点是引用链 |
| GC Roots | 判断对象是否可达 | 理解对象回收 | 栈变量、静态字段等 | 难点是可达性 |
| 排查工具 | 定位线上问题 | 不靠猜 | 脚本tack、jmap、jcmd | 重点是先保留现场 |
