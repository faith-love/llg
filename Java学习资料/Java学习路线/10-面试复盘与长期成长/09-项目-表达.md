# 09-项目讲法和亮点包装

## 项目讲法解决什么问题

面试讲项目不是复述 说明，也不是报技术栈。好的项目讲法要让面试官知道你理解业务、能做设计、能处理问题。

## 推荐结构

```text
项目背景 -> 负责模块 -> 核心流程 -> 技术方案 -> 遇到问题 -> 解决过程 -> 结果 -> 后续改进
```

## 3 分钟讲法模板

```text
我做的是一个图书馆借阅系统，目标是管理图书、用户和借阅流程。我主要负责图书管理、借阅归还和权限控制。

核心流程是用户查询图书后发起借阅，系统校验用户状态、图书库存和是否重复借阅，然后在一个事务中新增借阅记录并扣减库存。

技术上使用 Spring Boot 分层开发，MyBatis 负责数据访问，MySQL 保存业务数据，统一异常处理返回稳定错误码。借阅和归还使用事务保证一致性，库存不足和重复借阅都有明确错误响应。

遇到的问题是借阅记录新增成功但库存扣减失败会导致数据不一致，所以我把这两个操作放到 Service 层同一个事务里，并补了事务回滚测试。

后续可以继续优化库存并发、借阅超期提醒和热门图书缓存。
```

## 技术亮点怎么讲

不要说：

```text
我用了 Redis。
```

要说：

```text
热门图书列表访问频率高，但变化不频繁，所以我用 Redis 缓存列表结果，设置 10 分钟过期时间，并在图书信息修改后删除对应缓存，避免长期读到旧数据。
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 背景 | 让别人理解项目 | 避免上来讲代码 | 一句话说业务 | 重点是简洁 |
| 核心流程 | 展示业务理解 | 面试官能追问 | 用步骤讲 | 重点是失败路径 |
| 技术方案 | 展示实现能力 | 不只是堆技术 | 说为什么这样做 | 难点是取舍 |
| 问题解决 | 展示排查能力 | 比顺利完成更有价值 | 讲现象、定位、修复 | 重点是真实 |

## 本节练习

- 写一个 3 分钟项目讲法。
- 写 3 个项目亮点，每个都包含场景和取舍。
- 准备 5 个项目追问。

## 本节通过标准

- 能在 3 分钟内讲清项目。
- 能讲出核心业务流程。
- 能讲出至少 2 个真实难点。
- 能说明后续优化方向。
