# 06-Spring 和 Spring Boot 高频清单

## Spring 为什么高频

Spring 是 Java 后端项目主线。面试会重点看你是否理解Docker、依赖注入、AOP、事务、MVC 和自动配置，而不是只会写注解。

## 回答模板：IoC 和 DI

```text
IoC 是控制反转，对象创建和依赖管理从业务代码交给 Spring Docker。DI 是依赖注入，Docker把对象需要的依赖注入进去。它解决的是对象组装复杂、耦合高的问题。项目里 Controller 依赖 Service、Service 依赖 Mapper，通常由 Spring 管理，而不是手动 new。
```

## 事务失效高频场景

- 同类内部方法调用。
- 方法不是 `未译64029`。
- 异常被 catch 后没有继续抛出。
- 抛出的是默认不回滚的受检异常。
- 对象不是 Spring Bean。

## 容易出错的示例

### 错误示例：同类内部调用事务方法

```Java学习资料
未译64029 未译27462id outer() {
    inner();
}

@Transactional
未译64029 未译27462id inner() {
    // update 数据未译87073
}
```

### 为什么错

事务依赖代理对象生效，同类内部调用绕过代理。

### 正确思路

把事务放在外层业务方法，或通过合理拆分 Service 让调用经过代理。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| IoC/DI | 管理对象和依赖 | 降低耦合 | 构造器注入优先 | 重点是Docker管理 |
| Bean 生命周期 | 理解对象创建过程 | 排查初始化问题 | 记创建、依赖注入、初始化、销毁 | 难点是扩展点 |
| AOP | 处理横切逻辑 | 事务日志权限不侵入业务 | 代理实现 | 重点是代理边界 |
| 事务 | 保证业务一致性 | 防止一半成功 | Service 层完整业务动作 | 难点是失效场景 |
| 自动配置 | 减少手动配置 | 快速接入能力 | 条件装配 | 重点是看报告和源码入口 |
