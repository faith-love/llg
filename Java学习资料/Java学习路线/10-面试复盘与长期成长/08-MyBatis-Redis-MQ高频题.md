# 08-MyBatis、Redis 和 MQ 高频清单

## 为什么这些技术高频

MyBatis、Redis、MQ 是 Java 后端项目里常见的中间层能力。面试重点不是问你会不会配置，而是问你是否理解它们解决什么问题、适合什么场景、有哪些风险。

## MyBatis 高频问题

- MyBatis 相比 JDBC 解决什么问题。
- `#{}` 和 `${}` 区别。
- resultMap 解决什么问题。
- 动态 SQL 常用标签。
- N+1 查询是什么。
- MyBatis 一级缓存和二级缓存了解。
- MyBatis-Plus 适合什么场景。

## Redis 高频问题

- Redis 为什么快。
- 常见数据结构。
- 缓存穿透、击穿、雪崩。
- 缓存和数据库一致性。
- 分布式锁基础。
- 热点 key。

## MQ 高频问题

- 为什么需要消息队列。
- 异步、削峰、解耦分别是什么意思。
- 消息重复消费怎么办。
- 消息丢失怎么办。
- 消息积压怎么办。
- 顺序消息了解。

## 回答模板：Redis 缓存

```text
Redis 常用于缓存访问频率高、变化不太频繁的数据，减少数据库压力。项目里热门文章列表可以缓存，但要设置过期时间，并在文章发布或修改后主动删除相关缓存。风险是缓存穿透、击穿、雪崩和数据不一致，需要按场景处理。
```

## 容易出错的示例

### 错误说法：用了 Redis 项目就高并发

### 为什么错

Redis 只是一个工具。没有说明缓存什么、为什么缓存、如何失效、如何处理穿透击穿，就不能证明你理解高并发。

### 正确说法

说清业务场景、key 设计、过期策略、更新策略和风险处理。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| MyBatis | 简化 JDBC 并保留 SQL 控制 | 少写模板代码 | 用户输入用 `#{}` | 重点是 SQL 可控 |
| MyBatis-Plus | 简化通用 CRUD | 提升开发效率 | 简单 CRUD 用 Plus，复杂 SQL 回 XML | 难点是别滥用 |
| Redis | 缓存和高性能数据结构 | 降低数据库压力 | 设置过期和命名规范 | 重点是一致性 |
| MQ | 异步、削峰、解耦 | 慢流程不阻塞主链路 | 消息要幂等 | 难点是失败补偿 |

## 本节练习

- 给热门文章设计 Redis key。
- 写缓存穿透、击穿、雪崩的处理方法。
- 给订单支付成功设计一条 MQ 消息。
