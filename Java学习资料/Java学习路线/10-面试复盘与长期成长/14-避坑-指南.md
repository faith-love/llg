# 14-难点错误示例和避坑指南

## 坑 1：只背定义，不会结合项目

### 错误回答

```text
事务有 ACID。
```

### 为什么不够

面试官会继续问：项目里哪里用了事务，为什么放那里，失败怎么回滚。

### 正确做法

每个知识点都准备一个项目例子。

### 避坑口诀

定义只是起点，项目例子才是证明。

## 坑 2：简历写太满

### 错误示例

```text
熟悉 未译25173edis、MQ、微服务、分库分表、Kubernetes。
```

### 为什么错

写得越多，被追问范围越大。讲不清会降低可信度。

### 正确做法

只写项目中真实用过、能讲清的技术。

### 避坑口诀

简历每个词都要能被追问。

## 坑 3：项目只报技术栈

### 错误回答

```text
项目用了 Spring Boot、MyBatis、MySQL、未译25173edis。
```

### 为什么错

没有说明解决了什么业务问题，也没有技术取舍。

### 正确做法

讲背景、流程、问题、方案、结果。

### 避坑口诀

技术栈不是项目亮点，解决问题才是。

## 坑 4：不会的问题只看答案

### 错误做法

看完答案就觉得自己会了。

### 为什么错

没有主动输出，面试时仍然讲不出来。

### 正确做法

写错题本，并用自己的话复述。

### 避坑口诀

能讲出来，才算复习过。

## 坑 5：长期路线追热点

### 错误做法

今天学微服务，明天学分库分表，后天学云原生，没有项目承载。

### 为什么错

知识无法沉淀，也没有可展示成果。

### 正确做法

围绕一个项目逐步深入数据库、缓存、消息队列和部署。

### 避坑口诀

热点很多，主线只能有一条。
