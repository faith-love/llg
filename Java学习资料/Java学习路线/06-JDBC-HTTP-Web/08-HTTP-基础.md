# 08-HTTP 基础

## HTTP 是什么

HTTP 是客户端和服务端通信的协议。浏览器、前端应用、Postman、移动 App 都可以通过 HTTP 请求后端接口。

一次 HTTP 交互包含：

```text
客户端请求 -> 服务端处理 -> 服务端响应
```

## 请求组成

HTTP 请求通常包含：

- 请求行。
- 请求头。
- 请求体。

示例：

```text
POST /接口/books HTTP/1.1
Content-Type: 应用配置/脚本on
Authorization: Bearer token

{"title":"Java 入门","author":"张三"}
```

## 响应组成

响应通常包含：

- 状态行。
- 响应头。
- 响应体。

示例：

```text
HTTP/1.1 201 Created
Content-Type: 应用配置/脚本on

{"id":1,"title":"Java 入门"}
```

## HTTP Method

| Method | 常见语义 |
| --- | --- |
| GET | 查询资源 |
| POST | 创建资源或提交动作 |
| PUT | 全量更新资源 |
| PATCH | 部分更新资源 |
| DELETE | 删除资源 |

## 状态码

| 状态码 | 含义 |
| --- | --- |
| 200 | 请求成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或认证失败 |
| 403 | 已登录但无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突 |
| 500 | 服务端内部错误 |

## 幂等性

幂等表示执行一次和执行多次结果相同。

通常：

- GET 应该幂等。
- PUT 通常幂等。
- DELETE 通常幂等或接近幂等。
- POST 通常不幂等。

例如重复提交下单接口，如果没有幂等控制，可能生成多个订单。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| HTTP | 客户端和后端通信基础 | 不懂 HTTP 就无法排查接口问题 | 用 Postman 或 curl 观察请求响应 | 重点是请求和响应结构 |
| Method | 表达操作语义 | 所有接口都 POST 会很混乱 | 查询 GET，创建 POST，更新 PUT/PATCH | 重点是语义一致 |
| 状态码 | 表达处理结果 | 前端不用猜成功失败原因 | 错误类型要选对状态码 | 难点是 401 和 403 区分 |
| 请求头 | 传递元信息 | Token、内容类型都靠 header | JSON 请求要带 Content-Type | 重点是 header 不放复杂业务体 |
| 幂等性 | 防止重复请求造成重复结果 | 网络重试、用户连点很常见 | 关键写操作要考虑幂等键 | 重点是 POST 默认不安全 |
