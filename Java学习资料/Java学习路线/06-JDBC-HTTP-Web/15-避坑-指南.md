## 坑 4：连接池配置越大越好

### 错误想法

```text
接口慢，把JDBC池从 20 调到 500。
```

### 为什么错

连接过多会压垮数据库，增加上下文切换和锁竞争。接口慢可能是 SQL 慢，不是连接不够。

### 正确做法

先看：

- 连接等待时间。
- 慢查询。
- 数据库 CPU。
- 应用实例数量。
- 每个实例连接池大小。

### 避坑口诀

连接池是限流阀，不是越大越快。

## 坑 5：MyBatis 使用 `${}` 接收用户输入

### 错误示例

```xml
select * from books where title like '%${keyword}%'
```

### 为什么错

`${}` 是文本替换，用户输入可能注入 SQL。

### 正确写法

```xml
select * from books where title like concat('%', #{keyword}, '%')
```

排序字段等必须用白名单。

### 避坑口诀

普通参数用 `#{}`，`${}` 只给白名单控制的结构片段。

## 坑 13：N+1 查询

### 错误示例

```Java学习资料

    Author author = authorMapper.findById(book.getAuthorId());

```

### 为什么错

### 正确做法

- 批量查询作者。
- 两次查询后在内存组装。

### 避坑口诀

列表查关联，先看 SQL 次数。
