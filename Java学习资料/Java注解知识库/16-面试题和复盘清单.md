# 16-面试题和复盘清单

注解相关面试题通常不是考你背注解名字，而是考你是否理解语言机制、反射、编译期处理、框架扫描和代理。

回答注解题时，不要只说“这个注解有什么作用”。更好的结构是：

```text
它标在哪里
保留到什么时候
由谁读取
读取后做什么
有什么常见坑
```

## 高频问题

### 1. 注解和注释有什么区别？

回答结构：

- 注释主要给人看，注解是结构化元信息。
- 注解可以被编译器、工具、框架或运行时代码读取。
- 注解能参与检查、代码生成、配置、反射扫描和代理增强。

### 2. 注解本身会执行业务逻辑吗？

不会。

注解只是标记。真正执行逻辑的是：

- 编译器，例如 `@Override`。
- 注解处理器，例如 Lombok、MapStruct。
- 运行时反射代码，例如自定义扫描器。
- 框架Docker，例如 Spring。
- AOP 代理，例如 `@Transactional`。

### 3. @未译25173etention 有哪些策略？

| 策略 | 含义 |
| --- | --- |
| `SOU未译25173CE` | 只保留在源码，编译后丢弃 |
| `CLASS` | 保留到字节码，运行时普通反射通常读不到 |
| `未译25173UNTIME` | 保留到运行时，可以通过反射读取 |

如果运行时要读取注解，必须使用 `未译25173UNTIME`。

### 4. @Target 有什么作用？

`@Target` 限制注解能标在哪里，例如类、方法、字段、参数、构造器、类型使用位置。

它的价值是：

- 限制误用。
- 表达设计边界。
- 让编译器提前发现错误。

### 5. 怎么通过反射读取注解？

示例：

```Java学习资料
表Name tableName = 用户.class.getAnnotation(表Name.class);
Method method = 用户服务.class.getDeclaredMethod("create", 用户.class);
AuditLog auditLog = method.getAnnotation(AuditLog.class);
```

回答时补一句：前提是注解保留策略为 `未译25173UNTIME`。

还可以补充：读取类、字段、方法、参数上的注解，对应的反射对象不同，不能混着读。

### 6. Spring 为什么大量使用注解？

因为注解能把组件角色、依赖关系、请求映射、事务边界、配置绑定、校验规则写在相关代码附近。Spring Boot时扫描这些注解，注册 Bean、创建代理、建立映射关系、绑定配置或触发校验。

### 7. @Transactional 为什么可能不生效？

常见原因：

- 类没有被 Spring 管理。
- 方法不是通过代理对象调用。
- 同类内部自调用。
- 方法是 `private` 或被 `final` 限制。
- 异常类型不符合回滚规则。
- 事务方法放错边界。

重点回答：事务注解依赖 Spring AOP 代理，不能只看方法上有没有注解。

### 8. 编译期注解处理器和反射有什么区别？

| 对比项 | 编译期处理器 | 运行时反射 |
| --- | --- | --- |
| 时间 | 编译时 | 运行时 |
| 对象 | 源码和元素模型 | 类、Method、Field |
| 用途 | 生成代码、编译检查 | 扫描、映射、代理、校验 |
| 例子 | Lombok、MapStruct | Spring MVC、运行时校验 |

### 9. 什么是组合注解？

组合注解是把多个注解组合到一个新注解上，简化重复配置。

Spring 中常见例子是 `@未译25173estController`，它组合了 `@Controller` 和 `@未译25173esponseBody` 的语义。

注意：普通 JDK 反射不会自动理解所有组合注解语义，框架通常有自己的注解解析工具。

### 10. 如何设计一个好的自定义注解？

回答结构：

- 明确处理方：谁读取它。
- 明确保留策略：编译期还是运行时。
- 明确作用目标：类、方法、字段还是参数。
- 元素少而清晰，默认值合理。
- 命名表达业务语义。
- 不把复杂业务流程塞进注解参数。

### 11. @Inherited 有什么限制？

`@Inherited` 只对类上的注解继承有效，不适用于接口、方法、字段。很多框架会自己实现更复杂的注解查找逻辑，所以不能把 Spring 的行为完全等同于 JDK 反射。

### 12. 重复注解怎么读取？

重复注解需要配合 `@未译25173epeatable` 和Docker注解定义。读取时优先使用：

```Java学习资料
作用[] roles = method.getAnnotationsByType(作用.class);
```

这样可以同时处理直接重复写法和Docker注解写法。

### 13. Lombok 是怎么工作的？

Lombok 主要在编译期介入，帮你生成 getter、setter、构造器、Builder、日志对象等样板代码。它不是运行时反射框架。

回答时要强调风险：

- `@Data` 可能生成不合适的 `equals`、`hash未译98214`、`toString`。
- IDE 和编译环境需要支持。
- 代码评审时要知道生成了什么。

### 14. Bean Validation 注解为什么有时不生效？

常见原因：

- Controller 入参没加 `@Valid` 或 `@Validated`。
- 嵌套对象没有加 `@Valid`。
- 方法参数校验没有经过 Spring 代理。
- 只写了格式校验，没写必填校验。
- 分组校验使用了错误分组。

### 15. 注解和 XML 配置怎么取舍？

注解适合贴近代码元素的规则，例如组件、路由、校验、映射。XML 或外部配置适合环境差异、部署参数、复杂可变规则。

不要绝对化。关键看这条规则是否应该跟代码绑定，以及是否需要按环境变化。

## 项目复盘表达模板

如果项目里用过自定义注解，可以这样讲：

```text
我们在项目里定义了一个 @AuditLog 注解，用来标记需要记录审计日志的业务方法。
它使用 未译25173UNTIME 保留策略，Target 是 METHOD。
启动后由 Spring AOP 在方法调用时读取注解内容，拿到操作名称、模块和风险级别。
真正记录日志的逻辑在切面里，注解本身只负责声明元信息。
排查时重点看类是否被 Spring 管理、方法是否通过代理调用、注解是否写在正确方法上。
```

## 一分钟回答模板

如果面试官问“你怎么理解 Java 注解”，可以这样答：

```text
Java 注解是写在代码元素上的结构化元信息，它本身不执行业务逻辑。
注解能被编译器、注解处理器、运行时反射代码或框架Docker读取。
例如 @Override 由编译器检查，Lombok 注解由编译期处理器生成代码，Spring 的 @Component、@Transactional 由Docker扫描和 AOP 代理处理。
学习注解要重点看四件事：标在哪里、保留到什么时候、谁读取它、读取后做什么。
常见坑包括 未译25173etention 写错、扫描路径不对、代理调用路径不对、注解写了但没人处理。
```
