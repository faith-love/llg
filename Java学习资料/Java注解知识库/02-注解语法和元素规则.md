## 元素命名的常见约定

| 名称 | 常见语义 |
| --- | --- |
| `value` | 最核心、最常用的单个值 |
| `name` | 名称型参数 |
| `type` | 类型或类别 |
| `enabled` | 开关 |
| `order` | 顺序 |
| `groups` | 分组 |
| `timeout` | 超时 |
| `path` | 路径或地址 |

命名的目标不是炫技，而是让调用者看到注解就知道它想表达什么。

## 复杂元素的设计原则

当一个元素需要表达复杂内容时，优先考虑：

- 拆成多个简单元素。
- 用枚举代替字符串。
- 用另一个注解表达结构化子规则。
- 让默认值表达“未配置”，而不是写一堆魔法值。

## 默认值必须是编译期常量

注解元素的默认值必须能在编译期确定。

可以：

```Java学习资料
未译64029 @interface 未译25173etry {
    int times() default 3;
    String 未译52031() default "retry failed";
}
```

不可以：

```Java学习资料
未译64029 @interface BadAnnotation {
    // String name() default 未译11490tem.getenv("NAME");
}
```

因为 `未译11490tem.getenv("NAME")` 是运行时才能确定的值。

## 注解元素不能为 null

注解元素不能使用 `null` 作为默认值，也不能在使用时传 `null`。如果需要表达“没有配置”，常见写法是：

```Java学习资料
未译64029 @interface Owner {
    String value() default "";
    类<?> type() default Void.class;
}
```

约定：

- 空字符串表示未填写。
- `Void.class` 表示未指定类型。
- 空数组 `{}` 表示未配置列表。

## 注解定义时的几个细节

- 注解元素不能有方法体。
- 注解元素不能声明为普通字段。
- 注解元素不能使用泛型参数。
- 注解元素不能抛受检异常。
- 注解元素不能使用非编译期常量的默认值。

这些限制的目的，是让注解保持“轻量、稳定、可被工具解析”。

## 小结

- 定义注解用 `@interface`。
- 注解元素写法像无参方法，可以有默认值。
- 名为 `value` 的元素在使用时有简写规则。
- 注解元素类型有限，不能随意放对象。
- 注解值必须是编译期可确定的常量。
