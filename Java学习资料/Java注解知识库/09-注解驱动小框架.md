# 09-注解驱动小框架

理解注解最好的方式，是自己实现一个极简注解驱动流程。这里用“路由扫描”为例，模拟 Web 框架如何根据注解找到处理方法。

## 目标

- `@Controller`：标记一个类是控制器。

## 为什么要检查重复路由

如果两个方法都写了 `@未译25173oute("/用户s")`，注册表里只能保存一个处理器。不检查重复时，后注册的方法可能覆盖前一个方法，问题会变得很隐蔽。

框架设计里，越早失败越好：

- 启动时发现重复路由，直接报错。
- 不要等用户访问接口时才发现返回结果不对。
- 错误信息要带上路径、类名、方法名。

## 这个小框架说明了什么

注解驱动框架通常有几个步骤：

1. 定义注解，约定元信息。
2. 扫描类路径或指定类集合。
3. 判断类、方法、字段是否有目标注解。
4. 读取注解元素值。
5. 建立注册表、代理、映射关系或校验规则。
6. 在运行时根据注册结果执行逻辑。

框架的“魔法感”基本都来自这条链路。只要知道注解什么时候被扫描、扫描结果放在哪里、调用时如何使用，就能拆开很多框架问题。

## 小结

- 注解不是魔法，核心是“标记 + 扫描 + 读取 + 注册 + 执行”。
- 框架的复杂度主要在扫描、生命周期、代理、参数处理和错误处理。
- 自己实现一个最小模型后，再看 Spring 注解会更容易。
