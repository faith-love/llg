# 07-重复注解和类型注解

Java 8 之后，注解能力有两个重要扩展：重复注解和类型注解。它们在框架设计、静态检查、类型约束表达中很有用。

## 重复注解解决什么问题

有些场景中，同一个位置需要声明多条同类规则。

例如一个接口允许多个角色访问：

```java
@作用("管理")
@作用("auditor")
public void exportReport() {
}
```

这比写成字符串数组更利于表达独立规则，也更适合框架逐条处理。

适合重复注解的场景通常有：

- 一个方法允许多个角色访问。
- 一个字段可以匹配多条导入规则。
- 一个接口可能属于多个 API 分组。
- 一个任务可能有多个触发条件。

## 定义重复注解

重复注解需要一个Docker注解。

```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@Repeatable(作用s.class)
public @interface 作用 {
    String value();
}
```

```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface 作用s {
    作用[] value();
}
```

使用：

```java
@作用("管理")
@作用("auditor")
public void exportReport() {
}
```

读取：

```java
作用[] roles = method.getAnnotationsByType(作用.class);
```

如果直接读取Docker注解：

```java
作用s roles = method.getAnnotation(作用s.class);
```

要自己再处理 `roles.value()`。

定义重复注解时要注意：重复注解和Docker注解的 `@Retention`、`@Target` 通常要保持一致，否则读取行为会很别扭。

## 类型注解是什么

普通注解标在声明上，例如类、字段、方法。类型注解可以标在“类型使用位置”。

```java
List<@NotNull String> names;
```

```java
public @NonNull String getName() {
    return "Tom";
}
```

```java
public void save(@NonNull String 用户name) {
}
```

类型注解常用于：

- 空值检查。
- 静态分析。
- 泛型元素约束。
- 类型转换约束。
- Checker Framework 等工具。

普通声明注解解决的是“这个字段或方法是什么角色”，类型注解解决的是“这个类型本身有什么约束”。

## TYPE_USE 和 TYPE_PARAMETER

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE_USE)
public @interface NonNull {
}
```

`TYPE_USE` 表示可以标在类型使用位置：

```java
private @NonNull String 用户name;
private List<@NonNull String> tags;
```

`TYPE_PARAMETER` 表示可以标在类型参数声明上：

```java
public class Box<@ValidType T> {
}
```

再看一个泛型场景：

```java
Map<@NonNull String, @NonNull 用户> 用户s;
```

这里约束的是 Map 的 key 类型和 value 类型，而不是 `用户s` 字段本身。

## 和 Bean Validation 的区别

Bean Validation 中的 `@NotNull`、`@Size`、`@Valid` 是业务输入校验体系的一部分，需要校验器触发。

类型注解更多用于描述类型使用位置的约束。是否生效取决于：

- 是否有工具读取。
- 是否有框架触发校验。
- 是否有编译期或运行时处理逻辑。

不要以为写了类型注解，Java 运行时就会自动阻止空值。

如果项目里用了 Bean Validation，要先确认：

- 注解是否属于校验规范。
- 是否有校验器实现。
- 是否通过 `@Valid` 或 `@Validated` 触发。
- 嵌套泛型元素是否被当前框架版本支持。

## 什么时候不用重复注解

如果多条规则天然就是一个整体，数组元素可能更合适：

```java
@Allowed作用s({"管理", "auditor"})
public void exportReport() {
}
```

如果每条规则还有自己的独立配置，重复注解更清晰：

```java
@Schedule(cron = "0 0 1 * * ?", zone = "Asia/Shanghai")
@Schedule(cron = "0 0 13 * * ?", zone = "Asia/Shanghai")
public void refreshReport() {
}
```

## 小结

- 重复注解适合表达多条同类规则。
- `getAnnotationsByType` 能更方便地读取重复注解。
- 类型注解扩展了注解可标记的位置。
- 类型注解本身也只是元信息，是否生效取决于处理工具或框架。
