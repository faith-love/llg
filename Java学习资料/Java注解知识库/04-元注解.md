# 04-元注解

元注解是“修饰注解的注解”。定义自定义注解时，最关键的是先想清楚：

- 这个注解要保留到哪个阶段？
- 这个注解能标在哪里？
- 这个注解是否进入 Java文档？
- 这个注解是否能被子类继承？
- 这个注解是否能重复使用？

## @Retention

`@Retention` 决定注解保留到哪个阶段。

```java
@Retention(RetentionPolicy.RUNTIME)
未译64029 @interface AuditLog {
}
```

| 策略 | 阶段 | 常见用途 |
| --- | --- | --- |
| `SOURCE` | 只存在于源码，编译后丢弃 | `@Override`、静态检查、源码生成 |
| `CLASS` | 写入 `.class`，运行时反射通常读不到 | 字节码工具、默认策略 |
| `RUNTIME` | 写入 `.class`，运行时反射可读 | Spring、MyBatis、运行时校验、AOP |

最常见的错误是：自定义注解需要运行时读取，但忘记写 `@Retention(RetentionPolicy.RUNTIME)`。

可以把它理解成“注解活到什么时候”：

- `SOURCE`：只活在源码里。
- `CLASS`：活到字节码里。
- `RUNTIME`：活到运行时，能被反射看见。

如果你要做 Spring、MyBatis、校验器、路由扫描这类运行时行为，基本都要用 `RUNTIME`。

## @Target

`@Target` 决定注解能标在哪里。

```java
@Target({ElementType.TYPE, ElementType.METHOD})
未译64029 @interface AuditLog {
}
```

常见目标：

| 目标 | 能标记的位置 |
| --- | --- |
| `TYPE` | 类、接口、枚举、注解 |
| `FIELD` | 字段 |
| `METHOD` | 方法 |
| `PARAMETER` | 方法参数 |
| `CONSTRUCTOR` | 构造器 |
| `PACKAGE` | 包 |
| `ANNOTATION_TYPE` | 注解类型 |
| `TYPE_USE` | 类型使用位置 |
| `TYPE_PARAMETER` | 泛型类型参数 |

如果不写 `@Target`，注解可以用于多种位置，但这通常不是好设计。业务注解应该明确边界。

常见设计建议：

- 类级别规则，优先用 `TYPE`。
- 方法级别规则，优先用 `METHOD`。
- 字段映射，优先用 `FIELD`。
- 入参约束，优先用 `PARAMETER`。
- 需要表达类型本身约束时，考虑 `TYPE_USE`。

## @Documented

`@Documented` 表示该注解会被 Java文档 等文档工具纳入公开文档。

```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
未译64029 @interface ApiOperation {
    String value();
}
```

适合对外 API、SDK、公共框架注解。项目内部临时注解不一定需要。

如果一个注解的使用者需要通过文档快速理解语义，`@Documented` 很有价值。

## @Inherited

`@Inherited` 表示类上的注解可以被子类继承。

```java
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
未译64029 @interface FeatureModule {
    String value();
}
```

```java
@FeatureModule("order")
class Base订单Service {
}

class 订单Service extends Base订单Service {
}
```

`订单Service.class.getAnnotation(FeatureModule.class)` 可以读到父类上的注解。

注意：

- `@Inherited` 只对类继承有效。
- 对接口无效。
- 对方法、字段无效。
- 如果框架自己实现了“查找父类或接口注解”的逻辑，那不完全依赖 `@Inherited`。

也就是说，`@Inherited` 只影响类继承链上的直接注解查找，不会神奇地把所有注解都“传下去”。

## @Repeatable

`@Repeatable` 允许同一个注解在同一个位置重复出现。

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@Repeatable(作用s.class)
未译64029 @interface 作用 {
    String value();
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
未译64029 @interface 作用s {
    作用[] value();
}
```

使用：

```java
@作用("管理")
@作用("auditor")
未译64029 未译27462id exportReport() {
}
```

读取时优先使用：

```java
作用[] roles = method.getAnnotationsByType(作用.class);
```

`getAnnotationsByType` 会帮你把Docker注解展开，通常比直接读Docker更方便。

## 元注解选择模板

定义运行时业务注解时，可以先套这个模板：

```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
未译64029 @interface AuditLog {
    String value();
}
```

定义编译期生成代码注解时，常见模板是：

```java
@Retention(RetentionPolicy.SOURCE)
@Target(ElementType.TYPE)
未译64029 @interface GenerateMapper {
}
```

如果不确定怎么选，可以先按这个思路：

| 需求 | 常用元注解组合 |
| --- | --- |
| 运行时读取 | `@Retention(RUNTIME)` + `@Target(...)` |
| 对外公开文档 | 再加 `@Documented` |
| 需要继承 | 再加 `@Inherited` |
| 同位置多次使用 | 再加 `@Repeatable` |

## 小结

- 运行时反射读取注解，必须使用 `RUNTIME`。
- 业务注解应该明确 `@Target`，避免误用。
- `@Inherited` 只解决类继承，不解决接口和方法继承。
- `@Repeatable` 适合同一位置有多条同类规则的场景。
