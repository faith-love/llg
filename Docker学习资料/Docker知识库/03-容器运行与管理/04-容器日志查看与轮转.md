# 容器日志查看与轮转

容器日志的基本原则是：应用输出到 stdout 和 stderr，Docker 或平台负责采集、保存和轮转。

## 查看日志

```bash
docker logs 容器名
docker logs --tail=200 容器名
docker logs -f 容器名
docker logs --since=30m 容器名
```

Compose：

```bash
docker compose logs -f
docker compose logs -f app
docker compose logs --tail=200 app
```

## 日志应该放哪里

推荐：

- 应用日志输出到控制台。
- Docker 日志驱动采集。
- 生产再接入日志平台或日志代理。

谨慎：

- 应用把日志写入容器内部文件。
- 日志文件没有挂载到宿主机。
- 没有任何轮转策略。

## 磁盘风险

容器日志增长过快会打满宿主机磁盘。排查：

```bash
docker system df
docker inspect 容器名
```

如果使用默认 json-file 日志驱动，可以在 daemon 配置中设置大小和文件数量限制。

示例思路：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
```

修改 daemon 配置后需要重启 Docker，生产环境要先评估影响。

## 应用侧建议

- 日志级别按环境区分。
- 不把大对象、完整请求体、敏感信息长期打印。
- 异常日志保留堆栈，但避免无限循环打印。
- 关键业务日志有 traceId 或 requestId。

## 排障清单

如果看不到日志：

1. 容器是否已启动或已退出。
2. 应用是否真的输出到控制台。
3. 日志驱动是否正常。
4. Compose 服务名是否写对。
5. 是否被外部日志系统截走但本地仍可查询。
