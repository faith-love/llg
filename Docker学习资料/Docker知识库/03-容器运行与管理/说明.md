## 生命周期

| 阶段 | 说明 | 常用命令 |
| --- | --- | --- |
| 创建 | 根据镜像创建容器，但不启动 | `docker create` |
| 运行 | 容器主进程正在执行 | `docker run`、`docker start` |
| 暂停 | 进程被冻结 | `docker pause`、`docker unpause` |
| 停止 | 主进程退出或被停止 | `docker stop` |
| 删除 | 删除容器元数据和可写层 | `docker rm` |

容器是否存活取决于主进程是否存活。主进程退出，容器就退出。

## 最常用启动命令

```bash
docker run -d \
  --name web \
  --restart unless-stopped \
  -p 8080:80 \
  -v web-html:/usr/share/nginx/html \
  nginx:stable
```

参数含义：

- `-d`：后台运行。
- `--name web`：指定容器名。
- `--restart unless-stopped`：Docker 重启后自动拉起，除非手动停止。
- `-p 8080:80`：宿主机 `8080` 映射到容器 `80`。
- `-v web-html:/usr/share/nginx/html`：挂载 named volume。
- `nginx:stable`：使用的镜像。

进一步阅读：[docker run 参数清单](03-docker-run参数清单.md)。

## 查看和进入容器

```bash
docker ps
docker ps -a
docker logs --tail=100 web
docker logs -f web
docker exec -it web sh
docker inspect web
```

注意：

- `exec` 是进入已经运行的容器，不是重新启动容器。
- Alpine 镜像通常没有 `bash`，要用 `sh`。
- `inspect` 输出很大，适合配合 `--format` 或 `jq` 查看网络、挂载、环境变量。

## 停止和删除

```bash
docker stop web
docker start web
docker restart web
docker rm web
docker rm -f web
```

删除容器不会删除 named volume，除非显式删除卷。删除容器会删除容器可写层，所以不要把重要数据只写在容器内部路径。

## 资源限制

```bash
docker run -d \
  --name app \
  --memory 512m \
  --cpus 1.5 \
  --pids-limit 200 \
  app:1.0.0
```

建议：

- 开发环境可以不严格限制，但压测和生产要明确资源边界。
- JVM 容器化时要确认 Java 版本能正确感知容器内存限制。
- 不要只看宿主机 `top`，也要看 `docker stats`。
- OOM 后先查容器退出码、内核日志和应用日志。

## 清理原则

```bash
docker container prune
docker image prune
docker volume prune
docker network prune
docker system df
```

清理前确认：

- 是否有停止但仍需要保留的容器。
- 是否有未打标签但仍被使用的镜像层。
- 是否有数据库或文件服务使用的 volume。
- 是否在生产服务器上执行。

生产环境不要机械执行全量清理命令，尤其是带 `--volumes` 的命令。
