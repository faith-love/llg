# 容器资源限制与退出码

容器资源限制用于避免单个服务拖垮宿主机，也用于压测环境模拟生产边界。

## 常见资源限制

```bash
docker run -d \
  --name app \
  --memory 512m \
  --cpus 1.5 \
  --pids-limit 200 \
  app:1.0.0
```

含义：

- `--memory 512m`：限制内存。
- `--cpus 1.5`：限制 CPU 使用量。
- `--pids-limit 200`：限制进程数量。

## 查看资源使用

```bash
docker stats
docker stats 容器名
```

重点看：

- CPU 是否长期打满。
- 内存是否接近限制。
- 网络和块设备 IO 是否异常。

## 常见退出码

| 退出码 | 常见含义 |
| --- | --- |
| `0` | 正常退出 |
| `1` | 应用或脚本一般性错误 |
| `125` | Docker daemon 执行命令失败 |
| `126` | 命令不可执行 |
| `127` | 命令不存在 |
| `137` | 常见于被 OOM Kill 或强制 kill |
| `143` | 收到 SIGTERM 后退出 |

查看退出码：

```bash
docker inspect 容器名 --format '{{.State.ExitCode}}'
docker inspect 容器名 --format '{{.State.OOMKilled}}'
```

## Java 容器内存注意点

Java 应用要确认 JVM 能感知容器内存限制。现代 JDK 通常支持容器感知，但仍建议显式配置：

```bash
JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75.0"
```

不要只按宿主机内存配置 `-Xmx`。

## 排查 OOM

1. 看退出码是否为 `137`。
2. 看 `OOMKilled` 是否为 true。
3. 看应用日志最后输出。
4. 看宿主机内核日志。
5. 看是否有内存限制过小、缓存过大、泄漏或瞬时峰值。
