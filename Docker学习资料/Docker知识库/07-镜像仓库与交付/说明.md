## 镜像标签策略

| 标签 | 作用 | 建议 |
| --- | --- | --- |
| `latest` | 默认标签 | 不建议作为生产唯一标签 |
| 语义版本号 | `1.4.2` 这类稳定版本 | 适合发布版本 |
| Git 提交短哈希 | 追踪构建来源 | 适合回滚和定位 |
| 环境标签 | `dev`、`test`、`prod` | 适合环境区分，但不要替代版本号 |

推荐同时打两个标签，例如：

```bash
docker build -t registry.example.com/demo/app:1.4.2 -t registry.example.com/demo/app:git-abc1234 .
```

## 常见仓库

- Docker Hub
- Harbor
- 云厂商镜像仓库
- 企业内部 Registry

## 基本交付命令

```bash
docker login registry.example.com
docker push registry.example.com/demo/app:1.4.2
docker pull registry.example.com/demo/app:1.4.2
```

## 交付流程建议

1. CI 里构建镜像。
2. 给镜像打上可追踪标签。
3. 推送到仓库。
4. 部署系统只拉取明确标签。
5. 保留上一版本镜像用于回滚。

## 注意事项

- 不要把仓库地址、账号密码硬编码在 Dockerfile 里。
- 私有仓库拉取需要登录或镜像拉取凭据。
- 生产环境部署时要固定镜像标签，不要用浮动标签。
- 如果镜像很大或构建慢，先优化 Dockerfile，再考虑缓存和镜像仓库策略。
