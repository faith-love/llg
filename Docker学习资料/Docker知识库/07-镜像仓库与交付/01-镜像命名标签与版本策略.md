# 镜像命名标签与版本策略

镜像命名要服务于追溯、回滚和权限管理，不只是让本地能跑。

## 完整镜像名

```text
registry.example.com/team/demo-api:1.4.2
```

拆开看：

| 部分 | 示例 | 含义 |
| --- | --- | --- |
| Registry | `registry.example.com` | 仓库服务地址 |
| Namespace | `team` | 团队或项目空间 |
| Repository | `demo-api` | 镜像仓库名 |
| Tag | `1.4.2` | 镜像版本 |

## 标签组合

推荐一次构建打多个标签：

```bash
docker build \
  -t registry.example.com/team/demo-api:1.4.2 \
  -t registry.example.com/team/demo-api:git-abc1234 \
  .
```

这样既能按发布版本部署，也能按 Git 提交追溯。

## latest 的边界

`latest` 只是默认标签，不代表最新稳定版本。生产环境不建议只写：

```text
demo-api:latest
```

因为它无法说明实际运行的是哪一次构建。

## 回滚标签

上线前记录：

- 当前运行镜像。
- 新版本镜像。
- 上一个稳定版本镜像。
- 对应 Git 提交。

回滚时只改镜像标签，不临时重新构建。

## digest

Digest 能精确标识镜像内容。高要求环境可以记录：

```bash
docker inspect --format='{{index .RepoDigests 0}}' 镜像名
```

标签便于人读，digest 便于精确追溯。
