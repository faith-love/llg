# Docker 知识库总纲

这个知识库面向后端开发、测试、运维入门和需要把项目稳定交付到服务器的人。目标不是只会执行 `docker run hello-world`，而是建立一套能落地的容器化工作流：能写出可维护的 Dockerfile，能用 Compose 管理开发环境，能处理数据卷、网络、日志、权限、镜像发布、升级回滚和常见故障。

## 学习目标

- 能解释容器、镜像、仓库、数据卷、网络、Compose、Registry 的关系。
- 能写出适合 Java、Node、Nginx、MySQL、Redis 等常见项目的 Dockerfile 或 Compose 文件。
- 能判断什么时候用容器，什么时候不该强行容器化。
- 能管理容器生命周期、日志、资源限制、环境变量、健康检查和数据持久化。
- 能把镜像从本地构建、打标签、推送到仓库，再在服务器拉取运行。
- 能排查容器启动失败、端口访问失败、数据丢失、镜像过大、磁盘打满和 Compose 启动顺序问题。
- 能建立生产部署底线：非 root 用户、只暴露必要端口、持久化数据、日志清理、升级回滚和镜像版本固定。

## 推荐学习路线

1. 先学 `00-01`：理解 Docker 的定位、架构和基础术语。
2. 再学 `02-03`：会构建镜像，也会正确运行、停止、进入、查看和限制容器。
3. 接着学 `04-06`：掌握数据、网络和 Compose，这是本地开发环境和多服务项目的主线。
4. 然后学 `07-09`：把镜像推到仓库，在服务器上稳定运行，并守住安全底线。
5. 最后学 `10-11`：用排障路径和实战模板，把知识落到项目中。

## 常用工作流

### 本地开发环境

1. 写 `Dockerfile` 或确认使用官方镜像。
2. 写 `compose.yaml`，把数据库、缓存、后端、前端放入同一个项目网络。
3. 使用 `.env` 管理端口、账号、密码和镜像标签。
4. 使用 named volume 保存数据库数据。
5. 用 `docker compose up -d` 启动，用 `docker compose logs -f 服务名` 看日志。

### 镜像交付

1. 本地或 CI 构建镜像。
2. 使用明确标签：`项目名:版本号`、`项目名:git短提交`。
3. 推送到 Docker Hub、Harbor 或内部 Registry。
4. 服务器拉取指定标签，不在生产上直接使用不受控的 `latest`。
5. 更新前保留旧镜像标签和回滚命令。

### 生产排障

1. 先看容器状态：`docker ps -a`。
2. 再看日志：`docker logs --tail=200 容器名`。
3. 确认端口映射：`docker port 容器名`。
4. 确认网络：`docker network inspect 网络名`。
5. 确认挂载：`docker inspect 容器名`。
6. 确认资源：`docker stats`、`docker system df`。
7. 修复后写清楚现象、根因、止血动作和长期修复。
