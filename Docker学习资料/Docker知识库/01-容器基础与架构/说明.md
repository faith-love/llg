# 容器基础与架构

本模块建立 Docker 的基础模型：镜像是可分发的软件包，容器是镜像运行后的进程隔离环境，仓库负责保存和分发镜像，Docker Engine 负责构建、拉取、运行和管理容器。

## 核心概念

| 概念 | 解释 | 常见命令 |
| --- | --- | --- |
| Image 镜像 | 只读模板，包含文件系统、运行时依赖和默认启动命令 | `docker images`、`docker pull`、`docker build` |
| Container 容器 | 镜像运行后的实例，本质上是被隔离和限制的进程 | `docker ps`、`docker run`、`docker stop` |
| Registry 仓库服务 | 保存和分发镜像的服务，例如 Docker Hub、Harbor | `docker login`、`docker push`、`docker pull` |
| Dockerfile | 描述镜像构建步骤的文本文件 | `docker build -f Dockerfile .` |
| Volume 数据卷 | 由 Docker 管理的持久化数据目录 | `docker volume ls`、`docker volume inspect` |
| Network 网络 | 容器之间、容器与宿主机之间通信的网络抽象 | `docker network ls`、`docker network inspect` |

## Docker Engine 组成

| 组件 | 作用 |
| --- | --- |
| Docker CLI | 用户执行的命令行客户端，例如 `docker run` |
| Docker daemon | 后台守护进程，接收 API 请求并管理镜像、容器、网络、卷 |
| containerd | 管理容器生命周期的底层运行时组件 |
| runc | 根据 OCI 规范创建和运行容器进程 |
| Registry | 镜像仓库，不属于本机 Engine，但参与镜像分发 |

简化链路是：

```text
docker 命令 -> Docker daemon -> containerd -> runc -> 容器进程
```

## 容器不是小型虚拟机

容器共享宿主机内核，不包含完整操作系统内核。容器镜像里通常只有应用运行所需的文件系统、依赖和启动命令。容器更轻，启动快，但隔离程度和虚拟机不同。

进一步阅读：[容器与虚拟机区别](01-容器与虚拟机区别.md)、[镜像容器仓库关系](02-镜像容器仓库关系.md)。

## 一条命令背后的动作

执行：

```bash
docker run -d --name web -p 8080:80 nginx:stable
```

大致发生这些事情：

1. Docker 检查本地是否存在 `nginx:stable` 镜像。
2. 如果不存在，从镜像仓库拉取。
3. 创建一个容器可写层。
4. 分配容器网络和 IP。
5. 设置宿主机 `8080` 到容器 `80` 的端口映射。
6. 按镜像默认命令启动 Nginx 主进程。
7. 返回容器 ID，容器在后台运行。

## 常见误区

- 误区一：容器越多越好。实际要按服务边界拆分，不要把同一个应用拆成过多容器。
- 误区二：容器内改配置就永久生效。容器可写层会随着容器删除而丢失，配置要通过镜像、挂载或环境变量管理。
- 误区三：容器里能访问本机 localhost。容器内的 `127.0.0.1` 指容器自己，不是宿主机。
- 误区四：镜像构建成功就代表服务可用。还要验证启动命令、端口、健康检查、配置和依赖。
- 误区五：Docker 等于 Kubernetes。Docker 是容器工具链，Kubernetes 是容器编排平台。
