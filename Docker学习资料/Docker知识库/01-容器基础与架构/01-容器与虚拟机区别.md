# 容器与虚拟机区别

理解容器和虚拟机的区别，可以避免两个常见错误：把容器当完整服务器维护，或者误以为容器具备虚拟机级别的强隔离。

## 对比表

| 维度 | 容器 | 虚拟机 |
| --- | --- | --- |
| 内核 | 共享宿主机内核 | 每台虚拟机有自己的操作系统内核 |
| 启动速度 | 通常秒级甚至更快 | 通常更慢 |
| 镜像体积 | 通常较小 | 通常较大 |
| 隔离方式 | namespace、cgroup、能力控制、文件系统隔离 | Hypervisor 提供硬件级虚拟化 |
| 运行内容 | 推荐一个容器一个主进程或一个清晰服务 | 可以像完整服务器一样运行多个服务 |
| 适合场景 | 应用交付、开发环境、测试隔离、轻量部署 | 强隔离、多系统环境、完整服务器模拟 |

## 容器的隔离边界

容器主要依赖这些 Linux 能力：

- `namespace`：隔离进程、网络、挂载点、用户、主机名等视图。
- `cgroup`：限制和统计 CPU、内存、IO 等资源。
- capability：控制进程能执行哪些内核级操作。
- seccomp、AppArmor、SELinux：限制系统调用和访问行为。
- layered filesystem：把只读镜像层和容器可写层组合起来。

这些能力让容器足够适合应用隔离，但它仍共享宿主机内核。因此高安全要求场景要继续评估虚拟机、沙箱、专用节点或云平台隔离能力。

## 设计建议

### 容器中应该放什么

- 应用进程。
- 应用运行依赖。
- 最小必要系统工具。
- 启动脚本或入口脚本。
- 默认配置模板。

### 容器中不应该放什么

- 长期运行的 SSH 服务。
- 与应用无关的一堆后台进程。
- 写死的生产密码和私钥。
- 只能在某台机器上工作的绝对路径。
- 依赖人工进入容器修改的关键配置。

## 判断是否该容器化

适合容器化：

- 应用能以前台进程启动。
- 运行依赖清晰。
- 配置能通过环境变量、文件挂载或配置中心注入。
- 数据能明确挂载到持久化目录。
- 日志能输出到标准输出或指定挂载目录。

暂缓容器化：

- 应用启动强依赖桌面、硬件驱动或特殊内核模块。
- 运行过程需要大量手工交互。
- 状态文件位置混乱，无法确认哪些数据必须持久化。
- 团队没有镜像仓库、备份、回滚和监控机制。

## 面试表达

可以这样回答：

> 容器和虚拟机都能提供隔离环境，但虚拟机虚拟化的是硬件和完整操作系统，容器共享宿主机内核，主要隔离进程、网络、文件系统和资源。容器更轻、更适合应用交付和弹性启动；虚拟机隔离更强，适合完整系统和强隔离场景。生产里选择哪个，要看安全边界、运维能力和应用特征。
