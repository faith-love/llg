# 敏感信息与镜像扫描

镜像是可分发产物，一旦把密码、Token、私钥写进镜像，后续删除文件也不一定能消除风险，因为内容可能已经存在于历史层。

## 不要写进镜像的内容

- 数据库密码。
- API Token。
- SSH 私钥。
- 云厂商密钥。
- 生产 `.env`。
- 内部证书和账号。

## 常见错误

```dockerfile
ENV DB_PASSWORD=prod_password
COPY .env /app/.env
COPY id_rsa /root/.ssh/id_rsa
```

这些内容会进入镜像层，推送到仓库后更难控制。

## 推荐方式

- 运行时环境变量注入。
- Compose `env_file` 加本地权限控制。
- 部署平台 Secret。
- 配置中心。
- 只读挂载受控配置文件。

## 镜像扫描

生产发布前建议检查：

- 基础镜像漏洞。
- 系统包漏洞。
- 应用依赖漏洞。
- 是否含有敏感文件。
- 是否使用过期基础镜像。

## 自查命令

```bash
docker history 镜像名
docker run --rm -it 镜像名 sh
```

进入镜像后检查：

- `/root/.ssh`
- `/app/.env`
- 临时目录。
- 构建脚本残留。
- 测试数据和日志。
