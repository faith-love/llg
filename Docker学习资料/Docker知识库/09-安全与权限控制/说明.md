# 安全与权限控制

容器的安全重点不只是镜像漏洞，更包括运行用户、挂载权限、敏感配置、网络暴露和宿主机能力边界。

## 安全底线

- 容器默认不要以 root 跑业务。
- 不要开启不必要的 `--privileged`。
- 不要把宿主机敏感目录随意挂进容器。
- 不要把密码、Token、私钥放进镜像或公开仓库。
- 不要把数据库和 Redis 直接暴露到公网。

## 最小权限

示例：

```dockerfile
FROM alpine:3.20
RUN addgroup -S app && adduser -S app -G app
WORKDIR /app
COPY --chown=app:app app.sh /app/app.sh
USER app
CMD ["sh", "/app/app.sh"]
```

## 敏感信息管理

敏感信息的推荐放置顺序：

1. 平台 Secret。
2. 运行时环境变量注入。
3. 挂载配置文件。
4. 镜像内默认配置。

越敏感的内容越不应该进入镜像层。

## 供应链和漏洞

- 固定基础镜像来源。
- 定期重建镜像。
- 关注基础镜像安全更新。
- 检查镜像内是否残留测试文件、调试工具和私钥。
- 生产发布前做镜像扫描或基础安全检查。

## 权限和挂载

bind mount 最容易出权限问题。出现写入失败时，优先检查：

- 容器运行用户。
- 宿主机目录属主。
- 是否只读挂载。
- SELinux 或类似强制访问控制。

不要把 `chmod 777` 当成安全修复。
