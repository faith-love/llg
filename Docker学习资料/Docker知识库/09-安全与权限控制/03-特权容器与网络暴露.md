# 特权容器与网络暴露

Docker 的很多高危配置不是不能用，而是必须知道为什么用、影响范围是什么、有没有替代方案。

## privileged 风险

```bash
docker run --privileged ...
```

特权容器会获得大量宿主机能力，可能突破普通容器边界。除非是明确的系统级工具场景，否则业务容器不应使用。

## 危险挂载

高风险示例：

```bash
-v /:/host
-v /var/run/docker.sock:/var/run/docker.sock
```

挂载 Docker socket 等价于让容器控制宿主机 Docker，风险很高。

## 网络暴露

不应公网暴露：

- MySQL。
- Redis。
- MongoDB。
- Elasticsearch。
- 内部管理后台。
- 未鉴权调试端口。

生产中优先：

- 内部 Docker 网络访问。
- Nginx 或网关统一入口。
- 防火墙和云安全组限制来源。
- 必要时加 VPN、堡垒机或零信任访问。

## 检查命令

```bash
docker ps
docker port 容器名
docker inspect 容器名
```

重点看：

- 是否发布了多余端口。
- 是否使用 host 网络。
- 是否挂载敏感路径。
- 是否开启特权模式。
