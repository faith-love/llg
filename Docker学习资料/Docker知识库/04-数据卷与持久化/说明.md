# 数据卷与持久化

本模块解决容器数据问题。容器本身适合无状态运行，但真实项目中数据库、上传文件、缓存持久化、配置文件、日志目录都需要明确挂载策略。

## 三种挂载方式

| 方式 | 典型写法 | 适合场景 | 风险 |
| --- | --- | --- | --- |
| named volume | `-v mysql-data:/var/lib/mysql` | 数据库、Redis、应用持久化数据 | 位置由 Docker 管理，需要会 inspect 和备份 |
| bind mount | `-v /opt/app/config:/app/config` | 配置文件、开发源码挂载、固定宿主机目录 | 宿主机路径和权限更容易出问题 |
| tmpfs | `--tmpfs /tmp` | 临时文件、敏感短期文件 | 容器停止后数据消失 |

## 容器可写层不适合保存重要数据

容器运行时可以写入自己的文件系统，但这些数据属于容器可写层。删除容器后，可写层也会删除。

因此：

- MySQL 数据目录必须挂载。
- Redis 开启持久化时 `/data` 必须挂载。
- 文件上传目录必须挂载。
- 需要保留的日志要挂载或输出到标准输出后被采集。

## named volume 示例

```bash
docker volume create mysql-data

docker run -d \
  --name mysql-dev \
  -e MYSQL_ROOT_PASSWORD=dev_password \
  -e MYSQL_DATABASE=demo \
  -p 3306:3306 \
  -v mysql-data:/var/lib/mysql \
  mysql:8
```

查看卷：

```bash
docker volume ls
docker volume inspect mysql-data
```

删除容器后卷仍在：

```bash
docker rm -f mysql-dev
docker volume ls
```

## bind mount 示例

```bash
docker run -d \
  --name nginx-dev \
  -p 8080:80 \
  -v /opt/nginx/html:/usr/share/nginx/html:ro \
  nginx:stable
```

这里 `:ro` 表示容器内只读挂载，适合静态文件或配置只读场景。

## 备份和恢复

备份 named volume 的一种通用方式：

```bash
docker run --rm \
  -v mysql-data:/data \
  -v "$PWD":/backup \
  alpine \
  tar czf /backup/mysql-data.tar.gz -C /data .
```

恢复：

```bash
docker volume create mysql-data-new

docker run --rm \
  -v mysql-data-new:/data \
  -v "$PWD":/backup \
  alpine \
  sh -c "cd /data && tar xzf /backup/mysql-data.tar.gz"
```

真实数据库备份优先使用数据库自身工具，例如 `mysqldump`、物理备份或云厂商备份。直接打包卷适合停机或明确一致性边界的场景。

## 权限排查

挂载后应用报权限错误，按这个顺序看：

1. 容器内应用使用哪个用户运行：`docker exec 容器名 id`。
2. 宿主机目录属主和权限：`ls -lah 宿主机目录`。
3. 容器内路径权限：`docker exec 容器名 ls -lah 容器路径`。
4. 是否使用了只读挂载 `:ro`。
5. SELinux 环境是否需要额外挂载标记。

不要用 `chmod 777` 当默认解法。正确做法是让宿主机目录属主、容器运行用户和应用写入路径对齐。

## 生产建议

- 数据库、对象存储、消息队列等有状态服务优先使用成熟托管服务或专门运维方案。
- 如果单机 Docker 部署有状态服务，必须有备份、恢复演练和磁盘监控。
- 区分配置、数据、日志三类挂载，不要全部混在一个目录。
- 对配置使用只读挂载。
- 对上传文件和数据库数据设置明确备份周期。
