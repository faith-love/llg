# 挂载权限问题排查

挂载权限问题常见表现是：应用启动失败、无法写日志、上传文件失败、数据库初始化失败。

## 先确认三件事

```bash
docker inspect 容器名
docker exec -it 容器名 id
docker exec -it 容器名 ls -lah /目标路径
```

要知道：

- 容器内路径实际挂载到哪里。
- 应用进程使用哪个 UID/GID。
- 容器内目标路径权限是什么。

## 宿主机检查

```bash
ls -lah /opt/app/data
namei -l /opt/app/data
```

`namei -l` 可以看到路径上每一级目录权限，很多问题不是最终目录，而是上级目录没有执行权限。

## 常见原因

| 原因 | 表现 | 修复方向 |
| --- | --- | --- |
| 宿主机目录属主不匹配 | 容器内无法写入 | 调整目录属主或容器运行用户 |
| 只读挂载 | 写入时报 read-only | 去掉 `:ro` 或改写入路径 |
| 路径不存在 | 容器内看到空目录 | 创建正确宿主机目录并放入配置 |
| SELinux 限制 | 权限看似正确仍失败 | 按系统策略调整挂载标签 |
| 容器非 root | 老脚本假设 root 权限 | 修复脚本或预先赋权 |

## 不建议的处理

```bash
chmod -R 777 /opt/app/data
```

这会扩大权限风险，尤其是生产服务器。更合理的是确认应用 UID/GID，然后只给需要的目录最小写权限。

## 推荐修复流程

1. 明确容器内应用用户。
2. 明确需要写入的目录。
3. 在宿主机创建目录。
4. 调整属主或组权限。
5. 用同样用户在容器内写测试文件。
6. 重启应用验证。
