# 数据库卷备份与恢复

数据库容器化后，数据安全不由 Docker 自动保证。挂载只是保存数据的位置，备份和恢复仍然要单独设计。

## MySQL 推荐备份方式

逻辑备份：

```bash
docker exec mysql-dev sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" demo' > demo.sql
```

恢复：

```bash
docker exec -i mysql-dev sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" demo' < demo.sql
```

优点：

- 可读性较好。
- 适合中小库和迁移。
- 不强依赖底层卷路径。

风险：

- 大库耗时长。
- 需要处理锁、一致性和业务写入。

## Redis 备份思路

如果启用 RDB 或 AOF：

```bash
docker exec redis-dev redis-cli BGSAVE
```

然后备份挂载的 `/data` 内容。恢复时要确保 Redis 停止或使用正确的恢复流程。

## 通用 volume 打包

```bash
docker run --rm \
  -v mysql-data:/data \
  -v "$PWD":/backup \
  alpine \
  tar czf /backup/mysql-data.tar.gz -C /data .
```

这个方式适合停机或明确一致性边界的场景。运行中的数据库直接打包文件系统可能得到不一致数据。

## 恢复演练

备份是否有效，只有恢复过才知道。建议定期做：

1. 新建空 volume。
2. 把备份恢复到新 volume。
3. 启动临时数据库容器。
4. 校验表数量、核心数据和业务查询。
5. 记录恢复耗时和问题。

## 生产底线

- 备份文件不能只保存在同一台宿主机。
- 备份要加密和权限控制。
- 备份脚本失败要告警。
- 数据库升级前必须先验证备份可恢复。
