# 容器性能定位

容器慢不一定是 Docker 慢。定位时要分清容器资源、宿主机资源和应用自身瓶颈。

## 先看容器资源

```bash
docker stats
```

关注：

- CPU 是否长期接近限制。
- 内存是否接近限制。
- 网络 IO 是否异常。
- 磁盘 IO 是否异常。

## 再看宿主机

```bash
top
free -h
df -h
iostat
ss -s
```

如果宿主机已经资源紧张，单个容器优化效果有限。

## Java 应用重点

- JVM 是否识别容器内存限制。
- `-Xmx` 是否过大或过小。
- GC 是否频繁。
- 线程池是否耗尽。
- 外部依赖是否慢。

## 网络慢

检查：

- DNS 解析。
- 反向代理。
- 跨主机链路。
- 外部 API。
- 容器是否经过多层代理。

## 应用层排查

如果容器资源正常，但请求慢，继续查：

- 慢 SQL。
- 缓存命中率。
- 锁等待。
- 线程池。
- 第三方接口超时。

Docker 只提供运行边界，不替代应用性能分析。
