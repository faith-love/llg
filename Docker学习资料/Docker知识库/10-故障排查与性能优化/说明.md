## 排查顺序

1. 容器是否存在、是否启动。
2. 镜像和标签是否正确。
3. 日志里有没有明显报错。
4. 端口是否映射正确。
5. 应用是否监听了正确地址。
6. 网络是否能互通。
7. 卷和权限是否正确。
8. 资源是否耗尽。
9. 配置是否注入成功。
10. 升级或改动后是否出现回归。

## 常见性能问题

| 问题 | 可能原因 |
| --- | --- |
| 容器很慢 | CPU 限制、IO 限制、镜像过大、启动命令有额外初始化 |
| 内存飙升 | 应用泄漏、JVM 参数不适配、缓存过大、日志暴涨 |
| 磁盘满 | 日志文件没轮转、无用镜像堆积、卷增长过快 |
| 网络慢 | DNS、NAT、反向代理、跨网络通信或防火墙 |

## 常用检查命令

```bash
docker ps -a
docker logs 容器名
docker inspect 容器名
docker stats
docker system df
docker network ls
docker volume ls
```

## 何时不是 Docker 的问题

如果容器本身没问题，但应用依然慢，常见根因可能在：

- 慢 SQL。
- 外部依赖超时。
- 应用线程池配置。
- 缓存设计。
- 反向代理或网关超时。

Docker 只是运行环境，不会自动修复应用层性能问题。
