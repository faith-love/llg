# 容器启动失败排查

容器启动失败先不要重建镜像，先保留现场看状态、日志和退出码。

## 基础命令

```bash
docker ps -a
docker logs 容器名
docker inspect 容器名
docker inspect 容器名 --format '{{.State.ExitCode}}'
```

## 常见原因

| 原因 | 现象 | 处理 |
| --- | --- | --- |
| 启动命令错误 | `executable file not found` | 检查 `CMD`、`ENTRYPOINT` 和文件路径 |
| 配置缺失 | 应用日志报配置不存在 | 检查环境变量和挂载 |
| 端口冲突 | 容器创建或启动失败 | 更换宿主机端口 |
| 权限不足 | permission denied | 检查用户和挂载目录权限 |
| 依赖不可用 | 数据库连接失败 | 检查网络、服务名和依赖状态 |
| OOM | 退出码 137 | 检查内存限制和应用内存 |

## 临时进入镜像排查

如果容器一启动就退出，可以覆盖启动命令：

```bash
docker run --rm -it --entrypoint sh 镜像名
```

然后检查：

- 文件是否存在。
- 权限是否正确。
- 环境变量是否符合预期。
- 启动命令能否手动执行。

## 修复原则

- 能通过配置解决的，不要临时进入容器手改。
- 能通过 Dockerfile 修复的，不要依赖运行时手工操作。
- 启动失败要保留日志和镜像标签，方便复盘。
