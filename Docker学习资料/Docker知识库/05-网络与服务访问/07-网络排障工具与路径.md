# 网络排障工具与路径

Docker 网络问题不要从改配置开始，先收集证据。

## 排障路径

1. 容器是否运行。
2. 服务是否监听端口。
3. 端口是否发布到宿主机。
4. 容器是否在正确网络。
5. DNS 是否能解析服务名。
6. 防火墙和安全组是否放行。
7. 反向代理是否转发到正确地址。

## 常用命令

```bash
docker ps
docker port 容器名
docker network ls
docker network inspect 网络名
docker inspect 容器名
```

容器内：

```bash
ss -lntp
getent hosts 服务名
curl -v http://服务名:端口/health
nc -vz 服务名 端口
```

## 临时调试容器

业务镜像不应该塞满调试工具。需要排障时，用临时容器加入同一网络。

```bash
docker run --rm -it --network app-net nicolaka/netshoot
```

可检查：

- DNS。
- TCP 端口。
- HTTP 接口。
- 路由。
- TLS 握手。

## 常见结论

| 现象 | 常见根因 |
| --- | --- |
| 宿主机能访问，其他机器不能访问 | 防火墙、安全组或绑定地址 |
| 容器 A 不能访问容器 B | 不在同一网络或服务名写错 |
| 端口映射了仍打不开 | 应用监听 `127.0.0.1` 或启动失败 |
| Compose 里数据库连接失败 | 写了 localhost 或数据库未就绪 |
