本模块解决容器之间、容器与宿主机之间、外部客户端与容器之间怎样通信的问题。网络问题是 Docker 排障最高频的问题之一。

## 常见网络模式

| 模式 | 说明 | 适合场景 |
| --- | --- | --- |
| bridge | 默认单机桥接网络，容器有独立 IP | 大多数单机容器和 Compose 项目 |
| host | 共享宿主机网络命名空间 | 高性能或特殊网络场景，Linux 上更常见 |
| none | 不配置网络 | 极端隔离或特殊任务 |
| overlay | 跨主机容器网络 | Swarm 或特定集群场景 |

日常开发和单机部署优先使用 bridge 或 Compose 自动创建的项目网络。

## 端口映射

```bash
docker run -d --name web -p 8080:80 nginx:stable
```

含义：

- 容器内服务监听 `80`。
- 宿主机监听 `8080`。
- 访问 `http://宿主机IP:8080` 会转发到容器 `80`。

常见错误：

- 端口方向写反。
- 宿主机端口已被占用。
- 应用只监听 `127.0.0.1`，没有监听容器网卡。
- 云服务器安全组没有放行宿主机端口。
- 防火墙拦截。

进一步阅读：[端口映射和容器互联](05-端口映射和容器互联.md)。

## 容器之间通信

推荐做法：创建用户自定义网络，然后用容器名访问服务。

```bash
docker network create app-net

docker run -d --name redis --network app-net redis:7
docker run --rm -it --network app-net redis:7 redis-cli -h redis ping
```

在用户自定义 bridge 网络中，Docker 提供内置 DNS，容器可以用容器名或网络别名互相访问。

## Compose 网络

Compose 默认会为项目创建一个网络，同一个 Compose 文件里的服务可以直接用服务名互访。

示例：

```yaml
services:
  app:
    image: my-app:1.0.0
    environment:
      REDIS_HOST: redis
  redis:
    image: redis:7
```

应用中连接 Redis 时主机名写 `redis`，不是 `127.0.0.1`。

## 排查命令

```bash
docker network ls
docker network inspect app-net
docker port web
docker exec -it web sh
docker logs web
```

容器内排查可用：

```bash
getent hosts redis
nc -vz redis 6379
curl -v http://app:8080/health
```

如果业务镜像很精简，没有排查工具，可以临时启动调试容器加入同一网络。

```bash
docker run --rm -it --network app-net nicolaka/netshoot
```

## 设计建议

- 容器间访问用服务名，不要写动态容器 IP。
- 对外暴露的端口越少越好。
- 数据库、Redis、MQ 通常不应直接公网暴露。
- 本地开发可以映射数据库端口，生产中优先只允许应用容器在内部网络访问。
- 端口、域名、防火墙、安全组和反向代理要一起排查。
