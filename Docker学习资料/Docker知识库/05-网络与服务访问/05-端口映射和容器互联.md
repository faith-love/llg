# 端口映射和容器互联

端口和网络问题的核心是先分清四个位置：访问方、宿主机端口、容器端口、应用真实监听地址。

## 端口映射方向

```bash
docker run -p 8080:80 nginx
```

格式是：

```text
宿主机端口:容器端口
```

访问路径是：

```text
浏览器 -> 宿主机IP:8080 -> 容器IP:80 -> Nginx进程
```

## 绑定地址

默认：

```bash
docker run -p 8080:80 nginx
```

通常会在宿主机所有地址监听。也可以只绑定本机：

```bash
docker run -p 127.0.0.1:8080:80 nginx
```

这表示只有宿主机本机能访问 `127.0.0.1:8080`，外部机器访问不了。

## 容器内 localhost 的含义

容器内的 `127.0.0.1` 指容器自己，不是宿主机，也不是其他容器。

常见错误：

```properties
spring.redis.host=127.0.0.1
```

如果 Spring Boot 应用在容器里，Redis 是另一个容器，那么这里应该写 Compose 服务名：

```properties
spring.redis.host=redis
```

## 应用监听地址

有些应用默认只监听 `127.0.0.1`。在容器中这会导致端口已映射但外部仍无法访问。

排查：

```bash
docker exec -it app sh
ss -lntp
```

如果看到应用只监听 `127.0.0.1:8080`，需要改成监听 `0.0.0.0:8080`。

Spring Boot 通常可配置：

```properties
server.address=0.0.0.0
server.port=8080
```

## 容器互联示例

```bash
docker network create demo-net

docker run -d --name redis --network demo-net redis:7

docker run --rm -it --network demo-net redis:7 redis-cli -h redis ping
```

返回 `PONG` 说明：

- 两个容器在同一网络。
- DNS 能解析 `redis`。
- Redis 服务端口可访问。

## 排查路径

外部访问失败时：

1. 容器是否运行：`docker ps -a`。
2. 应用是否启动成功：`docker logs 容器名`。
3. 端口是否发布：`docker port 容器名`。
4. 宿主机是否监听：`ss -lntp`。
5. 应用是否监听 `0.0.0.0`。
6. 防火墙是否放行。
7. 云安全组是否放行。
8. 反向代理配置是否转发到正确端口。

容器之间访问失败时：

1. 是否在同一网络。
2. 主机名是否写服务名或容器名。
3. 目标服务是否监听正确端口。
4. 是否写成了 `localhost`。
5. 是否有应用鉴权、密码、TLS 或白名单限制。
