# 健康检查与启动依赖

Compose 里容器启动成功，不代表服务已经可用。数据库、Redis、消息队列都可能需要初始化时间。

## healthcheck 示例

```yaml
services:
  redis:
    image: redis:7
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
```

含义：

- 每 5 秒检查一次。
- 单次超时 3 秒。
- 连续失败 10 次后标记不健康。

## depends_on 的边界

```yaml
services:
  app:
    depends_on:
      - mysql
```

这只表示启动顺序，不保证 MySQL 已经可以连接。

更好的方向：

- 依赖服务加健康检查。
- 应用连接依赖时有重试。
- 部署后用健康接口确认整体可用。

## 应用侧重试

应用不应该只依赖 Compose 启动顺序。合理的应用应该能处理短暂依赖不可用：

- 数据库连接池重试。
- Redis 连接失败可重试或降级。
- 外部 HTTP 服务有超时和重试上限。

## 排查步骤

```bash
docker compose ps
docker inspect 容器名 --format '{{json .State.Health}}'
docker compose logs -f app
docker compose logs -f mysql
```

如果 app 先启动失败，再过几秒数据库才就绪，就说明需要健康检查、等待逻辑或应用重试。
