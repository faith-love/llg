# Docker Compose 编排

Compose 用来管理一组相关容器，例如应用、数据库、缓存、消息队列、Nginx。它特别适合本地开发、测试环境和单机部署。

## Compose 解决什么问题

- 一个命令启动多个依赖服务。
- 用统一文件描述网络、卷、端口和环境变量。
- 让开发环境更接近生产结构。
- 简化停止、重启、查看日志和清理。

## 常见文件名

- `compose.yaml`
- `docker-compose.yaml`
- `docker-compose.yml`

当前建议优先使用 `compose.yaml`，但兼容老项目没有问题。

## 基本结构

```yaml
services:
  app:
    image: my-app:1.0.0
    ports:
      - "8080:8080"
    depends_on:
      - redis
  redis:
    image: redis:7
    volumes:
      - redis-data:/data

volumes:
  redis-data:
```

## 关键字段

| 字段 | 作用 |
| --- | --- |
| `services` | 定义多个服务 |
| `image` | 直接使用镜像 |
| `build` | 从本地 Dockerfile 构建 |
| `ports` | 端口映射 |
| `volumes` | 数据卷挂载 |
| `environment` | 环境变量 |
| `env_file` | 从文件加载环境变量 |
| `depends_on` | 定义启动依赖 |
| `healthcheck` | 健康检查 |
| `networks` | 自定义网络 |

## 常用命令

```bash
docker compose up -d
docker compose down
docker compose ps
docker compose logs -f
docker compose restart
docker compose exec app sh
```

## 推荐做法

- 数据库和缓存使用 named volume。
- 应用服务优先通过服务名访问依赖。
- 敏感变量通过 `.env` 或平台 Secret 注入。
- 为关键服务加 `healthcheck`。
- 使用项目目录作为 Compose 根目录，避免命名冲突。

## 注意事项

- `depends_on` 只表示启动顺序，不等于服务已经可用。
- `localhost` 只表示当前容器自己。
- Compose 项目名会影响网络和容器名称，切换目录时要留意。
- 生产环境部署前先明确日志、数据、升级和回滚策略。
