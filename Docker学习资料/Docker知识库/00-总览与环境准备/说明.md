## Docker 适合解决的问题

| 场景 | Docker 的价值 | 注意点 |
| --- | --- | --- |
| 开发环境统一 | 把 MySQL、Redis、MQ、Nginx 等依赖固定成配置文件 | 数据要挂卷，端口不要冲突 |
| 应用交付 | 把运行时、依赖、启动命令打包成镜像 | 镜像标签要可追溯 |
| 测试隔离 | 每个分支或测试任务可以启动独立依赖 | 清理策略要明确 |
| 本地复现线上问题 | 使用相同镜像和启动参数复现问题 | 配置、数据、网络也要对齐 |
| 轻量部署 | 单机或小规模服务可用 Compose 快速部署 | 生产仍要考虑监控、备份、安全 |

## Docker 不适合直接解决的问题

- 不替代应用架构设计。慢 SQL、内存泄漏、线程池配置错误不会因为进容器而消失。
- 不替代配置管理。容器只是运行单元，配置仍要分环境管理。
- 不替代备份。容器删除后，未挂载的数据会丢。
- 不替代集群编排。多机弹性伸缩、高可用调度、滚动发布通常需要 Kubernetes、Nomad 或云厂商平台。
- 不适合把一个容器当成完整服务器，容器里不应长期运行 SSH、systemd 和一堆无关进程。

## 学习前准备

| 环境 | 建议 |
| --- | --- |
| Windows | 使用 Docker Desktop，并开启 WSL 2 后端 |
| macOS | 使用 Docker Desktop |
| Linux | 安装 Docker Engine 和 Compose 插件 |
| 编辑器 | 准备 Dockerfile、YAML、Shell 的语法高亮 |
| 练习目录 | 每个实验单独目录，避免镜像、卷和端口互相污染 |

## 必会检查命令

```bash
docker version
docker info
docker compose version
docker run --rm hello-world
docker system df
```

这些命令分别确认客户端和服务端版本、守护进程状态、Compose 是否可用、镜像拉取和容器运行是否正常、当前 Docker 占用多少磁盘。

## 推荐练习顺序

1. 拉取并运行一个官方镜像，例如 `nginx`。
2. 用端口映射访问容器服务。
3. 进入容器查看文件和进程。
4. 给容器挂载一个本地目录。
5. 写一个最小 Dockerfile 构建自己的镜像。
6. 用 Compose 同时启动应用、数据库和缓存。
7. 删除容器后验证数据是否仍然存在。
8. 故意制造端口冲突、配置错误、权限错误，再按排障路径修复。

## 学习底线

- 所有破坏性命令执行前先确认目标：容器名、镜像名、卷名、网络名。
- 不要在不理解影响范围时执行 `docker system prune -a --volumes`。
- 数据库、Redis、MinIO 等有状态服务必须挂载 volume 或 bind mount。
- 生产环境不要依赖 `latest`，不要把密码写死进镜像。
- 先学会单机 Docker 和 Compose，再考虑 Kubernetes。
