# 实验目录与清理边界

Docker 学习最容易把本地环境搞乱：镜像越来越多、容器名冲突、端口占用、卷里不知道存了什么。练习前先定目录和命名规则，后面排障会简单很多。

## 推荐目录结构

```text
docker-labs/
  00-hello-world/
  01-nginx-port/
  02-dockerfile/
  03-volume/
  04-network/
  05-compose/
```

每个实验目录只放当前实验需要的 `Dockerfile`、`compose.yaml`、`.env.example` 和说明，避免一个目录混用多个实验。

## 命名规则

| 对象 | 建议命名 | 示例 |
| --- | --- | --- |
| 镜像 | `项目名:版本` | `demo-api:1.0.0` |
| 容器 | `项目-服务-环境` | `demo-redis-dev` |
| 网络 | `项目-net` | `demo-net` |
| 卷 | `项目-服务-data` | `demo-mysql-data` |
| Compose 项目 | 使用目录名或 `-p` 指定 | `docker compose -p demo up -d` |

## 清理命令分级

| 命令 | 风险 | 说明 |
| --- | --- | --- |
| `docker rm 容器名` | 低 | 删除指定停止容器 |
| `docker rm -f 容器名` | 中 | 强制删除运行容器 |
| `docker image prune` | 中 | 删除悬空镜像 |
| `docker container prune` | 中 | 删除所有停止容器 |
| `docker volume prune` | 高 | 删除未被使用的卷，可能包含重要数据 |
| `docker system prune -a --volumes` | 极高 | 全面清理镜像、容器、网络、卷 |

## 清理前检查

```bash
docker ps -a
docker images
docker volume ls
docker system df
```

生产服务器上清理前必须确认：

- 是否有回滚镜像。
- 是否有停止但需要保留的容器。
- volume 里是否有数据库、上传文件、对象存储或其他业务数据。
- 当前机器是否有备份。

## 练习建议

- 每个实验使用独立容器名、网络名和卷名。
- 完成一个实验后写下启动命令和清理命令。
- 数据卷实验不要立刻清理，先验证删除容器后数据是否还在。
- 故意制造端口冲突和挂载错误，练习排查路径。
