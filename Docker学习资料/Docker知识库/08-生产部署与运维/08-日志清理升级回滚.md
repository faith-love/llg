# 日志清理升级回滚

这是一份偏操作的运维清单，适合单机 Docker 或 Compose 场景。

## 日志清理

如果容器日志写得过快，宿主机磁盘会先满。先确认日志位置，再做轮转或限额。

常见查看方式：

```bash
docker logs --tail=200 容器名
docker inspect 容器名
```

如果是文件日志，应该找到挂载目录并确认是否有轮转。

## 镜像清理

```bash
docker image ls
docker image prune
```

不要在没确认回滚需求前直接做全量清理。

## 升级流程

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs -f
```

升级后重点看：

- 容器是否重新创建成功。
- 健康检查是否通过。
- 业务接口是否正常。
- 数据是否被正确挂载。

## 回滚流程

如果新版本异常：

1. 恢复上一个镜像标签。
2. 回到上一个 Compose 配置。
3. 重新启动。
4. 对比日志差异。
5. 记录根因和修复方案。

## 清理原则

- 清理前先判断是镜像、容器、卷还是网络占用空间。
- 数据库卷不能当成垃圾清掉。
- 生产环境保留最近几个可回滚版本。
- 定期做恢复演练，确认备份真的可用。
