# 生产目录规划

单机 Docker 部署最怕文件散落：Compose 文件在一个地方，数据在另一个地方，日志又在默认位置。目录规划先做好，后续备份、迁移和排障都会简单。

## 推荐结构

```text
/opt/docker/
  demo-api/
    compose.yaml
    .env
    .env.example
    config/
    data/
    logs/
    backup/
    scripts/
```

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `config/` | 外置配置、Nginx 配置、应用配置模板 |
| `data/` | 上传文件、业务持久化文件 |
| `logs/` | 需要落盘的应用日志 |
| `backup/` | 备份输出目录或备份脚本临时目录 |
| `scripts/` | 启停、备份、恢复、健康检查脚本 |

## 配置管理

- `.env.example` 可以提交，说明必填变量。
- `.env` 不提交仓库。
- 生产密码、Token、私钥优先使用平台 Secret 或受控配置。
- 配置变更要记录时间、原因和回滚方式。

## 权限建议

- 业务目录不归 root 应用进程随意写。
- 数据目录只给需要写入的容器用户权限。
- 配置目录尽量只读挂载。
- 备份目录限制访问权限。

## 迁移清单

迁移机器时至少带走：

- Compose 文件。
- `.env` 或部署配置。
- 持久化数据。
- 外置配置。
- 备份脚本和恢复说明。
- 镜像版本记录。
