# 基础镜像选择策略

基础镜像决定了运行环境、镜像体积、安全更新方式和排障能力。选择基础镜像时，不要只看大小。

## 常见类型

| 类型 | 优点 | 风险 |
| --- | --- | --- |
| Debian/Ubuntu 类 | 兼容性好，排障工具容易安装 | 体积相对大 |
| Alpine | 体积小 | musl libc 兼容性可能带来坑 |
| distroless | 攻击面小 | 排障困难，不适合新手直接上生产 |
| JDK 镜像 | 能编译 Java 项目 | 运行镜像体积大 |
| JRE 镜像 | 更适合运行 Java 应用 | 无法在运行阶段编译 |
| Nginx 镜像 | 适合托管静态文件和反向代理 | 配置需要外置管理 |

## Java 项目建议

构建阶段用 Maven 或 Gradle 镜像：

```dockerfile
FROM maven:3.9-eclipse-temurin-17 AS build
```

运行阶段用 JRE：

```dockerfile
FROM eclipse-temurin:17-jre
```

这样既能在镜像构建时编译，又不会把完整构建工具链带到生产运行镜像。

## 前端项目建议

构建阶段用 Node：

```dockerfile
FROM node:20-alpine AS build
```

运行阶段用 Nginx：

```dockerfile
FROM nginx:stable-alpine
```

最终镜像只放 `dist` 静态产物和 Nginx 配置。

## 选择原则

- 优先使用官方或可信基础镜像。
- 固定主版本，不依赖浮动 `latest`。
- 新手不要为了极致体积直接选难排障镜像。
- 生产镜像要能定期重建和安全更新。
- 团队里保持基础镜像标准化。

## 常见误区

- 只看镜像大小，不看兼容性。
- 在运行镜像里安装一堆构建工具。
- 每个项目随意选不同基础镜像，导致维护成本上升。
- 生产镜像多年不重建，基础系统漏洞长期存在。
