# 镜像与 Dockerfile

本模块解决镜像构建问题。镜像不是把服务器复制一份，而是把应用运行所需的文件、依赖、启动命令和元数据组织成可复现的软件包。

## 镜像分层模型

Docker 镜像由多层只读文件系统组成。Dockerfile 中多数指令都会产生新层，例如 `RUN`、`COPY`、`ADD`。容器启动时会在镜像层上方加一个可写层。

这个模型带来两个关键影响：

1. 构建缓存依赖指令顺序。越稳定的步骤越应该靠前。
2. 删除文件不一定能减少最终镜像体积，因为文件可能已经存在于上一层。

## Dockerfile 常用指令

| 指令 | 作用 | 建议 |
| --- | --- | --- |
| `FROM` | 指定基础镜像 | 固定主版本或具体标签 |
| `WORKDIR` | 设置工作目录 | 比反复 `cd` 更稳定 |
| `COPY` | 复制构建上下文文件 | 优先用 `COPY`，除非需要 `ADD` 的特殊能力 |
| `RUN` | 构建阶段执行命令 | 合理合并清理步骤 |
| `ENV` | 设置镜像内环境变量 | 不放敏感信息 |
| `ARG` | 设置构建参数 | 只在构建期有效 |
| `EXPOSE` | 声明容器服务端口 | 不是端口映射 |
| `USER` | 切换运行用户 | 生产镜像优先非 root |
| `CMD` | 默认启动命令 | 可被 `docker run` 后续命令覆盖 |
| `ENTRYPOINT` | 固定入口命令 | 适合包装启动脚本或固定可执行文件 |

## 最小示例

```dockerfile
FROM nginx:stable-alpine
COPY dist/ /usr/share/nginx/html/
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

这个 Dockerfile 的含义：

1. 基于 Nginx Alpine 镜像。
2. 把本地构建产物复制到 Nginx 静态目录。
3. 声明容器内服务端口是 `80`。
4. 以前台方式启动 Nginx。

## 构建命令

```bash
docker build -t my-web:1.0.0 .
docker images my-web
docker run --rm -p 8080:80 my-web:1.0.0
```

构建时最后的 `.` 是构建上下文，不是随便写的路径。Docker 只能访问构建上下文里的文件，`.dockerignore` 可以排除不需要发送给 Docker daemon 的内容。

## 构建上下文和 .dockerignore

常见 `.dockerignore`：

```text
.git
node_modules
dist
target
logs
*.log
.env
```

原则：

- 不把源码管理历史放进构建上下文。
- 不把本地依赖目录放进构建上下文，除非明确需要。
- 不把日志、临时文件、密钥、`.env` 放进镜像。
- Java 项目通常排除 `target` 后再按构建策略决定是否复制 jar。
- 前端项目如果镜像内构建，就排除 `node_modules`；如果镜像只放产物，就复制 `dist`。
