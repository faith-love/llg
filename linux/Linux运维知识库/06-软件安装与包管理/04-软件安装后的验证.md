# 软件安装后的验证

## 作用

软件安装后的验证，是把“命令执行成功”推进到“服务真的可用”的关键步骤。包管理器显示安装完成，只代表软件包写入系统，并不代表版本正确、路径正确、配置正确、服务启动、自启生效、端口监听、业务能访问。

运维部署里，每次安装软件后都应该形成固定检查链路：

1. 命令是否存在。
2. 命令路径是否符合预期。
3. 版本是否满足项目要求。
4. 包来源和安装文件是否清楚。
5. 配置文件是否存在且语法正确。
6. systemd 服务是否启动和开机自启。
7. 端口是否监听。
8. 日志是否有错误。
9. 业务请求是否能成功。

## 痛点

- `apt install nginx` 成功了，但 `systemctl status nginx` 显示启动失败。
- `java -version` 有输出，但版本不是项目要求的 Java 17。
- 终端里 `node -v` 正常，systemd 服务启动时却找不到 `node`。
- Nginx 进程在运行，但防火墙或安全组没放行，外部仍然访问不到。
- 软件安装路径不清楚，后续升级和回滚无从下手。

## 核心小点

### 1. 验证命令路径

常用命令：

```bash
command -v nginx
which nginx
type -a java
readlink -f "$(command -v java)"
```

区别：

- `command -v` 是 Shell 内置能力，脚本里更常用。
- `which` 直观，但有些情况下不能展示 Shell 函数或别名。
- `type -a` 可以显示同名命令的多个来源。
- `readlink -f` 可以解析软链接后的真实路径。

示例：

```bash
type -a java
readlink -f "$(command -v java)"
```

如果输出指向 `/usr/bin/java`，还要继续看它是否链接到 `/etc/alternatives/java`，最终指向哪个 JDK。

### 2. 验证软件版本

常用命令：

```bash
nginx -v
java -version
node -v
npm -v
python3 --version
redis-server --version
mysql --version
```

版本验证要结合项目要求：

- Java 项目：确认 Java 8、11、17、21 哪个版本。
- 前端构建：确认 Node.js 大版本是否符合 `package.json` 或团队约定。
- Python 项目：确认 Python 3.x 版本和虚拟环境。
- Nginx：确认是否需要 HTTP/2、stream、特定模块。

不要只看“大概能运行”，要记录准确版本号。

### 3. 验证包来源

Ubuntu/Debian：

```bash
dpkg -S "$(command -v nginx)"
dpkg -L nginx
apt-cache policy nginx
```

RHEL 系：

```bash
rpm -qf "$(command -v nginx)"
rpm -ql nginx
dnf info nginx
```

作用：

- 确认命令是不是包管理器安装的。
- 确认配置文件、服务文件、默认目录在哪里。
- 确认软件来自系统仓库、第三方仓库还是手动路径。

### 4. 验证配置文件

不同软件有不同的配置检测命令：

```bash
nginx -t
redis-server /etc/redis/redis.conf --test-memory 2
sshd -t
named-checkconf
```

有些软件没有统一的语法检查命令，此时至少要：

- 找到配置文件路径。
- 查看启动日志是否报配置错误。
- 用最小业务请求验证配置生效。

修改配置时推荐流程：

```bash
sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak.$(date +%F-%H%M)
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl status nginx --no-pager
```

### 5. 验证 systemd 服务

查看服务状态：

```bash
systemctl status nginx --no-pager
systemctl is-active nginx
systemctl is-enabled nginx
```

启动和自启：

```bash
sudo systemctl start nginx
sudo systemctl enable nginx
sudo systemctl enable --now nginx
```

查看服务文件：

```bash
systemctl cat nginx
systemctl show nginx -p User -p Group -p ExecStart -p Environment
```

要看清楚：

- 服务是否 active。
- 是否 enabled。
- 启动用户是谁。
- `ExecStart` 指向哪个命令。
- 是否有额外环境变量。
- 日志中是否有失败原因。

### 6. 验证端口监听

```bash
ss -lntup
ss -lntup | grep ':80'
ss -lntup | grep nginx
```

字段理解：

- `l`：监听中的 socket。
- `n`：不解析域名和服务名，直接显示数字端口。
- `t`：TCP。
- `u`：UDP。
- `p`：进程信息。

示例：

```bash
sudo ss -lntup | grep ':80'
```

如果本机端口监听正常，但外部访问失败，还要继续检查：

- 防火墙。
- 云安全组。
- Nginx server_name。
- DNS 解析。
- 上游服务健康状态。

### 7. 验证日志

systemd 日志：

```bash
journalctl -u nginx -n 100 --no-pager
journalctl -u nginx -f
```

常见应用日志位置：

```bash
/var/log/nginx/access.log
/var/log/nginx/error.log
/var/log/redis/
/var/log/mysql/
/var/log/messages
/var/log/syslog
```

安装后要看最近日志，不要只看服务状态。服务可能 active，但日志里持续报连接失败、权限不足、配置警告。

### 8. 验证业务可用

本机请求：

```bash
curl -I http://127.0.0.1
curl http://127.0.0.1:8080/health
```

从其他机器请求：

```bash
curl -I http://服务器IP
```

DNS 场景：

```bash
curl -I http://example.com
dig example.com
```

业务验证要尽量覆盖：

- 本机访问。
- 内网访问。
- 外网访问。
- 域名访问。
- 健康检查接口。

## 安装后检查模板

可以把下面模板复制到部署记录里：

```text
软件名称：
安装方式：
安装命令：
包名：
版本：
命令路径：
真实路径：
配置文件：
服务名：
运行用户：
监听端口：
日志路径：
自启状态：
验证命令：
回滚方式：
```

## 好用工具

- `ss`：查看端口监听，替代旧的 `netstat`。
- `lsof`：查看端口或文件被哪个进程占用。
- `curl`：验证 HTTP 服务和接口。
- `jq`：格式化 JSON 响应，检查接口返回。
- `journalctl`：查看 systemd 服务日志。
- `nc`：测试 TCP 端口连通性。

安装示例：

```bash
sudo apt install curl jq lsof netcat-openbsd
sudo dnf install curl jq lsof nc
```

## 使用技巧

- 安装后按“路径 -> 版本 -> 包来源 -> 配置 -> 服务 -> 端口 -> 日志 -> 业务请求”的顺序检查。
- 命令行里能运行，不代表 systemd 也能运行；systemd 的环境变量更少。
- 本机能访问，不代表外部能访问；外部访问还受防火墙、安全组、DNS、代理影响。
- 服务 active 不代表业务正常；要结合端口、日志和接口响应。
- 每次安装都写部署记录，后续升级、迁移、排障会节省大量时间。

## 难点

- 多版本并存时，`which` 找到的命令可能不是服务实际使用的命令。
- Nginx、Redis、MySQL 等服务可能启动成功，但因权限、端口、配置或认证问题不可用。
- 云服务器本机防火墙开放了，云安全组没开放，外部仍然访问不到。
- 包管理器安装的软件和手动解压软件混用时，路径和服务文件容易不一致。

## 重点

- 安装完成不等于可用，必须做验证闭环。
- 版本、路径、服务名、端口、配置路径和日志路径都要记录。
- systemd 服务验证要看 `status`、`is-enabled`、`systemctl cat` 和 `journalctl`。
- 排障时从本机到外部逐层验证，不要直接跳到重装软件。

## 练习

1. 安装 `nginx` 后，完成路径、版本、包来源、服务、自启、端口、日志验证。
2. 使用 `systemctl cat nginx` 找出 Nginx 的启动命令和运行方式。
3. 用 `ss`、`lsof`、`curl` 分别验证 80 端口监听和 HTTP 返回。
4. 写一份安装记录，包含版本、路径、配置文件、服务名、端口和回滚方式。
