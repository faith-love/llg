# 03 进程性能与日志监控工具

进程、性能和日志工具用于回答三个问题：当前谁在消耗资源，系统瓶颈在哪里，服务为什么失败或变慢。排障时先用轻量命令确认现象，再决定是否引入监控平台。

## htop

### 作用

`htop` 是交互式进程查看工具，比 `top` 更直观。

### 适合场景

- 查看 CPU、内存占用最高的进程。
- 临时观察负载。
- 找到异常进程 PID。

### 使用

```bash
htop
```

关注：

- CPU 是否长期打满。
- 内存是否接近耗尽。
- Load average 是否明显高于 CPU 核数。
- 进程用户是否符合预期。

### 注意事项

- 结束进程前确认是否由 systemd 或容器管理。
- 生产环境优先用服务管理命令停止，不要直接杀核心进程。

## glances

### 作用

`glances` 是一屏式系统监控工具，可同时看 CPU、内存、磁盘、网络、进程。

### 使用

```bash
glances
```

适合快速判断：

- CPU 瓶颈。
- 内存瓶颈。
- 磁盘 IO 瓶颈。
- 网络吞吐异常。

### 注意事项

- 适合临时观察，不替代长期监控。
- 如果要 Web 模式，注意不要无保护暴露公网。

## iotop

### 作用

`iotop` 用于查看进程级磁盘 IO。

### 使用

```bash
sudo iotop
sudo iotop -o
```

`-o` 只显示有 IO 的进程。

适合排查：

- 系统很卡但 CPU 不高。
- 数据库或日志大量写盘。
- 备份任务影响业务。

### 注意事项

- 需要 root 权限。
- 某些系统需要内核支持 taskstats。

## sysstat

### 作用

`sysstat` 提供 `iostat`、`mpstat`、`sar` 等工具，用于性能分析和历史数据查看。

### 安装

```bash
sudo apt install sysstat
sudo dnf install sysstat
```

### 常用命令

磁盘 IO：

```bash
iostat -x 1
```

CPU 每核情况：

```bash
mpstat -P ALL 1
```

CPU 历史或采样：

```bash
sar -u 1 5
```

内存：

```bash
sar -r 1 5
```

网络：

```bash
sar -n DEV 1 5
```

### 判断点

- `iostat` 中 `%util` 高，说明磁盘可能繁忙。
- `await` 高，说明 IO 等待明显。
- `mpstat` 中 `%iowait` 高，说明 CPU 等 IO。
- `sar` 适合看间歇性问题的历史趋势。

## lsof

### 作用

`lsof` 查看进程打开的文件、端口和已删除但仍被占用的文件。

### 常用命令

查端口：

```bash
sudo lsof -i :8080
```

查进程打开文件：

```bash
sudo lsof -p PID
```

查删除但仍占用空间的文件：

```bash
sudo lsof | grep deleted
```

### 场景

- 端口被占用。
- 删除日志后磁盘空间没释放。
- 判断进程是否仍在读写某个文件。

## journalctl

### 作用

`journalctl` 查看 systemd 管理服务的日志。

### 常用命令

查看最近日志：

```bash
journalctl -u demo-api -n 100 --no-pager
```

跟随日志：

```bash
journalctl -u demo-api -f
```

按时间：

```bash
journalctl -u demo-api --since "2026-05-12 10:00"
```

看错误级别：

```bash
journalctl -p err -n 100 --no-pager
```

清理旧日志：

```bash
sudo journalctl --vacuum-time=7d
```

### 注意事项

- 不要只看最后一行，启动失败要找第一条关键错误。
- 日志可能包含敏感信息，外发前脱敏。

## logrotate

### 作用

`logrotate` 用于日志轮转，避免日志文件无限增长撑满磁盘。

### 配置示例

```text
/opt/apps/demo-api/shared/logs/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}
```

测试配置：

```bash
sudo logrotate -d /etc/logrotate.d/demo-api
```

强制执行：

```bash
sudo logrotate -f /etc/logrotate.d/demo-api
```

### 注意事项

- `copytruncate` 简单但可能丢少量日志。
- 更好的方式是应用支持重新打开日志文件。
- 轮转后要确认新日志属主和权限正确。

## Prometheus、Grafana、Loki

### Prometheus + Grafana

用于指标监控和图表展示。

常见组件：

- Prometheus：采集和存储指标。
- Node Exporter：采集 Linux 主机指标。
- Grafana：展示图表。
- Alertmanager：发送告警。

适合：

- 多台服务器监控。
- CPU、内存、磁盘、网络趋势。
- 服务可用性告警。

### Loki + Promtail

用于集中日志查询，常与 Grafana 配合。

适合：

- 多台服务器集中查日志。
- 按服务名、主机名、环境标签过滤。

### 注意事项

- 监控端口不要裸露公网。
- 日志采集前先做脱敏。
- 告警要有处理人和处理动作，否则只是噪音。

## 排障组合

| 现象 | 工具组合 |
| --- | --- |
| 服务启动失败 | `systemctl status` + `journalctl` |
| CPU 高 | `htop` + `mpstat` |
| 内存高 | `free` + `htop` + `ps` |
| 磁盘 IO 高 | `iotop` + `iostat` |
| 磁盘空间没释放 | `df` + `lsof deleted` |
| 日志太大 | `du` + `logrotate` |

## 练习

1. 用 `htop` 找出当前 CPU 和内存最高的进程。
2. 用 `iostat -x 1` 观察磁盘 IO。
3. 用 `journalctl -u` 查看一个 systemd 服务日志。
4. 创建一个测试日志并配置 logrotate。
5. 删除一个被进程打开的文件，观察 `lsof | grep deleted`。
