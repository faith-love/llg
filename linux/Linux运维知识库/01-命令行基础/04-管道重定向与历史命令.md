# 管道重定向与历史命令

## 作用

管道、重定向与历史命令用于提高命令行处理效率。Linux 运维经常需要从大量日志、进程、端口、文本中找出关键信息。管道负责把多个命令串起来，重定向负责把输出写入文件，历史命令负责复用之前的操作。

## 痛点

- 日志很多，只能手动翻页。
- 不会组合命令，找不到真正有用的信息。
- 不理解 `>` 和 `>>`，把文件覆盖了。
- 不知道错误输出和标准输出的区别。
- 历史命令中包含密码或 Token，有泄露风险。
- 直接重复执行历史命令，忘记路径和服务名已经变化。

## 优点

- 能快速过滤日志和进程。
- 能把命令结果保存成文件，方便复盘。
- 能把复杂排查过程串成可复用命令。
- 能快速找回之前执行过的部署或排障命令。

## 管道

管道符是：

```bash
|
```

作用：把左边命令的标准输出交给右边命令处理。

示例：

```bash
ps aux | grep nginx
```

理解：

- `ps aux` 输出所有进程。
- `grep nginx` 从输出中筛选包含 nginx 的行。

## 常见管道场景

### 查进程

```bash
ps aux | grep demo-api
pgrep -af demo-api
```

注意：`ps aux | grep demo-api` 可能会把 `grep demo-api` 自己也匹配出来。

### 查日志错误

```bash
journalctl -u demo-api --since "1 hour ago" | grep -i error
tail -n 1000 app.log | grep -n "Exception"
```

### 统计访问 IP

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head
```

拆解：

- `awk '{print $1}'` 取第一列。
- `sort` 排序。
- `uniq -c` 统计重复次数。
- `sort -nr` 按数字倒序。
- `head` 取前几行。

## 标准输出和错误输出

Linux 命令常见输出：

| 名称 | 编号 | 含义 |
| --- | --- | --- |
| 标准输入 | 0 | 输入 |
| 标准输出 | 1 | 正常输出 |
| 标准错误 | 2 | 错误输出 |

示例：

```bash
ls /not-exist > out.log
```

这可能不会把错误写入 `out.log`，因为错误走的是标准错误。

把错误也写入：

```bash
ls /not-exist > out.log 2>&1
```

## 重定向

### 覆盖写入

```bash
echo "hello" > demo.txt
```

如果 `demo.txt` 已存在，会被覆盖。

### 追加写入

```bash
echo "world" >> demo.txt
```

追加到文件末尾。

### 错误输出

```bash
command 2> error.log
command > all.log 2>&1
```

### 丢弃输出

```bash
command > /dev/null 2>&1
```

适合不关心输出的命令，但排障时不要随便丢弃错误。

## `sudo` 与重定向陷阱

错误示例：

```bash
sudo echo "test" > /etc/demo.conf
```

原因：`echo` 用 sudo 执行，但 `>` 是当前 Shell 执行，当前用户可能没有写 `/etc/demo.conf` 权限。

正确方式：

```bash
echo "test" | sudo tee /etc/demo.conf
```

追加：

```bash
echo "test" | sudo tee -a /etc/demo.conf
```

## 历史命令

查看历史：

```bash
history
history | grep systemctl
```

反向搜索：

```text
Ctrl + r
```

清理当前会话历史中的敏感命令要谨慎，重点是不要把敏感信息直接写进命令。

风险示例：

```bash
mysql -u root -p明文密码
curl -H "Authorization: Bearer 明文Token" ...
```

更好的做法：

- 使用交互式密码输入。
- 使用环境变量或受控 secret。
- 避免在命令历史中留下完整密钥。

## 使用技巧

- 管道适合查看、过滤、统计，不适合直接接危险删除。
- 重定向到文件前确认 `>` 还是 `>>`。
- 排障命令输出建议保存到带时间戳的文件。

示例：

```bash
journalctl -u demo-api --since "1 hour ago" > demo-api-$(date +%F-%H%M%S).log
```

## 难点

- 管道默认只传标准输出，不传错误输出。
- `>` 会覆盖文件，很多误操作来自这里。
- `sudo` 不会自动让重定向具备 root 权限。
- 历史命令可能记录敏感信息。

## 重点

- 管道是“输出 -> 输入”的组合。
- `>` 覆盖，`>>` 追加。
- `2>&1` 合并错误输出。
- 写 root 文件用 `sudo tee`。
- 历史命令复用前要检查路径、服务名、环境。

## 练习

1. 用 `ps aux | grep` 查找当前 Shell 或 ssh 进程。
2. 创建一个日志文件，用 `grep`、`sort`、`uniq -c` 做简单统计。
3. 对比 `>` 和 `>>` 对文件内容的影响。
4. 尝试 `sudo echo ... > /root/test`，理解为什么失败，再用 `sudo tee` 修复。
5. 用 `Ctrl + r` 找回一条历史命令，但不要直接执行，先检查内容。
