# 路径切换与目录定位

## 作用

路径切换与目录定位用于解决“我在哪里、目标文件在哪里、命令会作用到哪个路径”的问题。Linux 运维中大量错误都来自路径误判：在错误目录执行删除、把文件复制到错误位置、以为配置在当前目录但服务实际读取另一个路径。

## 痛点

- 不理解绝对路径和相对路径，命令执行结果和预期不一致。
- 在 `/tmp`、`/root`、项目目录之间切换后忘记当前位置。
- 用相对路径写脚本，换个目录执行就失败。
- 不知道 `.`、`..`、`~`、`-` 的含义。
- 找不到配置文件、日志文件或部署目录。

## 优点

- 能快速定位文件和目录。
- 能降低误删、误移动风险。
- 写脚本时路径更稳定。
- 排查服务时能区分“当前看到的文件”和“服务实际读取的文件”。

## 路径基础

### 绝对路径

以 `/` 开头，从根目录开始。

```bash
/opt/apps/demo-api/current/app.jar
/etc/nginx/nginx.conf
/var/log/nginx/error.log
```

优点：

- 不依赖当前目录。
- 脚本中更稳定。
- 适合生产操作和配置文件引用。

### 相对路径

不以 `/` 开头，相对于当前目录。

```bash
logs/app.log
../config/app.env
./deploy.sh
```

风险：

- 当前目录一变，目标就变。
- 在脚本中容易因为运行位置不同而失败。

## 常用定位命令

### `pwd`

显示当前目录：

```bash
pwd
```

高风险操作前先执行：

```bash
hostname && whoami && pwd
```

### `ls`

查看目录内容：

```bash
ls
ls -l
ls -lah
ls -lt
```

常用选项：

- `-l`：显示详细信息。
- `-a`：显示隐藏文件。
- `-h`：人类可读大小。
- `-t`：按修改时间排序。

### `cd`

切换目录：

```bash
cd /opt/apps
cd ..
cd ~
cd -
```

含义：

- `cd /opt/apps`：进入绝对路径。
- `cd ..`：返回上级目录。
- `cd ~`：回到当前用户家目录。
- `cd -`：回到上一次所在目录。

## 特殊路径符号

| 符号 | 含义 | 示例 |
| --- | --- | --- |
| `.` | 当前目录 | `./deploy.sh` |
| `..` | 上级目录 | `cd ..` |
| `~` | 当前用户家目录 | `cd ~` |
| `-` | 上一次目录 | `cd -` |
| `/` | 根目录 | `cd /` |

注意：

```bash
sudo cd /root
```

这通常没有意义，因为 `cd` 是 Shell 内置命令。要进入 root shell 可以使用：

```bash
sudo -i
```

但生产环境不要长期在 root shell 中操作。

## 查找文件路径

按名称找文件：

```bash
find /opt/apps -name "*.log"
find /etc -name "nginx.conf" 2>/dev/null
```

查看命令路径：

```bash
which java
command -v nginx
readlink -f $(which java)
```

查看软链接真实路径：

```bash
readlink -f /opt/apps/demo-api/current
```

## 路径定位排障场景

### 场景一：服务找不到 jar

检查：

```bash
ls -lah /opt/apps/demo-api/current
readlink -f /opt/apps/demo-api/current
systemctl cat demo-api
```

判断：

- `current` 是否指向真实 release。
- `ExecStart` 中 jar 路径是否存在。
- 服务用户是否有权限读取。

### 场景二：Nginx 静态资源 404

检查：

```bash
nginx -T | grep -n "root"
ls -lah /opt/apps/demo-web/current
readlink -f /opt/apps/demo-web/current
```

判断：

- Nginx `root` 指向的目录是否存在。
- `index.html` 是否在该目录下。
- `current` 是否指向正确版本。

### 场景三：脚本手动运行成功，cron 失败

常见原因是脚本使用相对路径。

修复思路：

```bash
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
cd "$SCRIPT_DIR"
```

或者在脚本里全部使用绝对路径。

## 使用技巧

- 生产脚本中尽量使用绝对路径。
- 删除前用 `pwd` 和 `ls` 确认目标。
- 软链接部署时用 `readlink -f` 确认真实版本。
- 查看服务配置时不要只看当前目录文件，要看 systemd 或 Nginx 实际引用路径。

## 难点

- 软链接路径和真实路径容易混淆。
- cron、systemd 的工作目录不一定是你手动执行时的目录。
- `~` 表示当前用户家目录，root 和普通用户的 `~` 不一样。
- 相对路径在脚本中非常容易受执行位置影响。

## 重点

- 绝对路径稳定，相对路径依赖当前目录。
- `pwd` 是高风险操作前的基本确认。
- `current` 软链接要用 `readlink -f` 确认。
- 服务实际读取路径以 systemd、Nginx、应用配置为准。

## 练习

1. 创建 `/tmp/linux-path-lab/a/b/c`，练习 `cd ..`、`cd -`、`cd ~`。
2. 在不同目录执行 `ls logs`，观察相对路径差异。
3. 创建一个软链接，用 `readlink -f` 查看真实路径。
4. 写一个脚本，分别用相对路径和绝对路径读取文件，比较在不同目录执行的结果。
