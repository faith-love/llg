# 通配符与危险命令边界

## 作用

通配符与危险命令边界用于解决“如何批量匹配文件，又不误删误改”的问题。Linux Shell 会在命令执行前展开通配符，批量操作非常方便，但也很危险。尤其是 `rm`、`chmod -R`、`chown -R`、`find -delete` 这类命令，执行前必须确认范围。

## 痛点

- `rm *.log` 以为只删一个文件，实际删了一批。
- 当前目录不对，通配符匹配到错误目标。
- 变量为空时执行删除脚本，导致范围扩大。
- 用 `chmod -R 777` 快速修权限，留下安全风险。
- `find ... -delete` 没预览就直接删除。

## 优点

- 能安全执行批量操作。
- 能在删除、改权限、移动文件前确认影响范围。
- 能写更稳妥的清理脚本。
- 能避免生产环境大范围误操作。

## 常见通配符

| 通配符 | 含义 | 示例 |
| --- | --- | --- |
| `*` | 匹配任意长度字符 | `*.log` |
| `?` | 匹配任意一个字符 | `app-?.log` |
| `[abc]` | 匹配集合中的一个字符 | `file[123].txt` |
| `[0-9]` | 匹配数字范围 | `log-[0-9].txt` |

示例：

```bash
ls *.log
ls app-2026-05-*.log
ls file?.txt
```

重点：通配符通常由 Shell 展开，不是 `rm`、`ls` 自己展开。

## 执行前预览

危险操作前先用只读命令预览。

删除前：

```bash
ls -lah *.log
```

确认后再：

```bash
rm *.log
```

find 删除前：

```bash
find /opt/apps/demo-api/shared/logs -name "*.log.*" -mtime +14
```

确认后再：

```bash
find /opt/apps/demo-api/shared/logs -name "*.log.*" -mtime +14 -delete
```

## 高风险命令

### `rm -rf`

风险：递归强制删除。

更稳妥做法：

```bash
ls -lah "$target"
mv "$target" /tmp/delete-review/
```

先移动到待删除区，观察确认后再删除。

### `chmod -R`

风险：递归改变权限，可能让敏感配置过宽，或让脚本不可执行。

不推荐：

```bash
chmod -R 777 /opt/apps/demo-api
```

更合理：

```bash
chown -R app:app /opt/apps/demo-api
chmod 750 /opt/apps/demo-api
chmod 640 /opt/apps/demo-api/shared/config/demo-api.env
chmod 750 /opt/apps/demo-api/shared/logs
```

### `chown -R`

风险：递归改变属主，可能破坏系统目录或其他服务权限。

安全边界：

- 只对应用目录执行。
- 不对 `/`、`/etc`、`/usr` 这类系统目录随便递归。

### `find -delete`

风险：匹配范围错误时批量删除。

原则：

- 先不加 `-delete`。
- 限制目录范围。
- 限制文件类型。
- 限制名称和时间。

示例：

```bash
find /opt/apps/demo-api/shared/logs -type f -name "*.log.*" -mtime +14
```

## 变量为空风险

脚本中最危险的情况之一：

```bash
rm -rf "$TARGET_DIR"/*
```

如果 `TARGET_DIR` 为空或错误，后果可能严重。

更稳妥：

```bash
if [ -z "${TARGET_DIR:-}" ]; then
  echo "TARGET_DIR is empty"
  exit 1
fi

if [ ! -d "$TARGET_DIR" ]; then
  echo "TARGET_DIR not exists: $TARGET_DIR"
  exit 1
fi

echo "will clean: $TARGET_DIR"
ls -lah "$TARGET_DIR"
```

## `sudo` 风险

`sudo` 会扩大命令权限。不要用 sudo 掩盖理解不足。

执行前问：

- 为什么当前用户没有权限？
- 目标文件应该归谁？
- 是不是应该调整目录权限，而不是 sudo 执行？
- 这条命令会不会影响系统目录？

## 使用技巧

- 批量操作前先 `ls` 或 `find` 预览。
- 删除前优先移动到临时待删除目录。
- 脚本中检查变量是否为空。
- 生产环境少用一行命令完成复杂删除。
- 递归改权限前先明确目录边界。

## 难点

- 通配符没匹配到文件时，不同 Shell 行为可能不同。
- 带空格的文件名需要正确引用变量。
- 通配符展开发生在命令执行前。
- 递归操作的影响范围很难从一眼看清。

## 重点

- 通配符很方便，但必须先预览。
- `rm -rf`、`chmod -R`、`chown -R`、`find -delete` 都是高风险命令。
- 不要用 `chmod -R 777` 修生产权限。
- 脚本中所有关键路径变量都要做空值和目录检查。
