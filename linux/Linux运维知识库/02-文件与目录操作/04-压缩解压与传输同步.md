# 压缩解压与传输同步

## 作用

压缩、解压、传输、同步用于解决“如何打包日志、上传部署产物、下载排障文件、同步静态资源”的问题。运维工作中经常需要把日志打包发给别人，把前端 `dist` 同步到服务器，把 jar 包上传到 release 目录。

## 痛点

- 不知道 `tar -czf`、`tar -xzf`、`tar -tf` 分别做什么。
- 解压包直接覆盖当前目录，导致文件混乱。
- `rsync` 路径末尾 `/` 用错，同步结果多一层目录或少一层目录。
- 上传文件后属主不对，服务用户无法读取。
- 下载日志时直接拷贝大文件，耗时且不方便传输。

## 优点

- 能安全打包和解包。
- 能用 `scp` 快速传单文件。
- 能用 `rsync` 高效同步目录。
- 能在部署前预览同步范围。
- 能减少传输大日志的成本。

## tar 压缩和解压

### 创建压缩包

```bash
tar -czf app-logs.tar.gz logs/
```

参数含义：

- `c`：create，创建归档。
- `z`：使用 gzip。
- `f`：指定文件名。

### 查看压缩包内容

```bash
tar -tzf app-logs.tar.gz | head
```

这是解压前必须养成的习惯。先看内部路径，避免解压后覆盖当前目录。

### 解压

```bash
tar -xzf app-logs.tar.gz
```

解压到指定目录：

```bash
mkdir -p /tmp/extract-check
tar -xzf app-logs.tar.gz -C /tmp/extract-check
```

推荐先解压到临时目录检查结构，再移动到目标目录。

## 常见 tar 场景

打包应用日志：

```bash
cd /opt/apps/demo-api/shared
tar -czf demo-api-logs-$(date +%F-%H%M%S).tar.gz logs/
```

打包配置备份：

```bash
tar -czf nginx-config-$(date +%F).tar.gz /etc/nginx
```

注意：打包绝对路径时，tar 可能提示移除开头 `/`，这是为了避免解压时直接写回根目录。

## scp

`scp` 适合简单文件传输。

上传：

```bash
scp app.jar user@server:/tmp/
```

下载：

```bash
scp user@server:/var/log/nginx/error.log .
```

复制目录：

```bash
scp -r dist user@server:/tmp/
```

适合场景：

- 单个 jar 包。
- 单个日志包。
- 少量配置文件。

不足：

- 目录同步能力弱。
- 大目录重复传输效率不如 `rsync`。

## rsync

`rsync` 适合增量同步目录。

基本命令：

```bash
rsync -avz dist/ user@server:/opt/apps/demo-web/releases/2026-05-11/
```

常用参数：

- `-a`：归档模式，保留权限、时间等。
- `-v`：显示过程。
- `-z`：传输时压缩。
- `--delete`：删除目标中源端没有的文件，危险。
- `--dry-run`：预演，不实际修改。

## rsync 末尾斜杠

这是最容易出错的点。

```bash
rsync -av dist/ target/
```

含义：同步 `dist` 里面的内容到 `target/`。

```bash
rsync -av dist target/
```

含义：把 `dist` 这个目录同步到 `target/dist`。

部署前端静态资源时通常使用：

```bash
rsync -avz dist/ user@server:/opt/apps/demo-web/releases/版本/
```

## rsync 预演

带删除的同步一定先预演：

```bash
rsync -avz --delete --dry-run dist/ user@server:/opt/apps/demo-web/current/
```

确认输出后再去掉 `--dry-run`。

## 传输后的权限

上传后检查：

```bash
ls -lah /opt/apps/demo-api/releases/版本/
```

必要时修正：

```bash
sudo chown -R app:app /opt/apps/demo-api/releases/版本
sudo chmod 750 /opt/apps/demo-api/releases/版本
```

如果文件由 root 上传，而服务用户是 `app`，可能出现读取失败。

## 使用技巧

- 解压前先 `tar -tf` 查看内容。
- 重要目录不要直接解压未知包。
- 单文件用 `scp`，目录同步用 `rsync`。
- `rsync --delete` 必须先 `--dry-run`。
- 上传后检查属主和权限。

## 难点

- tar 解压路径不当会覆盖现有文件。
- rsync 末尾斜杠影响同步结构。
- `--delete` 会删除目标端多余文件，风险很高。
- 传输成功不代表服务用户能读取。

## 重点

- `tar -czf` 压缩，`tar -tzf` 查看，`tar -xzf` 解压。
- 解压到临时目录更安全。
- `scp` 简单传输，`rsync` 增量同步。
- `rsync` 注意源路径末尾 `/`。
- 同步后检查权限。

## 练习

1. 创建一个 logs 目录，打包成 `logs.tar.gz`，再查看压缩包内容。
2. 把压缩包解压到 `/tmp/extract-check`。
3. 用 `rsync --dry-run` 预演一次目录同步。
4. 对比 `rsync dist/ target/` 和 `rsync dist target/` 的目录结果。
