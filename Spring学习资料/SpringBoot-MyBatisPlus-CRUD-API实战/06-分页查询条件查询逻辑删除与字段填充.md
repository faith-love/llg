# 分页查询、条件查询、逻辑删除与字段填充

这一节专门展开 MyBatis-Plus 常用能力：分页插件、条件查询、逻辑删除、创建时间和更新时间自动填充。

## MyBatis-Plus 分页配置

`src/main/java/com/example/crud/config/MybatisPlusConfig.java`：

```java
package com.example.crud.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * MyBatis-Plus 配置类。
 */
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 分页插件：没有它时，page() 可能不会自动拼 limit
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));

        return interceptor;
    }
}
```

注意事项：

- 使用 MyBatis-Plus 分页前，要配置分页插件。
- `DbType.MYSQL` 表示按 MySQL 方言生成分页 SQL。

## 分页查询代码拆解

ServiceImpl 中的分页查询：

```java
Page<UserDO> page = new Page<>(request.getPageNo(), request.getPageSize());

LambdaQueryWrapper<UserDO> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(request.getStatus() != null, UserDO::getStatus, request.getStatus());
wrapper.and(StringUtils.hasText(request.getKeyword()), w -> w
        .like(UserDO::getUsername, request.getKeyword())
        .or()
        .like(UserDO::getNickname, request.getKeyword()));
wrapper.orderByDesc(UserDO::getCreatedAt);

IPage<UserDO> entityPage = page(page, wrapper);
```

逐行解释：

- `new Page<>(pageNo, pageSize)`：告诉 MyBatis-Plus 第几页、每页多少条。
- `eq(condition, column, value)`：condition 为 true 时才加这个条件。
- `like`：模糊查询。
- `and(..., w -> ...)`：把 username 和 nickname 的模糊查询包成一组。
- `orderByDesc`：按创建时间倒序。

最终 SQL 类似：

```sql
SELECT id, username, nickname, email, status, created_at, updated_at
FROM users
WHERE deleted = 0
  AND status = 1
  AND (username LIKE '%ada%' OR nickname LIKE '%ada%')
ORDER BY created_at DESC
LIMIT 10 OFFSET 0;
```

`deleted = 0` 是 MyBatis-Plus 根据逻辑删除配置自动加的。

## 控制分页大小

不要完全相信前端传来的 `pageSize`。可以在 Service 里限制：

```java
private long safePageSize(long pageSize) {
    if (pageSize <= 0) {
        return 10;
    }
    return Math.min(pageSize, 100);
}
```

使用：

```java
Page<UserDO> page = new Page<>(request.getPageNo(), safePageSize(request.getPageSize()));
```

注意事项：

- 不限制 pageSize，前端可以传 `100000`，把数据库拖慢。
- 真实项目还要限制排序字段，不能让前端直接传任意 SQL 字段。

## 自动填充创建时间和更新时间

`src/main/java/com/example/crud/config/MyMetaObjectHandler.java`：

```java
package com.example.crud.config;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import java.time.LocalDateTime;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;

/**
 * MyBatis-Plus 自动字段填充。
 *
 * 配合 Entity 上的：
 * @TableField(fill = FieldFill.INSERT)
 * @TableField(fill = FieldFill.INSERT_UPDATE)
 */
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        LocalDateTime now = LocalDateTime.now();

        // 插入时填充 createdAt
        strictInsertFill(metaObject, "createdAt", LocalDateTime.class, now);

        // 插入时也填充 updatedAt
        strictInsertFill(metaObject, "updatedAt", LocalDateTime.class, now);
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        // 更新时只填充 updatedAt
        strictUpdateFill(metaObject, "updatedAt", LocalDateTime.class, LocalDateTime.now());
    }
}
```

注意事项：

- 填充字段名写 Java 属性名 `createdAt`，不是数据库字段名 `created_at`。
- Entity 上必须配 `@TableField(fill = ...)`，否则不会自动填。
- 数据库也可以设置默认值，但 Java 层自动填充更容易统一测试。

## 逻辑删除

Entity 字段：

```java
@TableLogic
private Integer deleted;
```

配置：

```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
```

调用：

```java
removeById(id);
```

实际 SQL 类似：

```sql
UPDATE users
SET deleted = 1
WHERE id = 1
  AND deleted = 0;
```

之后普通查询会自动过滤：

```sql
SELECT *
FROM users
WHERE id = 1
  AND deleted = 0;
```

注意事项：

- 逻辑删除不是物理删除，数据库记录还在。
- 唯一索引要考虑逻辑删除后是否允许重新创建同名数据。
- 管理后台如果要查已删除数据，需要单独设计接口，不要污染普通查询。

## 练习

1. 配置分页插件。
2. 给 `pageUsers` 增加 pageSize 最大 100 的限制。
3. 删除一个用户后，在数据库里确认 `deleted` 变成 1。
4. 再调用详情接口，确认查不到被删除用户。

## 验收

- 分页 SQL 有 `LIMIT`。
- 条件查询能按 `keyword` 和 `status` 过滤。
- 删除接口执行逻辑删除。
- 创建和更新时自动维护时间字段。
