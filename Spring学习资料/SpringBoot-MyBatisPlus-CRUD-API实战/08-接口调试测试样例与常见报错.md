# 接口调试、测试样例与常见报错

这一节补齐调试和测试。CRUD API 写完不算结束，你还要能自己验证接口是否按预期工作。

## 推荐调试顺序

1. 启动项目。
2. 调新增接口，插入一条用户。
3. 调详情接口，确认能查到。
4. 调分页接口，确认列表里有这条用户。
5. 调修改接口，确认字段变化。
6. 调删除接口，确认逻辑删除生效。
7. 再查详情，确认返回用户不存在。

## HTTP 请求样例

新增：

```http
POST http://localhost:8080/api/users
Content-Type: application/json

{
  "username": "ada",
  "nickname": "Ada Lovelace",
  "email": "ada@example.com"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "username": "ada",
    "nickname": "Ada Lovelace",
    "email": "ada@example.com",
    "status": 1,
    "createdAt": "2026-05-22T10:00:00",
    "updatedAt": "2026-05-22T10:00:00"
  }
}
```

参数错误响应：

```json
{
  "code": 400,
  "message": "email 格式不正确",
  "data": null
}
```

## Spring Boot 测试样例

`src/test/java/com/example/crud/user/UserControllerTest.java`：

```java
package com.example.crud.user;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;

/**
 * 用户接口集成测试。
 *
 * SpringBootTest 会启动完整 Spring 容器。
 * MockMvc 可以模拟 HTTP 请求，不需要真的开浏览器。
 */
@SpringBootTest
@AutoConfigureMockMvc
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void createUserShouldSuccess() throws Exception {
        String body = """
                {
                  "username": "test_user",
                  "nickname": "Test User",
                  "email": "test@example.com"
                }
                """;

        mockMvc.perform(post("/api/users")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(body))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.code").value(0))
                .andExpect(jsonPath("$.data.username").value("test_user"));
    }

    @Test
    void createUserShouldFailWhenEmailInvalid() throws Exception {
        String body = """
                {
                  "username": "bad_email_user",
                  "nickname": "Bad Email User",
                  "email": "not-email"
                }
                """;

        mockMvc.perform(post("/api/users")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(body))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.code").value(400));
    }

    @Test
    void pageUsersShouldSuccess() throws Exception {
        mockMvc.perform(get("/api/users")
                        .param("pageNo", "1")
                        .param("pageSize", "10"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.code").value(0))
                .andExpect(jsonPath("$.data.records").isArray());
    }
}
```

注意事项：

- 这个测试会连接真实测试数据库，最好给测试环境单独配置数据库。
- 如果想隔离数据库，可以后续学习 H2 或 Testcontainers。
- 测试数据要避免和已有唯一索引冲突。

## 常见报错

### 找不到 UserMapper

报错类似：

```text
No qualifying bean of type 'com.example.crud.user.mapper.UserMapper'
```

原因：

- 没有加 `@MapperScan`。
- `@MapperScan` 包路径写错。
- Mapper 不在启动类扫描范围内。

解决：

```java
@MapperScan("com.example.crud.**.mapper")
@SpringBootApplication
public class CrudDemoApplication {
}
```

### 数据库连接失败

报错类似：

```text
Communications link failure
Access denied for user
Unknown database
```

排查：

- MySQL 是否启动。
- 数据库名 `crud_demo` 是否存在。
- 用户名密码是否正确。
- 端口是否是 `3306`。

### 参数校验不生效

表现：

- `username` 传空，接口仍然成功。

排查：

- 是否引入 `spring-boot-starter-validation`。
- Controller 参数是否加了 `@Valid`。
- DTO 字段是否加了校验注解。

### 分页不生效

表现：

- 查询没有 `LIMIT`。
- 返回记录不按 pageSize 限制。

排查：

- 是否配置 `PaginationInnerInterceptor`。
- Service 是否用了 `page(page, wrapper)`。

### 删除后还能查到

排查：

- Entity 是否加了 `@TableLogic`。
- `application.yml` 逻辑删除配置是否正确。
- 数据库字段是不是 `deleted`。
- 是否手写 SQL 绕过了 MyBatis-Plus 逻辑删除规则。

## 最终自测清单

```text
新增用户：成功
新增用户：邮箱格式错误时失败
新增用户：用户名重复时失败
查询详情：存在时成功
查询详情：不存在时失败
分页查询：支持 pageNo/pageSize
分页查询：支持 keyword/status
修改用户：存在时成功
修改用户：不存在时失败
删除用户：逻辑删除成功
删除后查询：返回用户不存在
```

- 能用 HTTP 请求完整验证 CRUD。
- 能写基础 MockMvc 测试。
- 能根据报错定位是配置、数据库、Mapper 扫描还是参数校验问题。
