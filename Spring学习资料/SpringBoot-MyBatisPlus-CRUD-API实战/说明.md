# Spring Boot + MyBatis-Plus CRUD API 实战

这个专题面向“会 Java 基础，但还不懂 Spring、MyBatis-Plus 怎么搭 API”的学习场景。目标是用一个 `users` 用户模块，从 0 到 1 搭出标准增删改查接口，并讲清每个文件的作用、放置位置和注意事项。

## 项目目标

最终你要能写出这些接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/users` | 新增用户 |
| `GET` | `/api/users/{id}` | 根据 id 查询用户详情 |
| `GET` | `/api/users` | 分页查询用户列表 |
| `PUT` | `/api/users/{id}` | 修改用户 |
| `DELETE` | `/api/users/{id}` | 删除用户，练习里用逻辑删除 |

## 小白先记住的分层

| 层 | 文件 | 负责什么 | 不应该做什么 |
| --- | --- | --- | --- |
| Controller | `UserController` | 接 HTTP 请求、参数校验、返回响应 | 不写 SQL、不写复杂业务 |
| Service | `UserService`、`UserServiceImpl` | 业务规则、事务、调用 Mapper | 不接收 HTTP 对象 |
| Mapper | `UserMapper` | 数据库访问 | 不写业务判断 |
| Entity | `UserDO` | 映射数据库表 | 不直接暴露给前端 |
| DTO | `UserCreateRequest` 等 | 接收请求、返回响应 | 不承载数据库映射 |
| Common | 统一响应、异常 | 统一接口风格 | 不混入业务逻辑 |

## 最终验收

完成后你应该能做到：

- 能说清一次 `POST /api/users` 请求经过哪些文件。
- 能解释 `Controller`、`Service`、`Mapper`、`Entity`、`DTO` 的职责边界。
- 能写出带参数校验、统一响应、统一异常处理的 CRUD API。
- 能用 MyBatis-Plus 的 `BaseMapper`、`ServiceImpl`、`LambdaQueryWrapper`、`Page`。
- 能解释逻辑删除、自动填充、事务边界和常见报错。
