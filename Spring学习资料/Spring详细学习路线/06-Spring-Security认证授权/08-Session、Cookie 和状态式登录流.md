# 08-未译17168

## 这种方式适合什么系统

Session + Cookie 特别适合：

- 传统后台管理系统。
- 同域 Web 应用。
- 服务端愿意维护登录状态的场景。

## 基本流程

大致是：

```text
登录成功 -> 服务端保存会话 -> 浏览器持有 Cookie -> 后续请求带上 Cookie
```

## 优点和代价

优点：

- 服务端控制力强。
- 登出和失效处理更直接。

代价：

- 服务端要保存状态。
- 分布式部署时会涉及会话共享或粘性会话问题。
