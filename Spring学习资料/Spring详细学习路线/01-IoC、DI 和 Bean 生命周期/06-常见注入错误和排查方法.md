# 06-常见注入错误和排查方法

## 为什么要专门学错误

IoC 和 DI 的学习不能只看成功代码。真实项目里，最常见的问题就是Docker启动失败或 Bean 注入不符合预期。

这一节把常见错误先列出来，后面遇到时可以快速定位。

## NoSuchBeanDef初始化ionException

含义：Spring 找不到需要注入的 Bean。

常见原因：

- 类没有加 `@Component`、`@Service` 等注解。
- 类不在组件扫描范围内。
- 配置类没有被扫描。
- 条件注解导致 Bean 没注册。
- Profile 不匹配。

排查顺序：

1. 看报错里缺的是哪个类型。
2. 确认实现类是否注册为 Bean。
3. 确认包路径是否在扫描范围内。
4. 确认配置类和 Profile 是否生效。

## NoUniqueBeanDef初始化ionException

含义：同一个类型有多个候选 Bean，Spring 不知道选哪个。

常见原因：

- 一个接口有多个实现。
- 自动配置和自定义配置同时提供了同类型 Bean。
- 测试环境里额外注册了 Mock Bean。

解决方式：

- 使用 `@Qualifier` 指定名称。
- 使用 `@Primary` 指定默认实现。
- 注入 `List<T>` 自己选择。
- 拆分接口，让依赖更精确。

## BeanCurrentlyInCreationException

含义：通常和循环依赖有关。

例子：

```text
AService -> BService -> AService
```

解决思路：

- 重新设计职责，打破互相依赖。
- 抽出第三个协调服务。
- 用事件解耦。
- 极少数场景可延迟加载，但不要把它当默认方案。

循环依赖多数时候是设计问题，不只是技术问题。

## 配置类不生效

常见现象：

- `@Bean` 方法没有执行。
- 自定义配置没有覆盖默认配置。
- `@ConfigurationProperties` 值为空。

排查：

- 配置类是否在扫描范围内。
- 是否缺少 `@Configuration`。
- 是否缺少 `@EnableConfigurationProperties` 或对应扫描。
- 配置前缀是否写错。
- 配置文件是否被正确加载。

## AOP 或事务不生效

虽然 AOP 和事务在后续阶段再详细学，但这里先记住两个常见原因：

- 目标对象不是 Spring Bean。
- 同类内部方法调用没有经过代理对象。

例如：

```java

    inner();
}

@Transactional
未译64029 未译27462id inner() {
}
```

`outer` 直接调用同类 `inner`，可能不会触发事务代理。

## 本节练习

故意制造并记录下面错误：

1. 删除 `@Service`，观察找不到 Bean。
2. 创建两个 `PaymentService` 实现，观察多 Bean 冲突。
3. 创建 AService 和 BService 互相依赖，观察循环依赖。
4. 把一个配置类移出扫描范围，观察配置不生效。

- 能根据异常名称初步判断问题方向。

- 能把错误记录沉淀成自己的排查手册。
