# 04-统一响应、异常和状态码

## 为什么要统一

如果每个接口都返回不同结构，前端和调用方会很难处理错误。

统一响应的目标不是包装一切，而是约定常见业务接口的成功和失败结构。

## 常见成功响应

可以直接返回资源对象，也可以返回统一包装对象。

例如：

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "id": 1,
    "title": "Spring 实战"
  }
}
```

团队可以自行约定，但要保持一致。

## 常见错误响应

失败时至少建议包含：

- 错误码。
- 错误消息。
- 可选的字段名。
- 可选的 traceId。

例如：

```json
{
  "code": "BOOK_NOT_FOUND",
  "message": "图书不存在"
}
```

## 状态码不要乱用

常见语义：

- `200`：成功。
- `201`：创建成功。
- `400`：请求参数有问题。
- `401`：未认证。
- `403`：已认证但无权限。
- `404`：资源不存在。
- `409`：状态冲突或唯一约束冲突。
- `500`：服务器内部错误。

不要把所有失败都返回 `200` 再在 body 里塞错误码。

## 统一异常处理

建议使用 `@RestControllerAdvice`：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
}
```

你至少要处理：

- 参数校验异常。
- 业务异常。
- 兜底系统异常。

这样 Controller 不需要到处写 `try/catch`。

## 本节练习

1. 定义统一成功响应类。
2. 定义业务异常基类。
3. 为图书不存在、状态冲突定义错误码。
4. 写统一异常处理。
5. 用 Postman 或 Apifox 验证 400、404、409、500 的返回结构。

## 本节通过标准

- 能设计一套稳定的成功和失败响应结构。
- 能区分状态码和业务错误码。
- 能用 `@RestControllerAdvice` 统一处理常见异常。
