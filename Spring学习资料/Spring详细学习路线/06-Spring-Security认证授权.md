# 06-Spring Security 认证授权

## 阶段目标

这个阶段学习接口保护、登录认证、权限判断和安全配置。目标不是背默认过滤器，而是能为一个后台系统设计清楚的认证授权流程。

学完后要掌握：

- 认证和授权的区别。
- SecurityFilterChain 的基本流程。
- Session、JWT、OAuth2 Resource 服务端 的适用场景。
- 密码加密、登录失败、退出登录、跨域、CSRF 的处理。
- 方法级权限和 URL 级权限的边界。

## 基础概念

认证回答“你是谁”，授权回答“你能做什么”。

常见对象：

- Principal：当前用户主体。
- Authentication：认证结果。
- GrantedAuthority：权限或角色。
- 用户DetailsService：加载用户信息。
- PasswordEncoder：密码哈希。
- SecurityContext：当前请求的安全上下文。

## 登录方式选择

常见选择：

- 传统后台管理系统：Session + Cookie，服务端保存登录状态。
- 前后端分离 API：JWT 或不透明 Token，配合刷新机制。
- 对接统一身份平台：OAuth2/OIDC。
- 内部服务调用：服务间 Token、mTLS 或网关统一鉴权。

不要只因为“前后端分离”就盲目选择 JWT。JWT 一旦签发，撤销、续期、权限变更都要明确设计。

## 必做练习

- 给图书管理 API 加登录接口。
- 使用 BCrypt 保存密码。
- 配置公开接口和受保护接口。
- 实现用户、角色、权限三张表。
- 给接口添加RBAC限制。
- 实现统一的 401、403 响应。
- 实现退出登录或 Token 失效逻辑。

## 验收标准

- 能解释 401 和 403 的区别。
- 能说明密码为什么不能明文保存，也不应该可逆加密。
- 能区分认证过滤器、异常处理器、权限决策的位置。
- 能排查“明明登录了却访问不了接口”的原因。

## 常见误区

- 误区：权限只在前端隐藏按钮就够了。
  纠正：前端隐藏只是体验，后端必须做强制校验。

- 误区：JWT 里放越多用户信息越方便。
  纠正：Token 体积、泄露风险、权限变更延迟都要控制。

- 误区：关闭 CSRF 就没有安全问题。
  纠正：CSRF 只是其中一种风险，还要考虑 XSS、越权、弱密码、Token 泄露。
