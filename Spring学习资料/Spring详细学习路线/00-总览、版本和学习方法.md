# 00-总览、版本和学习方法

## 阶段目标

这个阶段先建立 Spring 体系的地图，避免一上来就把 Spring、Spring MVC、Spring Boot、Spring Cloud 混在一起背注解。

学完后要能说明：

- Spring Framework 是基础能力集合，核心是 IoC、AOP、事务、数据访问、Web、测试支持。
- Spring Boot 是工程化启动器，核心是自动配置、依赖管理、外部化配置、嵌入式服务器、Actuator。
- Spring Cloud 是分布式系统工具箱，解决服务发现、配置、网关、调用、熔断、链路追踪等问题。
- Spring Data、Spring Security、Spring Batch、Spring Integration 是围绕特定领域扩展的项目。

## 版本选择

新学习主线建议用 Spring Boot 4.0.x + Spring Framework 7.0.x + JDK 25 LTS。这样能接触新的 Jakarta、模块化、HTTP Client、可观测性和原生镜像相关能力。

如果你跟随企业项目或老教程：

- Spring Boot 3.x：仍然是大量项目的现实基线，要求 Java 17+，使用 Spring Framework 6.x 和 Jakarta 命名空间。
- Spring Boot 2.x：只适合维护旧项目，不建议作为新学习主线。
- Spring Framework 5.x 以前：主要用于理解历史项目，不作为新项目技术栈。

## 学习顺序

1. 先搭环境：JDK、IDE、Maven/Gradle、Git、Postman/Apifox、Docker。
2. 再学 Spring Framework 核心：IoC、DI、Bean 生命周期、AOP、事务。
3. 然后进入 Spring MVC：请求映射、参数绑定、响应、异常、校验。
4. 再学 Spring Boot：Starter、自动配置、配置文件、Profile、Actuator。
5. 最后按项目需要学习 Security、Data、Redis、MQ、Cloud。

## 必做练习

- 用 Spring Initializr 创建一个最小 Spring Boot Web 项目。
- 写一个 `/health/simple` 接口，返回当前时间和应用名。
- 修改端口、应用名、日志级别，确认配置生效。
- 找到启动类、Controller、配置文件、`pom.xml` 或 `build.gradle` 的作用。

## 验收标准

- 能说清 `@SpringBootApplication` 大致包含哪些能力。
- 能解释为什么 Spring Boot 项目能直接 `java -jar` 启动。
- 能分辨“框架核心能力”和“Boot 自动配置便利性”。
- 能说明为什么现代 Spring 使用 `jakarta.*` 而不是旧的 `javax.*`。

## 常见误区

- 误区：学 Spring Boot 就等于学 Spring。
  纠正：Boot 是入口，核心机制仍来自 Spring Framework。

- 误区：项目能跑就说明配置懂了。
  纠正：至少要知道配置项由谁读取、什么时候绑定、默认值是什么。

- 误区：一开始就学微服务。
  纠正：先把单体项目的分层、事务、安全、测试和部署做扎实。
