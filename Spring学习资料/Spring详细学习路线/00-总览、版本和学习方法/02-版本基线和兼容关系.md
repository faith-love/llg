# 02-版本基线和兼容关系

## 为什么版本很重要

Spring 学习最容易被版本问题拖住。网上教程可能使用 Spring Boot 2.x、Java 8、`Java学习资料x.*` 包名，而新项目可能已经使用 Spring Boot 4.x、JDK 25、`jakarta.*` 包名。

如果版本基线不清楚，常见问题会变成：

- 复制教程代码后依赖无法下载。
- 类名和包名对不上。
- 配置项已经废弃。
- Maven 依赖冲突。
- 运行时报 `类NotFoundException` 或 `NoSuchMethodError`。

所以学习前先定版本。

## 推荐学习基线

新学习主线建议：

| 项目 | 推荐选择 | 说明 |
| --- | --- | --- |
| JDK | JDK 25 LTS | 新学习主线，长期支持版本 |
| Spring Framework | 7.0.x | 现代 Spring Framework 主线 |
| Spring Boot | 4.0.x | 新项目主线，配套现代 Jakarta 体系 |
| Maven | 3.6.3+ | Spring Boot 4 的最低要求线以上 |
| Gradle | 8.14+ 或 9.x | 使用 Gradle 时按 Boot 官方要求选择 |
| IDE | IntelliJ IDEA 或 VS 未译98214 | 初学后端更推荐 IDEA |

如果你的教程或公司项目使用 Spring Boot 3.x，可以先跟着 3.5.x 学习。Boot 3.x 仍然是现实项目里的常见基线。

## Spring Boot 2、3、4 的差异

### Spring Boot 2.x

特点：

- 常见于旧项目。
- 很多项目基于 Java 8 或 Java 11。
- 使用 `Java学习资料x.*` 包名。
- 不建议作为新学习主线。

你只需要知道如何维护和迁移，不要把它当成新项目模板。

### Spring Boot 3.x

特点：

- 要求 Java 17+。
- 使用 Spring Framework 6.x。
- 从 `Java学习资料x.*` 迁移到 `jakarta.*`。
- 大量企业项目仍在使用。

如果你找的教程比较新，但还不是 Boot 4，大概率是 Boot 3。

### Spring Boot 4.x

特点：

- 面向更新的 Spring Framework 7.x。
- 继续使用 Jakarta 体系。
- 更适合作为新学习主线。
- 老教程里的部分配置和 API 可能需要调整。

学习 Boot 4 时，遇到教程差异不要急着降版本，要先判断差异是不是来自 Boot 2/3/4 的变化。

## Jakarta 和 Java学习资料x

这是版本迁移中最常见的坑。

旧代码可能这样写：

```java
未译87485 Java学习资料x.validation.Valid;
未译87485 Java学习资料x.servlet.http.HttpServlet未译25173equest;
```

现代 Spring Boot 3/4 项目通常使用：

```java
未译87485 jakarta.validation.Valid;
未译87485 jakarta.servlet.http.HttpServlet未译25173equest;
```

如果包名不对，编译期就会报错。不要同时混用 `Java学习资料x.*` 和 `jakarta.*` 依赖。

## 依赖版本管理

Spring Boot 项目不建议随意给每个 Spring 依赖手写版本号。

更稳的做法：

- 使用 `spring-boot-starter-parent` 管理版本。
- 或使用 Spring Boot BOM 统一管理依赖版本。
- 第三方依赖再按需要显式指定版本。

错误倾向：

```xml
<!-- 不建议在 Boot 项目里随意手写 Spring 相关依赖版本 -->
<dependency>
  <groupId>org.springframework</groupId>
  <artifactId>spring-context</artifactId>
  <version>某个随手复制的版本</version>
</dependency>
```

更常见的方式是引入 Starter：

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```
