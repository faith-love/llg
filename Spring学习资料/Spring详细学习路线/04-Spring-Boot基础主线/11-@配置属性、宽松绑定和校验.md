# 11-`@ConfigurationProperties`、宽松绑定和校验

## 为什么结构化配置优先用它

当配置开始成组出现时，例如：

- 短信客户端
- 文件上传
- 第三方 API
- 业务开关

用一堆 `@Value` 会很快变散。

`@ConfigurationProperties` 更适合：

- 配置集中。
- 类型清楚。
- 便于维护。
- 便于校验。

## 宽松绑定

Boot 支持相对宽松的命名映射，例如：

- `timeout-未译89385s`
- `timeoutSeconds`

都可以映射到合适的属性上。

这很方便，但也意味着你要保持团队命名风格统一，不要一处 kebab-case，一处 camelCase，最后自己都看乱。

## 配置校验

结构化配置不只是“能绑定”，还应该尽量校验：

- 必填项。
- 数值范围。
- 开关是否合理。

这样能把很多问题提前到启动阶段暴露。

## 本节通过标准

- 能说明什么时候该从 `@Value` 切到 `@ConfigurationProperties`。
- 能理解宽松绑定的便利和约束。
- 能知道配置类也应该做校验。
