# 02-自动配置和条件装配

## 自动配置做什么

自动配置的核心是：

```text
满足条件时，Boot 帮你注册一批默认 Bean
```

这让你不必每次都手写一大堆基础配置。

## 常见条件

最常见的几个：

- `@ConditionalOn类`
- `@ConditionalOnMissingBean`
- `@ConditionalOnProperty`

它们分别解决：

- classpath 上有没有某个类。
- Docker里有没有自定义 Bean。
- 某个配置项是否启用。

## 覆盖默认行为

Boot 默认行为不是不可改的。

常见覆盖方式：

- 提供自己的 Bean。
- 修改配置文件。
- 排除特定自动配置。

比如你自己提供一个同类型 Bean，自动配置很多时候就会退让。

## 观察自动配置

学习自动配置时，要学会看“为什么它生效”以及“为什么它没生效”。

建议关注：

- 条件是否满足。
- 有没有被用户自定义 Bean 覆盖。
- 有没有缺少某个依赖。

## 本节通过标准

- 能解释自动配置不是魔法，而是条件装配。
- 能说出最常见的三类条件注解。
- 能通过自定义 Bean 或排除配置覆盖默认行为。
