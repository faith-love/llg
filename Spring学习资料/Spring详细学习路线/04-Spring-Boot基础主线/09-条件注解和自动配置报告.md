# 09-条件注解和自动配置报告

## 条件注解为什么关键

自动配置之所以不是“乱配一通”，核心就在条件注解。

常见条件：

- `@ConditionalOn类`
- `@ConditionalOnMissingBean`
- `@ConditionalOnProperty`

它们控制“什么时候配”“什么时候不配”。

## 三类常见判断

`@ConditionalOn类`：

- classpath 上有没有某个类。

`@ConditionalOnMissingBean`：

- 容器里有没有用户自己定义的 Bean。

`@ConditionalOnProperty`：

- 某个配置项是否打开。

## 自动配置报告怎么看

学习 Boot 时，不要只关心“结果能不能跑”，还要能看：

- 哪些自动配置 matched 了。
- 哪些没生效。
- 没生效的原因是什么。

这会极大提升排错速度。

## 用户自定义 Bean 的优先级

很多默认自动配置在你自己提供 Bean 后会让位。

这也是 Boot 可覆盖性的核心设计之一。

## 本节通过标准

- 能解释最常见的条件注解含义。
- 能理解 matched / unmatched 报告的价值。
- 能通过自定义 Bean 干预默认装配结果。
