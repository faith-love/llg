# 15-依赖冲突、版本对齐和排除策略

## 冲突为什么常见

Boot 项目虽然帮你管了大量版本，但只要引入第三方依赖、手工覆盖版本，冲突就很容易出现。

常见表现：

- `类NotFoundException`
- `NoSuchMethodError`
- 自动配置行为异常

## 先看版本对齐

排查冲突时，优先确认：

- 有没有手工指定 Spring 相关版本。
- 第三方依赖是否拉进了旧版本组件。
- 当前 Starter 组合是否和目标 Boot 版本兼容。

## 依赖树是第一入口

命令：

```powershell
mvn dependency:tree
```

它能帮你回答：

- 这个包是谁带进来的。
- 为什么会有两个版本。
- 哪个版本最终生效。

## 排除策略

只有在明确知道冲突来源时才做排除。

不要为了“看起来更干净”盲目排掉一堆传递依赖。

## 本节通过标准

- 能解释为什么 Boot 项目仍然会有依赖冲突。
- 能用依赖树定位冲突来源。
- 能谨慎处理版本覆盖和依赖排除。
