# 09-Spring Cloud 和分布式基础

## 阶段目标

这个阶段学习 Spring Cloud 和分布式系统基础。重点不是把系统拆得越多越好，而是理解什么时候需要拆、拆了以后要承担哪些复杂度。

学完后要能说明：

- 服务注册和发现解决什么问题。
- 配置中心解决什么问题。
- 网关在认证、路由、限流、灰度中的位置。
- 服务间调用如何处理超时、重试、熔断和降级。
- 分布式系统里的数据一致性、幂等和可观测性为什么更难。

## 微服务前置条件

拆服务前先确认：

- 单体已经有清晰模块边界。
- 团队有独立部署和运维能力。
- 有日志、指标、链路追踪基础设施。
- 有自动化测试和发布流程。
- 服务之间的数据归属清楚。

如果这些条件没有准备好，微服务会放大问题。

## 核心组件

常见能力：

- Spring Cloud Gateway：统一入口、路由、过滤器、限流。
- 服务注册发现：Nacos、Eureka、Consul 等。
- 配置中心：Nacos Config、Spring Cloud Config 等。
- OpenFeign：声明式 HTTP 客户端。
- Circuit Breaker：熔断、降级、隔离。
- Spring Cloud Stream：消息驱动。

具体组件版本要按 Spring Boot 和 Spring Cloud 官方版本映射选择，不要混搭。

## 必做练习

- 拆出用户服务、订单服务、库存服务。
- 用注册中心完成服务发现。
- 用网关统一转发请求。
- 用 OpenFeign 调用库存服务。
- 给远程调用设置超时和失败降级。
- 用配置中心管理不同环境配置。
- 打通 traceId，让一次请求能跨服务追踪。

## 验收标准

- 能说清网关、注册中心、配置中心的职责边界。
- 能解释超时、重试、熔断、降级之间的关系。
- 能处理服务调用失败时的业务结果。
- 能说明为什么跨服务事务要优先考虑最终一致性和补偿。

## 常见误区

- 误区：服务越多越先进。
  纠正：服务拆分带来网络、部署、数据一致性、观测和治理成本。

- 误区：用了注册中心就是微服务。
  纠正：微服务更重要的是业务边界、独立部署、数据自治和治理能力。
