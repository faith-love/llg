# 06-缓存 key、过期时间和失效策略

## key 设计不是随便拼字符串

缓存 key 至少要满足：

- 稳定。
- 可读。
- 能唯一定位对象。

如果 key 设计混乱，后面清理和排查都会很痛苦。

## 过期时间怎么想

过期时间不是越长越好，也不是越短越安全。

要结合：

- 数据更新频率。
- 允许过期数据存在多久。
- 读取压力。

## 失效策略

最常见的是：

- 更新数据库后删除缓存。
- 更新数据库后直接更新缓存。

多数业务里，“更新后删除缓存”更容易控制一致性。

## 本节通过标准

- 能设计稳定的缓存 key。
- 能根据业务选择合理过期时间。
- 能解释常见缓存失效策略。
