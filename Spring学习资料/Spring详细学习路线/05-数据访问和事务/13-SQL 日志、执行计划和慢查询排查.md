# 13-DataSource

## 为什么最后还是要回到 SQL

不管框架包了多少层，数据库最终还是执行 SQL。

所以排查性能问题时，必须能回到：

- SQL 长什么样。
- 执行计划怎么样。
- 哪个条件或排序导致慢。

## 最小排查路径

建议至少掌握：

- 打开 SQL 日志。
- 看执行计划。
- 检查索引。
- 检查分页和排序字段。

## 不要只怪框架

慢查询很多时候不是框架问题，而是：

- SQL 写法不合理。
- 索引设计不对。
- 查询条件和排序组合有问题。

## 本节通过标准

- 能通过 SQL 日志看到真实查询。
- 能建立慢查询排查的最小方法。
- 能知道执行计划为什么重要。
