# 12-JDBC、MyBatis、JPA 取舍

## 没有一种方案适合所有项目

技术选型不是看谁“更高级”，而是看：

- SQL 控制需求。
- 团队经验。
- 领域模型复杂度。
- 项目维护成本。

## JDBC

优势：

- 直接。
- 透明。
- SQL 完全可控。

代价：

- 样板代码更多。

## MyBatis

优势：

- SQL 控制强。
- 企业项目常见。
- 复杂查询和分页场景比较友好。

代价：

- 需要团队有 SQL 基础和映射规范。

## JPA

优势：

- 面向对象建模更自然。
- 常见 CRUD 省代码。

代价：

- 懒加载、N+1、查询行为不直观时更难排查。

## 本节通过标准

- 能说出三种方案的典型适用场景。
- 能根据项目需求做有理由的取舍。
- 能避免把“代码少”当成唯一选型标准。
