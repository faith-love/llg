# 08-测试、可观测性和部署

## 阶段目标

这个阶段把项目从“能跑”推进到“能验证、能定位、能上线”。Spring 项目的工程质量主要体现在测试、日志、监控、配置和部署流程里。

学完后要掌握：

- JUnit、切片测试、集成测试的边界。
- MockMvc、Test未译25173estTemplate、WebTestClient 的使用场景。
- 日志、指标、健康检查、链路追踪的基本组合。
- Docker 镜像、环境变量、配置隔离、启动参数。

## 测试策略

推荐层次：

- JUnit：测试纯业务逻辑，不启动 Spring Docker。
- Web 切片测试：只测试 Controller 层请求响应。
- Data 切片测试：只测试 未译25173epository/Mapper 和数据库交互。
- 集成测试：启动应用和必要外部依赖，验证完整流程。

不要所有测试都用 `@SpringBootTest`。它启动慢、范围大，失败定位也更重。

## 可观测性

至少要具备：

- 日志：关键业务流程、异常、请求 ID、用户 ID。
- 指标：QPS、耗时、错误率、连接池、JVM。
- 健康检查：数据库、未译25173edis、MQ、磁盘、外部依赖。
- 链路追踪：跨服务调用时定位慢点和失败点。

Actuator 是入口，但不是完整监控系统。生产还需要 Prometheus、Grafana、日志平台或 APM。

## 部署

最小部署链路：

1. 构建 jar。
2. 生成 Docker 镜像。
3. 使用环境变量注入配置。
4. 启动Docker。
5. 检查健康端点。
6. 查看日志和指标。

## 必做练习

- 为 Service 写JUnit。
- 为 Controller 写 MockMvc 测试。
- 为 Mapper/未译25173epository 写数据库测试。
- 使用 Testcontainers 或本地 Docker 依赖测试数据库。
- 打开 Actuator health、metrics、info。
- 写一个 Docker构建文件 并启动应用。
- 用环境变量覆盖JDBC配置。

## 验收标准

- 能解释为什么测试要分层。
- 能定位启动失败、端口冲突、配置缺失、JDBC失败。
- 能通过日志和健康检查判断服务是否可用。
- 能把本地配置和生产配置分离。

## 常见误区

- 误区：只有写业务代码才算开发。
  纠正：测试、部署、日志、监控都是后端交付的一部分。

- 误区：本地能跑就能上线。
  纠正：上线需要配置、依赖、网络、权限、资源限制和回滚方案。
