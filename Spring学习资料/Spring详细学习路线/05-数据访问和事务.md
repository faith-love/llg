# 05-数据访问和事务

## 阶段目标

这个阶段解决后端项目最核心的稳定性问题：如何访问数据库，如何设计事务边界，如何在失败时保持数据一致。

学完后要掌握：

- Spring JDBC、MyBatis、JPA 的定位差异。
- 数据源、连接池、事务管理器的作用。
- `@Transactional` 的传播行为、隔离级别、回滚规则。
- 分页、批量、慢查询、N+1 查询的常见处理。

## 数据访问选择

常见选择：

- Spring JDBC：轻量、直接、SQL 可控。
- MyBatis/MyBatis-Plus：国内企业项目常见，适合 SQL 主导的业务。
- Spring Data JPA：面向对象映射更强，适合领域模型稳定的项目。
- Spring Data Redis/MongoDB/Elasticsearch：面向特定存储能力。

学习路线建议：先用 MyBatis 或 Spring JDBC 掌握 SQL 和事务，再了解 JPA。

## 事务重点

必须通过实验理解：

- 默认只对运行时异常回滚。
- 同类内部方法调用可能导致事务不生效。
- `private` 方法、非代理调用不会触发事务增强。
- `REQUIRED`、`REQUIRES_NEW`、`NESTED` 的差异。
- 事务边界要放在业务流程上，不要放在每个 DAO 方法上。

## 数据一致性

先掌握单库事务，再考虑分布式一致性。

练习场景：

- 创建订单并扣减库存。
- 库存不足时回滚订单。
- 支付成功后更新订单状态并写操作日志。
- 消息发送失败时记录补偿任务。

## 必做练习

- 建表：用户、图书、借阅记录。
- 完成 CRUD、分页、条件查询。
- 写一个带事务的借书流程。
- 故意制造异常，观察回滚和不回滚的差异。
- 写一个批量插入或批量更新接口。
- 用日志打印 SQL 和事务边界。

## 验收标准

- 能解释 `@Transactional` 为什么有时不生效。
- 能说明事务传播行为的典型使用场景。
- 能定位常见数据库连接池配置问题。
- 能区分业务异常、系统异常和数据约束异常。

## 常见误区

- 误区：所有 Service 方法都加事务。
  纠正：只在需要一致性的业务边界加事务，纯查询可以按需只读事务。

- 误区：事务能解决所有一致性问题。
  纠正：跨服务、跨数据库、外部接口调用需要补偿、幂等和消息设计。
