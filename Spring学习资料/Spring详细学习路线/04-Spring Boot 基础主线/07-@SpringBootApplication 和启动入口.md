# 07-`@SpringBootApplication` 和启动入口

## 这个注解到底做了什么

`@SpringBootApplication` 不是一个普通标记，它本质上是组合注解。

初学阶段至少要知道它大致包含三类能力：

- 配置类能力。
- 组件扫描。
- 自动配置入口。

这就是为什么一个很短的启动类就能把项目拉起来。

## 启动类为什么通常放在根包

Spring Boot 默认会从启动类所在包开始做组件扫描。

如果启动类放得太深，常见问题就是：

- Controller 没被扫描。
- Service 没被扫描。
- 自定义配置类没生效。

所以启动类通常放在业务根包最上层。

## `main` 方法做了什么

启动入口大致是：

```text
main -> SpringApplication.run -> 创建应用上下文 -> 刷新容器 -> 启动 Web 容器
```

你不需要一开始追源码到最后一层，但要知道项目不是“凭空就启动了”。

## 启动类不要塞业务逻辑

启动类适合做：

- 启动应用。
- 少量启动参数配置。

不适合做：

- 业务初始化。
- 手工查库。
- 大量环境判断。

这些逻辑应当放在更明确的配置或启动钩子里。
