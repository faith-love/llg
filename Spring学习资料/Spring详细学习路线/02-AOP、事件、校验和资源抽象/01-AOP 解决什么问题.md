# 01-AOP 解决什么问题

## 先看重复代码

假设很多 Service 方法都要记录耗时：

```java
public void create订单() {
    long start = System.currentTimeMillis();
    try {
        // 业务逻辑
    } finally {
        long cost = System.currentTimeMillis() - start;
        System.out.println("cost=" + cost);
    }
}
```

如果每个方法都这样写，会有几个问题：

- 日志逻辑淹没业务逻辑。
- 每个方法都要复制一遍。
- 日志格式一变，很多地方都要改。
- 很难统一处理异常、耗时、上下文信息。

AOP 就是为这种横切逻辑准备的。

## 什么是横切逻辑

横切逻辑不是某一个业务独有的逻辑，而是横跨很多模块的通用逻辑。

常见例子：

- 方法耗时日志。
- 操作审计。
- 权限入口判断。
- 事务控制。
- 接口限流。
- 指标埋点。
- 异常监控。

这些逻辑如果散落在业务代码里，会让业务代码越来越难读。

## AOP 的核心概念

| 概念 | 说明 |
| --- | --- |
| Aspect | 切面，横切逻辑的载体 |
| Join Point | 连接点，Spring AOP 里通常是方法执行 |
| Pointcut | 切点，定义哪些方法需要被增强 |
| Advice | 通知，定义增强逻辑在什么时候执行 |
| Target | 目标对象，原始业务对象 |
| Proxy | 代理对象，对目标对象进行增强 |

初学时不要被术语吓住。可以简单理解为：

```text
哪些方法要增强 -> 切点
增强什么逻辑 -> 通知
增强逻辑放在哪里 -> 切面
增强如何生效 -> 代理
```

## AOP 适合和不适合的场景

适合：

- 日志、耗时、审计。
- 统一权限入口。
- 事务。
- 指标和监控。
- 重试、限流等技术性逻辑。

不适合：

- 复杂业务流程。
- 需要明确阅读顺序的核心业务规则。
- 与业务结果强相关的分支判断。
- 为了少写几行代码而隐藏关键逻辑。

AOP 用得太多，会让代码“表面上没逻辑，运行时到处有逻辑”。初学阶段要克制使用。

## Spring AOP 和完整 AspectJ

Spring AOP 主要基于代理，重点增强 Spring Bean 的方法调用。

它不是完整 AspectJ 的全部能力。初学阶段先掌握 Spring AOP 即可，因为日常 Spring Boot 项目里最常用的就是这部分。
