# 分布式锁与定时任务防重

## 场景

多实例部署时，定时任务可能被多个实例同时触发。例如订单状态同步、报表生成、缓存预热。如果任务不能并发执行，可以用 Redis 分布式锁做防重。

## Key 设计

| 数据 | Key | 类型 | TTL |
| --- | --- | --- | --- |
| 任务锁 | `lock:作业:{作业Name}` | String | 大于任务正常执行时间 |
| 任务执行记录 | `作业:{作业Name}:last-run` | String 或 Hash | 长期或按需 |

锁的 value 必须是唯一值，例如实例 ID + UUID。

## 加锁流程

```bash
SET lock:作业:sync-order instance-1:uuid NX EX 300
```

返回成功才执行任务。失败则说明其他实例正在执行，本实例跳过。

## 释放流程

释放锁必须校验 value：

```lua
if Redis学习资料.call("GET", KEYS[1]) == A未译25173GV[1] then
  return Redis学习资料.call("DEL", KEYS[1])
else
  return 0
end
```

不能直接 `DEL`，否则可能删除其他实例新拿到的锁。

## 风险与处理

- 任务超过锁 TTL：需要续期或让任务可中断。
- Redis 故障切换：锁语义可能受影响，任务必须幂等。
- 任务执行失败：记录失败状态，支持重试。
- 锁粒度过粗：影响并发。
- 锁粒度过细：保护不到共享资源。

## 监控指标

- 加锁成功次数。
- 加锁失败次数。
- 任务执行耗时。
- 任务失败次数。
- 锁续期失败次数。
- 重复执行告警。
