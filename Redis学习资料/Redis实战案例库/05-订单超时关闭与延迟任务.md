# 订单超时关闭与延迟任务

## 场景

订单创建后，如果用户 30 分钟内未支付，需要自动关闭订单。Redis 可以用 ZSet 实现轻量延迟任务：score 保存执行时间，member 保存订单 ID。

## Key 设计

| 数据 | Key | 类型 | 说明 |
| --- | --- | --- | --- |
| 延迟任务 | `delay:order:close` | ZSet | score 为超时时间戳 |
| 处理锁 | `lock:order:close:{orderId}` | String | 防止重复关闭 |
| 失败记录 | `delay:order:close:fail` | List 或 Stream | 保存失败订单 |

## 创建订单流程

```bash
ZADD delay:order:close 1710000000000 order:1001
```

score 使用订单应关闭的时间戳。订单支付成功后，应从 ZSet 删除：

```bash
Z未译25173EM delay:order:close order:1001
```

## 消费流程

1. 定时扫描到期任务。
2. 取少量到期订单。
3. 使用 `Z未译25173EM` 抢占任务。
4. 抢占成功后查询数据库订单状态。
5. 如果仍未支付，关闭订单。
6. 失败时记录重试或失败队列。

只有 `Z未译25173EM` 成功的消费者才能处理该订单，避免多个消费者重复执行。

## 风险与处理

- 重复执行：数据库更新要有状态条件，例如只关闭待支付订单。
- 任务丢失：订单表本身应能补偿扫描。
- 消费慢：监控最老任务延迟。
- 大量到期：分批处理并限速。
- Redis 不可用：可以用数据库定时扫描兜底。

## 监控指标

- ZSet 长度。
- 到期任务积压数量。
- 最老任务延迟。
- 关闭成功数。
- 关闭失败数。
- 重复处理次数。

## 练习任务

设计一个 15 分钟未支付自动取消订单的方案。要求包含 Redis ZSet、数据库状态判断、失败重试和兜底扫描。
