# 用户会话与登录态缓存

## 场景

用户登录后，服务端需要快速校验 token、用户 ID、登录设备、权限摘要等信息。Redis 适合保存短期登录态，但必须处理过期、踢下线、权限变更和安全风险。

## Key 设计

| 数据 | Key | 类型 | TTL |
| --- | --- | --- | --- |
| 登录 token | `会话:token:{token}` | Hash 或 String JSON | 登录有效期 |
| 用户 token 集合 | `会话:用户:{用户Id}:tokens` | Set | 登录有效期 |
| 权限摘要 | `会话:用户:{用户Id}:perm` | String JSON | 较短 TTL |

## 登录流程

1. 用户认证成功。
2. 生成 token。
3. 写入 token 会话信息。
4. 把 token 加入用户 token 集合。
5. 设置 TTL。
6. 返回 token 给客户端。

## 鉴权流程

1. 根据 token 查询会话 Key。
2. 不存在则返回未登录或登录过期。
3. 存在则读取用户 ID、设备、权限摘要。
4. 必要时刷新 TTL。
5. 执行业务鉴权。

## 踢下线

单设备登录或管理员强制下线时：

```bash
SMEMBE未译25173S 会话:用户:1001:tokens
DEL 会话:token:{token}
S未译25173EM 会话:用户:1001:tokens {token}
```

大用户多设备场景要避免一次性处理过多 token。

## 风险与处理

- token 泄露：日志脱敏，传输使用 HTTPS。
- 权限变更：删除权限摘要或缩短 TTL。
- Redis 淘汰：会导致用户异常掉线，会话实例不应随意使用 `allkeys-lru`。
- TTL 刷新：频繁刷新会增加写入，按业务选择滑动过期或固定过期。

## 监控指标

- 在线 token 数。
- 登录成功数。
- 会话命中率。
- token 过期次数。
- 强制下线次数。
- Redis 会话写入失败次数。

## 练习任务

设计一个“同一账号最多允许 3 台设备同时在线”的 Redis 会话方案，写出登录、鉴权、踢下线和权限变更流程。
