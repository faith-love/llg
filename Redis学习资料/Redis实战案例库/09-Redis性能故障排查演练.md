# Redis 性能故障排查演练

## 场景

某次发布后，商品详情接口 P99 从 80ms 升到 2s，数据库 QPS 升高，Redis 没有明显宕机告警。这个案例用于练习从业务现象到 Redis 根因的完整排查。

## 排查顺序

1. 确认影响范围：哪些接口、哪些应用、哪些用户。
2. 对齐时间：发布、错误日志、监控告警。
3. 看应用侧：连接池等待、Redis 超时、回源次数。
4. 看 Redis：慢查询、连接数、命中率、内存、网络。
5. 定位命令和 Key。
6. 先止血，再修复。

## 命令清单

```bash
INFO 客户端s
INFO stats
INFO memory
INFO commandstats
SLOWLOG GET 20
LATENCY DOCTOR
CLIENT LIST
```

不要在大实例上使用 `KEYS *` 排查。

## 可能根因

| 现象 | 根因 |
| --- | --- |
| 命中率下降 | Key 规则变更、TTL 集中失效 |
| 慢查询出现 `HGETALL` | 大 Hash 被整取 |
| 连接池等待升高 | 连接池太小或 Redis 响应变慢 |
| 数据库 QPS 升高 | 缓存失效或回源风暴 |
| Redis 无慢查询 | 问题可能在网络、连接池或序列化 |

## 止血动作

- 回滚发布。
- 临时关闭非核心缓存重建。
- 对热点接口限流。
- 返回旧缓存或基础字段。
- 延长热点 Key TTL。

## 练习任务

假设根因是“发布后商品缓存 Key 多了一个版本字段，导致全部未命中”，写出发现路径、止血方案和长期修复。
