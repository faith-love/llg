# 生产上线评审模板

## 目标

任何 Redis 新方案上线前，都应该经过设计评审。评审模板的价值是提前发现 Key 命名、容量、TTL、一致性、降级、监控和权限问题。


## Key 设计表

| 场景 | Key 模板 | 类型 | TTL | 最大规模 | 清理方式 |
| --- | --- | --- | --- | --- | --- |
| 示例 | `mall:product:{id}:detail` | String | 30 分钟 | 300 万 | 过期 + 主动删除 |

## 读写流程

必须写清：

- 读缓存流程。
- 缓存未命中流程。
- 写数据库后缓存如何处理。
- 删除缓存失败如何补偿。
- Redis 不可用如何降级。

## 安全与权限

- 是否使用独立账号。
- 是否限制 Key 前缀。
- 是否限制危险命令。
- 密码是否进入代码仓库。
- 是否只允许内网访问。

## 监控与告警

- 缓存命中率。
- 回源数据库次数。
- Redis 错误数。
- 慢查询。
- 内存使用率。
- 连接池等待时间。
- 业务降级次数。
