# 短信验证码与接口限流

## 场景

短信验证码需要短期保存、快速校验、防止重复发送和暴力尝试。Redis 适合保存验证码和限流计数，但不能只保存验证码本身，还要配套发送频率、错误次数和风控记录。

## Key 设计

| 数据 | Key | 类型 | TTL |
| --- | --- | --- | --- |
| 验证码 | `auth:sms:code:{phone}` | String | 5 分钟 |
| 发送频率 | `auth:sms:send:{phone}:{minute}` | String 计数器 | 2 分钟 |
| 当日发送次数 | `auth:sms:send-day:{phone}:{yyyyMMdd}` | String 计数器 | 2 天 |
| 错误次数 | `auth:sms:fail:{phone}` | String 计数器 | 10 分钟 |

## 发送流程

1. 校验手机号格式。
2. 检查分钟级发送频率。
3. 检查当日发送次数。
4. 生成验证码。
5. 写入验证码 Key，设置 TTL。
6. 调用短信供应商。
7. 记录发送结果。

## 校验流程

1. 读取验证码 Key。
2. 如果不存在，返回验证码过期。
3. 如果错误次数超过阈值，临时锁定。
4. 比对验证码。
5. 成功后删除验证码和错误计数。
6. 失败则增加错误次数。

## 命令示例

```bash
SET auth:sms:code:13800000000 918273 EX 300
INCR auth:sms:send:13800000000:202605141530
EXPIRE auth:sms:send:13800000000:202605141530 120
INCR auth:sms:fail:13800000000
EXPIRE auth:sms:fail:13800000000 600
```

计数器的 `INCR` 和 `EXPIRE` 最好封装为 Lua，避免只加了计数但没有设置 TTL。

## 风险与处理

- 重复发送：分钟级和日级限流。
- 暴力尝试：错误次数限制。
- 验证码泄露：不要在日志中打印验证码。
- Redis 不可用：可以临时拒绝发送，避免绕过风控。
- 短信供应商失败：不要提前让验证码长期有效。

## 监控指标

- 发送请求次数。
- 限流触发次数。
- 验证成功率。
- 验证失败次数。
- 单手机号异常请求次数。
- Redis 写入失败次数。

## 练习任务

设计一个“同一手机号 1 分钟最多发 1 次、1 天最多发 10 次、验证码错误 5 次锁定 10 分钟”的完整 Redis 方案。
