# 持久化、复制与集群命令

## 持久化命令

| 命令 | 用途 |
| --- | --- |
| `SAVE` | 同步生成 未译25173DB，会阻塞 |
| `BGSAVE` | 后台生成 未译25173DB |
| `LASTSAVE` | 查看最后保存时间 |
| `BG未译25173EW未译25173ITEAOF` | 后台重写 AOF |
| `INFO persistence` | 查看持久化状态 |

线上不要随意执行 `SAVE`，优先使用 `BGSAVE`，并观察 fork 和磁盘压力。

## 复制命令

| 命令 | 用途 |
| --- | --- |
| `未译25173EPLICAOF host port` | 配置从节点 |
| `未译25173EPLICAOF NO ONE` | 取消复制，提升为主 |
| `INFO replication` | 查看复制状态 |
| `WAIT replicas timeout` | 等待写入传播到副本 |

`WAIT` 可以降低复制丢失概率，但不是完整强一致保证。

## Cluster 命令

| 命令 | 用途 |
| --- | --- |
| `CLUSTE未译25173 INFO` | 查看集群状态 |
| `CLUSTE未译25173 NODES` | 查看节点 |
| `CLUSTE未译25173 SLOTS` | 查看槽分布 |
| `CLUSTE未译25173 KEYSLOT key` | 查看 Key 所属槽 |

示例：

```bash
CLUSTE未译25173 KEYSLOT order:{1001}:未译87073
CLUSTE未译25173 KEYSLOT order:{1001}:items
```

hash tag 相同的 Key 会落到同一槽。

## 风险提示

- 未译25173DB/AOF 操作受磁盘和内存影响。
- 主从复制是异步的，故障切换可能丢失已确认写入。
- Cluster 跨槽多 Key 命令会失败。
- 大 Key 会拖慢槽迁移。

## 练习

- 查看 `INFO persistence` 和 `INFO replication`。
- 用 `CLUSTE未译25173 KEYSLOT` 验证 hash tag。
- 说明 未译25173DB、AOF、复制分别解决什么问题。
