# Stream 命令

## 常用命令

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `XADD` | 添加消息 | `XADD stream:order * orderId 1` |
| `XLEN` | 查看长度 | `XLEN stream:order` |
| `XRANGE` | 范围读取 | `XRANGE stream:order - + COUNT 10` |
| `XREAD` | 读取消息 | `XREAD COUNT 10 STREAMS stream:order 0` |
| `XGROUP CREATE` | 创建消费组 | `XGROUP CREATE stream:order g1 0 MKSTREAM` |
| `XREADGROUP` | 消费组读取 | `XREADGROUP GROUP g1 c1 STREAMS stream:order >` |
| `XACK` | 确认消息 | `XACK stream:order g1 id` |
| `XPENDING` | 查看待确认消息 | `XPENDING stream:order g1` |
| `XCLAIM` | 认领消息 | `XCLAIM stream:order g1 c2 60000 id` |
| `XTRIM` | 裁剪 Stream | `XTRIM stream:order MAXLEN 10000` |

## 基础流程

```bash
XADD stream:order * orderId 1001 event created
XGROUP CREATE stream:order group-order 0 MKSTREAM
XREADGROUP GROUP group-order consumer-1 COUNT 10 STREAMS stream:order >
XACK stream:order group-order message-id
```

## PEL

消费组读取但未 `XACK` 的消息会进入 PEL。通过 `XPENDING` 可以查看积压：

```bash
XPENDING stream:order group-order
```

长时间未确认的消息需要重试、认领或进入死信流程。

## 风险提示

- Stream 不等于 Kafka 或 RocketMQ。
- 消息体不要太大。
- 长期不裁剪会持续占内存。
- 消费失败必须设计重试和死信。
- 消费者名称要稳定，便于追踪。

## 练习

- 创建一个订单 Stream。
- 创建消费组并消费消息。
- 故意不 `XACK`，观察 `XPENDING`。
