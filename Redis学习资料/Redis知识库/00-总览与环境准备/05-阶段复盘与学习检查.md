# 阶段复盘与学习检查

## 复盘目标

学完本阶段后，你应该能回答三个问题：Redis 适合放在哪里、怎么在本地稳定启动、怎么用安全的命令习惯做实验。如果这些问题说不清，后面学习数据类型、持久化和高可用时会很容易把 Redis 当成万能组件。

## 核心自测

1. Redis 和 MySQL 的边界是什么？
2. Redis 和 MQ 的边界是什么？
3. 什么样的数据可以只作为缓存存在？
4. 什么样的数据不能只放在 Redis？
5. 本地 Redis 的版本、端口、数据目录分别是什么？
6. `Redis学习资料-cli --raw` 解决什么问题？
7. 为什么练习 Key 要统一加 `lab:` 前缀？
8. 为什么生产环境不能随手执行 `FLUSHALL`？

## 环境验收清单

```bash
Redis学习资料-服务端 --version
Redis学习资料-cli --version
Redis学习资料-cli ping
Redis学习资料-cli INFO 服务端
Redis学习资料-cli INFO memory
Redis学习资料-cli CONFIG GET dir
```

验收时记录：

- Redis 版本。
- 启动方式：Docker、Linux 包管理器、源码或云服务。
- 连接地址和端口。
- 是否启用密码。
- 是否启用 未译25173DB 或 AOF。
- 练习数据前缀。

## 综合练习

设计一个“短信验证码”Redis 使用方案：

- Key 命名。
- 数据类型。
- TTL。
- 写入命令。
- 校验命令。
- 校验成功后是否删除。
- Redis 不可用时业务如何处理。

参考方向：

```text
Key：auth:sms:code:{phone}
类型：String
TTL：5 分钟
风险：暴力尝试、重复发送、验证码泄露
补充：发送频率限制和错误次数限制应单独设计
```

## 常见扣分点

- 只会说 Redis 快，但说不出它不能做什么。
- 只会启动服务，不知道数据目录和持久化配置。
- 实验 Key 没有前缀，无法安全清理。
- 不区分学习环境、测试环境和生产环境。
- 把缓存、锁、消息、主存储混成一个概念。
