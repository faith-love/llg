# 版本许可与生态选择

## 版本选择

学习阶段可以使用 Redis 7.x 或 8.x。Redis 7.x 是很多生产环境仍在使用的主线，命令、持久化、主从、哨兵、Cluster、Lua、Stream 等核心能力都足够完整。Redis 8.x 进一步合并 Redis Stack 能力，包含更多扩展数据结构和搜索能力。

生产选型不要只看“最新”：

- 客户端是否支持对应协议和命令。
- 公司镜像源、运维脚本、监控插件是否兼容。
- 现有 Redis 集群是否允许滚动升级。
- 许可证、云厂商托管服务和公司合规要求是否匹配。

## Redis、Valkey 与托管服务

Redis 生态中常见选择包括：

- Redis Open Source：官方 Redis 开源版本。
- Valkey：Redis 分支生态，常见于部分云厂商和开源社区环境。
- 云厂商托管 Redis：减少运维成本，但要关注版本、参数限制、费用和故障切换行为。

学习资料中的基础命令和工程原则大多通用，但生产环境要以实际产品文档为准。

## 需要关注的兼容点

- 客户端协议：RESP2、RESP3。
- 高可用模式：单机、主从、Sentinel、Cluster。
- 模块能力：搜索、JSON、Bloom、TimeSeries 等是否内置或需要额外组件。
- 命令差异：新命令在旧版本不可用，代码中要避免无意绑定到过高版本。
- 配置差异：持久化、内存、ACL、安全默认值可能随版本变化。

## 推荐学习基线

如果只是本地学习：

```bash
redis-server --version
redis-cli --version
redis-cli ping
```

如果用于项目：

1. 先确认目标环境版本。
2. 再选择客户端和序列化方式。
3. 最后补充该版本的生产配置、备份和监控清单。

## 升级前需要检查什么

Redis 升级不能只替换镜像标签。升级前至少检查：

- 客户端版本是否支持目标 Redis 版本和部署模式。
- 是否使用了新版本变更过行为的命令或配置。
- 持久化文件是否能被目标版本读取。
- Sentinel、Cluster、监控插件和运维脚本是否兼容。
- 回滚时旧版本是否能读取新版本产生的数据文件。

本地学习可以大胆试新版本，生产环境要先在测试环境恢复一份真实数据，再跑核心读写链路。

## 选型建议

小团队或学习环境优先用官方 Redis 镜像，降低资料查找成本。企业项目如果使用云托管 Redis，要先确认云厂商对命令、配置、持久化、备份、审计、网络和版本升级的限制。不要在业务代码里使用只有某个托管产品支持的特殊能力，除非已经接受供应商绑定。

## 练习

- 查看本地 Redis 版本。
- 查出当前客户端库版本。
- 写一份“从 Redis 7 升级到 Redis 8 前要验证的清单”。
