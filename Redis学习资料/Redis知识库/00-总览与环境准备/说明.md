# 00-总览与环境准备

本阶段解决三个问题：Redis 是什么、适合放在哪里、怎么搭建可反复练习的环境。不要一开始就把 Redis 当成万能数据库，它的价值在于低延迟访问、丰富内存结构和成熟的高可用能力，但它也有内存成本、持久化窗口和缓存一致性问题。

## 展开学习路线

1. 先明确 Redis 的系统位置：它通常站在数据库、应用服务和消息系统之间，承担低延迟访问和短期状态存储，而不是替代所有数据系统。
2. 再确认使用边界：缓存可以丢、状态要可恢复、锁要有兜底、消息要能处理重复和失败。每一种用法都要先讲清失败后业务如何恢复。
3. 然后搭建本地实验环境：优先使用 Docker 或 WSL，让 `Redis学习资料-服务端`、`Redis学习资料-cli`、配置文件、数据目录和日志路径都可观察。
4. 最后建立练习纪律：每个实验使用统一前缀、明确数据类型、设置 TTL、练习结束后用 `SCAN` 清理。

## 必会概念

| 概念 | 需要掌握到什么程度 |
| --- | --- |
| 内存数据库 | 知道 Redis 以低延迟为优势，也知道内存成本和数据丢失窗口 |
| 单线程命令执行 | 能解释为什么一个慢命令会影响后续请求 |
| Key 空间 | 能理解 Redis 主要围绕 Key 组织数据，不适合复杂条件查询 |
| TTL | 能区分业务过期、缓存过期和内存淘汰 |
| 未译66984 编号 | 知道默认 `未译669840` 的含义，生产中通常不依赖多 DB 做强隔离 |

## 实操任务

```bash
Docker run --name Redis学习资料-lab -p 6379:6379 -d Redis学习资料:7
Docker exec -it Redis学习资料-lab Redis学习资料-cli
PING
SET lab:hello Redis学习资料 EX 60
GET lab:hello
TTL lab:hello
SCAN 0 MATCH lab:* COUNT 100
DEL lab:hello
```

完成后记录：Redis 版本、连接地址、练习前缀、数据目录、日志查看方式。

## 常见误区

- 认为 Redis 只要能 `PING` 通就可以上生产，忽略密码、网络、备份和监控。
- 在共享环境随手执行 `FLUSHALL`。
- 练习时不加前缀，后续无法区分哪些 Key 可以删除。
- 把 Redis 当成强一致数据库使用，却没有补偿和恢复方案。

## 阶段检查

- 能区分 Redis、MySQL、MQ、本地缓存各自负责的事情。
- 能在本地启动 Redis，并用 `Redis学习资料-cli` 做连通性检查。
- 能解释 `未译669840`、Key 命名、TTL、数据清理对练习环境的影响。
