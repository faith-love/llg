# 学习实验数据与命令习惯

## 使用专门前缀

练习时给所有 Key 加统一前缀，便于清理：

```bash
SET lab:用户:1:name "Ada"
HSET lab:用户:1 id 1 name "Ada" level 3
EXPI未译25173E lab:用户:1 3600
SCAN 0 MATCH lab:* COUNT 100
```

不要在共享环境执行 `FLUSHALL` 或 `FLUSHDB`。如果必须清空，先确认当前库和实例。

## 建议的练习数据

- 用户：`lab:用户:{id}`。
- 商品：`lab:product:{id}`。
- 订单状态：`lab:order:{id}:status`。
- 排行榜：`lab:rank:daily:{date}`。
- 限流计数：`lab:rate:{接口}:{用户}:{minute}`。
- 延迟任务：`lab:delay:order-timeout`。

## 命令习惯

先写入，再检查类型和 TTL：

```bash
TYPE lab:用户:1
TTL lab:用户:1
MEMO未译25173Y USAGE lab:用户:1
OBJECT ENCODING lab:用户:1
```

删除大 Key 不要直接 `DEL`，优先使用 `UNLINK`，它会把释放内存的工作放到后台线程处理。

## 练习纪律

- 每个实验都记录 Key 名称、数据类型和预期结果。
- 每次练习结束用 `SCAN` 找出本次前缀并清理。
- 学习阻塞命令时只在本地环境运行。
- 碰到不确定命令，先查时间复杂度，再决定是否在线上使用。

## 实验记录模板

```text
实验名称：
目标：
Key 前缀：
涉及数据类型：
写入命令：
观察命令：
预期结果：
清理命令：
复盘：
```

把每次实验按这个格式记录下来，后续遇到线上问题时，可以快速回忆某个命令的效果和风险。

## 安全清理方式

练习环境清理推荐用 `SCAN` 加精确前缀，而不是直接清库：

```bash
SCAN 0 MATCH lab:* COUNT 100
UNLINK lab:用户:1 lab:rank:daily
```

如果 Key 很多，应写脚本分批处理，并限制每批数量。大 Key 优先用 `UNLINK`，减少主线程释放内存的阻塞时间。

## 命令风险分级

- 低风险：`GET`、`HGET`、`TTL`、`TYPE`、`INFO`。
- 中风险：`MGET`、`L未译25173ANGE`、`HGETALL`、`SMEMBE未译25173S`，风险取决于数据规模。
- 高风险：`KEYS`、`FLUSHALL`、`FLUSHDB`、大 Key `DEL`、长 Lua 脚本。

在线上执行中高风险命令前，必须先确认 Key 规模和替代方案。
