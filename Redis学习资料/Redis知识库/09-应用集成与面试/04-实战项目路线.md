# 实战项目路线

## 项目一：商品详情缓存

目标：实现缓存 Aside 模式。

要求：

- 商品详情先查 Redis，未命中查数据库。
- 写入缓存时设置 TTL 和随机抖动。
- 缓存空值防穿透。
- 商品更新时删除缓存。
- 记录命中率和回源次数。

## 项目二：排行榜

目标：使用 ZSet 实现日榜和周榜。

要求：

- 用 `ZINCRBY` 增加分数。
- 用 `ZREVRANGE` 查询 Top N。
- 用 `ZREVRANK` 查询个人排名。
- 历史榜单设置归档或 TTL。
- 处理并发写入和重复计分。

## 项目三：分布式锁保护缓存重建

目标：防止热点 Key 过期后大量请求同时回源。

要求：

- 使用 `SET NX EX` 加锁。
- 锁值使用唯一 requestId。
- Lua 校验后释放锁。
- 获取锁失败时短暂等待或返回旧值。
- 任务执行超时时要有兜底。

## 项目四：轻量消息流

目标：使用 Stream 处理订单事件。

要求：

- 生产者写入订单创建事件。
- 消费组读取并确认消息。
- 处理未确认消息和重试。
- 监控 Stream 长度和 PEL。
- 明确什么时候应切换到专业 MQ。

## 输出物

每个项目都建议沉淀：

- Key 设计表。
- 命令流程图。
- 异常和降级策略。
- 监控指标。
- 复盘问题清单。

## 项目验收标准

每个实战项目都不要只写命令，要能跑通完整闭环：

- 正常路径能执行。
- 异常路径有处理。
- Key 有命名规范和 TTL。
- 数据规模增长有边界。
- 关键指标能观察。
- 失败后能恢复或补偿。

## 推荐顺序

1. 商品详情缓存：最贴近实际项目。
2. 排行榜：练 ZSet 和历史数据清理。
3. 分布式锁：理解原子性、过期和释放校验。
4. 限流：理解计数、窗口和降级响应。
5. Stream：理解消费组、确认和重试。
