# Java 客户端与连接池

## 常见客户端

Java 项目常见 Redis 客户端包括 Lettuce、Jedis 和 Redisson。

| 客户端 | 特点 |
| --- | --- |
| Lettuce | 基于 Netty，支持同步、异步、响应式，Spring Boot 默认常见选择 |
| Jedis | API 直观，传统项目常见，需要关注连接池 |
| Redisson | 提供分布式锁、集合、限流器等高级封装 |

## 连接池关注点

- 最大连接数是否匹配业务并发。
- 获取连接等待时间是否过长。
- 命令超时是否合理。
- 是否有无限重试。
- 是否按读写、业务重要性隔离客户端。

## 序列化

不要随意使用 JDK 默认序列化保存长期数据。常见选择：

- String：适合简单值和跨语言。
- JSON：可读性好，注意字段兼容。
- Kryo、Protostuff 等二进制：性能好，但兼容和排障成本更高。

## 项目建议

- Key 统一由工具类或常量生成，避免散落字符串。
- 序列化方式统一配置，避免同一 Key 被不同格式写入。
- 超时、重试和降级要按业务链路设置。
- Redis 异常不能无限拖垮主业务线程。

## Lettuce、Jedis、Redisson 怎么选

普通 Spring Boot 项目使用 Lettuce 通常足够，生态集成顺手。已有老项目使用 Jedis 时，重点检查连接池和超时配置。需要分布式锁、限流器、延迟队列等高级封装时，可以评估 Redisson，但不能因为用了 Redisson 就不理解底层语义。

选型要结合团队熟悉度、部署模式、监控能力和故障排查成本。

## 连接池和线程池联动

如果 Web 线程池有 200 个线程，而 Redis 连接池只有 10 个连接，高峰时大量线程可能等待连接。如果 Redis 连接池开到 10000，又可能打满 Redis `max客户端s`。配置要按接口并发、命令耗时和 Redis 实例能力一起压测。
