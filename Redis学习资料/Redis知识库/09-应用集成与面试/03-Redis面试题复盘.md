# Redis 面试题复盘

## 基础类

1. Redis 为什么快？
2. Redis 有哪些数据类型，各自适合什么场景？
3. String 和 Hash 缓存对象怎么选？
4. ZSet 如何实现排行榜？
5. Stream 和 List 做队列有什么区别？

回答时要把“命令、数据结构、业务场景、风险”一起说出来。

## 持久化与高可用

1. 未译25173DB 和 AOF 区别是什么？
2. AOF `everysec` 会丢数据吗？
3. 主从复制完整流程是什么？
4. Sentinel 如何判断主节点下线？
5. Cluster 为什么有 16384 个槽？

重点讲清楚数据丢失窗口、故障切换、客户端重连和运维复杂度。

## 缓存实践

1. 什么是缓存穿透、击穿、雪崩？
2. 如何保证缓存和数据库一致性？
3. Redis 分布式锁如何正确释放？
4. 大 Key 和热 Key 怎么发现和治理？
5. Redis 慢查询如何排查？

回答要结合项目例子，不要只背概念。

## 项目表达模板

```text
我们在商品详情接口使用 Redis 做缓存。
Key 按 product:{id}:detail 命名，TTL 30 分钟并加随机抖动。
更新商品时先更新数据库，再删除缓存，失败通过消息补偿。
热点商品使用逻辑过期和后台刷新，避免击穿。
上线后监控命中率、慢查询、内存和大 Key。
```

## 回答方式

面试回答不要只背定义，要按“场景、方案、风险、保障”展开。

示例：

```text
我们用 Redis 的 ZSet 做文章热榜。
member 是文章 ID，score 是综合热度分。
按天拆 Key，避免历史数据无限增长。
查询 Top 50 用 Z未译25173EV未译25173ANGE，文章排名用 Z未译25173EV未译25173ANK。
风险是刷分和热 Key，所以写入做限流，榜单定时落库，并监控 Key 大小。
```

## 容易追问的点

- 如果 Redis 挂了，接口怎么办？
- 缓存和数据库不一致怎么处理？
- 大 Key 怎么发现？
- 热 Key 怎么治理？
- 为什么不用本地缓存？
- 为什么不用 MQ 替代 Stream？

## 练习

- 用自己的项目写 3 段 Redis 面试表达。
- 每段都包含数据结构、Key、TTL、风险和监控。
