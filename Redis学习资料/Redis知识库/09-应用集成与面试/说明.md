## 展开学习路线

1. 先掌握 Java 客户端差异：Lettuce、Jedis、Redisson 分别适合什么场景。
2. 再学习 Spring Boot 集成：连接配置、序列化、`RedisTemplate`、Spring Cache 和异常降级。
3. 然后把 Redis 用法组织成项目表达：为什么用、怎么设计 Key、怎么保证一致性、怎么监控。
4. 最后做实战项目，把缓存、排行榜、锁、限流和 Stream 各做一个小闭环。

## 项目落地清单

| 内容 | 需要明确 |
| --- | --- |
| 客户端 | Lettuce、Jedis 还是 Redisson |
| 序列化 | String、JSON 或二进制 |
| Key 规范 | 是否统一封装，是否带业务前缀 |
| TTL | 默认 TTL 和业务单独 TTL |
| 异常处理 | Redis 不可用时接口如何降级 |
| 连接池 | 最大连接、等待时间、命令超时 |
| 监控 | 命中率、错误率、慢查询、连接池等待 |

## 面试表达框架

```text
场景：哪个业务用了 Redis
结构：用了什么数据类型和 Key 设计
策略：TTL、更新、删除、预热和降级
风险：一致性、穿透、击穿、大 Key、热 Key
保障：监控、告警、压测和故障演练
结果：数据库压力、接口耗时或稳定性改善
```

## 常见误区

- 面试只背八股，不结合项目。
- Spring Cache 默认 Key 和 TTL 没有定制。
- RedisTemplate 序列化混乱，同一 Key 被写成多种格式。
- Redisson 锁拿来就用，但不理解过期、续期和失败语义。
- 连接池、超时和重试没有和业务线程池一起设计。

## 阶段检查

- 能在 Spring Boot 中完成 Redis 连接、序列化和缓存配置。
- 能结合真实业务讲清 Redis 的数据结构选择。
- 能把缓存、高可用、性能、安全问题组织成完整面试答案。
