## 展开学习路线

1. 先掌握缓存 Aside，这是业务系统最常见的 Redis 使用方式。
2. 再学习穿透、击穿、雪崩，把缓存失效后的数据库保护机制设计完整。
3. 然后处理一致性，重点不是追求口号式强一致，而是明确不一致窗口、补偿和巡检。
4. 接着学习锁、限流、计数、排行榜和消息流，把 Redis 的原子命令用到真实业务中。
5. 最后设计降级方案：Redis 慢、Redis 挂、缓存未命中暴涨时，业务应该怎么退。

## 缓存方案模板

| 项目 | 示例 |
| --- | --- |
| 缓存对象 | 商品详情 |
| Key | `mall:product:{id}:detail` |
| 数据类型 | String JSON 或 Hash |
| TTL | 30 分钟 + 随机抖动 |
| 空值策略 | 不存在商品缓存空值 2 分钟 |
| 更新策略 | 更新数据库后删除缓存 |
| 击穿保护 | 热点 Key 使用逻辑过期或互斥锁 |
| 降级 | 返回基础字段或提示稍后重试 |
| 监控 | 命中率、回源次数、重建耗时、锁等待 |

## 实操任务

- 写一个商品详情缓存流程图。
- 为一个不存在商品 ID 设计空值缓存。
- 用 `SET NX EX` 和 Lua 做缓存重建互斥。
- 用 ZSet 实现日榜，并给历史榜单设置清理策略。
- 用 Stream 模拟订单创建事件，处理未确认消息。

## 常见误区

- 缓存没有 TTL，长期堆积。
- 更新数据库后直接更新缓存，双写失败后没有补偿。
- 分布式锁没有唯一值，释放时可能删掉别人的锁。
- 限流只写计数，不考虑窗口边界和降级响应。
- 把 Stream 当成所有消息队列场景的替代品。

## 阶段检查

- 能为查询接口设计缓存、空值、互斥、预热和降级策略。
- 能说明先更新数据库还是先删缓存的取舍。
- 能解释 Redis 分布式锁的过期时间、续期、唯一值和释放校验。
