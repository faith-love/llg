# 缓存穿透、击穿、雪崩

## 缓存穿透

穿透指查询一个数据库也不存在的数据，缓存无法命中，请求持续打到数据库。

治理方式：

- 缓存空值，并设置较短 TTL。
- 对明显非法参数做前置校验。
- 使用 Bloom Filter 拦截不存在 ID。
- 对异常来源限流。

## 缓存击穿

击穿指某个热点 Key 过期，大量请求同时查数据库重建缓存。

治理方式：

- 热点 Key 设置逻辑过期，由后台刷新。
- 互斥锁控制只有一个请求重建缓存。
- 提前异步刷新热点数据。
- 对重建失败设置短期兜底值。

## 缓存雪崩

雪崩指大量缓存同一时间失效，数据库被瞬时流量压垮。

治理方式：

- TTL 加随机抖动。
- 分批预热。
- 多级缓存。
- 限流、降级和熔断。
- 核心接口保留静态兜底或只读兜底。

## 设计模板

```text
缓存对象：商品详情
TTL：30 分钟 + 0 到 5 分钟随机抖动
空值 TTL：2 分钟
热点策略：逻辑过期 + 后台刷新
降级：返回基础字段，不展示实时推荐
```

## 三类问题的区别

| 问题 | 核心原因 | 典型表现 |
| --- | --- | --- |
| 穿透 | 查询不存在数据 | 缓存永远不命中，数据库被打穿 |
| 击穿 | 单个热点 Key 失效 | 大量请求同时回源同一数据 |
| 雪崩 | 大量 Key 同时失效 | 数据库整体流量暴涨 |

区分清楚原因，治理手段才不会混乱。空值缓存主要处理穿透，互斥锁和逻辑过期主要处理击穿，TTL 抖动和分批预热主要处理雪崩。

## 降级设计

缓存保护不能只依赖 Redis。数据库压力过高时，可以临时：

- 返回旧缓存。
- 返回基础字段。
- 限制非核心接口。
- 对异常参数直接拒绝。
- 对热点接口开启本地缓存。
