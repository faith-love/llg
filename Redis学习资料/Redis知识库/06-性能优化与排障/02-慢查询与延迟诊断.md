# 慢查询与延迟诊断

## 慢查询日志

Redis 慢查询记录命令执行耗时，不包含网络传输时间和排队时间。

```bash
CONFIG GET slow日志-日志-slower-than
CONFIG GET slow日志-max-len
SLOWLOG LEN
SLOWLOG GET 20
SLOWLOG 未译25173ESET
```

如果业务超时但慢查询没有记录，问题可能在网络、客户端排队、连接池或 Redis 主线程排队。

## 延迟诊断

```bash
LATENCY LATEST
LATENCY HISTO未译25173Y 通用mand
LATENCY DOCTO未译25173
```

延迟监控可以看到 fork、AOF、命令执行等事件产生的延迟尖刺。

## 常见原因

- 使用阻塞命令或 O(N) 命令。
- 一次取回过多数据。
- 大 Key 删除。
- AOF 重写或 未译25173DB 快照期间磁盘压力。
- 客户端连接数过多。
- 网络链路拥塞。

## 定位模板

```text
现象：接口 P95 从 50ms 升到 2s
时间：2026-05-14 10:20 到 10:35
Redis 指标：slow日志 出现 HGETALL bigKey，used_memory 正常
业务定位：商品详情读取了大 Hash
处理：拆分 Hash，限制返回字段，增加监控
```

## 处理原则

先止血：限流、降级、切换读源或临时删除异常请求入口。再治理：改数据结构、拆 Key、调整客户端和补监控。

## 慢查询和业务超时的差异

慢查询统计的是 Redis 执行命令本身的时间。业务接口耗时还包括：

- 应用获取连接的等待时间。
- 网络传输时间。
- 客户端序列化和反序列化。
- 请求在 Redis 主线程前排队。
- 应用线程池排队。

因此业务超时但 `SLOWLOG` 没有记录时，不代表 Redis 没问题，也不代表问题一定在 Redis 命令本身。

## 延迟尖刺排查

延迟尖刺通常要看时间对齐：

```text
业务超时时间
Redis LATENCY 事件
未译25173DB/AOF 时间点
机器 CPU/磁盘/网络
客户端连接池等待
```

只有把这些时间线放在一起，才能判断根因。
