# 性能基准与压测方法

## 压测目标

Redis 压测不是为了得到一个漂亮 QPS，而是回答：当前数据规模、命令组合、客户端连接和网络条件下，系统能承受多少流量，延迟在什么位置开始恶化。

## Redis学习资料-benchmark

```bash
Redis学习资料-benchmark -h 127.0.0.1 -p 6379 -c 100 -n 100000
Redis学习资料-benchmark -t get,set -d 1024 -c 200 -n 200000
```

它适合做基础基准，但和真实业务仍有差异。

## 真实压测要素

- 使用接近生产的数据大小。
- 使用真实命令组合，不只测 `PING`。
- 包含 Pipeline 或客户端序列化成本。
- 观察 P50、P95、P99，而不只看平均值。
- 同时观察应用侧、Redis、网络和机器指标。

## 指标

- Redis CPU、内存、网络吞吐。
- `instantaneous_ops_per_sec`。
- 慢查询数量。
- 连接数和拒绝连接。
- 缓存命中率。
- 客户端超时和错误率。

## 压测结论模板

```text
数据规模：100 万商品缓存，平均 value 1KB
命令组合：GET 90%，SET 8%，DEL 2%
并发：200 连接
结果：P95 4ms，P99 12ms，CPU 65%，无慢查询
结论：当前规格可承载目标流量，超过 1.5 倍后 P99 明显上升
```

## 压测前提

压测前要固定变量：

- Redis 版本和部署模式。
- 机器规格、网络位置和磁盘类型。
- 数据量和 value 大小。
- 命令比例。
- 客户端连接数和 Pipeline 批量。
- 是否开启持久化、复制和 TLS。

否则不同压测结果没有可比性。

## 不合格压测

这些压测结论参考价值很低：

- 只测 `PING`。
- 只测空实例。
- 只看平均耗时。
- 客户端和 Redis 在同一进程或同一机器，却拿结果代表生产网络。
- 不记录慢查询、CPU、内存、网络。

## 练习

- 分别压测 100B、1KB、10KB value。
- 对比不开 Pipeline 和开 Pipeline 的差异。
- 输出一份包含 P95/P99、CPU、内存、网络的压测报告。
