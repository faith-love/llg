# 性能排障复盘

## 复盘目标

Redis 性能排障要从“业务慢”追到“具体命令、具体 Key、具体客户端、具体资源”。只会看 `SLOWLOG` 不够，因为很多超时发生在连接池、网络、排队和序列化阶段。

## 排障时间线

记录一次性能问题时，先按时间线组织证据：

```text
10:00 发布开始
10:05 商品详情 P99 升高
10:06 Redis connected_客户端s 上升
10:07 数据库 QPS 上升
10:08 SLOWLOG 出现 HGETALL
10:10 回滚发布
```

时间线比零散指标更容易定位根因。

## 证据清单

```bash
INFO 客户端s
INFO memory
INFO stats
INFO commandstats
SLOWLOG GET 20
LATENCY DOCTOR
CLIENT LIST
```

应用侧还要保留：

- 连接池等待时间。
- Redis 命令超时次数。
- 缓存命中率。
- 回源数据库次数。
- 接口 P95/P99。

## 常见根因映射

| 表现 | 可能根因 |
| --- | --- |
| 慢查询多 | 大 Key、O(N) 命令、Lua 过长 |
| 无慢查询但接口慢 | 连接池排队、网络、客户端序列化 |
| 命中率下降 | Key 规则变化、TTL 集中失效、发布问题 |
| 连接数暴涨 | 短连接、连接池配置错误、重试风暴 |
| 淘汰增长 | 内存不足、TTL 缺失、容量估算失败 |
