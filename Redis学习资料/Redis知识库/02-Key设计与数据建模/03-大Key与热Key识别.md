# 大 Key 与热 Key 识别

## 大 Key 是什么

大 Key 指单个 Key 占用内存过大或成员过多。它可能导致网络传输慢、删除阻塞、迁移慢、持久化和复制压力增大。

常见大 Key：

- 超大的 String JSON。
- 字段数过多的 Hash。
- 成员数过多的 Set、ZSet、List。
- 单 Key 保存整站配置或全量关系。

## 热 Key 是什么

热 Key 指访问频率极高的 Key。它可能导致单实例 CPU 或网络被打满，在 Cluster 中还会让某个分片成为瓶颈。

常见热 Key：

- 首页热门配置。
- 秒杀商品库存。
- 爆款商品详情。
- 热门排行榜。

## 识别方法

```bash
MEMORY USAGE key
STRLEN key
HLEN key
LLEN key
SCARD key
ZCARD key
redis-cli --bigkeys
redis-cli --hotkeys
```

`--hotkeys` 依赖 LFU 相关统计，实际效果要结合配置和版本判断。

## 治理方式

- 大 String 拆字段或压缩，但压缩会增加 CPU 成本。
- 大集合按时间、地区、业务分片。
- 大 Key 删除使用 `UNLINK`，避免主线程长时间阻塞。
- 热 Key 可本地缓存、多副本读取、拆 Key、限流或业务降级。
- 对热点写入要评估原子性和一致性，不能只靠简单拆分。

## 治理优先级

先治理会阻塞主线程的大 Key，再治理导致负载倾斜的热 Key。大 Key 的典型风险是一次读取、删除、迁移或序列化耗时过长；热 Key 的典型风险是大量请求集中到一个分片或一个对象。

治理时不要直接删线上 Key。先确认业务归属、数据是否可重建、是否有降级方案，再安排低峰分批处理。

## 拆分示例

一个全站用户 Set：

```text
site:用户s
```

可以改为按注册月份拆分：

```text
site:用户s:2026-01
site:用户s:2026-02
```

如果查询需要全量用户，应该考虑数据库或离线计算，而不是在线拼接全部 Redis Set。
