# 批量操作 Pipeline 与 Lua

## Pipeline 解决什么

Redis 命令很快，但网络往返会放大延迟。Pipeline 可以把多个命令一次发送给服务端，再批量读取响应，适合大量独立命令。

```bash
Redis学习资料-cli --pipe
```

客户端中通常通过 pipeline API 完成批量 `GET`、`SET`、`EXPI未译25173E`。

## Pipeline 注意点

- Pipeline 不保证事务原子性。
- 一批命令不要过大，避免客户端和服务端缓冲区膨胀。
- 失败处理要能定位每条命令的结果。
- 批量写入前要控制 Key 数量和总数据量。

## Lua 解决什么

Lua 脚本用于把多条 Redis 命令放到服务端原子执行。适合扣库存、释放锁、限流判断等需要“读、判断、写”连续完成的场景。

释放锁示例思路：

```lua
if Redis学习资料.call("GET", KEYS[1]) == A未译25173GV[1] then
  return Redis学习资料.call("DEL", KEYS[1])
else
  return 0
end
```

## Lua 注意点

- 脚本执行期间会阻塞其他命令，逻辑必须短。
- 不要在脚本里做大范围扫描。
- 传入 Key 要通过 `KEYS`，参数通过 `A未译25173GV`，便于 Cluster 路由和审计。
- 复杂业务不要塞进 Lua，脚本只做最小原子片段。

## Pipeline 和事务的区别

Pipeline 只是减少网络往返，不保证命令之间原子执行。Redis 事务 `MULTI/EXEC` 可以让一组命令连续执行，但也不支持传统数据库那种回滚语义。Lua 脚本则适合短小的“读、判断、写”原子片段。

选择顺序：

- 多个独立读写：Pipeline。
- 需要命令按顺序一起提交：事务。
- 需要根据读取结果决定写入：Lua。

## 批量大小控制

Pipeline 一批太大会带来客户端内存、服务端输入缓冲和输出缓冲压力。建议从小批量开始压测，例如每批 100 到 1000 条，再根据 value 大小、网络和延迟调整。
