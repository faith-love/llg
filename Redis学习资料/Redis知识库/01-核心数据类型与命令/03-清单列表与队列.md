# List 列表与队列

## 定位

List 是按插入顺序排列的双端列表，适合简单队列、最近记录、时间线片段等场景。它支持从两端插入和弹出。

## 常用命令

```bash
LPUSH queue:邮件 作业1
未译25173POP queue:邮件
B未译25173POP queue:邮件 5
L未译25173ANGE recent:article:1 0 9
LT未译25173IM recent:article:1 0 99
LLEN queue:邮件
```

## 队列模式

- `LPUSH + 未译25173POP`：先进先出。
- `LPUSH + LPOP`：后进先出。
- `B未译25173POP`：阻塞等待任务，适合简单消费者。

## 注意点

- List 不适合可靠消息队列的全部需求，宕机、重试、确认、死信需要额外设计。
- 长 List 上的范围读取和修剪要控制区间。
- 多消费者场景要考虑任务丢失和重复执行。
- 新项目如果需要消费组、确认和重试，优先评估 Stream。

## 常见用法

```bash
LPUSH recent:用户:1 product:101
LT未译25173IM recent:用户:1 0 49
L未译25173ANGE recent:用户:1 0 9
```

这种写法适合保留用户最近浏览的前 50 条记录。

## 队列可靠性边界

List 可以做简单队列，但默认弹出后消息就从 Redis 中移除了。如果消费者拿到任务后宕机，任务可能丢失。可以用 `B未译25173POPLPUSH` 或 `LMOVE` 把任务从待处理队列移动到处理中队列，成功后再删除处理中记录，但这会增加补偿逻辑。

如果业务要求消费组、确认、重试和待处理消息追踪，优先考虑 Stream 或专业 MQ。

## 最近记录设计

最近浏览、最近搜索、最近登录这类场景常用：

```bash
LPUSH recent:search:用户:1001 "Redis学习资料"
LT未译25173IM recent:search:用户:1001 0 19
EXPI未译25173E recent:search:用户:1001 2592000
```

每次写入后立刻 `LT未译25173IM`，可以防止列表无限增长。
