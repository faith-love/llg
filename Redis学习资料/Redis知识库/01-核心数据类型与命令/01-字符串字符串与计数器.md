# String 字符串与计数器

## 定位

String 是 Redis 最基础的数据类型，值可以是普通字符串、数字字符串、JSON 文本或二进制内容。常用于缓存单值、计数器、开关状态、验证码和短期令牌。

## 常用命令

```bash
SET 用户:1:name "Ada"
GET 用户:1:name
SETEX sms:code:13800000000 300 918273
SETNX lock:order:1001 request-id
INCR view:article:1
INCRBY stock:sku:1 -1
MGET 用户:1:name 用户:2:name
```

## 典型场景

- 缓存单个查询结果：`缓存:product:{id}`。
- 访问计数：`counter:article:{id}:views`。
- 短期验证码：`sms:code:{phone}`。
- 幂等标记：`idem:支付:{requestId}`。
- 简单分布式锁：`lock:作业:{作业Id}`。

## 注意点

- 数字操作要求值能被解析为整数。
- JSON 字符串更新局部字段不方便，频繁更新字段时优先考虑 Hash。
- `MGET` 可以减少网络往返，但一次不要取过多 Key。
- `SETNX` 做锁时必须配合过期时间和唯一值，不能只用 `SETNX`。

## 检查问题

1. 这个值是否需要局部字段更新？
2. 是否需要 TTL？
3. 是否可能成为热点 Key？
4. 是否能从数据库或其他源恢复？

## 原子计数细节

`INCR` 和 `INCRBY` 是原子命令，多个客户端同时增加同一个计数时不会互相覆盖。但这只保证 Redis 内部计数原子，不代表业务一定正确。阅读数可以容忍重复，库存扣减通常还要校验库存是否足够，支付计数还要有幂等标记。

库存扣减更安全的思路是把“读取库存、判断是否大于 0、扣减”放到 Lua 脚本或数据库事务中，避免先 `GET` 再 `DECR` 时出现并发穿透。

## TTL 写法

优先使用一个命令同时写值和设置过期：

```bash
SET sms:code:13800000000 918273 EX 300
SET idem:支付:req-001 done NX EX 600
```

不要先 `SET` 再 `EXPIRE`，中间如果应用崩溃，会留下没有过期时间的 Key。

## 练习

- 用 `INCR` 实现文章阅读数。
- 用 `SET NX EX` 实现 10 分钟幂等标记。
- 用 `MGET` 批量读取 5 个用户昵称，并说明批量数量过大有什么风险。
