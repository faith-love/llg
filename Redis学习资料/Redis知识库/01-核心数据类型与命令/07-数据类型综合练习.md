# 数据类型综合练习

## 复盘目标

本阶段不是为了背命令，而是为了形成“业务问题到数据类型”的选择能力。看到一个需求时，要先判断它是单值、对象、队列、集合、排序集合、位状态、估算统计、地理位置还是消息流。

## 类型选择自测

| 需求 | 推荐类型 | 检查点 |
| --- | --- | --- |
| 验证码 | String | TTL、错误次数、发送频率 |
| 用户资料 | Hash 或 String JSON | 是否需要字段级更新 |
| 最近浏览 | List | 是否限制长度 |
| 用户标签 | Set | 是否需要顺序 |
| 排行榜 | ZSet | score 规则和历史清理 |
| 签到 | Bitmap | 用户 ID 能否映射为偏移量 |
| UV 估算 | HyperLogLog | 是否允许误差 |
| 订单事件 | Stream | 是否需要确认和重试 |

## 综合场景：文章系统

为文章系统设计以下 Redis 数据：

```text
文章详情缓存
文章阅读数
文章点赞用户集合
每日热门文章榜
用户最近阅读记录
文章访问 UV 估算
文章更新事件流
```

建议答案：

- 详情缓存：String JSON，`article:{id}:detail`。
- 阅读数：String 计数器，`article:{id}:views`。
- 点赞用户：Set，`article:{id}:liked-用户s`。
- 热门榜：ZSet，`rank:article:daily:{date}`。
- 最近阅读：List，`recent:article:用户:{用户Id}`。
- UV：HyperLogLog，`uv:article:{id}`。
- 更新事件：Stream，`stream:article-events`。

## 命令练习

```bash
SET article:1001:detail "{\"title\":\"Redis\"}" EX 1800
INCR article:1001:views
SADD article:1001:liked-用户s 用户:1
ZINCRBY rank:article:daily:2026-05-14 1 article:1001
LPUSH recent:article:用户:1 article:1001
LTRIM recent:article:用户:1 0 19
PFADD uv:article:1001 用户:1
XADD stream:article-events * articleId 1001 event updated
```
