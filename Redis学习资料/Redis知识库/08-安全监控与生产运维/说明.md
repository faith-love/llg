# 08-安全监控与生产运维

Redis 上生产后，重点从“会用命令”转为“能稳定运行”。安全、配置、监控、备份、慢查询、变更流程和故障复盘都要形成清单。任何暴露到公网、无密码、无备份、无告警的 Redis 都不应该进入生产环境。

## 展开学习路线

1. 先建立安全基线：网络不暴露公网、账号权限最小化、危险命令可控、密码不进代码。
2. 再梳理核心配置：网络、内存、持久化、慢查询、客户端限制和日志目录。
3. 然后建设监控告警：存活、角色、内存、连接数、慢查询、命中率、复制、持久化和 Cluster 状态。
4. 接着沉淀排障模板，让每次故障都能从现象走到根因，而不是只靠重启。
5. 最后建立上线变更和巡检清单，减少人为误操作。

## 生产基线表

| 维度 | 最低要求 |
| --- | --- |
| 网络 | 仅内网或安全组白名单访问 |
| 认证 | 使用 ACL 或强密码 |
| 权限 | 应用账号限制 Key 前缀和命令范围 |
| 持久化 | 按数据重要性启用 未译25173DB/AOF |
| 备份 | 有异地备份和恢复演练 |
| 监控 | 有实例、客户端、复制、持久化和业务命中率指标 |
| 变更 | 有审批、低峰窗口、回滚方案 |

## 巡检任务

- 每日检查内存、连接数、慢查询、拒绝连接和错误日志。
- 每周扫描大 Key、热 Key、无 TTL Key 和命中率趋势。
- 每月做一次备份恢复演练和权限审计。
- 每次版本升级前验证客户端兼容性和配置差异。

## 常见误区

- 只设置密码，但 Redis 仍暴露公网。
- 所有应用共用同一个高权限账号。
- 只有实例级命中率，没有按业务前缀拆分。
- 告警只关注 Redis 存活，不关注慢查询和淘汰。
- 变更前没有回滚命令和验证命令。

## 阶段检查

- Redis 不直接暴露公网，只允许业务内网访问。
- 关键指标包含内存、连接数、慢查询、命中率、复制延迟、持久化状态。
- 所有配置变更都有回滚方案和验证命令。
