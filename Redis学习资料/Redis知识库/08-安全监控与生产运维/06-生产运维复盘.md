# 生产运维复盘

## 复盘目标

生产 Redis 的目标是稳定、可观察、可恢复、可审计。学完本阶段后，你应该能拿出一份上线前检查表、一份日常巡检表和一份故障复盘模板。

## 上线前总检查

| 类别 | 检查项 |
| --- | --- |
| 网络 | 是否只允许内网或白名单访问 |
| 认证 | 是否启用 ACL 或强密码 |
| 权限 | 应用账号是否限制前缀和命令 |
| 内存 | 是否设置 `maxmemory` 和合适策略 |
| 持久化 | RDB/AOF 是否符合数据重要性 |
| 备份 | 是否有恢复演练 |
| 监控 | 是否覆盖内存、连接、慢查询、复制、命中率 |
| 变更 | 是否有回滚方案 |

## 日常巡检输出

```text
实例状态：
内存使用率：
连接数：
慢查询 Top：
大 Key 风险：
热 Key 风险：
淘汰数量：
复制状态：
持久化状态：
命中率趋势：
待处理风险：
```

巡检要输出结论，而不是只贴指标截图。

## 事故复盘重点

Redis 事故复盘至少回答：

- 为什么监控发现或没有发现？
- 为什么降级生效或没有生效？
- 是否存在人为误操作？
- 是否有配置、容量、发布或客户端问题？
- 哪个机制可以提前发现同类问题？

## 运维红线

- 不在生产执行未评估的全量命令。
- 不把 Redis 暴露公网。
- 不让所有应用共用管理员账号。
- 不在无备份情况下升级或迁移。
- 不把缓存命中率下降当成小问题。

## 练习

选择一个生产 Redis 实例，写一份巡检报告。如果没有真实实例，就基于测试环境模拟指标，重点练习报告结构和风险判断。
