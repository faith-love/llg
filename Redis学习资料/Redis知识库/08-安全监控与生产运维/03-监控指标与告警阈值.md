# 监控指标与告警阈值

## 核心指标

Redis 监控至少覆盖：

- 实例存活和角色。
- CPU、内存、网络、磁盘。
- 连接数、阻塞客户端、拒绝连接。
- QPS、命令耗时、慢查询。
- 缓存命中率。
- 过期和淘汰数量。
- RDB/AOF 状态。
- 主从复制延迟。
- Cluster 槽状态。

## INFO 命令

```bash
INFO 服务端
INFO 客户端s
INFO memory
INFO stats
INFO persistence
INFO replication
INFO commandstats
```

监控系统通常会定期采集这些指标。

## 告警建议

| 指标 | 建议 |
| --- | --- |
| 内存使用率 | 70% 预警，85% 告警 |
| `evicted_keys` | 非预期增长立即排查 |
| `rejected_connections` | 大于 0 需要排查 |
| `blocked_客户端s` | 持续大于 0 需要排查 |
| 慢查询 | 核心业务时段出现即记录 |
| 复制延迟 | 超过业务容忍窗口告警 |
| AOF/RDB 失败 | 立即告警 |

## 命中率

缓存命中率下降可能来自：

- TTL 过短。
- 缓存 Key 规则变化。
- 批量失效。
- 热点转移。
- 数据库异常导致缓存无法回填。

命中率要按业务前缀拆分，只看实例总体命中率容易掩盖核心接口问题。

## 业务指标也要监控

Redis 指标正常不代表业务正常。缓存系统还要关注：

- 缓存命中率按接口拆分。
- 回源数据库次数。
- 缓存重建耗时。
- 分布式锁等待和失败次数。
- 限流触发次数。
- 降级返回次数。

这些指标能把 Redis 状态和业务影响关联起来。

## 告警处理动作

告警必须有动作：

| 告警 | 第一动作 |
| --- | --- |
| 内存高 | 查增长前缀、大 Key、无 TTL |
| 慢查询 | 定位命令和 Key |
| 复制中断 | 判断是否影响读从和切换 |
| AOF/RDB 失败 | 检查磁盘、权限、错误日志 |
| 命中率下降 | 查发布、TTL、Key 规则和数据库压力 |
