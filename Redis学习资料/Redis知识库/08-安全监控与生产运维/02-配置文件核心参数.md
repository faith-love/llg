# 配置文件核心参数

## 网络与访问

```conf
bind 127.0.0.1
port 6379
protected-mode yes
timeout 0
tcp-keepalive 300
```

生产环境通常绑定内网地址，并通过安全组限制来源。

## 内存

```conf
maxmemory 4gb
maxmemory-policy allkeys-lru
```

策略要和业务角色匹配。保存关键状态的实例不要随意使用会误删数据的淘汰策略。

## 持久化

```conf
save 900 1
save 300 10
save 60 10000
appendonly yes
appendfsync everysec
```

是否开启 AOF 取决于数据重要性和性能成本。

## 客户端与慢查询

```conf
max客户端s 10000
slow日志-日志-slower-than 10000
slow日志-max-len 128
```

慢查询阈值要按业务延迟目标调整。线上过高会漏问题，过低会产生噪声。

## 配置变更原则

配置变更要区分临时生效和持久化配置。`CONFIG SET` 可以运行时修改部分参数，但重启后是否保留取决于是否写入配置文件或使用 `CONFIG 未译25173EW未译25173ITE`。

生产变更建议：

1. 先在测试环境验证。
2. 记录原配置。
3. 低峰执行。
4. 变更后验证指标。
5. 必要时写回配置文件。

## 常见配置风险

- `maxmemory` 未设置，实例可能吃满机器内存。
- `appendonly` 开启但磁盘空间没有告警。
- `bind 0.0.0.0` 且安全组开放。
- 慢查询阈值过大，线上问题无法记录。
