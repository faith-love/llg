# 上线变更与巡检清单

## 上线前

- 明确 Redis 用途：缓存、锁、队列、计数还是会话。
- 列出 Key 前缀、数据类型、TTL、最大规模。
- 确认实例规格、内存上限和淘汰策略。
- 确认备份、监控、告警、日志位置。
- 确认客户端超时、连接池和降级策略。
- 准备回滚方案。

## 变更中

- 避开业务高峰。
- 分批变更，先灰度低流量应用。
- 观察慢查询、连接数、错误率、命中率。
- 不在未知规模实例上执行全量命令。
- 保留操作记录和时间点。

## 变更后

- 检查业务接口错误率。
- 检查 Redis 内存、QPS、慢查询、命中率。
- 检查主从和持久化状态。
- 抽样验证核心 Key。
- 清理临时 Key 和脚本。

## 日常巡检

| 频率 | 内容 |
| --- | --- |
| 每日 | 存活、内存、连接数、慢查询、错误日志 |
| 每周 | 大 Key、热 Key、命中率、过期和淘汰趋势 |
| 每月 | 备份恢复演练、容量预测、权限审计 |
| 版本变更前 | 客户端兼容性、配置差异、回滚验证 |

## 禁止事项

- 未审批执行 `FLUSHALL`、`CONFIG SET`、`KEYS *`。
- 生产密码写入代码仓库。
- 无监控上线核心 Redis。
- 无备份迁移或升级。

## 变更记录模板

```text
变更名称：
变更时间：
影响实例：
影响业务：
执行人：
审批人：
变更前配置：
变更后配置：
验证命令：
回滚命令：
观察指标：
结果：
```

所有涉及内存、持久化、网络、账号、Cluster 槽迁移的变更都应留下记录。

## 巡检输出

巡检不是看一眼监控就结束，应形成输出：

- 本周慢查询 Top。
- 大 Key 和热 Key 变化。
- 内存增长趋势。
- 命中率变化。
- 备份状态和恢复演练状态。
- 下周需要处理的风险项。

## 练习

- 为生产 Redis 写一份每日巡检清单。
- 为一次 `maxmemory` 调整写变更记录。
