# 日志排障与常见故障

## 常见故障类型

- 连接超时。
- 认证失败。
- 内存达到上限。
- 慢查询导致请求排队。
- 主从复制中断。
- AOF/RDB 持久化失败。
- Cluster 槽异常。
- 客户端连接池耗尽。

## 排障顺序

1. 确认影响范围：单接口、单应用、单实例还是全链路。
2. 对齐时间：业务日志、Redis 日志、监控告警。
3. 看服务端：`INFO`、`SLOWLOG`、`LATENCY`、日志。
4. 看客户端：连接池、超时、重试、序列化。
5. 看数据：是否存在大 Key、热 Key、批量命令。
6. 先止血，再根因分析。

## 常见命令

```bash
PING
INFO
SLOWLOG GET 20
LATENCY DOCTOR
CLIENT LIST
MEMORY STATS
```

在大实例上避免使用高风险全量命令。


## 常见误判

- 只看到 Redis 超时，就认为 Redis 服务端慢。
- 只看平均延迟，忽略 P99。
- 忽略客户端连接池排队。
- 未区分缓存未命中和 Redis 不可用。

## 日志和指标对齐

排障时要把不同系统的时间对齐：

```text
应用错误日志
Redis 慢查询
Redis 日志
机器 CPU/内存/磁盘/网络
数据库 QPS
发布和配置变更记录
```

很多故障的根因不是 Redis 单点，而是发布改变了 Key 规则、数据库变慢导致回源堆积、客户端重试放大流量。

## 止血动作

常见止血方式：

- 降低非核心接口流量。
- 关闭异常缓存重建任务。
- 临时延长热点 Key TTL。
- 切换读源或关闭读从。
- 限制异常客户端连接。

止血后再做根因修复，避免边排查边扩大影响。
