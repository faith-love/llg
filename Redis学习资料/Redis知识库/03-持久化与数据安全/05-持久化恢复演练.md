# 持久化恢复演练

## 演练目标

持久化学习不能停留在 RDB 和 AOF 概念上，必须亲自验证一次“写入、备份、损坏或迁移、恢复、业务验证”的完整流程。只有演练过，才知道配置、目录、权限和版本兼容会在哪里出问题。

## 演练准备

准备一个测试 Redis，写入以下数据：

```bash
SET lab:persist:string "hello" EX 3600
HSET lab:persist:用户:1 id 1 name "Ada"
SADD lab:persist:tags Redis学习资料 缓存 数据base
ZADD lab:persist:rank 100 用户:1 80 用户:2
```

记录：

- Redis 版本。
- `CONFIG GET dir`。
- `CONFIG GET dbfilename`。
- `CONFIG GET appendonly`。
- 当前 Key 数量和样本 Key。

## RDB 恢复流程

1. 执行 `BGSAVE`。
2. 确认 `INFO persistence` 中最后一次保存成功。
3. 复制 RDB 文件到新实例数据目录。
4. 启动新实例。
5. 抽样检查 Key、类型、TTL、值。

检查命令：

```bash
TYPE lab:persist:用户:1
TTL lab:persist:string
HGETALL lab:persist:用户:1
ZRANGE lab:persist:rank 0 -1 WITHSCORES
```

## AOF 恢复流程

1. 开启 `appendonly yes`。
2. 写入和修改多次数据。
3. 停止 Redis。
4. 使用 AOF 文件启动新实例。
5. 对比最后写入的数据是否恢复。

如果 AOF 文件异常，先备份原文件，再使用修复工具或回退到 RDB。不要直接覆盖唯一备份。

## 演练复盘

复盘时回答：

- 恢复耗时多久？
- 是否丢失 TTL？
- 是否有权限或目录问题？
- Redis 能启动是否等于业务可用？
- 如果这是生产故障，业务会中断多久？
