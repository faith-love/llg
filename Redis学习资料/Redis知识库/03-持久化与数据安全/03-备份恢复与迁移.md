# 备份恢复与迁移

## 备份目标

备份不是把文件拷走就结束，而是要满足恢复目标：

- RPO：最多允许丢多少数据。
- RTO：故障后多久恢复服务。
- 恢复范围：整实例、单业务前缀、单个 Key。
- 验证方式：恢复后如何确认数据可用。

## 常见备份内容

- RDB 文件。
- AOF 文件或 AOF 目录。
- Redis 配置文件。
- ACL 用户配置。
- 部署拓扑、端口、密码和监控配置。

## 恢复流程

1. 停止目标 Redis。
2. 备份现有数据目录，避免覆盖后无法回退。
3. 放入要恢复的 RDB/AOF 文件。
4. 检查文件权限和配置路径。
5. 启动 Redis。
6. 用 `INFO`、抽样 Key、业务校验脚本验证。

## 迁移方式

- 小规模：`DUMP`/`RESTORE` 或客户端扫描迁移。
- 实例级：复制 RDB/AOF 到新实例。
- 在线迁移：主从复制、迁移工具、云厂商迁移能力。
- Cluster：按槽迁移，控制迁移速率和业务低峰窗口。

## 风险控制

- 迁移前确认 TTL 是否保留。
- 迁移后抽样比较 Key 数、类型、TTL、核心业务值。
- 避免用 `KEYS` 统计大实例。
- 迁移期间给业务设置降级或只读窗口。

## 备份策略设计

备份要分层：

- 本机短期备份：便于快速回滚。
- 异机备份：防止机器或磁盘损坏。
- 异地备份：防止机房级故障。
- 定期恢复演练：证明备份真的可用。

保留周期要结合数据变化频率和合规要求。普通缓存可以短保留，重要状态和审计相关数据要保留更久，但 Redis 不应承担唯一审计存储。

## 迁移校验表

| 校验项 | 说明 |
| --- | --- |
| Key 数量 | 按前缀抽样或统计 |
| 类型 | `TYPE` 对比 |
| TTL | 过期时间是否保留 |
| 值 | 核心对象抽样对比 |
| 业务读写 | 应用真实接口验证 |
| 监控 | 新实例指标是否正常 |

- 写出迁移失败时的回滚方案。
