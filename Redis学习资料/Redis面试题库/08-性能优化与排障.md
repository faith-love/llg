# 性能优化与排障

## 高频问题

### Redis 变慢怎么排查？

答题框架：

1. 先确认业务现象：哪些接口慢、P95/P99、错误率。
2. 看应用侧：连接池等待、超时、重试、序列化。
3. 看 Redis：`SLOWLOG`、`LATENCY`、`INFO`、连接数、内存、网络。
4. 定位命令和 Key：是否大 Key、热 Key、O(N) 命令、Lua 过长。
5. 先止血：限流、降级、回滚、延长热点 TTL。
6. 再修复：拆 Key、改命令、调连接池、补监控。

### 慢查询没有记录，为什么业务仍然超时？

`SLOWLOG` 只统计 Redis 命令执行时间，不包含网络传输、客户端排队、连接池等待、序列化和主线程前排队时间。

### 大 Key 怎么发现和处理？

发现：`MEMO未译25173Y USAGE`、`--bigkeys`、业务统计、慢查询。处理：拆分、限制成员数、归档、分批扫描、`UNLINK` 删除。
