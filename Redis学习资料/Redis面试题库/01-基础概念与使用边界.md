# 基础概念与使用边界

## 高频问题

### Redis 为什么快？

答题框架：

1. Redis 主要基于内存读写，避免了大量磁盘随机 IO。
2. 常用命令的数据结构设计高效，例如 Hash、跳表、整数编码等。
3. Redis 使用事件驱动模型处理网络请求，命令执行路径简洁。
4. 单线程命令执行减少锁竞争，但慢命令会阻塞后续请求。

补充一句：Redis 快不代表任何用法都快，大 Key、慢 Lua、全量扫描和大响应都会让它变慢。

### Redis 能不能替代 MySQL？

不能简单替代。Redis 适合缓存、短期状态、计数、排行榜、锁、限流和轻量消息。MySQL 更适合事务、强一致、复杂查询、持久化事实数据。

项目表达：

```text
我们项目里 MySQL 保存商品事实数据，Redis 只缓存商品详情和热点状态。Redis 数据可以通过数据库重建，所以 Redis 故障不会导致核心数据丢失。
```

### Redis 常见使用场景有哪些？

- 缓存。
- 会话和登录态。
- 验证码。
- 计数器。
- 排行榜。
- 分布式锁。
- 限流。
- 延迟任务。
- 消息流。

## 回答误区

- 只说“Redis 是内存数据库，所以快”，没有讲阻塞风险。
- 把 Redis 当强一致主库。
- 说 Redis 可以做 MQ，却不提确认、重试和堆积限制。
