# 分布式锁与并发控制

## 高频问题

### Redis 分布式锁怎么实现？

基础写法：

```bash
SET lock:order:1001 request-uuid NX EX 30
```

释放锁要用 Lua 校验 value：

```lua
if redis.call("GET", KEYS[1]) == ARGV[1] then
  return redis.call("DEL", KEYS[1])
else
  return 0
end
```

### 为什么释放锁要校验 value？

因为锁可能过期后被其他线程重新获取。如果原线程直接 `DEL`，会误删别人的锁。唯一 value 可以保证只释放自己持有的锁。

### 锁过期但业务没执行完怎么办？

可以续期，但续期也要校验 value。更关键的是业务要幂等，锁只能降低并发冲突概率，不能替代数据库约束和状态机。

## 项目表达

```text
我们在缓存重建时使用 Redis 锁保护热点 Key，锁 Key 按 lock:product:{id}:rebuild 设计，value 是请求 UUID，TTL 10 秒。释放锁时用 Lua 校验 value，拿不到锁的请求返回旧值或短暂等待。
```

## 回答误区

- 只说 `SETNX`，不设置过期。
- 释放锁直接 `DEL`。
- 认为有锁就不需要业务幂等。
