# 生产运维与安全

## 高频问题

### Redis 生产环境要注意什么？

答题框架：

- 网络：不暴露公网，只允许内网或白名单。
- 认证：启用密码或 ACL。
- 权限：应用账号限制前缀和危险命令。
- 内存：设置 `maxmemory` 和合适淘汰策略。
- 持久化：按数据重要性配置 RDB/AOF。
- 监控：内存、连接、慢查询、命中率、复制、持久化。
- 备份：有恢复演练。
- 变更：有审批和回滚。

### Redis 常见危险命令有哪些？

`FLUSHALL`、`FLUSHDB`、`CONFIG`、`SHUTDOWN`、`KEYS`、高风险 `EVAL`、大 Key `DEL`。生产要通过 ACL、审计和流程限制。

### Redis 内存满了怎么办？

先确认是否出现淘汰或写入失败，再查增长最快前缀、大 Key、无 TTL Key。临时可以扩容或降级，长期要治理 Key、TTL、拆分实例或调整策略。

- `maxmemory-policy` 怎么选？

- 如何做 Redis 上线评审？

## 项目表达

```text
我们生产 Redis 不暴露公网，应用使用独立 ACL 账号，只能访问业务前缀。监控内存、连接数、慢查询、命中率、复制延迟和持久化状态。核心变更需要低峰执行并准备回滚。
```

## 回答误区

- 只说设置密码，不说网络隔离。
- 所有应用共用管理员账号。
- 只监控 Redis 存活，不监控业务命中率。
