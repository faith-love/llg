# 主从、哨兵与 Cluster

## 高频问题

### 主从复制的作用是什么？

主从复制用于提供副本、读扩展和故障切换基础。主节点处理写入，从节点复制主节点数据。复制通常是异步的，所以可能有延迟和数据丢失窗口。

### Sentinel 解决什么问题？

Sentinel 负责监控主从节点，在主节点故障时自动选举新主，并通知客户端新的主节点地址。它解决自动故障切换，不解决异步复制带来的全部数据一致性问题。

### Redis Cluster 解决什么问题？

Cluster 通过 16384 个 hash slot 把数据分布到多个主节点，解决单实例内存和吞吐瓶颈。客户端根据槽访问节点，跨槽多 Key 命令会受限制。

- 热 Key 在 Cluster 中为什么仍然是问题？

## 项目表达

```text
我们使用 Sentinel 做 Redis 高可用，客户端通过 master name 发现主节点。主节点故障时 Sentinel 自动切换，应用会重连新主。由于复制是异步的，Redis 中只保存可重建缓存，核心事实数据仍以数据库为准。
```

## 回答误区

- 说主从复制是强一致。
- 说上了 Cluster 就没有热点问题。
- 客户端是否支持 Sentinel/Cluster 不提。
