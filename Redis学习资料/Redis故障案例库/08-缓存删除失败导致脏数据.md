# 缓存删除失败导致脏数据

## 现象

商品价格在数据库中已更新，但用户仍看到旧价格。检查发现 Redis 缓存未删除，旧值持续返回。

## 影响

- 用户看到错误数据。
- 价格、权限、库存展示等场景可能造成业务损失。
- 客服和运营介入成本增加。

## 排查路径

1. 查看数据库更新时间。
2. 查看 Redis 缓存值和 TTL。
3. 查看应用更新流程日志。
4. 检查删除缓存是否失败。
5. 检查是否有旧值回填缓存。

## 常见根因

- 数据库更新成功后删除缓存失败。
- 删除缓存没有重试。
- 并发读在更新期间回填旧值。
- 缓存 Key 规则不一致，删除了错误 Key。
- 更新缓存而不是删除缓存，双写失败。

## 止血动作

- 手动删除受影响 Key。
- 临时回源数据库。
- 对关键接口关闭缓存。
- 重新投递缓存删除消息。

## 长期修复

- 更新数据库后删除缓存。
- 删除失败记录重试任务。
- 使用消息或 bin日志 补偿删除。
- Key 模板统一封装。
- 对价格、权限等敏感缓存缩短 TTL 或增加版本。

## 复盘问题

- 删除缓存失败为什么没有告警？
- 是否有延迟双删或消息补偿？
- 旧值为什么能重新写回缓存？
- 这个缓存是否应该拆分或缩短 TTL？
