# 分布式锁过期引发重复执行

## 现象

定时任务或订单处理任务被两个实例重复执行。日志显示第一个实例任务执行时间超过锁 TTL，锁过期后第二个实例拿到锁。

## 影响

- 重复发送消息。
- 重复生成报表。
- 重复扣减或重复状态更新。
- 下游系统收到重复请求。

## 排查路径

1. 查看锁 Key 的 TTL 配置。
2. 查看任务实际执行耗时。
3. 检查是否有续期机制。
4. 检查释放锁是否校验 value。
5. 检查业务是否幂等。

## 常见根因

- 锁 TTL 设置过短。
- 任务耗时波动大。
- 没有续期机制。
- 锁释放直接 `DEL`，误删别人锁。
- 业务没有幂等保护。

## 止血动作

- 暂停重复任务实例。
- 提高锁 TTL。
- 增加数据库状态条件，防止重复写。
- 对已重复执行的数据做对账。

## 长期修复

- 加锁使用 `SET NX EX`。
- value 使用唯一请求 ID。
- 释放锁用 Lua 校验。
- 长任务支持续期或拆小。
- 业务侧必须幂等。
- 记录任务执行状态。

## 复盘问题

- 锁保护的资源是什么？
- TTL 如何估算？
- 任务超时时应该停止还是继续？
- 是否可以用数据库任务表替代锁？
