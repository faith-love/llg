# 缓存命中率突然下降

## 现象

商品详情接口延迟升高，数据库 QPS 明显上涨，Redis 实例存活正常。监控显示缓存命中率从 92% 下降到 35%。

## 影响

- JDBC数升高。
- 商品详情接口 P95/P99 上升。
- 部分请求超时。
- Redis QPS 可能下降，但数据库压力上升。

## 排查路径

1. 对齐命中率下降时间和应用发布时间。
2. 查看应用日志中缓存 Key 是否变化。
3. 检查 TTL 是否被改短。
4. 检查是否有批量删除缓存任务。
5. 查看数据库慢查询和连接池等待。
6. 抽样查询新旧 Key 是否并存。

## 常见根因

- 发布后 Key 模板变化，旧缓存全部失效。
- 版本字段或环境字段拼接错误。
- 批量清缓存脚本误删。
- TTL 从 30 分钟改成 30 秒。
- 缓存写入失败但应用没有告警。

## 止血动作

- 回滚最近发布。
- 临时恢复旧 Key 读取兼容。
- 对热点数据预热。
- 对非核心接口限流。
- 数据库压力过高时返回降级字段。

## 长期修复

- Key 模板统一封装，不允许业务代码散写。
- 缓存命中率按接口和业务前缀拆分监控。
- 发布前做缓存 Key 兼容性检查。
- 批量清缓存必须审批和灰度。
- 缓存写入失败要有告警。

## 复盘问题

- 为什么发布前没有发现 Key 规则变化？
- 命中率告警是否及时？
- 是否有预热和降级方案？
- 是否需要支持新旧 Key 双读一段时间？
