# 主从切换后读到旧数据

## 现象

Redis 主节点故障切换后，部分业务读到旧缓存或短时间内读写不一致。用户反馈刚修改的信息又变回旧值。

## 影响

- 用户看到旧数据。
- 状态判断错误。
- 缓存和数据库短暂不一致。
- 业务对 Redis 高可用信任下降。

## 排查路径

1. 查看故障切换时间点。
2. 查看主从复制延迟。
3. 确认客户端是否读从库。
4. 检查旧主是否仍被客户端连接。
5. 对比数据库事实数据和 Redis 缓存。

## 常见根因

- 主从复制异步，切换前部分写入未同步。
- 客户端读从库，复制延迟导致读旧值。
- Sentinel/Cluster 切换后客户端连接刷新不及时。
- 缓存没有版本号，旧值覆盖新值。

## 止血动作

- 强一致接口临时读主或回源数据库。
- 删除受影响缓存前缀。
- 关闭读从。
- 检查客户端连接目标。
- 对核心数据做对账。

## 长期修复

- 关键写后读主。
- 监控复制延迟。
- 客户端支持 Sentinel/Cluster 自动刷新。
- Redis 只保存可重建缓存。
- 重要状态使用数据库事务和业务补偿。

## 复盘问题

- 这类数据是否允许读旧？
- 为什么故障切换后没有自动回源？
- 客户端是否写死旧地址？
- 是否需要缓存版本号或逻辑时间？
