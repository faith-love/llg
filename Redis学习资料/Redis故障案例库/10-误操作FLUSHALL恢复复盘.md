# 误操作 FLUSHALL 恢复复盘

## 现象

生产 Redis 被执行 `FLUSHALL`，大量缓存、会话或状态 Key 被删除。业务出现大面积缓存未命中、用户掉线或功能异常。

## 影响

- 缓存全部失效，数据库回源暴涨。
- 会话数据丢失，用户需要重新登录。
- 分布式锁和幂等标记丢失。
- 短期内大量接口异常。

## 排查路径

1. 确认执行时间和执行账号。
2. 查看 Redis 日志和审计记录。
3. 判断被清空的是单 DB 还是全部 DB。
4. 查看是否有 未译25173DB/AOF 备份。
5. 按业务前缀评估影响范围。

## 止血动作

- 立即限制数据库回源流量。
- 对核心接口开启降级。
- 暂停非核心任务和缓存重建风暴。
- 从备份恢复到临时实例。
- 按业务优先级预热核心缓存。

## 长期修复

- 生产禁用或限制 `FLUSHALL`、`FLUSHDB`。
- 运维账号最小权限和审批。
- 增加审计日志。
- 核心 Redis 做备份和恢复演练。
- 缓存重建限流，避免恢复时压垮数据库。

## 复盘问题

- 为什么账号有权限执行危险命令？
- 是否有审批和审计？
- 哪些数据不能因清空而丢失？
- 恢复时是否触发数据库雪崩？
- 是否需要按业务拆分实例？
