## 使用方式

1. 先按现象找相似案例。
2. 按排查路径保留证据，不急着重启。
3. 先做止血，控制影响范围。
4. 再做根因修复和复盘。
5. 最后把新增监控和流程固化到上线检查里。

## 通用排障原则

- 先看业务影响，再看 Redis 指标。
- 对齐发布时间、错误日志、慢查询和监控。
- 明确是缓存未命中、Redis 不可用、Redis 变慢还是客户端等待。
- 线上避免 `KEYS *`、大 Key `DEL`、未评估的 `CONFIG SET`。
- 每次故障都要留下复盘文档。
