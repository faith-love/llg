# 热 Key 打满单分片

## 现象

Redis Cluster 中某个分片 CPU 和网络明显高于其他分片，业务接口整体延迟升高。热点集中在一个商品详情、首页配置或活动库存 Key。

## 影响

- 单分片成为瓶颈。
- Cluster 总容量没有用满，但局部过载。
- 热点 Key 访问变慢。
- 可能触发客户端超时和重试。

## 排查路径

1. 查看各分片 CPU、网络、QPS。
2. 查看客户端日志中的高频 Key。
3. 使用热点 Key 统计工具或业务埋点。
4. 检查是否滥用 hash tag 导致数据集中。
5. 查看是否有热点活动或突发流量。

## 常见根因

- 爆款商品详情被大量访问。
- 首页配置每个请求都读 Redis。
- 活动库存 Key 高频扣减。
- 大量 Key 使用相同 hash tag。
- 客户端没有本地缓存。

## 止血动作

- 对热点接口加本地缓存。
- 临时延长热点 Key TTL。
- 对非核心请求限流。
- 活动库存分片。
- 开启降级返回静态配置。

## 长期修复

- 热点 Key 访问 Top 监控。
- 热点数据本地短 TTL 缓存。
- 逻辑过期和后台刷新。
- 避免 hash tag 滥用。
- 热点写入设计分片和聚合。

## 复盘问题

- 热点是否可预测？
- 是否需要活动预案？
- 是否有本地缓存和降级？
- 热点 Key 是否影响了同实例其他业务？
