# 连接池耗尽导致雪崩

## 现象

应用大量报 Redis 获取连接超时，Redis 服务端 CPU 不高，业务接口开始堆积。随后数据库 QPS 上升，接口错误率扩大。

## 影响

- 应用线程等待 Redis 连接。
- 请求堆积导致线程池耗尽。
- Redis 重试放大流量。
- 缓存未命中或不可用导致数据库压力上升。

## 排查路径

1. 查看应用连接池指标：活跃连接、等待队列、获取连接耗时。
2. 查看 Redis `INFO 客户端s`。
3. 查看是否有慢命令占用连接。
4. 查看客户端超时和重试配置。
5. 对齐是否有流量突增或发布。

## 常见根因

- 连接池最大连接太小。
- 命令超时时间太长。
- 慢 Redis 命令导致连接长时间占用。
- 重试没有退避，故障时放大请求。
- 每次请求新建连接。

## 止血动作

- 降低非核心接口流量。
- 关闭无意义重试。
- 缩短 Redis 超时，让请求快速失败。
- 回滚最近发布。
- 临时扩容应用或 Redis 实例。

## 长期修复

- 连接池、线程池、Redis `max客户端s` 联合压测。
- 按业务链路设置超时和降级。
- 监控连接池等待时间。
- 禁止循环中逐条同步 Redis 调用。
- 高风险接口使用批量或 Pipeline。

## 复盘问题

- 为什么 Redis 服务端不忙但应用仍然超时？
- 连接池等待有没有告警？
- 重试策略是否加剧故障？
- 降级是否足够快？
