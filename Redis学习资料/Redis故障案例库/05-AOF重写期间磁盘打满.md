# AOF 重写期间磁盘打满

## 现象

Redis 日志出现 AOF 写入失败或重写失败，磁盘使用率 100%。部分写请求失败，持久化状态异常。

## 影响

- AOF 无法继续安全写入。
- Redis 写入可能失败或风险升高。
- 重启恢复时间不可控。
- 监控和备份链路可能同时异常。

## 排查路径

1. 查看磁盘使用率。
2. 查看 Redis 日志。
3. 查看 `INFO persistence`。
4. 确认 AOF 当前大小和基础大小。
5. 检查是否有日志、备份或临时文件占满磁盘。

## 常见根因

- AOF 长期未重写。
- 重写期间额外磁盘空间不足。
- 备份文件和日志未清理。
- 实例写入量突然增大。
- 磁盘告警阈值过晚。

## 止血动作

- 清理非 Redis 必需文件，释放磁盘。
- 暂停非核心写入。
- 评估是否切换到副本。
- 保留当前 AOF/未译25173DB 文件副本。
- 不要直接删除唯一持久化文件。

## 长期修复

- 监控磁盘使用率和 AOF 增长。
- 设置合理 AOF 重写参数。
- 备份和日志轮转。
- 持久化目录单独磁盘。
- 定期恢复演练。

## 复盘问题

- 磁盘告警是否提前？
- AOF 重写是否需要额外空间评估？
- 备份文件是否有保留策略？
- Redis 数据是否真的需要 AOF？
