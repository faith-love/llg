# 14-难点错误示例和避坑指南

## 坑 1：提交真实密码和 Token

### 错误示例

```yaml
password: MyRealPassword123
token: abc.def.real
```

### 为什么错

Git 历史会保存这些内容，后续删除也不代表彻底消失。

### 正确做法

```yaml
password: ${DB_PASSWORD}
token: ${APP_TOKEN}
```

### 避坑口诀

密钥进仓库，就是泄露。

## 坑 2：测试没有断言

### 错误示例

```java
@Test
void testCreateBook() {
    bookService.create(request);
}
```

### 为什么错

没有断言时，测试无法证明结果正确。

### 正确做法

```java
Book book = bookService.create(request);
assertEquals("Java 入门", book.getTitle());
```

### 避坑口诀

没有断言的测试，基本等于没测。

## 坑 3：只测成功，不测失败

### 错误想法

```text
成功流程通了，功能就没问题。
```

### 为什么错

真实项目更容易出问题的是库存不足、重复提交、参数非法、权限不足这些失败路径。

### 正确做法

每个核心业务至少补一个失败用例。

### 避坑口诀

失败路径不测，线上替你测。

## 坑 4：日志只打印一句失败

### 错误示例

```java
log.error("failed");
```

### 为什么错

不知道哪个用户、哪个业务 ID、哪个异常。

### 正确做法

```java
log.error("borrow failed, userId={}, bookId={}", userId, bookId, e);
```

### 避坑口诀

日志要能定位，不是只说失败。

## 坑 5：Docker 容器里用 localhost 连数据库

### 错误示例

```text
jdbc:mysql://localhost:3306/book
```

### 为什么错

容器里的 `localhost` 是容器自己，不是 MySQL 容器。

### 正确做法

```text
jdbc:mysql://mysql:3306/book
```

### 避坑口诀

Compose 内部互连用服务名。

## 坑 6：README 写得太空

### 错误示例

```text
运行项目即可。
```

### 为什么错

别人不知道 JDK、数据库、配置、初始化脚本和接口路径。

### 正确做法

写清环境要求、启动步骤、配置说明、接口示例和常见问题。

### 避坑口诀

README 的标准是别人能跑起来。

## 坑 7：依赖冲突只靠删依赖

### 错误做法

```text
看到报错就随机删除 pom 里的依赖。
```

### 为什么错

可能删掉真正需要的依赖，也无法理解冲突来源。

### 正确做法

先看：

```text
mvn dependency:tree
```

再判断哪个版本被谁引入。

### 避坑口诀

依赖冲突先看树，不要靠猜删。

## 坑 8：部署后只看容器状态

### 错误想法

```text
容器 running，部署成功。
```

### 为什么错

容器运行不代表应用接口可用。

### 正确做法

验证健康检查和核心接口。

### 避坑口诀

部署成功看接口，不只看进程。
