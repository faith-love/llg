# 13-长期提升路线

## 为什么要规划长期路线

Java 后端入门后，知识会变得更广。如果没有方向，很容易今天学微服务、明天学大数据、后天学 AI，最后每个都只会一点。

长期提升的关键是先选主线，再补宽度。

## 可选方向

| 方向 | 重点 |
| --- | --- |
| 业务后端 | 复杂业务建模、权限、工作流、报表 |
| 高并发 | 缓存、限流、熔断、压测、异步化 |
| 微服务 | 注册发现、配置中心、网关、链路追踪 |
| 数据方向 | SQL 优化、分库分表、冷热数据、数据一致性 |
| 云原生 | Docker、Kubernetes、CI/CD、可观测性 |
| 架构能力 | 需求拆解、边界划分、技术方案评审 |

## 推荐顺序

小白完成入门后，建议先按这个顺序：

1. 把一个 Spring Boot 项目做扎实。
2. 深入数据库和缓存。
3. 补充消息队列和异步。
4. 学习系统设计和架构拆分。
5. 根据工作方向选择微服务或云原生。

## 每月提升节奏

每月只选一个主题：

```text
第 1 月：SQL 优化
第 2 月：Redis 缓存
第 3 月：消息队列
第 4 月：权限模型
第 5 月：压测和性能排查
```

## 容易出错的示例

### 错误做法：同时追所有热门技术

```text
Kubernetes、微服务、分库分表、DDD、秒杀、大模型全都学。
```

### 为什么错

没有项目承载，很快遗忘，也难以形成深度。

### 正确做法

围绕一个项目逐步引入技术，每次引入都回答“解决什么问题”。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 主线 | 保持学习方向 | 防止乱学 | 先选业务后端或性能方向 | 重点是持续 |
| 项目承载 | 让技术落地 | 不容易忘 | 每学一个技术就改项目 | 难点是设计场景 |
| 深度 | 能被追问 | 提升竞争力 | 原理、实践、坑点都补 | 重点是复盘 |
| 宽度 | 理解系统全貌 | 便于协作 | 了解边界和适用场景 | 难点是不贪多 |

## 本节练习

- 选择未来 3 个月主线。
- 每个月只设一个主题。
- 给每个主题绑定项目改造点。
- 写出不学哪些内容。

## 本节通过标准

- 有明确长期方向。
- 学习内容能落到项目。
- 不同时追太多热点。
- 每月有复盘和产出。
