# 07-数据库高频清单

## 数据库为什么高频

后端项目最终都要落到数据。数据库问题能看出你是否理解表设计、索引、事务、锁、慢查询和数据一致性。

## 必会问题

- 索引的作用和代价。
- 联合索引和最左前缀。
- 慢查询怎么排查。
- `EXPLAIN` 看什么。
- 事务 ACID。
- 隔离级别。
- MVCC 基础。
- 乐观锁和悲观锁。
- 分页优化。
- SQL 注入防护。
- 连接池参数。

## 回答模板：索引

```text
索引用来加速查询，减少全表扫描。它的代价是占用空间，并且插入、更新、删除时需要维护索引。项目里不能看到慢 SQL 就乱加索引，要先看查询条件、排序字段和 EXPLAIN，再设计普通索引或联合索引。
```

## 慢查询排查顺序

```text
确认慢 SQL
看返回行数
看 where 条件
看是否命中索引
看 order by/group by
看是否 N+1
看锁等待
用 EXPLAIN 验证
```

## 容易出错的示例

### 错误示例：每个字段都加索引

### 为什么错

索引不是免费的，会增加写入成本和存储成本，也可能让优化器选择变复杂。

### 正确做法

围绕高频查询和排序设计索引，并用执行计划验证。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 索引 | 加速查询 | 读快写慢 | 围绕查询设计 | 重点是联合索引顺序 |
| 事务 | 保证一致性 | 多步操作安全 | Service 业务边界 | 难点是隔离级别 |
| MVCC | 提升并发读写能力 | 减少读写阻塞 | 结合快照读理解 | 难点是版本链 |
| 锁 | 控制并发修改 | 防止数据冲突 | 锁范围越小越好 | 重点是死锁和等待 |
| 分页 | 控制返回量 | 深分页会慢 | 游标分页 | 重点是排序稳定 |

## 本节练习

- 写一个乐观锁更新 SQL。
