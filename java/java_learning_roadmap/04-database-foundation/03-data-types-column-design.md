# 03-数据类型和字段设计

## 为什么字段类型重要

字段类型会影响：

- 存储空间。
- 查询性能。
- 数据合法性。
- Java 映射。
- 后续扩展。

字段类型不是随便都用字符串。

## 常见类型

| 类型 | 适合数据 |
| --- | --- |
| bigint | ID、计数 |
| int | 数量、状态码 |
| decimal | 金额 |
| varchar | 短文本 |
| text | 长文本 |
| datetime/timestamp | 时间 |
| boolean/tinyint | 布尔状态 |

金额不要用浮点数。

```sql
price decimal(10,2)
```

## 字段命名

建议：

- 小写加下划线。
- 名称表达业务含义。
- 避免数据库关键字。

示例：

```text
created_at
updated_at
deleted_at
borrow_status
```

## 通用字段

业务表常见通用字段：

- `id`
- `created_at`
- `updated_at`
- `created_by`
- `updated_by`
- `deleted`
- `version`

不是每张表都必须全有，但要知道用途。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 数字类型 | 保存 ID、数量、状态 | 类型过小会溢出 | ID 常用 bigint | 重点是估算范围 |
| decimal | 保存金额 | 避免浮点精度问题 | 金额统一 decimal | 重点是不要用 double 存钱 |
| varchar/text | 保存文本 | 长度影响索引和存储 | 短文本 varchar，长内容 text | 重点是别所有字段都 text |
| 时间字段 | 记录业务时间 | 排查和审计依赖时间 | 创建/更新时间建议保留 | 重点是时区和格式统一 |
| 软删除字段 | 标记删除状态 | 防止误删，保留历史 | 查询默认过滤 deleted | 难点是唯一约束要考虑软删除 |
