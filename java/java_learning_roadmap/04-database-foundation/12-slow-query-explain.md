# 12-慢查询和 EXPLAIN

## 慢查询是什么

慢查询是执行时间超过阈值的 SQL。

慢查询会导致：

- 接口响应慢。
- 数据库连接被长时间占用。
- 线程等待。
- 系统吞吐下降。

## 排查顺序

1. 找到慢 SQL。
2. 查看执行频率。
3. 使用 `EXPLAIN`。
4. 看是否走索引。
5. 看扫描行数。
6. 看排序和临时表。
7. 优化 SQL 或索引。
8. 修改后对比数据。

## EXPLAIN

```sql
explain
select id, title
from books
where isbn = '978711';
```

先关注：

- type。
- possible_keys。
- key。
- rows。
- Extra。

## 常见慢查询原因

- 没有合适索引。
- 返回行太多。
- 深分页。
- 排序没有索引支持。
- 函数包裹索引列。
- N+1 查询。
- 锁等待。

## 不要凭感觉加索引

错误做法：

```text
接口慢，加几个索引试试。
```

正确做法：

- 先看 SQL。
- 再看执行计划。
- 再结合查询频率和写入成本决定。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 慢查询 | 定位数据库瓶颈 | 接口慢常由 SQL 引起 | 先抓慢 SQL 再优化 | 重点是找到具体 SQL |
| EXPLAIN | 查看执行计划 | 不靠猜判断索引使用 | 先看 key 和 rows | 难点是字段多，先抓核心 |
| 扫描行数 | 判断查询成本 | 扫描越多越可能慢 | 优化 where 和索引 | 重点是 rows 只是估算 |
| Extra | 观察排序、临时表等 | 暴露额外操作 | 关注 filesort、temporary | 重点是结合 SQL 判断 |

## 本节练习

- 对按 ISBN 查询执行 `EXPLAIN`。
- 删除或忽略索引后对比执行计划。
- 对分页查询执行 `EXPLAIN`。
- 找一个可能导致慢查询的 SQL 并说明原因。

- 能列出常见慢查询原因。
