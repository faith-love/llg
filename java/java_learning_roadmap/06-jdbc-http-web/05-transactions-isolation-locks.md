# 05-事务、隔离级别和锁

## 事务是什么

事务是一组要么全部成功、要么全部失败的数据库操作。

例如借书：

1. 新增借阅记录。
2. 图书库存减 1。

这两个操作必须一起成功。如果记录新增成功但库存没减，数据就不一致。

## ACID

| 特性 | 含义 |
| --- | --- |
| Atomicity 原子性 | 要么全成功，要么全失败 |
| Consistency 一致性 | 事务前后数据符合业务规则 |
| Isolation 隔离性 | 并发事务之间互不随意干扰 |
| Durability 持久性 | 提交后数据持久保存 |

## JDBC 事务控制

```java
connection.setAutoCommit(false);
try {
    // 1. 插入借阅记录
    // 2. 更新库存
    connection.commit();
} catch (Exception e) {
    connection.rollback();
    throw e;
}
```

默认自动提交时，每条 SQL 都可能单独提交，不适合多步业务。

## 隔离级别

常见隔离级别：

- READ UNCOMMITTED。
- READ COMMITTED。
- REPEATABLE READ。
- SERIALIZABLE。

要理解它们主要解决：

- 脏读。
- 不可重复读。
- 幻读。

小白阶段先知道隔离级别越高，并发能力通常越低，数据隔离越强。

## 乐观锁

乐观锁适合冲突不高的场景。

常见做法：加版本号。

```sql
update books
set stock = stock - 1, version = version + 1
where id = ? and version = ? and stock > 0;
```

如果影响行数是 0，说明数据被别人改过或库存不足。

## 悲观锁

悲观锁认为冲突可能发生，先锁住数据。

```sql
select * from books where id = ? for update;
```

要在事务中使用。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 事务 | 保证多步业务一致 | 避免一半成功一半失败 | 业务动作完整包进事务 | 重点是事务边界 |
| ACID | 描述事务能力 | 帮助理解为什么事务可靠 | 用借书、转账举例理解 | 难点是隔离性最抽象 |
| 隔离级别 | 控制并发事务互相影响 | 防止脏读等问题 | 先理解现象，再背级别 | 重点是隔离越强成本越高 |
| 乐观锁 | 无锁冲突检测 | 冲突少时性能较好 | 版本号或条件更新 | 重点是检查影响行数 |
| 悲观锁 | 提前锁定数据 | 冲突高时更直接，但可能阻塞 | 锁范围要小，事务要短 | 重点是必须在事务中使用 |
