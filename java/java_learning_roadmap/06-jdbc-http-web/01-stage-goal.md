# 01-阶段目标

## 总目标

这一阶段的目标是把 Java 程序接入真实后端链路：接收 HTTP 请求、执行业务逻辑、通过数据访问层访问数据库、返回 JSON 响应。

你不需要一开始就上 Spring Boot 全家桶，但必须先理解底层问题：

- JDBC 底层链路怎么帮助你理解框架。
- 数据库连接怎么管理。
- 事务为什么重要。
- HTTP 请求是什么。
- REST API 怎么表达资源。
- Web 项目为什么要分层。

## 能力目标

| 能力 | 说明 |
| --- | --- |
| 数据库访问 | 能理解 JDBC CRUD 链路，并知道它和 MyBatis/Plus 的关系 |
| SQL 安全 | 能使用参数化查询防止 SQL 注入 |
| 事务意识 | 能解释借阅、扣库存等操作为什么要事务 |
| HTTP 理解 | 能说清请求行、请求头、请求体和响应状态码 |
| API 设计 | 能设计基础 REST API |
| 分层设计 | 能区分 Controller、Service、Mapper、DTO、Entity |
| 错误处理 | 能设计统一错误响应 |

## 学习边界

先把单体后端请求链路跑通。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 数据库访问 | 让 Java 程序保存和读取持久化数据 | 没数据库时数据只在内存里，程序重启就丢 | 先手写 JDBC，再学 MyBatis | 重点是理解框架解决了什么痛点 |
| HTTP | 让前端或客户端和后端通信 | 不懂 HTTP 就很难设计接口和排查问题 | 先抓 Method、状态码、JSON | 重点是请求和响应的结构 |
| REST API | 用统一风格表达资源操作 | 接口混乱会让前后端协作成本很高 | URL 表资源，Method 表动作 | 难点是状态码和错误结构要一致 |
| 分层 | 把接收请求、业务、数据访问分开 | 所有逻辑堆一起会难改难测 | Controller 薄，Service 承担业务 | 重点是事务通常在 Service 层 |
