# 13-代码生成器和项目规范

## 代码生成器解决什么问题

数据库表多时，重复创建 Entity、Mapper、XML、Service 很耗时。

代码生成器可以生成基础结构。

但生成器不是替你设计项目，它只减少重复劳动。

## 适合生成的内容

- Entity。
- Mapper。
- XML 基础模板。
- Service 接口和实现。
- Controller 基础模板，视团队规范决定。

## 不适合生成后不改的内容

- 复杂业务 Service。
- 权限逻辑。
- 复杂查询。
- 事务边界。
- 接口 DTO。

## 项目规范

建议统一：

- 表名前缀处理。
- Entity 命名。
- Mapper 命名。
- XML 位置。
- 字段填充规则。
- 逻辑删除字段。
- version 字段。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 代码生成 | 减少重复模板代码 | 表多时效率高 | 生成后必须审查 | 重点是生成不等于设计 |
| 命名规范 | 保持项目一致 | 文件和类名不乱 | 团队统一模板 | 重点是长期维护 |
| 生成边界 | 区分模板和业务 | 防止业务逻辑被覆盖 | 业务代码不要放在会被覆盖的位置 | 难点是二次生成冲突 |

## 本节练习

- 设计 Entity、Mapper、Service 命名规范。
- 说明哪些文件可以生成。
- 说明哪些业务代码必须手写。
- 写一份生成后检查清单。

## 本节通过标准

- 能解释代码生成器的价值和边界。
- 能制定基础命名规范。
- 知道生成后要审查代码。
