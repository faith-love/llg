# 14-MyBatis 与 Plus 怎么选择

## 选择原则

不要争论哪个“更高级”。选择要看场景。

## 适合 MyBatis 手写 SQL

- 多表复杂查询。
- 报表统计。
- 性能敏感 SQL。
- 需要精确控制 join、索引、排序。
- DBA 要审 SQL。

## 适合 MyBatis-Plus

- 单表 CRUD。
- 简单条件查询。
- 通用分页。
- 逻辑删除。
- 乐观锁。
- 自动填充。

## 混合使用

真实项目经常混合：

- 简单 CRUD 用 Plus。
- 复杂查询写 XML。
- 关键 SQL 手动优化。

## 不推荐的做法

- 所有查询都硬用 Wrapper。
- 所有查询都手写 XML。
- Controller 直接调用 BaseMapper。
- 为了少写代码牺牲可读性。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 手写 SQL | 精确控制查询 | 复杂场景可读可优化 | 复杂查询优先 XML | 重点是性能和可控 |
| Plus CRUD | 快速完成单表操作 | 减少重复代码 | 简单 CRUD 优先用 | 重点是别滥用 |
| 混合策略 | 兼顾效率和可控 | 避免一刀切 | 按复杂度选择 | 难点是团队规范 |

## 本节练习

判断这些场景用什么：

- 按 ID 查询图书。
- 多条件分页查询图书。
- 统计每个分类的借阅量。
- 扣库存并检查 version。
- 导出复杂报表。

## 本节通过标准

- 能给出选型理由。
- 能接受混合使用。
- 能知道可读性和可维护性优先。
