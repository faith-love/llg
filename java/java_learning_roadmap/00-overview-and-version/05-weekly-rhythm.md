# 05-每周学习节奏

## 为什么要固定节奏

小白学习最怕三种情况：

- 今天学很多，后面三天完全不碰。
- 只看视频，不写代码。
- 一直学新内容，从不复盘旧问题。

固定节奏能减少这些问题。你不需要每天都学很多，但要让学习、练习、复盘形成闭环。

## 推荐节奏

每周 7 天可以这样安排：

| 天数 | 任务 | 目标 |
| --- | --- | --- |
| 第 1 天 | 学新知识 | 看文档或课程，理解概念 |
| 第 2 天 | 写小练习 | 把概念变成代码 |
| 第 3 天 | 学新知识 | 继续下一个主题 |
| 第 4 天 | 写小练习 | 做变形练习，不只抄例子 |
| 第 5 天 | 项目实践 | 把知识放进小项目 |
| 第 6 天 | 整理笔记 | 记录错误、问题、总结 |
| 第 7 天 | 复盘和补缺 | 回看不会的点，调整下周计划 |

如果每周只能学 3 天：

- 第 1 天：学新知识。
- 第 2 天：写练习。
- 第 3 天：项目实践加复盘。

## 每次学习的结构

一次 2 小时学习，可以这样切：

```text
20 分钟：回顾上次内容
40 分钟：学习新知识
40 分钟：写代码练习
15 分钟：记录问题
5 分钟：提交 Git
```

如果只有 1 小时：

```text
10 分钟：回顾
25 分钟：学习
20 分钟：练习
5 分钟：记录和提交
```

## 学习时必须写代码

每学习一个概念，至少写一个例子。

例子：

- 学 `if`：写成绩等级判断。
- 学数组：写最大值、平均值、排序。
- 学集合：写学生列表增删改查。
- 学异常：写非法输入处理。
- 学线程：写多线程计数错误示例。
- 学事务：写借书库存扣减。

不要只复制教程代码。至少改一个条件、加一个字段、换一个场景。

## 笔记怎么写

小白笔记不要追求漂亮，先追求有用。

推荐格式：

```markdown
# 今日学习

## 学了什么

## 写了什么代码

## 报了什么错

## 错误原因

## 怎么解决

## 明天要补什么
```

关键是记录错误。错误是最好的学习材料。

## Git 提交节奏

每完成一个小练习，就提交一次。

提交示例：

```powershell
git add .
git commit -m "practice: add array max value exercise"
```

不要等一周后一次性提交。提交越小，越容易复盘。

## 每周复盘问题

每周末回答：

1. 本周写了多少代码？
2. 本周完成了哪些练习？
3. 哪 3 个知识点还不懂？
4. 哪个错误最值得记录？
5. 下周最重要的 1 个目标是什么？

## 本节练习

创建 `weekly-review-template.md`：

```markdown
# Java 每周复盘

## 本周学习时间

## 本周完成练习

## 本周项目进展

## 本周错误记录

## 仍然不懂的问题

## 下周计划
```

## 本节通过标准

- 能制定自己的每周学习安排。
- 能保证每周至少有代码练习。
- 能用 Git 保存学习进度。
- 能每周写一次复盘。
