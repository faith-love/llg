# 00A-知识点深挖模板

## 为什么要加这个模板

只知道“语法怎么写”是不够的。真正能把 Java 学明白，需要知道每个知识点为什么存在、解决什么问题、什么时候该用、什么时候不该用。

后续每个知识点都尽量按下面 6 个角度理解。

## 6 个理解角度

| 角度 | 要回答的问题 |
| --- | --- |
| 作用 | 这个知识点让代码具备什么能力？ |
| 痛点 | 没有它时，代码会出现什么麻烦？ |
| 优点 | 使用它之后，代码在哪些方面更好？ |
| 使用技巧 | 写代码时怎么用更稳、更清晰？ |
| 难点 | 小白最容易误解或写错哪里？ |
| 重点 | 复习、项目、面试时必须抓住什么？ |
| 错误示例 | 最容易写错的代码长什么样？为什么错？怎么改？ |

## 示例：接口

| 角度 | 说明 |
| --- | --- |
| 作用 | 定义一组能力或规则，让调用方依赖抽象。 |
| 痛点 | 如果直接依赖具体类，后续换实现时要改很多调用方代码。 |
| 优点 | 降低耦合，方便替换实现，也方便测试。 |
| 使用技巧 | 先从调用方需要什么能力出发设计方法，不要把实现细节塞进接口。 |
| 难点 | 小白容易把接口当成“没有方法体的类”，没有理解它是契约。 |
| 重点 | 接口解决的是调用方和实现方的隔离问题。 |

## 复习方法

每学完一个文件，用自己的话写 3 句话：

1. 这个知识点解决什么问题？
2. 我能写一个什么例子证明我会用？
3. 它最容易错在哪里？

如果这 3 个问题答不上来，说明还停留在“看过”，没有到“学会”。

## 错误示例模板

```markdown
## 坑：一句话描述问题

### 错误示例

### 为什么错

### 正确写法

### 避坑口诀
```

错误示例不是为了背错误，而是为了训练你看到类似代码时能立刻发现风险。
