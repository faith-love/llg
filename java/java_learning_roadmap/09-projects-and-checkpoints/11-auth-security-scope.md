# 11-权限、登录和安全边界

## 权限解决什么问题

权限控制决定谁能访问什么资源、执行什么操作。没有权限控制，项目很容易出现越权访问。

常见角色：

- 游客。
- 普通用户。
- 管理员。

## 登录和认证

认证解决“你是谁”。

常见流程：

```text
用户提交账号密码
后端校验
生成 Token 或 Session
后续请求携带凭证
后端识别用户身份
```

## 授权

授权解决“你能做什么”。

示例：

| 操作 | 游客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 查看图书 | 可以 | 可以 | 可以 |
| 借阅图书 | 不可以 | 可以 | 可以 |
| 新增图书 | 不可以 | 不可以 | 可以 |
| 删除用户 | 不可以 | 不可以 | 可以 |

## 安全边界

后端必须自己校验：

- 是否登录。
- 是否有角色。
- 是否只能操作自己的资源。
- 参数是否合法。
- 状态是否允许操作。

不要只依赖前端隐藏按钮。

## 容易出错的示例

### 错误示例：只隐藏前端按钮

普通用户页面不显示“删除图书”按钮，但后端接口没有权限校验。

### 为什么错

用户可以直接调用：

```text
DELETE /api/books/1
```

### 正确做法

后端接口必须校验管理员权限。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 认证 | 确认用户身份 | 未登录不能访问私有接口 | Token 或 Session | 重点是凭证校验 |
| 授权 | 判断操作权限 | 防止越权 | 角色和资源所有者结合 | 难点是数据权限 |
| 后端校验 | 安全底线 | 前端可被绕过 | 所有敏感接口都校验 | 重点是不能只靠前端 |
| 错误状态 | 明确失败原因 | 前端处理清楚 | 401 未登录，403 无权限 | 重点是区分 |
