# 07-需求拆解和功能清单

## 需求拆解解决什么问题

需求拆解是把“我要做一个系统”变成可开发、可测试、可验收的小任务。

没有需求拆解的痛点：

- 不知道先做什么。
- 功能越写越乱。
- 做完不知道是否完成。
- 面试时说不清项目范围。

## 拆解方法

先按角色拆：

```text
游客
普通用户
管理员
系统任务
```

再按业务动作拆：

```text
注册
登录
查询
新增
修改
删除
借阅
归还
```

最后按异常场景补：

```text
参数为空
资源不存在
重复提交
权限不足
状态不允许
库存不足
```

## 功能清单模板

| 模块 | 功能 | 角色 | 优先级 | 验收标准 |
| --- | --- | --- | --- | --- |
| 图书 | 新增图书 | 管理员 | P0 | ISBN 不能重复 |
| 借阅 | 借书 | 普通用户 | P0 | 库存不足时失败 |
| 借阅 | 归还 | 普通用户 | P0 | 归还后库存恢复 |

## 优先级

| 优先级 | 含义 |
| --- | --- |
| P0 | 没有它项目不能成立 |
| P1 | 项目重要增强 |
| P2 | 可选优化 |

小白项目先完成 P0，再做 P1，不要一开始做 P2。

## 容易出错的示例

### 错误示例：功能清单只写名词

```text
用户模块
图书模块
借阅模块
```

### 为什么错

名词不能直接开发。开发需要知道谁做什么、输入什么、输出什么、失败怎么办。

### 正确做法

```text
管理员新增图书：输入 ISBN、标题、作者、库存；ISBN 重复返回错误；成功后返回图书 ID。
```

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 角色 | 明确谁使用功能 | 权限边界更清楚 | 游客/用户/管理员 | 重点是权限差异 |
| 业务动作 | 转成接口和方法 | 名词不能开发 | 动词描述功能 | 重点是输入输出 |
| 异常场景 | 让功能可控 | 真实问题多在失败路径 | 每个 P0 功能列失败 | 难点是状态错误 |
| 优先级 | 控制范围 | 防止项目膨胀 | P0 先闭环 | 重点是克制 |

## 本节练习

- 给图书馆项目拆出 15 个功能。
- 给每个功能标角色和优先级。
- 给 P0 功能补失败场景。
- 删除 3 个当前阶段不需要的功能。

## 本节通过标准

- 功能清单能直接指导开发。
- 每个核心功能有验收标准。
- 能区分 P0、P1、P2。
- 能说明哪些功能暂时不做。
