# 06-订单系统简化版

## 项目定位

订单系统简化版适合进阶和面试准备。它不追求完整电商，而是训练事务、库存并发、幂等、状态机、定时任务和异步处理。

## 核心功能

- 商品列表。
- 创建订单。
- 库存扣减。
- 支付状态模拟。
- 订单取消。
- 超时关闭订单。
- 消息队列异步处理。

## 推荐表设计

```text
products
product_stock
orders
order_items
payment_records
order_status_logs
```

## 订单状态

```text
CREATED -> PAID -> FINISHED
CREATED -> CANCELED
CREATED -> CLOSED
```

状态流转必须受控，不能随意改状态。

## 核心难点

| 难点 | 说明 |
| --- | --- |
| 库存扣减 | 并发下不能超卖 |
| 幂等 | 重复支付、重复回调不能重复处理 |
| 状态机 | 状态只能按规则流转 |
| 事务边界 | 下单、扣库存、写订单要一致 |
| 异步消息 | 消息失败要有重试或补偿 |

## 容易出错的示例

### 错误示例：先查库存再更新

```text
select stock from product_stock where product_id = 1
如果 stock > 0
update product_stock set stock = stock - 1
```

### 为什么错

并发请求可能都查到有库存，然后都扣减，导致超卖。

### 正确做法

用条件更新：

```sql
update product_stock
set stock = stock - 1
where product_id = ? and stock > 0;
```

然后检查影响行数。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| 条件更新 | 防止超卖 | 并发下比先查再改安全 | 检查影响行数 | 重点是原子性 |
| 幂等 | 防止重复处理 | 支付回调可能重复 | 唯一业务号和状态判断 | 难点是所有入口都要考虑 |
| 状态机 | 控制业务流转 | 防止状态乱跳 | 明确允许的流转 | 重点是拒绝非法状态 |
| 异步 | 解耦慢流程 | 提升响应速度 | 消息要可重试 | 难点是最终一致性 |

## 验收标准

- 库存不足不会生成有效订单。
- 并发扣库存不会出现负数。
- 重复支付不会重复改状态。
- 取消和支付状态不会互相覆盖。
- 超时关闭订单有定时任务。
- 异步消息失败有重试或补偿思路。

## 面试讲法

```text
订单项目重点训练并发和状态控制。我用条件更新扣库存，并检查影响行数防止超卖。订单状态只能按预设流转，重复支付通过支付流水号和订单状态保证幂等。超时订单由定时任务关闭，异步消息失败需要重试或补偿。
```
