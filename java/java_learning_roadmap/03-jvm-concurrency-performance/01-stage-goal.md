# 01-阶段目标

## 总目标

这一阶段目标不是成为 JVM 专家，而是建立后端开发必须具备的运行时意识。

你要知道代码运行后会占用内存、会产生对象、会创建线程、会竞争资源，也会因为错误设计出现卡顿、内存溢出和数据错乱。

## 需要掌握的能力

| 能力 | 说明 |
| --- | --- |
| 运行理解 | 知道 `.java` 如何变成 `.class`，再由 JVM 执行 |
| 内存理解 | 知道堆、栈、方法区大致放什么 |
| GC 理解 | 知道垃圾对象怎么判断，GC 日志怎么看个大概 |
| 并发理解 | 知道线程安全问题来自共享可变状态 |
| 线程池理解 | 知道线程池参数控制什么风险 |
| 排查理解 | 遇到慢、卡、OOM、CPU 高时知道从哪里看 |

## 学习边界

现在先不深入：

- JVM 源码。
- 每种垃圾收集器的底层算法细节。
- 锁优化的全部实现。
- 高级并发框架源码。
- 大规模压测平台。

先能做实验、能解释现象、能避开常见坑。

## 知识点深挖

| 知识点 | 作用 | 痛点或优点 | 技巧 | 难点和重点 |
| --- | --- | --- | --- | --- |
| JVM | 让 Java 程序跨平台运行 | 不理解 JVM 时，遇到内存和 GC 问题只能猜 | 先从内存区域和工具实验学起 | 重点是知道程序运行时发生什么 |
| 并发 | 提高资源利用率和吞吐能力 | 写错会导致数据错乱、死锁、资源耗尽 | 先写错误示例，再写修复版 | 重点是共享可变状态要受控 |
| 性能排查 | 用数据定位问题 | 不靠感觉优化，避免越改越乱 | 先确认现象，再定位瓶颈 | 重点是对比修改前后数据 |
